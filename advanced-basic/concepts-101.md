# 概念入门：助手、智能体、技能、MCP 与频道

Cherry Studio V2 把“和模型对话”与“让模型执行任务”分成了不同层次。理解下面几个概念后，就能更快判断该从哪里开始配置。

## 先看结论

| 概念 | 主要作用 | 典型场景 |
| :--- | :--- | :--- |
| 模型服务 | 提供模型和 API 访问能力 | 接入 DeepSeek、Claude、GPT 等模型 |
| 助手 | 保存一套可重复使用的对话配置 | 翻译、写作、问答、知识库检索 |
| 智能体 | 在受控权限下调用工具并完成多步骤任务 | 处理文件、运行命令、执行工作流 |
| 技能 | 向智能体提供特定任务的说明、流程和资源 | 生成演示文稿、审阅代码、按团队规范写文档 |
| MCP | 以统一协议连接外部工具和数据 | 搜索网页、读取数据库、调用第三方服务 |
| 频道 | 把智能体接入即时通讯平台 | 在飞书、Telegram、Slack 等平台中使用智能体 |
| 定时任务 | 按一次、间隔或 Cron 计划运行智能体 | 每日简报、周期检查、定时汇总 |

最常见的选择方式是：

* 只需要稳定的人设、模型参数或知识库问答：使用**助手**。
* 需要 AI 读取目录、修改文件、运行命令或连续调用工具：使用**智能体**。
* 智能体缺少某种工作方法：安装并启用**技能**。
* 助手或智能体需要 Cherry Studio 之外的工具：配置 **MCP**。
* 希望团队成员从聊天软件中使用智能体：配置**频道**。
* 希望智能体无人值守地按计划运行：创建**定时任务**。

## 模型服务是能力来源

模型服务保存 API 地址、密钥和模型列表。助手与智能体都要选择模型，但两者的模型要求不同：

* 助手面向日常对话，可根据场景选择支持文本、视觉、推理或工具调用的模型。
* 智能体的模型选择器只显示支持 Anthropic Messages 端点、且适合对话执行的模型；Embedding、Rerank 和图像生成模型不会出现在这里。

先在 **设置 → 模型服务** 完成配置，再创建助手或智能体。具体步骤见[模型服务](../pre-basic/providers/)。

## 助手：可复用的对话配置

助手用于保存一套长期复用的对话行为。除了名称和提示词，还可以配置模型、采样参数、上下文数量、知识库和 MCP 模式。

例如，你可以创建：

* 固定术语和输出格式的翻译助手。
* 连接产品资料知识库的客服助手。
* 可以调用搜索 MCP 的研究助手。

助手适合以对话为中心的任务。它可以检索知识库或调用已配置的 MCP 工具，但不会像智能体那样获得本地工作目录、文件编辑权限和命令执行权限。

助手在[资源库](../cherrystudio/preview/library.md)中创建和维护，在主对话页面中使用。继续阅读[助手库](../cherrystudio/preview/assistants.md)和[对话](../cherrystudio/preview/chat.md)。

## 智能体：可执行的任务配置

智能体除了提示词和模型，还可以配置：

* 允许访问的本地目录。
* 工具权限模式。
* 内置工具、MCP Server 和技能。
* 主模型、规划模型和小模型。
* 最大轮次、环境变量、心跳等运行设置。

这些设置让智能体可以围绕一个目标持续执行多步操作，而不只是给出操作建议。例如，它可以读取工作区文件、修改文档、调用 MCP 服务，并把结果保存在本地。

{% hint style="warning" %}
智能体的权限范围决定它能读写哪些目录、是否可以直接执行工具。开始使用时应限制可访问目录，并优先采用需要确认的权限模式；只有在明确了解风险时才使用跳过确认的模式。
{% endhint %}

智能体页面底层依赖 Cherry Studio 的本地 **API 服务器**。V2 在新建智能体时会自动尝试启动它，通常不需要先去设置页手动配置；如果服务被停用或未能运行，智能体页面会显示启动提示。API 服务器也可以供其他应用通过本地 HTTP 接口调用 Cherry Studio。详见[智能体](agent.md)和[API 服务器](api-server.md)。

## 技能：告诉智能体“怎样完成一类工作”

技能是一组可安装的任务说明和配套资源。它更像工作手册：描述触发条件、执行步骤、质量要求，以及可能需要使用的脚本或模板。

技能与智能体按智能体 ID 绑定。新建智能体时要先保存，随后才能在该智能体的 **能力扩展 → 技能** 中启用技能。

适合使用技能的情况包括：

* 希望同一类任务每次都遵循固定流程。
* 需要复用团队规范、模板或检查清单。
* 想把一套成熟的方法交给多个智能体使用。

安装、搜索和管理方法见[技能](../pre-basic/settings/skills.md)。

## MCP：给 AI 连接外部能力

MCP（Model Context Protocol）是连接 AI 应用与外部工具、提示词和资源的协议。Cherry Studio 可以添加本地 STDIO Server，也可以连接 SSE 或 Streamable HTTP Server。

MCP Server 可以向模型提供三类能力：

| 能力 | 用途 |
| :--- | :--- |
| Tools | 执行搜索、查询、写入或调用 API 等操作 |
| Prompts | 提供可复用的提示模板 |
| Resources | 提供可读取的数据或上下文 |

助手支持停用、自动和手动三种 MCP 模式；智能体可以从已启用的 MCP Server 中选择要绑定的服务。

{% hint style="warning" %}
MCP Server 可能在本机运行程序，也可能把内容发送给远程服务。添加前应确认来源、命令、环境变量、访问目录和远程地址，并只授予完成任务所需的权限。
{% endhint %}

配置方法见[MCP 使用教程](mcp/)。

## 技能与 MCP 有什么区别

两者经常配合使用，但解决的问题不同：

| 对比 | 技能 | MCP |
| :--- | :--- | :--- |
| 核心问题 | 告诉智能体“怎样做” | 给模型提供“可以调用什么” |
| 主要内容 | 说明、流程、模板、脚本和资源 | 工具、提示词和资源接口 |
| 主要使用位置 | 智能体 | 助手和智能体 |
| 是否依赖外部服务 | 不一定 | 取决于具体 Server |

例如，“按团队模板撰写周报”可以做成技能；“从项目管理系统读取本周任务”可以通过 MCP 提供。把两者组合后，智能体既知道写作流程，也能取得所需数据。

## 频道：把智能体接入聊天平台

频道把一个智能体绑定到即时通讯平台。Cherry Studio V2 当前提供飞书 / Lark、Telegram、QQ、微信、Discord 和 Slack 的频道配置。

频道负责接收平台消息、把消息交给已绑定的智能体处理，再将结果发回原平台。它不会替代智能体本身：模型、提示词、工具、目录和权限仍在智能体中配置。

频道通常会在无人值守状态下运行。启用前应同时检查：

* 绑定的智能体和模型是否正确。
* 允许响应的会话或频道 ID 是否受到限制。
* 智能体是否具备完成任务所需的工具权限。
* 平台令牌和密钥是否只保存在对应配置中。

详见[频道](agent-channels.md)。

## 定时任务：按计划运行智能体

定时任务同样以智能体为执行主体。你可以创建：

* 只运行一次的任务。
* 按固定间隔重复的任务。
* 使用 Cron 表达式安排的任务。

定时任务适合无需等待人工输入的工作。创建前，应先让对应智能体在普通会话中成功完成同一任务，再为它设置合适的权限、超时时间和运行计划。详见[定时任务](scheduled-tasks.md)。

## 一套能力如何组合

以“每天汇总团队项目进展并发送到飞书群”为例：

1. 在**模型服务**中配置智能体可用的模型。
2. 创建**智能体**，写明汇总规则和输出格式。
3. 安装并启用团队周报**技能**，固化写作流程。
4. 通过 **MCP** 连接项目管理系统，读取任务数据。
5. 创建**定时任务**，每天按计划运行智能体。
6. 创建飞书**频道**，让团队成员也能从群聊中继续查询。

并不是每个场景都需要全部能力。先从助手或智能体开始，只在遇到明确需求时增加技能、MCP、频道或定时任务，配置会更容易维护。

## 推荐学习顺序

1. 配置[模型服务](../pre-basic/providers/)，完成一次普通对话。
2. 通过[资源库](../cherrystudio/preview/library.md)创建助手，熟悉提示词、模型和知识库。
3. 创建[智能体](agent.md)，从受限目录和需要确认的权限开始。
4. 根据任务添加[技能](../pre-basic/settings/skills.md)或 [MCP](mcp/)。
5. 智能体稳定运行后，再配置[定时任务](scheduled-tasks.md)和[频道](agent-channels.md)。
