# MCP 使用教程

MCP（Model Context Protocol）是一种让模型使用外部工具和数据的标准协议。连接 MCP Server 后，Cherry Studio 中的助手或 Agent 可以在回答过程中读取网页、查询数据库、操作文件、调用业务 API，或使用服务端提供的提示词和资源。

## MCP 如何工作

一次典型调用包含以下角色：

| 角色 | 作用 |
| --- | --- |
| 模型 | 判断是否需要工具，并生成工具参数 |
| Cherry Studio | 连接 MCP Server、执行权限检查并展示调用过程 |
| MCP Server | 提供工具、提示词或资源，并执行实际操作 |

大致流程如下：

1. 你向助手或 Agent 提出任务；
2. 模型从已授权的工具中选择一个工具；
3. Cherry Studio 根据服务器和工具权限决定是否需要你确认；
4. MCP Server 执行操作并返回结果；
5. 模型结合结果继续回答。

模型并不是直接“登录电脑或账号”，它通过 MCP Server 提供的接口工作。但 MCP Server 本身可能是本地可执行程序，也可能是远程服务，因此仍需审查来源和权限。

## 常见用途

- 读取和搜索本地文件；
- 获取网页、操作浏览器或调用网络接口；
- 查询知识库、数据库和团队文档；
- 运行 Python 或其他代码；
- 连接笔记、消息、项目管理等在线服务；
- 在明确授权后执行写入、删除或业务操作。

实际能力取决于服务器提供的工具。相同类型的 MCP Server 在权限、数据去向和质量上也可能不同。

## MCP Server 可以提供什么

MCP 不只有“工具”：

- **Tools**：模型可以调用的操作，例如搜索、读取、写入；
- **Prompts**：服务器提供的可复用提示词模板；
- **Resources**：服务器提供的文件、文档或其他上下文资源。

服务器启用后，可以在详情页查看它实际提供了哪些能力。没有提供某类能力时，对应页签可能为空或不显示。

## MCP 与 Skills 的区别

| 对比项 | Skills | MCP |
| --- | --- | --- |
| 核心作用 | 告诉 Agent 如何完成某类任务 | 让模型能够调用外部工具或数据 |
| 主要内容 | 指令、流程和可选资源 | 工具、提示词、资源及连接协议 |
| 是否执行外部操作 | 取决于 Skill 调用的工具 | 通常会连接本地程序或远程服务 |
| V2 使用位置 | 主要用于 Agent | 可用于普通助手和 Agent |

Skill 可以指导 Agent 何时、以什么步骤使用 MCP；MCP 则负责真正执行工具调用。二者可以配合使用。详细说明请参阅 [Skills](../../pre-basic/settings/skills.md)。

## 在 Cherry Studio 中使用 MCP

完整流程是：

1. 在 **设置 → MCP 服务器** 中安装或添加服务器；
2. 填写命令、URL、参数、Header 或环境变量；
3. 启用服务器并检查工具与日志；
4. 在普通助手或 Agent 中添加该服务器；
5. 使用支持工具调用的模型开始任务。

{% hint style="info" %}
只有使用 `uv`、`uvx`、`npx`、`bun` 等本地命令启动的 STDIO 服务器才可能需要额外运行环境。远程服务器和多数内置服务器不需要先安装 UV 或 Bun。
{% endhint %}

详细步骤请参阅 [配置和使用 MCP](config.md)。

## 去哪里找服务器

Cherry Studio 的 MCP 设置提供多个入口：

- **内置服务器**：Cherry Studio 已适配的常用服务器；
- **MCP 市场**：从已接入的市场浏览服务器；
- **服务商**：连接支持的 MCP 服务提供商；
- **从 JSON 或 DXT 导入**：使用开发者提供的配置或扩展包；
- **手动新建**：按官方文档填写 STDIO、SSE 或 Streamable HTTP 配置。

第一次使用建议从[内置 MCP 服务器](builtin.md)开始。它们的配置路径更明确，也更容易验证权限。

## 安全边界

{% hint style="danger" %}
MCP 的工具声明不是安全沙箱。STDIO Server 是在当前用户权限下运行的程序，恶意或被入侵的服务器可能访问其进程权限允许的数据；远程 Server 也会收到你发送给工具的内容。
{% endhint %}

安装或启用服务器前：

- 核对开发者、软件包、下载地址和更新记录；
- 只授权完成任务所需的目录、账号和 API Scope；
- 不把真实密钥写进提示词或共享 JSON；
- 在 **工具**页关闭不需要的工具；
- 对写文件、删除数据、发送消息、创建订单等操作保留人工确认；
- 不再使用时停用或卸载服务器。

自动批准只会减少确认步骤，不会降低工具本身的权限。不要为不熟悉的服务器批量开启自动批准。
