# 智能体工作区记忆

Cherry Studio V2 可以让智能体在同一工作区的多次会话之间保留重要信息。记忆保存在智能体首个可访问目录下的 `memory` 文件夹中，不需要配置全局记忆开关或 Embedding 模型。

该能力用于智能体任务，不会自动把普通对话合并进来。记忆按工作区目录保存，而不是按智能体 ID 另建目录；如果两个智能体使用相同的首个可访问目录，它们会读写同一组记忆文件。

## 使用条件

智能体必须配置可访问目录。第一个可访问目录会作为工作区，记忆文件保存在：

```text
<工作区>/memory/
├── FACT.md
└── JOURNAL.jsonl
```

如果智能体没有可访问目录，工作区记忆无法读写。

## 两类记忆

| 文件 | 保存内容 | 使用方式 |
| :--- | :--- | :--- |
| `FACT.md` | 会长期有效的事实、约定和技术决策 | 智能体会在后续会话中加载，并在事实变化时更新 |
| `JOURNAL.jsonl` | 已完成任务、一次性事件和会话记录 | 按时间追加；需要时由智能体搜索，不会全部加载到上下文 |

判断一条信息是否适合写入 `FACT.md` 时，可以问：“六个月后这条信息仍然重要吗？”如果只是某次任务的过程或结果，更适合写入 Journal。

## 让智能体记住信息

在智能体会话中直接说明需要保留的内容，例如：

> 记住：这个项目统一使用 pnpm，提交前运行 lint 和单元测试。

对于长期规则，可以要求智能体更新持久事实；对于一次性进度，可以要求它记录到 Journal。智能体会通过内置的工作区记忆工具完成写入。

{% hint style="warning" %}
记忆文件位于本地工作区。不要让智能体记录密码、API Key、访问令牌或其他敏感信息。
{% endhint %}

## 在后续会话中使用

使用支持工作区记忆的智能体，并在同一工作区开始新会话时，Cherry Studio 会把 `FACT.md` 中的持久事实提供给智能体。需要查找以前的事件时，可以让智能体搜索 Journal，例如：

> 查一下上周关于发布失败的记录。

搜索可以按文字和标签过滤，并返回最近的匹配记录。

目前，`FACT.md` 的自动加载适用于 Soul Mode 和普通自定义智能体；内置 Cherry Assistant 不会自动加载这部分工作区事实。

## 查看或维护记忆

你可以在工作区中查看 `memory/FACT.md`，了解当前保存了哪些长期信息。更正事实时，优先在会话中告诉智能体更新记忆，让它通过记忆工具安全写入。

`JOURNAL.jsonl` 是逐行 JSON 记录。建议通过智能体搜索，不要手动批量改写。

## 没有记住时

依次检查：

1. 当前智能体是否配置了可访问目录。
2. 当前智能体的首个可访问目录是否仍指向原来的工作区。
3. `memory/FACT.md` 中是否已经写入对应信息。
4. 需要查找的是长期事实还是 Journal 中的一次性记录。

旧版全局记忆与 V2 的智能体工作区记忆是两套独立机制。排查 V2 的记忆内容时，以当前工作区内的 `memory/FACT.md` 和 `memory/JOURNAL.jsonl` 为准。
