# Agent 案例

这里收录的是使用 Cherry Studio 智能体完成真实任务的完整案例。每个案例不仅展示最终结果，还会拆解目标、模型、工作目录、技能、工具权限和验收方法，便于你按自己的场景改造。

如果你还不熟悉助手、智能体、技能和 MCP 的区别，建议先阅读[概念入门](../concepts-101.md)和[智能体使用教程](../agent.md)。

## 阅读案例时关注什么

一个可靠的智能体配置通常包含以下部分：

1. **目标**：说明要解决的问题和最终交付物，避免只有“帮我分析一下”这样的宽泛要求。
2. **输入**：列出允许读取的文件、网页、目录或用户提供的数据。
3. **能力**：选择合适的模型，再按需要启用内置工具、技能或 MCP Server。
4. **权限**：只开放必要目录和工具；写文件、运行命令或访问外部服务时保留确认步骤。
5. **输出**：约定文件格式、保存位置、引用方式和失败时的处理规则。
6. **验收**：检查事实来源、生成文件、关键计算和异常情况，而不只看答案是否“像真的”。

案例正文会尽量沿着这条链路说明配置原因。复刻时可以替换模型或数据源，但不应跳过权限和验收步骤。

## 开始复刻前

### 1. 准备可用模型

智能体的模型选择器只显示支持 **Anthropic Messages** 端点、且不属于 Embedding、Rerank 或图像生成类型的模型。先在[模型服务](../../pre-basic/providers/)中完成配置，并确认模型能正常对话。

模型名称只是配置的一部分。涉及工具调用时，还应先用一个小任务确认所选服务商、端点和模型确实支持当前工作流。

### 2. 建立独立工作目录

为每个案例准备单独目录，并在智能体设置中只添加需要访问的路径。这样更容易查看它创建或修改了哪些文件，也能避免误操作其他项目。

如果案例提供示例文件，请先复制一份再修改；不要直接在唯一原件上运行写入任务。

### 3. 从受限权限开始

首次运行时，优先选择需要确认的工具权限模式。看到工具请求后，先核对：

* 要调用的工具是否与当前步骤有关。
* 读写路径是否位于已授权目录。
* 命令和网络请求是否会产生费用或修改外部数据。
* 输出中是否可能包含 API Key、个人信息或未公开文件。

只有在同一流程已经稳定复现，并且你理解所有副作用后，才考虑减少确认步骤。

### 4. 先跑最小任务

不要一开始就把完整项目交给智能体。可以先要求它：

1. 读取工作目录并列出将使用的文件。
2. 说明计划调用的技能和工具。
3. 只生成一份小型样例或草稿。
4. 展示引用来源和输出文件位置。

样例通过后，再扩大时间范围、数据量或交付物规模。这样能更快发现模型不兼容、路径错误、外部网页失效或权限不足。

## 结果如何验收

不同案例的验收标准会有所区别，但至少应检查：

* **来源可追溯**：关键事实和数据能回到真实来源，链接与发布时间匹配。
* **输入输出一致**：报告使用的是本次获取的数据，而不是模型记忆中的旧信息。
* **文件可打开**：生成的 Markdown、HTML、CSV 或其他文件可以在对应应用中正常打开。
* **失败可见**：请求失败、数据缺失或工具不可用时明确说明，而不是用猜测补齐。
* **范围受控**：没有读取或改动授权目录以外的内容。

{% hint style="warning" %}
案例生成的分析不等于专业意见。涉及金融、医疗、法律或其他高风险决策时，应核对原始资料，并由具备相应资质的人复核。
{% endhint %}
