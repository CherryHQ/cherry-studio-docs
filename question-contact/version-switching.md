# 版本升级与降级

本页适用于 V1 升级 V2、V2 返回 V1，以及手动切换历史版本。请从对应的官方下载页获取安装包：

* [下载 Cherry Studio V2](https://cherryai.com.cn/download/v2)
* [下载 Cherry Studio V1](https://cherryai.com.cn/download/v1)

{% hint style="danger" %}
切换版本有数据丢失风险。正确顺序是：**先在应用内创建备份，再完全退出 Cherry Studio，最后复制整个数据目录**。不要颠倒顺序，也不要让 V1 和 V2 同时读写同一个目录。
{% endhint %}

### 先判断升级路径

| 当前版本                   | 正确路径                               |
| ---------------------- | ---------------------------------- |
| V1 低于 `1.9.12`，或无法确认版本 | 先安装并运行 V1 `1.9.13`，再迁移到 V2         |
| V1 `1.9.12` 或 `1.9.13` | 可以进入 V2 迁移流程；推荐先更新到 V1 `1.9.13`    |
| 已完成 V2 数据迁移            | 可以继续升级后续 V2 版本                     |
| V2 返回 V1               | 只能恢复迁移前保留的 V1 数据，不能把 V2 数据反向转换成 V1 |

代码中的最低迁移门槛是 V1 `1.9.12`，V1 `1.9.13` 也通过检查。由于 V1 官方下载页目前提供 `1.9.13`，旧用户直接先升级到 `1.9.13` 最简单。

### 切换前：按顺序做两份备份

### 1. 先在应用内创建完整备份

1. 保持 Cherry Studio 正常运行，停止正在生成的对话和其他写入操作；
2. 打开 `设置 → 数据`；V1 中该页面可能显示为“数据设置”；
3. 找到“数据备份与恢复”，关闭“精简备份”；
4. 点击 **备份**，把备份文件保存到 Cherry Studio 数据目录之外；
5. 等待界面提示备份成功。

应用内备份不是在退出后创建的。它需要由 Cherry Studio 在运行时生成：V2 会暂停写入、刷新缓存并校验数据库副本的一致性；V1 也会通过设置页复制其持久化存储。

### 2. 再记录并复制整个数据目录

1. 仍在 `设置 → 数据` 中找到“数据目录”，记录完整路径；
2. 完全退出 Cherry Studio，包括系统托盘、macOS 菜单栏和后台进程；
3. 确认程序已退出后，把**整个数据目录**复制到另一个安全位置；
4. 给备份文件和目录副本标注版本与日期，例如 `V1.9.13-迁移前-20260805`。

应用内备份用于恢复，退出后的整目录副本用于保留原始现场。两者用途不同，建议同时保留。

### 备份是否包含 API Key？

包含。根据当前代码：

* V1 `1.9.12` / `1.9.13` 的完整备份会复制 IndexedDB、Local Storage 和 `Data` 目录；模型服务的 API Key 位于被复制的持久化数据中；
* V2 的模型服务 API Key 保存在 SQLite 数据库中，完整备份会复制并校验该数据库，同时备份缓存、IndexedDB、Local Storage 和 `Data` 目录；
* “精简备份”仍会保留核心设置和数据库，但会省略部分文件或浏览器存储。版本切换前应关闭它，创建完整备份。

{% hint style="warning" %}
备份中可能包含 API Key、访问令牌和其他凭据。请把备份文件当作敏感文件保存，不要上传到公开网盘、Issue 或群聊。
{% endhint %}

### 从较早的 V1 升级到 V2

当前代码强制使用下面的迁移链路：

```
较早的 V1
  ↓
V1 1.9.12 或更高版本（推荐 1.9.13）
  ↓
V2 2.0.0 网关版本
  ↓
后续 V2 版本
```

### 第一步：先运行 V1 1.9.13

如果当前版本低于 `1.9.12`，或者数据目录中没有可识别的版本记录：

1. 打开 [V1 官方下载页](https://cherryai.com.cn/download/v1)，下载与当前系统和 CPU 架构匹配的安装包；
2. 安装并启动 V1 `1.9.13`；
3. 确认对话、模型服务、知识库和文件仍然可见；
4. 按上文重新创建一份 V1 `1.9.13` 完整备份；
5. 记录数据目录，然后正常退出。

V1 会在启动时写入 `version.log`。V2 的迁移门会读取该文件：没有版本记录、记录低于 `1.9.12`，都会阻止迁移。因此不能从很早的 V1 直接跳到 V2。

### 第二步：进入 V2.0.0 网关

1. 打开 [V2 官方下载页](https://cherryai.com.cn/download/v2)；
2. 确认页面显示的版本以 `2.0.0` 开头，例如 `2.0.0-rc.x`；代码会把这些官方预发布版本按 `2.0.0` 网关处理；
3. 安装后，在迁移向导中核对数据目录，必须与备份前记录的 V1 路径一致；
4. 路径不一致、外置磁盘未连接或目录不可访问时，立即退出，不要开始迁移；
5. 迁移期间不要关闭窗口、强制结束进程、断开磁盘或让设备休眠；
6. 按提示完成迁移并重启。

首次迁移不能直接跳到 `2.0.1`、`2.1.0` 等更高版本；当前版本策略会直接阻止这种路径。如果 V2 下载页不再提供 `2.0.0` 开头的网关版本，请先停止操作，到 [GitHub Releases](https://github.com/CherryHQ/cherry-studio/releases) 获取官方 V2.0.0 历史版本。

### 第三步：验证后再继续升级

迁移完成后，至少检查：

* 对话及消息是否完整；
* 模型服务、API Key、默认模型是否正常；
* 知识库及其文件是否可访问；
* 笔记、附件和自定义数据目录是否正确。

确认无误并重启一次后，再升级后续 V2 版本。迁移前的 V1 备份和整目录副本不要立即删除。

{% hint style="info" %}
V2 迁移读取的是当前 V1 数据目录，不是导入 V1 备份 ZIP。当前 V2 只接受 V2 备份格式，直接恢复 V1 `1.9.12` / `1.9.13` 创建的备份会被拒绝。V1 备份应留给 V1 自身恢复。
{% endhint %}

### 从 V2 返回 V1

V2 没有自动“降级并反向迁移”功能。V2 中新增或修改的数据不会自动出现在 V1。

1. 在 V2 仍然运行时，进入 `设置 → 数据` 创建完整备份；
2. 记录 V2 数据目录，完全退出后再复制整个目录；
3. 打开 [V1 官方下载页](https://cherryai.com.cn/download/v1)，下载对应系统和架构的 V1 安装包；
4. 只替换程序，不要在卸载时选择“删除用户数据”或“清除配置”；
5. 使用迁移前保留的 V1 数据目录，或在 V1 中恢复**由 V1 创建的备份**；
6. 启动 V1，检查迁移前的数据。

{% hint style="danger" %}
不要把 V2 备份恢复到 V1，也不要用 V2 数据目录覆盖 V1 数据目录。V1 的恢复代码会把带有元数据的备份当作可恢复格式处理，但 V2 的数据结构已经不同，跨版本恢复可能破坏仍可用的 V1 数据。
{% endhint %}

如果必须保留仅存在于 V2 的新内容，请先在 V2 中使用对应功能导出，再单独保存；不要尝试通过复制数据库完成反向迁移。

### 同一大版本内切换历史版本

1. 阅读目标版本与当前版本之间的发布说明；
2. 先创建应用内完整备份，再退出并复制整个数据目录；
3. 从 [GitHub Releases](https://github.com/CherryHQ/cherry-studio/releases) 选择同系统、同架构的目标安装包；
4. 只切换程序文件，不删除用户数据；
5. 首次启动后立即检查数据。出现崩溃、格式不兼容或数据缺失时，退出应用并恢复原程序版本。

即使主版本号相同，较新版本写入的数据也不保证能被较旧版本完整识别。

### 迁移失败时

如果迁移向导白屏、长时间无响应、提示版本链路错误，或 V2 中没有显示原数据：

1. 立即退出 V2，停止继续写入；
2. 不要点击“重置数据”，不要用空目录覆盖旧目录；
3. 保留 V1 原目录、V2 当前目录和两份备份；
4. 检查 V1 是否已运行 `1.9.12` 或 `1.9.13`，以及 V2 是否经过 `2.0.0` 网关；
5. 检查迁移向导中的路径、外置磁盘挂载点和目录权限；
6. 返回 V1 验证原数据仍可读取后，再重新尝试。

默认路径和自定义目录说明见数据存储位置，备份功能说明见数据设置。
