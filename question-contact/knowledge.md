# 知识科普

本页解释 Cherry Studio 中经常出现的 AI 概念。理解这些概念的目的不是记术语，而是知道模型为什么会失败、哪些设置会影响结果，以及数据可能发送到哪里。

## 模型、服务商与接口

### 模型

模型是处理输入并生成输出的计算系统。不同模型可能专注于文本、图片理解、图片生成、Embedding、Rerank、推理或工具调用。

同一个模型名称可能由多个服务商提供。服务商不同，可能意味着：

* Model ID、版本和上下文上限不同。
* 可用地区、价格、限流和账户权限不同。
* 使用 OpenAI、Anthropic、Gemini 或其他接口。
* 图片、工具、推理参数等能力不同。

因此，“模型名称相同”不能证明接口行为相同。使用前应在当前服务商上完成实际测试。

### 服务商

服务商负责提供 API 地址、认证、模型列表、计费和请求限制。Cherry Studio 负责保存连接配置、组织请求和展示结果，但不能替代服务商开通账户、额度或模型权限。

配置入口见[模型服务](../pre-basic/providers/)。

### 接口与端点

接口定义请求和响应的格式。常见端点包括：

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* Ollama Chat

“兼容某接口”通常只表示基础格式相似，不保证实现了该接口的每一项高级能力。智能体还要求模型能够通过 **Anthropic Messages** 端点使用。

## Token 与 Tokenizer

### Token 是什么

Token 是模型处理文本时使用的片段。一个 Token 可能是：

* 一个完整单词。
* 单词的一部分。
* 一个或多个字符。
* 标点、空格或特殊符号。

Token 不等于字数，也不固定等于某种语言中的字符数。

### Tokenizer 是什么

Tokenizer 负责把输入转换成模型使用的 Token 序列。不同模型和版本可能使用不同 Tokenizer，因此同一段文字的 Token 数可以不同。

这会影响：

* 是否超过上下文上限。
* 请求速度。
* 输入与输出费用。
* 长文档如何切分。

Cherry Studio 中显示的 Token 数用于帮助判断上下文规模，最终计费和精确用量以服务商返回为准。

## 上下文窗口

上下文是模型在一次请求中实际收到的信息。它可能包括：

* 系统提示词和助手配置。
* 当前用户消息。
* 被保留的历史消息。
* 图片、文件或网页内容。
* 知识库召回片段。
* 工具定义、调用参数和返回结果。
* 模型需要继续生成的输出空间。

上下文窗口有上限。内容过多时，服务商可能拒绝请求，应用可能截断部分内容，或模型只关注其中一部分。

### 上下文越长越好吗

不一定。更长的上下文会增加费用和等待时间，也可能让无关信息干扰任务。更有效的方法是：

* 不同项目使用不同话题。
* 阶段切换时使用**新上下文**。
* 只附上任务需要的文件。
* 知识库只召回相关片段。
* 把稳定规则放进助手，临时信息放进当前消息。

对话中的话题与上下文操作见[对话界面](../cherrystudio/preview/chat.md)。

## 系统提示词、助手与话题

### 系统提示词

系统提示词用于规定长期角色、行为边界和输出规则。它不能改变模型本身的知识、上下文上限和服务端能力。

系统提示词过长或互相冲突时，会占用上下文并降低可预测性。只保留稳定规则；日期、资料和本次目标放在用户消息中。

### 助手

助手保存一套可重复使用的对话配置，例如：

* 系统提示词。
* 默认模型和参数。
* 上下文数量。
* 知识库。
* 联网搜索和 MCP。

同一个助手可以拥有多个话题。助手配置共用，话题历史彼此独立。完整说明见[助手库](../cherrystudio/preview/assistants.md)。

## Temperature、Top P 与输出参数

Temperature 和 Top P 常用于调整生成的随机性与候选范围，但不同模型和服务商的实现并不完全相同。部分推理模型会忽略、限制或固定这些值。

一般建议：

* 事实抽取、格式转换和代码修改优先保持稳定的默认值。
* 创意写作可以适度增加多样性。
* 不要同时大幅调整多个参数后再判断单个参数效果。
* 参数报错时恢复默认值，并查看当前模型官方说明。

最大输出长度限制模型本次能生成的内容，不会扩大输入上下文。输出突然中断时，应同时检查输出上限、服务商限制和请求是否超时。

## 推理模型

推理模型会在回答前进行额外计算，适合多步分析、数学、规划和复杂代码任务。推理通常意味着更多等待时间或费用。

需要注意：

* 界面显示“思考”不代表所有模型都以相同方式返回推理内容。
* 隐藏推理过程不等于模型没有推理。
* 推理能力强不代表事实一定正确。
* 简单任务不一定需要最高推理强度。

选择模型时，应按任务准确率、速度、价格和工具兼容性共同评估。

## 工具调用

模型本身不能因为“知道某个网站”就自动访问它。工具调用通常包含三个步骤：

1. 应用把可用工具和参数格式告诉模型。
2. 模型返回结构化的工具调用请求。
3. Cherry Studio 或对应 Server 执行工具，再把结果返回模型。

因此，工具失败可能发生在不同位置：

* 模型没有选择工具。
* 模型生成了错误参数。
* 用户拒绝权限。
* 工具程序或远程服务失败。
* 工具结果太大或格式异常。

“模型在文字中说它将搜索”不等于真实调用。应查看消息中的工具记录或[调用链](../advanced-basic/trace.md)。

## 联网搜索

联网搜索可能来自：

* 模型服务商的原生搜索能力。
* Cherry Studio 配置的搜索服务。
* MCP 提供的搜索工具。

搜索通常先返回候选网页，再读取部分内容并交给模型。引用链接存在，不代表它一定支持模型的结论；还要检查发布时间、原始来源和引用内容。

配置方式见[联网模式](../pre-basic/websearch/)。

## 多模态

多模态模型可以处理文本以外的输入，例如图片、音频或文件。不同能力应分别判断：

| 能力 | 说明 |
| :--- | :--- |
| 视觉理解 | 读取图片并回答问题 |
| 图片生成 | 根据提示创建或编辑图片 |
| 文件输入 | 接收 PDF、文档或其他文件 |
| 音频理解 | 接收并分析音频 |

一个模型支持视觉，不代表支持图片生成；能读取图片也不代表能读取所有文件格式。

Cherry Studio 的能力标签用于控制界面和请求路由。手动修改标签不会改变服务商实际接口，应在修改后完成最小测试。

## 幻觉

“幻觉”是指模型生成了流畅但缺少依据、与输入不符或事实错误的内容。常见原因包括：

* 问题缺少关键上下文。
* 模型使用了训练时的旧信息。
* 检索结果不相关或来源不可靠。
* 长上下文中关键信息被忽略。
* 用户要求模型必须给出答案，模型不愿保留空缺。

降低风险的方法：

* 要求来源、日期和输入位置。
* 区分事实、推断和假设。
* 允许回答“不确定”。
* 对关键数据进行人工抽查。
* 高风险决策由专业人员复核。

联网和知识库可以提供新资料，但不会自动消除幻觉。

## Embedding

Embedding 模型把文本转换为一组数字，也就是向量。语义相近的文本在向量空间中通常更接近，因此可以用于相似度检索。

Embedding 模型不是聊天模型。它通常返回向量，不生成自然语言回答。

### 维度

维度是向量中数字的数量。同一知识库建立索引和查询时，需要使用兼容的模型与维度。更换模型或维度后，旧向量通常需要重建。

维度更大不等于一定更准确。还应考虑语言、文本类型、输入上限、速度、费用和实际召回效果。

详见[嵌入模型](../knowledge-base/emb-models-info.md)。

## 分块与向量检索

建立知识库时，长文档会先被分成较小片段，再分别生成向量。

分块过大可能：

* 包含太多主题。
* 超过 Embedding 输入上限。
* 让返回片段占用过多上下文。

分块过小可能：

* 丢失句子之间的关系。
* 生成大量索引和请求。
* 只召回局部词句而缺少解释。

重叠用于保留相邻片段的部分上下文，但会增加索引数量。最佳值取决于文档结构和问题类型，应通过召回测试选择。

## Rerank

向量检索先找出一批候选片段，Rerank 模型再根据当前问题重新排序。它可以改善候选顺序，但不会修复：

* 原文不存在答案。
* 文档提取错误。
* 候选阶段完全没有找回相关片段。
* 最终聊天模型误解了正确片段。

Embedding 与 Rerank 是两种能力，不能互换。

## RAG

RAG 是 Retrieval-Augmented Generation，即“检索增强生成”。在 Cherry Studio 知识库中，可以概括为：

1. 文档提取与分块。
2. Embedding 建立索引。
3. 用户问题生成查询向量。
4. 检索相似片段。
5. 可选的 Rerank 重新排序。
6. 把片段作为上下文交给聊天模型。
7. 聊天模型生成回答。

检索正确但回答错误时，应检查聊天模型和提示词；检索本身错误时，应检查资料、分块、Embedding 和 Rerank。完整流程见[知识库教程](../knowledge-base/knowledge-base.md)。

## MCP

MCP（Model Context Protocol）用于让 AI 应用以统一方式连接外部能力。Server 可以提供：

* **Tools**：执行查询、写入或调用 API。
* **Prompts**：提供可复用提示模板。
* **Resources**：提供可读取的内容。

MCP 是协议，不是安全沙箱。STDIO Server 可能以当前用户权限在本机运行，远程 Server 会接收发送给它的数据。安装前应检查来源、命令、参数、环境变量和访问范围。

使用方法见[MCP](../advanced-basic/mcp/)。

## 技能

技能是一组给智能体使用的任务说明、流程和资源。它主要告诉智能体“怎样完成一类工作”，而 MCP 主要提供“可以调用什么”。

技能本身也可能引用脚本、模板或工具。安装前阅读 `SKILL.md` 和附带文件，只启用可信来源。详见[技能](../pre-basic/settings/skills.md)。

## 助手与智能体

| | 助手 | 智能体 |
| :--- | :--- | :--- |
| 核心用途 | 持续对话和固定配置 | 在目标与权限下执行多步任务 |
| 本地工作目录 | 不提供智能体式目录权限 | 可以限制可访问目录 |
| 文件和命令工具 | 通过特定 MCP 等扩展 | 可使用内置工具、MCP 和技能 |
| 适合场景 | 写作、问答、知识库检索 | 修改文件、运行命令、完成工作流 |

需要判断使用哪一个时，参见[概念入门](../advanced-basic/concepts-101.md)。

## 本地模型与云端模型

### 云端模型

请求会发送到服务商。优点通常包括无需本机部署、模型选择多；需要考虑网络、账户、费用、地区和服务商数据政策。

### 本地模型

模型推理在自己的设备或局域网服务中运行，可以减少模型请求发送到外部，但需要足够的内存、显存、存储和计算能力。

“使用本地模型”不等于整条工作流完全离线。以下环节仍可能访问外部服务：

* 联网搜索。
* 远程 MCP。
* 云端 Embedding 或 Rerank。
* 云端文档处理器。
* 图片生成、频道和第三方集成。

评估隐私时，应沿着完整数据流逐项检查，而不是只看聊天模型的位置。

本地模型配置见 [Ollama](../pre-basic/providers/ollama.md) 和 [LM Studio](../pre-basic/providers/lm-studio.md)。

## 费用从哪里产生

可能产生费用的环节包括：

* 聊天模型输入、输出和推理 Token。
* 图片、音频或文件处理。
* Embedding 和 Rerank 请求。
* 图像生成。
* 搜索、文档处理器、MCP 或其他第三方 API。
* 云存储和网络流量。

同一任务多模型并行、反复重试、长上下文和高频定时任务都会增加用量。Cherry Studio 展示的估算不能替代服务商账单。

## 数据与隐私

在一次工作流中，数据可能经过：

```text
用户输入
→ Cherry Studio
→ 文档处理 / 搜索 / 知识库 / MCP
→ 模型服务商
→ Cherry Studio 展示或本地文件
```

实际路径取决于启用的能力。使用前检查：

* 数据是否离开设备。
* 由哪个服务处理。
* 是否会保存请求或用于训练。
* 凭据保存在何处、权限多大。
* 日志、备份和截图是否包含敏感信息。

不要把 API Key、Token、密码、私钥或不必要的个人数据放进提示词、知识库和文档。高敏感资料应先脱敏，并选择符合组织政策的模型与工具。

## 推荐学习顺序

1. 先理解模型、服务商、Token 和上下文。
2. 在[对话界面](../cherrystudio/preview/chat.md)完成一个小任务。
3. 使用助手保存稳定提示词。
4. 创建知识库并进行召回测试。
5. 需要外部工具时再学习 MCP。
6. 需要本地文件与多步执行时再使用智能体和技能。

遇到概念之外的实际故障，请从[常见问题](questions.md)开始排查。
