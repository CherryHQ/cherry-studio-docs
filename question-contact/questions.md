# 常见问题

本页用于快速判断问题属于哪一类，并进入对应专题。遇到故障时，先保留原始错误和数据，不要一开始就重装、重置数据或删除应用目录。

## 先做五项检查

1. 在 **设置 → 关于**记录 Cherry Studio 完整版本号。
2. 记录操作系统、芯片架构和问题发生时间。
3. 保存界面显示的完整错误，不要只写“不能用”。
4. 用一个新对话、一个小文件或一个简单工具缩小问题范围。
5. 判断是所有模型都失败，还是只有某个服务商、模型或功能失败。

如果问题在升级后出现，还应记录升级前版本和是否迁移过数据目录。

{% hint style="warning" %}
重置数据会清空本地数据库和应用管理的文件，不是通用修复步骤。没有可用备份时不要使用；清除缓存也不能修复账户、模型或 API 配置错误。
{% endhint %}

## 应用无法安装或启动

### 安装包无法打开

确认下载的系统与架构正确：

* Apple Silicon Mac 使用 arm64 包，Intel Mac 使用 x64 包。
* Windows 和 Linux 也要选择与设备架构匹配的版本。
* 安装包应来自[客户端下载](../cherrystudio/download.md)或官方 Release。

macOS 出现“无法验证开发者”或文件损坏提示时，按[macOS 安装教程](../cherry-studio/installation/macos.md)处理，不要从不明来源下载重新签名的安装包。

### 启动后白屏、布局错乱或按钮消失

如果使用过自定义 CSS，先参考[清除 CSS 设置](../pre-basic/personalization-settings/clear-css.md)。错误选择器可能遮挡设置入口，但删除整个数据目录会同时丢失其他内容。

没有使用自定义 CSS 时，记录版本和系统，重启后再次复现。仍然出现时，保留日志并提交反馈。

### 更新后像全新安装

先检查是否修改过应用数据目录、外接磁盘是否在线，以及启动时是否选择了新的空目录。不要立即在新目录中产生大量数据，也不要删除旧目录。参见[修改存储位置](../pre-basic/personalization-settings/storage.md)。

## 模型服务

### API Key 保存后仍无法使用

依次确认：

1. 服务商开关已启用。
2. API Key 属于当前服务商和当前区域，没有多余空格。
3. API 地址使用该服务商要求的根路径和接口类型。
4. 账户已开通目标模型，且余额、配额或计费方式可用。
5. 模型已同步或手动添加，并在模型列表中启用。

连接检查成功通常只说明一次基础请求可达，不代表视觉、推理、工具调用、Embedding 或图像生成都可用。每项能力都应单独测试。

通用配置见[模型服务](../pre-basic/providers/)，各模板入口见[全部 Provider 快速参考](../pre-basic/providers/quick-reference.md)。

### 无法获取模型列表

部分兼容服务不提供标准模型列表，或只返回账户有权访问的模型。先核对 Base URL、凭据、区域和代理；服务商允许手动 Model ID 时，可以按其官方文档添加。

不要从其他平台复制“看起来相同”的 Model ID。命名空间、大小写和版本后缀都可能不同。

### 模型在服务商页面可见，但对话中找不到

模型必须同时满足：

* 所属服务商已启用。
* 模型本身已启用。
* 模型类型适合当前入口。

Embedding、Rerank 和图像生成模型不会作为普通聊天模型显示。智能体还要求模型通过 **Anthropic Messages** 端点可用。

### 常见 HTTP 状态码

不同服务商的错误定义可能不同，应以返回正文和服务商文档为准。

| 状态码 | 常见方向 | 优先检查 |
| :--- | :--- | :--- |
| `400` | 请求参数、上下文或内容格式无效 | 模型端点、附件、上下文长度、自定义参数 |
| `401` | 身份认证失败 | API Key、Authorization 方式、Key 是否过期 |
| `403` | 账户、模型、区域或内容权限不足 | 模型授权、计费、地区、组织权限 |
| `404` | 路径、部署或模型不存在 | Base URL、Deployment、Model ID、接口类型 |
| `408` / `504` | 请求或上游超时 | 网络、代理、服务状态、输入规模 |
| `413` | 请求体过大 | 图片和文件大小、上下文、批量输入 |
| `422` | 参数可解析但无法处理 | 字段类型、必填值、模型专用参数 |
| `429` | 频率、Token 或额度限制 | RPM/TPM、余额、并发数、稍后重试 |
| `500` / `502` / `503` | 上游内部错误、网关或过载 | 服务状态、代理、换小请求后重试 |

错误只在某个模型出现时，先换同一服务商的另一个基础文本模型测试；所有服务商都失败时，再检查本机网络和代理。

## 对话

### 发送后没有回复

检查消息上方显示的实际模型和服务商。多模型对话中，一个模型失败不代表其他模型也失败；分别查看每条响应的错误。

可以新建一个默认助手和空对话，只发送短文本：

```text
请回复：连接正常
```

小请求成功、原对话失败时，问题更可能来自上下文长度、附件、工具或助手自定义参数。详细操作见[对话界面](../cherrystudio/preview/chat.md)。

### 上下文过长或请求体过大

减少历史消息、关闭不需要的上下文、移除大附件，或新建对话。清除上下文只影响后续发送给模型的历史范围，不等于删除界面中的所有消息。

### 无法上传图片或模型不能识图

确认模型具有视觉能力标签，并且当前服务商端点实际接受图片。手动勾选能力只会改变 Cherry Studio 的界面筛选和请求路由，不会让服务端获得原本没有的能力。

多模型对话上传图片时，所有被提及的模型都应支持图片输入。

### 公式显示为源码

先确认模型输出了完整定界符：

* 行内公式：`$...$` 或 `\(...\)`
* 独立公式：`$$...$$` 或 `\[...\]`

如果定界符被代码块包裹、转义不完整或模型输出被截断，公式不会按数学内容渲染。先查看原始消息，再判断是否属于显示问题。

## 网络与代理

### 浏览器能访问，Cherry Studio 不能

系统浏览器和 Electron 应用可能使用不同代理、证书或登录状态。打开[常规设置](../pre-basic/settings/general.md)，核对代理模式、代理地址和是否需要重启。

还应检查：

* 公司网络或防火墙是否拦截目标域名。
* HTTPS 证书是否被代理替换。
* 系统时间是否正确。
* 服务是否限制地区或必须登录。

不要通过关闭系统安全软件或忽略证书错误来长期解决连接问题。

### 开启代理后所有请求都失败

暂时切回系统代理或无代理进行对比。手动代理需要正确的协议、主机和端口；HTTP、HTTPS、SOCKS 不能只按端口相同就互换。

## 知识库

### 无法创建知识库或获取维度失败

创建前需要可用的 Embedding 模型。检查：

1. 选择的确实是 Embedding，而不是普通聊天模型。
2. 服务商、API Key、Base URL 和 Model ID 正确。
3. 该模型能完成一次真实的嵌入请求。
4. 模型返回的向量维度与配置一致。

详细排查见[嵌入模型](../knowledge-base/emb-models-info.md)。

### 文件一直处理中或显示失败

先等待当前队列结束，再查看失败状态。常见原因包括文件无法读取、网页不可访问、文档处理器失败、Embedding 请求失败或触发限流。

修复配置后，对失败资料执行重新索引。知识库完整流程见[知识库教程](../knowledge-base/knowledge-base.md)。

### 聊天回答不准确

先使用召回测试检查是否找到了正确片段：

* 召回错误：调整资料、分块、Embedding 或 Rerank。
* 召回正确但回答错误：再检查聊天模型、提示词和上下文。

知识库只提供检索片段，最终回答仍由聊天模型生成。

## 智能体

### 模型没有出现在智能体选择器

智能体要求模型的端点类型包含 **Anthropic Messages**，并排除 Embedding、Rerank 和图像生成模型。检查服务商端点和能力标签，再用简单工具任务验证实际兼容性。

### 智能体页面提示服务未运行

先点击页面中的启动按钮。仍失败时，打开 **设置 → API 服务器**，检查端口和运行状态。端口被其他程序占用时需要停止冲突进程或改用可用端口。

### 智能体读不到文件或不能写入

检查目标目录是否加入可访问路径、工具是否启用、权限请求是否批准。不要把整个用户目录或磁盘加入可访问路径来绕过错误。

更多排查见[智能体](../advanced-basic/agent.md)和[API 服务器](../advanced-basic/api-server.md)。

## MCP

### Server 无法启动

本地 STDIO Server 优先检查 Command、Arguments、运行环境和工作目录；远程 Server 优先检查 URL、Headers、认证和协议类型。

打开 Server 详情中的**查看日志**，关闭后重新启用一次，更容易找到第一条启动错误。完整清单见[MCP 常见问题](../advanced-basic/mcp/faq.md)。

### 已连接但没有工具

连接成功不代表 Server 一定提供 Tools。它也可能只提供 Prompts 或 Resources。检查 Server 详情中的能力列表，以及日志中是否存在初始化或 `listTools` 错误。

### 模型只描述工具，但没有调用

确认：

* 当前助手或智能体已绑定该 MCP Server。
* Server 已启用且目标工具可见。
* 当前模型和端点支持工具调用。
* 工具审批没有被拒绝。

## 数据、备份与恢复

### 自动备份没有生成

检查周期不是“关闭”、目标目录或远程服务在线，并查看页面显示的最近错误。外接磁盘、NAS 和远程存储还要确认空间、权限和连接状态。

### 恢复后缺少图片或知识库文件

如果备份时启用了**精简备份**，应用 `Data` 目录中的图片和知识库文件会被跳过。这是预期行为，不能从精简备份恢复被排除的文件。

### 多台电脑的数据没有自动合并

备份与恢复是覆盖式流程，不是实时双向同步。恢复前比较版本和时间，并先备份当前设备。

详细说明见[数据设置](../pre-basic/data-settings/)。

## 获取日志

进入 **设置 → 数据设置 → 数据**，在**应用日志**一项打开日志目录。复现问题后，按发生时间找到对应文件。

提交前删除或遮盖：

* API Key、Token、Cookie 和认证 Header。
* 对话、提示词、知识库与文件内容。
* 邮箱、用户名、个人目录和内网地址。
* 第三方服务的请求或返回数据。

日志可能跨多行记录同一个错误。保留错误前后的必要上下文，但不要公开上传整个应用数据目录或备份文件。

## 提交反馈时提供什么

一个可处理的问题至少包含：

```text
Cherry Studio 版本：
操作系统与架构：
服务商与模型（如相关）：
问题发生时间：
预期结果：
实际结果：
最小复现步骤：
完整错误：
已尝试的操作：
脱敏日志或截图：
```

先阅读[如何高效提问](ask.md)，再通过[反馈与建议](suggestions.md)中的渠道提交。涉及崩溃或数据问题时，说明是否有备份、是否迁移过数据目录以及问题发生后是否继续写入。
