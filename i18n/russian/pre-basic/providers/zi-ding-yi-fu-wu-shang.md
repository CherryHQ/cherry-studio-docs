# Пользовательский провайдер

Пользовательский провайдер позволяет подключить облачную платформу, OpenAI-совместимый прокси, шлюз локальной сети или самостоятельно размещенный сервис моделей, которые еще не встроены в Cherry Studio.

Cherry Studio V2 предлагает два способа создания:

| Способ | Сценарий использования | Основные особенности |
| --- | --- | --- |
| Добавить пользовательского провайдера | Новая платформа, OpenAI-совместимый сервис, локальный сервис инференса | По умолчанию основным протоколом диалога является OpenAI Chat Completions |
| Добавить экземпляр предустановленного провайдера | Второй аккаунт, регион, шлюз или частный адрес того же поставщика | Сохраняет способ аутентификации, протокол по умолчанию и специальную адаптацию исходного провайдера |

{% hint style="info" %}
Если для целевой платформы уже есть предустановленный провайдер, сначала добавьте еще один его экземпляр. Полностью пользовательский провайдер предназначен для стандартных совместимых интерфейсов и не получает автоматически специальную аутентификацию, задачи изображений или адаптацию параметров конкретного поставщика.
{% endhint %}

## Подготовка к работе

Перед созданием уточните в официальной документации целевого сервиса:

1. Какой протокол API используется.
2. Base URL, а не адрес веб-консоли.
3. API Key или другой способ аутентификации.
4. Доступен ли интерфейс списка моделей.
5. Полный Model ID нужной модели.
6. Поддерживает ли модель компьютерное зрение, рассуждение, инструменты, Embedding или Rerank.
7. Требуются ли дополнительные заголовки запроса.
8. Есть ли требования к списку разрешенных IP-адресов, прокси или сертификатам.

Одной «совместимости интерфейса» недостаточно. Поля ответа, потоковый формат, вызов инструментов, содержимое рассуждения и структура ошибок также должны быть совместимы с выбранным протоколом.

## Выбор способа создания

### Добавление полностью пользовательского провайдера

Подходит для:

- OpenAI-совместимых облачных сервисов;
- единых шлюзов, таких как OneAPI и NewAPI;
- самостоятельно размещенных сервисов, таких как vLLM и LocalAI;
- совместимых прокси внутри организации;
- платформ, которых еще нет в списке предустановленных.

Основной конечной точкой полностью пользовательского провайдера V2 по умолчанию является:

```text
OpenAI Chat Completions
```

При создании больше не используется раскрывающийся список типов провайдера «OpenAI / Gemini / Anthropic / Azure OpenAI» из старой версии.

### Добавление экземпляра предустановленного провайдера

Подходит, если:

- для одного провайдера используются несколько независимых аккаунтов;
- в разных регионах используются разные Base URL;
- одновременно используются корпоративный прокси и официальный адрес;
- требуется сохранить специальную аутентификацию Azure, Vertex AI, Bedrock и других сервисов;
- требуется сохранить специальную адаптацию изображений, рассуждения или синхронизации моделей провайдера.

Нажмите **Добавить экземпляр** в группе предустановленного провайдера либо откройте меню провайдера и выберите то же действие. После создания нового экземпляра укажите собственные данные аутентификации и адрес.

{% hint style="warning" %}
При копировании предустановленного провайдера копируется только структура конфигурации, но не конфиденциальные учетные данные исходного экземпляра. После создания заново заполните данные аутентификации на странице нового экземпляра.
{% endhint %}

## Добавление полностью пользовательского провайдера

1. Откройте `Настройки → Провайдеры моделей`.
2. При необходимости переключите фильтр на **Все провайдеры**.
3. Нажмите `+` справа от поля поиска провайдера.
4. Укажите понятное имя провайдера.
5. Выберите встроенный значок или загрузите собственный.
6. Укажите основной Base URL.
7. При необходимости укажите первый API Key.
8. Если платформа также предоставляет другие совместимые протоколы, разверните раздел **Дополнительные конечные точки**.
9. Нажмите **Добавить**.
10. Продолжите настройку моделей на странице нового провайдера.

Имя влияет только на отображение и не меняет протокол запроса. Рекомендуется включить в имя платформу, регион или назначение, например «Внутренний шлюз — Москва».

## Указание Base URL

Base URL — корневой адрес интерфейса, а не полный адрес запроса.

Пример для OpenAI Chat Completions:

```text
Правильно: https://api.example.com/v1
Неправильно: https://api.example.com/v1/chat/completions
Неправильно: https://console.example.com/models
```

V2 добавляет конкретный путь запроса в зависимости от типа конечной точки. Необходимость `/v1`, `/v1beta` или пользовательского пути определяйте по официальной документации целевого сервиса.

{% hint style="warning" %}
Не копируйте «адрес прокси» из другого клиента, пока не убедитесь, что там требуется именно Base URL. Для одной платформы разные инструменты могут запрашивать корневой адрес или полный адрес запроса.
{% endhint %}

### Адрес локального компьютера и локальной сети

Распространенный адрес локального сервиса:

```text
http://127.0.0.1:8000/v1
```

Если сервис работает в Docker, виртуальной машине или на другом компьютере, `localhost` может указывать на другое устройство. Используйте адрес, доступный с компьютера, на котором работает Cherry Studio, и проверьте межсетевой экран и сетевой интерфейс прослушивания.

При использовании самоподписанного сертификата HTTPS подключение также может блокироваться системной проверкой сертификатов. Не отключайте проверку безопасности на всем компьютере только для решения проблемы с сертификатом.

## Настройка дополнительных конечных точек

На странице создания полностью пользовательского провайдера можно дополнительно указать:

- Anthropic Messages;
- Google Gemini;
- OpenAI Responses.

После создания также можно открыть **Настройки запроса** справа от API Host и добавить или изменить конечные точки.

Эти адреса описывают входы разных протоколов одного провайдера. Они не превращают модель, поддерживающую только OpenAI, автоматически в модель Anthropic или Gemini.

Для обычной пользовательской модели, добавленной вручную, основным протоколом остается конечная точка провайдера по умолчанию. Если обязательно требуется протокол или специальная аутентификация конкретного поставщика, добавьте экземпляр соответствующего предустановленного провайдера.

## API Key и несколько Key

Первый API Key можно указать при создании или оставить поле пустым и настроить его позже.

На странице провайдера можно:

- добавить несколько Key;
- добавить к Key понятную метку;
- приостановить отдельный Key;
- удалить недействительный или скомпрометированный Key.

Для запросов используются только включенные Key. Наличие у нескольких Key доступа к одинаковым моделям, балансу и правам организации по-прежнему определяется сервером.

{% hint style="danger" %}
Не добавляйте реальный API Key в документы, чаты, публичные репозитории, снимки экрана и примеры пользовательских заголовков. При утечке немедленно отзовите его на сервере.
{% endhint %}

Для локального сервиса без аутентификации Key можно не указывать. Не вводите рабочие учетные данные произвольно только для прохождения формы.

## Пользовательские заголовки запроса

Нажмите кнопку настроек запроса справа от API Host, чтобы добавить заголовки в виде списка или JSON.

Распространенные сценарии:

- идентификатор организации или проекта;
- заголовок тенанта корпоративного шлюза;
- заголовок версии, требуемый прокси;
- пользовательский заголовок аутентификации, явно требуемый сервером.

Перед заполнением учитывайте:

1. Добавляйте только поля, явно требуемые официальной документацией.
2. Не переопределяйте `Content-Type` повторно.
3. Не настраивайте конфликтующие значения `Authorization` одновременно в API Key и пользовательском заголовке.
4. В режиме JSON необходимо указать объект.
5. Значения объекта отправляются как строки.
6. После изменения повторно проверьте подключение.

Заголовки отправляются по целевому адресу вместе с соответствующими запросами. Не передавайте конфиденциальные заголовки ненадежному прокси.

## Включение провайдера

После создания:

1. Выберите нового провайдера.
2. Проверьте API Key и API Host.
3. Включите провайдера.
4. Синхронизируйте или вручную добавьте модели.
5. Включите только необходимые модели.
6. Запустите проверку работоспособности.

Если провайдер не включен, добавленные модели не будут корректно отображаться в соответствующих списках выбора.

## Синхронизация моделей

Для OpenAI-совместимого сервиса V2 по умолчанию пытается получить:

```text
GET {Base URL}/models
```

Если целевой сервис правильно реализует интерфейс списка моделей, Cherry Studio покажет предварительный результат синхронизации. Перед применением проверьте:

- новые модели;
- обновляемые модели;
- модели, удаленные с сервера;
- Model ID и отображаемое имя;
- правильно ли распознаны возможности модели.

Неудачная синхронизация не означает, что интерфейс диалога обязательно не работает. Некоторые сервисы реализуют только Chat Completions, но не `/models`; в таком случае добавьте модель вручную.

## Добавление модели вручную

1. Нажмите **Добавить модель** в списке моделей.
2. Укажите полный Model ID, требуемый сервером.
3. При необходимости задайте более понятное отображаемое имя и группу.
4. Укажите контекст и максимальный вывод по официальной спецификации.
5. Выберите возможности, которые модель действительно поддерживает.
6. Сохраните и включите модель.
7. Запустите проверку работоспособности.

Вручную можно отметить:

- понимание изображений;
- веб-поиск;
- рассуждение;
- вызов инструментов;
- Embedding;
- Rerank.

Метки возможностей используются для фильтрации в интерфейсе и маршрутизации запросов, но не меняют возможности сервера. Неверная метка может привести к ошибке запроса либо ошибочному отображению модели Embedding или Rerank в списке диалогов.

{% hint style="warning" %}
Model ID должен полностью совпадать с сервером. Отображаемое имя можно изменить, но оно не заменяет Model ID в запросе.
{% endhint %}

## Проверка подключения и работоспособности модели

Рекомендуется проверять поэтапно:

1. Сначала проверьте подключение провайдера.
2. Затем проверьте отдельную диалоговую модель.
3. Отдельно проверьте потоковый вывод.
4. Отдельно проверьте компьютерное зрение, рассуждение и вызов инструментов.
5. Фактически проверьте Embedding и Rerank в базе знаний.

Общая проверка работоспособности в текущей версии V2 пропускает модели Rerank, поэтому Rerank необходимо проверять в процессе поиска по базе знаний.

Успешная проверка подключения не гарантирует, что:

- есть доступ ко всем моделям;
- на балансе достаточно средств;
- компьютерное зрение или вызов инструментов доступны;
- длинный контекст обязательно сработает;
- все дополнительные параметры сервера совместимы.

## Границы OpenAI-совместимых возможностей

Полностью пользовательский провайдер может использовать стандартные OpenAI-совместимые возможности:

- Chat Completions;
- потоковый вывод;
- ввод изображений;
- Function Calling;
- Embeddings;
- стандартный список моделей.

Доступность зависит от сервера и конкретной модели. Следующие возможности обычно нельзя получить автоматически только за счет «совместимости с OpenAI»:

- нативные асинхронные задачи изображений поставщика;
- специальная загрузка файлов;
- облачная база знаний;
- особые параметры рассуждения;
- нестандартный Rerank;
- OAuth, IAM или подпись облачного аккаунта;
- собственная классификация моделей при синхронизации.

Если провайдеру требуются эти возможности, используйте предустановленную адаптацию или специальную документацию.

## Создание локального провайдера с vLLM

vLLM предоставляет OpenAI-совместимый сервер. Сначала ознакомьтесь со способом установки и требованиями к оборудованию в [официальной документации vLLM](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/).

Запустите сервис с моделью, поддерживающей шаблон диалога:

```sh
vllm serve NousResearch/Meta-Llama-3-8B-Instruct \
  --dtype auto \
  --api-key local-test-token
```

Порт прослушивания по умолчанию — `8000`. Добавьте в Cherry Studio полностью пользовательского провайдера:

```text
Имя провайдера: vLLM Local
Base URL: http://127.0.0.1:8000/v1
API Key: local-test-token
```

Затем синхронизируйте `/v1/models` или вручную добавьте Model ID, возвращенный vLLM.

{% hint style="info" %}
Приведенный Key предназначен только для локального примера. При развертывании в локальной сети или интернете используйте надежные учетные данные, контроль доступа, TLS и межсетевой экран. Не открывайте напрямую порт инференса без аутентификации.
{% endhint %}

Если возвращается сообщение об отсутствии chat template, используйте модель с шаблоном диалога или настройте `--chat-template` по документации vLLM.

## PDF, вложения и конфиденциальность

Для обычной диалоговой модели Cherry Studio сначала извлекает текст PDF локально, а затем отправляет его серверу:

- текстовые PDF обычно можно обработать;
- для отсканированных документов требуется OCR;
- таблицы, сложное форматирование и сведения из изображений могут быть потеряны;
- извлеченный текст расходует контекст;
- для изображений из PDF требуется визуальная модель.

Base URL пользовательского провайдера определяет, куда в конечном итоге отправляются данные. Перед подключением прокси или корпоративного шлюза проверьте:

- личность оператора;
- политику хранения данных;
- правила журналирования и обучения;
- трансграничную передачу;
- TLS и сертификаты;
- требования организации к соответствию нормам.

## Частые проблемы

### Возвращается 401

API Key неверен, формат заголовка аутентификации несовместим или пользовательский заголовок запроса переопределил правильный `Authorization`. Сверьтесь с инструкцией по аутентификации сервера.

### Возвращается 403

У Key нет доступа к модели или проекту, IP отсутствует в списке разрешенных либо политика организации отклоняет запрос.

### Возвращается 404

Обычно в Base URL указан полный адрес запроса, отсутствует путь версии или на сервере нет соответствующего интерфейса. Отдельно проверьте `/models` и `/chat/completions`.

### Возвращается 400

Модель не поддерживает текущие параметры, формат сообщения, изображение, рассуждение или вызов инструментов. Сначала проверьте обычный текст с параметрами по умолчанию.

### Возвращается 429

Достигнуто ограничение запросов, Token или параллельности на сервере. Уменьшите параллельность и повторяйте запросы с увеличивающейся задержкой.

### Синхронизация моделей возвращает пустой результат

Целевой сервис может не реализовывать `/models` или этот интерфейс требует других прав. Проверьте адрес и добавьте Model ID вручную.

### Диалог работает, но изображение не обрабатывается

Обычная текстовая модель не обязательно поддерживает компьютерное зрение. Проверьте возможности модели и формат сообщения с изображением на сервере.

### Модель только описывает инструмент, но не вызывает его

Модель может не поддерживать Function Calling либо формат ответа несовместим. Сначала проверьте структурированный вызов с одним простым инструментом.

### Embedding отображается в списке диалогов

Неверно задан тип модели. Измените модель, включите возможность Embedding и отключите отсутствующую возможность диалога.

### Rerank не проходит проверку работоспособности

Общая проверка работоспособности пропускает Rerank. Настройте модель в базе знаний и фактически выполните поиск.

### Локальный сервис открывается в браузере, но Cherry Studio не подключается

Открытие корневой страницы в браузере не означает, что API доступен. Проверьте `/v1/models`, межсетевой экран, адрес прослушивания, прокси, самоподписанный сертификат и шаблон диалога.

### Добавлены адреса Anthropic или Gemini, но модель продолжает использовать OpenAI

Основная конечная точка полностью пользовательского провайдера по умолчанию — OpenAI Chat Completions. Одного заполнения дополнительной конечной точки недостаточно, чтобы обычная добавленная вручную модель гарантированно переключила протокол. Если требуется протокол конкретного поставщика, добавьте экземпляр предустановленного провайдера.

Общие настройки описаны в разделах [Провайдеры моделей](README.md) и [Настройки провайдеров моделей](../../cherrystudio/preview/settings/providers.md), а интерфейс vLLM — в [OpenAI-Compatible Server](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/). Каналы обратной связи указаны в разделе [Обратная связь и предложения](../../question-contact/suggestions.md).
