# NewAPI

NewAPI — это единый шлюз больших языковых моделей. На стороне сервера он подключается к вышестоящим каналам OpenAI, Anthropic, Google и других провайдеров, а Cherry Studio предоставляет единый список моделей, авторизацию, маршрутизацию и интерфейс оплаты.

В Cherry Studio V2 встроен специальный тип провайдера **New API**, поэтому его больше не нужно маскировать под обычного провайдера OpenAI. Этот специальный тип позволяет для каждой модели выбрать конечную точку OpenAI Chat Completions, OpenAI Responses, Anthropic Messages, Google Generate Content, генерации изображений или повторного ранжирования.

{% hint style="warning" %}
Запросы проходят через экземпляр NewAPI и настроенные в нём вышестоящие каналы. Используйте только развёрнутый вами сервис либо заведомо надёжный сервис, у которого есть законные права на вышестоящие сервисы и ответственность за соблюдение требований. Не передавайте конфиденциальные данные и API Key неизвестным общедоступным экземплярам.
{% endhint %}

## Сначала определите свою роль

Подготовка обычного пользователя и администратора NewAPI различается:

| Роль | Что нужно сделать в NewAPI |
| --- | --- |
| Обычный пользователь | Создать токен, проверить квоту, группу, разрешения моделей и ограничения IP |
| Администратор | Сначала настроить и проверить вышестоящие каналы, сопоставление моделей, группы и оплату, а затем выдать токены пользователям |

Если вы только используете экземпляр, который обслуживает другой человек, не вводите в Cherry Studio ключ вышестоящего провайдера. Введите только пользовательский токен, выданный этим экземпляром NewAPI.

## Создание токена в NewAPI

1. Войдите в надёжный экземпляр NewAPI.
2. Откройте страницу **Токены**.
3. Создайте отдельный токен для Cherry Studio.
4. При необходимости настройте квоту, срок действия, ограничения моделей, группу и белый список IP.
5. Скопируйте токен и сохраните его в безопасном месте.
6. Сначала проверьте одну модель во встроенном Playground NewAPI.

Рекомендуется создавать отдельные токены для разных устройств и задач. При утечке можно будет отозвать только затронутый токен, а расход будет проще проверить.

{% hint style="danger" %}
Не помещайте токен NewAPI в сообщения чата, документацию, репозиторий кода или снимки экрана с описанием проблемы. Если токен раскрыт, немедленно удалите его в консоли NewAPI и создайте новый.
{% endhint %}

## Получение правильного адреса API

Предпочтительно скопируйте API Base URL с главной страницы NewAPI или уточните его у администратора экземпляра. Распространённые форматы:

| Способ развёртывания | Пример |
| --- | --- |
| Домен HTTPS | `https://newapi.example.com` |
| С путём версии | `https://newapi.example.com/v1` |
| Локальное развёртывание | `http://localhost:3000` |
| IP в локальной сети | `http://192.168.1.20:3000` |

Cherry Studio добавляет `/v1` к обычному адресу NewAPI, но не добавляет его повторно, если адрес уже содержит `/v1`. Поэтому можно указать корневой адрес сайта или стандартный Base URL с `/v1`.

- `http` и `https` должны соответствовать фактической конфигурации сервера.
- Общедоступный экземпляр должен использовать действительный сертификат HTTPS.
- `/console/...` в административной веб-странице — не API Base URL.
- Не вводите в Base URL страницу токенов, страницу входа или конкретный путь `/chat/completions`.

## Настройка New API

1. Откройте `Настройки → Провайдеры моделей`.
2. Переключите фильтр слева на **Все поставщики**.
3. Выберите встроенный **New API**.
4. Введите токен, выданный NewAPI.
5. Измените Base URL на адрес API экземпляра.
6. Включите провайдера переключателем в верхней части страницы.
7. Нажмите **Добавить**, чтобы синхронизировать список моделей.
8. Проверьте модели и типы конечных точек, затем примените изменения.
9. Включите только те модели, которые собираетесь использовать.

Адрес встроенного шаблона по умолчанию — `http://localhost:3000`; он подходит только для стандартного локального развёртывания. При подключении к удалённому экземпляру обязательно замените его фактическим адресом.

Если администратор NewAPI настроил ссылку импорта в Cherry Studio одним нажатием, с её помощью можно заранее заполнить адрес и токен. Перед импортом всё равно проверьте целевой домен, чтобы вредоносная ссылка не отправила ключ на другой сервер.

## Типы конечных точек

В NewAPI одно имя модели может поддерживать один или несколько протоколов. Cherry Studio выбирает реализацию запроса в соответствии с типом конечной точки модели:

| Тип конечной точки Cherry Studio | Типичное назначение |
| --- | --- |
| OpenAI Chat Completions | Большинство моделей чата с совместимостью OpenAI |
| OpenAI Responses | Модели OpenAI с нативной поддержкой Responses API |
| Anthropic Messages | Claude или другие модели с нативной совместимостью Messages |
| Google Generate Content | Нативный протокол Gemini |
| OpenAI Image Generation | Модели генерации и редактирования на странице рисования |
| Jina Rerank | Модели повторного ранжирования базы знаний |

Новые экземпляры NewAPI в ответе `/models` возвращают `supported_endpoint_types`; Cherry Studio считывает эти сведения при синхронизации.

Если сервер не возвращает метаданные конечной точки:

- При пакетном добавлении выберите тип конечной точки, общий для всех моделей в этой группе.
- Добавляйте модели с разными протоколами отдельными группами.
- При ручном добавлении модели выберите хотя бы один тип конечной точки.
- Выбирайте только протокол, который действительно поддерживает экземпляр NewAPI.
- Не делайте вывод только по названию модели.

Неверный тип конечной точки может привести к ошибке 404, несовместимым параметрам, потере вызовов инструментов или сбою запроса изображения. Наличие модели в списке не означает, что доступны все протоколы.

## Администратору: сначала проверьте каналы и сопоставление моделей

Если вы обслуживаете экземпляр NewAPI, перед подключением пользователей через Cherry Studio проверьте следующее:

1. Каждый вышестоящий канал прошёл проверку канала NewAPI.
2. Выбранные в канале модели соответствуют фактическим разрешениям.
3. В сопоставлении моделей используется ID модели, который будет запрашивать клиент.
4. Группа пользовательского токена имеет доступ к соответствующему каналу.
5. Проверены коэффициенты оплаты, квоты и политика автоматического отключения.
6. `/v1/models` возвращает модели в соответствии с разрешениями пользователя.
7. Отдельно проверены конечные точки Chat, Responses, Messages, Gemini и изображений.

Сопоставление моделей преобразует имя из запроса Cherry Studio в имя вышестоящей модели. Если проверка состояния сообщает, что модель не существует, одновременно проверьте ID модели в Cherry Studio, сопоставление в NewAPI и фактический ID в вышестоящем канале.

## Чат, мышление и вызов инструментов

NewAPI — только слой маршрутизации. Итоговые возможности зависят от вышестоящей модели, типа канала, преобразования протокола и версии экземпляра.

- Параметр мышления должен соответствовать целевой модели и типу конечной точки.
- Для нативных возможностей Claude предпочтительно используйте Anthropic Messages.
- Для нативных возможностей OpenAI Responses предпочтительно используйте OpenAI Responses.
- Для нативных возможностей Gemini предпочтительно используйте Google Generate Content.
- Для MCP необходимо, чтобы модель, вышестоящий сервис и слой преобразования сохраняли поля инструментов.
- При сбое многоэтапного вызова инструментов сначала проверьте один инструмент.

Работа модели в обычном чате не гарантирует полноту содержимого мышления, вызова инструментов, веб-поиска или структурированного вывода. Отдельно проверяйте состояние каждого критически важного процесса, а не ограничивайтесь сообщением «Привет».

## Рисование, эмбеддинги и повторное ранжирование

Адаптер NewAPI в Cherry Studio также позволяет использовать:

- генерацию и редактирование изображений с совместимостью OpenAI;
- модели эмбеддингов с совместимостью OpenAI;
- модели повторного ранжирования с совместимостью Jina.

Перед использованием экземпляр NewAPI должен фактически предоставлять соответствующую конечную точку, а для модели нужно выбрать правильный тип конечной точки.

### Модели рисования

1. Синхронизируйте или вручную добавьте модель изображений.
2. Установите тип конечной точки **OpenAI Image Generation**.
3. Включите модель.
4. На странице рисования выберите этого провайдера NewAPI.
5. Отдельно проверьте генерацию и редактирование.

Успешная генерация изображения не гарантирует поддержку редактирования. Эти операции могут использовать разные вышестоящие конечные точки, параметры и способы оплаты.

### Эмбеддинги и повторное ранжирование

- Модели эмбеддингов используют интерфейс Embeddings и подходят для базы знаний и [глобальной памяти](../../advanced-basic/memory.md).
- Для модели повторного ранжирования необходимо выбрать **Jina Rerank**.
- Модели чата, эмбеддингов и повторного ранжирования могут поступать от разных вышестоящих сервисов.
- Запустите проверку состояния отдельно и проверьте коэффициенты.

## PDF и вложения

NewAPI — агрегирующий шлюз. Cherry Studio не предполагает, что шлюз полностью поддерживает нативный PDF, только потому что название модели содержит Claude, Gemini или OpenAI.

Текущая V2 сначала локально извлекает текст PDF, а затем отправляет этот текст в NewAPI:

- PDF с текстовым слоем обычно можно обработать.
- Для сканированных документов сначала требуется OCR.
- Информация в таблицах, сложной вёрстке и изображениях может потеряться.
- Извлечённый текст учитывается как входные Token.
- Если необходимы нативные мультимодальные вложения, используйте проверенные конечную точку и модель.

## Проверка подключения

Рекомендуется выполнять проверку в направлении от сервера к клиенту:

1. Проверьте целевую модель в NewAPI Playground с тем же токеном.
2. Запустите проверку подключения провайдера в Cherry Studio.
3. Нажмите **Добавить** и убедитесь, что модель синхронизируется.
4. Проверьте тип конечной точки модели.
5. Запустите проверку состояния модели.
6. Вернитесь в чат и отправьте обычное сообщение.
7. Затем проверьте мышление, MCP, рисование или базу знаний.

Если запрос также не работает в Playground, проблема обычно связана с токеном NewAPI, каналом, балансом или вышестоящим сервисом. Если Playground работает, а Cherry Studio — нет, в первую очередь проверьте Base URL, тип конечной точки и версию клиента.

## Частые вопросы

### Возвращается 401

Токен недействителен, удалён, просрочен или скопирован не полностью. Убедитесь, что введён пользовательский токен NewAPI, а не ключ вышестоящего провайдера.

### Возвращается 403

Разрешения моделей, группа или белый список IP токена не допускают текущий запрос. Попросите администратора экземпляра проверить пересечение токена, канала и группы.

### Возвращается 404

В Base URL введён путь консоли, тип конечной точки неверен или сервер не предоставляет соответствующий маршрут. Верните корневой адрес сайта или стандартный адрес `/v1` и повторите попытку.

### Список моделей пуст

У токена нет доступных моделей, канал не включён, группа не совпадает или ответ `/models` старой версии NewAPI несовместим. Сначала проверьте NewAPI Playground и `/v1/models`.

### Модель существует, но при вызове сообщается об отсутствии поддержки

Проверьте сопоставление моделей, вышестоящий канал и тип конечной точки Cherry Studio. Наличие модели в `/models` означает только её видимость и не гарантирует работу текущего сочетания протокола и параметров.

### Возвращается ошибка квоты или коэффициента

Проверьте баланс пользователя, квоту токена, коэффициент группы, коэффициент модели и баланс вышестоящей учётной записи. Даже если квоты NewAPI достаточно, вышестоящий канал может не иметь средств.

### MCP выводит только план вызова

Убедитесь, что модель поддерживает вызов инструментов, а версия и канал NewAPI сохраняют `tools`, `tool_calls` и результаты инструментов. Сначала используйте один простой инструмент и попробуйте нативный протокол модели.

### Модель рисования появилась в списке чата

Отредактируйте модель, измените тип конечной точки на **OpenAI Image Generation** и используйте её на странице рисования. Модель генерации изображений не является обычной моделью чата.

Дополнительные настройки описаны на страницах [Провайдеры моделей](README.md) и [Настройки провайдеров моделей](../../cherrystudio/preview/settings/providers.md). Использование и управление NewAPI описаны в [официальной документации](https://docs.newapi.pro/), а каналы обратной связи — на странице [Отзывы и предложения](../../question-contact/suggestions.md).
