# MiniMax Token Plan (ранее Coding Plan)

MiniMax обновила Coding Plan до **Token Plan**. Он предназначен для индивидуальных разработчиков, программирования с ИИ и регулярного использования моделей MiniMax за квоту подписки или Credits.

В Cherry Studio V2 нет отдельного провайдера «Coding Plan». Специальный ключ Token Plan нужно ввести у встроенного провайдера **MiniMax** или **MiniMax Global**.

{% hint style="info" %}
Путь этой страницы сохранён для совместимости со старой документацией. Фактическое название продукта, планы и квоты MiniMax определяются текущей страницей **Token Plan**. Не применяйте устаревшие сведения из старых инструкций о M2.1, фиксированной ежемесячной плате или «40 запросах каждые 5 часов».
{% endhint %}

## Различия Token Plan и обычного API

| Параметр | Token Plan | Обычный API с оплатой по факту |
| --- | --- | --- |
| Источник ключа | Token Plan / управление подпиской | Ключи API |
| Типичный ключ | `sk-cp...` | Обычный API Key |
| Учёт | Квота плана, Credits, скользящее окно | Оплата по фактическому расходу API |
| Срок действия | Зависит от подписки, места или Credits | Зависит от баланса и состояния ключа |
| Назначение | Личное взаимодействие, инструменты программирования, повседневное использование | Производственная интеграция, стабильные вызовы с оплатой по факту |

Эти два типа ключей **не взаимозаменяемы**. Использование обычного API Key вместо Token Plan Key или Token Plan Key как обычного ключа с оплатой по факту может привести к 401, ошибке квоты или неверному источнику оплаты.

MiniMax рекомендует для производственной среды предпочитать API с оплатой по факту. Token Plan может иметь ограничения RPM, TPM, скользящего окна, недельной квоты и динамические ограничения в часы пик, поэтому не подходит для неограниченного пакетного сервиса.

## Выбор платформы материкового Китая или международной платформы

| Учётная запись и подписка | Провайдер Cherry Studio | OpenAI Base URL | Anthropic Base URL |
| --- | --- | --- | --- |
| Платформа MiniMax в материковом Китае | MiniMax | `https://api.minimaxi.com/v1` | `https://api.minimaxi.com/anthropic` |
| Международная платформа MiniMax | MiniMax Global | `https://api.minimax.io/v1` | `https://api.minimax.io/anthropic` |

Не смешивайте учётные записи, ключи и Base URL китайской и международной платформ. Ориентируйтесь на платформу покупки Token Plan и создания ключа, а не на текущее местоположение.

## Получение Token Plan Key

### Платформа материкового Китая

1. Войдите на [открытую платформу MiniMax](https://platform.minimaxi.com/).
2. Откройте [Token Plan](https://platform.minimaxi.com/subscribe/token-plan).
3. Купите план, активируйте право или убедитесь, что Team назначила место.
4. Перейдите к ключам API.
5. Выберите **Создать Token Plan Key**.
6. Скопируйте новый ключ и сохраните его в безопасном месте.

### Международная платформа

1. Войдите на [MiniMax API Platform](https://platform.minimax.io/).
2. Откройте [Token Plan](https://platform.minimax.io/subscribe/token-plan).
3. Купите план или Credits либо проверьте место Team.
4. Перейдите к API Keys.
5. Создайте **Token Plan Key**.
6. Скопируйте новый ключ и сохраните его в безопасном месте.

{% hint style="danger" %}
Не помещайте Token Plan Key в чат, документацию, репозиторий кода или снимки экрана с проблемой. Утечка ключа может израсходовать квоту подписки или Credits; немедленно удалите его на платформе MiniMax и создайте новый.
{% endhint %}

Префикс `sk-cp` сам по себе не доказывает работоспособность ключа. Также убедитесь, что подписка действует, место назначено, Credits доступны и ключ получен на правильной платформе.

## Настройка в Cherry Studio

1. Откройте `Настройки → Провайдеры моделей`.
2. Переключите фильтр слева на **Все поставщики**.
3. Для китайской учётной записи выберите **MiniMax**, для международной — **MiniMax Global**.
4. Вставьте Token Plan Key в поле API Key.
5. Проверьте соответствие Base URL платформе учётной записи.
6. Включите провайдера переключателем в верхней части страницы.
7. Нажмите **Добавить** или синхронизируйте модели.
8. Проверьте предварительный результат и примените изменения.
9. Включите только модели, разрешённые текущим планом.
10. Запустите проверку состояния модели.

Шаблон MiniMax в Cherry Studio сохраняет адреса совместимости OpenAI и Anthropic. Обычный чат по умолчанию использует маршрут OpenAI, а некоторые Code Tools могут использовать маршрут Anthropic.

Подробнее об ограничениях протоколов, зрения, мышления, MCP и PDF см. на странице [MiniMax](minimax.md).

## Выбор модели

Текущий шаблон MiniMax в Cherry Studio V2 содержит:

- `MiniMax-M3`
- `MiniMax-M2.7`
- `MiniMax-M2.7-highspeed`

Доступные модели MiniMax Token Plan меняются вместе с планами и обновлением продукта. Ориентируйтесь на страницу подписки, использование учётной записи и фактический результат синхронизации.

Рекомендации:

1. Сначала проверьте рекомендуемую текущим планом `MiniMax-M3`.
2. Проверяйте `MiniMax-M2.7`, только если нужна совместимость со старым процессом.
3. Используйте `MiniMax-M2.7-highspeed`, только если план явно включает высокоскоростную модель.
4. Не добавляйте вручную старую `MiniMax-M2.1`, предполагая, что она всё ещё входит в план.
5. Одна модель может иметь разные правила квоты в Token Plan и API с оплатой по факту.

{% hint style="warning" %}
Наличие модели в шаблоне или синхронизированном списке Cherry Studio не гарантирует, что она входит в ваш Token Plan. Окончательное разрешение определяет сервер MiniMax.
{% endhint %}

## Мышление, зрение и MCP

### Мышление

Серия MiniMax M возвращает содержимое мышления. Для непрерывности контекста последующих запросов Cherry Studio должна сохранять блоки мышления и сведения о вызовах инструментов в многоэтапном диалоге.

Если после изменения параметра мышления возвращается ошибка, сначала верните значение **По умолчанию** и повторите запрос. Token Plan Key не меняет параметры, принимаемые самой моделью.

### Зрение

Token Plan расширен на мультимодальные модели, но возможность Cherry Studio напрямую отправлять изображения также зависит от ID модели и распознавания возможностей в V2.

После синхронизации убедитесь, что у модели отображается возможность изображений, и проверьте небольшое изображение. Если зрение `MiniMax-M3` ещё не распознаётся текущей V2, не обходите ограничение изменением отображаемого имени.

### MCP

MCP Cherry Studio использует Tool Calling модели. MiniMax Token Plan также предоставляет официальные Web Search MCP и Understand Image MCP, однако это не те же серверы MCP, которые настраиваются в Cherry Studio.

При использовании MCP Cherry Studio:

1. Сначала проведите обычный чат.
2. Включите только один простой инструмент.
3. Проверьте, что модель действительно создаёт структурированный вызов.
4. Затем добавьте инструменты.

Если нужен официальный Token Plan MCP MiniMax, настройте его отдельно по официальной инструкции и учитывайте расход соответствующих ресурсов плана.

## Просмотр использования

Надёжнее всего открыть Token Plan или управление подпиской на платформе MiniMax и проверить:

- текущий план или место Team;
- оставшуюся квоту и Credits;
- использование каждой модели;
- время восстановления скользящего окна;
- периодическую квоту;
- право на высокоскоростные модели;
- дату окончания подписки.

Не оценивайте остаток только по числу успешных запросов Cherry Studio. Длинный контекст, зрение, генеративные и разные модели могут использовать разные пулы квот.

## Ограничения и 429

В Token Plan одновременно могут действовать:

- краткосрочные ограничения RPM / TPM;
- пятичасовое скользящее окно;
- недельная квота;
- отдельная квота мультимодальных моделей;
- динамические ограничения в часы пик;
- ограничение параллельности плана.

Поэтому `429 Too Many Requests` не обязательно означает исчерпание всей квоты подписки.

Порядок проверки:

1. Подождите минуту и повторите запрос.
2. Откройте страницу использования Token Plan.
3. Проверьте скользящее окно и недельную квоту.
4. Уменьшите параллельность, длинный контекст и автоматические повторы.
5. Убедитесь, что несколько людей не используют один личный ключ.
6. При необходимости обновите план или используйте API Key с оплатой по факту.

Прямая замена на обычный API Key у того же провайдера меняет квоту и источник оплаты. Сначала проверьте баланс и бюджет.

## Частые вопросы

### Возвращается 401

Ключ неверен или удалён, подписка закончилась, место недействительно либо смешаны китайский и международный Base URL. Скопируйте Token Plan Key с соответствующей платформы заново.

### Возвращается 403

Текущий план, политика Team или разрешение модели запрещает запрос. Проверьте права Token Plan и диапазон моделей.

### Возвращается 404

Base URL, путь протокола или ID модели неверен. Восстановите адрес шаблона MiniMax / MiniMax Global и повторно синхронизируйте модели.

### Возвращается 429

Возможно минутное ограничение, скользящее окно, недельная квота или динамическое ограничение в часы пик. Ориентируйтесь на страницу использования Token Plan, а не повторяйте запрос непрерывно.

### Обычная модель работает, высокоскоростная — нет

Текущий план может не включать высокоскоростное право или ресурсы временно недоступны. Используйте стандартную модель и проверьте описание плана.

### В списке остаются старые модели

Повторно синхронизируйте и убедитесь, что провайдер подключён к правильной платформе. Сохранённая вручную старая модель не означает поддержку текущим планом.

### Проверка ключа успешна, но чат расходует баланс

Возможно, введён обычный API Key с оплатой по факту, а не Token Plan Key. Немедленно проверьте счета MiniMax и тип ключа.

### При производственном использовании постоянно возникает ограничение

Token Plan рассчитан на личное взаимодействие и разработку. Для производственного, пакетного или высокопараллельного сервиса используйте API с оплатой по факту и настройте бюджет, мониторинг и повторы.
