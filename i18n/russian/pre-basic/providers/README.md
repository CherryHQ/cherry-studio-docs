# Провайдеры моделей

Настройка провайдера моделей позволяет подключить Cherry Studio к облачной платформе моделей, локальной службе инференса или собственному шлюзу. После настройки необходимо включить нужные модели в списке моделей провайдера — только тогда их можно будет выбирать в ассистентах, переводе, базах знаний и других функциях.

{% hint style="info" %}
Если вы уже знаете, какого провайдера будете использовать, сразу перейдите к соответствующему [руководству по настройке провайдера](#руководства-по-настройке-провайдеров). Чтобы быстро сравнить поддержку, откройте [краткий справочник по всем Provider](quick-reference.md).
{% endhint %}

## Перед началом

Подготовьте следующие данные с учётом типа провайдера:

- **Облачная платформа моделей или агрегирующий шлюз**: API Key и модели, доступные в вашей учётной записи;
- **Собственный шлюз**: API Key, Base URL и протоколы API, поддерживаемые шлюзом;
- **Локальная служба инференса**: адрес запущенной службы и загруженные или подключённые модели;
- **Специализированное подключение к облачной платформе**: также могут потребоваться регион, проект, имя развёртывания или учётные данные облачной платформы.

Способы аутентификации и структура адресов различаются у разных провайдеров. В первую очередь используйте встроенный шаблон провайдера Cherry Studio. Создавайте пользовательского провайдера, только если нужного провайдера нет в списке или требуется подключиться к собственному совместимому API.

## Настройка провайдера

### 1. Найдите или добавьте провайдера

Откройте `Настройки → Провайдеры моделей`.

По умолчанию в списке слева отображаются включённые провайдеры. Вы можете:

- искать по названию провайдера или модели;
- отфильтровать провайдеров по вариантам **Включено**, **Отключено**, **Все поставщики** или по поддержке API Agent;
- перетаскивать провайдеров, чтобы изменить их порядок;
- нажать `+` справа от поля поиска, чтобы создать пользовательского провайдера;
- редактировать, копировать или удалять доступные для управления записи через контекстное меню провайдера.

{% hint style="warning" %}
Фильтр «Agent» означает только то, что у провайдера есть совместимая конечная точка, необходимая для текущих функций Agent. Он не гарантирует, что каждая модель этого провайдера поддерживает вызов инструментов. Фактические возможности зависят от выбранной модели и провайдера.
{% endhint %}

### 2. Укажите данные аутентификации и адрес API

Выберите провайдера и настройте аутентификацию справа:

1. Введите API Key или выполните специализированную аутентификацию OAuth, AWS, Azure, Google Cloud и других платформ согласно подсказкам на странице.
2. Проверьте Base URL. При использовании встроенного шаблона обычно достаточно оставить адрес по умолчанию.
3. Если провайдер предлагает несколько протоколов, в настройках API можно отдельно указать конечные точки OpenAI Chat Completions, Anthropic Messages, Google Generate Content или OpenAI Responses.
4. Включите переключатель провайдера в верхней части страницы.

Для пользовательского провайдера основным API по умолчанию служит **OpenAI Chat Completions**. Можно также раскрыть раздел «Дополнительные конечные точки» и добавить другие совместимые API. Подробные правила приведены на странице [Пользовательский провайдер](zi-ding-yi-fu-wu-shang.md).

{% hint style="danger" %}
API Key — конфиденциальные учётные данные. Не добавляйте настоящий Key в документы, сообщения чата или снимки экрана с описанием проблемы. При диагностике оставляйте видимыми только несколько символов в начале и конце, скрыв остальную часть.
{% endhint %}

### 3. Синхронизируйте и включите модели

В разделе **Список моделей**:

1. Нажмите **Добавить**, чтобы синхронизировать доступные в данный момент модели с провайдером.
2. Проверьте добавляемые, обновляемые и удаляемые элементы в предварительном просмотре синхронизации, а затем примените изменения.
3. Если API не поддерживает получение списка моделей, нажмите **Пользовательский** и вручную введите ID модели.
4. Включите переключатели моделей, которые планируете использовать.

В списке моделей можно искать по названию, а также фильтровать модели по поддержке зрения, рассуждений, вызова инструментов и другим возможностям. Теги возможностей в основном определяются по данным провайдера и правилам моделей Cherry Studio. Если автоматическое определение неточно, отредактируйте модель вручную.

### 4. Проверьте подключение

После настройки рекомендуется выполнить две проверки:

- запустить проверку подключения в области аутентификации, выбрать настроенную модель и API Key и проверить запрос;
- запустить проверку работоспособности в списке моделей, чтобы убедиться в доступности всех включённых моделей.

После успешной проверки создайте или откройте ассистента, выберите только что включённую модель в средстве выбора моделей и отправьте тестовое сообщение.

## Выбор способа подключения

| Сценарий | Рекомендуемый способ | Описание |
|---|---|---|
| Использование официальных API OpenAI, Anthropic, DeepSeek и других платформ | Выберите соответствующий встроенный шаблон | Адрес по умолчанию и тип API уже заданы |
| Использование моделей разных платформ с одним Key | Выберите шаблон агрегатора или шлюза | Модели, цены и доступные регионы определяются этой платформой |
| Подключение к собственному шлюзу NewAPI, OneAPI или аналогичному | В первую очередь используйте соответствующий шаблон | Если путь развёртывания отличается, измените Base URL |
| Использование локальной службы Ollama, LM Studio или аналогичной | Выберите шаблон локальной службы | Сначала убедитесь, что локальная служба запущена и её порт доступен |
| Подключение совместимого API, которого нет в списке | Создайте пользовательского провайдера | Необходимо уточнить протокол, Base URL и ID модели |

{% hint style="info" %}
Для одного провайдера можно настроить несколько API Key, а также более точно задать адреса запросов и параметры. См. [Настройки провайдеров моделей](../../cherrystudio/preview/settings/providers.md).
{% endhint %}

## Частые вопросы

### Не удаётся синхронизировать модели

Сначала убедитесь, что API Key, Base URL и протокол API согласованы между собой. Некоторые провайдеры не предоставляют API списка моделей. В таком случае добавьте ID модели вручную, взяв его из консоли провайдера.

### Модель не отображается в средстве выбора моделей

Убедитесь, что включены и переключатель провайдера в верхней части страницы, и переключатель нужной модели. Если модель синхронизирована, но отключена, она не будет отображаться как доступная для выбора.

### Возвращается ошибка 401 или 403

Обычно это означает, что API Key недействителен, прав недостаточно, нужная модель не подключена для учётной записи или провайдер ограничивает источники подключений. Проверьте состояние учётных данных и права на модель в консоли провайдера.

### Возвращается ошибка 404 или ошибка протокола

В первую очередь проверьте, нет ли в Base URL повторяющихся или пропущенных частей пути и соответствует ли выбранный протокол API фактически поддерживаемому провайдером. При использовании шлюза также убедитесь, что он совместим с конечной точкой выбранной модели.

### Истекает время ожидания при подключении к локальной модели

Убедитесь, что локальная служба инференса запущена, а её адрес прослушивания и порт совпадают с настройками Cherry Studio. Если служба работает в контейнере, виртуальной машине или на другом устройстве, также проверьте доступ через сеть и межсетевой экран.
