# LM Studio

LM Studio позволяет скачивать и запускать локальные модели в macOS, Windows и Linux, а также предоставлять Cherry Studio возможности чата, зрения, вызова инструментов и эмбеддингов через API с совместимостью OpenAI.

В Cherry Studio V2 встроен провайдер LM Studio, по умолчанию подключённый к `http://localhost:1234`. Обычный чат использует совместимый интерфейс OpenAI, а список моделей загружается из `/v1/models`.

{% hint style="info" %}
Синхронизация в Cherry Studio только считывает модели, видимые сейчас LM Studio, и не скачивает их. Сначала скачайте модель на странице **Discover** в LM Studio, затем запустите локальный API Server.
{% endhint %}

## Подготовка LM Studio

1. Скачайте и установите последнюю версию с [официального сайта LM Studio](https://lmstudio.ai/).
2. Откройте **Discover**, найдите и скачайте модель.
3. Выберите число параметров и вариант квантования с учётом оперативной или видеопамяти устройства.
4. Откройте страницу **Developer**.
5. Нажмите **Start server**, чтобы запустить API Server.

Адрес прослушивания по умолчанию:

```text
http://localhost:1234
```

Сервер также можно запустить в терминале:

```bash
lms server start
```

При первом использовании сначала загрузите модель и проведите один чат в LM Studio, чтобы убедиться в её работоспособности, а затем подключайте Cherry Studio.

## Выбор модели и квантования

Файл модели, способ квантования и длина контекста влияют на расход памяти и скорость.

- Большее число параметров обычно повышает возможности, но требует больше RAM или VRAM.
- Модели GGUF могут использовать смешанный вывод на CPU и GPU.
- На Apple Silicon можно использовать совместимые модели MLX.
- Низкобитное квантование уменьшает расход, но может снизить качество вывода.
- Чем длиннее контекст, тем больше KV Cache.
- Модели зрения также кодируют изображения и обычно требуют больше ресурсов, чем текстовые модели того же размера.

Если вы не уверены, сначала выберите малую или среднюю модель с распространённым квантованием, которую устройство стабильно загружает, а затем постепенно увеличивайте размер или контекст.

LM Studio CLI также умеет оценивать расход ресурсов:

```bash
lms load --estimate-only <model-key>
```

## Настройка в Cherry Studio

1. Откройте `Настройки → Провайдеры моделей`.
2. Переключите фильтр слева на **Все поставщики**.
3. Выберите **LM Studio**.
4. Сохраните Base URL `http://localhost:1234`.
5. Если авторизация LM Studio выключена, оставьте API Key пустым.
6. Включите провайдера переключателем в верхней части страницы.
7. Нажмите **Добавить** или синхронизируйте модели.
8. Проверьте предварительный результат и примените изменения.
9. Включите только нужные модели.
10. Запустите проверку состояния модели, затем протестируйте чат.

В Base URL достаточно указать хост и порт, не добавляя `/v1` вручную. Cherry Studio обращается к списку моделей и чату через совместимые интерфейсы OpenAI.

## Почему список моделей меняется

Интерфейс LM Studio `/v1/models` возвращает модели, видимые серверу сейчас:

| Настройка LM Studio | Поведение списка |
| --- | --- |
| Just-In-Time Model Loading включён | Возвращаются все скачанные модели, которые можно автоматически загрузить при первом запросе |
| Just-In-Time Model Loading выключен | Обычно возвращаются только модели, уже загруженные в память |

Поэтому утверждение старых инструкций о необходимости вручную выполнить Load перед синхронизацией применимо не ко всем версиям.

Если список в Cherry Studio пуст:

1. Убедитесь, что API Server запущен.
2. Откройте `http://localhost:1234/v1/models` в браузере или терминале.
3. Проверьте, включён ли JIT Loading в LM Studio.
4. Если JIT выключен, сначала загрузите модель в LM Studio.
5. Вернитесь в Cherry Studio и повторите синхронизацию.

{% hint style="warning" %}
Успешная синхронизация не означает, что устройство обязательно загрузит модель. При включённом JIT в списке видны и незагруженные модели; только первый чат запускает загрузку и может выявить нехватку памяти или слишком большой контекст.
{% endhint %}

## API Token и авторизация

По умолчанию LM Studio не требует API Token. При локальном использовании API Key в Cherry Studio можно оставить пустым.

В LM Studio 0.4.0 и новее на странице `Developer → Server Settings` можно включить **Require Authentication**:

1. Откройте **Manage Tokens**.
2. Создайте Token и задайте разрешения.
3. Скопируйте новый Token.
4. Введите его у провайдера LM Studio в Cherry Studio.
5. Повторно синхронизируйте модели и запустите проверку состояния.

Cherry Studio отправляет непустой API Key как Bearer Token. LM Studio также поддерживает распространённые заголовки авторизации совместимых интерфейсов OpenAI и Anthropic.

{% hint style="danger" %}
API Token полностью показывается только при создании. Не помещайте Token в чат, документацию, репозиторий кода или снимки экрана с проблемой; при утечке немедленно удалите его и создайте новый.
{% endhint %}

## Чат, зрение и MCP

### Обычный чат

Выберите инструктивную модель с поддержкой Chat Completions. После проверки обычного чата тестируйте мышление, изображения и инструменты.

Качество локальной модели зависит от модели, квантования, шаблона запросов и контекста. Успешный ответ подтверждает работу интерфейса, но не пригодность модели для любой задачи.

### Обработка изображений

Совместимый Chat Completions LM Studio поддерживает текст и изображения, но конкретная модель должна иметь возможности зрения.

1. Скачайте версию с явной отметкой модели зрения.
2. Загрузите её в LM Studio или разрешите JIT-загрузку.
3. Синхронизируйте с Cherry Studio.
4. Убедитесь, что отображается возможность изображений.
5. Сначала отправьте одно небольшое изображение.

Похожие имена не означают, что каждое квантование или разновидность поддерживает изображения. Если Cherry Studio не распознаёт зрение, сначала проверьте ID модели и поддержку среды выполнения, а не меняйте только отображаемое имя.

### Вызов инструментов и MCP

MCP в Cherry Studio зависит от структурированного Tool Calling модели. LM Studio предлагает нативный или совместимый режим по шаблону модели, но стабильность определяется самой моделью.

Рекомендуемый порядок:

1. Сначала проведите обычный чат.
2. Включите только один простой инструмент MCP.
3. Явно попросите модель его вызвать.
4. Проверьте появление структурированного вызова.
5. Убедитесь, что результат инструмента возвращается модели.
6. Затем постепенно добавляйте инструменты.

Малая модель может написать, что «готовится вызвать инструмент», но не выполнить вызов. В таком случае используйте модель с нативной отметкой Tool Use, большим числом параметров или более полным обучением инструментам.

MCP Cherry Studio и собственная интеграция MCP сервера LM Studio — разные цепочки. При использовании только MCP Cherry Studio не нужно повторно настраивать тот же инструмент в LM Studio.

## Модели мышления и структурированный вывод

Обработка параметров мышления и структурированного вывода зависит от шаблона модели и реализации совместимости OpenAI в LM Studio.

- Предпочтительно используйте модели и шаблоны с явной поддержкой LM Studio.
- Переключатели и интенсивность мышления разных моделей не универсальны.
- При ошибке параметра после включения мышления верните значение по умолчанию или отключите его.
- При сбое JSON или структурированного вывода сначала проверьте ту же модель в LM Studio.
- Не имитируйте другую возможность изменением отображаемого имени.

## Загрузка моделей, JIT и видеопамять

При включённом JIT Loading LM Studio может автоматически загрузить модель в память или VRAM при первом вызове из Cherry Studio. Первый ответ будет заметно медленнее последующих.

LM Studio 0.4+ также предоставляет:

- **Idle TTL**: время бездействия до автоматической выгрузки модели.
- **Auto-Evict**: автоматическая выгрузка ранее загруженной через JIT модели перед загрузкой новой.
- **Only Keep Last JIT Loaded Model**: сохранение только последней использованной JIT-модели.

На странице провайдера LM Studio в Cherry Studio также отображается **Время активности**. Фактическая выгрузка и освобождение памяти зависят от JIT, TTL, Auto-Evict и ручной загрузки LM Studio; при диагностике ориентируйтесь на список загруженных моделей и настройки сервера LM Studio.

Для ручного управления:

```bash
lms load <model-key> --context-length 8192 --gpu max
lms unload <model-key>
lms unload --all
```

Не загружайте одновременно несколько больших моделей, близких к пределу устройства. При частом переключении Auto-Evict обычно стабильнее постоянного накопления моделей.

## Длина контекста

Максимальный поддерживаемый и фактически загруженный контекст — разные понятия. Доступный диапазон определяет Context Length при загрузке модели в LM Studio.

Слишком длинный контекст может привести к:

- нехватке RAM или VRAM;
- увеличению времени первой загрузки;
- замедлению обработки запроса;
- обрезке запроса или ошибке лимита;
- более частым сбоям зрения и длинных документов.

Если сведения модели в Cherry Studio превышают фактическое значение загрузки LM Studio, ориентируйтесь на конфигурацию среды выполнения LM Studio. Сначала проверьте стабильность с коротким контекстом, затем увеличивайте его.

## База знаний и модели эмбеддингов

LM Studio предоставляет совместимый с OpenAI интерфейс `/v1/embeddings` для специальных моделей эмбеддингов.

1. Скачайте модель эмбеддингов.
2. Загрузите её в LM Studio или разрешите JIT-загрузку.
3. Синхронизируйте модели в Cherry Studio.
4. Убедитесь, что модель распознана как модель эмбеддингов.
5. Выберите её в базе знаний и определите размерность.
6. После проверки состояния импортируйте документы.

Cherry Studio не поддерживает модели повторного ранжирования LM Studio. Для Rerank выберите другого провайдера.

Не меняйте без необходимости модель или размерность, уже использованную в базе знаний, иначе обычно потребуется перестроить векторный индекс.

## PDF и вложения

Текущая V2 не отправляет исходный PDF непосредственно в LM Studio. Cherry Studio сначала локально извлекает текст, затем передаёт его модели:

- PDF с текстовым слоем обычно обрабатывается.
- Сканированному документу сначала нужен OCR.
- Таблицы, сложная вёрстка и изображения могут потеряться.
- Извлечённый текст занимает контекст.
- Изображения PDF нужно отдельно отправлять модели зрения.

## Code Tools и совместимый интерфейс Anthropic

Шаблон LM Studio в Cherry Studio также сохраняет совместимый адрес Anthropic, по умолчанию `http://localhost:1234`, для некоторых Code Tools.

LM Studio предоставляет `/v1/messages`. Если Code Tool требует совместимый сервис Anthropic:

1. Используйте достаточно новую версию LM Studio.
2. Запустите API Server.
3. Убедитесь, что модель поддерживает нужные инструменты.
4. При включённой авторизации введите тот же Token.
5. Используйте фактический идентификатор модели LM Studio.
6. Сначала проверьте простую задачу, затем разрешайте файлы или команды.

Поддержка Messages не гарантирует, что любая локальная модель надёжно выполнит задачу агента кода. На результат влияют возможности, контекст, качество инструментов и производительность устройства.

## Подключение к LM Studio в сети или удалённо

Если Cherry Studio и LM Studio находятся на разных устройствах:

1. В Server Settings LM Studio включите **Serve on Local Network**.
2. Включите **Require Authentication** и создайте Token.
3. Разрешите порт сервера в системном брандмауэре.
4. Введите в Cherry Studio адрес LM Studio в локальной сети.
5. Введите Token.
6. Сначала откройте `/v1/models`, затем запустите проверку состояния.

CLI также может прослушивать все интерфейсы:

```bash
lms server start --bind 0.0.0.0
```

Не открывайте порт LM Studio без авторизации напрямую в интернет. Используйте VPN или обратный прокси с HTTPS, авторизацией и надлежащим контролем доступа.

В Docker, виртуальной машине, WSL или удалённом рабочем столе `localhost` указывает на систему Cherry Studio, а не обязательно на хост LM Studio. Используйте фактически доступный адрес.

## Частые вопросы

### Не удаётся подключиться к `localhost:1234`

API Server LM Studio не запущен, порт изменён или заблокирован брандмауэром. Убедитесь, что страница Developer показывает работающий сервер.

### Список моделей пуст

Проверьте ответ `/v1/models`. При выключенном JIT сначала загрузите модель; при включённом убедитесь, что модель скачана и видима серверу.

### Модели синхронизируются, но чат возвращает ошибку

Модель могла не загрузиться, ресурсов недостаточно, контекст слишком велик или шаблон API несовместим. Проверьте журнал сервера и состояние загрузки LM Studio.

### Первый ответ медленный

JIT загружает модель. Последующие запросы обычно быстрее; предварительная загрузка ускорит первый ответ, но постоянно займёт память или VRAM.

### Недостаточно оперативной или видеопамяти

Выберите меньшую модель или более сильное квантование, сократите контекст, увеличивайте GPU Offload только при наличии ресурсов и выгрузите другие модели.

### Недоступны изображения или MCP

Обычный чат не доказывает наличие зрения или инструментов. Проверьте версию модели, шаблон, распознавание Cherry Studio и журналы LM Studio.

### API Token недействителен

Убедитесь, что Require Authentication включён, Token не удалён, разрешения верны и в Cherry Studio нет лишних пробелов.

### Удалённое подключение отклонено

Убедитесь, что Serve on Local Network включён, порт доступен, а пути брандмауэра и обратного прокси верны. Не отключайте все меры безопасности для решения проблемы доступа через интернет.
