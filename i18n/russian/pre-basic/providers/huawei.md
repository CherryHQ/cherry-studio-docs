# Huawei Cloud ModelArts Studio (MaaS)

Huawei Cloud ModelArts Studio (MaaS) предоставляет API инференса для встроенных и развернутых пользователем моделей. В текущей версии Cherry Studio V2 нет встроенного провайдера Huawei Cloud, поэтому необходимо создать **пользовательского OpenAI-совместимого провайдера**.

{% hint style="info" %}
В старых руководствах предлагалось указывать полный адрес `/chat/completions` в API Host и добавлять в конце `#`. В V2 этот устаревший способ обеспечения совместимости не нужен. Удалите `/chat/completions` из полного адреса вызова и оставьте только Base URL.
{% endhint %}

## Сначала выберите способ подключения

В Huawei Cloud MaaS обычно используются два способа вызова:

| Способ | Особенности адреса | Настройка Cherry Studio |
| --- | --- | --- |
| MaaS Standard API | Несколько встроенных моделей используют общий Base URL `/v1` или `/v2` | Обычно достаточно одного пользовательского провайдера |
| Пользовательский сервис инференса в реальном времени | У каждого сервиса может быть отдельный URL, Endpoint или путь | Для разных Base URL необходимо создавать отдельных провайдеров |

Это руководство относится только к OpenAI-совместимым сервисам MaaS, использующим Bearer API Key. IAM Token, AppKey/AppSecret, AppCode и аутентификацию по подписи из старой версии ModelArts нельзя напрямую указывать в обычном поле API Key в Cherry Studio.

## Регион и версия

Доступный регион MaaS, API Key и список моделей связаны между собой: их нельзя смешивать между регионами.

В актуальной документации международного сайта Huawei Cloud приведен следующий пример MaaS Standard API V2:

```text
https://api-ap-southeast-1.modelarts-maas.com/v2/chat/completions
```

В Cherry Studio следует указать:

```text
https://api-ap-southeast-1.modelarts-maas.com/v2
```

Развитие MaaS Standard API V1 прекращено. Для новой настройки используйте адрес V2, предоставленный консолью. Для существующего сервиса V1 по-прежнему ориентируйтесь на раздел с инструкцией по вызову в консоли.

{% hint style="warning" %}
Не копируйте пример адреса из этого руководства без проверки. Сначала откройте инструкцию по вызову для своего региона и сервиса Huawei Cloud. Если домен или версия в консоли отличаются, используйте адрес из консоли.
{% endhint %}

## Активация MaaS

1. Зарегистрируйтесь в [Huawei Cloud](https://auth.huaweicloud.com/authui/login) и войдите в аккаунт.
2. Переключитесь на регион, который сейчас поддерживает MaaS.
3. Откройте ModelArts Studio (MaaS).
4. Предоставьте разрешения IAM согласно указаниям консоли.
5. Выберите модель в каталоге моделей.
6. Активируйте встроенный сервис либо разверните модель как сервис инференса в реальном времени.
7. Дождитесь, когда сервис станет доступен для вызова.

Пользовательское развертывание использует вычислительные ресурсы и хранилище, за которые взимается плата. Не выбирайте развертывание всех моделей, пока не разберетесь в способе оплаты.

## Создание API Key

### Встроенный сервис MaaS

1. Откройте управление API Key в MaaS.
2. Нажмите **Создать API Key**.
3. Задайте метку.
4. При необходимости настройте список разрешенных IP-адресов, моделей и пользовательских Endpoint.
5. Сразу после создания скопируйте и сохраните ключ.

### Пользовательский сервис инференса в реальном времени

1. Откройте `Инференс моделей → Инференс в реальном времени → Мои сервисы`.
2. Найдите запущенный сервис.
3. Выберите `Дополнительно → Посмотреть инструкцию по вызову`.
4. Нажмите **Создать API Key**.
5. Настройте права и скопируйте Key.
6. Также скопируйте полный API URL и параметры модели.

Для активации MaaS Key после создания может потребоваться несколько минут.

{% hint style="danger" %}
API Key отображается только один раз при создании. Не добавляйте его в чаты, документы, репозитории кода и снимки экрана для отчетов о проблемах. При потере или утечке удалите ключ и создайте новый.
{% endhint %}

## Извлечение Base URL из полного URL

Предположим, консоль предоставляет следующий полный адрес:

```text
https://example.com/v2/chat/completions
```

В Cherry Studio следует указать:

```text
https://example.com/v2
```

Правила обработки:

1. Удалите `/chat/completions` в конце.
2. Сохраните `/v1` или `/v2`.
3. Не добавляйте `#`.
4. Не добавляйте имя модели к URL.
5. Не используйте URL страницы консоли как API URL.

Если в инструкции по вызову пользовательского сервиса используется другой путь, сначала убедитесь, что он совместим с OpenAI Chat Completions. Несовместимый интерфейс нельзя подключить одним лишь удалением пути.

## Создание пользовательского провайдера в Cherry Studio

1. Откройте `Настройки → Провайдеры моделей`.
2. Нажмите **Добавить провайдера**.
3. Укажите имя, например `Huawei Cloud MaaS`.
4. Выберите тип **OpenAI-совместимый**.
5. Вставьте MaaS API Key.
6. Укажите извлеченный Base URL.
7. Включите провайдера.
8. Синхронизируйте модели или добавьте Model ID вручную.
9. Включите только те модели, которые собираетесь использовать.
10. Запустите проверку работоспособности модели.

Если все модели используют один Base URL MaaS Standard API, их можно разместить в одном провайдере. Создавайте другого провайдера только при различиях в Base URL, аутентификации или пути прокси.

## Получение и синхронизация моделей

MaaS Standard API предоставляет следующие интерфейсы списка моделей:

```text
GET /v1/models
GET /v2/models
```

Конкретная версия зависит от Base URL, предоставленного консолью.

После синхронизации:

1. Проверьте возвращенные Model ID.
2. Примените результат синхронизации.
3. Проверьте тип модели.
4. Отдельно запустите проверку работоспособности каждой модели.

Если пользовательский сервис не предоставляет интерфейс списка моделей:

1. Скопируйте параметр `model` из инструкции по вызову.
2. Добавьте его в Cherry Studio вручную.
3. Полностью сохраните регистр и знаки препинания.
4. Запустите проверку работоспособности.

{% hint style="warning" %}
Для API Key можно настроить список разрешенных моделей и пользовательских Endpoint. Если модель существует, но возвращает 401, проверьте права Key, а не только копируйте ключ заново.
{% endhint %}

## Диалоговые модели

MaaS Standard API использует OpenAI-совместимый интерфейс Chat Completions.

Рекомендуемый порядок проверки:

1. Отправьте короткое текстовое сообщение.
2. Проверьте потоковый вывод.
3. Добавьте системный промпт.
4. Проверьте более длинный контекст.
5. Затем проверьте рассуждение, изображения и вызов инструментов.

Допустимые значения `role`, длина контекста и выходные параметры различаются у разных моделей. При ошибке 400 сверьтесь со спецификацией вызова MaaS API для этой модели.

## Режим рассуждения

Разные модели Huawei Cloud MaaS могут использовать:

- `reasoning_content`
- `thinking`
- `chat_template_kwargs`
- специальный переключатель модели

В текущей версии Cherry Studio нет специальной адаптации параметров Huawei Cloud. Параметры рассуждения, которые V2 формирует для обычного OpenAI-совместимого провайдера, могут не полностью соответствовать конкретной модели MaaS.

Если после включения рассуждения возникает ошибка:

1. Верните настройку рассуждения к значению **По умолчанию**.
2. Удалите пользовательские параметры модели.
3. Сначала убедитесь, что обычный диалог работает.
4. Посмотрите пример запроса для этой модели в MaaS.
5. Добавляйте только параметры, явно требуемые официальной документацией.

Не копируйте `chat_template_kwargs` одной модели в другую.

## Компьютерное зрение и мультимодальность

Изображения могут принимать только модели, которые MaaS явно обозначает как визуальные или мультимодальные.

Порядок проверки:

1. Добавьте точный Model ID.
2. Убедитесь, что Cherry Studio показывает поддержку изображений.
3. Сначала загрузите одно небольшое изображение.
4. Проверьте, действительно ли модель понимает его содержимое.
5. Затем попробуйте несколько изображений или более крупный файл.

Даже если визуальная модель развернута в пользовательском сервисе реального времени, для прямого подключения из Cherry Studio должен использоваться OpenAI-совместимый формат сообщения с изображением.

## MCP и вызов инструментов

Некоторые модели MaaS Standard API V2 поддерживают Tool Calling, но окончательные возможности зависят от модели.

1. Сначала настройте обычный диалог.
2. Включите только один простой инструмент MCP.
3. Явно попросите модель вызвать его.
4. Проверьте, сформирован ли структурированный вызов.
5. Убедитесь, что результат инструмента возвращается модели.
6. Только после этого добавляйте другие инструменты.

Если модель лишь пишет, что «собирается вызвать инструмент», это не является реальным вызовом. Проверьте модель, версию API и формат инструмента.

## Embedding, Rerank и генерация изображений

В текущей версии Cherry Studio нет специальных адаптеров Huawei Cloud для Embedding, Rerank и генерации изображений.

Пробовать эти функции следует только при выполнении всех условий:

1. Сервис MaaS предоставляет соответствующий OpenAI-совместимый интерфейс.
2. Cherry Studio позволяет выбрать для модели правильный Endpoint Type.
3. Форматы запроса и ответа совместимы с V2.
4. Проверка работоспособности или фактический тест на небольшом примере выполнены успешно.

Поддержка определенного типа модели в консоли MaaS не означает, что он уже интегрирован в базу знаний или страницу рисования Cherry Studio.

Для базы знаний надежнее всего использовать провайдеров Embedding и Rerank, явно поддерживаемых в V2. Для генерации изображений используйте провайдеров и модели, фактически доступные на странице рисования.

## PDF и вложения

Текущая версия V2 сначала извлекает текст PDF локально, а затем отправляет его диалоговой модели MaaS:

- текстовые PDF обычно можно обработать;
- для отсканированных документов сначала требуется OCR;
- таблицы, сложное форматирование и сведения из изображений могут быть потеряны;
- извлеченный текст расходует контекст модели и оплачиваемые токены;
- изображения из PDF необходимо отдельно отправлять визуальной модели.

Этот процесс не равнозначен нативному API загрузки файлов или понимания документов Huawei Cloud.

Перед загрузкой документов, изображений или содержимого базы знаний убедитесь, что это соответствует требованиям к региону хранения данных, конфиденциальности и безопасности вашей организации.

## Пользовательский сервис инференса в реальном времени

Для пользовательского сервиса инференса в реальном времени также необходимо учитывать:

- запущен ли сервис;
- находятся ли пул ресурсов и OBS в том же регионе, что и MaaS;
- включен ли Endpoint в список разрешенных для Key;
- включена ли проверка содержимого;
- QPS и тайм-аут;
- стоимость вычислений и хранения;
- статус обновления или остановки сервиса.

Если у каждого пользовательского сервиса свой Base URL, создайте отдельного провайдера для каждого URL. Если несколько моделей используют общий стандартный Base URL, повторно создавать провайдера не требуется.

## Частые проблемы

### Возвращается 401

API Key неверен, еще не активирован, не соответствует региону либо IP, модель или Endpoint отсутствуют в списке разрешенных для Key. Проверьте права Key и повторите запрос.

### Возвращается 403

Ограничены разрешения IAM, доступ к модели, проверка содержимого или состояние аккаунта. Посмотрите конкретный код ошибки в консоли MaaS.

### Возвращается 404

Указан неверный Base URL, версия API, путь или Model ID. Снова скопируйте полный URL из инструкции по вызову и удалите `/chat/completions` по описанному правилу.

### Возвращается 429

Достигнуто ограничение QPS или параллельности MaaS, модели или пользовательского сервиса инференса в реальном времени. Уменьшите параллельность и дождитесь восстановления.

### Возвращается 400

Модель не принимает текущую роль сообщения, вложение или параметр рассуждения. Удалите пользовательские параметры и проверьте минимальный текстовый запрос.

### Список моделей пуст

Пользовательский сервис может не предоставлять `/models`. Скопируйте параметр `model` из инструкции по вызову и добавьте его вручную.

### Только что созданный Key считается недействительным

Для активации MaaS Key может потребоваться несколько минут. Проверьте Key, регион и Base URL, немного подождите и повторите запрос.

### Для каждой модели нужно создавать отдельного провайдера

Не обязательно. Модели, использующие общий Base URL MaaS Standard API и Key, можно разместить у одного провайдера. Разделять их нужно только при разных адресах вызова или аутентификации.

### Почему в старом руководстве требуется добавлять `#`

Это устаревший способ обеспечения совместимости для полного адреса интерфейса в старой версии Cherry Studio. В V2 укажите Base URL без `/chat/completions` и не добавляйте `#`.

### Пользовательский сервис вызывается на веб-странице, но не работает в Cherry Studio

Сервис может использовать формат, несовместимый с OpenAI, старую аутентификацию AppCode или по подписи, пользовательский путь, либо его Endpoint отсутствует в списке разрешенных для Key. Обычный пользовательский провайдер не может автоматически адаптировать эти различия.

### После включения рассуждения возникает ошибка параметров

Верните настройку рассуждения к значению по умолчанию. В текущей версии V2 нет специальной адаптации параметров рассуждения Huawei Cloud MaaS.

Общие настройки описаны в разделах [Провайдеры моделей](README.md) и [Настройки провайдеров моделей](../../cherrystudio/preview/settings/providers.md). Актуальные способы вызова Huawei Cloud MaaS смотрите в документации: [спецификация вызова API](https://support.huaweicloud.com/intl/zh-cn/model-call-maas/model-call-017.html), [MaaS Standard API V2](https://support.huaweicloud.com/intl/zh-cn/model-call-maas/model-call-019.html), [вызов сервиса моделей](https://support.huaweicloud.com/intl/zh-cn/inference-maas/maas-modelarts-0011.html) и [формат API URL](https://support.huaweicloud.com/intl/zh-cn/maas_faq/maas_faq_0005.html). Каналы обратной связи указаны в разделе [Обратная связь и предложения](../../question-contact/suggestions.md).
