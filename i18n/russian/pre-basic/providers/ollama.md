# Ollama

Ollama позволяет запускать локальные модели в macOS, Windows и Linux, а также вызывать облачные модели через Ollama Cloud. Cherry Studio V2 использует нативный Chat API Ollama и синхронизирует модели, видимые текущему экземпляру, из `/api/tags`.

При локальном запуске вывод модели и запросы чата по умолчанию обрабатываются на вашем устройстве. Если выбрать модель Cloud, облачный API Ollama или возможности веб-поиска, запросы всё равно будут покидать локальное устройство.

{% hint style="info" %}
Кнопка **Добавить** и синхронизация моделей в Cherry Studio только считывают список уже существующих моделей Ollama и не скачивают их веса. Сначала загрузите модель в Ollama, затем вернитесь в Cherry Studio и выполните синхронизацию.
{% endhint %}

## Выбор способа использования

| Способ | Base URL | API Key |
| --- | --- | --- |
| Ollama на том же компьютере | `http://localhost:11434` | Оставить пустым |
| Ollama в локальной сети или на собственном удалённом сервере | Фактический адрес сервера | Зависит от обратного прокси |
| Прямое подключение к Ollama Cloud | `https://ollama.com` | Ollama API Key |
| Проксирование модели Cloud локальной Ollama | `http://localhost:11434` | После локального входа обычно оставить пустым |

Локальный API по умолчанию не требует авторизации. Если API Key не пуст, Cherry Studio отправляет `Authorization: Bearer ...`; это можно использовать для Ollama Cloud или обратного прокси с Bearer-авторизацией.

## Установка Ollama

Загрузите версию для своей системы с [официального сайта Ollama](https://ollama.com/) и установите её.

В Linux также можно использовать официальный сценарий установки:

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

После установки убедитесь, что сервис запущен:

```bash
ollama list
```

Если команда возвращает список моделей, Ollama CLI и локальный сервис в основном готовы к работе.

## Загрузка модели

Выберите модель и тег в [библиотеке моделей Ollama](https://ollama.com/library), затем выполните:

```bash
ollama pull <model>:<tag>
```

Например:

```bash
ollama pull gemma3
```

Распространённые команды управления:

```bash
ollama list
ollama ps
ollama stop <model>
ollama rm <model>:<tag>
```

- `ollama list`: показать загруженные модели.
- `ollama ps`: показать загруженные сейчас модели и использование CPU/GPU.
- `ollama stop`: выгрузить модель из оперативной или видеопамяти.
- `ollama rm`: удалить локальные файлы модели.

Тег модели влияет на число параметров, способ квантования, контекст и занимаемое место на диске. Не ориентируйтесь только на название серии: выбирайте конкретный тег с учётом оперативной памяти, видеопамяти и задачи.

## Настройка в Cherry Studio

1. Откройте `Настройки → Провайдеры моделей`.
2. Переключите фильтр слева на **Все поставщики**.
3. Выберите **Ollama**.
4. При локальном использовании сохраните Base URL `http://localhost:11434`.
5. Оставьте API Key локального сервиса пустым.
6. Включите провайдера переключателем в верхней части страницы.
7. Нажмите **Добавить**, чтобы считать список моделей Ollama.
8. Проверьте предварительный результат синхронизации и примените изменения.
9. Включите только те модели, которые собираетесь использовать.

Cherry Studio нормализует `http://localhost:11434`, адрес с `/v1` или адрес с `/api` до нативного пути Ollama `/api`. Чтобы избежать путаницы, рекомендуется указывать адрес хоста без конкретного интерфейса.

Если только что загруженная модель не появилась, сначала убедитесь, что `ollama list` показывает точно такой же тег, а затем снова нажмите **Добавить**.

## API Key и модели Cloud

### Использование модели Cloud через локальную Ollama

Сначала войдите в Ollama:

```bash
ollama signin
```

Затем загрузите или запустите модель с тегом `:cloud` по официальной инструкции. Cherry Studio продолжает подключаться к `http://localhost:11434`, а локальная Ollama выполняет облачную авторизацию.

### Прямое подключение к Ollama Cloud

1. Создайте API Key в учётной записи Ollama.
2. Измените Base URL на `https://ollama.com`.
3. Введите этот ключ в поле API Key.
4. Синхронизируйте доступные облачные модели.
5. Запустите проверку подключения и состояния модели.

{% hint style="warning" %}
Не помещайте API Key в сообщения чата, документацию, репозиторий кода или снимки экрана с описанием проблемы. Если Cloud Key раскрыт, немедленно отзовите его в учётной записи Ollama и создайте новый.
{% endhint %}

Локальная модель не становится облачной автоматически. Проверьте тег модели и хост Ollama, к которому подключается клиент, чтобы правильно понимать, где фактически обрабатываются данные.

## Выбор модели чата, зрения и инструментов

Возможности модели Ollama определяются самой моделью и тегом. Cherry Studio распознаёт распространённые возможности по ID модели.

### Обычный чат

Любая генеративная модель с поддержкой Ollama Chat API подходит для обычного чата. При первом запросе необходимо загрузить веса, поэтому ответ может быть заметно медленнее последующих.

### Обработка изображений

Выберите в библиотеке Ollama модель с явной отметкой поддержки Vision. После синхронизации проверьте, отображает ли Cherry Studio возможность работы с изображениями, а затем загрузите для теста одно небольшое изображение.

- Похожие названия моделей не означают одинаковую поддержку изображений.
- Разные теги могут иметь разные возможности.
- Изображения увеличивают расход контекста и памяти.
- Если ID модели не распознан автоматически, не имитируйте возможность, изменяя только отображаемое имя.

### Вызов инструментов и MCP

Для стабильной работы MCP в Cherry Studio модель должна нативно поддерживать Tool Calling.

1. Выберите в библиотеке модель с явно заявленной поддержкой вызова инструментов.
2. Сначала проведите обычный обмен сообщениями.
3. Включите только один простой инструмент MCP.
4. Явно попросите модель вызвать инструмент.
5. Убедитесь, что модель действительно инициировала вызов.
6. Затем добавьте другие инструменты.

Некоторые небольшие модели выводят текст о «намерении вызвать инструмент», но не создают структурированный вызов. В этом случае выберите модель с более сильными возможностями инструментов, а не добавляйте всё больше инструкций.

## Настройка режима мышления

Ollama Chat API управляет мышлением с помощью параметра `think`:

- Для моделей с поддержкой многоуровневого рассуждения GPT-OSS Cherry Studio может отправлять низкий, средний или высокий уровень.
- Другие модели с мышлением обычно принимают только включение или отключение.
- При выборе **Выключить** отправляется `think: false`.
- При значении по умолчанию или включении фактическое поведение всё равно зависит от модели.

Если модель не поддерживает `think` и возвращает ошибку параметра, выключите мышление или используйте правильный тег модели. Не применяйте параметр мышления одной модели ко всем локальным моделям.

## Контекст и использование оборудования

Фактический контекст Ollama определяется моделью, настройками сервера и доступной памятью. Более длинный контекст значительно увеличивает расход RAM или VRAM.

Контекст по умолчанию можно задать при запуске Ollama:

```bash
OLLAMA_CONTEXT_LENGTH=8192 ollama serve
```

Чтобы проверить, работает ли модель на GPU, выполните:

```bash
ollama ps
```

В столбце `PROCESSOR` отображается доля загрузки на CPU, GPU или в смешанном режиме.

Если контекст модели в Cherry Studio больше фактической настройки Ollama, сервер всё равно может обрезать входные данные или вернуть ошибку превышения лимита. Ориентируйтесь на конфигурацию среды выполнения и журналы Ollama.

## Загрузка моделей и параллельность

По умолчанию Ollama выгружает модель после периода бездействия, освобождая ресурсы. Для настройки можно использовать `OLLAMA_KEEP_ALIVE`, `OLLAMA_MAX_LOADED_MODELS`, `OLLAMA_NUM_PARALLEL` и `OLLAMA_MAX_QUEUE`.

- Постоянная загрузка модели сокращает ожидание первого ответа, но непрерывно занимает оперативную или видеопамять.
- Чем выше параллельность, тем больше памяти контекста требуется каждой модели.
- Одновременная загрузка нескольких больших моделей может вызвать постановку в очередь или выгрузку.
- Когда очередь заполнена, сервер может вернуть 503.

Не повышайте только параметры параллельности. Сначала проверьте запас ресурсов с помощью `ollama ps` и системного монитора.

## База знаний и модели эмбеддингов

Ollama может предоставлять локальные модели эмбеддингов для базы знаний и [глобальной памяти](../../advanced-basic/memory.md).

1. Загрузите из библиотеки специальную модель эмбеддингов.
2. Вернитесь в Cherry Studio и синхронизируйте модели.
3. Убедитесь, что модель распознана как модель эмбеддингов.
4. Выберите её в базе знаний.
5. Определите размерность и запустите проверку состояния.
6. Затем импортируйте документы.

Cherry Studio не поддерживает модели повторного ранжирования Ollama. Если нужен Rerank, выберите другого провайдера.

После использования модели эмбеддингов в существующей базе знаний не меняйте модель или размерность без необходимости, иначе обычно потребуется заново построить векторный индекс.

## PDF и вложения

Текущая V2 не отправляет PDF непосредственно в Ollama. Cherry Studio сначала локально извлекает текст PDF, а затем передаёт его модели:

- PDF с текстовым слоем обычно можно обработать.
- Для сканированных документов сначала требуется OCR.
- Информация в таблицах, сложной вёрстке и изображениях может потеряться.
- Извлечённый текст расходует контекст модели.
- Изображения из PDF необходимо отдельно отправлять модели зрения.

## Подключение к удалённой Ollama

По умолчанию Ollama прослушивает только `127.0.0.1:11434`. Чтобы Cherry Studio на другом устройстве могла подключиться, задайте адрес прослушивания на хосте Ollama, например:

```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

Способ настройки переменной среды и перезапуска сервиса зависит от системы. См. [Ollama FAQ](https://docs.ollama.com/faq).

{% hint style="danger" %}
Не открывайте порт Ollama без авторизации напрямую в интернет. Даже в локальной сети используйте брандмауэр; для доступа через интернет используйте VPN или обратный прокси с HTTPS и авторизацией.
{% endhint %}

При подключении к Ollama в Docker, виртуальной машине или WSL `localhost` указывает на систему, где работает Cherry Studio, а не обязательно на контейнер или виртуальную машину. Используйте доступный адрес хоста и проверьте перенаправление портов.

## Проверка подключения

1. Выполните `ollama list` на хосте Ollama.
2. Убедитесь, что целевая модель загружена.
3. Запустите проверку подключения провайдера в Cherry Studio.
4. Нажмите **Добавить**, чтобы синхронизировать модели.
5. Запустите проверку состояния модели.
6. Вернитесь в чат и отправьте простое сообщение.
7. Затем проверьте мышление, изображения, MCP или базу знаний.

Если не работает и локальная команда, сначала исправьте Ollama. Если не работает только Cherry Studio, проверьте прежде всего Base URL, сеть и тег модели.

## Частые вопросы

### Не удаётся подключиться к `localhost:11434`

Ollama не запущена, порт изменён или соединение блокирует брандмауэр. Сначала выполните `ollama list` и проверьте журналы Ollama.

### Список моделей пуст

На текущем хосте Ollama нет загруженных моделей или Cherry Studio подключена к неверному хосту. `ollama list` и Cherry Studio должны обращаться к одному экземпляру.

### Только что скачанная модель не найдена

Снова нажмите **Добавить**, чтобы синхронизировать список, и используйте полное имя и тег из `ollama list`. Синхронизация Cherry Studio не выполняет скачивание вместо вас.

### Первый ответ очень медленный

Ollama загружает модель в оперативную или видеопамять. Проверьте место загрузки с помощью `ollama ps`; последующие запросы обычно выполняются быстрее.

### Возвращается нехватка памяти, происходит сбой или запрос постоянно ожидает

Выберите модель с меньшим числом параметров или более сильным квантованием, сократите контекст, уменьшите параллельность и остановите другие загруженные модели.

### Возвращается 503

Нагрузка на сервер слишком высока или очередь заполнена. Уменьшите параллельность, дождитесь завершения текущего запроса или измените настройки очереди Ollama.

### Недоступны изображения или MCP

Убедитесь, что конкретный тег модели поддерживает соответствующую возможность и Cherry Studio правильно её распознала. Работа обычного чата не означает поддержку зрения или инструментов.

### Удалённое подключение отклонено

Убедитесь, что Ollama прослушивает не только локальный адрес, порт открыт, а путь обратного прокси настроен правильно. Не решайте проблемы подключения через интернет отключением всех мер безопасности.

Дополнительные настройки описаны на страницах [Провайдеры моделей](README.md) и [Настройки провайдеров моделей](../../cherrystudio/preview/settings/providers.md). API Ollama описан в [официальной документации](https://docs.ollama.com/api/introduction), а каналы обратной связи — на странице [Отзывы и предложения](../../question-contact/suggestions.md).
