# Azure OpenAI

Встроенный шаблон Azure OpenAI в Cherry Studio V2 предназначен для подключения к моделям, развёрнутым в Microsoft Azure. Он выбирает Azure Responses или способ вызова через развёртывание в зависимости от **API Version**, поэтому Base URL, API Version и ID модели должны соответствовать настройкам ресурса Azure.

{% hint style="info" %}
Azure OpenAI и официальный API OpenAI — независимые службы. Endpoint, API Key, API Version и имя развёртывания ресурса Azure нельзя напрямую вводить в шаблон OpenAI.
{% endhint %}

## Перед началом

Подготовьте в [Azure Portal](https://portal.azure.com/) следующие данные:

- Endpoint ресурса Azure AI Foundry или Azure OpenAI
- API Key этого ресурса
- API Version, поддерживаемую текущим ресурсом
- Хотя бы одно доступное для вызова развёртывание модели

Если используется API Version в формате даты, также запомните **имя развёртывания** каждой модели. Его задаёт пользователь в Azure, поэтому оно может отличаться от названия базовой модели.

## Настройка Azure OpenAI

1. Откройте `Настройки → Провайдеры моделей`.
2. Переключите фильтр слева на **Все поставщики** и выберите **Azure OpenAI**.
3. Введите API Key ресурса Azure.
4. Введите Endpoint ресурса в поле Base URL, например `https://<resource>.openai.azure.com`.
5. Введите API Version, которую сейчас поддерживает ресурс Azure.
6. Включите переключатель провайдера в верхней части страницы.
7. Добавьте и включите модели, которые планируете использовать.
8. Запустите проверку подключения и проверку работоспособности моделей.

{% hint style="warning" %}
В поле Base URL указывайте только Endpoint ресурса. Не добавляйте `/openai`, `/v1`, `/chat/completions` или путь развёртывания: Cherry Studio дополнит путь запроса согласно текущей конфигурации.
{% endhint %}

{% hint style="danger" %}
Не добавляйте Azure API Key в сообщения чата, документы, репозитории кода или снимки экрана с описанием проблемы. В случае утечки немедленно создайте Key заново в Azure Portal.
{% endhint %}

## Выбор API Version

Cherry Studio выбирает способ вызова на основе API Version:

| API Version | Способ обработки Cherry Studio | Важные настройки модели |
| --- | --- | --- |
| `v1` или `preview` | Используется способ Azure Responses | Настройте маршрутизацию моделей в соответствии с текущим ресурсом Azure |
| Версия в формате даты, например `2024-xx-xx-preview` | Используется URL развёртывания Azure | ID модели должен совпадать с именем развёртывания в Azure |

API Version должна быть значением, которое фактически поддерживает ресурс Azure. Пример в интерфейсе показывает только формат и не означает, что эта версия подходит вашему ресурсу.

Если после обновления существующее подключение внезапно возвращает 404, сначала проверьте текущие Endpoint, API Version и имя развёртывания в Azure Portal или [документации Azure OpenAI](https://learn.microsoft.com/azure/ai-services/openai/), а затем измените настройки Cherry Studio.

## Добавление и включение моделей

Нажмите **Добавить** в списке моделей, проверьте предварительный просмотр синхронизации и примените изменения. Если Azure не возвращает доступный список, нажмите **Пользовательский** и введите модель вручную.

При использовании API Version в формате даты:

- В поле **ID модели** введите имя развёртывания в Azure.
- Не вводите только название семейства базовой модели, если оно не совпадает с именем развёртывания.
- Несколько развёртываний необходимо добавлять отдельно.
- После удаления или переименования развёртывания Azure также обновите модель в Cherry Studio.

Например, если в Azure модели присвоено имя развёртывания `support-prod`, в поле ID модели в Cherry Studio следует указать `support-prod`, а не угадывать его по названию базовой модели.

## Проверка подключения

1. Убедитесь, что Base URL не содержит дополнительного пути API.
2. Убедитесь, что API Key относится к тому же ресурсу Azure.
3. Убедитесь, что ресурс поддерживает указанную API Version.
4. Выберите добавленную и включённую модель.
5. Запустите проверку подключения.
6. Затем запустите проверку работоспособности модели.
7. Вернитесь на экран чата и отправьте простое сообщение.

Успешная проверка подключения подтверждает только пригодность учётных данных и базового запроса. Если вы планируете использовать изображения, рассуждения или вызов инструментов, отдельно проверьте поддержку этих возможностей моделью и развёртыванием.

## Управление несколькими ресурсами или развёртываниями

Если у ресурсов Azure различаются Endpoint, Key или API Version, скопируйте провайдера Azure OpenAI и настройте отдельные экземпляры:

- Присвойте каждой копии понятное имя.
- В каждой копии оставьте только развёртывания, которые действительно существуют в этом ресурсе.
- Не смешивайте Key или имена развёртываний других ресурсов в одной копии.
- При обновлении API Version сначала протестируйте одну копию и только потом обновляйте остальные подключения.

Так можно изолировать рабочие, тестовые или расположенные в разных регионах ресурсы и упростить поиск проблем с квотами и правами.

## Частые вопросы

### Возвращается 401

API Key недействителен, скопирован не полностью или не принадлежит тому же ресурсу Azure, что и Base URL. Повторно проверьте данные на странице Keys and Endpoint ресурса.

### Возвращается 404

По очереди проверьте Base URL, API Version и имя развёртывания модели. Частые причины: дополнительный путь в адресе, отсутствие поддержки выбранной версии в формате даты или использование названия базовой модели вместо имени развёртывания.

### Возвращается 429

Текущий ресурс, регион или развёртывание достигли ограничения скорости или квоты. Проверьте квоту и использование в Azure Portal. Смена названия модели в Cherry Studio не позволяет обойти ограничение ресурса.

### Не удаётся синхронизировать модели

Некоторые конфигурации Azure не возвращают список моделей, пригодный для прямого использования. Нажмите **Пользовательский**, добавьте модель по фактическому развёртыванию Azure и запустите проверку работоспособности.

### Что выбрать: `v1`, `preview` или версию в формате даты

Ориентируйтесь на способ, который сейчас поддерживается ресурсом Azure и официальной документацией. `v1` или `preview` используют Responses, а версия в формате даты — URL развёртывания. Не меняйте API Version только на основании названия модели.

Дополнительные общие настройки см. в разделах [Провайдеры моделей](README.md) и [Настройки провайдеров моделей](../../cherrystudio/preview/settings/providers.md). Каналы обратной связи перечислены на странице [Отзывы и предложения](../../question-contact/suggestions.md).
