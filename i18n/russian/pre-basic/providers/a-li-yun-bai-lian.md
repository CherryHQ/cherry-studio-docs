# Alibaba Cloud Model Studio

Alibaba Cloud Model Studio (Bailian) предоставляет Qwen и модели нескольких сторонних поставщиков. В Cherry Studio V2 встроен провайдер Model Studio с поддержкой совместимого с OpenAI чата, совместимых вызовов Anthropic, Embedding, Rerank и отдельного канала генерации и редактирования изображений.

Адреса по умолчанию для региона Китай (Пекин) в V2:

| Протокол | Base URL по умолчанию |
| --- | --- |
| Совместимость с OpenAI | `https://dashscope.aliyuncs.com/compatible-mode/v1/` |
| Совместимость с Anthropic | `https://dashscope.aliyuncs.com/apps/anthropic` |

{% hint style="info" %}
API Key, Base URL и список моделей Model Studio разделены по регионам и не взаимозаменяемы. Пекинский ключ с адресом Сингапура или сингапурский ключ с адресом Пекина обычно возвращает 401.
{% endhint %}

## Подготовка к использованию

Перед первым использованием API Model Studio обычно требуется:

1. Зарегистрировать учётную запись Alibaba Cloud и войти.
2. Пройти проверку настоящего имени.
3. Активировать Alibaba Cloud Model Studio.
4. Выбрать нужный регион.
5. Создать API Key.
6. Проверить баланс, бесплатную квоту или права подписки.
7. Записать ID соответствующего рабочего пространства.

Модели, цены, бесплатные квоты и региональная доступность меняются. На этой странице не фиксируется стоимость; ориентируйтесь на [список моделей Model Studio](https://help.aliyun.com/zh/model-studio/models) и счета в консоли.

## Выбор региона и Base URL

Model Studio продвигает отдельные домены рабочих пространств. Обычно они стабильнее старого общего домена DashScope, при этом `{WorkspaceId}` необходимо заменить фактическим ID рабочего пространства.

Распространённые адреса с совместимостью OpenAI:

| Регион | Base URL |
| --- | --- |
| Китай (Пекин), по умолчанию | `https://dashscope.aliyuncs.com/compatible-mode/v1/` |
| Китай (Пекин), отдельный домен | `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/` |
| Сингапур | `https://{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1/` |
| Япония (Токио) | `https://{WorkspaceId}.ap-northeast-1.maas.aliyuncs.com/compatible-mode/v1/` |
| Германия (Франкфурт) | `https://{WorkspaceId}.eu-central-1.maas.aliyuncs.com/compatible-mode/v1/` |
| США (Вирджиния) | `https://dashscope-us.aliyuncs.com/compatible-mode/v1/` |

В соответствующем совместимом адресе Anthropic конечный путь обычно заменяется на `/apps/anthropic`. Поддерживаемые регионы и протоколы могут различаться по модели. Копируйте адрес со страницы модели, а не определяйте по имени.

{% hint style="warning" %}
Не вводите `{WorkspaceId}` в Cherry Studio без замены. ID можно посмотреть на странице управления рабочими пространствами Model Studio; обычно он выглядит как `llm-...`.
{% endhint %}

## Получение API Key

1. Откройте [управление API Key Model Studio](https://bailian.console.aliyun.com/?tab=model#/api-key).
2. Проверьте целевой регион в правом верхнем углу.
3. Нажмите **Создать API Key**.
4. Выберите рабочее пространство.
5. Выберите все разрешения либо настройте белый список IP и диапазон моделей по требованиям организации.
6. Введите понятное описание.
7. Сразу после создания скопируйте и сохраните ключ.

Новый ключ с оплатой по факту может начинаться с `sk-ws` и показывается только один раз при создании; старые ключи `sk-` также могут продолжать работать.

{% hint style="danger" %}
API Key равнозначен учётным данным. Не помещайте его в чат, документацию, репозиторий кода или снимки экрана с проблемой. При утечке немедленно сбросьте или удалите ключ в консоли Model Studio.
{% endhint %}

## Настройка в Cherry Studio

### Использование пекинского адреса по умолчанию

1. Откройте `Настройки → Провайдеры моделей`.
2. Переключите фильтр слева на **Все поставщики**.
3. Выберите **Bailian / Alibaba Cloud Model Studio**.
4. Вставьте API Key региона Пекин.
5. Сохраните OpenAI Base URL `https://dashscope.aliyuncs.com/compatible-mode/v1/`.
6. Включите провайдера переключателем в верхней части страницы.
7. Нажмите **Добавить** или синхронизируйте модели.
8. Проверьте предварительный результат и примените изменения.
9. Включите только нужные модели.
10. Запустите проверку состояния модели.

### Использование другого региона или отдельного домена

1. Скопируйте API Host целевого рабочего пространства в консоли Model Studio.
2. В Cherry Studio измените OpenAI Base URL на соответствующий адрес `/compatible-mode/v1/`.
3. Для совместимого рабочего процесса Anthropic также обновите Anthropic Base URL.
4. Используйте API Key, созданный в **том же регионе и в том же плане оплаты**.
5. Повторно синхронизируйте модели.
6. Запустите проверку состояния каждой модели.

V2 выводит хост интерфейса изображений из заданного пользователем OpenAI Base URL. Поэтому после перехода на отдельный домен запросы изображений также используют этот домен и не возвращаются принудительно к общему пекинскому домену.

## Синхронизация и добавление моделей

Набор моделей Model Studio часто меняется, а встроенный список V2 служит только для первого отображения. При синхронизации ориентируйтесь на текущий ответ Model Studio.

Рекомендации:

1. Сначала проверьте соответствие региона и ключа.
2. Синхронизируйте модели.
3. Просмотрите добавленные, обновлённые и удалённые элементы.
4. Примените результат.
5. Проверьте метки возможностей моделей.
6. Удалите устаревшие модели, оставленные вручную.
7. Запустите проверку состояния каждой модели.

Если результат неполный, скопируйте полный Model ID со страницы Model Studio и добавьте вручную. Регистр, косая черта и суффикс версии являются частью ID; сторонняя модель может содержать префикс организации.

{% hint style="warning" %}
Наличие модели в шаблоне V2 или другом регионе не означает права текущего API Key на вызов. Итоговое разрешение совместно определяется сервером Model Studio, правами рабочего пространства и региональным списком моделей.
{% endhint %}

## Модели чата

Обычный чат использует совместимый с OpenAI Chat Completions.

Рекомендуемый порядок проверки:

1. Отправьте короткое текстовое сообщение.
2. Проверьте потоковый вывод.
3. Добавьте системный запрос.
4. Проверьте более длинный контекст.
5. Затем проверьте изображения, мышление и инструменты.

Model Studio предоставляет Qwen и сторонние модели. Даже модель того же поставщика при вызове через Model Studio должна использовать Model ID и параметры со страницы Model Studio; не копируйте ID другой платформы.

## Совместимость Anthropic и Code Tools

Model Studio предоставляет совместимый с Anthropic Messages API для инструментов программирования и процессов Agent, поддерживающих пользовательский адрес Anthropic.

В Cherry Studio:

1. Убедитесь, что целевая модель поддерживает совместимый протокол Anthropic.
2. Введите Anthropic Base URL для нужного региона.
3. Согласуйте API Key и регион.
4. Сначала проведите обычный чат.
5. Затем проверьте Code Tools или сценарий Agent.

Совместимые адреса OpenAI и Anthropic используют разные пути. Изменение только OpenAI Base URL не гарантирует, что процесс Anthropic автоматически направлен в тот же регион.

## Режим мышления

Модели Qwen, DeepSeek, GLM, Kimi и другие в Model Studio могут использовать разные параметры мышления. Cherry Studio V2 адаптирует `enable_thinking`, бюджет мышления и другие параметры по серии модели.

Если после включения мышления возникает ошибка:

1. Верните настройку к значению **По умолчанию**.
2. Удалите пользовательские параметры модели.
3. Убедитесь, что используется текущий Model ID.
4. Проверьте официальный пример модели в текущем регионе.
5. Повторите проверку состояния.

Некоторые модели позволяют только включить или выключить мышление без уровней `low`, `medium`, `high`. Не копируйте напрямую параметры рассуждения с другой платформы в Model Studio.

## Зрение и мультимодальность

Получать изображения, аудио или видео может только модель с явной поддержкой соответствующих вложений.

При проверке модели зрения:

1. Синхронизируйте последний Model ID.
2. Убедитесь, что у модели отображается возможность изображений.
3. Сначала загрузите одно небольшое изображение.
4. Проверьте, действительно ли модель понимает содержимое.
5. Затем попробуйте несколько изображений, видео или высокое разрешение.

Текстовая, зрительная и Omni-версии одной серии могут быть разными моделями. Вложения увеличивают контекст, сетевое время и стоимость.

## MCP и вызов инструментов

Для MCP Cherry Studio модель должна поддерживать структурированный Tool Calling.

1. Сначала убедитесь, что обычный чат работает.
2. Включите только один простой инструмент MCP.
3. Явно попросите выполнить вызов.
4. Проверьте появление структурированного вызова.
5. Убедитесь, что результат инструмента возвращается модели.
6. Затем добавьте инструменты.

Текстовое описание намерения вызвать инструмент не является настоящим вызовом. В этом случае проверьте возможности модели, протокол, запрос и определение инструмента.

## Embedding, Rerank и база знаний

Model Studio предоставляет текстовые и мультимодальные Embedding, а также текстовые и мультимодальные Rerank. Текущие рекомендации страницы моделей могут включать:

- текстовый Embedding: `text-embedding-v4`;
- текстовый Rerank: `qwen3-rerank`;
- мультимодальный Embedding: `qwen3-vl-embedding`;
- мультимодальный Rerank: `qwen3-vl-rerank`.

Это примеры платформы, а не постоянный список. `gte-rerank` отключён 30 мая 2026 года и не должен настраиваться по старой инструкции.

При создании базы знаний:

1. Добавьте доступную сейчас модель Embedding.
2. Убедитесь, что Cherry Studio распознаёт её как модель эмбеддингов.
3. Определите размерность вектора.
4. Запустите проверку состояния.
5. Добавьте и проверьте модель Rerank.
6. Импортируйте несколько документов для проверки.
7. После проверки поиска и ранжирования выполните пакетный импорт.

После использования модели Embedding или размерности в существующей базе знаний не меняйте их напрямую, иначе обычно требуется перестроить векторный индекс.

Конечные точки и возможности Rerank Model Studio могут различаться по регионам. Если модель добавляется, но ранжирование завершается ошибкой, сначала выключите Rerank, чтобы сохранить базовый поиск, а затем проверьте версию V2, региональный интерфейс и разрешения модели.

## Генерация и редактирование изображений

Cherry Studio V2 реализует отдельный канал изображений Model Studio:

1. Выбирает нативный интерфейс изображений DashScope по модели.
2. Для асинхронной модели включает в запросе `X-DashScope-Async`.
3. Получает `task_id`.
4. Опрашивает состояние задачи.
5. После успеха считывает URL изображения.

V2 показывает режимы и параметры только для адаптированной модели, например:

- генерацию из текста;
- редактирование изображения;
- перевод изображения;
- размер;
- Seed;
- негативный запрос;
- водяной знак;
- эталонное изображение или тип функции у некоторых моделей.

Не каждая модель изображений на сайте Model Studio уже поддерживается текущей V2. Начинайте с моделей Model Studio, доступных на странице рисования Cherry Studio.

{% hint style="warning" %}
Задачи изображения могут оплачиваться по числу успешных выходных изображений. При первой проверке установите количество 1 и не отправляйте запрос повторно во время ожидания асинхронного результата.
{% endhint %}

Отмена ожидания в Cherry Studio прекращает только локальный опрос. DashScope не предоставляет общего интерфейса отмены задач для текущей V2, поэтому отправленная задача может продолжиться и создать расход.

## PDF и вложения

Текущая V2 сначала локально извлекает текст PDF, а затем отправляет его модели чата Model Studio:

- PDF с текстовым слоем обычно обрабатывается.
- Для сканированного документа сначала нужен OCR.
- Таблицы, сложная вёрстка и изображения могут потеряться.
- Извлечённый текст расходует контекст и средства.
- Изображения PDF нужно отдельно отправлять модели зрения.

Model Studio — облачный сервис. Перед загрузкой документа, изображения или базы знаний убедитесь в соответствии требованиям конфиденциальности, трансграничной передачи данных и безопасности организации; особенно учитывайте область обработки данных выбранного региона.

## Квоты, разрешения и ограничения

Model Studio может одновременно ограничиваться следующими факторами:

- балансом и бесплатной квотой;
- бюджетом рабочего пространства;
- белым списком IP ключа;
- разрешениями моделей ключа;
- RPM / TPM;
- числом параллельных задач;
- очередью задач изображений;
- доступностью региональных ресурсов.

Рекомендуется настроить в консоли бюджет и предупреждение об использовании, чтобы несколько автоматических задач не выполняли бесконечные повторы с одним ключом.

## Частые вопросы

### Возвращается 401

API Key неверен, сброшен или не совпадает по региону с Base URL. Сначала проверьте регион, затем скопируйте соответствующий ключ.

### Возвращается 403

Ключ не имеет разрешения модели, IP не входит в белый список, рабочее пространство не авторизовано или состояние учётной записи ограничено. Проверьте разрешения ключа и политику рабочего пространства.

### Возвращается 404

Base URL, Workspace ID, путь протокола или Model ID неверен. Не используйте URL страницы консоли как адрес API.

### Возвращается 429

Достигнут лимит RPM, TPM, параллельности или очереди. Уменьшите параллельность, сократите контекст и дождитесь восстановления; не запускайте немедленный цикл повторов.

### Недостаточный баланс или исчерпанная квота

Проверьте баланс, бесплатную квоту, бюджет рабочего пространства и способ оплаты модели. Разные модели могут использовать разные пулы квот.

### Список моделей пуст

Проверьте регион, API Key, Base URL и сетевой прокси. Также можно скопировать полный Model ID со страницы моделей текущего региона и добавить вручную.

### Модель из шаблона не работает

Шаблон V2 может быть старше отключения модели Model Studio или изменения региона. Повторно синхронизируйте и ориентируйтесь на список текущего региона.

### Обычный чат работает, а Agent или Code Tools — нет

Проверьте, не остался ли Anthropic Base URL на пекинском адресе по умолчанию, и поддерживает ли модель совместимый протокол Anthropic и вызов инструментов.

### Генерация изображения возвращает неверный адрес

Убедитесь, что OpenAI Base URL содержит правильный домен рабочего пространства и суффикс `/compatible-mode/v1/`. V2 выводит из него хост нативного интерфейса изображений.

### Задача изображения продолжает ожидать

Задача может оставаться в очереди, сетевой опрос завершился ошибкой, квоты недостаточно или модель загружена. Сначала проверьте ошибку и состояние задачи Model Studio, не отправляйте запрос повторно.

### Модель Rerank выбирается, но не действует

Убедитесь, что модель не отключена, региональный интерфейс совместим, а Rerank действительно включён в базе знаний. При необходимости временно выключите ранжирование и сначала проверьте поиск Embedding.
