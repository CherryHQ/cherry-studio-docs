# Данные о моделях

Cherry Studio V2 больше не полагается на большую статическую таблицу моделей в документации. Версии моделей, размеры контекста, цены и возможности провайдеров меняются быстро, поэтому при длительном ручном сопровождении устаревшие сведения могут выглядеть как достоверные.

На этой странице описано, откуда приложение получает данные о моделях, что означает каждое поле и как проверить, действительно ли модель доступна у выбранного провайдера.

{% hint style="info" %}
Данные о модели в приложении используются для настройки и маршрутизации. Окончательным источником сведений о доступности, ограничениях и оплате остаются официальная документация провайдера, права в консоли и фактические ответы API.
{% endhint %}

## Откуда берутся данные о моделях

V2 объединяет несколько источников в итоговую карточку модели:

1. **Каталог моделей**: содержит базовые сведения — общее название, возможности, типы входных и выходных данных, контекст, параметры и цены.
2. **Переопределения провайдера**: описывают эндпоинты, особые ограничения, псевдонимы и заменяющие модели у конкретного провайдера.
3. **Список моделей провайдера**: некоторые провайдеры возвращают через API идентификаторы Model ID, доступные текущей учётной записи.
4. **Пользовательские настройки**: вручную добавленные модели, названия, метки возможностей, эндпоинты, ограничения и другие пользовательские сведения.

Наивысший приоритет имеют пользовательские настройки, затем переопределения провайдера, а после них — общий каталог моделей.

Если API провайдера возвращает только Model ID, Cherry Studio пытается дополнить сведения из каталога. Идентификатор, которого нет в каталоге, всё равно можно добавить как пользовательскую модель, но некоторые поля останутся незаполненными.

## Где посмотреть

Откройте **Настройки → Сервисы моделей** и выберите провайдера. В списке моделей можно:

* искать по названию модели или ID;
* фильтровать по возможностям;
* включать и отключать отдельные модели;
* массово включать модели из текущей выборки;
* открывать панель редактирования модели для просмотра и изменения некоторых полей;
* вручную добавлять модели, которые провайдер не показал автоматически.

В большинстве селекторов отображаются только включённые модели. Отключение модели не удаляет её настройки.

Полная настройка провайдера описана в разделе [Сервисы моделей](../pre-basic/providers/).

## Основные поля

### Отображаемое название и Model ID

| Поле | Назначение |
| :--- | :--- |
| Отображаемое название | Название в интерфейсе Cherry Studio; оно может отличаться от API ID |
| Model ID | Реальный идентификатор модели в запросах к API провайдера |
| Провайдер | Настройка, отвечающая за аутентификацию, эндпоинт и маршрутизацию запросов |
| Группа | Используется только для организации списка и не меняет поведение API |

Один Model ID может существовать у нескольких провайдеров. Внутри приложения уникальный идентификатор формируется из провайдера и Model ID. Однако при ручном добавлении обычно следует вводить API Model ID из документации провайдера и не добавлять внутренний префикс приложения самостоятельно.

### Тип эндпоинта

Тип эндпоинта определяет формат запроса. V2 поддерживает следующие модельные эндпоинты:

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* OpenAI Image Generation
* Jina Rerank

Одинаковое название модели не означает, что каждый провайдер поддерживает одни и те же эндпоинты. При неверном выборе обычно возникают ошибки `400`, `404`, недопустимые параметры инструментов или невозможность разобрать структуру ответа.

### Контекст и ограничения вывода

| Поле | Значение |
| :--- | :--- |
| Контекстное окно | Общий объём Token, который можно обработать в одном запросе |
| Максимальный ввод | Предельное число входных Token, разрешённое провайдером |
| Максимальный вывод | Предельное число выходных Token в одной генерации |

Эти значения нельзя просто складывать. Провайдер может задавать отдельные ограничения для изображений, определений инструментов, кеша, Token рассуждений или конкретного тарифного плана.

Не считайте сокращения `k` и `M` в документации точными доступными значениями. Если требуется указать число, возьмите целое значение из актуальной документации API провайдера и проверьте его минимальным запросом.

### Типы входных и выходных данных

Модель может отдельно объявлять поддерживаемые типы входных и выходных данных:

* текст;
* изображения;
* аудио;
* видео.

«Понимать изображения» и «создавать изображения» — разные возможности. Поддержка аудиоввода также не означает, что модель умеет генерировать речь.

### Метки возможностей

В списке моделей могут отображаться следующие возможности:

| Возможность | Описание |
| :--- | :--- |
| Понимание изображений | Принимает изображение и выдаёт текстовый результат |
| Генерация изображений | Создаёт или редактирует изображения |
| Понимание аудио | Принимает или распознаёт аудио |
| Генерация аудио | Создаёт аудио или речь |
| Понимание видео | Принимает и анализирует видео |
| Генерация видео | Создаёт видео |
| Рассуждение | Поддерживает настройку интенсивности рассуждений или процесса размышления |
| Вызов инструментов | Создаёт структурированные вызовы функций или инструментов |
| Встроенный веб-поиск | Модель или эндпоинт провайдера предоставляет возможность поиска |
| Embedding | Создаёт векторы для индексации и поиска в базе знаний |
| Rerank | Пересортировывает набор текстовых кандидатов |

Метки влияют на фильтрацию моделей, элементы интерфейса и маршрутизацию запросов. Ручное включение метки только сообщает Cherry Studio, как использовать модель, и **не добавляет модели провайдера реальную возможность**.

### Поддерживаемые параметры

Разные модели могут поддерживать разные параметры, например:

* Temperature
* Top P
* Top K
* Frequency Penalty
* Presence Penalty
* Max Tokens
* Stop Sequences
* System Message

Модели рассуждений могут игнорировать или отклонять часть традиционных параметров семплирования. При ошибке `unsupported parameter` сначала восстановите настройки по умолчанию, а затем включайте параметры по одному согласно актуальной официальной документации модели.

### Настройки рассуждений

У моделей рассуждений также могут быть указаны:

* тип рассуждений;
* доступные уровни интенсивности;
* минимальное, максимальное и стандартное число Token для размышления;
* поддержка чередующегося процесса размышления.

Фактически доступные значения зависят одновременно от модели, эндпоинта и реализации провайдера. Формат параметров одной и той же модели может различаться при вызове через OpenAI-совместимый эндпоинт и Anthropic Messages.

### Цена

Каталог может хранить цены входных и выходных данных, кеша, изображений, аудио и видео, но эти сведения подходят только для оценки:

* провайдер может изменить цены в любой момент;
* цены могут различаться по регионам, тарифам и каналам;
* рассуждения, кеширование, пакетная обработка и вызовы инструментов могут оплачиваться отдельно;
* сторонний посредник может использовать собственную схему тарификации.

Для оплаты и сверки расходов используйте счёт провайдера.

## Почему у моделей с одинаковым названием разные сведения

Распространённые причины:

* провайдер сопоставляет название с другим снимком или псевдонимом;
* используется другой тип эндпоинта;
* текущей учётной записи доступна только часть возможностей;
* провайдер ограничил контекст или длину ответа;
* агрегатор использует собственные Model ID и цены;
* различаются квантование, шаблон или параметры запуска локальной модели;
* пользователь ранее вручную изменил возможности или ограничения.

При сравнении записывайте не только отображаемое название, но и **провайдера, Model ID, эндпоинт и дату**.

## Ограничения автоматического получения списка

«Список моделей получен» означает лишь, что провайдер вернул набор Model ID. Это не гарантирует, что:

* у текущего API Key есть право вызывать модель;
* модель поддерживает изображения, инструменты, рассуждения или веб-поиск;
* сведения о контексте и цене полны;
* модель подходит для всех эндпоинтов;
* провайдер позже не отключит и не переименует модель.

После получения списка включите нужную модель и выполните реальный запрос.

## Как проверить модель

### 1. Базовое подключение

Проверьте API Host и учётные данные в настройках провайдера, затем выполните проверку подключения. После её успешного завершения отправьте короткий текст и получите реальный ответ в чате.

### 2. Проверяйте только нужные возможности

| Целевая возможность | Минимальный тест |
| :--- | :--- |
| Понимание изображений | Загрузите изображение без конфиденциальных данных и попросите описать конкретный элемент |
| Вызов инструментов | Подключите инструмент без побочных эффектов и попросите прочитать фиксированные сведения |
| Рассуждение | Используйте многошаговую задачу, которую можно проверить вручную, и убедитесь, что параметры приняты |
| Встроенный веб-поиск | Спросите о недавно обновлённом проверяемом факте и проверьте реальную историю поиска и ссылки |
| Embedding | Получите размерность и выполните один тест поиска по небольшому образцу документа |
| Rerank | Пересортируйте фиксированный набор текстов и проверьте, соответствует ли результат вопросу |
| Генерация изображений | Создайте тестовое изображение по простому промпту и проверьте формат ответа и размер |

### 3. Запишите тестовое окружение

Запишите как минимум:

* версию Cherry Studio;
* провайдера;
* Model ID;
* тип эндпоинта;
* дату теста;
* успешно проверенные возможности и параметры.

После обновления модели провайдером это позволит отличить «изменение поведения модели» от «изменения локальной настройки».

## Ручное изменение данных модели

Если сведений в каталоге недостаточно или провайдер использует пользовательский ID, модель можно отредактировать.

Перед изменением рекомендуется:

1. сохранить текущие Model ID, эндпоинт и возможности;
2. изменять только одно поле за раз;
3. сразу выполнять соответствующий минимальный тест;
4. при ошибке восстанавливать исходное значение.

{% hint style="warning" %}
Не включайте возможности вслепую только ради появления модели в определённом фильтре. Неверная метка Embedding, Rerank, генерации изображений или вызова инструментов может отправить запрос в несовместимый интерфейс.
{% endhint %}

## Частые вопросы

### Модель есть в консоли провайдера, но не отображается в Cherry Studio

Сначала попробуйте получить список моделей. Если модель не появилась, добавьте её вручную с точным Model ID от провайдера. Проверьте, нужны ли ей специальный эндпоинт, регион или версия API.

### Модель есть в списке, но запрос возвращает 404

Обычно не совпадают API Host, Model ID, регион или эндпоинт. Не меняйте регистр букв и не удаляйте суффикс версии только на основании отображаемого названия.

### Метки модели не соответствуют реальным возможностям

Сначала ориентируйтесь на официальную документацию провайдера и реальный запрос, затем измените метки возможностей. Если ошибка находится в общем каталоге, сообщите о ней через раздел [Отзывы и предложения](../question-contact/suggestions.md), приложив название провайдера, Model ID, ссылку на официальную документацию и результат теста.

### Доступный контекст меньше заявленного

Проверьте максимальный вывод, изображения, файлы, определения инструментов и объём истории сообщений. Агрегатор также может установить более низкий предел, чем разработчик модели.

### Цена отличается от счёта

Цена в каталоге может устареть или не относиться к текущему каналу. Не используйте её для финансовых расчётов; проверьте актуальную страницу цен и детализацию счёта провайдера.
