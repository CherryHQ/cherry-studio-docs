# Данные базы знаний

На этой странице объясняется, где Cherry Studio хранит данные базы знаний, какие данные могут быть отправлены провайдерам моделей и как безопасно удалить, создать резервную копию и перенести эти данные.

Если вы хотите только создать и использовать базу знаний, начните с [Учебного пособия по базе знаний](knowledge-base.md).

## Что хранит база знаний

Данные базы знаний версии V2 — это не один файл, который можно скопировать сам по себе. Они состоят из нескольких типов данных, которые работают вместе.

| Данные | Основное содержимое | Назначение |
| --- | --- | --- |
| Метаданные базы знаний | Имя, группа, модель, чанкинг и конфигурация извлечения | Позволяет приложению идентифицировать и управлять базой знаний |
| Записи источников данных | Оригинальный путь или URL, тип, статус и информация об ошибках | Отслеживает импортированный контент и прогресс обработки |
| Векторный индекс | Фрагменты документов, векторы и поля извлечения | Поддерживает тесты извлечения и чат-извлечение |
| Записи файлов и артефакты обработки | Ссылки на оригинальные файлы, разобранный текст и связанные данные | Поддерживает предварительный просмотр источников, повторное индексирование и обработку документов |

Метаданные и записи источников данных хранятся в основной базе данных SQLite Cherry Studio. Каждая база знаний также имеет свой локальный файл векторного хранилища libSQL.

{% hint style="warning" %}
Не создавайте резервную копию только векторного файла базы знаний. Он должен оставаться согласованным с ID базы знаний, записями источников данных и конфигурацией модели в основной базе данных. Восстановление одного этого файла обычно не позволяет восстановить всю базу знаний.
{% endhint %}

## Копируются ли локальные файлы?

Когда вы добавляете локальный файл в базу знаний, Cherry Studio записывает **оригинальный абсолютный путь** файла и связывает его через запись о файле. Оригинальный файл остается в своем существующем месте и не перемещается при добавлении в базу знаний.

Это имеет несколько прямых последствий:

* Перемещение, переименование или удаление оригинального файла может вызвать сбой предварительного просмотра и повторного индексирования
* Существующий векторный индекс не обновляется автоматически при изменении оригинального файла
* После изменения оригинального файла вы должны вручную выполнить его повторное индексирование из базы знаний
* При создании резервной копии данных Cherry Studio вы должны отдельно создать резервную копию внешних оригинальных файлов

Промежуточные артефакты, сгенерированные обработчиком файлов, могут храниться в собственном каталоге данных Cherry Studio, но они не заменяют долгосрочное резервное копирование оригинальных файлов.

## Местоположение хранения данных

Данные базы знаний находятся в каталоге пользовательских данных Cherry Studio. По умолчанию это обычно:

| Система | Каталог пользовательских данных по умолчанию |
| --- | --- |
| macOS | `~/Library/Application Support/CherryStudio` |
| Windows | `%APPDATA%\CherryStudio` |
| Linux | `~/.config/CherryStudio` |

Фактический каталог может отличаться в зависимости от метода установки, версии приложения, среды разработки или пользовательского каталога данных. Используйте текущий путь, указанный в **Настройки → Данные → Каталог данных**, как источник истины.

Типичный контент V2, связанный с базами знаний, включает:

* `cherrystudio.sqlite` в корне каталога пользовательских данных: метаданные базы знаний и источников данных
* `Data/KnowledgeBase`: файлы векторного хранилища, организованные по базам знаний
* `Data/Files`: файлы и артефакты обработки, управляемые Cherry Studio

{% hint style="info" %}
Эти внутренние пути предоставлены для уточнения объема резервного копирования. Не изменяйте файлы вручную во время работы приложения. Чтобы изменить весь каталог данных, см. [Изменение места хранения](../personalization-settings/storage.md).
{% endhint %}

## Какой контент покидает ваше устройство?

«База знаний хранится локально» не означает «весь рабочий процесс обработки выполняется локально». То, отправляется ли контент во внешние службы, зависит от выбранных вами обработчиков и моделей.

### Обработка документов

Если вы используете онлайн-сервис парсинга документов или OCR, оригинальный файл или его содержимое могут быть отправлены соответствующему провайдеру. При использовании локального обработчика этот этап может выполняться на вашем устройстве.

### Индексирование

При использовании онлайн-модели встраивания фрагменты текста отправляются поставщику встраивания, а возвращенные векторы сохраняются локально. Повторное индексирование вызывает службу встраивания снова.

### Извлечение и переранжирование

При запросе к базе знаний вопрос пользователя обрабатывается моделью встраивания. Если включена онлайн-модель переранжирования, вопрос и кандидатные фрагменты также отправляются поставщику переранжирования.

### Генерация ответов

При использовании базы знаний в чате вопрос пользователя и извлеченные фрагменты отправляются текущей модели чата в качестве контекста.

### Импорт веб-страниц

При импорте URL или Sitemap Cherry Studio обращается к целевому веб-сайту. Его сервер может записать IP-адрес, время доступа и детали запроса.

{% hint style="warning" %}
Прежде чем обрабатывать конфиденциальные материалы, такие как контракты, медицинская информация или внутренний код, проверьте все четыре этапа: обработка документов, встраивание, переранжирование и модель чата. Переключение только модели чата на локальную не гарантирует, что другие этапы не будут выполнять исходящие запросы.
{% endhint %}

## Как уменьшить объем отправляемых данных во внешнюю среду

Если ваши источники не могут быть отправлены третьим лицам:

1. Используйте локальные возможности парсинга документов и OCR.
2. Запустите локальную модель встраивания через Ollama, LM Studio или аналогичный инструмент.
3. Не включайте онлайн-модель переранжирования или замените ее на локальный сервис.
4. Выберите локальную модель для этапа чата.
5. Избегайте импорта внутренних веб-страниц, требующих аутентификации.

Для настройки локальных моделей см. [Модели встраивания](emb-models-info.md) и соответствующие руководства поставщиков моделей.

## Что происходит при удалении данных?

### Удаление источника данных

При удалении источника данных Cherry Studio удаляет его запись и векторные фрагменты. Для папки или Sitemap также обрабатываются развернутые дочерние элементы.

Удаление источника файлов из базы знаний **не удаляет оригинальный файл с диска**.

### Удаление чанка

Удаление отдельного фрагмента из деталей чанков удаляет только данные об извлечении этого фрагмента; это не изменяет оригинальный файл. Если вы позже повторно проиндексируете источник данных, удаленный фрагмент может быть создан снова в соответствии с текущими правилами чанкинга.

### Удаление всей базы знаний

При удалении базы знаний Cherry Studio сначала останавливает связанные фоновые задачи, а затем удаляет ее векторное хранилище и записи из основной базы данных.

Эта операция не удаляет внешние оригинальные файлы, на которые были сделаны ссылки во время импорта, но она удаляет конфигурацию базы знаний и существующий индекс. Перед удалением убедитесь, что у вас есть полная резервная копия, которую можно восстановить.

## Создание резервной копии базы знаний

### Рекомендуемый метод

1. Используйте встроенную функцию резервного копирования в **Настройки → Данные**.
2. Если вам нужно восстановить полную базу знаний, не включайте **Пропустить данные файлов**.
3. Отдельно создайте резервную копию всех внешних оригинальных файлов и папок.
4. Запишите поставщика моделей, модель встраивания и обработчик документов, которые вы использовали.
5. Регулярно проверяйте в безопасной среде возможность восстановления резервной копии.

Встроенная опция резервного копирования «Пропустить данные файлов» исключает содержимое `Data` из каталога пользовательских данных. Это содержимое включает векторные файлы базы знаний и артефакты обработки, управляемые Cherry Studio, поэтому резервная копия, созданная с использованием этой опции, не является полной резервной копией базы знаний.

### Копирование всего каталога данных

Чтобы создать снимок на уровне файлов, полностью закройте Cherry Studio перед копированием **всего каталога пользовательских данных**, а не только `Data/KnowledgeBase`.

Пока приложение запущено, в базу данных SQLite и векторные файлы могут записываться новые данные. Прямое копирование активных файлов может привести к несогласованному снимку.

### Проверки после восстановления

После восстановления не проверяйте только наличие имени базы знаний. Также:

* Откройте список источников данных и подтвердите их статусы и количество
* Предварительно просмотрите несколько источников
* Выполните тест поиска с фиксированным набором вопросов
* Проверьте цитируемые источники в чате
* Повторно проиндексируйте внешние файлы, которые необходимо обновить

После переключения между операционными системами или основными версиями, или после изменения модели встраивания, сначала проверьте восстановление на копии среды. Если пути к внешним файлам меняются между устройствами, ссылки на оригинальные пути могут перестать работать.

## Миграция и дисковое пространство

Использование диска для базы знаний в основном зависит от:

* Размера оригинальных источников и артефактов обработки
* Количества чанков
* Размерности векторов встраивания
* Количества баз знаний
* Данных, полученных в результате многократного импорта и повторного индексирования

Для перемещения каталога данных используйте настройку каталога данных Cherry Studio и выполните резервное копирование перед миграцией. После миграции проверьте как минимум один предварительный просмотр источника данных, тест поиска и цитирование в чате.

Если вам просто нужно освободить место на диске, сначала удалите неиспользуемые источники данных или базы знаний внутри приложения. Не удаляйте внутренние файлы базы данных напрямую.

## Часто задаваемые вопросы

### Оригинальные файлы остаются после удаления базы знаний?

Да. Внешние локальные файлы, на которые ссылается база знаний, не удаляются вместе с базой знаний. Удаление удаляет только записи и индекс, управляемые Cherry Studio.

### Можно ли продолжить извлечение после перемещения оригинального файла?

Существующий индекс может временно продолжать возвращать старые фрагменты, но предварительный просмотр и повторное индексирование завершатся ошибкой, поскольку оригинальный путь больше недействителен. Добавьте файл снова по его новому пути и проверьте результаты извлечения.

### Можно ли создать резервную копию только `Data/KnowledgeBase`?

Нет. Этот каталог содержит только векторное хранилище. Ему не хватает метаданных и связей источников данных из основной базы данных, а также он не включает внешние оригинальные файлы.

### Гарантирует ли локальная модель встраивания полностью автономную работу?

Не обязательно. Вы также должны убедиться, что обработчик документов, модель переранжирования и модель чата работают локально, и проверить, были ли импортированы какие-либо внешние веб-страницы.

### Взимается ли плата за перестроение индекса?

Если вы используете онлайн-сервисы обработки документов, встраивания или переранжирования с оплатой по факту использования, повторное индексирование может снова повлечь расходы на вызовы модели.
