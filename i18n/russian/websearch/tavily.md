# Веб-поиск Tavily

Tavily — сервис веб-поиска для приложений ИИ. В Cherry Studio V2 он находит веб-страницы по ключевым словам и передает модели заголовки, краткие описания и ссылки для формирования ответа.

{% hint style="info" %}
В текущей версии Tavily является **провайдером поиска по ключевым словам** и не заменяет сервис чтения веб-страниц. Чтобы модель могла прочитать полный текст страницы из результатов, дополнительно настройте провайдера чтения URL по умолчанию, например Fetch или Jina.
{% endhint %}

## Подготовка к работе

Для настройки Tavily требуются:

- действующий аккаунт Tavily;
- Tavily API Key;
- хотя бы одна диалоговая модель в Cherry Studio;
- провайдер чтения URL, если требуется читать конкретные веб-страницы.

Tavily учитывает использование в API Credits. Бесплатная квота, платные планы и ограничения вызовов могут меняться. Актуальные сведения смотрите на странице [Tavily Pricing](https://www.tavily.com/pricing) и в консоли.

## Получение API Key

1. Откройте [Tavily Platform](https://app.tavily.com/home).
2. Зарегистрируйтесь или войдите в аккаунт согласно указаниям страницы.
3. Создайте или найдите доступный Key в области API Keys консоли.
4. Скопируйте Key для вставки в Cherry Studio.

Процесс регистрации и проверки Tavily может меняться, поэтому здесь не фиксируются экраны с кодом подтверждения, двухфакторной аутентификацией и сторонним входом. При различиях следуйте актуальным указаниям Tavily.

{% hint style="danger" %}
API Key является учетными данными аккаунта. Не добавляйте реальный Key в снимки экрана, историю чатов, публичные документы и репозитории кода. При подозрении на утечку немедленно отзовите старый Key в консоли Tavily и создайте новый.
{% endhint %}

## Настройка в Cherry Studio

### 1. Откройте настройки веб-поиска

Перейдите в:

> **Настройки → Веб-поиск**

Найдите **Tavily** в списке провайдеров.

### 2. Укажите API Key

Вставьте Key из консоли Tavily в поле **API Key**.

Если сохранено несколько Key, их можно переключать и настраивать в списке. Несколько Key позволяют чередовать учетные данные, но не увеличивают общую квоту одного аккаунта Tavily.

### 3. Проверьте API Host

API Host по умолчанию:

```text
https://api.tavily.com
```

Обычно оставьте значение по умолчанию. Изменяйте его только при использовании совместимого прокси или шлюза. Пользовательский адрес должен поддерживать интерфейс Tavily `/search` и Bearer-аутентификацию.

{% hint style="warning" %}
Неверный API Host, повторное добавление `/search` или отсутствие передачи заголовка `Authorization` через прокси приведут к ошибке проверки подключения или фактического поиска.
{% endhint %}

### 4. Проверьте конфигурацию

Нажмите **Проверить** на карточке Tavily.

- Проверка успешна: текущие API Host и Key позволяют выполнить базовый запрос.
- Проверка не удалась: сначала проверьте Key, Host, сетевой прокси и состояние аккаунта Tavily, затем обратитесь к разделу устранения неполадок ниже.

### 5. Назначьте провайдером поиска по ключевым словам по умолчанию

Назначьте Tavily **провайдером поиска по умолчанию**. Cherry Studio будет использовать его для внешнего поиска по ключевым словам.

Если модель также должна открывать страницы из результатов, выберите **провайдера чтения URL** по умолчанию. Распространенное сочетание:

| Задача | Рекомендуемый выбор |
| --- | --- |
| Поиск по ключевым словам | Tavily |
| Чтение URL | Fetch или Jina |

Провайдер поиска и провайдер чтения URL настраиваются независимо. Одна настройка Tavily не означает, что приложение может прочитать полный текст любой веб-страницы.

## Настройка общих параметров поиска

Общие параметры веб-поиска Cherry Studio применяются к Tavily и другим внешним провайдерам.

### Максимальное количество результатов

Можно задать максимальное количество результатов одного поиска. Большее число обычно дает модели больше источников, но также может увеличить время поиска, длину контекста и использование API.

Сначала используйте значение по умолчанию и постепенно увеличивайте его, только если в ответе недостаточно источников.

### Сжатие результатов поиска

В зависимости от задачи можно не сжимать или обрезать результаты. Сжатие сокращает расход контекста, но чрезмерная обрезка может удалить важные детали.

### Черный список веб-поиска

После получения результатов от Tavily Cherry Studio исключает URL из черного списка. Настройка описана в разделе [Черный список веб-поиска](blacklist.md).

{% hint style="info" %}
Текущий адаптер Tavily в Cherry Studio отправляет Tavily только запрос и максимальное количество результатов. Расширенные параметры официального API, включая `search_depth`, `topic`, `include_domains`, `exclude_domains` и `include_answer`, пока не доступны отдельно в интерфейсе V2.
{% endhint %}

## Использование в диалоге

1. Откройте ассистента или новый диалог.
2. Выберите модель.
3. Нажмите значок **глобуса** рядом с полем ввода, чтобы включить веб-поиск.
4. Введите и отправьте вопрос, требующий актуальных сведений или внешних источников.
5. Проверьте номера источников и ссылки в ответе.

Пример:

```text
Найдите описание изменений последнего стабильного выпуска Cherry Studio,
сгруппируйте их по функциям и приведите источник после каждого вывода.
```

Если модель поддерживает нативный поиск, Cherry Studio в первую очередь использует ее возможности. Для модели без нативного поиска, но с поддержкой вызова инструментов, Tavily может выступать внешним провайдером поиска по ключевым словам.

Различия между двумя способами описаны в разделе [Веб-поиск](README.md).

## Возможности текущей интеграции

| Возможность | Поддержка в текущей версии V2 |
| --- | --- |
| Поиск по ключевым словам | Поддерживается |
| Возврат заголовка, описания и URL страницы | Поддерживается |
| Настройка максимального количества результатов | Поддерживается через общие параметры веб-поиска |
| Несколько API Key | Поддерживается |
| Пользовательский API Host | Поддерживается |
| Чтение текста указанного URL | Не поддерживается; требуется Fetch или Jina |
| Расширенные параметры Tavily Search | Пока недоступны в интерфейсе |
| Tavily Extract, Crawl, Map, Research | Не интегрированы в текущий адаптер Tavily |

Cherry Studio отправляет запросы в интерфейс Tavily `/search` и использует Bearer API Key. Возможности интерфейса описаны в [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search).

## Частые проблемы

### Кнопка проверки сообщает об ошибке аутентификации

Обычно причина связана с API Key:

1. Скопируйте Key из консоли Tavily заново, не добавляя пробелы.
2. Убедитесь, что Key не отозван.
3. Убедитесь, что текущий аккаунт или команда все еще может использовать Key.
4. При подозрении на утечку отзовите старый Key и создайте новый.

### Недостаточно квоты или слишком много запросов

Проверьте Credits, оплату и ограничения частоты запросов в консоли Tavily. Дождитесь восстановления квоты, уменьшите частоту поиска или выберите подходящий план.

Не пытайтесь обойти ограничение постоянными повторными запросами: это создаст еще больше бесполезных вызовов.

### Проверка успешна, но диалог не использует веб-поиск

Последовательно убедитесь, что:

- Tavily назначен провайдером поиска по ключевым словам по умолчанию;
- значок глобуса в текущем диалоге включен;
- текущая модель поддерживает вызов инструментов или нативный веб-поиск;
- вопрос действительно требует внешнего поиска;
- инструменты не отключены в настройках ассистента или модели.

### Результаты есть, но модель не может прочитать страницу

В текущей версии Tavily отвечает только за поиск по ключевым словам. Назначьте Fetch или Jina провайдером чтения URL по умолчанию и повторите запрос.

### Результаты пусты или недостаточно релевантны

Можно:

- переписать вопрос в виде четких ключевых слов;
- добавить время, регион, название продукта или номер версии;
- умеренно увеличить максимальное количество результатов;
- проверить, не исключил ли черный список нужный сайт;
- проверить важный вывод еще раз с другим поисковым запросом.

### Ошибка после изменения API Host

Верните адрес по умолчанию:

```text
https://api.tavily.com
```

Если прокси или шлюз обязателен, убедитесь, что он:

- поддерживает `POST /search`;
- передает Bearer-аутентификацию;
- возвращает JSON, совместимый с Tavily Search API;
- не добавляет и не удаляет путь.

## Безопасность, конфиденциальность и точность

- Поисковые запросы отправляются Tavily. Не включайте в них пароли, API Key, персональные данные и непубличные рабочие сведения.
- Веб-результаты могут быть устаревшими, ошибочными или противоречивыми. Для выводов высокого риска в медицине, праве и финансах откройте исходный источник и проверьте его вручную.
- Квотой и оплатой Tavily управляет провайдер. Перед массовым использованием проверьте текущий план и правила расходования в консоли.
- Регулярно меняйте ненужные Key. Действия при утечке описаны в [Tavily API Key Management](https://docs.tavily.com/documentation/best-practices/api-key-management).
