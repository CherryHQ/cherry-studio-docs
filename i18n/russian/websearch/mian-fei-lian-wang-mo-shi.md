# Бесплатный режим веб-поиска

Если вы не хотите отдельно получать API Key поискового сервиса, в Cherry Studio V2 можно использовать:

```text
Провайдер поиска по умолчанию: ExaMCP
Провайдер получения URL по умолчанию: Fetch
```

В текущей версии для этой комбинации не требуется дополнительный поисковый API Key:

- ExaMCP отвечает за поиск веб-страниц по ключевым словам;
- Fetch напрямую читает основной текст результата поиска или указанного URL;
- Обычные модели используют эти возможности через вызов инструментов.

{% hint style="warning" %}
Здесь слово «бесплатно» означает, что в настоящее время Cherry Studio не требует дополнительного поискового API Key. Это не означает, что все связанные сервисы останутся бесплатными навсегда. Вызовы моделей могут по-прежнему тарифицироваться, а условия доступа, квоты и доступность ExaMCP могут меняться.
{% endhint %}

## Сценарии использования

Подходит для:

- Первого знакомства с веб-поиском;
- Периодического поиска самой свежей информации;
- Нежелания регистрироваться на нескольких поисковых платформах;
- Отсутствия API Key для Tavily, Exa, Bocha и аналогичных сервисов;
- Предварительной проверки качества вызова инструментов моделью.

Если вам нужны стабильно большие объёмы запросов, фиксированный уровень обслуживания, корпоративное соответствие требованиям или полный административный контроль, используйте поисковый API с официальным аккаунтом либо разверните собственный SearXNG.

## Рабочий процесс

Обычный внешний веб-поиск выполняется так:

1. Модель определяет, что для ответа требуется поиск;
2. Модель вызывает ExaMCP и передает поисковые ключевые слова;
3. ExaMCP возвращает список потенциальных веб-страниц;
4. Модель по мере необходимости вызывает Fetch для чтения конкретного URL;
5. Cherry Studio извлекает основной текст со страницы;
6. Модель организует ответ и цитаты на основе полученного контента.

ExaMCP и Fetch выполняют разные функции и не могут заменить друг друга:

| Провайдер | Возможность | Может ли самостоятельно обеспечить полный веб-поиск обычной модели |
| --- | --- | --- |
| ExaMCP | Поисковые ключевые слова | Нет, отсутствует провайдер получения URL по умолчанию |
| Fetch | Чтение URL | Нет, отсутствует провайдер поиска по умолчанию |
| ExaMCP + Fetch | Поиск и чтение веб-страниц | Да |

{% hint style="info" %}
Если текущая модель использует собственный нативный веб-поиск, Cherry Studio не переключается на эту внешнюю комбинацию. Нативный поиск выполняет провайдер модели; стоимость и формат ссылок определяются его правилами.
{% endhint %}

## Настройка ExaMCP и Fetch

### 1. Открытие настроек веб-поиска

Перейдите в:

```text
Настройки → Веб-поиск
```

В верхней части страницы есть две независимые опции:

- **Провайдер поиска по умолчанию**;
- **Провайдер получения URL по умолчанию**.

### 2. Выбор ExaMCP

В поле **Провайдер поиска по умолчанию** выберите:

```text
ExaMCP
```

Вы также можете открыть страницу деталей ExaMCP и нажать **Установить по умолчанию**.

Текущий адрес по умолчанию:

```text
https://mcp.exa.ai/mcp
```

Обычно никаких изменений вносить не нужно, а API Key заполнять тоже не требуется. Нажмите **Проверить**, чтобы убедиться, что текущая сеть имеет доступ к этому сервису.

{% hint style="warning" %}
Не заменяйте адрес API неизвестным адресом MCP. Поисковые запросы будут отправляться по этому адресу, а вредоносный сервис может вернуть вводящую в заблуждение информацию.
{% endhint %}

### 3. Выбор Fetch

В поле **Провайдер получения URL по умолчанию** выберите:

```text
Fetch
```

Fetch — встроенный в Cherry Studio способ чтения веб-страниц. Он не требует API Key и не содержит поля для адреса удалённого сервиса извлечения.

### 4. Подтверждение двух значений по умолчанию

В итоге должны быть выбраны одновременно:

| Настройка | Выбор |
| --- | --- |
| Провайдер поиска по умолчанию | ExaMCP |
| Провайдер получения URL по умолчанию | Fetch |

Если настроен только один из параметров, при нажатии значка веб-поиска обычная модель по-прежнему предложит перейти в настройки.

## Использование в диалоге

1. Вернитесь на страницу чата;
2. Выберите чат-модель со стабильным вызовом инструментов;
3. Нажмите на значок **глобуса** под полем ввода;
4. Отправьте вопрос, требующий актуальной информации.

Для первого тестирования можно использовать:

```text
Найди последнюю официальную версию Cherry Studio, цитируя только официальный GitHub Release,
и выведи номер версии, дату выпуска и три основные изменения.
```

После получения ответа проверьте:

- Был ли действительно выполнен поиск;
- Появились ли открываемые ссылки;
- Соответствуют ли ссылки запрошенному источнику;
- Соответствуют ли номер версии и дата выпуска исходному тексту.

## Что может читать Fetch

Fetch запрашивает целевой URL напрямую с компьютера Cherry Studio и извлекает основной текст из полученного HTML, преобразуя его в формат, удобный для чтения моделью.

Обычно подходит для:

- Основной части новостей и блогов;
- Документации продуктов;
- Статических веб-страниц;
- Открытых страниц, не требующих входа в систему;
- Ссылок на статьи из результатов поиска.

Следующие страницы могут вызвать сбой или иметь неполный контент:

- Страницы, доступные только после входа в систему;
- Страницы, чей основной контент загружается скриптами браузера;
- Сайты с CAPTCHA или строгой защитой от ботов;
- Страницы, доступные только из определенных регионов или сетей;
- Файлы PDF, аудио/видео или не-HTML файлы;
- Ссылки, которые устарели, имеют аномальные перенаправления или ошибки сертификатов.

У Fetch есть ограничение по времени на однократное чтение. Если целевой сайт отвечает слишком медленно, модель может не получить основной текст.

## «Без дополнительного Key» не означает «без затрат»

Тем не менее могут возникнуть:

- Стоимость токенов для ввода и вывода модели;
- Контекст, занимаемый результатами поиска;
- Сетевой трафик локального или удаленного сервера;
- Оборудование, доменное имя или эксплуатационные расходы при создании собственного SearXNG;
- Будущая плата за вызовы сторонних сервисов после изменения их условий.

Чем больше поисковых результатов и чем длиннее текст веб-страницы, тем выше обычно потребление контекстного окна модели. Вы можете снизить **Количество результатов** в разделе **Настройки → Веб-поиск** или включить **Обрезку**.

## Примечания о конфиденциальности

При использовании ExaMCP + Fetch:

- Ключевые слова поиска будут отправлены в сервис ExaMCP;
- Fetch будет напрямую обращаться к целевому веб-сайту с локальной машины;
- Целевой сайт обычно может видеть сетевой адрес источника запроса;
- Результаты поиска и текст веб-страницы будут отправляться текущему провайдеру модели как контекст.

Не включайте в поисковые запросы или URL:

- API Key, пароли или коды подтверждения;
- Ссылки с токенами доступа к частным системам;
- Клиентские данные или личную идентификационную информацию;
- Корпоративные секреты компании.

{% hint style="danger" %}
Содержимое веб-страницы — недоверенный ввод. Не выполняйте команды из неизвестных источников, указанные на странице или в ответе модели. Не отключайте по таким указаниям защитное ПО, не загружайте ключи и не скачивайте подозрительные файлы.
{% endhint %}

## Другие недорогие варианты

### Использование нативного веб-поиска модели

Если модель поддерживает нативный веб-поиск, обычно отдельный поисковый API Key не требуется. Однако веб-поиск может входить в тарификацию модели, поэтому считать его бесплатным нельзя.

### Собственный SearXNG + Fetch

Если вы хотите самостоятельно контролировать точку входа для поиска, вы можете использовать:

```text
Провайдер поиска по умолчанию: SearXNG
Провайдер получения URL по умолчанию: Fetch
```

Сам SearXNG не требует ввода поискового API Key в Cherry Studio, но необходим доступный экземпляр. При самостоятельном размещении вы отвечаете за развёртывание, обновления, безопасность и ограничения вышестоящих поисковых систем.

Подробные инструкции приведены в разделе [Настройка SearXNG](searxng.md).

### Использование бесплатных лимитов от провайдера

Некоторые API поиска могут предоставлять пробные или бесплатные лимиты для новых учетных записей, но правила постоянно меняются. Перед регистрацией обязательно ознакомьтесь с текущими официальными ценами, региональными ограничениями и политикой конфиденциальности провайдера; не планируйте долгосрочную работу, основываясь на цифрах лимитов из старых руководств.

## Часто задаваемые вопросы

### Сбой проверки ExaMCP

Пожалуйста, проверьте следующее:

1. Доступность `https://mcp.exa.ai/mcp` из вашей текущей сети;
2. Правильно ли настроен и разрешен для использования Cherry Studio прокси-сервер;
3. Не блокируют ли DNS, брандмауэр или антивирусное ПО доступ;
4. Временно ли недоступна служба ExaMCP;
5. Не был ли по ошибке изменён адрес API.

Восстановите адрес по умолчанию и повторите проверку. Если ошибка сохраняется, выберите другого поискового провайдера или разверните собственный SearXNG.

### Сбой чтения Fetch

Сначала откройте тот же URL в обычном браузере. Если браузер тоже не получает доступ, устраните проблему с сетью, входом, региональными ограничениями или сертификатом.

Если страница открывается в браузере, но происходит сбой при работе Fetch, частые причины следующие:

- Страница зависит от JavaScript;
- Сайт требует Cookie, активный сеанс или CAPTCHA;
- Сайт блокирует автоматические запросы;
- Возвращен HTML, из которого невозможно извлечь основной текст;
- Время ответа превысило лимит.

Вы можете использовать другой источник или вручную скопировать необходимый для анализа основной текст страницы в диалог.

### Настроено два элемента, но модель не выполняет поиск

Переключатель веб-поиска только предоставляет инструменты; модель всё равно сама решает, вызывать их или нет. Вы можете:

- Убедиться, что значок глобуса подсвечен;
- Четко запросить: «Сначала выполнить веб-поиск, а затем ответить и указать источники»;
- Использовать модель с более стабильной способностью вызова инструментов;
- Сформулировать вопрос более конкретно, указав временной диапазон и приоритетные источники;
- Повторить попытку в новом диалоге.

### Есть результаты поиска, но нет основного текста страницы

ExaMCP мог вернуть список потенциальных ссылок, но Fetch не смог прочитать содержимое некоторых страниц. Попробуйте уменьшить количество результатов, сменить источник или напрямую предоставить модели конкретный URL, доступный для публичного просмотра.
