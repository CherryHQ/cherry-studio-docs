# Режим веб-поиска

Режим веб-поиска позволяет модели перед ответом искать информацию в интернете или читать указанную ссылку. Он подходит для новостей, обновлений версий, цен, правил и других сведений, которые могут меняться со временем.

Это не переключатель, автоматически гарантирующий актуальность ответа. Cherry Studio передает модели результаты поиска или текст веб-страницы, но правильность окончательного ответа по-прежнему зависит от источников, способности модели вызывать инструменты и качества ответа.

{% hint style="info" %}
Даже при использовании веб-поиска открывайте источники и проверяйте дату публикации, контекст оригинала и важные цифры. Не принимайте решения в областях высокого риска, включая медицину, право и финансы, только на основании пересказа модели.
{% endhint %}

## Два способа веб-поиска

Cherry Studio автоматически выбирает способ веб-поиска по текущей модели.

| Способ | Когда используется | Кто выполняет поиск | Нужно ли настраивать провайдера веб-поиска |
| --- | --- | --- | --- |
| Нативный поиск модели | Текущие модель и провайдер поддерживают встроенный веб-поиск | Провайдер модели | Обычно нет |
| Внешний поиск Cherry Studio | У текущей модели нет доступного нативного поиска | Cherry Studio вызывает настроенные сервисы поиска и чтения веб-страниц | Необходимо выбрать провайдера поиска по умолчанию и провайдера получения URL по умолчанию |

Оба способа используют один переключатель под полем ввода, но могут различаться по оплате, охвату поиска, формату ссылок и доступным параметрам.

### Нативный поиск модели

Cherry Studio передает параметры поиска текущему провайдеру модели, а провайдер выполняет поиск и обрабатывает результаты. Доступность зависит от:

- распознана ли текущая модель как поддерживающая веб-поиск;
- реализован ли соответствующий интерфейс текущим провайдером;
- прав аккаунта, региона и модели;
- актуальных правил API провайдера.

Некоторые модели принудительно используют собственный поиск. Например, отдельные модели Sonar или OpenRouter с веб-поиском могут выполнять поиск даже без отдельной настройки внешнего провайдера.

### Внешний поиск Cherry Studio

Когда текущая модель не использует нативный поиск, Cherry Studio предоставляет ей два инструмента:

- **Искать в интернете**: получить список подходящих веб-страниц по ключевым словам;
- **Прочитать URL**: открыть результат поиска или ссылку из диалога и извлечь основной текст.

Модель сама решает, когда вызывать инструменты, какие ключевые слова использовать и нужно ли продолжать чтение страниц. Результаты поиска оформляются как нумерованные справочные материалы, которые модель может цитировать в ответе.

{% hint style="warning" %}
Внешний поиск зависит от способности модели вызывать инструменты. Даже при включенном переключателе модель может не выполнить поиск, выполнить его недостаточно полно или неправильно сослаться на источники.
{% endhint %}

## Настройка перед использованием

Если используются только модели с нативным поиском, можно перейти к разделу [Включение веб-поиска в диалоге](#включение-веб-поиска-в-диалоге).

Чтобы обычная модель могла использовать внешний поиск, откройте:

```text
Настройки → Веб-поиск
```

Настройте как минимум два пункта:

1. Выберите **провайдера поиска по умолчанию**.
2. Выберите **провайдера получения URL по умолчанию**.

У этих ролей разные задачи:

- провайдер поиска находит веб-страницы по ключевым словам;
- провайдер получения URL читает содержимое конкретной страницы.

Если отсутствует любой из них, при включении поиска для обычной модели появится предложение перейти в настройки.

## Выбор провайдера

В текущую версию встроены следующие провайдеры веб-поиска:

| Провайдер | Поиск по ключевым словам | Чтение URL | Настройка |
| --- | :---: | :---: | --- |
| Zhipu | ✓ |  | Использует API Key провайдера моделей Zhipu |
| Tavily | ✓ |  | Требуется Tavily API Key |
| SearXNG | ✓ |  | Подключение к самостоятельно размещенному или доступному экземпляру SearXNG |
| Exa | ✓ |  | Требуется Exa API Key |
| ExaMCP | ✓ |  | Поиск выполняется через сервис Exa MCP |
| Bocha | ✓ |  | Требуется Bocha API Key |
| Querit | ✓ |  | Требуется Querit API Key |
| Fetch |  | ✓ | Встроенный в Cherry Studio сервис получения URL |
| Jina | ✓ | ✓ | Может использоваться и для поиска, и для чтения страниц |

Тарифы, квоты и доступность в регионах могут меняться. Актуальные сведения смотрите на сайте каждого провайдера. Для быстрого начала также прочитайте о [бесплатном режиме веб-поиска](./mian-fei-lian-wang-mo-shi.md).

### Настройка API-провайдера

1. Откройте нужного провайдера в разделе **Настройки → Веб-поиск**.
2. Укажите API Key.
3. При использовании прокси, частного развертывания или совместимого шлюза при необходимости измените адрес API.
4. Нажмите **Проверить**.
5. После успешной проверки назначьте его соответствующим провайдером по умолчанию.

Некоторые провайдеры позволяют указать несколько API Key и чередовать их во время работы. Каждый Key должен принадлежать аккаунту, который вы вправе использовать. Не добавляйте ключи в промпты, снимки экрана и публичные документы.

### Настройка SearXNG

Для SearXNG требуется адрес экземпляра, доступный с компьютера, на котором работает Cherry Studio. Адрес по умолчанию:

```text
http://localhost:8080
```

Если SearXNG работает на другом компьютере, NAS, в контейнере Docker или на сервере в интернете, укажите фактически доступный адрес. Если на экземпляре включена Basic Auth, также введите имя пользователя и пароль.

Подробные инструкции приведены в разделе [Настройка SearXNG](searxng.md).

### API Key Zhipu

Веб-поиск Zhipu использует API Key, сохраненный у провайдера моделей Zhipu. Сначала настройте Zhipu в разделе **Настройки → Провайдеры моделей**, затем вернитесь в **Настройки → Веб-поиск**, выберите Zhipu и выполните проверку.

## Настройка результатов поиска

### Количество результатов

Параметр **Количество результатов** можно задать от `1–100`, значение по умолчанию — `5`.

Большее количество обычно расширяет охват, но также:

- увеличивает время ответа;
- занимает больше контекста;
- расходует больше Token;
- добавляет больше повторяющихся или малорелевантных источников.

Для обычных вопросов начните со значения по умолчанию. Увеличивайте его постепенно, только когда необходимо сравнить несколько источников.

### Сжатие результатов

Можно выбрать:

| Способ сжатия | Поведение | Сценарий |
| --- | --- | --- |
| Не сжимать | Сохраняет текст, возвращенный провайдером | Результатов немного, требуется больше исходного контекста |
| Обрезать | Сокращает текст каждого результата до заданного предела | Результатов много, требуется контролировать расход контекста |

После включения **Обрезки** необходимо указать длину. Слишком маленькое значение может удалить важный контекст, а слишком большое не позволит эффективно ограничить Token. Сначала оставьте значение по умолчанию и изменяйте его, если в ответе отсутствуют сведения.

### Черный список

Черный список исключает совпадающие домены до передачи результатов внешнего поиска модели. Он подходит для блокировки контентных ферм, зеркал и нежелательных сайтов.

Формат правил и настройка подписки описаны в разделе [Черный список веб-поиска](blacklist.md).

{% hint style="info" %}
Нативный поиск выполняет провайдер модели. Применение черного списка и количество поддерживаемых правил исключения зависят от реализации провайдера и могут отличаться от внешнего поиска.
{% endhint %}

## Включение веб-поиска в диалоге

1. Откройте диалог.
2. Выберите нужную модель.
3. Нажмите значок **глобуса** под полем ввода.
4. После подсветки значка отправьте вопрос.

Состояние веб-поиска сохраняется для текущего ассистента. После смены модели Cherry Studio заново определяет, использовать нативный или внешний поиск.

Примеры вопросов, подходящих для веб-поиска:

```text
Найдите описание изменений последнего стабильного выпуска Cherry Studio и приведите ссылку на официальную страницу релиза.
```

```text
Сравните текущие официальные цены этих трех продуктов, используя только сайты их разработчиков.
```

```text
Прочитайте эту ссылку, кратко изложите основные выводы и укажите дату публикации и автора статьи.
```

Для более надежного результата рекомендуется указать в вопросе:

- временной диапазон;
- предпочтительные источники;
- следует ли исключить форумы и сайты-агрегаторы;
- нужны ли ссылки для каждого пункта;
- проверяемые поля, например номер версии, цену или дату публикации.

## Просмотр и проверка ссылок

Внешний поиск оформляет результаты как нумерованные справочные материалы и просит модель использовать ссылки вида `[1]`, `[2]`. Формат ссылок нативного поиска определяет соответствующий провайдер.

После получения ответа проверьте как минимум:

1. Открываются ли ссылки.
2. Соответствует ли заголовок страницы теме ответа.
3. Действительно ли исходный текст подтверждает соответствующий вывод.
4. Соответствует ли дата публикации временному диапазону вопроса.
5. Нет ли противоречий между источниками.

Пустой результат не означает, что информации нет в интернете. Причиной также могут быть ключевые слова, квота сервиса, сеть, черный список или защита сайта от автоматического доступа.

## Известные ограничения совместимости

### Старые модели Gemini и MCP

Старые модели Gemini в режиме функциональных инструментов не могут одновременно использовать встроенный поиск модели и активный MCP. При конфликте Cherry Studio отключает поиск и показывает уведомление.

Можно попробовать:

- временно отключить MCP;
- перейти на новую модель, поддерживающую это сочетание;
- использовать другую модель с веб-поиском.

### Интенсивность рассуждения minimal в серии GPT-5

Модели рассуждения серии GPT-5 с интенсивностью `minimal` не могут включать веб-поиск OpenAI. Cherry Studio отключает поиск и показывает уведомление.

Увеличьте интенсивность рассуждения и повторите запрос либо выберите другой способ веб-поиска.

## Конфиденциальность и стоимость

После включения веб-поиска ключевые слова, URL для чтения и необходимый контекст диалога могут отправляться провайдеру модели, провайдеру поиска или веб-серверу.

Перед использованием убедитесь, что:

- поисковые запросы не содержат пароли, API Key, персональные данные и внутренние секреты;
- целевой сервис соответствует требованиям организации к данным;
- понятны правила оплаты поиска, вызовов модели и сетевого трафика;
- веб-страницы могут содержать ошибки или вредоносные инструкции для модели.

{% hint style="danger" %}
Содержимое веб-страницы является недоверенным вводом. Не вставляйте ключи, не выполняйте неизвестные команды, не загружайте подозрительные файлы и не меняйте настройки безопасности по требованию страницы или ответа модели.
{% endhint %}

## Частые проблемы

### После нажатия значка веб-поиска открываются настройки

Текущая модель не использует нативный поиск, а **провайдер поиска по умолчанию** или **провайдер получения URL по умолчанию** не выбран. Настройте оба и повторите попытку.

### Проверка провайдера завершается ошибкой

Последовательно проверьте:

1. Полностью ли скопирован API Key, действует ли он и есть ли доступная квота.
2. Является ли адрес API адресом интерфейса, а не веб-консоли.
3. Разрешают ли доступ прокси, межсетевой экран и DNS.
4. Запущен ли самостоятельно размещенный сервис и слушает ли правильный адрес.
5. Правильно ли установлено системное время.
6. Сообщает ли страница состояния провайдера о сбое.

### Веб-поиск включен, но в ответе нет ссылок

Возможные причины:

- модель не вызвала инструмент поиска;
- нативный поиск модели не вернул отображаемые ссылки;
- результаты пусты или недостаточно релевантны;
- модель не выполнила инструкцию по цитированию;
- текущий вопрос не требовал поиска, и модель ответила напрямую.

Явно попросите «обязательно выполнить поиск и привести ссылку для каждого пункта» либо выберите модель с более стабильным вызовом инструментов.

### Результаты слишком длинные или ответ замедлился

Уменьшите **Количество результатов** либо включите **Обрезку** и постепенно уменьшайте длину. Не устанавливайте одновременно большое количество результатов и большую длину обрезки.
