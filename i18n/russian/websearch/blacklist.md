# Черный список веб-поиска

Черный список веб-поиска исключает из контекста модели нежелательные страницы: контент-фермы, зеркала, низкокачественные агрегаторы и сайты, не связанные с работой.

Правила черного списка хранятся в:

```text
Настройки → Веб-поиск → Черный список
```

{% hint style="info" %}
Черный список предназначен в первую очередь для уменьшения количества ненужных источников, а не для проверки фактов или безопасности. Сайты, которые не были заблокированы, все равно могут содержать ошибочный, устаревший или вредоносный контент.
{% endhint %}

## Как работает черный список

Во внешнем веб-поиске Cherry Studio повторно фильтрует URL по черному списку после получения результатов от провайдера. Совпавшие результаты модели не передаются.

В нативном веб-поиске уровень поддержки черного списка зависит от провайдера модели:

- Нативный поиск Anthropic принимает преобразованные заблокированные домены;
- Нативный поиск xAI принимает максимум первые `5` преобразованных доменов;
- Другие службы нативного веб-поиска могут не поддерживать или использовать черный список.

Поэтому не следует ожидать, что один и тот же набор правил будет работать одинаково со всеми моделями и провайдерами.

## Добавление правил

1. Откройте **Настройки → Веб-поиск**;
2. Найдите **Черный список**;
3. Введите одно правило в каждой строке;
4. Нажмите **Сохранить**;
5. Убедитесь, что нет уведомления «Недопустимая запись»;
6. Выполните проверку, начав новый диалог с веб-поиском или продолжив существующий.

Цифра рядом с полем ввода показывает количество сохраненных правил.

{% hint style="warning" %}
Если есть хотя бы одно недопустимое правило, черный список не сохранится. Исправьте все недопустимые записи и снова нажмите «Сохранить».
{% endhint %}

## Поддерживаемые форматы

### Шаблон совпадения (Match Pattern)

Шаблоны совпадения подходят для блокировки сайтов по протоколу, домену, поддомену и пути.

Примеры использования:

```text
*://*.example.com/*
```

Блокирует страницы HTTP и HTTPS с `example.com` и всеми его поддоменами.

```text
https://example.com/private/*
```

Блокирует только страницы, находящиеся по адресу `https://example.com/private/`.

```text
*://news.example.com/archive/*
```

Блокирует только путь `archive` на указанном поддомене.

Структура шаблона совпадения:

```text
Протокол://Хост/Путь
```

| Часть | Пример | Описание |
| --- | --- | --- |
| Протокол | `https`, `http`, `*` | `*` здесь соответствует HTTP и HTTPS |
| Хост | `example.com`, `*.example.com`, `*` | `*.example.com` одновременно соответствует корневому домену и поддомену |
| Путь | `/*`, `/news/*` | Должен начинаться с `/`, можно использовать `*` |

Полное описание правил можно найти в [MDN Match Patterns](https://developer.mozilla.org/zh-CN/docs/Mozilla/Add-ons/WebExtensions/Match_patterns).

{% hint style="warning" %}
Не вводите только `example.com`. Имя домена само по себе не является допустимым шаблоном совпадения; используйте `*://*.example.com/*`.
{% endhint %}

### Регулярное выражение (Regular Expression)

Если требуется более точное сопоставление URL, можно использовать регулярные выражения. Правило должно начинаться с `/` и заканчиваться `/`:

```text
/example\.(com|org)/
```

```text
/example\.com\/(ads|sponsored)\//
```

Cherry Studio игнорирует регистр и тестирует правила на основе полного «протокол + домен + путь + параметры запроса».

Регулярные выражения подходят для:

- Одновременного сопоставления нескольких доменов верхнего уровня;
- Блокировки страниц, содержащих определенный фрагмент пути;
- Исключения результатов на основе параметров запроса URL;
- Правил, которые сложно представить обычным шаблоном совпадения.

Синтаксис можно найти в [MDN Regular Expression Guide](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Regular_expressions).

{% hint style="danger" %}
Чрезмерно широкие регулярные выражения могут ошибочно заблокировать большое количество результатов. Не копируйте сложные выражения, происхождение которых неизвестно и которые невозможно понять.
{% endhint %}

## Примеры для копирования

Следующие правила можно изменить по мере необходимости:

```text
*://*.example.com/*
*://mirror.example.org/*
https://news.example.net/archive/*
/example\.io\/sponsored/
```

Каждое правило занимает отдельную строку, пустые строки игнорируются.

### Блокировка домена и всех поддоменов

```text
*://*.example.com/*
```

Сопоставит:

```text
https://example.com/article
https://www.example.com/article
http://docs.example.com/guide
```

### Блокировка только указанного пути

```text
https://example.com/ads/*
```

Заблокирует:

```text
https://example.com/ads/page-1
```

Не заблокирует:

```text
https://example.com/blog/page-1
```

### Одновременная блокировка нескольких похожих доменов

```text
/example\.(com|net|org)/
```

Если нужно всего три фиксированных сайта, обычно проще поддерживать три отдельных шаблона совпадения.

## Неподдерживаемые старые возможности

Текущая страница черного списка V2 поддерживает только ручной ввод правил и не предоставляет:

- Прямую блокировку сайтов из панели инструментов браузера;
- Автоматическую загрузку правил по URL подписки;
- Автообновление подписки uBlacklist;
- Полную конфигурацию расширения браузера.

Таблицы источников подписок и снимки экрана из старой документации больше не соответствуют текущему интерфейсу.

Если нужен общедоступный набор правил, сначала проверьте его содержимое, а затем вручную преобразуйте правила в поддерживаемые Cherry Studio шаблоны совпадения или регулярные выражения. Не вставляйте тысячи правил без проверки: это усложняет обслуживание и повышает риск ошибочной блокировки нормальных источников.

## Проверка правил

После сохранения задайте вопрос, результат которого легко проверить:

```text
Найди информацию о Cherry Studio на example.com и перечисли источники цитирования.
```

Если `example.com` заблокирован, в ответе внешнего поиска не должно появиться результатов с этим доменом.

Обратите внимание при проверке:

1. Убедитесь, что текущая модель использует внешний веб-поиск или нативный веб-поиск модели;
2. Проверяйте окончательный URL цитирования, а не только заголовок;
3. Обращайте внимание на то, что домен может измениться после перенаправления страницы;
4. Новые правила не удаляют старые ссылки из истории сообщений;
5. Некоторые провайдеры нативного веб-поиска могут игнорировать часть правил.

## Часто задаваемые вопросы

### Уведомление «Недопустимая запись»

Распространенные ошибки:

| Ошибочный синтаксис | Проблема | Рекомендуемый синтаксис |
| --- | --- | --- |
| `example.com` | Отсутствуют протокол и путь | `*://*.example.com/*` |
| `https://example.com` | Отсутствует путь | `https://example.com/*` |
| `*.example.com` | Не является полным шаблоном совпадения | `*://*.example.com/*` |
| `/[example/` | Недействительный синтаксис регулярного выражения | Исправить скобки или группы символов |
| `# example` | Не поддерживаются строки комментариев | Удалить эту строку |

После исправления всех недопустимых записей нажмите «Сохранить» снова.

### Все равно видно заблокированный сайт после сохранения

Возможные причины включают:

- Текущая модель использует нативный веб-поиск, а провайдер не применил черный список;
- Правило соответствует только корневому домену, но не соответствующему фактическому поддомену;
- Правило соответствует только HTTPS, а результат получен по HTTP;
- Путь указан слишком узко;
- Цитирование получено из исторических ответов до сохранения правил;
- Страница перенаправила запрос на другой адрес;
- Модель упомянула этот сайт на основе уже имеющихся знаний без поиска.

Сначала проверьте с помощью полных правил, таких как `*://*.example.com/*`, а затем постепенно сужайте область действия.

### Исчезли все результаты поиска

Проверьте, не использовали ли вы:

```text
<all_urls>
```

Этот шаблон соответствует всем URL HTTP и HTTPS. Удалите его и сохраните.

Также проверьте, не слишком широкое ли регулярное выражение, например:

```text
/.*/
```

### Как восстановить состояние по умолчанию

Очистите поле ввода черного списка и нажмите **Сохранить**. После того как счетчик станет `0`, внешний веб-поиск перестанет исключать результаты по пользовательским правилам.

## Рекомендации по использованию

- В первую очередь блокируйте по домену; используйте регулярные выражения только в сложных сценариях;
- Начинайте с небольшого количества четких правил;
- Периодически удаляйте устаревшие или дублирующиеся правила;
- Перед блокировкой проверьте, не ограничивается ли низкокачественный контент лишь отдельными страницами сайта;
- Для ключевых выводов требуйте несколько независимых источников;
- Не используйте черный список вместо ручной проверки цитирования.
