# Основные понятия ИИ

На этой странице объясняются понятия ИИ, которые часто встречаются в Cherry Studio. Цель не в запоминании терминов, а в понимании причин ошибок модели, настроек, влияющих на результат, и возможных направлений передачи данных.

## Модели, провайдеры и API

### Модель

Модель — вычислительная система, которая обрабатывает ввод и создаёт вывод. Разные модели могут специализироваться на тексте, понимании изображений, генерации изображений, Embedding, Rerank, рассуждениях или вызове инструментов.

Одна модель может предоставляться несколькими провайдерами. При смене провайдера могут отличаться:

* Model ID, версия и предел контекста.
* Доступные регионы, цены, ограничения частоты и права учётной записи.
* Формат OpenAI, Anthropic, Gemini или другого API.
* Поддержка изображений, инструментов, параметров рассуждения и других возможностей.

Поэтому одинаковое имя модели не гарантирует одинаковое поведение API. Проведите реальную проверку у используемого провайдера.

### Провайдер

Провайдер предоставляет адрес API, аутентификацию, список моделей, оплату и ограничения запросов. Cherry Studio сохраняет настройки соединения, формирует запросы и показывает результаты, но не может вместо провайдера включить учётную запись, квоту или доступ к модели.

Настройка описана в разделе [Сервисы моделей](../pre-basic/providers/).

### API и конечная точка

API определяет форматы запроса и ответа. Распространённые конечные точки:

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* Ollama Chat

Фраза «совместимо с API» обычно означает сходство базового формата, а не поддержку каждой расширенной возможности этого API. Для агентов также нужна модель, доступная через конечную точку **Anthropic Messages**.

## Token и Tokenizer

### Что такое Token

Token — фрагмент текста, обрабатываемый моделью. Один Token может быть:

* Целым словом.
* Частью слова.
* Одним или несколькими символами.
* Знаком препинания, пробелом или специальным символом.

Token не равен числу слов или постоянному числу символов какого-либо языка.

### Что такое Tokenizer

Tokenizer преобразует ввод в последовательность Token, используемую моделью. Модели и их версии могут использовать разные Tokenizer, поэтому один текст может давать разное число Token.

Это влияет на:

* Превышение предела контекста.
* Скорость запроса.
* Стоимость ввода и вывода.
* Разбиение длинных документов.

Число Token в Cherry Studio помогает оценить размер контекста. Окончательная стоимость и точное использование определяются ответом провайдера.

## Окно контекста

Контекст — информация, которую модель фактически получает в одном запросе. Он может включать:

* Системный запрос и конфигурацию ассистента.
* Текущее сообщение пользователя.
* Сохранённую историю сообщений.
* Содержимое изображений, файлов или веб-страниц.
* Фрагменты, найденные в базе знаний.
* Определения инструментов, параметры вызовов и результаты.
* Место для дальнейшего вывода модели.

У окна контекста есть предел. Если содержимого слишком много, провайдер может отклонить запрос, приложение может обрезать часть данных, а модель может обратить внимание только на часть информации.

### Чем длиннее контекст, тем лучше?

Не обязательно. Длинный контекст увеличивает стоимость и время ожидания, а ненужная информация может мешать задаче. Более эффективные способы:

* Использовать отдельную тему для каждого проекта.
* При переходе к новому этапу использовать **Новый контекст**.
* Прикладывать только нужные для задачи файлы.
* Извлекать из базы знаний только относящиеся к делу фрагменты.
* Хранить стабильные правила в ассистенте, а временные сведения — в текущем сообщении.

Операции с темами и контекстом описаны в разделе [Интерфейс чата](../cherrystudio/preview/chat.md).

## Системные запросы, ассистенты и темы

### Системный запрос

Системный запрос определяет долгосрочную роль, границы поведения и правила вывода. Он не может изменить знания модели, предел контекста или возможности сервера.

Слишком длинный или противоречивый системный запрос занимает контекст и снижает предсказуемость. Оставляйте в нём только стабильные правила, а даты, материалы и текущую цель помещайте в сообщение пользователя.

### Ассистент

Ассистент сохраняет повторно используемую конфигурацию чата, например:

* Системный запрос.
* Модель и параметры по умолчанию.
* Число сообщений контекста.
* Базы знаний.
* Веб-поиск и MCP.

У одного ассистента может быть несколько тем. Они используют общую конфигурацию ассистента, но независимую историю. Подробнее см. [Библиотека ассистентов](../cherrystudio/preview/selection-assistant.md).

## Temperature, Top P и параметры вывода

Temperature и Top P часто управляют случайностью генерации и диапазоном кандидатов, но реализации у моделей и провайдеров различаются. Некоторые модели рассуждения игнорируют, ограничивают или фиксируют эти значения.

Общие рекомендации:

* Для извлечения фактов, преобразования формата и изменения кода используйте стабильные значения по умолчанию.
* Для творческого текста можно умеренно повысить разнообразие.
* Не меняйте сразу несколько параметров существенно, если хотите оценить эффект одного.
* При ошибке параметра восстановите значение по умолчанию и обратитесь к текущей официальной документации модели.

Максимальная длина вывода ограничивает объём, который модель создаёт в текущем запросе, но не расширяет входной контекст. Если вывод внезапно прекращается, проверьте предел вывода, ограничения провайдера и тайм-аут запроса.

## Модели рассуждения

Модель рассуждения выполняет дополнительные вычисления до ответа. Она подходит для многошагового анализа, математики, планирования и сложных задач программирования. Рассуждение обычно требует больше времени или средств.

Обратите внимание:

* Индикатор «Размышление» не означает, что все модели возвращают содержимое рассуждения одинаково.
* Скрытый процесс рассуждения не означает, что модель не рассуждает.
* Сильное рассуждение не гарантирует фактическую точность.
* Простым задачам не всегда нужна максимальная интенсивность рассуждения.

При выборе модели оценивайте вместе точность задачи, скорость, цену и совместимость с инструментами.

## Вызов инструментов

Модель не может автоматически открыть веб-сайт только потому, что «знает» его. Вызов инструмента обычно состоит из трёх шагов:

1. Приложение сообщает модели о доступных инструментах и формате параметров.
2. Модель возвращает структурированный запрос на вызов инструмента.
3. Cherry Studio или соответствующий Server выполняет инструмент и возвращает результат модели.

Поэтому инструмент может завершиться ошибкой на разных этапах:

* Модель не выбрала инструмент.
* Модель создала неверные параметры.
* Пользователь отклонил разрешение.
* Программа инструмента или удалённый сервис завершились ошибкой.
* Результат инструмента слишком велик или имеет неверный формат.

Слова модели о том, что она выполнит поиск, не подтверждают реальный вызов. Просмотрите запись инструмента в сообщении или [трассировку](../advanced-basic/diao-yong-lian-shi-yong-shuo-ming.md).

## Веб-поиск

Веб-поиск может предоставляться:

* Встроенной поисковой возможностью провайдера модели.
* Поисковым сервисом, настроенным в Cherry Studio.
* Поисковым инструментом через MCP.

Обычно поиск сначала возвращает веб-страницы-кандидаты, затем читает часть содержимого для модели. Наличие ссылки на источник не гарантирует, что он подтверждает вывод модели. Проверяйте дату публикации, первоисточник и процитированное содержимое.

Настройка описана в разделе [Веб-поиск](../websearch/README.md).

## Мультимодальность

Мультимодальная модель может обрабатывать не только текст, но и изображения, аудио или файлы. Каждую возможность нужно оценивать отдельно:

| Возможность | Описание |
| :--- | :--- |
| Понимание изображений | Прочитать изображение и ответить на вопросы |
| Генерация изображений | Создать или изменить изображение по запросу |
| Ввод файла | Принять PDF, документ или другой файл |
| Понимание аудио | Принять и проанализировать аудио |

Поддержка зрения не означает поддержку генерации изображений. Возможность читать изображения также не означает поддержку всех форматов файлов.

Метки возможностей Cherry Studio управляют интерфейсом и маршрутизацией запросов. Изменение метки вручную не меняет реальный API провайдера. После изменения выполните минимальный тест.

## Галлюцинации

«Галлюцинация» — связный вывод модели, который не имеет основания, противоречит входным данным или фактически неверен. Частые причины:

* В вопросе отсутствует важный контекст.
* Модель использует устаревшие сведения из обучения.
* Результаты поиска не относятся к вопросу или источники ненадёжны.
* В длинном контексте упущены важные сведения.
* Пользователь требует обязательного ответа, не позволяя оставить пробел.

Способы снизить риск:

* Требовать источники, даты и места во входных данных.
* Разделять факты, выводы и предположения.
* Разрешать ответ «неизвестно».
* Вручную проверять выборку важных данных.
* Передавать решения с высоким риском на проверку специалистам.

Доступ к Интернету и базы знаний могут предоставить новые материалы, но не устраняют галлюцинации автоматически.

## Embedding

Модель Embedding преобразует текст в набор чисел — вектор. Семантически близкие тексты обычно расположены близко в векторном пространстве, что позволяет выполнять поиск по сходству.

Модель Embedding не является чат-моделью. Обычно она возвращает векторы, а не ответы на естественном языке.

### Размерность

Размерность — число значений в векторе. Для индексации и поиска в одной базе знаний нужны совместимые модель и размерность. После смены модели или размерности старые векторы обычно нужно перестроить.

Большая размерность не гарантирует большую точность. Также учитывайте язык, тип текста, предел ввода, скорость, стоимость и фактическое качество поиска.

Подробнее см. [Модели векторизации](../knowledge-base/emb-models-info.md).

## Разбиение и векторный поиск

При создании базы знаний длинный документ сначала делится на небольшие фрагменты, после чего для каждого создаётся вектор.

Слишком большие фрагменты могут:

* Содержать слишком много тем.
* Превысить предел ввода Embedding.
* Занять слишком много контекста при возврате.

Слишком маленькие фрагменты могут:

* Потерять связи между предложениями.
* Создать слишком много индексов и запросов.
* Найти отдельные фразы без достаточного объяснения.

Перекрытие сохраняет часть контекста соседних фрагментов, но увеличивает их число в индексе. Лучшее значение зависит от структуры документа и вида вопросов; выбирайте его с помощью тестов поиска.

## Rerank

Векторный поиск сначала находит набор фрагментов-кандидатов, затем модель Rerank переставляет их для текущего вопроса. Это улучшает порядок кандидатов, но не исправляет:

* Отсутствие ответа в исходном тексте.
* Неверное извлечение документа.
* Полное отсутствие релевантных фрагментов на этапе кандидатов.
* Неверное понимание правильного фрагмента итоговой чат-моделью.

Embedding и Rerank — разные возможности, они не взаимозаменяемы.

## RAG

RAG означает Retrieval-Augmented Generation — генерацию с дополнением поиском. В базе знаний Cherry Studio процесс можно представить так:

1. Извлечение и разбиение документов.
2. Создание индекса с помощью Embedding.
3. Преобразование вопроса пользователя в вектор запроса.
4. Поиск похожих фрагментов.
5. Необязательная перестановка с помощью Rerank.
6. Передача фрагментов чат-модели как контекста.
7. Создание ответа чат-моделью.

Если поиск верен, а ответ ошибочен, проверьте чат-модель и запрос. Если ошибочен сам поиск, проверьте материалы, разбиение, Embedding и Rerank. Полный процесс описан в [руководстве по базе знаний](../knowledge-base/knowledge-base.md).

## MCP

MCP (Model Context Protocol) позволяет приложениям ИИ единообразно подключаться к внешним возможностям. Server может предоставлять:

* **Tools**: выполнять запросы, запись или вызовы API.
* **Prompts**: предоставлять повторно используемые шаблоны запросов.
* **Resources**: предоставлять доступное для чтения содержимое.

MCP — протокол, а не изолированная защищённая среда. STDIO Server может работать локально с правами текущего пользователя, а удалённый Server получает отправленные ему данные. До установки проверьте источник, команды, параметры, переменные среды и область доступа.

Использование описано в разделе [MCP](../advanced-basic/mcp/).

## Навыки

Навык — набор инструкций, процессов и ресурсов для агента. Он в основном сообщает агенту, «как выполнить работу такого типа», тогда как MCP главным образом предоставляет то, «что можно вызвать».

Навык может ссылаться на скрипты, шаблоны или инструменты. Перед установкой прочитайте `SKILL.md` и сопутствующие файлы и включайте только доверенные источники. Подробнее см. [Навыки](../pre-basic/settings/skills.md).

## Ассистенты и агенты

| | Ассистент | Агент |
| :--- | :--- | :--- |
| Основное назначение | Продолжительный чат с фиксированной конфигурацией | Многошаговые задачи в рамках цели и разрешений |
| Локальный рабочий каталог | Нет прав на каталог в стиле агента | Можно ограничить доступные каталоги |
| Инструменты файлов и команд | Расширяются выбранными MCP и аналогичными интеграциями | Доступны встроенные инструменты, MCP и навыки |
| Подходящие задачи | Тексты, вопросы и ответы, поиск по базе знаний | Изменение файлов, выполнение команд, рабочие процессы |

Чтобы выбрать подходящий вариант, см. [Основные понятия](../advanced-basic/concepts-101.md).

## Локальные и облачные модели

### Облачные модели

Запросы отправляются провайдеру. Обычные преимущества: не требуется локальное развёртывание и доступно больше моделей. Необходимо учитывать сеть, учётную запись, стоимость, регион и политику данных провайдера.

### Локальные модели

Вывод модели выполняется на вашем устройстве или сервисе в локальной сети. Это может уменьшить число запросов, отправляемых вовне, но требует достаточного объёма оперативной и видеопамяти, хранилища и вычислительных ресурсов.

«Использование локальной модели» не означает, что весь рабочий процесс полностью автономен. К внешним сервисам могут обращаться:

* Веб-поиск.
* Удалённый MCP.
* Облачные Embedding или Rerank.
* Облачные обработчики документов.
* Генерация изображений, каналы и сторонние интеграции.

При оценке конфиденциальности проверяйте весь поток данных по компонентам, а не только расположение чат-модели.

Настройка локальных моделей описана в разделах [Ollama](../pre-basic/providers/ollama.md) и [LM Studio](../pre-basic/providers/lm-studio.md).

## Источники расходов

Расходы могут возникать за:

* Входные, выходные и рассуждающие Token чат-модели.
* Обработку изображений, аудио и файлов.
* Запросы Embedding и Rerank.
* Генерацию изображений.
* Поиск, обработчики документов, MCP и другие сторонние API.
* Облачное хранилище и сетевой трафик.

Параллельные запросы к нескольким моделям, повторные попытки, длинный контекст и частые запланированные задачи увеличивают использование. Оценки Cherry Studio не заменяют счёт провайдера.

## Данные и конфиденциальность

В одном рабочем процессе данные могут проходить через:

```text
Ввод пользователя
→ Cherry Studio
→ Обработка документов / Поиск / База знаний / MCP
→ Провайдер модели
→ Отображение Cherry Studio или локальные файлы
```

Фактический путь зависит от включённых возможностей. До использования проверьте:

* Покидают ли данные устройство.
* Какой сервис их обрабатывает.
* Сохраняются ли запросы или используются ли они для обучения.
* Где хранятся учётные данные и какие права они предоставляют.
* Содержат ли журналы, резервные копии и снимки экрана конфиденциальные сведения.

Не помещайте API Key, Token, пароли, закрытые ключи или лишние персональные данные в запросы, базы знаний и документы. Сначала обезличивайте особо конфиденциальные материалы и выбирайте модели и инструменты, соответствующие политике организации.

## Рекомендуемый порядок изучения

1. Сначала разберитесь с моделями, провайдерами, Token и контекстом.
2. Выполните небольшую задачу в [Интерфейсе чата](../cherrystudio/preview/chat.md).
3. Сохраните стабильный запрос в ассистенте.
4. Создайте базу знаний и проведите тест поиска.
5. Изучите MCP, когда понадобятся внешние инструменты.
