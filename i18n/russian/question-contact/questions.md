# Часто задаваемые вопросы

Эта страница поможет определить тип проблемы и перейти к нужному разделу устранения неполадок. При сбое сначала сохраните исходную ошибку и данные. Не переустанавливайте приложение, не сбрасывайте данные и не удаляйте каталог приложения сразу же.

## Сначала выполните пять проверок

1. Запишите полный номер версии Cherry Studio в разделе **Настройки → О программе**.
2. Запишите операционную систему, архитектуру процессора и время возникновения проблемы.
3. Сохраните полный текст ошибки, показанный в интерфейсе. Не ограничивайтесь сообщением «не работает».
4. Сузьте область проблемы с помощью нового чата, небольшого файла или простого инструмента.
5. Определите, не работают ли все модели либо только определённый провайдер, модель или функция.

Если проблема появилась после обновления, также запишите предыдущую версию и укажите, переносили ли вы каталог данных.

{% hint style="warning" %}
Сброс данных удаляет локальную базу данных и файлы, которыми управляет приложение. Это не универсальный способ исправления. Не выполняйте его без пригодной резервной копии. Очистка кэша также не исправляет ошибки учётной записи, модели или конфигурации API.
{% endhint %}

## Приложение не устанавливается или не запускается

### Установщик не открывается

Убедитесь, что выбрали правильную операционную систему и архитектуру:

* Для Mac с Apple Silicon используйте пакет arm64, для Mac с Intel — пакет x64.
* В Windows и Linux также выбирайте версию, соответствующую архитектуре устройства.
* Загружайте установщик со страницы [загрузки клиента](../cherrystudio/download.md) или из официальных Release.

Если macOS сообщает, что не удаётся проверить разработчика или файл повреждён, следуйте [руководству по установке на macOS](../pre-basic/installation/macos.md). Не загружайте повторно подписанный установщик из неизвестного источника.

### После запуска пустой экран, нарушена компоновка или пропали кнопки

Если вы использовали пользовательский CSS, сначала откройте [Очистка настроек CSS](../personalization-settings/clear-css.md). Неверный селектор может скрыть вход в настройки, но удаление всего каталога данных также уничтожит другие материалы.

Если пользовательский CSS не использовался, запишите версию и систему, перезапустите приложение и повторите проблему. Если она сохраняется, сохраните журналы и отправьте отчёт.

### После обновления приложение выглядит как новая установка

Проверьте, не меняли ли вы каталог данных приложения, подключён ли внешний диск и не был ли при запуске выбран новый пустой каталог. Не создавайте сразу большой объём данных в новом каталоге и не удаляйте старый. См. [Изменение расположения хранилища](../personalization-settings/storage.md).

## Сервисы моделей

### API Key сохранён, но всё равно не работает

Проверьте по порядку:

1. Провайдер включён.
2. API Key принадлежит текущему провайдеру и региону и не содержит лишних пробелов.
3. В адресе API используется корневой путь и тип конечной точки, требуемые провайдером.
4. Учётной записи доступна нужная модель и действуют баланс, квота или способ оплаты.
5. Модель синхронизирована либо добавлена вручную и включена в списке моделей.

Успешная проверка соединения обычно означает лишь, что один базовый запрос достигает сервиса. Она не подтверждает работу зрения, рассуждений, вызова инструментов, Embedding или генерации изображений. Проверяйте каждую возможность отдельно.

Общие настройки описаны в разделе [Сервисы моделей](../pre-basic/providers/), а ссылки на шаблоны провайдеров — в [кратком справочнике провайдеров](../pre-basic/providers/quick-reference.md).

### Не удаётся получить список моделей

Некоторые совместимые сервисы не предоставляют стандартный список моделей или возвращают только модели, доступные учётной записи. Сначала проверьте Base URL, учётные данные, регион и прокси. Если провайдер разрешает вручную указать Model ID, добавьте его по официальной документации.

Не копируйте Model ID с другой платформы только потому, что он выглядит одинаково. Пространство имён, регистр и суффикс версии могут отличаться.

### Модель видна у провайдера, но отсутствует в чате

Модель должна соответствовать всем условиям:

* Провайдер модели включён.
* Сама модель включена.
* Тип модели подходит для текущего раздела.

Модели Embedding, Rerank и генерации изображений не отображаются как обычные чат-модели. Для агентов также требуется модель, доступная через конечную точку **Anthropic Messages**.

### Распространённые коды состояния HTTP

Провайдеры могут определять ошибки по-разному. Основывайтесь на теле ответа и документации провайдера.

| Статус | Частая причина | Что проверить сначала |
| :--- | :--- | :--- |
| `400` | Недопустимые параметры запроса, контекст или формат содержимого | Конечная точка модели, вложения, длина контекста, пользовательские параметры |
| `401` | Ошибка аутентификации | API Key, способ Authorization, срок действия Key |
| `403` | Недостаточно прав учётной записи, модели, региона или содержимого | Доступ к модели, оплата, регион, права организации |
| `404` | Путь, развёртывание или модель не существуют | Base URL, Deployment, Model ID, тип конечной точки |
| `408` / `504` | Тайм-аут запроса или вышестоящего сервиса | Сеть, прокси, состояние сервиса, размер ввода |
| `413` | Слишком большое тело запроса | Размер изображений и файлов, контекст, пакетный ввод |
| `422` | Параметры разобраны, но не могут быть обработаны | Типы полей, обязательные значения, параметры модели |
| `429` | Ограничение частоты, Token или квоты | RPM/TPM, баланс, параллелизм, повтор позже |
| `500` / `502` / `503` | Внутренняя ошибка вышестоящего сервиса, шлюза или перегрузка | Состояние сервиса, прокси, повтор с меньшим запросом |

Если ошибка возникает только у одной модели, проверьте другую базовую текстовую модель того же провайдера. Если не работает ни один провайдер, затем проверьте локальную сеть и прокси.

## Чат

### После отправки нет ответа

Проверьте фактическую модель и провайдера над сообщением. В чате с несколькими моделями ошибка одной модели не означает ошибку остальных. Просмотрите ошибку каждого ответа отдельно.

Можно создать ассистента по умолчанию и пустой чат, а затем отправить только короткий текст:

```text
Ответьте: соединение работает
```

Если небольшой запрос проходит, а исходный чат — нет, вероятнее всего, причина в длине контекста, вложении, инструменте или пользовательском параметре ассистента. Подробные инструкции см. в разделе [Интерфейс чата](../cherrystudio/preview/chat.md).

### Контекст или тело запроса слишком велики

Сократите историю сообщений, отключите ненужный контекст, удалите большие вложения или начните новый чат. Очистка контекста меняет только историю, отправляемую модели в последующих запросах; она не удаляет все сообщения из интерфейса.

### Не удаётся загрузить изображение или модель его не понимает

Убедитесь, что у модели есть метка поддержки зрения и текущая конечная точка провайдера действительно принимает изображения. Ручной выбор возможности меняет только фильтры интерфейса и маршрутизацию запросов Cherry Studio. Он не добавляет возможность, которой нет на сервере.

При загрузке изображения в чат с несколькими моделями все упомянутые модели должны поддерживать изображения на входе.

### Формулы отображаются как исходный текст

Сначала убедитесь, что модель вывела полные разделители:

* Встроенная формула: `$...$` или `\(...\)`
* Отдельная формула: `$$...$$` или `\[...\]`

Формула не отображается как математическая, если разделители помещены в блок кода, неверно экранированы или вывод модели обрезан. Перед выводом о проблеме отображения просмотрите исходное сообщение.

## Сеть и прокси

### Браузер подключается, а Cherry Studio — нет

Системный браузер и приложение Electron могут использовать разные прокси, сертификаты или сеансы входа. Откройте [Общие настройки](../cherrystudio/preview/settings/general.md) и проверьте режим и адрес прокси, а также необходимость перезапуска.

Также проверьте:

* Не блокирует ли корпоративная сеть или брандмауэр нужный домен.
* Не заменён ли сертификат HTTPS прокси-сервером.
* Правильно ли установлено системное время.
* Нет ли у сервиса регионального ограничения или требования входа.

Не используйте отключение защитного ПО или игнорирование ошибок сертификатов как постоянное решение проблем соединения.

### После включения прокси все запросы завершаются ошибкой

Для сравнения временно вернитесь к системному прокси или отключите прокси. Ручному прокси нужны правильные протокол, хост и порт. HTTP, HTTPS и SOCKS нельзя считать взаимозаменяемыми только из-за одинакового порта.

## База знаний

### Не удаётся создать базу знаний или получить размерность

Перед созданием базы знаний нужна работающая модель Embedding. Проверьте:

1. Выбрана модель Embedding, а не обычная чат-модель.
2. Провайдер, API Key, Base URL и Model ID указаны правильно.
3. Модель может выполнить реальный запрос векторизации.
4. Размерность вектора в ответе модели соответствует конфигурации.

Подробное устранение неполадок см. в разделе [Модели векторизации](../knowledge-base/emb-models-info.md).

### Файл долго обрабатывается или помечен как неудачный

Дождитесь завершения текущей очереди и затем просмотрите состояние ошибки. Частые причины: файл невозможно прочитать, веб-страница недоступна, обработчик документов завершился ошибкой, запрос Embedding не прошёл или сработало ограничение частоты.

После исправления конфигурации переиндексируйте неудачный источник. Полный процесс описан в [руководстве по базе знаний](../knowledge-base/knowledge-base.md).

### Ответы в чате неточны

Сначала с помощью теста поиска проверьте, найдены ли правильные фрагменты:

* Поиск неверен: настройте материалы, разбиение, Embedding или Rerank.
* Поиск верен, но ответ неверен: проверьте чат-модель, запрос и контекст.

База знаний предоставляет найденные фрагменты, но окончательный ответ всё равно создаёт чат-модель.

## Агенты

### Модель отсутствует в списке выбора агента

Агентам нужен тип конечной точки, включающий **Anthropic Messages**; модели Embedding, Rerank и генерации изображений исключаются. Проверьте конечную точку и метки возможностей, затем подтвердите совместимость простым заданием с инструментом.

### На странице агента указано, что сервис не запущен

Сначала нажмите кнопку запуска на странице. Если проблема сохраняется, откройте **Настройки → Сервер API** и проверьте порт и состояние. Если порт занят другой программой, остановите конфликтующий процесс или выберите свободный порт.

### Агент не может читать или записывать файлы

Проверьте, добавлен ли нужный каталог в доступные пути, включён ли инструмент и одобрены ли запросы разрешений. Не добавляйте весь пользовательский каталог или диск в доступные пути только для обхода ошибки.

Дополнительные сведения см. в разделах [Агенты](../advanced-basic/agent.md) и [Сервер API](../advanced-basic/api-server.md).

## MCP

### Server не запускается

Для локального STDIO Server сначала проверьте Command, Arguments, среду выполнения и рабочий каталог. Для удалённого Server сначала проверьте URL, Headers, аутентификацию и тип протокола.

Откройте **Просмотр журналов** в сведениях о Server, отключите и снова включите его. Так проще найти первую ошибку запуска. Полный список см. в разделе [Часто задаваемые вопросы MCP](../advanced-basic/mcp/chang-jian-wen-ti.md).

### Server подключён, но инструментов нет

Успешное подключение не гарантирует, что Server предоставляет Tools. Он может предоставлять только Prompts или Resources. Проверьте список возможностей в сведениях о Server и наличие в журнале ошибок инициализации или `listTools`.

### Модель описывает инструмент, но не вызывает его

Убедитесь, что:

* Текущий ассистент или агент подключён к MCP Server.
* Server включён, а нужный инструмент виден.
* Текущая модель и конечная точка поддерживают вызов инструментов.
* Разрешение на использование инструмента не было отклонено.

## Данные, резервное копирование и восстановление

### Автоматические резервные копии не создаются

Убедитесь, что расписание не установлено в «Выкл.», каталог назначения или удалённый сервис доступен, и просмотрите последнюю ошибку на странице. Для внешнего диска, NAS или удалённого хранилища также проверьте свободное место, разрешения и соединение.

### После восстановления отсутствуют изображения или файлы базы знаний

Если было включено **Компактное резервное копирование**, изображения и файлы базы знаний в каталоге приложения `Data` не сохранялись. Это ожидаемое поведение; исключённые файлы нельзя восстановить из компактной резервной копии.

### Данные с нескольких компьютеров не объединяются автоматически

Резервное копирование и восстановление перезаписывают данные, а не выполняют двустороннюю синхронизацию в реальном времени. Перед восстановлением сравните версии и время и сначала создайте резервную копию текущего устройства.

Подробнее см. [Настройки данных](../data-settings/README.md).

## Получение журналов

Перейдите в **Настройки → Настройки данных → Данные** и откройте каталог журналов через пункт **Журналы приложения**. Воспроизведите проблему и найдите файл по времени события.

Перед отправкой удалите или скройте:

* API Key, Token, Cookie и аутентификационные Header.
* Содержимое чатов, запросов, баз знаний и файлов.
* Адреса электронной почты, имена пользователей, личные каталоги и внутренние сетевые адреса.
* Запросы к сторонним сервисам и ответы от них.

Одна ошибка может занимать несколько строк журнала. Сохраните необходимый контекст непосредственно до и после ошибки, но не публикуйте весь каталог данных приложения или файл резервной копии.

## Что включить в отчёт

Полезный для обработки отчёт должен содержать как минимум:

```text
Версия Cherry Studio:
Операционная система и архитектура:
Провайдер и модель (если применимо):
Время возникновения проблемы:
Ожидаемый результат:
Фактический результат:
Минимальные шаги воспроизведения:
Полный текст ошибки:
Уже выполненные действия:
Обезличенный журнал или снимок экрана:
```

Сначала прочитайте [Как задавать вопросы эффективно](ask.md), затем отправьте отчёт через канал из раздела [Обратная связь и предложения](suggestions.md). Для сбоев или проблем с данными укажите наличие резервной копии, перенос каталога данных и продолжали ли вы записывать данные после возникновения проблемы.
