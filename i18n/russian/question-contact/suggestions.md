# Отзывы и предложения

Правильный канал и воспроизводимые сведения значительно ускоряют подтверждение и решение проблемы.

## Сначала выберите канал

| Потребность | Рекомендуемый канал | Что следует отправлять |
| :--- | :--- | :--- |
| Ошибка в программе | [GitHub Bug Report](https://github.com/CherryHQ/cherry-studio/issues/new/choose) | Сбои, неправильная работа функций, регрессии, ошибки интерфейса |
| Предложение функции | [GitHub Feature Request](https://github.com/CherryHQ/cherry-studio/issues/new/choose) | Новые функции, улучшения взаимодействия, расширение существующих возможностей |
| Обсуждение использования | [GitHub Discussions](https://github.com/CherryHQ/cherry-studio/discussions) | Способы использования, обмен опытом, обсуждение решений |
| Уязвимость безопасности | [GitHub Security Advisory](https://github.com/CherryHQ/cherry-studio/security/advisories/new) | Уязвимости, которые могут привести к утечке данных, обходу прав или несанкционированным действиям |
| Невозможно использовать GitHub | [support@cherry-ai.com](mailto:support@cherry-ai.com) | Невозможно войти в GitHub или обычные сведения для поддержки, которые нельзя публиковать |

{% hint style="warning" %}
Не отправляйте уязвимость в открытый Issue и не публикуйте подробности воспроизведения в групповых чатах. Используйте закрытый Security Advisory.
{% endhint %}

## Четыре действия перед отправкой

1. Обновитесь до последней стабильной версии и убедитесь, что проблема воспроизводится.
2. Просмотрите [частые вопросы](questions.md) и исключите проблемы с настройками, лимитами, сетью и провайдером модели.
3. Выполните поиск в существующих [Open Issues](https://github.com/CherryHQ/cherry-studio/issues), [Closed Issues](https://github.com/CherryHQ/cherry-studio/issues?q=is%3Aissue%20state%3Aclosed) и [Discussions](https://github.com/CherryHQ/cherry-studio/discussions).
4. Удалите из снимков экрана, журналов и настроек API Key, Token, Cookie, личные пути к файлам и конфиденциальное содержимое разговоров.

Если такая проблема уже зарегистрирована, добавьте новые сведения о воспроизведении вместо создания дублирующего Issue.

## Сообщение об ошибке

### Заголовок

Включите в заголовок **функцию, платформу и проявление**, чтобы сопровождающий мог понять суть, не открывая описание.

```text
[Bug] macOS: после повторной индексации база знаний постоянно показывает обработку
```

Не ограничивайтесь формулировками «не работает», «есть проблема» или «исправьте».

### Обязательные сведения

Обрабатываемый отчёт об ошибке должен содержать как минимум:

* версию Cherry Studio;
* Windows, macOS или Linux и версию системы;
* задействованные функцию, провайдера и название модели; не указывайте API Key;
* последовательность действий для стабильного воспроизведения;
* фактический и ожидаемый результат;
* версию или действие, после которых возникла проблема;
* уже выполненные проверки;
* необходимые снимки экрана, запись экрана и обезличенные журналы.

Версию можно посмотреть в разделе **Настройки → О программе**. Журналы открываются через **Настройки → Настройки данных → Данные → Логи приложения**.

### Рекомендуемый шаблон

```markdown
## Окружение

- Cherry Studio:
- Система:
- Источник установки:
- Провайдер / модель:

## Шаги воспроизведения

1.
2.
3.

## Фактический результат


## Ожидаемый результат


## Дополнительные сведения

- Воспроизводится стабильно:
- Версия, с которой возникло:
- Уже проверено:
- Обезличенный журнал / снимок экрана:
```

### Минимальное воспроизведение

Если проблема связана с конкретным ассистентом, базой знаний, MCP или пользовательским CSS, сначала сократите число переменных:

* создайте пустого ассистента или новую тему;
* временно отключите не относящиеся к проблеме MCP, навыки и веб-поиск;
* используйте небольшой тестовый фрагмент без конфиденциальных данных;
* запишите, после включения какой настройки появляется проблема.

Минимальное воспроизведение обычно помогает найти причину лучше, чем снимок всего окружения.

## Предложение функции

Опишите не только «что хотелось бы получить», но и «какая проблема существует сейчас».

Рекомендуется включить:

1. **Сценарий использования**: кто и в каком рабочем процессе сталкивается с проблемой.
2. **Текущее препятствие**: почему существующие функции не решают задачу.
3. **Ожидаемый результат**: желаемые действия и вывод.
4. **Альтернатива**: как задача решается сейчас и каковы недостатки обходного пути.
5. **Объём и границы**: что необходимо поддержать, а что можно отложить.
6. **Наглядные материалы**: при необходимости обезличенные снимки, схема процесса или эскиз интерфейса.

По возможности обсуждайте в одном Issue только одну независимую потребность. Несвязанные требования в одной записи усложняют определение объёма и планирование.

Направление проекта можно посмотреть в [Cherry Studio Roadmap](https://github.com/orgs/CherryHQ/projects/7). Roadmap не является обещанием поставки; фактические объём и сроки определяются последними сообщениями сопровождающих.

## Вопросы и обсуждения

Обычные вопросы по использованию можно задать в [GitHub Discussions](https://github.com/CherryHQ/cherry-studio/discussions). Вместе с вопросом укажите:

* какую цель вы хотите достичь;
* текущую конфигурацию и путь действий;
* что уже проверено;
* на каком шаге возникло затруднение;
* какая помощь требуется.

Если вопрос содержит стабильно воспроизводимый дефект программы, используйте Bug Report. Для новой потребности, состояние реализации которой необходимо отслеживать, используйте Feature Request.

## Сообщение о проблеме безопасности

Если вы обнаружили один из следующих случаев, отправьте закрытый отчёт через [GitHub Security Advisory](https://github.com/CherryHQ/cherry-studio/security/advisories/new):

* API Key, Token или локальные данные могут быть прочитаны непредусмотренным способом;
* проверку прав можно обойти;
* недоверенное содержимое может запустить несанкционированную команду или операцию с файлами;
* пакет обновления, зависимость или сетевое соединение содержит эксплуатируемый риск.

Включите в отчёт область влияния, шаги воспроизведения, необходимые доказательства и возможные меры снижения риска. Не отправляйте реальные пользовательские данные или действующие учётные данные.

По вопросам безопасности, не связанным с уязвимостями, можно написать на [security@cherry-ai.com](mailto:security@cherry-ai.com).

## Защита конфиденциальности

Перед отправкой убедитесь, что:

* API Key, Token доступа, Cookie и пароли полностью скрыты;
* имена людей, компаний и проектов в путях к файлам обезличены;
* в разговорах, базах знаний и документах нет ненужных персональных или деловых данных;
* в журнале оставлен только период, связанный с проблемой;
* на снимке экрана не видны конфиденциальные сведения из других приложений, вкладок браузера или уведомлений.

Если учётные данные уже опубликованы, недостаточно удалить сообщение. Немедленно отзовите их в консоли соответствующего провайдера и создайте новые.
