# Резервное копирование в S3-совместимое хранилище

Cherry Studio V2 может сохранять резервные копии в объектные хранилища с S3-совместимым API, включая AWS S3, Cloudflare R2, Alibaba Cloud OSS, Tencent Cloud COS, Volcengine TOS и MinIO.

Здесь S3 — удалённое расположение резервных копий, а не сервис синхронизации в реальном времени. Восстановление перезаписывает текущие данные выбранной копией и не объединяет содержимое, отдельно добавленное на разных устройствах.

{% hint style="warning" %}
Резервная копия может содержать чаты, конфигурацию провайдеров и другие конфиденциальные сведения. Bucket должен оставаться закрытым. Используйте отдельные учётные данные с доступом только к целевому Bucket или каталогу.
{% endhint %}

## Подготовка Bucket и учётных данных

В консоли объектного хранилища:

1. Создайте или выберите закрытый Bucket.
2. Уточните Region, в котором находится Bucket.
3. Найдите предоставленный сервисом S3 API Endpoint.
4. Создайте отдельные учётные данные доступа для Cherry Studio.
5. Если сервис позволяет, ограничьте доступ каталогом Cherry Studio в этом Bucket.

Cherry Studio нужны как минимум права на перечисление, загрузку и чтение объектов. Для автоматического удаления старых копий и удаления через диспетчер также требуется право удаления объектов.

Названия прав зависят от сервиса. В AWS IAM обычно используются `s3:ListBucket`, `s3:PutObject`, `s3:GetObject` и `s3:DeleteObject`. В других совместимых сервисах используйте эквивалентные права.

## Поля конфигурации

Откройте **Настройки > Настройки данных > S3** и заполните:

| Поле | Описание |
| --- | --- |
| Адрес API | S3 API Endpoint провайдера с `http://` или `https://` |
| Регион | Region Bucket; используйте точное значение провайдера |
| Bucket | Имя Bucket, а не отображаемое имя в консоли или каталог |
| Access Key ID | Идентификатор отдельных учётных данных |
| Secret Access Key | Секрет, соответствующий Access Key ID |
| Каталог резервных копий | Необязательный префикс Key объекта для изоляции резервных копий Cherry Studio |

Все поля, кроме **Каталог резервных копий**, обязательны для ручного копирования и открытия диспетчера резервных копий.

### Не добавляйте Bucket в Endpoint повторно

Формат Endpoint задаётся провайдером: адрес может относиться к региону, учётной записи или собственному сервису. Cherry Studio передаёт **Bucket** клиенту S3 отдельным параметром, поэтому не добавляйте Bucket в адрес самостоятельно, если это прямо не требуется документацией S3 SDK провайдера.

Адрес веб-консоли, публичный URL объекта и S3 API Endpoint могут полностью отличаться. Копируйте «S3-совместимый Endpoint», а не URL файла, открытого в браузере.

Cherry Studio выбирает virtual-host или path-style запрос по домену Endpoint:

- Распознанные официальные домены Alibaba Cloud, Tencent Cloud и Volcengine используют virtual-host
- `localhost`, IP-адреса и большинство других совместимых сервисов используют path-style
- Нераспознанный адрес возвращается к path-style

Если сервис поддерживает несколько форм адреса, используйте Endpoint из его документации AWS SDK / S3 SDK.

### Настройка каталога резервных копий

**Каталог резервных копий** становится префиксом Key объекта. Можно указать `cherry-studio` или `/cherry-studio/`; при сохранении лишние начальные и конечные `/` удаляются.

Для каждого набора данных Cherry Studio рекомендуется отдельный префикс, например:

```text
cherry-studio/personal
```

Диспетчер показывает только объекты с окончанием `.zip` под этим префиксом. После изменения каталога старые копии не перемещаются и не отображаются в новом списке.

## Проверка конфигурации

На странице нет отдельной кнопки «Проверить соединение». Наиболее полная проверка:

1. Заполните обязательные поля и временно отключите автоматическое копирование.
2. Нажмите **Создать копию сейчас**.
3. Создайте небольшую тестовую копию с именем по умолчанию.
4. Нажмите **Управление резервными копиями**.
5. Убедитесь, что в списке видны загруженный ZIP, время изменения и размер.

Этот процесс одновременно проверяет Endpoint, Region, Bucket, учётные данные, каталог копий и права на перечисление и запись. Если Bucket отображается, но загрузка не работает, обычно нет права записи объекта. Если загрузка проходит, а файл не виден, проверьте префикс и право перечисления.

## Ручное резервное копирование

После нажатия **Создать копию сейчас** можно подтвердить или изменить имя файла. Имя по умолчанию содержит время, имя хоста и тип устройства. Если нет расширения `.zip`, оно добавляется автоматически.

При включении **Компактная резервная копия** Cherry Studio исключает изображения, базы знаний и другие файловые данные из каталога приложения `Data`, сохраняя чаты, настройки и аналогичные данные. Это не инкрементная копия; исключённые файлы нельзя вернуть при восстановлении.

Перед загрузкой в S3 ZIP создаётся локально и считывается в память. Большая полная копия может заметно увеличить использование диска и памяти. Не закрывайте приложение, не отключайте сеть и не переводите систему в спящий режим во время операции.

## Автоматическое копирование и число копий

**Автоматическая синхронизация** фактически создаёт периодические резервные копии. Доступны:

- Выкл.
- Каждые 1, 5, 15 или 30 минут
- Каждые 1, 2, 6, 12 или 24 часа

Сначала успешно создайте ручную копию и только затем включайте автоматическое копирование. Чем выше частота, тем больше запросов, трафика и стоимости операций объектного хранилища.

Для **Максимального числа резервных копий** доступны: без ограничений, 1, 3, 5, 10, 20 или 50. После достижения лимита Cherry Studio удаляет старые копии текущего устройства по имени хоста и типу устройства в стандартном имени файла.

Обычно автоматически не удаляются:

- Копии других устройств
- Копии с пользовательским именем без идентификатора текущего устройства
- Объекты вне текущего каталога резервных копий
- Объекты без окончания `.zip`

При выборе «Без ограничений» настройте в объектном хранилище предупреждение о заполнении или правило жизненного цикла, чтобы данные не накапливались бесконечно.

## Управление и восстановление

Нажмите **Управление резервными копиями**, чтобы просматривать, обновлять, восстанавливать и удалять ZIP-копии из текущего каталога.

Перед восстановлением:

1. Создайте ещё одну резервную копию текущих данных.
2. Проверьте целевую версию по имени, времени изменения и размеру.
3. Убедитесь, что другое устройство не записывает данные в тот же каталог.
4. Нажмите **Восстановить** у нужного файла и подтвердите перезапись.

После восстановления приложение может автоматически перезапуститься. Удаление объекта необратимо. Если у учётных данных нет права удаления, просмотр и восстановление могут работать, а удаление и автоматическая очистка — нет.

{% hint style="warning" %}
Несколько компьютеров могут использовать один Bucket и префикс, но восстановление не объединяет данные. При переносе между устройствами сначала сохраните целевое устройство, затем восстановите нужную версию исходного.
{% endhint %}

## Рекомендации по безопасности и расходам

- Используйте закрытый Bucket и не разрешайте публичное чтение каталога резервных копий
- Используйте отдельный Access Key с минимальными правами, а не корневые учётные данные облачного аккаунта
- Не показывайте полный Secret Access Key на снимках, в журналах и отчётах
- Для публичного Endpoint используйте HTTPS; собственный MinIO также должен иметь доверенный сертификат или быть доступен только в доверенной сети
- Учитывайте стоимость объёма хранилища, запросов PUT / GET / LIST и исходящего трафика
- При утечке ключа немедленно отзовите и пересоздайте его в консоли провайдера, а не только измените значение в Cherry Studio

## Часто задаваемые вопросы

### Кнопка немедленного копирования неактивна

Убедитесь, что заполнены адрес API, Region, Bucket, Access Key ID и Secret Access Key. Каталог резервных копий можно оставить пустым.

### Возвращается 301, PermanentRedirect или несоответствие Region

Endpoint или Region не соответствует региону Bucket. Откройте консоль хранилища и скопируйте S3 Endpoint и точный Region этого Bucket.

### Возвращается 403, AccessDenied или SignatureDoesNotMatch

Проверьте пару Access Key и Secret, действительность учётных данных и системное время. Также проверьте формат Endpoint, Region и политику минимальных прав. Ошибка подписи часто возникает из-за несоответствия адреса или региона.

### Не удаётся подключиться к собственному MinIO

Убедитесь, что Endpoint содержит порт, например `https://minio.example.com:9000`, и устройство с Cherry Studio может открыть этот адрес. Для IP или `localhost` используется path-style. Если MinIO расположен за обратным прокси, проверьте сертификат, предел тела запроса и тайм-аут.

### Загрузка работает, но файл не виден в диспетчере

Убедитесь, что текущий **Каталог резервных копий** совпадает с использованным при загрузке, а учётные данные позволяют перечислять Bucket. Диспетчер показывает только объекты с окончанием `.zip` под текущим префиксом.

### Старые файлы остаются после достижения максимума

Автоматическая очистка распознаёт только копии текущего устройства со стандартным именем. Пользовательские имена, другие устройства и другие префиксы нужно удалять вручную или обрабатывать правилом жизненного цикла хранилища.

### Большая копия увеличивает использование памяти

Текущая загрузка S3 считывает созданный ZIP в память. Можно включить **Компактная резервная копия**, уменьшить объём баз знаний и изображений либо запускать операцию при меньшем объёме данных.

Если проблема сохраняется, отправьте через [Обратная связь и предложения](../../question-contact/suggestions.md) версию Cherry Studio, название хранилища, обезличенные Endpoint / Region / Bucket, код состояния HTTP и полный текст ошибки.
