# Память рабочего пространства агента

В Cherry Studio V2 агент может сохранять важную информацию между несколькими сеансами в одном рабочем пространстве. Память хранится в папке `memory` внутри первого доступного агенту каталога. Включать глобальную память или настраивать модель Embedding не требуется.

Эта функция предназначена для задач агента: обычные диалоги не добавляются в память автоматически. Память привязана к рабочему пространству. Если несколько агентов используют один каталог в качестве первого доступного каталога, они обращаются к одним и тем же файлам памяти.

## Требования

Для агента необходимо настроить доступный каталог. Первый доступный каталог становится рабочим пространством, а файлы памяти сохраняются по следующему пути:

```text
<workspace>/memory/
├── FACT.md
└── JOURNAL.jsonl
```

Если у агента нет доступного каталога, читать и записывать память рабочего пространства невозможно.

## Два типа памяти

| Файл | Что хранится | Как используется |
| :--- | :--- | :--- |
| `FACT.md` | Долговременные факты, договоренности и технические решения | Загружается для агента в последующих сеансах и обновляется при изменении фактов |
| `JOURNAL.jsonl` | Завершенные задачи, разовые события и записи сеансов | Дополняется в хронологическом порядке; агент выполняет поиск по мере необходимости, а весь файл не загружается в контекст |

Чтобы решить, следует ли сохранять информацию в `FACT.md`, спросите себя: «Будет ли она важна через шесть месяцев?» Ход или результат отдельной задачи лучше записать в Journal.

## Как попросить агента запомнить информацию

Сообщите агенту непосредственно в сеансе, что нужно сохранить. Например:

> Запомни: в этом проекте используется pnpm, а перед коммитом нужно запускать lint и модульные тесты.

Долгосрочные правила попросите добавить в постоянные факты, а разовый прогресс — записать в Journal. Для записи агент использует встроенный инструмент памяти рабочего пространства.

{% hint style="warning" %}
Файлы памяти находятся в локальном рабочем пространстве. Не просите агента сохранять пароли, API-ключи, токены доступа и другие конфиденциальные данные.
{% endhint %}

## Использование в последующих сеансах

Если начать новый сеанс в том же рабочем пространстве с агентом, поддерживающим память рабочего пространства, Cherry Studio передаст ему постоянные факты из `FACT.md`. Чтобы найти сведения о предыдущем событии, попросите агента выполнить поиск в Journal. Например:

> Найди записи о сбое публикации на прошлой неделе.

Результаты поиска можно отфильтровать по тексту и тегу; сначала возвращаются последние совпадающие записи.

Сейчас автоматическая загрузка `FACT.md` доступна в Soul Mode и для обычных пользовательских агентов. Встроенный Cherry Assistant не загружает эти факты рабочего пространства автоматически.

## Просмотр и обслуживание памяти

Откройте `memory/FACT.md` в рабочем пространстве, чтобы узнать, какие долговременные сведения сохранены. Если факт нужно исправить, рекомендуется попросить агента обновить память в сеансе, чтобы запись была безопасно выполнена через инструмент памяти.

`JOURNAL.jsonl` содержит по одной JSON-записи в каждой строке. Рекомендуется искать записи с помощью агента и не переписывать файл вручную.

## Если агент ничего не запомнил

Проверьте следующее по порядку:

1. Настроен ли для текущего агента доступный каталог.
2. Указывает ли первый доступный каталог текущего агента на прежнее рабочее пространство.
3. Записана ли нужная информация в `memory/FACT.md`.
4. Является ли искомая информация долговременным фактом или разовой записью в Journal.

Глобальная память из предыдущих версий и память рабочего пространства агента в V2 — отдельные механизмы. При диагностике памяти V2 ориентируйтесь на `memory/FACT.md` и `memory/JOURNAL.jsonl` в текущем рабочем пространстве.
