# Инструменты для кода

Раздел «Инструменты для кода» позволяет настраивать и запускать CLI-инструменты для программирования с ИИ прямо из Cherry Studio. Вы можете использовать уже настроенные сервисы моделей, выбрать каталог проекта и терминал, а затем работать с CLI в отдельном окне терминала.

## Перед началом

* Для работы инструментов требуется **Bun**. Если на странице указано, что Bun не установлен, нажмите **Установить Bun**.
* Для Kimi CLI дополнительно требуется **uv**. Его можно установить в разделе **Настройки → Настройки MCP → Зависимости среды**.
* Для всех инструментов, кроме GitHub Copilot CLI, заранее настройте в Cherry Studio доступный сервис моделей и API Key.

{% hint style="warning" %}
CLI-инструменты для программирования с ИИ могут читать и изменять файлы, а также выполнять команды в выбранном рабочем каталоге. Перед началом работы сохраните текущую версию с помощью Git или другим способом и не выбирайте каталоги с посторонними конфиденциальными файлами.
{% endhint %}

## Как открыть инструменты для кода

1. Нажмите `+` справа на верхней панели вкладок, чтобы открыть панель запуска.
2. Нажмите **Code**.
3. На странице инструментов для кода выберите нужный CLI.

В настоящее время поддерживаются:

| CLI | Источник моделей |
| :--- | :--- |
| Claude Code | Модели, совместимые с Anthropic |
| Qwen Code | Модели, совместимые с OpenAI |
| Gemini CLI | Модели, совместимые с Gemini |
| OpenAI Codex | Модели, совместимые с OpenAI или OpenAI Responses |
| iFlow CLI | Модели, совместимые с OpenAI |
| GitHub Copilot CLI | Выбор модели не отображается; используются собственная аутентификация и модели GitHub Copilot |
| Kimi CLI | Модели, совместимые с OpenAI |
| OpenCode | Модели, совместимые с OpenAI, OpenAI Responses или Anthropic |

Список моделей автоматически фильтруется по типу интерфейса выбранного CLI. Если нужная модель не отображается, проверьте, включён ли провайдер, добавлена ли модель и совместим ли тип интерфейса.

## Настройка и запуск

Выберите карточку CLI и заполните следующие поля в окне настройки:

1. **Модель**: выберите модель, которую будет использовать CLI. Для GitHub Copilot CLI этого поля нет.
2. **Рабочий каталог**: выберите каталог проекта, в котором должен запуститься CLI. Недавно использованные каталоги сохраняются в списке.
3. **Терминал**: в macOS или Windows выберите обнаруженный терминал. Если в Windows не удалось автоматически найти исполняемый файл WSL, Alacritty или WezTerm, укажите пользовательский путь к нему.
4. **Переменные окружения**: вводите по одной переменной на строку в формате `KEY=value`. Cherry Studio автоматически создаёт необходимые переменные на основе выбранной модели. Пользовательская переменная с тем же именем переопределяет автоматически созданное значение.
5. **Автоматически обновлять до последней версии**: включите при необходимости. Перед запуском Cherry Studio проверит наличие обновления и обновит выбранный CLI.
6. Нажмите **Запуск**.

Если CLI ещё не установлен, Cherry Studio скачает и установит его при первом запуске, а затем запустит в выбранном терминале и рабочем каталоге. Kimi CLI скачивается и запускается с помощью uv, поэтому для его первого запуска также требуется подключение к сети.

{% hint style="info" %}
GitHub Copilot CLI не использует выбор модели в Cherry Studio. Если требуются дополнительные данные для аутентификации, добавьте их в поле переменных окружения в соответствии с требованиями CLI, например `GITHUB_TOKEN`.
{% endhint %}

## Переменные окружения и учётные данные

Помимо пользовательских переменных окружения, Cherry Studio считывает из выбранного сервиса моделей адрес API, идентификатор модели и API Key, а затем преобразует их в переменные или аргументы запуска, необходимые соответствующему CLI.

Пользовательские переменные можно использовать для адреса прокси-сервера или специальных параметров CLI. Перед вводом проверьте имя переменной. Пользовательское значение имеет приоритет над автоматически созданным значением с тем же именем, поэтому неверное переопределение может привести к ошибке аутентификации или подключения.

{% hint style="warning" %}
Не публикуйте API Key, GitHub Token и другие учётные данные в снимках экрана, журналах или общедоступных обсуждениях. Инструменты для кода сохраняют пользовательские переменные окружения в текущей конфигурации, поэтому используйте их только на доверенном устройстве.
{% endhint %}

## Устранение неполадок

### Кнопка запуска недоступна

Убедитесь, что Bun установлен и выбран рабочий каталог. Для всех инструментов, кроме GitHub Copilot CLI, также требуется выбрать модель.

### Список моделей пуст

Для выбранного CLI отображаются только модели с совместимым типом интерфейса. Вернитесь к настройкам сервиса моделей и проверьте, включён ли провайдер, доступен ли API Key, добавлена ли модель и совместим ли тип её конечной точки (Endpoint).

### Kimi CLI сообщает, что uv не найден

Установите uv в разделе **Настройки → Настройки MCP → Зависимости среды**. Если uv по-прежнему не распознаётся сразу после установки, перезапустите Cherry Studio.

### Терминал не открывается

Выберите системный терминал по умолчанию. Если в Windows используется другой терминал, убедитесь, что соответствующее приложение установлено. Для WSL, Alacritty или WezTerm также можно указать исполняемый файл с помощью команды **Настроить пользовательский путь терминала**.

Первый запуск, установка CLI и проверка обновлений требуют подключения к сети и могут занять некоторое время. При ошибке проверьте настройки сети, прокси-сервера и API, а затем повторите запуск.
