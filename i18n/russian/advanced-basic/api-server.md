# Сервер API

Сервер API предоставляет настроенные в Cherry Studio модели, MCP и базы знаний через локальный HTTP API. Другие приложения могут обращаться к этим возможностям в формате запросов, совместимом с OpenAI или Anthropic, поэтому ключи поставщиков не нужно настраивать отдельно в каждом инструменте.

Основные сценарии:

* Использование настроенных в Cherry Studio поставщиков моделей из скриптов и сторонних инструментов.
* Ведение диалога через форматы OpenAI Chat Completions или Anthropic Messages.
* Получение сведений о серверах MCP и поиск по базам знаний Cherry Studio из внешних программ.
* Поддержка страницы Agent и некоторых внутренних операций Cherry Studio.

{% hint style="info" %}
В настоящее время для работы страницы Agent требуется сервер API. Если Cherry Studio обнаружит существующий Agent, приложение попытается запустить сервер автоматически. Если сервер остановлен, на странице Agent появится предложение снова включить его. Каналы и задачи по расписанию используют отдельные локальные службы основного процесса, поэтому отдельно включать для них сервер API не требуется.
{% endhint %}

## Запуск сервера

1. Откройте `Настройки → Сервер API`.
2. Убедитесь, что порт свободен. Порт по умолчанию — `23333`; допустимый диапазон — от `1000` до `65535`.
3. Нажмите **Запустить**.

После запуска на странице появятся статус **Работает**, адрес сервера и кнопка **Документация API**. При стандартной конфигурации используется адрес:

```
http://127.0.0.1:23333
```

Во время работы сервера порт изменить нельзя. Чтобы выбрать другой порт, сначала нажмите **Остановить**, измените значение и запустите сервер снова.

При следующем запуске Cherry Studio сервер попытается запуститься автоматически, если выполняется хотя бы одно условие:

* при предыдущем выходе сервер API оставался включён;
* в Cherry Studio уже существует Agent.

{% hint style="warning" %}
Сервер API работает вместе с Cherry Studio. После выхода из приложения локальный API также остановится.
{% endhint %}

## Ключ API

При первом запуске Cherry Studio создаёт ключ API с префиксом `cs-sk-` и сохраняет его локально. Перезапуск сервера или приложения не меняет ключ автоматически.

Защищённые API поддерживают два вида заголовков аутентификации:

```
Authorization: Bearer YOUR_API_KEY
```

или:

```
x-api-key: YOUR_API_KEY
```

На странице настроек по умолчанию показан формат Bearer и доступна кнопка копирования. Чтобы заменить ключ, сначала остановите сервер, а затем нажмите **Создать заново**. После создания нового ключа старый сразу перестанет проходить проверку.

{% hint style="danger" %}
Ключ API позволяет обращаться к включённым в Cherry Studio моделям и функциям обработки данных. Не добавляйте настоящий ключ в репозиторий кода, снимки экрана, документацию или общедоступные чаты. Рекомендуется передавать его вызывающей программе через переменную окружения.
{% endhint %}

## Доступные API

После запуска сервера откройте **Документацию API** в правом верхнем углу страницы или перейдите напрямую:

* `/api-docs` — интерактивная документация Swagger
* `/api-docs.json` — документ OpenAPI в формате JSON

Основные общедоступные API:

| Возможность | API |
|---|---|
| Состояние сервера | `GET /health` |
| Диалог в формате OpenAI | `POST /v1/chat/completions` |
| Диалог в формате Anthropic | `POST /v1/messages` |
| Диалог в формате Anthropic с указанным поставщиком | `POST /{provider_id}/v1/messages` |
| Список и сведения о серверах MCP | `GET /v1/mcps`, `GET /v1/mcps/:server_id` |
| Список и сведения о базах знаний | `GET /v1/knowledge-bases`, `GET /v1/knowledge-bases/:id` |
| Поиск по базам знаний | `POST /v1/knowledge-bases/search` |

Для `GET /`, `GET /health`, `/api-docs` и `/api-docs.json` аутентификация не требуется. Для моделей, MCP, баз знаний и остальных API в `/v1` нужен ключ API.

{% hint style="info" %}
Текущий API не предоставляет `GET /v1/models`. Если стороннему клиенту обязательно нужно автоматически получать список моделей, укажите идентификатор модели вручную или убедитесь, что клиент позволяет пропустить обнаружение моделей.
{% endhint %}

## Первый запрос

В следующем примере вызывается API, совместимый с OpenAI. Замените `YOUR_API_KEY`, `provider-id` и `model-id` своими значениями:

```bash
curl http://127.0.0.1:23333/v1/chat/completions \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "provider-id:model-id",
    "messages": [
      {
        "role": "user",
        "content": "Представь Cherry Studio одним предложением"
      }
    ]
  }'
```

Для потокового вывода добавьте в тело запроса:

```json
{
  "stream": true
}
```

Потоковый ответ передаётся через Server-Sent Events и завершается строкой `data: [DONE]`.

## Идентификатор модели

API определяет модель по следующему формату:

```
идентификатор поставщика:идентификатор модели
```

Например, если идентификатор поставщика — `my-openai`, а идентификатор модели — `gpt-4o-mini`, укажите:

```
my-openai:gpt-4o-mini
```

Требуется внутренний идентификатор поставщика Cherry Studio. Он не обязательно совпадает с именем, показанным на странице настроек. Модель должна быть добавлена к этому поставщику и быть доступна. Если двоеточие отсутствует, поставщик выключен или модель не существует, API вернёт ошибку запроса.

Сервер API разрешает доступные модели среди включённых поставщиков типов OpenAI, Anthropic, Ollama и New API. Конкретные возможности моделей по-прежнему определяются вышестоящим поставщиком.

У разных совместимых API разные ограничения:

* `/v1/chat/completions` в настоящее время принимает только поставщиков типа OpenAI.
* `/v1/messages` и `/{provider_id}/v1/messages` предназначены для запросов в формате Anthropic Messages.
* Наличие поставщика в настройках Cherry Studio не означает, что к нему можно обратиться через любой API.

Если возвращается ошибка о неподдерживаемом поставщике, сначала проверьте соответствие типа поставщика выбранному API, а не только имя модели.

## Использование в стороннем клиенте

В клиенте, который позволяет задать собственный OpenAI Base URL, обычно указывают:

| Параметр | Значение |
|---|---|
| Base URL | `http://127.0.0.1:23333/v1` |
| API Key | Ключ API Cherry Studio со страницы настроек |
| Model | `идентификатор поставщика:идентификатор модели` |

Некоторые клиенты автоматически добавляют `/v1`. Перед заполнением ознакомьтесь с описанием Base URL в клиенте. Если итоговый адрес содержит `/v1/v1/chat/completions`, удалите один из фрагментов `/v1`.

Некоторые клиенты принимают только общедоступные адреса HTTPS, обязательно вызывают `/v1/models` или запрещают двоеточие в идентификаторе модели. Такие клиенты не смогут напрямую работать с текущим локальным API.

## Границы безопасности

При стандартной конфигурации сервер прослушивает `127.0.0.1`, поэтому напрямую обратиться к нему могут только программы на этом компьютере. На странице настроек можно изменить только порт; переключателя для публикации в локальной сети нет.

При обновлении со старой версии мог сохраниться прежний адрес прослушивания. Проверьте фактический URL, показанный в состоянии работающего сервера на странице настроек. Если там указан `0.0.0.0` или адрес локальной сети, немедленно убедитесь, что именно такая конфигурация вам нужна.

Если вы перенаправляете API на другое устройство через обратный прокси, проброс портов, туннель SSH или другим способом, дополнительные меры контроля доступа необходимо организовать самостоятельно:

* обязательно используйте HTTPS;
* добавьте на уровне прокси ограничения по источнику и частоте запросов;
* не передавайте ключ API в параметрах URL;
* регулярно заменяйте ключ и отключайте перенаправление, когда оно не используется;
* помните, что `/health` и документация API не требуют аутентификации.

Не публикуйте адрес прослушивания напрямую в интернете. API разрешает межсайтовые запросы, поэтому политика одного источника браузера сама по себе не обеспечивает защиту.

## Устранение неполадок

### Сервер не запускается или порт занят

Если ошибка содержит `EADDRINUSE`:

1. Остановите другие экземпляры Cherry Studio или локальные службы, которые могут использовать тот же порт.
2. Выберите на странице настроек другой свободный порт.
3. В macOS или Linux выполните `lsof -i :23333`, а в Windows — `netstat -ano | findstr :23333`, чтобы определить процесс, занимающий порт.

### Возвращается 401 или 403

* `401` обычно означает, что заголовок аутентификации отсутствует, формат Bearer неверен или ключ пуст.
* `403` обычно означает, что ключ не совпадает с текущим значением на странице настроек.
* Если ключ только что создан заново, обновите переменную окружения или конфигурацию вызывающей программы и повторите запрос.

Сначала проверьте доступность сервера запросом без аутентификации:

```bash
curl http://127.0.0.1:23333/health
```

### Ошибка формата модели или поставщика

Убедитесь, что модель указана в формате `идентификатор поставщика:идентификатор модели`, и проверьте:

* поставщик включён;
* тип поставщика поддерживается сервером API;
* модель присутствует в списке моделей этого поставщика;
* в запросе используется внутренний идентификатор поставщика, а не только отображаемое имя.

Также проверьте соответствие API типу поставщика: OpenAI Chat Completions в настоящее время требует поставщика типа OpenAI, а для Anthropic Messages нужно использовать API Messages.

### API базы знаний возвращает 503

API базы знаний должен прочитать текущее состояние баз знаний из главного окна Cherry Studio. Если главное окно ещё не готово, закрывается или его внутреннее состояние недоступно, API вернёт `503`. Оставьте главное окно открытым, дождитесь полной загрузки приложения и повторите запрос.

### Сторонний клиент не подключается

* Убедитесь, что Cherry Studio и сервер API продолжают работать.
* Проверьте, не запущен ли клиент на другом устройстве, в контейнере или виртуальной машине. В таком окружении `127.0.0.1` не обязательно указывает на компьютер с Cherry Studio.
* Проверьте, не продублирован и не пропущен ли `/v1` в Base URL.
* Отдельно проверьте `/health` и целевой API с помощью `curl`, чтобы различить проблемы сети, аутентификации и тела запроса.

Для дальнейшей диагностики откройте каталог журналов через `Настройки → Настройки данных`. Перед публикацией журнала обязательно найдите и замаскируйте ключ API, Token, личные пути и рабочие данные.
