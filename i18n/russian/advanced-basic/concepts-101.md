# Основные понятия: ассистенты, агенты, навыки, MCP и каналы

В Cherry Studio V2 «общение с моделью» и «выполнение задач моделью» относятся к разным уровням возможностей. Разобравшись в приведённых ниже понятиях, вы сможете быстрее определить, с чего начать настройку.

## Кратко о главном

| Понятие | Основная задача | Типичные сценарии |
| :--- | :--- | :--- |
| Сервис моделей | Предоставляет модели и доступ к API | Подключение моделей DeepSeek, Claude, GPT и других |
| Ассистент | Сохраняет набор повторно используемых настроек диалога | Перевод, написание текстов, ответы на вопросы, поиск по базе знаний |
| Агент | Вызывает инструменты в рамках заданных разрешений и выполняет многоэтапные задачи | Работа с файлами, запуск команд, выполнение рабочих процессов |
| Навык | Предоставляет агенту инструкции, процесс и ресурсы для определённой задачи | Создание презентаций, проверка кода, подготовка документов по стандартам команды |
| MCP | Подключает внешние инструменты и данные по единому протоколу | Поиск в интернете, чтение баз данных, вызов сторонних сервисов |
| Канал | Подключает агента к платформе мгновенного обмена сообщениями | Использование агента через Feishu, Telegram, Slack и другие платформы |
| Запланированная задача | Запускает агента однократно, с заданным интервалом или по расписанию Cron | Ежедневные сводки, периодические проверки, регулярное составление отчётов |

Чаще всего выбор можно сделать так:

* Если нужны только постоянная роль, параметры модели или ответы с использованием базы знаний — выберите **ассистента**.
* Если AI должен читать каталоги, изменять файлы, запускать команды или последовательно вызывать инструменты — выберите **агента**.
* Если агенту не хватает определённого способа выполнения работы — установите и включите **навык**.
* Если ассистенту или агенту нужны инструменты за пределами Cherry Studio — настройте **MCP**.
* Если участники команды должны использовать агента через мессенджер — настройте **канал**.
* Если агент должен работать по расписанию без участия пользователя — создайте **запланированную задачу**.

## Сервисы моделей как источник возможностей

В сервисе моделей хранятся адрес API, ключ и список моделей. Модель выбирается и для ассистента, и для агента, но требования к ней различаются:

* Ассистент предназначен для повседневного общения. В зависимости от сценария можно выбрать модель, поддерживающую текст, зрение, рассуждения или вызов инструментов.
* В списке моделей агента отображаются только модели, которые поддерживают конечную точку Anthropic Messages и подходят для выполнения задач в диалоге. Модели Embedding, Rerank и генерации изображений в этот список не входят.

Сначала завершите настройку в разделе **Настройки → Сервисы моделей**, а затем создайте ассистента или агента. Пошаговые инструкции см. в разделе [Сервисы моделей](../pre-basic/providers/).

## Ассистент: повторно используемая конфигурация диалога

Ассистент сохраняет набор правил диалога для длительного повторного использования. Помимо имени и промпта, для него можно настроить модель, параметры сэмплирования, размер контекста, базу знаний и режим MCP.

Например, можно создать:

* ассистента-переводчика с заданной терминологией и форматом результата;
* ассистента службы поддержки, подключённого к базе знаний с документацией продукта;
* ассистента для исследований, который может вызывать поисковый MCP.

Ассистенты подходят для задач, основанных на диалоге. Ассистент может выполнять поиск по базе знаний или вызывать настроенные инструменты MCP, но, в отличие от агента, он не получает локальный рабочий каталог, разрешения на редактирование файлов и выполнение команд.

Ассистенты создаются и управляются в [Библиотеке ресурсов](../cherrystudio/preview/library.md), а используются на главной странице диалога. Далее ознакомьтесь с разделами [Библиотека ассистентов](../cherrystudio/preview/agents.md) и [Диалог](../cherrystudio/preview/chat.md).

## Агент: исполняемая конфигурация задачи

Помимо промпта и модели, для агента можно настроить:

* доступные локальные каталоги;
* режим разрешений инструментов;
* встроенные инструменты, MCP Server и навыки;
* основную модель, модель планирования и малую модель;
* максимальное число циклов, переменные окружения, пульс и другие параметры выполнения.

Благодаря этим настройкам агент может последовательно выполнять несколько действий для достижения цели, а не только давать рекомендации. Например, он может читать файлы в рабочей области, редактировать документы, обращаться к сервисам MCP и сохранять результаты локально.

{% hint style="warning" %}
Область разрешений агента определяет, какие каталоги он может читать и изменять, а также может ли он выполнять инструменты без подтверждения. В начале работы ограничьте доступные каталоги и отдавайте предпочтение режиму с подтверждением. Используйте режим без подтверждения, только если полностью понимаете связанные с ним риски.
{% endhint %}

Страница агента использует локальный **API Server** Cherry Studio. При создании нового агента V2 автоматически пытается запустить этот сервис, поэтому обычно предварительно настраивать его вручную на странице настроек не требуется. Если сервис отключён или не запущен, на странице агента появится предложение запустить его. API Server также позволяет другим приложениям обращаться к Cherry Studio через локальный HTTP-интерфейс. Подробнее см. в разделах [Агент](agent.md) и [API Server](api-server.md).

## Навык: объясняет агенту, «как выполнять определённую работу»

Навык — это устанавливаемый набор инструкций к задаче и сопутствующих ресурсов. Он похож на рабочее руководство: описывает условия применения, порядок действий, требования к качеству, а также сценарии или шаблоны, которые могут понадобиться.

Навыки связываются с агентом по Agent ID. После создания нового агента сначала сохраните его, а затем включите нужные навыки в разделе **Расширение возможностей → Навыки** этого агента.

Навык подходит, если:

* задачи одного типа должны каждый раз выполняться по установленному процессу;
* нужно повторно использовать стандарты, шаблоны или контрольные списки команды;
* вы хотите передать проверенный способ работы нескольким агентам.

Инструкции по установке, поиску и управлению см. в разделе [Навыки](../pre-basic/settings/skills.md).

## MCP: подключение AI к внешним возможностям

MCP (Model Context Protocol) — это протокол подключения AI-приложений к внешним инструментам, промптам и ресурсам. Cherry Studio позволяет добавлять локальные STDIO Server, а также подключаться к SSE или Streamable HTTP Server.

MCP Server может предоставить модели возможности трёх типов:

| Возможность | Назначение |
| :--- | :--- |
| Tools | Выполнение поиска, запросов, записи, вызова API и других операций |
| Prompts | Предоставление повторно используемых шаблонов промптов |
| Resources | Предоставление доступных для чтения данных или контекста |

Для ассистента доступны три режима MCP: отключённый, автоматический и ручной. Для агента можно выбрать сервисы из числа включённых MCP Server.

{% hint style="warning" %}
MCP Server может запускать программу на локальном компьютере или отправлять содержимое удалённому сервису. Перед добавлением проверьте источник, команду, переменные окружения, доступные каталоги и удалённый адрес. Предоставляйте только разрешения, необходимые для выполнения задачи.
{% endhint %}

Настройка описана в [Руководстве по использованию MCP](mcp/).

## Различия между навыком и MCP

Эти возможности часто используются вместе, но решают разные задачи:

| Критерий | Навык | MCP |
| :--- | :--- | :--- |
| Главный вопрос | Объясняет агенту, «как действовать» | Предоставляет модели то, «что можно вызвать» |
| Основное содержимое | Инструкции, процессы, шаблоны, сценарии и ресурсы | Интерфейсы инструментов, промптов и ресурсов |
| Основное место использования | Агент | Ассистент и агент |
| Зависимость от внешнего сервиса | Необязательно | Зависит от конкретного Server |

Например, навык может описывать, как составить еженедельный отчёт по шаблону команды, а MCP — получать задачи за неделю из системы управления проектами. Вместе они позволяют агенту следовать правильному процессу подготовки текста и получать необходимые данные.

## Канал: подключение агента к мессенджеру

Канал связывает агента с платформой мгновенного обмена сообщениями. В Cherry Studio V2 сейчас можно настроить каналы Feishu / Lark, Telegram, QQ, WeChat, Discord и Slack.

Канал получает сообщения платформы, передаёт их связанному агенту для обработки и отправляет результат обратно. Он не заменяет самого агента: модель, промпт, инструменты, каталоги и разрешения по-прежнему настраиваются в агенте.

Каналы обычно работают без участия пользователя. Перед включением проверьте:

* правильно ли выбраны связанный агент и модель;
* ограничены ли беседы или ID каналов, которым разрешено получать ответы;
* есть ли у агента разрешения инструментов, необходимые для задачи;
* сохраняются ли токены и ключи платформы только в соответствующей конфигурации.

Подробнее см. в разделе [Каналы](agent-channels.md).

## Запланированные задачи: запуск агента по расписанию

Исполнителем запланированной задачи также является агент. Можно создать:

* однократную задачу;
* задачу, повторяющуюся с заданным интервалом;
* задачу, запускаемую по выражению Cron.

Запланированные задачи подходят для работы, не требующей ввода со стороны пользователя. Перед созданием убедитесь, что агент успешно выполняет ту же задачу в обычном сеансе, а затем задайте подходящие разрешения, тайм-аут и расписание. Подробнее см. в разделе [Запланированные задачи](scheduled-tasks.md).

## Пример сочетания возможностей

Рассмотрим задачу «ежедневно собирать сведения о ходе командного проекта и отправлять их в группу Feishu»:

1. Настройте в **Сервисах моделей** модель, доступную агенту.
2. Создайте **агента** и укажите правила составления сводки и формат результата.
3. Установите и включите **навык** командного еженедельного отчёта, чтобы закрепить процесс подготовки текста.
4. Подключите через **MCP** систему управления проектами и считывайте данные о задачах.
5. Создайте **запланированную задачу**, которая будет ежедневно запускать агента по расписанию.
6. Создайте **канал** Feishu, чтобы участники команды могли задавать дополнительные вопросы в групповом чате.

Не для каждого сценария нужны все эти возможности. Начните с ассистента или агента и добавляйте навыки, MCP, каналы или запланированные задачи только при появлении конкретной потребности — так конфигурацию будет проще поддерживать.

## Рекомендуемый порядок изучения

1. Настройте [Сервисы моделей](../pre-basic/providers/) и проведите один обычный диалог.
2. Создайте ассистента через [Библиотеку ресурсов](../cherrystudio/preview/library.md) и познакомьтесь с промптами, моделями и базами знаний.
3. Создайте [агента](agent.md), начав с ограниченного каталога и разрешений, требующих подтверждения.
4. Добавьте [навык](../pre-basic/settings/skills.md) или [MCP](mcp/) в зависимости от задачи.
5. После того как агент начнёт работать стабильно, настройте [запланированные задачи](scheduled-tasks.md) и [каналы](agent-channels.md).
