# Agent для обзора рынка золота на Kimi K2.5

В этом примере показано, как с помощью агента Cherry Studio выполнить обзор колебаний цены на золото: найти открытые материалы, сопоставить время цен и событий, сохранить источники и создать отчёт, удобный для ручной проверки.

Kimi K2.5 используется здесь как пример модели. Его можно заменить другой моделью, если она работает в агенте Cherry Studio через эндпоинт **Anthropic Messages**. Модели, цены и совместимость инструментов у разных провайдеров могут отличаться, поэтому сначала выполните небольшую проверочную задачу.

{% hint style="warning" %}
Этот пример демонстрирует исследовательский процесс и не является инвестиционной рекомендацией. Модель может пропустить материал, неверно прочитать данные или создать ошибочный код. Не совершайте сделки непосредственно на основании созданного результата.
{% endhint %}

## Какой результат требуется

Рекомендуется ограничить результат четырьмя файлами:

```text
gold-review/
├── sources.md       # Источники, время публикации, время получения и назначение
├── market-data.csv  # Ценовые данные, фактически использованные в этом запуске
├── analysis.md      # Хронология событий, расчёты и неопределённые пункты
└── report.html      # Итоговый отчёт для чтения
```

Эти файлы отвечают соответственно на вопросы «откуда взяты материалы», «какие данные использованы», «как получен вывод» и «как показан результат». Не просите создать только красивый HTML: без первых трёх файлов итоговую страницу трудно проверить.

## Проектирование процесса

Разделите задачу на три этапа:

| Этап | Основная работа | Обязательные доказательства |
| :--- | :--- | :--- |
| Сбор данных | Получить цены и макроэкономические материалы за заданный период | URL источника, время публикации, время получения, исходные значения |
| Сопоставление событий | Сравнить значительные колебания с событиями того же временного окна | Часовой пояс, время события, диапазон цен, подтверждающие и опровергающие сведения |
| Создание отчёта | Составить графики, хронологию, выводы и ограничения | Методика расчёта, ссылки, отсутствующие данные, предупреждение о рисках |

С помощью инструмента `Task` агент может передать независимые исследования подзадачам, но сама по себе «параллельность» не гарантирует качество. Главная задача всё равно должна унифицировать время, единицы и правила выбора источников.

## Шаг 1. Подготовьте модель

1. Откройте **Настройки → Сервисы моделей**.
2. Настройте провайдера Kimi K2.5 или выберите другую модель, подходящую для вызова инструментов.
3. Убедитесь, что тип эндпоинта модели включает **Anthropic Messages**.
4. После сохранения завершите один обычный разговор, затем убедитесь, что модель видна в селекторе агента.

Селектор агента исключает модели типов Embedding, Rerank и генерации изображений. Если модель отвечает в обычном чате, но не показывается в агенте, сначала проверьте тип эндпоинта и метки возможностей.

Настройка описана в разделе [Сервисы моделей](../../pre-basic/providers/). Чтобы добавить модель вручную или исправить метки возможностей, используйте способ управления моделями из раздела [Пользовательский провайдер](../../pre-basic/providers/zi-ding-yi-fu-wu-shang.md).

## Шаг 2. Подготовьте рабочую директорию

Создайте пустую директорию, например `gold-review`, и поместите в неё только материалы текущей задачи. Не выбирайте всю домашнюю директорию, папку загрузок или проект с учётными данными.

Если ценовые данные уже есть, заранее сохраните их в `market-data.csv`. Рекомендуется включить как минимум:

```csv
timestamp,open,high,low,close,unit,timezone,source
2026-01-01T00:00:00Z,,,,,USD/oz,UTC,
```

Набор полей можно изменить, но единицы и часовой пояс должны быть указаны явно. Не объединяйте напрямую данные разных рынков и источников без приведения к единой системе.

## Шаг 3. Создайте агента

1. Откройте **Библиотека** и создайте агента.
2. Укажите имя `Обзор рынка золота`.
3. Выберите основной моделью вариант, проверенный на предыдущем шаге.
4. Добавьте созданную директорию `gold-review` в список доступных путей.
5. Сначала выберите для прав **обычный режим**.
6. Сохраните агента.

Обычный режим разрешает чтение, но запрашивает подтверждение при изменении файлов или запуске команд. Для первого запуска не рекомендуется «полностью автоматический» режим: получение финансовых данных и запись локальных файлов требуют наблюдения человека.

Настройки описаны в разделе [Агенты](../agent.md).

## Шаг 4. Добавьте инструменты

Убедитесь, что в разделе агента **Расширение возможностей → Встроенные инструменты** доступны:

| Инструмент | Назначение в примере | Обязателен |
| :--- | :--- | :--- |
| `Read`, `Glob`, `Grep` | Чтение материалов и поиск файлов | Да |
| `WebSearch` | Поиск открытых материалов | Да |
| `WebFetch` | Чтение заданной веб-страницы | Да |
| `Write` | Создание CSV, Markdown и HTML | Да |
| `Task`, `TodoWrite` | Разделение задачи и запись прогресса | Рекомендуется |
| `Bash` | Обработка данных и локальные команды проверки | Необязательно |

`WebSearch`, `WebFetch`, `Write` и `Bash` обращаются к сети или изменяют локальные данные. После добавления инструментов обычный режим всё равно запрашивает подтверждение при необходимости. Разрешайте только вызов, нужный для текущего шага.

Если страница требует входа, содержит CAPTCHA или запрещает автоматическое получение, скачайте материал вручную и положите в рабочую директорию. Не просите агента обходить ограничения доступа.

## Шаг 5. При необходимости установите навыки

Пример можно выполнить только с системным промптом. Для регулярного повторения оформите стабильный процесс как навыки, например:

* `market-data-verifier`: определяет поля данных, единицы, часовой пояс и способ проверки по нескольким источникам.
* `event-timeline`: задаёт способ отметки хронологии событий и силы причинной связи.
* `research-report`: задаёт структуру отчёта, формат ссылок и описание ошибок.

Устанавливаемый навык должен быть директорией или ZIP-архивом с файлом `SKILL.md`. Порядок действий:

1. Откройте **Настройки → Навыки**.
2. Установите навык из директории или ZIP.
3. Вернитесь в **Расширение возможностей → Навыки** сохранённого агента.
4. Включите нужный навык для этого агента.

Навык сначала сохраняется в глобальной библиотеке навыков Cherry Studio. После включения приложение связывает его с `.claude/skills/` в рабочей директории агента. Не копируйте вручную неизвестный комплект настроек `.claude` и не перезаписывайте созданные приложением ссылки навыков.

Подробности приведены в разделе [Навыки](../../pre-basic/settings/skills.md).

## Шаг 6. Укажите системный промпт

Поместите в системный промпт агента следующий шаблон и измените его при необходимости:

```text
Вы — помощник по исследованию рынка. Ваша задача — создать проверяемый обзор рынка золота,
а не прогнозировать доходность и не давать рекомендации по покупке или продаже.

Правила работы:
1. Сначала уточните инструмент, рынок, валюту, единицу, часовой пояс и диапазон дат.
2. Цены, ставки, индексы и события должны происходить из файлов или результатов инструментов
   текущего запуска; не дополняйте текущие значения из памяти модели.
3. Для важных фактов записывайте URL, название источника, время публикации и время доступа.
4. Проверяйте основные выводы минимум по двум независимым источникам; если источник один, отметьте это.
5. Строго разделяйте факты, результаты расчётов, объяснения и гипотезы. Соседство по времени
   не должно автоматически описываться как причинная связь.
6. При отсутствии данных, недоступной странице или ошибке расчёта сохраняйте пробел и объясняйте причину.
7. Перед записью перечисляйте план. Создавайте и изменяйте файлы только в текущей рабочей директории.
8. В конце создайте sources.md, market-data.csv, analysis.md и report.html.
9. report.html должен открываться локально и не содержать учётные данные или персональные сведения.
10. В конце отчёта добавьте: «Только для исследования и обучения, не является инвестиционной рекомендацией».
```

Системный промпт задаёт долгосрочные правила. Конкретные даты исследования и события указывайте в каждой задаче, не фиксируйте их в системном промпте.

## Шаг 7. Сначала запросите план материалов

В первом задании не просите сразу полный отчёт. Сначала запросите план:

```text
Составьте план материалов для обзора колебаний спотовой цены на золото.
Пока не создавайте отчёт.

Область:
- Инструмент: уточнить у меня перед началом
- Единица цены: доллары США за тройскую унцию
- Часовой пояс: UTC
- Диапазон дат: начать поиск после моего подтверждения

Выведите:
1. необходимые поля данных;
2. планируемые типы источников;
3. вызываемые инструменты и причины;
4. создаваемые файлы;
5. права и потенциальные расходы, которые нужно подтвердить.
```

Убедившись, что план не расширяет директорию и объём данных, разрешите начать сбор.

## Шаг 8. Выполните обзор

После подтверждения области отправьте:

```text
Выполните обзор в согласованной области.

Требования:
- сначала соберите и сохраните источники, затем анализируйте;
- отметьте временное окно с наибольшим изменением цены;
- преобразуйте время всех событий в UTC;
- для каждой причины укажите доказательства, возражения и уровень уверенности;
- для каждого расчёта укажите входные поля и формулу;
- непроверяемое поместите в «Требует проверки», не дополняйте;
- после готовности промежуточных Markdown-файлов создайте report.html;
- в конце перечислите созданные и изменённые файлы и нерешённые вопросы.
```

Во время работы особенно внимательно проверяйте три вида запросов инструментов:

1. **Сетевой запрос**: соответствует ли домен запланированному источнику.
2. **Запись файла**: находится ли путь внутри `gold-review`.
3. **Запуск команды**: обрабатывает ли команда только текущие данные, устанавливает ли пакеты или обращается к дополнительной сети.

Если требуется временно установить библиотеку обработки данных, остановитесь и самостоятельно проверьте название пакета, источник и команду. Не считайте установку зависимостей автоматически необходимым разрешением для продолжения задачи.

## Шаг 9. Примите промежуточные результаты

### Проверка `sources.md`

Каждый источник должен содержать как минимум:

* название и URL;
* время публикации веб-страницы или данных;
* время доступа в этом запуске;
* поддерживаемый факт или набор данных;
* сведения о необходимости входа, подписки или о вторичной публикации.

Недоступная ссылка не может быть единственным доказательством. Для перепечатки по возможности найдите первоначального издателя.

### Проверка `market-data.csv`

Убедитесь, что:

* формат времени и часовой пояс единообразны;
* единицы цены единообразны;
* отсутствующие значения не заполнены без объяснения;
* диапазон данных соответствует задаче;
* `source` соответствует записи в `sources.md`.

Выберите несколько случайных моментов времени и вручную сравните их с исходным источником.

### Проверка `analysis.md`

Фраза «после события цена упала» описывает только временную связь и не доказывает причинность. Для каждого объяснения рекомендуется структура:

```text
Наблюдение:
Временное окно:
Подтверждающие сведения:
Возражение или альтернативное объяснение:
Уверенность: высокая / средняя / низкая
Требует проверки:
```

Для технического индикатора также должны быть сохранены формула, параметры и входной диапазон. Одной итоговой цифры без расчёта недостаточно для приёмки.

### Проверка `report.html`

Откройте файл локально и проверьте:

* страница не зависит от недоступного локального абсолютного пути;
* числа в таблицах и графиках совпадают с CSV;
* каждый важный вывод ведёт к источнику;
* отсутствующие данные и ограничения не скрыты итоговым оформлением;
* страница не содержит API Key, Cookie, имя пользователя или личную директорию.

## Частые вопросы

### Kimi K2.5 не показывается в списке моделей агента

Убедитесь, что тип эндпоинта включает **Anthropic Messages**, а модель не помечена ошибочно как Embedding, Rerank или генерация изображений. Разные провайдеры модели с одинаковым названием могут предоставлять разные возможности эндпоинта.

### Агент не выполняет веб-поиск

Проверьте, добавлены ли `WebSearch` и `WebFetch` к текущему агенту и не был ли отклонён запрос инструмента. Заявленная провайдером «поддержка интернета» не означает, что Cherry Studio автоматически добавит веб-инструменты.

### Установленный навык не действует

Сначала сохраните агента и убедитесь, что у него есть рабочая директория, затем включите навык в списке навыков этого агента. Простое помещение файлов в рабочую директорию не означает установку и привязку.

### Не удаётся создать файл отчёта

Проверьте доступность `Write`, подтверждение текущего запроса прав и нахождение целевого пути в разрешённой директории. Не расширяйте права на весь диск ради решения проблемы пути.

### Данные выглядят полными, но не соответствуют источникам

Остановите создание итогового отчёта и попросите агента для каждого значения показать строку источника. Значение без источника следует удалить или пометить как требующее проверки, а не продолжать оформлять.

## Как расширить процесс

После приёмки базового процесса постепенно добавляйте:

* подключение проверенного сервиса данных через MCP;
* регулярное создание обзора по расписанию с сохранением ручной проверки;
* отправку через канал уведомления «отчёт создан» вместо торгового вывода;
* оформление стабильных правил проверки как командного навыка.

Добавляйте только одну возможность за раз и заново проверяйте права, расходы и результат. Дополнительная настройка описана в разделах [MCP](../mcp/), [Задачи по расписанию](../scheduled-tasks.md) и [Каналы](../agent-channels.md).

Вернитесь к [примерам Agent](./), чтобы посмотреть другие рабочие процессы.
