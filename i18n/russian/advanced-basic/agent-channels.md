# Каналы

Каналы позволяют подключить [агента](agent.md) Cherry Studio к платформам мгновенного обмена сообщениями. Когда участник отправляет сообщение в групповом или личном чате, связанный агент обрабатывает запрос в Cherry Studio и отвечает в исходной беседе.

В настоящее время поддерживаются:

* Feishu / Lark
* Telegram
* QQ
* WeChat
* Discord
* Slack

Например, помощник по базе знаний может отвечать на внутренние вопросы в группе Feishu, персональный ассистент — получать команды через Telegram, а [запланированная задача](scheduled-tasks.md) — отправлять ежедневный отчёт в указанный канал.

{% hint style="info" %}
Каналы работают локально в Cherry Studio. После закрытия приложения подключения и обработка сообщений прекращаются. При повторном открытии приложения включённые каналы со связанным агентом подключаются автоматически. Каналы не зависят от API Server.
{% endhint %}

## Подготовка

Перед добавлением канала:

1. Создайте и настройте [агента](agent.md), который может нормально отвечать в диалоге.
2. Выберите для агента доступную модель и убедитесь, что поставщик настроен правильно.
3. Подготовьте учётные данные бота, необходимые целевой платформе, либо используйте подключение по QR-коду для Feishu или WeChat.

К каналу можно привязать как обычного агента, так и агента с включённым автономным режимом. Для создания канала вручную автономный режим не требуется. Если агент должен самостоятельно создавать каналы, искать причины проблем с подключением или связывать каналы с задачами, рекомендуется включить автономный режим и внимательно проверить разрешения его инструментов.

## Добавление канала

Откройте `Настройки → Каналы`, выберите нужную платформу и нажмите **Добавить**.

Общие параметры:

| Параметр | Описание |
|---|---|
| Название | Помогает различать несколько экземпляров каналов одной платформы |
| Связать агента | Агент, обрабатывающий сообщения канала; без связанного агента канал не подключается |
| Учётные данные платформы | App ID, Token или Secret, необходимые конкретной платформе |
| Разрешённые ID чатов | Ограничивают беседы, из которых можно обращаться к боту |
| Режим прав доступа канала | Наследует настройки агента либо задаёт отдельный режим разрешений только для этого канала |
| Состояние включения | После включения сразу предпринимается попытка подключения; при выключении настройки сохраняются, а соединение разрывается |

Для одной платформы можно добавить несколько экземпляров, а одного агента можно связать с несколькими каналами. Например, один агент может одновременно работать в группе Feishu и личном чате Telegram, при этом каждый экземпляр канала может использовать собственные учётные данные, список разрешённых чатов и режим прав доступа.

После сохранения состояние подключения отображается на странице сведений о канале. При изменении состояния включения, учётных данных или связанного агента Cherry Studio повторно подключает этот экземпляр.

## Настройка для разных платформ

{% tabs %}
{% tab title="Feishu / Lark" %}
Feishu и Lark поддерживают два способа подключения:

* **Подключение по QR-коду**: не вводите App ID и App Secret, включите канал и отсканируйте QR-код на странице. После регистрации Cherry Studio сохранит полученные учётные данные и подключится повторно.
* **Ручное подключение**: введите App ID и App Secret собственного приложения и выберите домен `Feishu` или `Lark`. Encrypt Key и Verification Token заполняются при необходимости в соответствии с настройками приложения.

При ручном создании приложения включите возможности бота, разрешения на сообщения и подписку на события постоянного соединения на соответствующей открытой платформе. Приложения и домены Feishu и Lark нельзя смешивать.
{% endtab %}

{% tab title="Telegram" %}
Используйте Bot Token Telegram. Бота можно создать через BotFather, который предоставит Token.

В список разрешений вносятся Telegram Chat ID. После подключения бота отправьте `/whoami` в нужном личном или групповом чате, чтобы получить текущий Chat ID.
{% endtab %}

{% tab title="QQ" %}
Введите App ID и Client Secret приложения QQ Bot.

В списке разрешений поддерживаются ID бесед с указанием типа:

* `c2c:openid` — личный чат
* `group:groupid` — групповой чат
* `channel:channelid` — канал
* `dm:guildid` — личное сообщение в канале

Отправьте `/whoami`, чтобы посмотреть тип и ID текущей беседы.
{% endtab %}

{% tab title="WeChat" %}
Для входа в WeChat используется QR-код, поэтому вручную вводить Token не нужно. Добавьте и включите экземпляр, затем отсканируйте QR-код в WeChat. Учётные данные для входа сохраняются в локальном каталоге данных Cherry Studio.

В список разрешений вносятся ID пользователей WeChat. Отправьте `/whoami` в беседе, чтобы получить текущий ID.
{% endtab %}

{% tab title="Discord" %}
Введите Discord Bot Token и пригласите бота на нужный сервер.

В список разрешений вносятся Discord Channel ID. Можно также отправить `/whoami` в нужном канале или личном сообщении и скопировать ID беседы, возвращённый Cherry Studio.
{% endtab %}

{% tab title="Slack" %}
Slack использует Socket Mode, поэтому необходимо указать:

* Bot Token, обычно начинающийся с `xoxb-`
* App-Level Token, обычно начинающийся с `xapp-`

Установите приложение, предоставьте ему разрешения на сообщения и добавьте бота в нужный канал. В список разрешений вносится Slack Channel ID; его также можно получить командой `/whoami`.
{% endtab %}
{% endtabs %}

{% hint style="warning" %}
Учётные данные бота равнозначны данным доступа к аккаунту. Не отправляйте Token или Secret в общедоступные чаты и не включайте их в снимки экрана или документы. Если вы подозреваете утечку, немедленно отзовите эти данные на соответствующей платформе и создайте новые.
{% endhint %}

## Ограничение доступных бесед

**Разрешённые ID чатов** управляют доступом к каналу:

* **Пустое поле**: агент может быть вызван из любой беседы, которая может отправить сообщение боту.
* **Указанные ID**: агента могут вызывать только беседы из списка, остальные сообщения игнорируются.

Если список разрешений пуст, Cherry Studio автоматически записывает ID бесед, которые успешно взаимодействовали с ботом. Эти записи также можно использовать как адресатов для активной отправки из [запланированных задач](scheduled-tasks.md).

Рекомендуется сначала отправить `/whoami` в нужной беседе, скопировать возвращённый ID и добавить его в список разрешений. Не оставляйте список пустым надолго в групповых чатах и средах с несколькими участниками.

## Настройка прав доступа канала

Права доступа канала определяют, как запросы из этого канала могут вызывать инструменты агента. По умолчанию выбран режим **Унаследовать от агента**. Только для текущего канала его можно переопределить одним из следующих режимов:

* **Режим по умолчанию**: перед чувствительными операциями запрашивается подтверждение по стандартным правилам.
* **Автоматически принимать изменения**: изменения файлов подтверждаются автоматически, но остальные операции высокого риска остаются ограниченными.
* **Обход проверки разрешений**: подтверждение больше не запрашивается; это самый рискованный режим.
* **Режим планирования**: приоритет отдаётся анализу и подготовке плана, изменения непосредственно не выполняются.

Права доступа применяются при получении каждого сообщения, поэтому новые настройки действуют и в уже существующих беседах.

{% hint style="danger" %}
Сообщения в мессенджерах являются внешними входными данными. Используйте **Обход проверки разрешений** только при строгих ограничениях рабочей области, инструментов и списка разрешений агента. Не предоставляйте боту в общедоступной группе доступ к конфиденциальным каталогам или учётным данным.
{% endhint %}

## Команды в канале

После подключения боту можно отправлять:

| Команда | Действие |
|---|---|
| `/new` | Переключает текущий канал на новый сеанс |
| `/compact` | Сжимает контекст текущего сеанса |
| `/help` | Показывает сведения об агенте и доступные команды |
| `/whoami` | Показывает ID текущей беседы для настройки списка разрешений |

Если один канал должен обслуживать разные команды или задачи с разными уровнями доступа, рекомендуется создать отдельные экземпляры каналов и настроить для каждого своего агента, список разрешений и права, а не использовать одну конфигурацию с высокими разрешениями.

## Использование с запланированными задачами

Канал может не только принимать сообщения, но и быть адресатом [запланированной задачи](scheduled-tasks.md):

1. Создайте и подключите канал.
2. Хотя бы один раз взаимодействуйте с ботом в нужной беседе либо напрямую укажите разрешённый ID чата.
3. Создайте запланированную задачу и выберите канал для отправки.

Если список разрешений пуст и нужная беседа ни разу не взаимодействовала с ботом, у Cherry Studio может не быть доступного адресата для активной отправки.

## Устранение проблем с подключением

### После сохранения по-прежнему отображается состояние «Отключено»

Проверьте по порядку:

1. Включён ли канал и связан ли с ним агент.
2. Работают ли модель и поставщик агента.
3. Соответствуют ли друг другу Token, Secret, App ID и домен платформы.
4. Установлен ли бот в нужной рабочей области, на сервере или в групповом чате и предоставлено ли ему разрешение на сообщения.
5. Откройте **Журналы** в сведениях о канале и проверьте ошибки подключения в реальном времени.

После исправления неверных настроек и сохранения Cherry Studio повторно подключит канал. Можно также выключить и снова включить этот экземпляр.

### Бот в сети, но не отвечает

* Проверьте, входит ли ID текущей беседы в список разрешений.
* Убедитесь, что бот может читать сообщения в групповом чате. На некоторых платформах требуется упомянуть бота или отдельно предоставить разрешение на групповые сообщения.
* Убедитесь, что Cherry Studio всё ещё запущен.
* Проверьте, доступна ли модель агента и не блокируют ли права канала необходимые инструменты.

### После сканирования QR-кода подключение не завершилось

* Убедитесь, что срок действия QR-кода не истёк. Если код устарел, запустите подключение по QR-коду ещё раз.
* Для Feishu / Lark используйте аккаунт клиента, соответствующий выбранному домену.
* Если вход в WeChat перестал действовать, повторное сканирование QR-кода обновит локальные учётные данные.

{% hint style="warning" %}
У каждой платформы свои условия использования и требования организации к ботам, хранению сообщений и автоматизации. Перед добавлением бота в корпоративную группу или внешний сервис убедитесь, что получены необходимые разрешения.
{% endhint %}
