# Цепочка вызовов (Trace)

Цепочка вызовов (Trace) позволяет увидеть, какие этапы проходит диалог внутри Cherry Studio. На основе Trace и Span из OpenTelemetry запросы к моделям, вызовы инструментов, поиск по базам знаний и другие операции представляются в виде дерева. Для каждого узла показываются длительность, состояние, входные и выходные данные, а также использование Token.

Если ответ не соответствует ожиданиям, инструмент не сработал или отклик стал медленнее, Trace поможет определить уровень, на котором возникла проблема:

* получила ли модель правильный контекст;
* что вернул веб-поиск или поиск по базе знаний;
* какие параметры были переданы инструменту MCP;
* какой этап занял больше всего времени или завершился ошибкой;
* сколько Token использовано в каждом ответе разных моделей.

{% hint style="warning" %}
Trace — это диагностическая функция для разработчиков. В ней могут сохраняться подсказки, ответы модели, параметры инструментов и найденные материалы. Не оставляйте её надолго включённой в рабочих диалогах с конфиденциальными данными и не публикуйте полный Trace без предварительной проверки.
{% endhint %}

## Включение Trace

1. Откройте `Настройки → Общие настройки`.
2. Найдите **Режим разработчика**.
3. Включите **Включить режим разработчика**.
4. Полностью закройте и снова запустите Cherry Studio.
5. Создайте новый диалог и отправьте сообщение.

{% hint style="info" %}
Приложение обязательно нужно перезапустить. Окно Trace и служба кеша активируются при запуске Cherry Studio в соответствии с текущим состоянием режима разработчика. Если только переключить настройку без перезапуска, кнопка может не появиться, а данные могут не читаться.
{% endhint %}

Для сообщений, созданных до включения функции, цепочки задним числом не создаются. Кнопка появится только у сообщений, выполненных после перезапуска и успешно получивших Trace ID.

## Открытие цепочки вызовов

На странице обычного диалога найдите нужное сообщение, наведите указатель на панель действий сообщения и нажмите значок **Цепочка вызовов**.

Сейчас эта кнопка доступна только для сообщений обычного диалога. На панели действий сообщений Agent Session она не отображается.

Кнопка появляется только при одновременном выполнении всех условий:

* режим разработчика включён;
* текущее сообщение содержит Trace ID;
* служба Trace была активирована при текущем запуске приложения.

Cherry Studio откроет отдельное окно цепочки вызовов. Если нажать кнопку для другого сообщения, существующее окно переключится на соответствующий Trace.

Если один вопрос создал ответы от нескольких моделей, открывайте цепочку отдельно на сообщении с ответом каждой модели. Данные Trace в окне будут отфильтрованы по модели этого сообщения.

## Чтение дерева Trace

Один полный запрос соответствует одному Trace, а каждый этап обработки — одному Span. Дочерний узел означает, что этап выполнялся в контексте родительского.

После выбора узла в области сведений могут отображаться:

| Информация | Назначение |
|---|---|
| Время начала и окончания | Определение порядка этапов |
| Duration | Поиск наиболее долгих операций |
| Выделение ошибки | Если имя узла стало красным, проверьте ошибочный вывод этого этапа |
| Input / Attributes | Проверка входных данных, параметров и контекста |
| Outputs | Просмотр возвращённых данных; здесь же показываются сведения об ошибке |
| Token Usage | Сравнение Prompt Token и Completion Token |

Набор узлов различается от запроса к запросу. Фактическая структура зависит от модели, использования интернета, подключения базы знаний и вызовов инструментов MCP.

### Вызов модели

В узле модели можно проверить:

* фактически вызванную модель;
* входные данные, отправленные модели;
* текст или потоковый результат, возвращённый моделью;
* Prompt Token и Completion Token;
* длительность запроса и состояние ошибки.

Если в ответе явно не хватает информации, сначала убедитесь, что соответствующий контекст присутствовал во входных данных модели.

### Веб-поиск

При использовании веб-поиска Trace может содержать узлы поискового запроса, обработки результатов и вызова модели. В первую очередь проверьте:

* правильность поискового запроса;
* были ли успешно получены результаты;
* были ли результаты отобраны перед передачей модели;
* не стал ли поиск основным источником задержки.

### Поиск по базе знаний

После подключения [базы знаний](../knowledge-base/knowledge-base.md) с помощью цепочки вызовов можно проверить, были ли найдены ожидаемые материалы. Обратите внимание на поисковый запрос, возвращённые фрагменты, сведения о сходстве и контекст, в итоге переданный модели.

Если в узле базы знаний нет результатов, дополнительно проверьте модель встраивания, состояние обработки документов, порог поиска и формулировку вопроса пользователя.

### Вызов инструмента MCP

При использовании [MCP](mcp/README.md) Trace помогает проверить имя инструмента, параметры вызова, возвращённое значение, длительность и ошибки.

Если инструмент не выполнился, различайте следующие ситуации:

* модель выбрала неправильный инструмент;
* параметры инструмента неполны или имеют неверный формат;
* MCP Server не запущен или подключение не удалось;
* инструмент выполнился, но модель неправильно использовала возвращённые данные.

{% hint style="info" %}
Trace показывает диагностические данные, но не повторяет и не исправляет неудачные этапы автоматически. После определения причины вернитесь к настройкам диалога, модели, базы знаний или MCP и внесите изменения.
{% endhint %}

## Хранение и удаление данных

Данные Trace хранятся в домашнем каталоге текущего пользователя:

```
~/.cherrystudio/trace
```

Внутри данные организованы по идентификаторам темы и Trace. В Windows `~` означает каталог текущего пользователя, например `C:\Users\<имя пользователя>`.

При удалении сообщения или темы Cherry Studio удаляет соответствующую часть данных Trace. Чтобы удалить все локальные данные Trace:

1. Откройте `Настройки → Настройки данных`.
2. Найдите сведения о кеше.
3. Нажмите **Очистить кеш** и подтвердите действие.

Очистка кеша одновременно удалит и другие кешированные данные приложения. Перед выполнением убедитесь, что нужные диагностические данные сохранены.

{% hint style="danger" %}
Не редактируйте файлы Trace вручную во время работы Cherry Studio. Если данные нужно передать, предпочтительно сделайте снимок только необходимых узлов и заранее скройте ключи API, личные данные, пути к файлам и рабочую информацию.
{% endhint %}

## Часто задаваемые вопросы

### Режим разработчика включён, но кнопки Trace нет

Проверьте по порядку:

1. Был ли Cherry Studio полностью перезапущен после включения режима.
2. Было ли текущее сообщение создано после перезапуска.
3. Просматриваете ли вы сообщение обычного диалога. У старых сообщений без Trace ID кнопка не отображается.
4. Создайте новую тему и отправьте простое сообщение для проверки.

### Окно Trace пустое

* Дождитесь завершения текущего ответа модели и вызовов инструментов, затем откройте окно снова.
* Убедитесь, что соответствующее сообщение не удалено, а кеш Trace не очищен.
* Если режим разработчика только что включён, перезапустите приложение, создайте новый диалог и повторите попытку.
* Для ответов нескольких моделей открывайте Trace отдельно на сообщении с ответом соответствующей модели.

### Нет узлов базы знаний, поиска или MCP

Соответствующий Span появляется, только если эта возможность действительно была выполнена в текущем запросе. Сначала проверьте по результату диалога и журналу вызовов инструментов модели, был ли этап фактически запущен.

### Слишком много данных Trace

После завершения диагностики отключите режим разработчика и перезапустите Cherry Studio. Если нужно немедленно освободить место, очистите кеш в настройках данных.

***

### 💡 Получение помощи и отправка отзывов

Если данные Trace выглядят неверно, к сообщению об ошибке рекомендуется приложить необходимые снимки Trace, версию Cherry Studio, использованную модель и указать, были ли включены база знаний, веб-поиск или MCP. Официальные каналы перечислены на странице [Отзывы и предложения](../question-contact/suggestions.md).
