# Руководство по использованию MCP

MCP (Model Context Protocol) — это стандартный протокол, позволяющий моделям использовать внешние инструменты и данные. После подключения к MCP Server помощник или Agent в Cherry Studio сможет в ходе ответа читать веб-страницы, выполнять запросы к базам данных, работать с файлами, вызывать бизнес-API, а также использовать предоставленные сервером промпты и ресурсы.

## Как работает MCP

В типичном вызове участвуют следующие стороны:

| Участник | Назначение |
| --- | --- |
| Модель | Определяет, нужен ли инструмент, и формирует его параметры |
| Cherry Studio | Подключается к MCP Server, проверяет разрешения и показывает процесс вызова |
| MCP Server | Предоставляет инструменты, промпты или ресурсы и выполняет фактические операции |

Общий порядок работы выглядит так:

1. Вы ставите задачу помощнику или Agent.
2. Модель выбирает инструмент из числа разрешённых.
3. Cherry Studio определяет по разрешениям сервера и инструмента, требуется ли ваше подтверждение.
4. MCP Server выполняет операцию и возвращает результат.
5. Модель продолжает ответ с учётом полученного результата.

Модель не «входит» напрямую в компьютер или учётную запись — она работает через интерфейсы, предоставленные MCP Server. Однако сам MCP Server может быть как локальной исполняемой программой, так и удалённым сервисом, поэтому его источник и разрешения всё равно необходимо проверять.

## Распространённые сценарии

- Чтение и поиск локальных файлов.
- Получение веб-страниц, управление браузером или вызов сетевых интерфейсов.
- Поиск в базах знаний, базах данных и документах команды.
- Выполнение Python или другого кода.
- Подключение к заметкам, сообщениям, системам управления проектами и другим онлайн-сервисам.
- Выполнение операций записи, удаления или бизнес-операций после явного разрешения.

Фактические возможности зависят от инструментов, предоставленных сервером. Даже MCP Server одного типа могут различаться по разрешениям, месту передачи данных и качеству.

## Что может предоставлять MCP Server

MCP — это не только «инструменты»:

- **Tools** — операции, которые может вызывать модель, например поиск, чтение и запись.
- **Prompts** — предоставляемые сервером шаблоны промптов для повторного использования.
- **Resources** — предоставляемые сервером файлы, документы и другие контекстные ресурсы.

После включения сервера на странице сведений можно посмотреть, какие возможности он фактически предоставляет. Если возможности определённого типа отсутствуют, соответствующая вкладка может быть пустой или не отображаться.

## Различия между MCP и Skills

| Критерий | Skills | MCP |
| --- | --- | --- |
| Основная задача | Объяснить Agent, как выполнить определённую задачу | Дать модели доступ к внешним инструментам или данным |
| Основное содержимое | Инструкции, процессы и необязательные ресурсы | Инструменты, промпты, ресурсы и протокол подключения |
| Выполняет ли внешние операции | Зависит от инструментов, вызываемых Skill | Обычно подключается к локальной программе или удалённому сервису |
| Где используется в V2 | Преимущественно в Agent | Доступен в обычных помощниках и Agent |

Skill может указывать Agent, когда и в какой последовательности использовать MCP, а MCP отвечает за фактический вызов инструментов. Их можно использовать совместно. Подробнее см. в разделе [Skills](../../pre-basic/settings/skills.md).

## Использование MCP в Cherry Studio

Полный процесс выглядит так:

1. Установите или добавьте сервер в разделе **Настройки → Серверы MCP**.
2. Укажите команду, URL, параметры, Header или переменные окружения.
3. Включите сервер и проверьте инструменты и журналы.
4. Добавьте этот сервер в обычного помощника или Agent.
5. Начните задачу с моделью, поддерживающей вызов инструментов.

{% hint style="info" %}
Дополнительная среда выполнения может потребоваться только для STDIO-серверов, запускаемых локальными командами `uv`, `uvx`, `npx`, `bun` и подобными. Для удалённых серверов и большинства встроенных серверов предварительно устанавливать UV или Bun не нужно.
{% endhint %}

Подробные инструкции см. в разделе [Настройка и использование MCP](config.md).

## Где искать серверы

В настройках MCP Cherry Studio доступны несколько вариантов:

- **Встроенные серверы** — распространённые серверы, уже адаптированные для Cherry Studio.
- **Маркетплейс MCP** — просмотр серверов в подключённых маркетплейсах.
- **Поставщики услуг** — подключение к поддерживаемым поставщикам MCP-сервисов.
- **Импорт из JSON или DXT** — использование конфигурации или пакета расширения, предоставленного разработчиком.
- **Создать вручную** — заполнение конфигурации STDIO, SSE или Streamable HTTP по официальной документации.

Для первого знакомства рекомендуется начать со [встроенных MCP-серверов](in-memory.md). Для них путь настройки понятнее, а разрешения проще проверить.

## Границы безопасности

{% hint style="danger" %}
Описание инструментов MCP не является безопасной песочницей. STDIO Server — это программа, работающая с правами текущего пользователя. Вредоносный или скомпрометированный сервер может получить доступ к данным, доступным его процессу. Удалённый Server также получает содержимое, которое вы отправляете инструменту.
{% endhint %}

Перед установкой или включением сервера:

- Проверьте разработчика, программный пакет, адрес загрузки и историю обновлений.
- Разрешайте доступ только к каталогам, учётным записям и API Scope, необходимым для задачи.
- Не добавляйте настоящие секретные ключи в промпты или общий JSON.
- Отключите ненужные инструменты на странице **Инструменты**.
- Сохраняйте ручное подтверждение для записи файлов, удаления данных, отправки сообщений, создания заказов и подобных операций.
- Отключите или удалите сервер, когда он больше не нужен.

Автоматическое подтверждение лишь уменьшает число запросов подтверждения и не ограничивает разрешения самого инструмента. Не включайте его сразу для всех инструментов незнакомого сервера.
