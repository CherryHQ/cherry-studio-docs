# Настройка и использование MCP

Использование MCP в Cherry Studio состоит из двух частей:

1. Добавьте MCP Server в разделе **Настройки → MCP Server** и настройте подключение и разрешения.
2. Добавьте включённый Server к тому ассистенту или Agent, который будет его использовать.

Если назначение MCP вам ещё неизвестно, сначала прочитайте [Руководство по MCP](README.md). Если в системе нет NPX, Bun или UV, сначала выполните [Установку среды MCP](install.md).

## Выбор способа добавления

Откройте **Настройки → MCP Server** и нажмите **Добавить**. Доступны следующие варианты:

| Способ | Когда использовать |
| --- | --- |
| Создать | Ввести конфигурацию STDIO, SSE или Streamable HTTP вручную |
| Импортировать из JSON | Разработчик предоставил JSON `mcpServers` |
| Импортировать из DXT | Получен пакет расширения `.dxt` |
| Встроенные Server | Использовать распространённые инструменты, адаптированные Cherry Studio |

Для распространённых задач сначала проверьте [встроенные MCP Server](in-memory.md). Встроенные варианты не требуют ручного поиска команд и позволяют проще управлять разрешениями.

## Типы подключения

### STDIO

STDIO Server запускается Cherry Studio на этом компьютере. Обычно требуется заполнить:

| Поле | Описание |
| --- | --- |
| Имя | Произвольное имя для идентификации Server |
| Тип | `STDIO` |
| Команда | Исполняемая программа, например `npx`, `uvx` или `node` |
| Аргументы | По одному аргументу на строку в порядке из документации разработчика |
| Переменные окружения | По одному `KEY=value` на строку |

Если команда содержит NPX, Bun, UV или UVX, на странице появятся необязательные настройки зеркала пакетов. Изменять их не требуется, если источник по умолчанию доступен.

Ниже приведена минимальная конфигурация на примере официального Time Server:

| Поле | Значение |
| --- | --- |
| Имя | `time` |
| Тип | `STDIO` |
| Команда | `uvx` |
| Аргументы | В первой строке `mcp-server-time`, во второй — `--local-timezone=Asia/Shanghai` |

Параметр часового пояса можно опустить и передавать часовой пояс явно при вызове инструмента моделью.

### SSE

Используется для подключения к удалённому MCP Server через Server-Sent Events. Выберите `SSE` и введите Server URL, например:

```text
https://example.com/sse
```

Если службе требуется аутентификация, укажите в **Headers** по одному `KEY=value` на строку:

```text
Authorization=Bearer your-token
```

### Streamable HTTP

Используется для подключения к более новым MCP Server с протоколом Streamable HTTP. Настройка аналогична SSE, но URL обычно заканчивается на `/mcp`:

```text
https://example.com/mcp
```

Тип протокола должен совпадать с серверным. Возможность открыть URL в браузере не означает, что он одновременно поддерживает SSE и Streamable HTTP.

{% hint style="warning" %}
Header удалённого Server может содержать Token учётной записи. Указывайте ключ только в настройках Server и не добавляйте его в подсказки, снимки экрана или общую конфигурацию.
{% endhint %}

## Импорт из JSON

Cherry Studio импортирует только один Server за раз. Типичный формат:

```json
{
  "mcpServers": {
    "example-server": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"],
      "env": {
        "EXAMPLE_API_KEY": "在导入后替换"
      }
    }
  }
}
```

Для удалённого Server можно использовать `type`, `url` и `headers`:

```json
{
  "mcpServers": {
    "remote-example": {
      "type": "streamableHttp",
      "url": "https://example.com/mcp",
      "headers": {
        "Authorization": "Bearer your-token"
      }
    }
  }
}
```

После импорта Server по умолчанию выключен. Сначала откройте страницу сведений, проверьте команду, аргументы, URL, Header и переменные окружения, а затем попробуйте подключиться.

## Импорт из DXT

DXT — это пакет расширения с манифестом и ресурсами Server. После выбора файла `.dxt` Cherry Studio прочитает конфигурацию запуска и создаст Server.

DXT по-прежнему является исполняемым расширением. Устанавливайте файлы только из доверенных источников и после импорта проверяйте поставщика, команду, аргументы и требуемые разрешения.

## Проверка сведений о Server

Нажмите установленный Server, чтобы открыть страницу сведений. После сохранения конфигурации и включения доступны:

- **Настройки** — тип подключения, команда, аргументы, переменные окружения, Header, тайм-аут и расширенные сведения;
- **Инструменты** — предоставляемые Server инструменты, структура аргументов, состояние и автоматическое утверждение;
- **Подсказки** — MCP Prompts, предоставляемые Server;
- **Ресурсы** — MCP Resources, предоставляемые Server;
- **Журнал** — процесс подключения и вывод ошибок STDIO.

Не каждый Server предоставляет подсказки или ресурсы. Эти вкладки появляются только после включения Server.

### Тайм-аут и долгие задачи

Обычный вызов инструмента по умолчанию завершается по тайм-ауту через 60 секунд. Включайте **Long Running** или увеличивайте тайм-аут только тогда, когда Server действительно должен работать долго. Настройка тайм-аута не исправит неверную команду, недействительный ключ или недоступный URL.

### Разрешения инструментов

На странице **Инструменты** можно отдельно выключить любой инструмент и настроить его автоматическое утверждение. Рекомендуется:

- включать инструменты запросов и чтения только при необходимости;
- сохранять ручное подтверждение для записи файлов, удаления данных, отправки сообщений, создания заказов и подобных действий;
- выключать неиспользуемые инструменты, уменьшая вероятность ошибочного вызова моделью.

## Использование в обычном ассистенте

На странице **MCP** в настройках ассистента или на панели быстрого доступа MCP в поле ввода можно выбрать один из трёх режимов:

| Режим | Поведение |
| --- | --- |
| Выключено | Текущий ассистент не использует MCP |
| Автоматически | Встроенный Hub обнаруживает и вызывает инструменты всех включённых MCP Server |
| Вручную | Используются только включённые Server, выбранные для текущего ассистента |

Для работы с чувствительными разрешениями рекомендуется режим **Вручную**. Автоматический режим удобен при большом количестве инструментов, когда модель должна сама обнаруживать возможности, но операции высокого риска всё равно следует ограничивать на странице **Инструменты** каждого Server.

Выбрав режим, используйте модель с поддержкой вызова инструментов и сформулируйте точную задачу. Например:

```text
Используй инструмент time, чтобы узнать текущее время в Токио, и укажи разницу со временем в Шанхае.
```

Решение о вызове инструмента зависит от возможностей модели, вопроса и подсказки. Если обращение к инструменту обязательно, явно укажите назначение Server или инструмента.

## Использование в Agent

1. Откройте страницу редактирования или настроек нужного Agent.
2. Перейдите в **Инструменты → MCP**.
3. Добавьте необходимые Server.
4. Сохраните Agent.

Можно выбрать только включённые MCP Server. Если Server выключен, его инструменты не предоставляются, даже когда он остаётся в конфигурации Agent.

## Проверка подключения

Рекомендуется проверять в следующем порядке:

1. В списке Server отображается состояние «включён».
2. На странице **Инструменты** в сведениях о Server показаны инструменты.
3. Server добавлен к нужному ассистенту или Agent.
4. Выбранная модель поддерживает вызов инструментов.
5. Отправлен тестовый вопрос с чёткими границами и легко проверяемым результатом.
6. В ответе раскрыта запись вызова инструмента и проверена правильность аргументов и результата.

Если Server не запускается, после подключения нет инструментов или вызов завершается по тайм-ауту, см. [Часто задаваемые вопросы о MCP Server](chang-jian-wen-ti.md).
