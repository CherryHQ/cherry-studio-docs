# Часто задаваемые вопросы о MCP

Эта страница поможет устранить проблемы, из-за которых MCP Server не запускается, после подключения не показывает инструменты, вызовы завершаются по тайм-ауту или возникают ошибки аргументов. При первой настройке MCP рекомендуется сначала прочитать [Настройка и использование MCP](config.md). Если в системе нет необходимой среды выполнения, сначала выполните инструкции из раздела [Установка среды MCP](install.md).

## Сначала определите тип подключения

Откройте `Настройки → MCP Server`, перейдите к проблемному Server и убедитесь, что его тип соответствует обязательным параметрам:

| Тип | Обязательные параметры | Частые проблемы |
|---|---|---|
| `stdio` | Command, Arguments и при необходимости переменные окружения | Команда не существует, аргументы разделены неверно, зависимости не установлены |
| `SSE` | Server URL и при необходимости Headers | Неверный путь URL, служба не запущена, ошибка аутентификации |
| `Streamable HTTP` | Server URL и при необходимости Headers | Адрес SSE ошибочно указан как `/mcp` или наоборот |
| Встроенный | Настройка в соответствии с инструкциями на странице | Отсутствуют разрешения, каталог или ключ поиска |

Для `stdio` Cherry Studio запускает локальный дочерний процесс. SSE и Streamable HTTP подключаются к уже работающей удалённой или локальной службе. Способы диагностики различаются, поэтому не стоит многократно повторять попытку, меняя только URL или Command.

## Просмотр журнала в реальном времени

На странице сведений о Server нажмите **Просмотреть журнал** рядом с заголовком. В журнале отображаются:

* `stdout` / `stderr` — вывод локальной команды;
* `info` / `warn` / `error` — состояние подключения, инициализации и вызовов;
* последние параметры запуска, ошибки подключения и данные, возвращённые инструментами.

Рекомендуется сначала выключить Server, затем открыть журнал и снова включить Server — так проще найти первую ошибку. Журнал хранит только последние записи текущего сеанса страницы. После воспроизведения проблемы своевременно скопируйте нужную часть.

{% hint style="warning" %}
Журнал может содержать аргументы команд, пути к файлам, адреса запросов и данные, возвращённые инструментами. Перед отправкой отзыва скройте Token, API Key, Cookie, личные каталоги и рабочие данные.
{% endhint %}

## Server не включается

### Команда `npx`, `uvx` или другая команда не существует

Cherry Studio читает переменные окружения Shell входа, чтобы найти команду. Для `npx` приложение также пытается использовать встроенный Bun, а для `uv` / `uvx` — установленную встроенную версию.

Если по-прежнему появляется `not found`:

1. Откройте `Настройки → MCP Server → Установка среды`.
2. Установите требуемую для Server среду Node.js или `uv`.
3. Полностью закройте и снова запустите Cherry Studio, чтобы применился новый PATH.
4. Вернитесь на страницу сведений о Server и снова включите его.

Команды также можно проверить в терминале:

```bash
node --version
npx --version
uvx --version
```

Проверяйте только команду, которую фактически использует этот Server. Устанавливать все среды не требуется.

### Неверно заполнены Command и Arguments

В Cherry Studio:

* в поле **Command** указывается только исполняемая команда, например `npx`, `uvx` или абсолютный путь к исполняемому файлу;
* в поле **Arguments** каждый самостоятельный аргумент указывается на отдельной строке;
* не копируйте полную команду в поле Command;
* путь к файлу с пробелами указывайте как один полный аргумент. Не добавляйте кавычки Shell самостоятельно, если документация Server явно этого не требует.

Например, следующий JSON:

```json
{
  "command": "npx",
  "args": ["-y", "@example/mcp-server", "--mode", "read-only"]
}
```

в форме следует ввести так:

```text
Command
npx

Arguments
-y
@example/mcp-server
--mode
read-only
```

### Не удаётся импортировать JSON

При добавлении из JSON верхний уровень должен содержать `mcpServers`, а за один раз следует импортировать только один Server:

```json
{
  "mcpServers": {
    "example": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"]
    }
  }
}
```

Частые причины:

* используются типографские кавычки или лишняя запятая;
* `args` не является массивом строк;
* один JSON содержит несколько Server;
* `url`, `command` и тип смешаны в несовместимой конфигурации;
* скопированный текст содержит ограждение блока кода Markdown.

## Не удаётся подключиться к удалённому Server

### URL или протокол не соответствует

Проверьте в официальной документации Server, какой протокол предоставляется: SSE или Streamable HTTP.

* типичный адрес SSE: `http://localhost:3000/sse`;
* типичный адрес Streamable HTTP: `http://localhost:3000/mcp`.

Путь определяется самим Server, поэтому `/sse` и `/mcp` — лишь распространённые варианты. Сначала убедитесь через терминал или браузер, что служба действительно прослушивает этот адрес, а затем выберите соответствующий тип.

Если Server работает в Docker, виртуальной машине или на другом устройстве, `127.0.0.1` указывает на систему, в которой запущен Cherry Studio, а не обязательно на хост Server.

### Возвращается 401 или 403

В поле **Headers** укажите данные аутентификации в формате `Имя=Значение`, по одной записи на строку. Например:

```text
Authorization=Bearer YOUR_TOKEN
```

Не добавляйте настоящий Token в конфигурацию, которая может быть опубликована. После изменения Headers сохраните настройки. Включённый Server попытается подключиться заново с новой конфигурацией, а при неудаче автоматически вернётся в выключенное состояние.

## Server подключён, но инструменты не отображаются

Последовательно проверьте:

1. Server включён в разделе `Настройки → MCP Server`.
2. На вкладке **Инструменты** в сведениях о Server перечислены инструменты.
3. Нужный инструмент не выключен отдельно в списке.
4. Этот MCP Server включён для текущего ассистента или Agent.
5. Начат новый диалог, чтобы обновлённая конфигурация инструментов вошла в контекст.

Состояние «Server подключён» означает только успешную инициализацию протокола. Оно не предоставляет инструменты автоматически каждому ассистенту.

Если список инструментов пуст, хотя документация Server утверждает, что они существуют, проверьте журнал на наличие `listTools`, ошибок версии протокола или инициализации.

## Вызов инструмента завершается по тайм-ауту

По умолчанию тайм-аут вызова инструмента в Cherry Studio составляет 60 секунд. Значение **Timeout** в сведениях о Server можно увеличить в секундах. Если включена поддержка долгих задач, ожидание может продлеваться, пока Server отправляет события выполнения, однако общее время всё равно ограничено.

Для инициализации подключения используется более длительное ожидание. Первая загрузка зависимостей или запуск удалённого Server могут занять несколько минут. Различайте:

* **тайм-аут при включении** — обычно связан с установкой, сетью, URL или инициализацией;
* **тайм-аут выполнения инструмента** — обычно означает, что задача Server выполняется слишком долго или Server не отправляет сведения о прогрессе.

Не увеличивайте Timeout без ограничений. Сначала убедитесь по журналу, что запрос действительно выполняется, и проверьте поддержку MCP Progress со стороны Server.

## Переменные окружения не применяются

Переменные окружения Server указываются в формате `KEY=VALUE`, по одной на строку. Cherry Studio объединяет их с окружением Shell входа и передаёт дочернему процессу `stdio`.

Проверьте:

* полностью ли имя ключа совпадает с документацией Server;
* нет ли в значении случайных кавычек или пробелов в начале и конце;
* были ли изменения сохранены и выполнено повторное подключение;
* не истёк ли срок действия Token;
* читает ли Server данные из переменной окружения или требует Header либо файл конфигурации.

Для удалённых SSE / Streamable HTTP Server данные аутентификации обычно указываются в Headers, а не в переменных окружения локального процесса.

## Неверный часовой пояс в `mcp-server-time`

Официальный Time Server — это Server на Python, который обычно запускается через `uvx`. Чтобы указать местный часовой пояс, добавьте его отдельным аргументом:

```json
{
  "mcpServers": {
    "time": {
      "command": "uvx",
      "args": [
        "mcp-server-time",
        "--local-timezone=Asia/Shanghai"
      ]
    }
  }
}
```

Используйте название часового пояса IANA, например `Asia/Shanghai`, `Europe/Berlin` или `America/New_York`, а не сокращение смещения вроде `UTC+8`.

Если появляется `uvx not found`, сначала установите среду Python для MCP и перезапустите Cherry Studio. Способ установки и аргументы Time Server могут меняться между версиями; актуальные сведения приведены в [официальном репозитории MCP Servers](https://github.com/modelcontextprotocol/servers/tree/main/src/time).

## Минимальное воспроизведение проблемы

Если решить проблему не удалось:

1. Создайте новую конфигурацию Server только с обязательными полями.
2. Временно удалите прокси, пользовательские зеркала и необязательные переменные окружения.
3. В пустом ассистенте включите только этот MCP Server.
4. Вызовите один самый простой инструмент без побочных эффектов.
5. Сохраните сообщение об ошибке и записи соответствующего периода из раздела **Просмотреть журнал**.

При отправке отзыва приложите версию Cherry Studio, операционную систему, тип Server, конфигурацию и журнал с удалёнными конфиденциальными данными. Не прикладывайте настоящие учётные данные. Официальные каналы перечислены на странице [Отзывы и предложения](../../question-contact/suggestions.md).
