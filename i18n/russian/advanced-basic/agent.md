# Агент

Агент может в рамках заданных разрешений читать содержимое рабочей области, вызывать инструменты и последовательно выполнять многоэтапные задачи. Он подходит для работы, требующей реальных действий: упорядочивания группы файлов, изменения кода проекта, вызова сервисов MCP или подготовки отчётов по расписанию.

Если вам нужны только постоянная роль, ответы с использованием базы знаний или повседневное общение, проще начать с ассистента. Различия описаны в разделе [Основные понятия](concepts-101.md).

## Перед началом

### Настройка доступной модели

Модель агента должна поддерживать конечную точку Anthropic Messages. Из списка автоматически исключаются модели Embedding, Rerank и генерации изображений: в нём остаются только модели, подходящие для выполнения задач агентом в диалоге.

Если список пуст, сначала выполните следующие действия в разделе **Настройки → Сервисы моделей**:

1. Настройте адрес API и API Key.
2. Получите список моделей или добавьте модель вручную.
3. Убедитесь, что модель поддерживает конечную точку Anthropic Messages.

Общие инструкции по настройке см. в разделе [Сервисы моделей](../pre-basic/providers/).

### Проверка доступности локального API Server

Страница агента использует локальный API Server Cherry Studio. При создании нового агента V2 автоматически пытается запустить сервис, поэтому обычно предварительно открывать страницу настроек не требуется.

Если на странице агента указано, что сервис отключён или не запущен, нажмите расположенную там кнопку запуска. Если сервис всё равно не запускается, откройте **Настройки → API Server** и проверьте порт и состояние. Подробнее см. в разделе [API Server](api-server.md).

## Создание агента

Откройте раздел **Агент** через стартовую панель или боковую панель, затем нажмите **+ Агент** над списком агентов слева.

Можно также открыть [Библиотеку ресурсов](../cherrystudio/preview/library.md), переключиться на вкладку **Агент** и нажать кнопку создания. Из библиотеки сразу откроется полная страница настроек.

### Что необходимо заполнить

| Поле | Обязательно | Описание |
| :--- | :--- | :--- |
| Название | Да | Название агента, отображаемое в списке и сеансах |
| Модель | Да | Основная исполняющая модель; отображаются только модели с поддержкой Anthropic Messages |
| Доступные каталоги | Нет | Ограничивают локальные каталоги, доступные агенту; если ничего не указано, создаётся рабочий каталог по умолчанию |
| Описание | Нет | Объясняет назначение и помогает найти агента в библиотеке ресурсов |

{% hint style="warning" %}
Доступные каталоги также являются границей безопасности. Не предоставляйте доступ ко всему пользовательскому каталогу, системным каталогам или каталогам с секретами. По возможности создайте для задачи отдельную рабочую область и добавьте только действительно необходимые расположения.
{% endhint %}

После сохранения агент появится в списке слева и в библиотеке ресурсов. Навыки связываются с конкретным агентом, поэтому сначала сохраните его, а затем включайте навыки.

## Страница настроек

Чтобы продолжить редактирование, нажмите карточку агента в библиотеке ресурсов или откройте настройки в верхней части сеанса агента. Доступны следующие разделы:

| Раздел настроек | Доступные параметры |
| :--- | :--- |
| Основные настройки | Аватар, название, основная модель, модель планирования, малая модель, доступные каталоги, автономный режим, пульс и описание |
| Настройки промпта | Системные инструкции агента |
| Режим разрешений | Порядок подтверждения вызовов инструментов по умолчанию |
| Расширение возможностей | Встроенные инструменты, MCP Server и навыки |
| Расширенные настройки | Максимальное число циклов выполнения и переменные окружения |

### Основная модель, модель планирования и малая модель

* **Основная модель** обязательна и отвечает за большинство диалогов и вызовов инструментов.
* **Модель планирования** необязательна и может использоваться в процессах, требующих отдельного планирования.
* **Малая модель** необязательна и может использоваться для вспомогательных шагов, подходящих лёгкой модели.

Во всех трёх списках отображаются только совместимые с агентом модели. Если особых требований нет, достаточно настроить основную модель.

### Промпт

Промпт определяет роль, цель, рабочие правила и требования к результату. Вместо длинного описания контекста лучше чётко указать:

* за что отвечает и не отвечает агент;
* какие каталоги, источники данных и инструменты он может использовать;
* какие операции требуют подтверждения перед выполнением;
* где и в каком формате сохранять результаты.

Не полагайтесь только на промпт для обеспечения безопасности. Область каталогов, режим разрешений и переключатели инструментов необходимо настраивать отдельно.

## Выбор режима разрешений

Режим разрешений определяет, какие инструменты подтверждаются автоматически. При переключении режима Cherry Studio синхронно обновляет инструменты, которые этот режим добавляет автоматически.

| Режим | Поведение по умолчанию | Подходящие сценарии |
| :--- | :--- | :--- |
| Обычный режим | Свободно читает файлы; запрашивает подтверждение перед редактированием файлов или выполнением команд | Первое знакомство, интерактивные задачи |
| Режим планирования | Только читает файлы и составляет план; не может изменять файлы или выполнять команды | Проверка кода, проектирование, оценка рисков |
| Режим автоматического редактирования | Свободно читает и изменяет файлы; запрашивает подтверждение перед выполнением команд | Упорядочивание документов, контролируемое изменение кода |
| Полностью автоматический режим | Доступные инструменты выполняются без отдельного подтверждения | Работа без участия пользователя в строго ограниченной области |

Помимо инструментов, автоматически добавленных режимом, другие инструменты можно вручную добавить в разделе **Расширение возможностей → Встроенные инструменты**.

{% hint style="danger" %}
В полностью автоматическом режиме подтверждение инструментов пропускается. Агент может записывать файлы, запускать команды или обращаться к внешним сервисам. Используйте этот режим только в изолированной рабочей области и сначала полностью проверьте ту же задачу в обычном режиме.
{% endhint %}

## Автономный режим и пульс

### Автономный режим

После включения автономного режима агент формирует собственный системный промпт из Soul-файлов рабочей области, получает возможность автономно управлять задачами и отключает интерактивные инструменты, не подходящие для работы без участия пользователя.

При включении автономного режима режим разрешений также переключается на **Полностью автоматический режим**. При переходе с полностью автоматического режима на любой другой автономный режим отключается.

Автономный режим подходит для длительной работы, каналов и других сценариев без участия пользователя. Это не универсальный переключатель для повышения качества ответов. Если задача требует частых подтверждений пользователя, лучше использовать обычного агента.

### Пульс

Пульс позволяет агенту с поддержкой автономной работы периодически проверять состояние и продолжать выполнение задач через настроенный интервал. Его можно включить или отключить в основных настройках и задать интервал в минутах.

Включайте пульс, только когда у агента уже есть чёткая цель, ограниченный каталог и безопасный набор инструментов, чтобы избежать бессмысленных повторных запусков.

## Добавление инструментов, MCP и навыков

Откройте раздел **Расширение возможностей**, где можно переключаться между тремя вкладками:

### Встроенные инструменты

Встроенные инструменты предоставляют чтение и редактирование файлов, выполнение команд, управление задачами и другие возможности. Некоторые инструменты автоматически добавляются режимом разрешений; инструменты с отметкой режима нельзя удалять по отдельности.

Включайте только те инструменты, которые действительно нужны для задачи. Даже в обычном режиме слишком большой набор повышает вероятность того, что модель выберет неправильный инструмент.

### MCP

Здесь перечислены MCP Server, добавленные в Cherry Studio. Отключённый Server может отображаться среди уже связанных, но выбрать его в списке добавления нельзя. Сначала включите его в разделе **Настройки → Серверы MCP**.

MCP Server может обращаться к локальной программе или удалённому сервису. Перед связыванием проверьте команду, переменные окружения, каталоги и удалённый адрес. Полное описание см. в [Руководстве по использованию MCP](mcp/).

### Навыки

Навыки содержат инструкции к задаче, процессы, сценарии и шаблоны. Включать навыки можно только для сохранённого агента, уже получившего ID.

Если список пуст, сначала установите навыки через библиотеку ресурсов или раздел **Настройки → Навыки**. Подробнее см. в разделе [Навыки](../pre-basic/settings/skills.md).

## Настройка расширенных параметров

### Максимальное число циклов выполнения

Максимальное число циклов выполнения ограничивает продолжительность одной задачи. Если оставить поле пустым или указать `0`, будет использовано значение по умолчанию. Текущий предел по умолчанию — 100.

Число циклов — не «длина ответа». Каждое планирование, вызов инструмента и продолжение выполнения агентом может занимать цикл. Если задача зациклилась, сначала проверьте промпт и результаты инструментов, а не просто увеличивайте предел.

### Переменные окружения

Переменные окружения вводятся по одной в строке в формате `KEY=VALUE`, например:

```text
PROJECT_ENV=staging
OUTPUT_FORMAT=markdown
```

Переменные окружения передаются в конфигурацию выполнения агента. Не добавляйте пароли, API Key или токены доступа в документы, промпты или снимки экрана. Конфиденциальные значения следует хранить только в контролируемой конфигурации и предоставлять к ним минимально необходимые права.

## Начало сеанса

1. Откройте страницу **Агент**.
2. Выберите агента в списке слева.
3. Создайте новый сеанс и введите задачу с чёткими границами.
4. Просматривайте карточки вызовов инструментов; в обычном режиме, режиме планирования и режиме автоматического редактирования подтверждайте или отклоняйте операции согласно запросу.
5. Проверьте созданные или изменённые файлы, прежде чем переходить к следующему шагу.

Для первой проверки выберите небольшую задачу, результат которой легко проверить, например:

> Прочитай файл `README.md` в текущей рабочей области и перечисли три места, которые нужно обновить. Пока не изменяй файл.

Убедившись, что область чтения задана правильно, постепенно разрешайте редактирование, выполнение команд и внешние инструменты.

## Рабочая область и память

Первый доступный агенту каталог используется как основная рабочая область. Некоторые функции сохраняют в рабочей области постоянные файлы, например Soul-файлы автономного режима и память рабочей области агента.

Если два агента используют один и тот же первый доступный каталог, они могут читать и изменять один набор файлов рабочей области. Для разделения проектов или ролей используйте для каждого агента отдельный каталог.

Структура файлов и использование памяти описаны в разделе [Память рабочей области агента](memory.md).

## Частые вопросы

### На странице агента указано, что API Server не запущен

Сначала нажмите кнопку запуска на странице. Если запуск завершился ошибкой:

1. Откройте **Настройки → API Server**.
2. Проверьте, не занят ли порт другой программой.
3. Перезапустите сервис и вернитесь на страницу агента.

### При создании нет доступных моделей

Для агента отображаются только диалоговые модели с поддержкой конечной точки Anthropic Messages. Проверьте, добавлена ли модель в сервис моделей и правильно ли определены возможности конечной точки. Модели Embedding, Rerank и генерации изображений не отображаются.

### Не удаётся включить навык

Сначала сохраните агента. Состояние включения навыков сохраняется по ID агента, поэтому у нового несохранённого агента ещё нет ID для связывания.

### Не удаётся найти определённый MCP Server

Откройте **Настройки → Серверы MCP** и убедитесь, что Server добавлен и включён. В списке добавления агента можно выбрать только включённый Server.

### При каждом изменении файла или выполнении команды запрашивается подтверждение

Это нормальное поведение обычного режима. Выберите режим автоматического редактирования с учётом рисков или настройте отдельные инструменты в разделе расширения возможностей. Не переходите сразу в полностью автоматический режим только для того, чтобы уменьшить число запросов.

### Задача останавливается раньше времени или повторяется

Проверьте по порядку:

1. Стабильно ли модель поддерживает вызов инструментов.
2. Не содержат ли результаты инструментов ошибок и достаточно ли в них данных.
3. Задан ли в промпте чёткий критерий завершения.
4. Не слишком ли мало максимальное число циклов выполнения.
5. Не продолжают ли автономный режим или пульс задачу в неподходящем сценарии.

## Дальнейшие действия

* Закрепите рабочие процессы с помощью [навыков](../pre-basic/settings/skills.md).
* Подключите внешние инструменты и данные через [MCP](mcp/).
* Узнайте больше о [памяти рабочей области агента](memory.md).
* После того как агент начнёт работать стабильно, настройте [каналы](agent-channels.md) или [запланированные задачи](scheduled-tasks.md).
