# 模型服務設定

模型服務是 Cherry Studio 呼叫大型語言模型、視覺模型、嵌入模型和重新排序模型的連線入口。這裡負責設定服務商憑證、請求位址、通訊協定端點和模型清單；各服務商的註冊和 Key 取得方式請參閱[模型服務](../../../pre-basic/providers/)。

{% hint style="info" %}
不同平台可能將憑證稱為 API Key、密鑰、權杖或 Token。它們的具體格式和權限由服務商決定，不代表不同平台的 Key 可以互換。
{% endhint %}

## 開啟模型服務

進入：

> **設定 → 模型服務**

左側是服務商清單，右側是目前服務商的連線和模型設定。

服務商清單支援：

- 依服務商名稱、模型名稱或模型 ID 搜尋；
- 查看已啟用、已停用、全部或適合智慧代理的服務商；
- 拖曳調整顯示順序；
- 展開在相同預設下建立的多個執行個體；
- 透過右鍵選單複製、編輯或刪除可管理的服務商；
- 點選搜尋框旁的 **+** 新增自訂服務商。

如果所有服務商都處於停用狀態，清單會自動顯示全部服務商，方便完成首次設定。

## 設定內建服務商

### 1. 選擇並啟用服務商

在左側選擇服務商，開啟右上角的開關。

服務商開關只決定該服務商是否可在應用程式中使用，不代表 API Key、位址和模型已正確設定。

### 2. 填寫 API Key

將服務商控制台中建立的 API Key 貼到 **API 金鑰**。

輸入框右側通常提供：

- 顯示或隱藏 Key；
- 複製 Key；
- 開啟多 Key 管理；
- 開啟連線檢查。

少數服務商使用 OAuth、雲端帳號身分或裝置授權，不一定顯示一般 API Key 輸入框。應依對應服務商頁面的流程登入或填寫雲端帳號參數。

{% hint style="danger" %}
不要將真實 API Key 放入螢幕截圖、公開儲存庫、聊天記錄或意見回饋附件。螢幕截圖前應關閉 Key 顯示；如果懷疑洩漏，立即在服務商控制台撤銷舊 Key。
{% endhint %}

### 3. 檢查請求位址

內建服務商通常已提供預設 API 位址。未使用代理、相容閘道或私人部署時，建議保留預設值。

常見的 Base URL 範例：

```text
https://api.example.com/v1
```

不要因服務商文件顯示了完整請求範例，就直接將 `/chat/completions`、`/responses` 或 `/messages` 串接到 Base URL 後面。Cherry Studio 會依模型端點類型產生請求路徑。

如果位址已修改，介面可能提供**還原預設位址**。請求設定入口還可管理不同通訊協定的端點位址和自訂請求標頭。

### 4. 檢查連線

點選 API Key 輸入框右側的**連線檢查**。

目前 V2 會開啟檢查面板，讓您選擇：

- 一組已啟用的 API Key；
- 一個已新增且可用於檢查的模型。

檢查會實際向所選模型發出請求。連線成功至少表示這組 Key、位址、端點和模型可以完成基本呼叫，但不保證所有模型、圖片、工具呼叫或長上下文請求都可用。

## 管理多組 API Key

點選 Key 輸入框旁的**金鑰清單**按鈕，可以：

- 新增多組 Key；
- 為 Key 新增容易識別的標籤；
- 個別啟用或停用 Key；
- 編輯、複製或刪除 Key；
- 查看已啟用數量。

執行時會在已啟用的 Key 之間依序輪替。停用的 Key 不參與輪替；沒有任何已啟用 Key 時，一般 API Key 服務商將無法完成請求。

{% hint style="warning" %}
舊版常用英文逗號將多組 Key 寫在同一個輸入框中。V2 更適合透過金鑰清單逐項管理，這樣可以個別命名、停用和檢查，也能避免誤用中文逗號或將標籤當成 Key。
{% endhint %}

多 Key 輪替無法繞過服務商的帳號層級額度、組織層級限制或使用條款。同一帳號下的多組 Key 可能共用帳單與限額。

## API 位址與端點

### Base URL

大多數情況下應填寫服務根位址或版本根路徑，例如：

```text
https://api.example.com/v1
```

具體是否需要 `/v1`，請以服務商文件和 Cherry Studio 對應預設為準。位址必須使用有效的 `http://` 或 `https://` URL。

### 完整端點與 `#`

相容介面如果只提供完整端點，可以在位址結尾保留 `#`，讓 Cherry Studio 識別並停止繼續串接該端點。例如：

```text
https://api.example.com/custom/chat/completions#
```

只有在服務商明確提供非常規完整路徑時才使用此寫法。目前可識別的常見端點包括：

- `chat/completions`
- `responses`
- `messages`
- `generateContent`
- `streamGenerateContent`
- 圖像產生或編輯端點

一般 Base URL 不應加入 `#`。

### 多通訊協定端點

自訂服務商和部分內建服務商可分別設定：

| 通訊協定端點 | 常見用途 |
| --- | --- |
| OpenAI Chat Completions | 多數 OpenAI 相容聊天模型 |
| OpenAI Responses | 使用 Responses API 的模型 |
| Anthropic Messages | Claude 原生或相容 Messages API |
| Google Generate Content | Gemini 原生或相容介面 |

一個閘道顯示多種通訊協定，不代表每個模型都支援所有端點。模型的端點類型必須與伺服器端實際通訊協定一致。

### 自訂請求標頭

在**請求設定**中可以使用清單或 JSON 方式設定額外請求標頭。

僅在閘道文件明確要求時新增，例如租用戶 ID 或專案識別碼。不要重複新增 Cherry Studio 已管理的驗證標頭，也不要將 API Key 同時寫入多個位置。

### 服務商 API 選項

服務商名稱旁的閃電按鈕可能提供：

- 陣列內容格式；
- `developer` 角色；
- Stream Options；
- Service Tier；
- 思考開關或 verbosity；
- Anthropic Prompt Cache 相關設定。

這些選項只會改變請求格式，不會讓伺服器端獲得原本不支援的能力。遇到 `400`、未知參數或回應格式錯誤時，可以先還原預設選項。

## 同步模型清單

在服務商下方的模型清單中點選**拉取**，Cherry Studio 會從服務商取得可用模型，並先顯示同步預覽。

預覽通常會區分：

- 伺服器端新增、可加入本機的模型；
- 本機已有、仍存在於伺服器端的模型；
- 本機存在但已從伺服器端清單中消失的模型；
- 使用者可以選擇啟用、停用或保留的項目。

確認選擇後再套用，不要假定拉取會自動啟用伺服器端的所有模型。

如果服務商未提供模型清單介面，或代理未實作對應介面，可以使用**新增**手動建立模型。

## 手動新增和編輯模型

手動新增至少需要正確的**模型 ID**。模型 ID 是請求中傳送給伺服器端的值，應與服務商文件完全一致。

還可以設定：

- 顯示名稱；
- 群組名稱；
- 端點類型；
- 上下文視窗；
- 最大輸入和輸出 Token；
- 模型能力。

可標記的常見能力包括：

- 視覺；
- 原生網路搜尋；
- 推理；
- 工具呼叫；
- 嵌入；
- 重新排序。

{% hint style="warning" %}
能力標記只告訴 Cherry Studio 應如何使用模型，不會改變伺服器端能力。將一般模型誤標為視覺、原生聯網或工具呼叫模型，可能導致請求失敗，或讓外部工具無法正確注入。
{% endhint %}

嵌入模型和重新排序模型用於知識庫等檢索流程，不應作為一般對話模型使用。

## 模型可見性與健康檢查

服務商開關和模型開關是兩層獨立控制：

1. 服務商必須啟用；
2. 特定模型也必須啟用。

模型清單工具列可以：

- 搜尋模型；
- 依能力篩選；
- 批次啟用或停用可見模型；
- 執行模型健康檢查；
- 拉取伺服器端模型；
- 手動新增模型。

健康檢查適合一次核對多個模型；連線檢查適合驗證指定 Key 與指定模型。兩者都可能產生真實 API 請求和少量費用。

## 新增自訂服務商

點選服務商搜尋框旁的 **+**，建立自訂服務商。

基本流程：

1. 填寫服務商名稱；
2. 選擇或上傳圖示；
3. 填寫主要 Base URL；
4. 可選擇填寫第一組 API Key；
5. 如有需要，展開**更多端點**填寫其他通訊協定位址；
6. 建立後進入詳細資料頁面補充 Key 和模型；
7. 啟用服務商並執行連線檢查。

新建自訂服務商預設以 OpenAI Chat Completions 作為主要端點。如果目標服務只相容 Anthropic、Google 或 Responses API，應在端點設定和模型設定中明確選擇正確的通訊協定。

還可以從某個內建預設**複製服務商**，建立彼此獨立的設定執行個體。例如同一閘道有測試和正式環境位址時，可以分別命名、設定 Key 和啟用狀態。

## 建議設定順序

為了縮小疑難排解範圍，建議：

1. 啟用服務商；
2. 填寫一組確認有效的 Key；
3. 保留或核對預設 API 位址；
4. 拉取或手動新增一個對話模型；
5. 確認該模型已啟用；
6. 使用該 Key 和模型執行連線檢查；
7. 返回對話頁面傳送簡短訊息；
8. 基本呼叫正常後，再增加多 Key、自訂標頭和進階端點。

不要一開始同時修改 Key、位址、端點、請求標頭和進階選項，否則失敗時難以確定原因。

## 常見問題

### 服務商已設定，但模型選擇器中沒有模型

檢查：

- 服務商右上角開關是否已啟用；
- 模型清單中是否已新增目標模型；
- 目標模型本身是否已啟用；
- 目前頁面是否因能力篩選而隱藏了模型；
- 模型 ID 是否成功儲存。

### 連線檢查提示沒有可檢查的模型

先拉取或手動新增至少一個非重新排序模型，並啟用它。重新排序模型不能用於一般連線檢查。

### 傳回 401 或 403

通常與驗證或權限有關：

- Key 是否完整且未撤銷；
- Key 是否屬於正確的專案、地區或組織；
- 所選模型是否已授權；
- 自訂請求標頭是否覆寫了正確的驗證標頭；
- 雲端服務是否還需要地區、專案或 API 版本。

### 傳回 404

重點核對：

- Base URL 是否包含或缺少必要的版本路徑；
- 是否誤將完整 `/chat/completions` 當作一般 Base URL；
- 模型端點類型是否與伺服器端通訊協定一致；
- 自訂閘道是否實作模型清單和對話路徑；
- Azure 等服務是否要求部署名稱或 API Version。

### 傳回 400 或「未知參數」

將服務商 API 選項和模型能力還原為預設值，移除不必要的自訂請求標頭，再測試最簡單的文字對話。

### 拉取模型失敗

有些服務商未開放模型清單介面，或閘道只代理對話介面。此時可以依官方模型 ID 手動新增。

拉取成功也不代表每個模型都已向目前帳號開放；仍需使用健康檢查或實際對話驗證。

### 連線檢查成功，對話仍然失敗

檢查通常只涵蓋一組 Key、一個模型和一次基本請求。繼續核對：

- 對話實際選擇的是否為相同模型；
- 多 Key 輪替中是否有無效 Key；
- 長上下文、圖片、聯網或工具呼叫是否超出模型能力；
- 助理是否設定了不相容的自訂參數；
- 服務商是否出現額度、並行或內容政策限制。

### Key 輪替到無效憑證

開啟金鑰清單，停用或刪除失敗的 Key，再分別檢查剩餘 Key。只要無效 Key 仍處於啟用狀態，它就會繼續參與輪替。

## 安全與備份

- 不要使用真實 Key 製作文件螢幕截圖；
- 不要在問題回報中貼上完整請求標頭；
- 不要將正式環境和測試 Key 混在無法識別的清單中；
- 刪除服務商或清理資料前先建立備份；
- 備份或同步後，在目標裝置上重新核對本機路徑、代理和雲端帳號權限；
- 需要共用設定時，優先分享不含憑證的服務商名稱、位址結構和模型 ID。

### 取得協助與提交意見

如果設定失敗，請透過[意見回饋](../../../question-contact/suggestions.md)中列出的官方管道提交意見。建議附上 Cherry Studio 版本、服務商、模型 ID、端點類型、經過遮蔽處理的 API 位址和完整錯誤文字，但不要附上真實 API Key。
