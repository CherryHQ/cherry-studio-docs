# 知識庫

知識庫可以將文件、網頁等資料整理成可檢索的參考庫。聊天時，Cherry Studio 會先從知識庫找回相關片段，再將片段交給模型產生回答。

知識庫不會訓練或修改模型。它更適合需要反覆查詢、跨對話重複使用，或資料總量較大的情境。

{% hint style="info" %}
這是知識庫的快速入門頁。如需了解每個參數，請查看[完整知識庫教學](../../knowledge-base/knowledge-base.md)。
{% endhint %}

## 使用前準備

建立知識庫前，至少需要啟用一個支援**嵌入（Embedding）**功能的模型。嵌入模型會將資料和問題轉換為可檢索的資料。

建議事先確認：

* 模型服務已設定完成，嵌入模型可以正常呼叫
* 掃描版 PDF 或複雜文件已設定適合的文件處理方式
* 需要進一步改善排序時，再準備重排序（Rerank）模型

可以參考：

* [嵌入模型參考](../../knowledge-base/emb-models-info.md)
* [文件預處理](../../knowledge-base/zhi-shi-ku-wen-dang-yu-chu-li.md)

## 建立知識庫

1. 在啟動台開啟 **知識庫**。
2. 按一下左側的新增按鈕，選擇建立知識庫。
3. 輸入知識庫名稱。
4. 如有需要，將知識庫放入現有群組。
5. 選擇一個已啟用的嵌入模型，然後完成建立。

{% hint style="warning" %}
嵌入模型和向量維度決定知識庫的索引格式。日後更換模型或維度時，需要重建知識庫；因此建議在批次匯入資料前先確定設定。
{% endhint %}

## 新增資料

進入知識庫後，按一下新增資料並選擇來源。

| 來源 | 適用內容 | 目前說明 |
| --- | --- | --- |
| 檔案 | 單一或多個本機檔案 | 支援 PDF、DOCX、MD、XLSX、TXT、CSV、EPUB |
| 資料夾 | 一組本機資料 | 選擇資料夾後，批次匯入其中的檔案 |
| 網址 | 單一網頁 | 輸入網頁位址並擷取頁面內容 |
| Sitemap | 網站中的多個頁面 | 輸入 Sitemap 位址後，批次探索網頁 |
| 筆記 | 手動輸入內容 | 目前版本的新增介面尚未開放提交 |

提交新增任務後，可以關閉對話方塊繼續使用應用程式。資料讀取、分段和嵌入會在背景繼續進行。

## 等待索引完成

資料會依序經過準備、讀取、處理和嵌入等階段。不同來源顯示的中間狀態可能不同，最終應以狀態為**已完成**為準。

| 狀態 | 含義 | 建議操作 |
| --- | --- | --- |
| 準備中 / 讀取中 / 處理中 / 嵌入中 | 正在建立索引 | 保持應用程式執行並等待 |
| 已完成 | 可以檢索並用於聊天 | 先進行一次召回測試 |
| 失敗 | 目前資料尚未完成索引 | 修正模型、網路或檔案問題後重新索引 |
| 刪除中 | 正在清除資料和索引 | 等待清除完成 |

只有完成索引的內容才能穩定參與檢索。正在處理的資料無法強制重新索引；需要等待處理完成或失敗後再操作。

## 檢查和管理資料

知識庫的資料來源頁面提供下列操作：

* 依照檔案、資料夾、網址或 Sitemap 篩選
* 搜尋資料名稱並查看已就緒數量
* 預覽擷取後的內容
* 查看資料分段後的片段
* 刪除單一片段
* 對已完成或失敗的資料重新索引
* 多選資料後，批次重新索引或刪除

如果原始檔案已更新，重新索引可以用新內容取代舊索引。刪除資料時，對應的檢索資料也會以非同步方式清除。

## 先進行召回測試

在知識庫頂部開啟**召回測試**，輸入一個使用者實際可能提出的問題。

測試結果會顯示相符片段、分數、排序和耗時。請重點檢查：

* 正確資料是否出現在前幾筆結果中
* 召回片段是否包含回答問題所需的資訊
* 片段是否過長、過短或遭到錯誤截斷
* 不相關結果是否過多

如果召回結果本身不準確，聊天模型通常也無法提供可靠答案。應先調整資料或檢索設定，再測試聊天效果。

## 在聊天中使用

### 暫時選擇知識庫

1. 開啟**對話**並進入一個聊天。
2. 在輸入框的工具區域開啟知識庫選擇器。
3. 選擇一個或多個知識庫。
4. 提出與資料相關的問題。

只有目前助手和工具模式支援知識庫時，才能使用此入口。當輸入框已附加檔案時，知識庫選擇會停用；請先移除附件，再選擇知識庫。

### 固定至助手

如果某個助手需要長期使用同一組資料，可以開啟**資源庫 → 助手**，編輯助手並關聯知識庫。日後使用該助手時，不必每次重新選擇。

更多助手設定請查看[助手](agents.md)。

{% hint style="warning" %}
知識庫負責提供相關片段，最終回答仍由聊天模型產生。重要結論應結合引用片段和原始資料進行複核。
{% endhint %}

## 調整 RAG 設定

按一下知識庫頂部的 RAG 設定按鈕，可以調整檢索流程。

| 設定 | 功能 | 調整提示 |
| --- | --- | --- |
| 文件處理器 | 將文件轉換為可分段文字 | 掃描檔、圖片或複雜版面應優先檢查此項 |
| 分段大小和重疊 | 決定每個檢索片段的範圍 | 修改後，現有資料需要重新索引 |
| 嵌入模型和維度 | 產生並儲存向量索引 | 修改會觸發重建或復原流程 |
| 搜尋模式 | 在向量、關鍵字或混合檢索之間選擇 | 一般先使用預設的混合檢索 |
| 結果數量 | 控制傳回給模型的片段數量 | 過少可能遺漏資訊，過多可能加入雜訊 |
| 相似度門檻 | 過濾相關性不足的結果 | 僅在相應檢索模式下生效 |
| 混合權重 | 平衡語意比對和關鍵字比對 | 專有名詞較多時，可以配合召回測試調整 |
| 重排序模型 | 再次排序初次召回結果 | 會增加一次模型呼叫和等待時間 |

建議每次只修改一類參數，並使用同一組問題重複進行召回測試，以便判斷哪項調整真正有效。

## 常見問題

### 建立時沒有可選的嵌入模型

請檢查模型服務是否已啟用、模型是否帶有嵌入功能標記，以及 API 設定是否可用。一般聊天模型不會顯示在嵌入模型清單中。

### 資料持續處理中或顯示失敗

請先等待目前任務結束，再檢查網路、模型服務、檔案格式和文件處理器。修正後，對已失敗的資料執行重新索引。

### 掃描版 PDF 沒有有效文字

掃描版 PDF 通常只包含圖片，需要使用支援 OCR 或圖片解析的文件處理方式。請參考[文件預處理](../../knowledge-base/zhi-shi-ku-wen-dang-yu-chu-li.md)。

### 無法召回正確內容

請先確認資料已完成索引，再使用召回測試找出問題。可以依序檢查原文品質、分段大小、搜尋模式、結果數量、門檻和重排序設定。

### 聊天沒有使用知識庫

請確認目前聊天已選取知識庫、目標資料狀態為已完成，而且助手和工具模式支援知識庫。如果輸入框已附加檔案，請先移除附件。

## 資料、隱私權和費用

知識庫中繼資料和向量索引由 Cherry Studio 管理。根據所選的文件處理、嵌入、重排序和聊天服務，原文或擷取後的內容可能會傳送給相應服務商處理；回答時，召回片段也會傳送給目前的聊天模型。

匯入敏感資料前，請確認服務商的資料政策和部署方式。建立索引、重新索引、重排序和聊天回答也可能產生模型呼叫費用。

知識庫相關檔案和清理方式請查看[知識庫資料](../../knowledge-base/data.md)。
