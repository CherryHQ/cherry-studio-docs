# MCP 常見問題

本頁可協助排查 MCP 伺服器無法啟動、連線後沒有工具、呼叫逾時或參數錯誤等問題。第一次設定 MCP 時，建議先閱讀[設定與使用 MCP](config.md)；如果系統缺少執行環境，請先完成 [MCP 環境安裝](install.md)。

## 先確認連線類型

開啟 `設定 → MCP 伺服器`，進入發生問題的伺服器，先確認類型和必填項目相符：

| 類型 | 必填設定 | 常見問題 |
|---|---|---|
| `stdio` | 指令、參數，視需要填寫環境變數 | 指令不存在、參數拆分錯誤、相依套件未安裝 |
| `SSE` | 伺服器 URL，視需要填寫請求標頭 | URL 路徑錯誤、服務未執行、驗證失敗 |
| `Streamable HTTP` | 伺服器 URL，視需要填寫請求標頭 | 將 SSE 位址誤填為 `/mcp`，或反之 |
| 內建 | 依頁面說明設定 | 缺少授權、目錄或搜尋金鑰 |

`stdio` 會由 Cherry Studio 啟動本機子程序；SSE 和 Streamable HTTP 則會連線至已經執行的遠端或本機服務。疑難排解方式不同，請勿只替換 URL 或指令後反覆重試。

## 查看即時日誌

進入伺服器詳細資料，按一下標題旁的**查看日誌**。日誌會顯示：

* `stdout` / `stderr`：本機指令的輸出；
* `info` / `warn` / `error`：連線、初始化和呼叫狀態；
* 最近的啟動參數、連線錯誤或工具傳回資訊。

建議先關閉伺服器，再開啟日誌並重新啟用，如此更容易找到第一則錯誤。日誌最多保留頁面目前工作階段中的近期記錄，重現問題後請及時複製必要部分。

{% hint style="warning" %}
日誌可能包含指令參數、檔案路徑、請求位址或工具傳回內容。提交意見反應前，請先遮蔽 Token、API Key、Cookie、個人目錄和業務資料。
{% endhint %}

## 伺服器無法啟用

### 找不到 `npx`、`uvx` 或其他指令

Cherry Studio 會讀取登入 Shell 的環境變數來尋找指令。對於 `npx`，應用程式也會嘗試使用內建 Bun；對於 `uv` / `uvx`，則會嘗試使用已安裝的內建版本。

如果仍提示 `not found`：

1. 開啟 `設定 → MCP 伺服器 → 環境安裝`。
2. 安裝伺服器所需的 Node.js 或 `uv` 執行環境。
3. 完全結束並重新開啟 Cherry Studio，讓新的 PATH 生效。
4. 返回伺服器詳細資料並重新啟用。

也可以在終端機中驗證：

```bash
node --version
npx --version
uvx --version
```

只需驗證該伺服器實際使用的指令，不必安裝所有環境。

### 指令和參數填寫錯誤

在 Cherry Studio 中：

* **指令**只填寫可執行指令，例如 `npx`、`uvx` 或執行檔的絕對路徑；
* **參數**的每一行填寫一個獨立參數；
* 請勿將完整指令複製到指令欄位；
* 含空格的檔案路徑應填寫為一個完整參數，請勿自行加入 Shell 引號，除非伺服器文件有明確要求。

例如，下列 JSON：

```json
{
  "command": "npx",
  "args": ["-y", "@example/mcp-server", "--mode", "read-only"]
}
```

應在表單中填寫：

```text
指令
npx

參數
-y
@example/mcp-server
--mode
read-only
```

### JSON 匯入失敗

從 JSON 新增時，最外層應包含 `mcpServers`，且每次只能匯入一個伺服器：

```json
{
  "mcpServers": {
    "example": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"]
    }
  }
}
```

常見原因包括：

* 使用了中文引號或多餘逗號；
* `args` 不是字串陣列；
* 同一份 JSON 中包含多個伺服器；
* 將 `url`、`command` 和類型混合為不相容的設定；
* 複製的內容包含 Markdown 程式碼圍欄。

## 無法連線至遠端伺服器

### URL 或通訊協定不相符

確認伺服器的官方文件提供的是 SSE 還是 Streamable HTTP：

* SSE 的常見位址類似 `http://localhost:3000/sse`；
* Streamable HTTP 的常見位址類似 `http://localhost:3000/mcp`。

路徑由伺服器本身決定，`/sse` 和 `/mcp` 只是常見形式。請先在終端機或瀏覽器中確認服務確實監聽該位址，再選擇相應類型。

如果伺服器在 Docker、虛擬機器或另一部裝置中執行，`127.0.0.1` 指向 Cherry Studio 所在的系統，不一定是伺服器所在的主機。

### 傳回 401 或 403

在**請求標頭**中，以每行 `名稱=值` 的格式填寫驗證資訊，例如：

```text
Authorization=Bearer YOUR_TOKEN
```

請勿將真實 Token 寫入可以公開分享的設定。修改請求標頭後儲存；已啟用的伺服器會嘗試依新設定重新連線，失敗時會自動恢復為停用狀態。

## 已連線，但看不到工具

請依序檢查：

1. 伺服器已在 `設定 → MCP 伺服器` 中啟用。
2. 伺服器詳細資料的**工具**分頁是否列出工具。
3. 對應工具未在清單中被個別關閉。
4. 目前的助手或 Agent 已啟用該 MCP 伺服器。
5. 開始新對話，讓新的工具設定加入上下文。

「伺服器已連線」只表示通訊協定初始化成功，不代表每位助手都會自動取得其工具。

如果工具清單空白，但伺服器文件聲明有提供工具，請查看日誌中是否出現 `listTools`、通訊協定版本或初始化錯誤。

## 工具呼叫逾時

Cherry Studio 的預設工具呼叫逾時時間為 60 秒。伺服器詳細資料中的**逾時**可提高秒數；開啟長時間任務支援後，伺服器傳送進度事件時可以延長等待時間，但總時間仍有限制。

連線初始化使用較寬鬆的等待時間，首次下載相依套件或啟動遠端伺服器可能需要數分鐘。請區分：

* **啟用時逾時**：通常是安裝、網路、URL 或初始化問題；
* **工具執行時逾時**：通常是伺服器任務本身太慢，或沒有傳送進度。

請勿無限制提高逾時時間。先在日誌中確認請求確實正在推進，並檢查伺服器是否支援 MCP Progress。

## 環境變數未生效

伺服器的環境變數應依每行 `KEY=VALUE` 的格式填寫。Cherry Studio 會將它們與登入 Shell 環境合併後，傳給 `stdio` 子程序。

請檢查：

* 鍵名是否與伺服器文件完全一致；
* 值中是否意外包含引號或前後空格；
* 修改後是否已儲存並重新連線；
* Token 是否已經過期；
* 伺服器是否實際從環境變數讀取，而不是要求使用請求標頭或設定檔。

對於遠端 SSE / Streamable HTTP 伺服器，驗證資訊通常應放在請求標頭中，而不是本機程序的環境變數。

## `mcp-server-time` 時區錯誤

官方 Time Server 是 Python 伺服器，通常透過 `uvx` 啟動。如需指定本機時區，可以使用獨立參數填寫：

```json
{
  "mcpServers": {
    "time": {
      "command": "uvx",
      "args": [
        "mcp-server-time",
        "--local-timezone=Asia/Shanghai"
      ]
    }
  }
}
```

時區應使用 IANA 名稱，例如 `Asia/Shanghai`、`Europe/Berlin` 或 `America/New_York`，請勿填寫 `UTC+8` 這類時差縮寫。

如果提示 `uvx not found`，請先安裝 MCP 的 Python 環境並重新啟動 Cherry Studio。Time Server 的安裝方式或參數可能會隨版本變更，最終請以[官方 MCP Servers 儲存庫](https://github.com/modelcontextprotocol/servers/tree/main/src/time)為準。

## 最小化重現問題

如果問題仍未解決：

1. 建立只包含必要欄位的伺服器設定。
2. 暫時移除 Proxy、自訂映像來源和非必要的環境變數。
3. 在空白助手中只啟用這個 MCP 伺服器。
4. 呼叫一個最簡單且沒有副作用的工具。
5. 儲存錯誤對話方塊和**查看日誌**中對應時間範圍的資訊。

提交意見反應時，請附上 Cherry Studio 版本、作業系統、伺服器類型、已脫敏的設定和日誌。請勿附上真實憑證。官方管道請參閱[意見與建議](../../question-contact/suggestions.md)。
