# 使用 Kimi K2.5 建立黃金市場回顧 Agent

本案例示範如何使用 Cherry Studio 智能體完成一次「黃金價格波動回顧」：檢索公開資料、對齊價格與事件時間、儲存來源，並產生一份方便人工複核的報告。

Kimi K2.5 是本案例的示範模型。只要模型能透過 **Anthropic Messages** 端點在 Cherry Studio 智能體中使用，也可以替換成其他模型。不同服務商提供的模型、價格和工具相容性可能不同，應先用小型工作驗證。

{% hint style="warning" %}
本案例用於示範研究工作流程，不提供投資建議。模型可能遺漏資料、誤讀資料或產生錯誤程式碼；請勿根據產生的結果直接交易。
{% endhint %}

## 最終要取得什麼

建議將交付成果限制為四個檔案：

```text
gold-review/
├── sources.md       # 來源、發布時間、擷取時間和用途
├── market-data.csv  # 本次實際使用的價格資料
├── analysis.md      # 事件時間軸、計算過程和不確定項目
└── report.html      # 最終可閱讀的報告
```

這四個檔案分別回答「資料來自哪裡」、「使用了哪些資料」、「如何得出結論」和「如何呈現結果」。不要只要求產生一份漂亮的 HTML；缺少前三項時，最終頁面很難驗證。

## 工作流程設計

將工作拆成三個階段：

| 階段 | 主要工作 | 必須保留的證據 |
| :--- | :--- | :--- |
| 資料收集 | 取得指定時間範圍內的價格與總體資料 | 來源 URL、發布時間、擷取時間、原始數值 |
| 事件對齊 | 將顯著波動與同一時間範圍內的事件進行比較 | 時區、事件時間、價格區間、支持和反對證據 |
| 報告產生 | 組織圖表、時間軸、結論和限制 | 計算口徑、引用連結、缺漏資料、風險提示 |

可以讓智能體使用 `Task` 工具，將獨立的研究步驟交給子工作，但「平行處理」本身並不保證品質。最終仍要由主工作統一時間、單位和來源口徑。

## 第一步：準備模型

1. 開啟 **設定 → 模型服務**。
2. 設定提供 Kimi K2.5 的服務商，或選擇其他適合工具呼叫的模型。
3. 確認該模型的端點類型包含 **Anthropic Messages**。
4. 儲存後先完成一次一般對話，再到智能體模型選擇器中確認該模型可見。

智能體模型選擇器會排除 Embedding、Rerank 和圖片產生模型。如果模型可用於一般對話，卻沒有出現在智能體中，請優先檢查端點類型和模型能力標籤。

模型服務設定請參閱[模型服務](../../pre-basic/providers/)。需要手動補充模型或修正能力標籤時，可參閱[自訂服務商](../../pre-basic/providers/zi-ding-yi-fu-wu-shang.md#手動新增模型)中的模型管理方法。

## 第二步：準備工作目錄

建立一個空白目錄，例如 `gold-review`，並只放入本次工作需要的資料。不要選擇整個使用者目錄、下載目錄或包含金鑰的專案目錄。

如果已有價格資料，可以先放入 `market-data.csv`。建議至少包含：

```csv
timestamp,open,high,low,close,unit,timezone,source
2026-01-01T00:00:00Z,,,,,USD/oz,UTC,
```

欄位可以調整，但單位和時區必須明確。來自不同市場或資料來源的資料，在尚未轉換口徑前不應直接合併。

## 第三步：建立智能體

1. 開啟 **資源庫**，建立一個新的智能體。
2. 名稱填寫 `黃金市場回顧`。
3. 主模型選擇上一步驗證過的模型。
4. 在可存取目錄中新增剛才建立的 `gold-review`。
5. 權限模式先選擇**一般模式**。
6. 儲存智能體。

一般模式允許讀取檔案，但編輯檔案或執行指令時會要求確認。首次執行時不建議選擇「完全自動」；金融資料檢索和本機檔案寫入都需要人工觀察。

關於智能體的各項設定，請參閱[智能體](../agent.md)。

## 第四步：新增工具

在智能體的 **能力擴充 → 內建工具** 中確認下列工具可用：

| 工具 | 本案例用途 | 是否必要 |
| :--- | :--- | :--- |
| `Read`、`Glob`、`Grep` | 讀取現有資料和尋找檔案 | 是 |
| `WebSearch` | 搜尋公開資料 | 是 |
| `WebFetch` | 讀取指定網頁 | 是 |
| `Write` | 建立 CSV、Markdown 和 HTML | 是 |
| `Task`、`TodoWrite` | 拆分工作並記錄進度 | 建議 |
| `Bash` | 執行資料處理或本機驗證指令 | 選用 |

`WebSearch`、`WebFetch`、`Write` 和 `Bash` 涉及網路存取或修改本機內容。新增工具後，一般模式仍會在需要時要求確認。只核准目前步驟所需的呼叫。

如果網頁需要登入、包含驗證碼或禁止自動擷取，應改為手動下載資料後放入工作目錄，不要要求智能體繞過存取限制。

## 第五步：依需要安裝技能

本案例可以只使用系統提示詞完成。需要多次重複使用時，再將穩定流程整理成技能，例如：

* `market-data-verifier`：規定資料欄位、單位、時區和多來源核對方法。
* `event-timeline`：規定事件時間軸和因果強度的標記方式。
* `research-report`：規定報告結構、引用格式和失敗說明。

每個可安裝的技能都應是一個包含 `SKILL.md` 的目錄或 ZIP 壓縮檔。操作步驟：

1. 開啟 **設定 → 技能**。
2. 從目錄或 ZIP 安裝技能。
3. 回到已儲存智能體的 **能力擴充 → 技能**。
4. 為目前的智能體啟用所需技能。

技能會先儲存在 Cherry Studio 的全域技能庫中；為智能體啟用後，應用程式會將技能連結至該智能體工作目錄中的 `.claude/skills/`。不要手動複製來源不明的整套 `.claude` 組態，也不要覆寫應用程式建立的技能連結。

完整說明請參閱[技能](../../pre-basic/settings/skills.md)。

## 第六步：填寫系統提示詞

將下列範本放入智能體的系統提示詞，並依需要修改：

```text
你是一名市場研究助理。你的工作是整理可驗證的黃金市場回顧，
而不是預測收益或提供買賣建議。

工作規則：
1. 先確認使用者要求的品種、市場、幣別、單位、時區和日期範圍。
2. 價格、利率、指數和事件必須來自本次讀取的檔案或工具結果；
   不得使用模型記憶補寫目前數值。
3. 為關鍵事實記錄來源 URL、來源名稱、發布時間和本次存取時間。
4. 至少使用兩個互相獨立的來源核對核心結論；如果只有一個來源，請明確標記。
5. 嚴格區分事實、計算結果、解釋和假設，不要將時間相近直接寫成因果關係。
6. 資料缺漏、網頁無法存取或計算失敗時，保留缺口並說明原因。
7. 寫入檔案前先列出計畫；只在目前的工作目錄中建立或修改檔案。
8. 最終產生 sources.md、market-data.csv、analysis.md 和 report.html。
9. report.html 必須能在本機開啟，不得在頁面中嵌入金鑰或個人資訊。
10. 在報告結尾加入「僅供研究與學習，不構成投資建議」。
```

系統提示詞定義長期規則；特定研究日期和事件應放在每次傳送的工作中，不要硬寫在系統提示詞裡。

## 第七步：先執行資料清單

首次傳送的工作不要直接要求完整報告。先讓智能體提出資料計畫：

```text
請先為一次黃金現貨價格波動回顧制定資料清單，暫時不要撰寫報告。

範圍：
- 品種：請在開始前向我確認
- 計價單位：美元/盎司
- 時區：UTC
- 日期範圍：由我確認後再開始檢索

請輸出：
1. 需要的資料欄位；
2. 計畫使用的來源類型；
3. 將呼叫的工具和原因；
4. 將建立的檔案；
5. 需要我確認的權限和潛在費用。
```

檢查計畫沒有擴大目錄和資料範圍後，再允許它開始收集。

## 第八步：執行回顧

確認範圍後，可以傳送：

```text
依照已確認的範圍執行回顧。

要求：
- 先收集並儲存來源，再進行分析；
- 標記價格變化最大的時間範圍；
- 將事件時間統一轉換成 UTC；
- 每個原因都列出證據、反證和可信度；
- 所有計算都要寫明輸入欄位和公式；
- 無法驗證的內容放入「待核實」，不要補寫；
- 完成 Markdown 中間產物後，再產生 report.html；
- 最後回報建立或修改的檔案，以及仍未解決的問題。
```

執行過程中請重點檢查三類工具要求：

1. **網路要求**：網域是否與計畫中的來源一致。
2. **檔案寫入**：路徑是否位於 `gold-review` 中。
3. **指令執行**：指令是否只處理本次資料，以及是否會安裝套件或存取其他網路。

如果需要臨時安裝資料處理函式庫，請先暫停並自行審查套件名稱、來源和指令。不要將安裝相依套件預設為「繼續工作」的必要授權。

## 第九步：驗收中間產物

### 檢查 `sources.md`

每個來源至少包含：

* 來源名稱和 URL。
* 網頁或資料的發布時間。
* 本次存取時間。
* 它支援哪一項事實或資料。
* 是否需要登入、訂閱，或屬於二次轉載。

無法開啟的連結不能作為唯一證據。轉載文章應盡量追溯至原始發布者。

### 檢查 `market-data.csv`

確認：

* 時間格式和時區一致。
* 價格單位一致。
* 缺漏值沒有被默默填補。
* 資料範圍符合工作要求。
* `source` 可以對應至 `sources.md`。

隨機抽取幾個時間點，與原始來源手動比較。

### 檢查 `analysis.md`

「某個事件發生後價格下跌」只說明時間關係，並不能自動證明因果。建議每項解釋使用下列結構：

```text
觀察：
時間範圍：
支持證據：
反對或替代解釋：
可信度：高 / 中 / 低
仍需核實：
```

技術指標也必須保留公式、參數和輸入區間。只提供結果數字而沒有計算過程，不能視為驗收通過。

### 檢查 `report.html`

在本機開啟後檢查：

* 頁面沒有依賴無法存取的本機絕對路徑。
* 表格和圖表中的數字與 CSV 一致。
* 每項關鍵結論都能回到來源。
* 缺漏資料和限制沒有在最終版面配置中被隱藏。
* 頁面不包含 API Key、Cookie、使用者名稱或個人目錄。

## 常見問題

### Kimi K2.5 沒有出現在智能體模型列表中

確認模型的端點類型包含 **Anthropic Messages**，並檢查模型是否被錯誤標記為 Embedding、Rerank 或圖片產生類型。即使不同服務商提供同名模型，也不一定公開相同的端點能力。

### 智能體沒有搜尋網頁

檢查 `WebSearch` 和 `WebFetch` 是否已新增至目前的智能體，以及工具要求是否遭到拒絕。模型本身宣稱「支援聯網」，不代表 Cherry Studio 會自動提供網頁工具。

### 技能已安裝但沒有生效

先儲存智能體，確認它已有工作目錄，再到該智能體的技能列表中啟用技能。只將檔案放入工作目錄，並不代表已完成安裝和綁定。

### 無法建立報告檔案

檢查 `Write` 是否可用、目前的權限要求是否已核准，以及目標路徑是否位於可存取目錄。不要透過將範圍擴大到整個磁碟來解決路徑問題。

### 資料看起來很完整，但來源對不上

停止產生最終報告，要求智能體逐項標出每個數值的來源列。找不到來源的數值應刪除或標記為待核實，而不是繼續潤飾。

## 可以如何擴充

基礎流程通過後，可以逐步增加：

* 透過 MCP 連線至已審查的資料服務。
* 使用排程工作定期產生回顧，但仍保留人工審核。
* 透過頻道傳送「報告已產生」的通知，而不是直接傳送交易結論。
* 將穩定的驗證規則整理成團隊技能。

每次只增加一種能力，並重新檢查權限、費用和輸出。進一步設定請參閱[MCP](../mcp/)、[排程工作](../scheduled-tasks.md)和[頻道](../agent-channels.md)。
