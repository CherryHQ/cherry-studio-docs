# Agent 案例

這裡收錄使用 Cherry Studio 智能體完成真實工作的完整案例。每個案例不只呈現最終結果，還會拆解目標、模型、工作目錄、技能、工具權限和驗收方法，方便你依照自己的情境調整。

如果你還不熟悉助理、智能體、技能和 MCP 的差異，建議先閱讀[概念入門](../concepts-101.md)和[智能體使用教學](../agent.md)。

## 目前案例

| 案例 | 適合解決的問題 | 可以學到什麼 |
| :--- | :--- | :--- |
| [黃金市場回顧 Agent](gold-price-case.md) | 彙整公開資料、分析市場事件並產生容易閱讀的回顧報告 | 如何定義研究範圍、組織技能、限制檔案權限，以及核對資料來源 |

案例中的模型、第三方服務和網頁可能會隨時間變更。應將案例視為可修改的工作流程，而不是保證長期可以直接執行的固定範本。

## 閱讀案例時應注意什麼

可靠的智能體組態通常包含下列部分：

1. **目標**：說明要解決的問題和最終交付成果，避免只提出「幫我分析一下」這類過於寬泛的要求。
2. **輸入**：列出允許讀取的檔案、網頁、目錄或使用者提供的資料。
3. **能力**：選擇合適的模型，再依需要啟用內建工具、技能或 MCP Server。
4. **權限**：只開放必要的目錄和工具；寫入檔案、執行指令或存取外部服務時保留確認步驟。
5. **輸出**：約定檔案格式、儲存位置、引用方式和失敗時的處理規則。
6. **驗收**：檢查事實來源、產生的檔案、關鍵計算和異常情況，而不只是看答案是否「像真的」。

案例正文會盡量沿著這個流程說明組態原因。重現案例時可以替換模型或資料來源，但不應略過權限和驗收步驟。

## 開始重現前

### 1. 準備可用的模型

智能體的模型選擇器只會顯示支援 **Anthropic Messages** 端點，且不屬於 Embedding、Rerank 或圖片產生類型的模型。請先在[模型服務](../../pre-basic/providers/)中完成設定，並確認模型可以正常對話。

模型名稱只是組態的一部分。涉及工具呼叫時，還應先用一個小型工作確認所選服務商、端點和模型確實支援目前的工作流程。

### 2. 建立獨立工作目錄

為每個案例準備個別目錄，並只在智能體設定中新增需要存取的路徑。這樣更容易查看智能體建立或修改了哪些檔案，也能避免誤操作其他專案。

如果案例提供範例檔案，請先複製一份再修改；不要直接在唯一的原始檔案上執行寫入工作。

### 3. 從受限權限開始

首次執行時，請優先選擇需要確認的工具權限模式。看到工具要求後，先核對：

* 要呼叫的工具是否與目前步驟相關。
* 讀寫路徑是否位於已授權的目錄中。
* 指令和網路要求是否會產生費用或修改外部資料。
* 輸出中是否可能包含 API Key、個人資訊或未公開的檔案。

只有在同一流程已經可以穩定重現，而且你瞭解所有副作用後，才考慮減少確認步驟。

### 4. 先執行最小工作

不要一開始就將完整專案交給智能體。可以先要求它：

1. 讀取工作目錄，並列出將使用的檔案。
2. 說明預計呼叫的技能和工具。
3. 只產生一份小型範例或草稿。
4. 顯示引用來源和輸出檔案位置。

範例通過後，再擴大時間範圍、資料量或交付成果規模。這樣可以更快發現模型不相容、路徑錯誤、外部網頁失效或權限不足等問題。

## 如何驗收結果

不同案例的驗收標準會有所差異，但至少應檢查：

* **來源可追溯**：關鍵事實和資料可以回到真實來源，連結與發布時間相符。
* **輸入輸出一致**：報告使用的是這次取得的資料，而不是模型記憶中的舊資訊。
* **檔案可開啟**：產生的 Markdown、HTML、CSV 或其他檔案可以在對應的應用程式中正常開啟。
* **失敗可見**：要求失敗、資料缺漏或工具無法使用時會明確說明，而不是用猜測補齊。
* **範圍受控**：沒有讀取或修改已授權目錄以外的內容。

{% hint style="warning" %}
案例產生的分析不等同於專業意見。涉及金融、醫療、法律或其他高風險決策時，應核對原始資料，並由具備對應資格的人員再次確認。
{% endhint %}
