# 智能體工作區記憶

Cherry Studio V2 可以讓智能體在使用同一工作區的多個工作階段之間保留重要資訊。記憶會儲存在智能體第一個可存取目錄下的 `memory` 資料夾中，不需要設定全域記憶開關或 Embedding 模型。

此功能用於智能體任務，不會自動將一般對話合併進來。記憶依工作區目錄儲存，而不是依智能體 ID 另外建立目錄；如果兩個智能體使用相同的第一個可存取目錄，它們就會讀寫同一組記憶檔案。

## 使用條件

智能體必須設定可存取目錄。第一個可存取目錄會作為工作區，記憶檔案儲存在：

```text
<工作區>/memory/
├── FACT.md
└── JOURNAL.jsonl
```

如果智能體沒有可存取目錄，工作區記憶便無法讀寫。

## 兩類記憶

| 檔案 | 儲存內容 | 使用方式 |
| :--- | :--- | :--- |
| `FACT.md` | 長期有效的事實、約定和技術決策 | Soul Mode 和一般自訂智能體會在後續工作階段載入，並在事實變更時更新 |
| `JOURNAL.jsonl` | 已完成的任務、一次性事件和工作階段記錄 | 按時間附加；需要時由智能體搜尋，不會全部載入內容脈絡 |

判斷一項資訊是否適合寫入 `FACT.md` 時，可以問：「六個月後這項資訊仍然重要嗎？」如果只是某次任務的過程或結果，則更適合寫入 Journal。

## 讓智能體記住資訊

在智能體工作階段中直接說明需要保留的內容，例如：

> 記住：這個專案統一使用 pnpm，提交前執行 lint 和單元測試。

對於長期規則，可以要求智能體更新持久事實；對於一次性進度，可以要求它記錄到 Journal。智能體會透過內建的工作區記憶工具完成寫入。

{% hint style="warning" %}
記憶檔案位於本機工作區。請勿讓智能體記錄密碼、API Key、存取權杖或其他敏感資訊。
{% endhint %}

## 在後續工作階段中使用

使用支援工作區記憶的智能體，並在同一工作區開始新的工作階段時，Cherry Studio 會將 `FACT.md` 中的持久事實提供給智能體。需要查找先前的事件時，可以要求智能體搜尋 Journal，例如：

> 查找上週有關發佈失敗的記錄。

搜尋可以依文字和標籤篩選，並傳回最近的相符記錄。

目前，`FACT.md` 的自動載入適用於 Soul Mode 和一般自訂智能體；內建 Cherry Assistant 不會自動載入這部分工作區事實。

## 查看或維護記憶

你可以在工作區中查看 `memory/FACT.md`，了解目前儲存了哪些長期資訊。更正事實時，建議在工作階段中告訴智能體更新記憶，讓它透過記憶工具安全寫入。

`JOURNAL.jsonl` 是逐行 JSON 記錄。建議透過智能體搜尋，不要手動大量改寫。

## 未能記住資訊時

請依序檢查：

1. 目前的智能體是否已設定可存取目錄。
2. 目前智能體的第一個可存取目錄是否仍指向原本的工作區。
3. `memory/FACT.md` 中是否已寫入對應資訊。
4. 需要查找的是長期事實，還是 Journal 中的一次性記錄。

舊版全域記憶與 V2 的智能體工作區記憶是兩套獨立機制。排查 V2 的記憶內容時，請以目前工作區中的 `memory/FACT.md` 和 `memory/JOURNAL.jsonl` 為準。
