# 文件預處理

文件預處理會在分塊和向量化之前，將 PDF、Word、試算表等文件轉換成更適合檢索的 Markdown 文字。它主要用於掃描文件、複雜版面配置、表格和多欄文件。

如果文件本身已有清楚的文字層，Cherry Studio 的內建讀取通常就能正常運作。不要為了「更進階」而預設為所有檔案啟用線上處理器，應先使用少量資料比較實際效果。

## 處理流程

未選擇文件處理器時：

1. Cherry Studio 直接讀取支援的檔案。
2. 擷取文字並分塊。
3. 呼叫嵌入模型建立索引。

選擇文件處理器後：

1. Cherry Studio 將文件交給所選的處理器。
2. 處理器輸出 Markdown。
3. Markdown 會作為處理產物由應用程式管理。
4. Cherry Studio 再進行分塊並建立索引。

{% hint style="info" %}
文件處理器負責「將檔案轉換成可檢索的文字」，嵌入模型負責「將文字轉換成向量」，聊天模型負責「根據召回片段回答」。三者是不同的處理環節。
{% endhint %}

## 哪些文件需要預處理

下列情況應優先考慮使用文件處理器：

* 掃描版 PDF 中沒有可複製的文字
* PDF 包含複雜表格、多欄版面配置或大量公式
* Word、Excel 等檔案的內建解析結果結構混亂
* 關鍵內容位於圖片或頁面版面配置中
* 召回片段出現亂碼、順序錯誤或大量內容遺漏

下列情況通常不需要額外處理：

* 純文字、Markdown、CSV 等結構清楚的文字檔案
* 文字層完整、版面配置簡單的 PDF
* 內建解析後，預覽和召回測試都已正常

預處理無法自動解決所有問題。手寫文字、低解析度掃描、複雜公式和巢狀表格仍可能辨識錯誤。

## V2 支援的處理能力

Cherry Studio 的檔案處理分為兩類：

| 能力 | 輸入 | 輸出 | 與知識庫的關係 |
| --- | --- | --- | --- |
| 文件轉 Markdown | 文件檔案 | Markdown | 可在知識庫 RAG 設定中選擇 |
| 圖片轉文字 | 圖片 | 文字 | 用於其他圖片 OCR 情境，不等同於知識庫文件處理 |

目前知識庫新增資料的入口不會將圖片當作獨立資料來源。要處理包含圖片的 PDF 或 Office 文件，應選擇支援**文件轉 Markdown**的處理器。

## 可選的文件處理器

目前 V2 `main` 中，知識庫可以選擇下列文件轉 Markdown 處理器：

| 處理器 | 部署方式 | 常見組態 |
| --- | --- | --- |
| Mistral OCR | 線上 API | API Key、API Host、模型 |
| MinerU | 線上 API | API Key、API Host |
| Doc2X | 線上 API | API Key、API Host |
| Open MinerU | 自行託管的服務 | 本機或內部網路 API Host |
| PaddleOCR | API 服務或自行部署 | API Key、API Host、解析模型 |

實際可見項目取決於目前的系統和應用程式版本。服務商位址、模型和申請方式可能會變更，應以 **設定 → 文件處理** 中的即時介面為準。

{% hint style="warning" %}
線上處理器通常需要上傳原始檔案。匯入合約、內部資料或個人資訊前，請確認服務商的資料政策、部署區域和刪除機制。處理敏感資料時，應優先使用本機或自行託管的處理器。
{% endhint %}

## 設定文件處理器

1. 開啟 **設定 → 文件處理**。
2. 在左側選擇一個支援文件轉 Markdown 的處理器。
3. 根據處理器要求填寫 API Key。
4. 檢查 API Host；自行託管的服務應填寫實際可存取的位址。
5. 如果介面提供模型選項，請選擇服務端已部署的模型。
6. 按一下**設為預設**，可將它設為一般文件處理的預設處理器。

API Key 輸入框支援管理多個金鑰。設定金鑰時，請勿將金鑰放入文件、螢幕擷取畫面或回饋日誌中。

### 線上處理器

線上處理器需要符合下列條件：

* API Key 有效且帳戶狀態正常
* API Host 與帳戶所在區域一致
* 網路能夠存取服務
* 目前模型支援文件解析
* 檔案大小和格式符合服務商限制

### Open MinerU

Open MinerU 用於連線至自行部署的 MinerU 服務。預設位址只適用於本機測試；如果服務執行於容器、遠端主機或其他連接埠，應填寫 Cherry Studio 所在裝置可存取的完整位址。

### PaddleOCR

PaddleOCR 可以設定解析模型。模型名稱必須與服務端部署一致。應用程式介面中的預設項目不代表你的服務端一定已安裝對應的模型。

## 圖片 OCR 與知識庫文件處理

設定頁面也可能顯示系統 OCR、Tesseract、PaddleOCR、Mistral 和 OpenVINO OCR 等圖片轉文字處理器。

* 系統 OCR 只會出現在支援的平台上
* Tesseract 可以設定辨識語言
* OpenVINO OCR 只會在執行環境符合條件時出現
* PaddleOCR 和 Mistral 可能同時支援圖片與文件處理能力

這些圖片 OCR 設定不會自動取代知識庫中的文件轉 Markdown 選擇。知識庫處理 PDF、DOCX、XLSX 等文件時，應在該知識庫的 RAG 設定中選擇文件處理器。

## 在知識庫中啟用

1. 開啟目標知識庫。
2. 按一下頂端的 **RAG 設定**。
3. 在**檔案處理器**中選擇已設定的文件處理器。
4. 儲存設定。
5. 新增一份測試文件，等待狀態變成已完成。

建立新的知識庫時，預設可以不選擇檔案處理器。只有在選取處理器後，支援的文件檔案才會進入文件轉 Markdown 流程。

{% hint style="warning" %}
更換檔案處理器不會自動重寫已完成的資料。要讓舊資料使用新的處理器，需要為對應的資料來源重新建立索引。
{% endhint %}

## 驗證處理結果

不要只查看「已完成」狀態。至少完成下列三個步驟。

### 1. 預覽來源

在資料來源列的更多選單中選擇**預覽來源**，檢查：

* 標題和段落順序是否正確
* 表格是否保留列與欄的關係
* 頁首、頁尾是否產生大量雜訊
* 關鍵數字、專有名詞和公式是否正確辨識
* 是否出現缺頁、空白或亂碼

### 2. 查看分塊

開啟分塊詳細資料，檢查內容是否在合理的位置切分。即使解析結果完整，不當的分塊仍會影響檢索。

### 3. 召回測試

使用文件中實際存在的問題測試召回：

* 表格中的特定數值
* 跨段落資訊
* 專有名詞和編號
* OCR 容易混淆的文字

如果沒有擷取到正確文字，請先更換處理器或改善原始檔案；如果文字正確但召回不佳，再調整分塊和檢索設定。

## 如何比較處理器

選擇 3–5 份具代表性的文件，為每個候選處理器執行相同的測試。

| 維度 | 需要觀察的結果 |
| --- | --- |
| 完整性 | 是否漏掉頁面、段落或表格 |
| 順序 | 多欄內容和頁碼是否依正確順序排列 |
| 準確性 | 數字、符號和專有名詞是否正確 |
| 結構 | 是否保留標題、列表和表格 |
| 速度 | 單一文件與批次處理所需時間 |
| 穩定性 | 是否經常逾時或失敗 |
| 隱私與費用 | 是否上傳原文以及如何計費 |

同一個處理器在不同文件類型上的表現可能不同。合約、論文、報表和掃描票據不必使用相同的組態。

## 常見問題

### 知識庫中沒有檔案處理器選項

確認目前開啟的是知識庫頂端的 RAG 設定，並檢查應用程式版本。知識庫只會列出支援文件轉 Markdown 的處理器，不會列出只有圖片 OCR 能力的處理器。

### 文件處理一直等待

遠端處理器可能會採用背景工作。讓應用程式保持執行，並檢查網路和服務商工作狀態。逾時後資料會顯示失敗，修正組態後即可重新建立索引。

### 顯示 API Key 或 Host 錯誤

檢查金鑰是否包含多餘的空格、Host 是否包含正確的通訊協定、帳戶區域是否相符，以及目前裝置能否存取自行託管的服務。

### 掃描 PDF 處理後仍是空白

確認所選的是文件轉 Markdown 處理器，而不是只有圖片轉文字能力的處理器。也請檢查掃描解析度、頁面方向和服務商支援的語言。

### 表格解析混亂

先在預覽來源中確認問題來自文件處理，而不是分塊。可以改用更擅長複雜版面配置的處理器，或預先將關鍵表格匯出成結構較簡單的檔案。

### 更換處理器後結果沒有變化

修改處理器只會影響後續處理。請為現有資料來源重新建立索引，並等待新的處理工作完成。

### 一般 Markdown 也會使用線上處理器嗎

知識庫只會針對辨識為文件類型且已在知識庫中選擇處理器的檔案啟動文件預處理。文字和 Markdown 檔案會直接進入讀取與建立索引流程。

## 隱私與費用

線上文件處理可能會產生上傳、解析和儲存費用。處理完成後，還會繼續呼叫嵌入模型；如果啟用重新排序和線上聊天模型，後續檢索與回答也可能會產生費用。

完整資料流和備份建議請參閱[知識庫資料](data.md)。
