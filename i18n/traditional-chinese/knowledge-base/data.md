# 知識庫資料

本頁說明 Cherry Studio 將知識庫資料儲存在哪裡、哪些內容可能會傳送給模型服務商，以及如何安全地刪除、備份和移轉。

如果只想建立和使用知識庫，請先閱讀[知識庫教學](knowledge-base.md)。

## 知識庫儲存了哪些內容

V2 的知識庫資料不是一個可單獨複製的檔案，而是由多種類型的資料共同組成。

| 資料 | 主要內容 | 用途 |
| --- | --- | --- |
| 知識庫中繼資料 | 名稱、群組、模型、分塊和檢索組態 | 讓應用程式辨識並管理知識庫 |
| 資料來源記錄 | 原始路徑或網址、類型、狀態和錯誤資訊 | 追蹤匯入內容與處理進度 |
| 向量索引 | 文件片段、向量和檢索欄位 | 執行召回測試與聊天檢索 |
| 檔案記錄與處理產物 | 原始檔案參照、解析後的文字等 | 預覽來源、重新建立索引和處理文件 |

中繼資料與資料來源記錄會儲存在 Cherry Studio 的主要 SQLite 資料庫中。每個知識庫還有一個獨立的本機 libSQL 向量儲存檔案。

{% hint style="warning" %}
不要只複製某個知識庫的向量檔案作為備份。向量檔案必須與主要資料庫中的知識庫 ID、資料來源記錄和模型組態保持一致，單獨復原通常無法取得完整的知識庫。
{% endhint %}

## 是否會複製本機檔案

從知識庫新增本機檔案時，Cherry Studio 會記錄該檔案的**原始絕對路徑**，並透過檔案記錄加以關聯。原始檔案仍會保留在原本的位置，不會因為加入知識庫而被移動。

這會直接造成下列影響：

* 移動、重新命名或刪除原始檔案後，預覽和重新建立索引可能會失敗
* 已建立的向量索引不會自動隨原始檔案更新
* 修改原始檔案後，需要在知識庫中手動執行重新建立索引
* 備份 Cherry Studio 資料時，仍需另外備份外部原始檔案

檔案處理器產生的中間產物可能會由 Cherry Studio 儲存在自己的資料目錄中，但這些產物不能取代原始檔案的長期備份。

## 資料儲存位置

知識庫資料位於 Cherry Studio 的使用者資料目錄。預設位置通常是：

| 系統 | 預設使用者資料目錄 |
| --- | --- |
| macOS | `~/Library/Application Support/CherryStudio` |
| Windows | `%APPDATA%\CherryStudio` |
| Linux | `~/.config/CherryStudio` |

實際目錄可能因安裝方式、應用程式版本、開發環境或自訂資料目錄而異。應以 **設定 → 資料 → 資料目錄** 中顯示的目前路徑為準。

V2 中與知識庫直接相關的典型內容包括：

* 使用者資料目錄根目錄中的 `cherrystudio.sqlite`：知識庫與資料來源中繼資料
* `Data/KnowledgeBase`：依知識庫儲存的向量儲存檔案
* `Data/Files`：由 Cherry Studio 管理的檔案和處理產物

{% hint style="info" %}
這些內部路徑是用來瞭解備份範圍，不建議在應用程式執行時手動修改檔案。如果需要調整整個資料目錄，請參閱[修改儲存位置](../personalization-settings/storage.md)。
{% endhint %}

## 哪些內容會離開本機

「知識庫儲存在本機」不代表「整個處理過程都在本機」。是否向外部服務傳送內容，取決於你選擇的處理器和模型。

### 文件處理

如果使用線上文件解析或 OCR 服務，原始檔案或其中的內容可能會傳送給對應的服務商。使用本機處理器時，這個步驟可以留在本機。

### 建立索引

使用線上嵌入模型時，切分後的文字片段會傳送給嵌入服務商，傳回的向量則儲存在本機。重新建立索引也會再次呼叫嵌入服務。

### 檢索與重新排序

查詢知識庫時，使用者問題會由嵌入模型處理。如果啟用了線上重新排序模型，問題和候選片段還會傳送給重新排序服務商。

### 產生回答

在對話中使用知識庫時，使用者問題和召回的相關片段會作為內容傳送給目前的聊天模型。

### 匯入網頁

匯入網址或 Sitemap 時，Cherry Studio 會存取目標網站。目標伺服器可能會記錄 IP、存取時間和請求資訊。

{% hint style="warning" %}
處理合約、醫療、內部程式碼等敏感資料前，應同時檢查文件處理、嵌入、重新排序和聊天模型這四個環節。只將聊天模型換成本機模型，並不能保證其他環節沒有對外連線請求。
{% endhint %}

## 減少資料外傳

如果資料不能傳送給第三方，可以：

1. 使用本機文件解析和 OCR 功能。
2. 透過 Ollama、LM Studio 等方式執行本機嵌入模型。
3. 不啟用線上重新排序模型，或改用本機服務。
4. 在聊天階段選擇本機模型。
5. 避免直接匯入需要身分驗證的內部網頁。

本機模型的設定方法請參閱[嵌入模型](emb-models-info.md)和對應的模型服務教學。

## 刪除資料後會發生什麼

### 刪除一個資料來源

刪除資料來源時，Cherry Studio 會清理該資料來源的記錄和向量片段。如果是資料夾或 Sitemap，展開後產生的子項目也會一併處理。

刪除知識庫中的檔案資料來源**不會刪除磁碟上的原始檔案**。

### 刪除一個分塊

在分塊詳細資料中刪除單一片段，只會移除該片段的檢索資料，不會修改原始檔案。之後為該資料來源重新建立索引時，已刪除的片段可能會依目前的分塊規則再次產生。

### 刪除整個知識庫

刪除知識庫時，Cherry Studio 會先停止相關的背景工作，再刪除該知識庫的向量儲存內容和主要資料庫記錄。

這項操作不會刪除匯入時參照的外部原始檔案，但會移除知識庫組態和已建立的索引。刪除前應確認已有可復原的完整備份。

## 備份知識庫

### 建議方式

1. 在 **設定 → 資料** 中使用內建備份功能。
2. 如果目標是完整復原知識庫，請勿啟用**略過檔案資料**。
3. 另外備份所有外部原始檔案和資料夾。
4. 記錄所使用的模型服務、嵌入模型和文件處理器。
5. 定期在安全環境中驗證備份是否能夠復原。

內建備份中的「略過檔案資料」會略過使用者資料目錄下的 `Data` 內容，其中包含知識庫向量檔案和 Cherry Studio 管理的處理產物，因此不適合作為完整的知識庫備份。

### 複製整個資料目錄

如果需要製作檔案層級的快照，應先完全結束 Cherry Studio，再複製**整個使用者資料目錄**，而不是只複製 `Data/KnowledgeBase`。

應用程式執行時，SQLite 資料庫和向量檔案可能正在寫入。直接複製使用中的檔案可能會得到不一致的快照。

### 復原後檢查

復原完成後，不要只檢查知識庫名稱是否出現，還應：

* 開啟資料來源列表，確認狀態與數量
* 預覽幾份資料
* 使用固定問題執行召回測試
* 在對話中核對引用來源
* 對需要更新的外部檔案重新建立索引

跨系統、跨主要版本或更換嵌入模型後，建議先在副本環境中驗證。如果外部檔案路徑在不同裝置上發生變更，原始路徑參照可能會失效。

## 移轉與磁碟空間

知識庫占用的空間主要取決於：

* 原始資料與處理產物的大小
* 分塊數量
* 嵌入向量維度
* 知識庫數量
* 多次匯入和重新建立索引所產生的資料

需要移動資料目錄時，應使用 Cherry Studio 的資料目錄設定，並在移轉前完成備份。移轉後至少檢查一次資料來源預覽、召回測試和對話引用。

如果只是要釋放空間，請優先在應用程式內刪除不再使用的資料來源或知識庫。不要直接刪除內部資料庫檔案。

## 常見問題

### 刪除知識庫後，原始檔案還在嗎

還在。知識庫參照的外部本機檔案不會隨知識庫一起刪除。刪除操作只會清理 Cherry Studio 管理的記錄和索引。

### 移動原始檔案後還能繼續檢索嗎

現有索引可能暫時仍會傳回舊片段，但預覽和重新建立索引會因原始路徑失效而失敗。應重新新增新路徑下的檔案，並確認召回結果。

### 只備份 `Data/KnowledgeBase` 可以嗎

不可以。該目錄只有向量儲存內容，缺少主要資料庫中的中繼資料和資料來源關聯，也不包含外部原始檔案。

### 使用本機嵌入模型就完全離線了嗎

不一定。還需要確認文件處理器、重新排序模型和聊天模型是否也在本機，以及是否匯入了外部網頁。

### 重建索引會產生費用嗎

如果使用依用量計費的線上文件處理、嵌入或重新排序服務，重新建立索引可能會再次產生呼叫費用。
