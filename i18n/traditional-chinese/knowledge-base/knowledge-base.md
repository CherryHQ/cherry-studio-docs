# 知識庫教學

知識庫可以將本機文件和網頁整理成可檢索的資料庫。聊天時，Cherry Studio 會先找出與問題相關的片段，再將這些片段交給目前的模型產生回答。

知識庫不會訓練或修改模型。它適合需要反覆查詢、跨對話重複使用，或資料量較大、不方便每次作為附件傳送的情境。

本頁會帶你完成一次完整流程：**準備嵌入模型 → 建立知識庫 → 新增資料 → 測試召回 → 在對話中使用**。

{% hint style="info" %}
如果只想快速瞭解用途，可以先閱讀[知識庫功能介紹](../cherrystudio/preview/knowledge-base.md)。模型選擇、資料儲存和文件解析請分別參閱[嵌入模型](emb-models-info.md)、[知識庫資料](data.md)和[文件預處理](zhi-shi-ku-wen-dang-yu-chu-li.md)。
{% endhint %}

## 使用前準備

建立知識庫前，至少需要設定一個可用的**嵌入（Embedding）模型**。嵌入模型負責將資料和問題轉換成可檢索的資料，一般聊天模型不會出現在知識庫的嵌入模型列表中。

在 **設定 → 模型服務** 中完成服務商設定，並確認目標模型：

* 已新增至模型列表且處於啟用狀態
* 能力類型包含嵌入
* API 位址、金鑰和網路連線皆可正常使用

模型列表可能會隨服務商變更，文件不會固定推薦某個線上模型。選擇方法和常見模型請參閱[嵌入模型](emb-models-info.md)。

## 建立知識庫

1. 開啟頂端啟動台，在應用程式列表中選擇**知識庫**。
2. 按一下左側導覽區域的新增按鈕，選擇**建立知識庫**。
3. 輸入一個容易辨識的名稱。
4. 如果已建立群組，可選擇知識庫所屬的群組。
5. 選擇已啟用的嵌入模型，完成建立。

建立視窗只會顯示具有嵌入能力標記的已啟用模型。如果列表是空的，請先返回模型服務設定檢查組態。

{% hint style="warning" %}
嵌入模型和向量維度會決定索引格式。批次匯入資料前，建議先使用少量內容完成一次召回測試。日後更換嵌入模型或維度時，需要透過重建流程重新產生索引。
{% endhint %}

## 新增資料

進入知識庫後，按一下資料來源區域的新增按鈕，選擇資料來源。

| 來源 | 適合的內容 | 目前說明 |
| --- | --- | --- |
| 檔案 | 一個或多個本機檔案 | 支援 PDF、DOCX、MD、XLSX、TXT、CSV、EPUB |
| 資料夾 | 同一目錄中的一組資料 | 選擇本機目錄後批次匯入 |
| 網址 | 單一公開網頁 | 輸入完整的 `http://` 或 `https://` 位址 |
| Sitemap | 網站中的多個頁面 | 輸入可直接存取的 Sitemap 位址 |
| 筆記 | 手動輸入文字 | 目前 V2 新增介面尚未開放提交 |

### 匯入檔案

1. 選擇**檔案**。
2. 拖曳檔案，或按一下以選擇本機檔案。
3. 確認檔案列表後提交。
4. 返回資料來源列表，等待處理完成。

一次可以選擇多個檔案。如果不支援某個檔案格式，請先轉換為上表列出的格式。

### 匯入資料夾

1. 選擇**資料夾**。
2. 按一下以選擇目錄，並確認系統檔案存取權限。
3. 確認目錄後提交。

資料夾適合集中匯入一組資料。匯入後仍應檢查資料來源列表，確認所需檔案都已成功處理。

### 匯入網頁或 Sitemap

1. 選擇**網址**或 **Sitemap**。
2. 輸入可公開存取的完整位址。
3. 提交後等待頁面擷取和索引完成。

如果網頁需要登入、依賴動態指令碼才會顯示，或已啟用存取限制，Cherry Studio 可能無法擷取有效內容。Sitemap 也必須是應用程式可直接存取的位址。匯入完成後，建議先預覽擷取結果並進行召回測試。

{% hint style="info" %}
新增工作提交後，資料會繼續在背景讀取、分塊和嵌入。處理過程中不要結束應用程式或中斷模型服務。
{% endhint %}

## 檢查處理狀態

資料建立索引時，會依序經過準備、讀取、處理、分塊和嵌入等階段。不同來源顯示的中間狀態可能不同，最終以**已完成**為準。

| 狀態 | 含義 | 建議操作 |
| --- | --- | --- |
| 準備中 / 讀取中 / 處理中 / 分塊中 / 嵌入中 | 正在建立索引 | 保持應用程式執行並等待 |
| 已完成 | 可以檢索並用於聊天 | 先進行召回測試 |
| 失敗 | 目前資料尚未完成索引 | 查看錯誤原因，修正後重新建立索引 |

資料來源列表還可以：

* 依檔案、資料夾、網址和 Sitemap 篩選
* 搜尋資料名稱並查看就緒數量
* 預覽擷取後的原始內容
* 查看已完成資料的分塊結果
* 對已完成或失敗的資料重新建立索引
* 多選資料後批次重新建立索引或刪除

如果原始檔案或網頁內容發生變更，請執行**重新建立索引**以更新檢索內容。處理中的資料無法重新建立索引，需要先等待目前的工作結束。

## 先進行召回測試

知識庫頂端提供**召回測試**。它會直接測試檢索結果，適合在開始聊天前排查資料、分塊和檢索設定。

1. 按一下頂端的召回測試按鈕。
2. 輸入使用者實際可能提出的問題。
3. 查看傳回的片段、結果數量、耗時，以及相關度或排序資訊。
4. 展開結果，確認片段包含回答問題所需的原文。
5. 換幾種問法重複測試。

測試時請重點檢查：

* 正確資料是否排在前幾筆
* 片段是否包含完整的關鍵資訊
* 片段是否過長、過短，或在關鍵句中間被截斷
* 不相關的結果是否過多

召回測試會為每個知識庫保留查詢歷程，可重複使用同一組問題來比較不同組態。如果召回結果本身不準確，聊天模型通常也無法提供可靠的答案。

## 在對話中使用知識庫

1. 開啟**對話**並進入一個聊天。
2. 按一下輸入框工具區域中的知識庫按鈕。
3. 選擇一個或多個知識庫。
4. 輸入與資料相關的問題並傳送。
5. 閱讀回答時，同時核對檢索到的知識庫引用和原始資料。

知識庫選擇器支援多選，也可以一鍵清空。所選知識庫會連結至目前的助理，之後繼續使用該助理時仍可重複使用。

{% hint style="warning" %}
在下列情況中，可能看不到或無法使用知識庫按鈕：

* 目前的助理或工具模式不支援知識庫
* 輸入框已新增檔案附件

如果已新增附件，請先移除附件，再選擇知識庫。
{% endhint %}

知識庫只負責提供相關片段，最終回答仍由聊天模型產生。重要結論應搭配引用內容和原始資料再次確認。

## 調整 RAG 設定

按一下知識庫頂端的設定按鈕，即可調整文件處理與檢索流程。

| 設定 | 作用 | 調整建議 |
| --- | --- | --- |
| 檔案處理器 | 將文件轉換成可分塊的文字 | 掃描文件、圖片或複雜版面配置應優先檢查此項 |
| 分塊大小與重疊 | 決定每個檢索片段的範圍 | 變更後需要為現有資料重新建立索引 |
| 嵌入模型與維度 | 產生並儲存向量索引 | 變更會進入重建流程 |
| 搜尋模式 | 選擇不同的檢索方式 | 先保留預設值，再根據召回測試調整 |
| 結果數量 | 控制每次傳回的片段數 | 過少可能遺漏資訊，過多可能帶入雜訊 |
| 相似度臨界值 | 篩除相關性不足的結果 | 只在對應的搜尋模式下生效 |
| 混合權重 | 平衡語意與關鍵字檢索 | 專有名詞較多時可重點測試 |
| 重新排序模型 | 將初次召回結果再次排序 | 會增加一次模型呼叫和等待時間 |

建議每次只修改一類參數，並使用相同問題重複執行召回測試。這樣更容易判斷效果來自哪一項變更。

## 常見問題

### 建立時沒有可選的嵌入模型

檢查模型服務是否已啟用、模型能力是否標記為嵌入，以及 API 組態是否可用。一般聊天模型無法取代嵌入模型。

### 資料一直處理中

先讓應用程式保持執行並等待。如果長時間沒有進度，請檢查模型服務、網路、檔案存取權限和文件處理器，再為失敗的資料重新建立索引。

### 檔案顯示失敗

將滑鼠移至失敗狀態以查看錯誤原因。常見原因包括不支援的格式、無法讀取檔案、無法存取網頁，以及呼叫嵌入服務失敗。

### 掃描版 PDF 沒有有效文字

掃描版 PDF 通常只包含圖片，需要使用支援 OCR 或圖片解析的文件處理方式。請參閱[文件預處理](zhi-shi-ku-wen-dang-yu-chu-li.md)。

### 無法召回正確內容

請確認資料已完成索引，再依序檢查原文品質、分塊大小、搜尋模式、結果數量、臨界值和重新排序組態。不要只靠更換聊天模型掩蓋召回問題。

### 聊天沒有使用知識庫

確認目前的助理已選取知識庫、目標資料狀態為已完成，而且輸入框中沒有檔案附件。也可以先在召回測試中使用相同問題，確認檢索是否正常。

## 資料、隱私與費用

知識庫中繼資料和索引由 Cherry Studio 管理。根據所選的文件處理、嵌入、重新排序和聊天服務，原文或擷取後的內容可能會傳送給對應的服務商；回答時，召回片段也會傳送給目前的聊天模型。

匯入敏感資料前，請確認服務商的資料政策和部署方式。建立索引、重新建立索引、重新排序和聊天回答也可能產生模型呼叫費用。

本機儲存、備份和清理方式請參閱[知識庫資料](data.md)。
