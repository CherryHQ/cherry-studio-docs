# 自訂服務商

自訂服務商用於接入 Cherry Studio 尚未內建的雲端平台、OpenAI 相容 Proxy、區域網路閘道或自託管模型服務。

Cherry Studio V2 提供兩種建立方式：

| 方式 | 適用情境 | 主要特點 |
| --- | --- | --- |
| 新增自訂服務商 | 新平台、OpenAI 相容服務、本機推論服務 | 預設以 OpenAI Chat Completions 作為主要對話協定 |
| 從預設服務商新增執行個體 | 同一廠商的第二個帳號、地區、閘道或私有位址 | 保留原服務商的驗證方式、預設協定和專用適配 |

{% hint style="info" %}
如果目標平台已有預設服務商，應優先新增該服務商的另一個執行個體。完全自訂服務商適合標準相容介面，不會自動取得某個廠商的專用驗證、圖片工作或參數適配。
{% endhint %}

## 使用前準備

建立前，先從目標服務的官方文件確認：

1. 使用哪一種 API 協定；
2. Base URL，而不是網頁控制台位址；
3. API Key 或其他驗證方式；
4. 模型清單介面是否可用；
5. 準備呼叫的完整 Model ID；
6. 模型是否支援視覺、思考、工具、Embedding 或 Rerank；
7. 是否要求額外的請求標頭；
8. 是否有 IP 白名單、Proxy 或憑證要求。

只有「介面相容」還不夠。傳回欄位、串流格式、工具呼叫、思考內容和錯誤結構也需要與所選協定相容。

## 選擇建立方式

### 新增完全自訂服務商

適合：

- OpenAI 相容雲端服務；
- OneAPI、NewAPI 等統一閘道；
- vLLM、LocalAI 等自託管服務；
- 企業內部的相容 Proxy；
- 尚未出現在預設清單中的平台。

V2 的完全自訂服務商預設主端點是：

```text
OpenAI Chat Completions
```

建立時不再使用舊版的「OpenAI / Gemini / Anthropic / Azure OpenAI」服務商類型下拉式選單。

### 從預設服務商新增執行個體

適合：

- 同一服務商使用多組獨立帳號；
- 不同地區使用不同 Base URL；
- 公司 Proxy 與官方位址並存；
- 需要保留 Azure、Vertex AI、Bedrock 等專用驗證；
- 需要保留服務商專用的圖片、思考或模型同步適配。

在預設服務商所在群組點選**新增執行個體**，或開啟服務商選單後選擇相同操作。建立新的執行個體後，再填寫自己的驗證資訊和位址。

{% hint style="warning" %}
複製預設服務商只會複製設定結構，不會複製原執行個體的敏感認證資料。建立後應在新執行個體詳細資料頁重新填寫驗證資訊。
{% endhint %}

## 新增完全自訂服務商

1. 開啟 `設定 → 模型服務`；
2. 如有需要，將篩選切換為**全部服務商**；
3. 點選服務商搜尋框右側的 `+`；
4. 填寫容易識別的服務商名稱；
5. 可以選擇內建圖示或上傳自己的圖示；
6. 填寫主要 Base URL；
7. 可以選填第一組 API Key；
8. 如果平台同時提供其他相容協定，展開**更多端點**；
9. 點選**新增**；
10. 進入新服務商詳細資料頁繼續設定模型。

名稱只會影響顯示，不會改變請求協定。建議在名稱中包含平台、地區或用途，例如「內部閘道-上海」。

## 填寫 Base URL

Base URL 是介面根位址，不是完整請求位址。

以 OpenAI Chat Completions 為例：

```text
正確：https://api.example.com/v1
錯誤：https://api.example.com/v1/chat/completions
錯誤：https://console.example.com/models
```

V2 會根據端點類型拼接具體請求路徑。是否需要 `/v1`、`/v1beta` 或自訂路徑，應以目標服務的官方文件為準。

{% hint style="warning" %}
不要照搬其他用戶端的「Proxy 位址」，除非確認它要求的正是 Base URL。同一個平台在不同工具中可能要求填寫根位址或完整請求位址。
{% endhint %}

### 本機與區域網路位址

本機服務的常見位址：

```text
http://127.0.0.1:8000/v1
```

如果服務在 Docker、虛擬機器或另一台電腦上執行，`localhost` 指向的裝置可能不同。應使用 Cherry Studio 所在電腦可以存取的位址，並確認防火牆和監聽網路介面。

HTTPS 服務使用自簽憑證時，系統憑證驗證也可能阻止連線。不要為了解決憑證問題而直接關閉整台電腦的安全驗證。

## 設定更多端點

完全自訂服務商建立頁面可以額外填寫：

- Anthropic Messages；
- Google Gemini；
- OpenAI Responses。

建立後也可以在 API Host 右側開啟**請求設定**，新增或修改端點。

這些位址用於描述同一個服務商提供的不同協定入口。它們不會將只支援 OpenAI 的模型自動變成 Anthropic 或 Gemini 模型。

對於一般手動新增的自訂模型，主要協定仍以服務商預設端點為準。如果必須使用某個廠商協定或專用驗證，應優先從對應的預設服務商新增執行個體。

## API Key 與多組 Key

建立時可以填寫第一組 API Key，也可以留空後再設定。

在服務商詳細資料頁可以：

- 新增多組 Key；
- 為 Key 新增容易識別的標籤；
- 暫停某組 Key；
- 刪除已失效或外洩的 Key。

只有已啟用的 Key 才能用於請求。多組 Key 是否都擁有相同的模型、餘額和組織權限，仍由伺服器端決定。

{% hint style="danger" %}
不要將真實 API Key 寫入文件、聊天、公開儲存庫、截圖或自訂請求標頭範例。外洩後應立即在伺服器端撤銷。
{% endhint %}

沒有驗證要求的本機服務可以不填 Key。不要為了通過表單而隨意填寫正式環境認證資料。

## 自訂請求標頭

在 API Host 右側點選請求設定按鈕，可以使用清單或 JSON 方式填寫額外的請求標頭。

常見用途包括：

- 組織或專案識別碼；
- 企業閘道的租戶標頭；
- Proxy 要求的版本標頭；
- 伺服器端明確要求的自訂驗證標頭。

填寫前應注意：

1. 只新增官方文件明確要求的欄位；
2. 不要重複覆寫 `Content-Type`；
3. 不要同時在 API Key 和自訂標頭中設定衝突的 `Authorization`；
4. JSON 模式必須是物件；
5. 物件值會以字串傳送；
6. 修改後重新執行連線檢查。

請求標頭會隨相關請求傳送至目標位址。不要將敏感標頭用於不受信任的 Proxy。

## 啟用服務商

建立完成後：

1. 選擇新的服務商；
2. 檢查 API Key 和 API Host；
3. 開啟服務商開關；
4. 同步或手動新增模型；
5. 只啟用實際需要的模型；
6. 執行健康檢查。

服務商未啟用時，即使模型已新增，也不會正常出現在對應的模型選擇位置。

## 同步模型

對於 OpenAI 相容服務，V2 預設嘗試讀取：

```text
GET {Base URL}/models
```

如果目標服務正確實作模型清單介面，Cherry Studio 會顯示同步預覽。套用前請檢查：

- 新增模型；
- 更新模型；
- 已從伺服器端移除的模型；
- Model ID 和顯示名稱；
- 是否正確識別模型能力。

同步失敗不代表對話介面一定失敗。有些服務只實作 Chat Completions，沒有實作 `/models`，此時應手動新增模型。

## 手動新增模型

1. 點選模型清單中的**新增模型**；
2. 填寫伺服器端要求的完整 Model ID；
3. 可以填寫較容易閱讀的顯示名稱和群組；
4. 依官方規格填寫上下文與最大輸出；
5. 選擇模型實際支援的能力；
6. 儲存並啟用；
7. 執行健康檢查。

可手動標記的能力包括：

- 圖片理解；
- 聯網搜尋；
- 思考；
- 工具呼叫；
- Embedding；
- Rerank。

能力標記用於介面篩選和請求路由，不會改變伺服器端能力。錯誤標記可能導致請求失敗，或將 Embedding、Rerank 模型錯誤顯示在對話清單中。

{% hint style="warning" %}
Model ID 必須與伺服器端完全一致。顯示名稱可以自訂，但不能用顯示名稱取代請求中的 Model ID。
{% endhint %}

## 連線檢查與模型健康檢查

建議分層檢查：

1. 先檢查服務商連線；
2. 再檢查單一對話模型；
3. 單獨測試串流輸出；
4. 單獨測試視覺、思考和工具呼叫；
5. 在知識庫中實際測試 Embedding 與 Rerank。

目前 V2 的通用健康檢查會略過 Rerank 模型，因此 Rerank 需要在知識庫檢索流程中驗證。

連線檢查通過不代表：

- 每個模型都有權限；
- 餘額充足；
- 視覺或工具呼叫可用；
- 長上下文一定成功；
- 伺服器端所有擴充參數都相容。

## OpenAI 相容能力邊界

完全自訂服務商可以重複使用標準 OpenAI 相容能力：

- Chat Completions；
- 串流輸出；
- 視覺輸入；
- Function Calling；
- Embeddings；
- 標準模型清單。

是否可用取決於伺服器端與具體模型。下列能力通常無法只靠「相容 OpenAI」自動取得：

- 廠商原生非同步圖片工作；
- 專用檔案上傳；
- 雲端知識庫；
- 特殊思考參數；
- 非標準 Rerank；
- OAuth、IAM 或雲端帳號簽章；
- 廠商特有的模型同步分類。

如果服務商需要這些能力，應使用預設適配或專門文件。

## 使用 vLLM 建立本機服務商

vLLM 提供 OpenAI 相容伺服器。安裝方式和硬體要求請先參閱 [vLLM 官方文件](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)。

使用一個支援聊天範本的模型啟動服務：

```sh
vllm serve NousResearch/Meta-Llama-3-8B-Instruct \
  --dtype auto \
  --api-key local-test-token
```

預設監聽連接埠為 `8000`。在 Cherry Studio 中新增完全自訂服務商：

```text
服務商名稱：vLLM Local
Base URL：http://127.0.0.1:8000/v1
API Key：local-test-token
```

然後同步 `/v1/models`，或手動新增 vLLM 傳回的 Model ID。

{% hint style="info" %}
上述 Key 只用於本機範例。區域網路或公網部署必須使用高強度認證資料、存取控制、TLS 和防火牆，不要直接暴露未經驗證的推論連接埠。
{% endhint %}

如果傳回「缺少 chat template」，需要使用附帶聊天範本的模型，或依 vLLM 文件設定 `--chat-template`。

## PDF、附件與隱私

對於通用對話模型，Cherry Studio 會先在本機擷取 PDF 文字，再傳送至伺服器端：

- 文字型 PDF 通常可以處理；
- 掃描檔需要 OCR；
- 表格、複雜排版和圖片資訊可能遺失；
- 擷取的文字會占用上下文；
- PDF 中的圖片需要視覺模型。

自訂服務商的 Base URL 決定資料最終傳送至何處。接入 Proxy 或企業閘道前，應確認：

- 營運方身分；
- 資料保留政策；
- 記錄與訓練政策；
- 跨境傳輸；
- TLS 與憑證；
- 組織合規要求。

## 常見問題

### 傳回 401

API Key 錯誤、驗證標頭格式不相容，或自訂請求標頭覆寫了正確的 `Authorization`。重新檢查伺服器端驗證說明。

### 傳回 403

Key 沒有模型或專案權限、IP 不在白名單中，或組織政策拒絕請求。

### 傳回 404

通常是 Base URL 被填成完整請求位址、缺少版本路徑，或伺服器端沒有對應介面。分別檢查 `/models` 和 `/chat/completions`。

### 傳回 400

模型不支援目前的參數、訊息格式、圖片、思考或工具呼叫。先使用純文字和預設參數測試。

### 傳回 429

已達到伺服器端的請求、Token 或並行限制。降低並行數並使用退避重試。

### 模型同步是空的

目標服務可能未實作 `/models`，或該介面需要不同權限。確認位址後手動新增 Model ID。

### 模型可以對話，但圖片失敗

一般文字模型不一定支援視覺；檢查模型能力和伺服器端的圖片訊息格式。

### 工具只被模型描述，沒有真正呼叫

模型可能不支援 Function Calling，或傳回格式不相容。先使用一個簡單工具驗證結構化呼叫。

### Embedding 出現在對話清單

模型類型標記錯誤。編輯模型並啟用 Embedding 能力，關閉不真實的對話能力。

### Rerank 無法通過健康檢查

通用健康檢查會略過 Rerank。請在知識庫中設定模型並實際執行檢索。

### 本機服務可以在瀏覽器中開啟，但 Cherry Studio 仍連線失敗

瀏覽器開啟根頁面不代表 API 可用。檢查 `/v1/models`、防火牆、監聽位址、Proxy、自簽憑證和聊天範本。

### 新增了 Anthropic 或 Gemini 位址，但模型仍使用 OpenAI

完全自訂服務商的主要端點預設是 OpenAI Chat Completions。只填寫次要端點不會保證一般手動模型自動切換協定；需要對應廠商協定時，應優先從預設服務商新增執行個體。

更多一般設定請參閱[模型服務](README.md)和[模型服務設定](../../cherrystudio/preview/settings/providers.md)，vLLM 介面請參閱 [OpenAI-Compatible Server](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)；意見回饋管道請參閱[回饋與建議](../../question-contact/suggestions.md)。
