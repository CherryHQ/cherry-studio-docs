# 常見問題

本頁用於快速判斷問題所屬類別，並前往對應主題。遇到故障時，請先保留原始錯誤與資料，不要一開始就重新安裝、重設資料或刪除應用程式目錄。

## 先完成五項檢查

1. 在 **設定 → 關於**記錄 Cherry Studio 的完整版本號。
2. 記錄作業系統、晶片架構與問題發生時間。
3. 儲存介面顯示的完整錯誤，不要只寫「無法使用」。
4. 使用新對話、小型檔案或簡單工具縮小問題範圍。
5. 判斷是所有模型都失敗，還是只有特定服務商、模型或功能失敗。

如果問題在升級後出現，還應記錄升級前的版本，以及是否曾移轉資料目錄。

{% hint style="warning" %}
重設資料會清空本機資料庫與應用程式管理的檔案，並非通用修復步驟。沒有可用備份時請勿使用；清除快取也無法修復帳戶、模型或 API 設定錯誤。
{% endhint %}

## 應用程式無法安裝或啟動

### 安裝套件無法開啟

確認下載的系統與架構正確：

* Apple Silicon Mac 使用 arm64 套件，Intel Mac 使用 x64 套件。
* Windows 與 Linux 也要選擇符合裝置架構的版本。
* 安裝套件應來自[客戶端下載](../cherrystudio/download.md)或官方 Release。

macOS 出現「無法驗證開發者」或檔案損毀提示時，請依照 [macOS 安裝教學](../pre-basic/installation/macos.md)處理，不要從不明來源下載重新簽署的安裝套件。

### 啟動後白畫面、版面錯亂或按鈕消失

如果使用過自訂 CSS，請先參考[清除 CSS 設定](../personalization-settings/clear-css.md)。錯誤的選擇器可能遮住設定入口，但刪除整個資料目錄也會同時遺失其他內容。

未使用自訂 CSS 時，請記錄版本與系統，重新啟動後再次重現。若問題仍然出現，請保留日誌並提交意見。

### 更新後看起來像全新安裝

先檢查是否修改過應用程式資料目錄、外接磁碟是否在線，以及啟動時是否選擇了新的空白目錄。不要立即在新目錄中建立大量資料，也不要刪除舊目錄。請參閱[修改儲存位置](../personalization-settings/storage.md)。

## 模型服務

### 儲存 API Key 後仍無法使用

依序確認：

1. 服務商開關已啟用。
2. API Key 屬於目前服務商與區域，且沒有多餘空格。
3. API 位址使用該服務商要求的根路徑與介面類型。
4. 帳戶已開通目標模型，且餘額、配額或計費方式可用。
5. 模型已同步或手動新增，並已在模型清單中啟用。

連線檢查成功通常只代表一次基礎請求可以到達，不代表視覺、推理、工具呼叫、Embedding 或圖片產生都可用。每項能力都應個別測試。

通用設定請參閱[模型服務](../pre-basic/providers/)，各範本入口請參閱[全部 Provider 快速參考](../pre-basic/providers/quick-reference.md)。

### 無法取得模型清單

部分相容服務不提供標準模型清單，或只回傳帳戶有權存取的模型。請先核對 Base URL、憑證、區域與代理；若服務商允許手動填寫 Model ID，可以依其官方文件新增。

不要從其他平台複製「看起來相同」的 Model ID。命名空間、大小寫與版本後綴都可能不同。

### 模型在服務商頁面可見，但對話中找不到

模型必須同時符合：

* 所屬服務商已啟用。
* 模型本身已啟用。
* 模型類型適合目前入口。

Embedding、Rerank 與圖片產生模型不會顯示為一般聊天模型。Agent 還要求模型可透過 **Anthropic Messages** 端點使用。

### 常見 HTTP 狀態碼

不同服務商對錯誤的定義可能不同，應以回傳本文與服務商文件為準。

| 狀態碼 | 常見方向 | 優先檢查 |
| :--- | :--- | :--- |
| `400` | 請求參數、上下文或內容格式無效 | 模型端點、附件、上下文長度、自訂參數 |
| `401` | 身分驗證失敗 | API Key、Authorization 方式、Key 是否過期 |
| `403` | 帳戶、模型、區域或內容權限不足 | 模型授權、計費、地區、組織權限 |
| `404` | 路徑、部署或模型不存在 | Base URL、Deployment、Model ID、介面類型 |
| `408` / `504` | 請求或上游逾時 | 網路、代理、服務狀態、輸入規模 |
| `413` | 請求本文過大 | 圖片與檔案大小、上下文、批次輸入 |
| `422` | 參數可解析但無法處理 | 欄位類型、必填值、模型專用參數 |
| `429` | 頻率、Token 或額度限制 | RPM/TPM、餘額、並行數、稍後重試 |
| `500` / `502` / `503` | 上游內部錯誤、閘道或過載 | 服務狀態、代理、改用小型請求後重試 |

錯誤只在特定模型出現時，請先改用同一服務商的另一個基礎文字模型測試；所有服務商都失敗時，再檢查本機網路與代理。

## 對話

### 傳送後沒有回覆

檢查訊息上方顯示的實際模型與服務商。在多模型對話中，一個模型失敗不代表其他模型也失敗；請分別查看每則回覆的錯誤。

可以建立一個預設助理與空白對話，只傳送簡短文字：

```text
請回覆：連線正常
```

小型請求成功、原對話失敗時，問題更可能來自上下文長度、附件、工具或助理自訂參數。詳細操作請參閱[對話介面](../cherrystudio/preview/chat.md)。

### 上下文過長或請求本文過大

減少歷史訊息、關閉不需要的上下文、移除大型附件，或建立新對話。清除上下文只影響後續傳送給模型的歷史範圍，不等同於刪除介面中的所有訊息。

### 無法上傳圖片或模型無法辨識圖片

確認模型具有視覺能力標籤，而且目前服務商端點確實接受圖片。手動勾選能力只會改變 Cherry Studio 的介面篩選與請求路由，不會讓服務端獲得原本沒有的能力。

在多模型對話中上傳圖片時，所有被提及的模型都應支援圖片輸入。

### 公式顯示為原始碼

先確認模型輸出了完整定界符：

* 行內公式：`$...$` 或 `\(...\)`
* 獨立公式：`$$...$$` 或 `\[...\]`

如果定界符被程式碼區塊包住、跳脫不完整或模型輸出遭截斷，公式就不會呈現為數學內容。請先查看原始訊息，再判斷是否為顯示問題。

## 網路與代理

### 瀏覽器可以存取，Cherry Studio 無法存取

系統瀏覽器與 Electron 應用程式可能使用不同的代理、憑證或登入狀態。開啟[一般設定](../cherrystudio/preview/settings/general.md)，核對代理模式、代理位址以及是否需要重新啟動。

還應檢查：

* 公司網路或防火牆是否封鎖目標網域。
* HTTPS 憑證是否被代理替換。
* 系統時間是否正確。
* 服務是否限制地區或要求登入。

不要以關閉系統安全軟體或忽略憑證錯誤的方式，長期解決連線問題。

### 啟用代理後所有請求都失敗

暫時切回系統代理或不使用代理進行比較。手動代理需要正確的協定、主機與連接埠；HTTP、HTTPS、SOCKS 不能只因連接埠相同就互換。

## 知識庫

### 無法建立知識庫或取得維度失敗

建立前需要可用的 Embedding 模型。請檢查：

1. 選擇的確實是 Embedding，而不是一般聊天模型。
2. 服務商、API Key、Base URL 與 Model ID 正確。
3. 該模型能完成一次實際的嵌入請求。
4. 模型回傳的向量維度與設定一致。

詳細疑難排解請參閱[嵌入模型](../knowledge-base/emb-models-info.md)。

### 檔案持續處理中或顯示失敗

先等待目前佇列結束，再查看失敗狀態。常見原因包括檔案無法讀取、網頁無法存取、文件處理器失敗、Embedding 請求失敗或觸發限流。

修正設定後，對失敗資料執行重新索引。知識庫完整流程請參閱[知識庫教學](../knowledge-base/knowledge-base.md)。

### 聊天回答不準確

先使用召回測試檢查是否找到正確片段：

* 召回錯誤：調整資料、分塊、Embedding 或 Rerank。
* 召回正確但回答錯誤：再檢查聊天模型、提示詞與上下文。

知識庫只提供檢索片段，最終回答仍由聊天模型產生。

## Agent

### 模型沒有出現在 Agent 選擇器

Agent 要求模型的端點類型包含 **Anthropic Messages**，並排除 Embedding、Rerank 與圖片產生模型。請檢查服務商端點與能力標籤，再使用簡單工具任務驗證實際相容性。

### Agent 頁面提示服務未執行

請先點擊頁面中的啟動按鈕。若仍然失敗，請開啟 **設定 → API 伺服器**，檢查連接埠與執行狀態。連接埠被其他程式占用時，需要停止衝突程序或改用可用的連接埠。

### Agent 無法讀取或寫入檔案

檢查目標目錄是否已加入可存取路徑、工具是否啟用、權限請求是否核准。不要將整個使用者目錄或磁碟加入可存取路徑來規避錯誤。

更多疑難排解請參閱 [Agent](../advanced-basic/agent.md)與 [API 伺服器](../advanced-basic/api-server.md)。

## MCP

### Server 無法啟動

本機 STDIO Server 應優先檢查 Command、Arguments、執行環境與工作目錄；遠端 Server 則應優先檢查 URL、Headers、驗證與協定類型。

開啟 Server 詳細資料中的**查看日誌**，關閉後重新啟用一次，較容易找到第一筆啟動錯誤。完整清單請參閱 [MCP 常見問題](../advanced-basic/mcp/chang-jian-wen-ti.md)。

### 已連線但沒有工具

連線成功不代表 Server 一定提供 Tools。它也可能只提供 Prompts 或 Resources。請檢查 Server 詳細資料中的能力清單，以及日誌中是否有初始化或 `listTools` 錯誤。

### 模型只描述工具，但沒有呼叫

確認：

* 目前助理或 Agent 已繫結該 MCP Server。
* Server 已啟用且目標工具可見。
* 目前模型與端點支援工具呼叫。
* 工具核准未遭拒絕。

## 資料、備份與復原

### 自動備份沒有產生

檢查週期不是「關閉」、目標目錄或遠端服務在線，並查看頁面顯示的最近錯誤。外接磁碟、NAS 與遠端儲存還要確認空間、權限與連線狀態。

### 復原後缺少圖片或知識庫檔案

如果備份時啟用了**精簡備份**，應用程式 `Data` 目錄中的圖片與知識庫檔案會被略過。這是預期行為，無法從精簡備份復原遭排除的檔案。

### 多台電腦的資料沒有自動合併

備份與復原是覆寫式流程，不是即時雙向同步。復原前請比較版本與時間，並先備份目前裝置。

詳細說明請參閱[資料設定](../data-settings/README.md)。

## 取得日誌

前往 **設定 → 資料設定 → 資料**，在**應用程式日誌**項目開啟日誌目錄。重現問題後，依發生時間找到對應檔案。

提交前請刪除或遮蓋：

* API Key、Token、Cookie 與驗證 Header。
* 對話、提示詞、知識庫與檔案內容。
* 電子郵件、使用者名稱、個人目錄與內部網路位址。
* 第三方服務的請求或回傳資料。

日誌可能以多行記錄同一個錯誤。請保留錯誤前後的必要上下文，但不要公開上傳整個應用程式資料目錄或備份檔案。

## 提交意見時應提供什麼

一個可處理的問題至少包含：

```text
Cherry Studio 版本：
作業系統與架構：
服務商與模型（如相關）：
問題發生時間：
預期結果：
實際結果：
最小重現步驟：
完整錯誤：
已嘗試的操作：
去識別化日誌或截圖：
```

請先閱讀[如何有效提問](ask.md)，再透過[意見與建議](suggestions.md)中的管道提交。若涉及當機或資料問題，請說明是否有備份、是否曾移轉資料目錄，以及問題發生後是否繼續寫入。
