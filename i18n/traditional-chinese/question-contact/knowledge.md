# 知識入門

本頁說明 Cherry Studio 中常見的 AI 概念。理解這些概念的目的不是背誦術語，而是了解模型為何會失敗、哪些設定會影響結果，以及資料可能被傳送到哪裡。

## 模型、服務商與介面

### 模型

模型是處理輸入並產生輸出的計算系統。不同模型可能專注於文字、圖片理解、圖片產生、Embedding、Rerank、推理或工具呼叫。

同一個模型名稱可能由多個服務商提供。服務商不同，可能代表：

* Model ID、版本與上下文上限不同。
* 可用地區、價格、限流與帳戶權限不同。
* 使用 OpenAI、Anthropic、Gemini 或其他介面。
* 圖片、工具、推理參數等能力不同。

因此，「模型名稱相同」無法證明介面行為相同。使用前應在目前服務商上完成實際測試。

### 服務商

服務商負責提供 API 位址、驗證、模型清單、計費與請求限制。Cherry Studio 負責儲存連線設定、組織請求與顯示結果，但無法代替服務商開通帳戶、額度或模型權限。

設定入口請參閱[模型服務](../pre-basic/providers/)。

### 介面與端點

介面定義請求與回應格式。常見端點包括：

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* Ollama Chat

「相容某介面」通常只代表基礎格式相似，不保證實作了該介面的每一項進階能力。Agent 還要求模型可透過 **Anthropic Messages** 端點使用。

## Token 與 Tokenizer

### 什麼是 Token

Token 是模型處理文字時使用的片段。一個 Token 可能是：

* 一個完整單字。
* 單字的一部分。
* 一個或多個字元。
* 標點符號、空格或特殊符號。

Token 不等於字數，也不固定等於某種語言中的字元數。

### 什麼是 Tokenizer

Tokenizer 負責將輸入轉換成模型使用的 Token 序列。不同模型與版本可能使用不同的 Tokenizer，因此同一段文字的 Token 數可能不同。

這會影響：

* 是否超過上下文上限。
* 請求速度。
* 輸入與輸出費用。
* 長篇文件如何分割。

Cherry Studio 顯示的 Token 數用於協助判斷上下文規模，最終計費與精確用量應以服務商回傳為準。

## 上下文視窗

上下文是模型在單次請求中實際收到的資訊。它可能包括：

* 系統提示詞與助理設定。
* 目前的使用者訊息。
* 保留的歷史訊息。
* 圖片、檔案或網頁內容。
* 知識庫召回片段。
* 工具定義、呼叫參數與回傳結果。
* 模型繼續產生輸出所需的空間。

上下文視窗有上限。內容過多時，服務商可能拒絕請求，應用程式可能截斷部分內容，或模型只關注其中一部分。

### 上下文越長越好嗎

不一定。更長的上下文會增加費用與等待時間，也可能讓無關資訊干擾任務。更有效的方法是：

* 不同專案使用不同話題。
* 階段切換時使用**新上下文**。
* 只附上任務需要的檔案。
* 知識庫只召回相關片段。
* 將穩定規則放進助理，暫時資訊放進目前訊息。

對話中的話題與上下文操作請參閱[對話介面](../cherrystudio/preview/chat.md)。

## 系統提示詞、助理與話題

### 系統提示詞

系統提示詞用於規定長期角色、行為邊界與輸出規則。它無法改變模型本身的知識、上下文上限與服務端能力。

系統提示詞過長或彼此衝突時，會占用上下文並降低可預測性。只保留穩定規則；日期、資料與本次目標應放在使用者訊息中。

### 助理

助理會儲存一套可重複使用的對話設定，例如：

* 系統提示詞。
* 預設模型與參數。
* 上下文數量。
* 知識庫。
* 連網搜尋與 MCP。

同一個助理可以擁有多個話題。助理設定共用，話題歷史彼此獨立。完整說明請參閱[助理庫](../cherrystudio/preview/selection-assistant.md)。

## Temperature、Top P 與輸出參數

Temperature 與 Top P 常用於調整產生內容的隨機性與候選範圍，但不同模型與服務商的實作不完全相同。部分推理模型會忽略、限制或固定這些值。

一般建議：

* 事實擷取、格式轉換與程式碼修改，優先保留穩定的預設值。
* 創意寫作可以適度增加多樣性。
* 不要同時大幅調整多個參數，再判斷單一參數的效果。
* 參數報錯時恢復預設值，並查看目前模型的官方說明。

最大輸出長度限制模型本次可產生的內容，不會擴大輸入上下文。輸出突然中斷時，應同時檢查輸出上限、服務商限制與請求是否逾時。

## 推理模型

推理模型會在回答前進行額外計算，適合多步驟分析、數學、規劃與複雜程式碼任務。推理通常代表更多等待時間或費用。

需要注意：

* 介面顯示「思考」不代表所有模型都以相同方式回傳推理內容。
* 隱藏推理過程不等於模型沒有推理。
* 推理能力強不代表事實一定正確。
* 簡單任務不一定需要最高推理強度。

選擇模型時，應綜合評估任務準確率、速度、價格與工具相容性。

## 工具呼叫

模型不會因為「知道某個網站」就能自動存取該網站。工具呼叫通常包含三個步驟：

1. 應用程式將可用工具與參數格式告訴模型。
2. 模型回傳結構化的工具呼叫請求。
3. Cherry Studio 或對應 Server 執行工具，再將結果回傳給模型。

因此，工具可能在不同位置失敗：

* 模型沒有選擇工具。
* 模型產生了錯誤參數。
* 使用者拒絕授權。
* 工具程式或遠端服務失敗。
* 工具結果過大或格式異常。

「模型在文字中說會搜尋」不等於實際呼叫。應查看訊息中的工具記錄或[呼叫鏈](../advanced-basic/diao-yong-lian-shi-yong-shuo-ming.md)。

## 連網搜尋

連網搜尋可能來自：

* 模型服務商的原生搜尋能力。
* Cherry Studio 設定的搜尋服務。
* MCP 提供的搜尋工具。

搜尋通常會先回傳候選網頁，再讀取部分內容並交給模型。存在引用連結，不代表引用內容一定支持模型結論；還要檢查發布時間、原始來源與引用內容。

設定方式請參閱[連網模式](../websearch/README.md)。

## 多模態

多模態模型可以處理文字以外的輸入，例如圖片、音訊或檔案。不同能力應分別判斷：

| 能力 | 說明 |
| :--- | :--- |
| 視覺理解 | 讀取圖片並回答問題 |
| 圖片產生 | 根據提示建立或編輯圖片 |
| 檔案輸入 | 接收 PDF、文件或其他檔案 |
| 音訊理解 | 接收並分析音訊 |

模型支援視覺，不代表支援圖片產生；能讀取圖片也不代表能讀取所有檔案格式。

Cherry Studio 的能力標籤用於控制介面與請求路由。手動修改標籤不會改變服務商的實際介面，修改後應完成最小測試。

## 幻覺

「幻覺」是指模型產生了流暢但缺乏依據、與輸入不符或事實錯誤的內容。常見原因包括：

* 問題缺少關鍵上下文。
* 模型使用了訓練時的舊資訊。
* 檢索結果不相關或來源不可靠。
* 長上下文中的關鍵資訊被忽略。
* 使用者要求模型必須給出答案，使模型不願保留空缺。

降低風險的方法：

* 要求來源、日期與輸入位置。
* 區分事實、推論與假設。
* 允許回答「不確定」。
* 人工抽查關鍵資料。
* 高風險決策由專業人員複核。

連網與知識庫可以提供新資料，但不會自動消除幻覺。

## Embedding

Embedding 模型會將文字轉換成一組數字，也就是向量。語意相近的文字在向量空間中通常更接近，因此可用於相似度檢索。

Embedding 模型不是聊天模型。它通常回傳向量，不會產生自然語言回答。

### 維度

維度是向量中數字的數量。同一個知識庫在建立索引與查詢時，需要使用相容的模型與維度。更換模型或維度後，舊向量通常需要重建。

維度更大不代表一定更準確。還應考量語言、文字類型、輸入上限、速度、費用與實際召回效果。

詳細說明請參閱[嵌入模型](../knowledge-base/emb-models-info.md)。

## 分塊與向量檢索

建立知識庫時，長篇文件會先分成較小片段，再分別產生向量。

分塊過大可能會：

* 包含太多主題。
* 超過 Embedding 輸入上限。
* 讓回傳片段占用過多上下文。

分塊過小可能會：

* 遺失句子之間的關係。
* 產生大量索引與請求。
* 只召回局部詞句而缺少解釋。

重疊用於保留相鄰片段的部分上下文，但會增加索引數量。最佳值取決於文件結構與問題類型，應透過召回測試選擇。

## Rerank

向量檢索會先找出一批候選片段，Rerank 模型再依目前問題重新排序。它可以改善候選順序，但無法修復：

* 原文中沒有答案。
* 文件擷取錯誤。
* 候選階段完全沒有找回相關片段。
* 最終聊天模型誤解了正確片段。

Embedding 與 Rerank 是兩種能力，不能互換。

## RAG

RAG 是 Retrieval-Augmented Generation，也就是「檢索增強產生」。在 Cherry Studio 知識庫中，可以概括為：

1. 文件擷取與分塊。
2. 使用 Embedding 建立索引。
3. 使用者問題產生查詢向量。
4. 檢索相似片段。
5. 選用 Rerank 重新排序。
6. 將片段作為上下文交給聊天模型。
7. 聊天模型產生回答。

檢索正確但回答錯誤時，應檢查聊天模型與提示詞；檢索本身錯誤時，應檢查資料、分塊、Embedding 與 Rerank。完整流程請參閱[知識庫教學](../knowledge-base/knowledge-base.md)。

## MCP

MCP（Model Context Protocol）用於讓 AI 應用程式以統一方式連接外部能力。Server 可以提供：

* **Tools**：執行查詢、寫入或呼叫 API。
* **Prompts**：提供可重複使用的提示範本。
* **Resources**：提供可讀取的內容。

MCP 是通訊協定，不是安全沙箱。STDIO Server 可能以目前使用者權限在本機執行，遠端 Server 會收到傳送給它的資料。安裝前應檢查來源、命令、參數、環境變數與存取範圍。

使用方式請參閱 [MCP](../advanced-basic/mcp/)。

## 技能

技能是一組供 Agent 使用的任務說明、流程與資源。它主要告訴 Agent「如何完成某一類工作」，而 MCP 主要提供「可以呼叫什麼」。

技能本身也可能引用指令碼、範本或工具。安裝前請閱讀 `SKILL.md` 與附帶檔案，只啟用可信來源。詳細說明請參閱[技能](../pre-basic/settings/skills.md)。

## 助理與 Agent

| | 助理 | Agent |
| :--- | :--- | :--- |
| 核心用途 | 持續對話與固定設定 | 在目標與權限下執行多步驟任務 |
| 本機工作目錄 | 不提供 Agent 式目錄權限 | 可以限制可存取目錄 |
| 檔案與命令工具 | 透過特定 MCP 等擴充 | 可以使用內建工具、MCP 與技能 |
| 適合情境 | 寫作、問答、知識庫檢索 | 修改檔案、執行命令、完成工作流程 |

需要判斷使用哪一個時，請參閱[概念入門](../advanced-basic/concepts-101.md)。

## 本機模型與雲端模型

### 雲端模型

請求會傳送到服務商。優點通常包括不需在本機部署、模型選擇多；但需要考量網路、帳戶、費用、地區與服務商資料政策。

### 本機模型

模型推理會在自己的裝置或區域網路服務中執行，可以減少傳送到外部的模型請求，但需要足夠的記憶體、顯示記憶體、儲存空間與運算能力。

「使用本機模型」不代表整個工作流程完全離線。下列環節仍可能存取外部服務：

* 連網搜尋。
* 遠端 MCP。
* 雲端 Embedding 或 Rerank。
* 雲端文件處理器。
* 圖片產生、頻道與第三方整合。

評估隱私時，應沿著完整資料流逐項檢查，而不是只看聊天模型所在位置。

本機模型設定請參閱 [Ollama](../pre-basic/providers/ollama.md) 與 [LM Studio](../pre-basic/providers/lm-studio.md)。

## 費用從哪裡產生

可能產生費用的環節包括：

* 聊天模型輸入、輸出與推理 Token。
* 圖片、音訊或檔案處理。
* Embedding 與 Rerank 請求。
* 圖片產生。
* 搜尋、文件處理器、MCP 或其他第三方 API。
* 雲端儲存與網路流量。

同一任務使用多模型並行、反覆重試、長上下文與高頻排程任務，都會增加用量。Cherry Studio 顯示的估算無法取代服務商帳單。

## 資料與隱私

在單次工作流程中，資料可能經過：

```text
使用者輸入
→ Cherry Studio
→ 文件處理 / 搜尋 / 知識庫 / MCP
→ 模型服務商
→ Cherry Studio 顯示或本機檔案
```

實際路徑取決於啟用的能力。使用前請檢查：

* 資料是否離開裝置。
* 由哪個服務處理。
* 是否會儲存請求或用於訓練。
* 憑證儲存在哪裡、具有多大權限。
* 日誌、備份與截圖是否包含敏感資訊。

不要將 API Key、Token、密碼、私鑰或不必要的個人資料放入提示詞、知識庫與文件。高度敏感資料應先去識別化，並選擇符合組織政策的模型與工具。

## 建議學習順序

1. 先理解模型、服務商、Token 與上下文。
2. 在[對話介面](../cherrystudio/preview/chat.md)完成一個小型任務。
3. 使用助理儲存穩定提示詞。
4. 建立知識庫並進行召回測試。
5. 需要外部工具時再學習 MCP。
6. 需要本機檔案與多步驟執行時，再使用 Agent 與技能。

遇到概念以外的實際故障，請從[常見問題](questions.md)開始排查。
