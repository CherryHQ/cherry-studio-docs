# WebDAV Backup

Cherry Studio V2 can save backup files to a cloud drive, NAS, or self-hosted server that supports WebDAV. You can create backups manually or run automatic backups on a fixed schedule with a retention limit.

Here, WebDAV is a storage channel for creating and restoring backup files; it is not real-time, bidirectional synchronization between devices. Restoring overwrites current data and does not merge conversations created separately on each device.

{% hint style="warning" %}
WebDAV backups may contain conversations, provider configurations, and other sensitive information. Use a private directory and an app-specific password. Do not share credentials or backup files publicly.
{% endhint %}

## Prepare Connection Details

Obtain the following from your WebDAV provider or server administration page:

| Field | What to enter |
| --- | --- |
| WebDAV URL | The WebDAV service endpoint, usually a complete URL that includes `https://` |
| WebDAV Username | The account name, email address, or dedicated WebDAV username assigned by the provider |
| WebDAV Password | A regular password or an app-specific password generated by the provider |
| WebDAV Path | The remote directory where Cherry Studio stores backups |

Address and authentication requirements differ between services. A normal web sign-in address is not necessarily a WebDAV URL. After enabling two-factor authentication, you will usually need an app-specific password instead of your account sign-in password.

The default remote path is `/cherry-studio`. If the target directory does not exist, Cherry Studio tries to create it recursively during the first upload. Use a dedicated Cherry Studio directory so the backup manager does not mix backups with other files.

{% hint style="info" %}
Cherry Studio V2 also has a separate **Nutstore** backup page. Use that entry to connect through Nutstore account authorization. Use this page only when you need to enter general WebDAV parameters manually.
{% endhint %}

## Configure WebDAV in Cherry Studio

1. Open **Settings > Data Settings > WebDAV**.
2. Enter the **WebDAV URL**, keeping the `http://` or `https://` scheme.
3. Enter the **WebDAV Username** and **WebDAV Password**.
4. Enter a remote path, such as `/cherry-studio`.
5. Keep **Automatic Backup** turned off temporarily.
6. Click **Back Up to WebDAV** and use the default filename to create a test backup.
7. After the upload finishes, click **Restore from WebDAV** and confirm that the backup manager lists the new file.

The current page has no separate connection test button. A successful test upload that reappears in the backup manager verifies the URL, authentication, directory creation, and write permission.

Using a small data set without sensitive attachments makes test failures easier to diagnose. After confirming the connection, decide whether to enable complete backups and automatic backup.

## Create a Manual Backup

Clicking **Back Up to WebDAV** displays a default filename containing the time, host name, and device type. You can change the name. If it does not end in `.zip`, Cherry Studio adds the extension automatically.

Enabling **Compact Backup** skips images, knowledge base files, and other file data in the app's `Data` directory, retaining only chat history, settings, and similar content. It is not an incremental backup and cannot recover the skipped files.

After a manual backup finishes, the remote directory contains an independent ZIP file. Do not quit the app, disconnect the network, or let the system sleep during upload.

## Configure Automatic Backup

**Automatic Backup** supports:

- Off;
- 1, 5, 15, or 30 minutes;
- 1, 2, 6, 12, or 24 hours.

Complete a manual test before selecting a schedule. Higher frequency creates more remote requests and storage writes. Large complete backups generally do not need to run every few minutes.

The page displays the last backup time or the latest error. “Waiting for next backup” means there is no successful record yet; it does not prove that the connection is valid.

### Control Retention

**Maximum Backups** can be Unlimited, 1, 3, 5, 10, 20, or 50.

Automatic cleanup applies only to backups created by the current device with the default naming convention. Cherry Studio identifies the current device from the host name and device type in the filename, then deletes older files beyond the limit.

A custom filename without the current device identifier may not be cleaned up automatically. Unlimited also does not actively free remote storage. Open the backup manager periodically to check usage.

## Manage and Restore Backups

Click **Restore from WebDAV** to open the backup manager. From here, you can:

- View filenames, modification times, and sizes.
- Refresh the remote file list.
- Select a backup to restore.
- Delete one backup or delete several at once.

Before restoring:

1. Create a new backup of the current device.
2. Verify the target version by filename, modification time, and size.
3. Confirm that no other device is writing to the same directory.
4. Click **Restore** and confirm that current data will be overwritten.

The app may restart automatically after restoration. Deleting backups cannot be undone, so review selected files before a bulk delete.

{% hint style="warning" %}
Several devices can read the same remote directory, but restore does not merge data. To use Device A's data on Device B, first back up B, then restore the target version from A.
{% endhint %}

## When to Enable “Disable Streaming Upload”

By default, Cherry Studio uploads backups as a stream, which suits large files and uses less memory.

Some WebDAV services are incompatible with chunked or streaming upload. Small files may succeed while large backups fail, or the server may return an error related to request length or `chunked` transfer. In that case, enable **Disable Streaming Upload** and try again.

When enabled, Cherry Studio reads the entire backup file into memory before upload:

- Memory usage approaches the backup file size.
- A large backup can noticeably slow down the app.
- Use this only as a compatibility workaround; do not enable it by default.

If the upload still fails, check the server's single-file size, request body, and timeout limits instead of repeatedly increasing backup frequency.

## Security Recommendations

- Prefer `https://` on public networks to avoid sending passwords and backups over plain HTTP.
- Create a dedicated account or app-specific password for Cherry Studio and grant only the permissions needed for the target directory.
- Do not show private information from the full URL, username, or password in screenshots, feedback, or shared configurations.
- Do not restore ZIP files from unknown sources.
- Periodically verify that at least one complete backup can be listed and recognized.

## FAQ

### Backup reports unauthorized, 401, or 403

Confirm that the username and password are WebDAV credentials rather than a normal website sign-in. If the service uses two-factor authentication, use an app-specific password. Also confirm that the account can create directories and write files at the target path.

### The server returns 404 or reports a missing path

Confirm that you entered the WebDAV service endpoint, not a cloud drive home page or file-sharing link. Change the path to a simple directory that begins with `/`, such as `/cherry-studio`, then test with a manual backup.

### Files can be listed, but a large backup fails to upload

First check the server's single-file size, reverse proxy request body, and timeout limits. If the error involves chunked upload, enable **Disable Streaming Upload**. Reserve enough memory for the complete backup when using this option.

### Automatic backup does not run

Confirm that the schedule is not Off, the WebDAV URL is not empty, and review the backup status at the bottom of the page. A scheduled backup cannot finish while the computer sleeps, the network is disconnected, or the service is unavailable.

### Old files remain after reaching the maximum backup count

Automatic cleanup filters files by the current device identifier. Files renamed manually, created by another device, or not following the default naming format may remain and must be deleted manually in the backup manager.

### New local conversations disappeared after restoring from another computer

Restore is an overwrite operation, not a data merge. Before migrating between devices with a remote backup, back up each device separately and restore only a verified target version.

If the issue persists, submit your Cherry Studio version, operating system, redacted URL and path, HTTP status code, and complete error message through [Feedback and Suggestions](../question-contact/suggestions.md).
