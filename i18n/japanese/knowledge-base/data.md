# 知識ベースデータ

本ページでは、Cherry Studioが知識ベースデータをどこに保存しているか、モデルプロバイダーにどのようなコンテンツが送信される可能性があるか、また、そのデータを安全に削除、バックアップ、移行する方法について説明します。

知識ベースの作成と利用のみを行いたい場合は、[知識ベースチュートリアル](knowledge-base.md)から始めてください。

## 知識ベースが保存するもの

V2の知識ベースデータは、単独でコピーできる単一のファイルではありません。複数の種類のデータが組み合わさって構成されています。

| データ | 主な内容 | 用途 |
| --- | --- | --- |
| 知識ベースメタデータ | 名前、グループ、モデル、チャンキング、検索設定 | アプリケーションが知識ベースを識別し管理できるようにする |
| データソースレコード | 元のパスまたはURL、タイプ、ステータス、エラー情報 | 取り込んだコンテンツと処理の進捗を追跡する |
| ベクトルインデックス | ドキュメントの抜粋、ベクトル、検索フィールド | 検索テストやチャットでの検索をサポートする |
| ファイルレコードおよび処理アーティファクト | 元のファイル参照、解析されたテキスト、関連データ | ソースプレビュー、再インデックス作成、ドキュメント処理をサポートする |

メタデータとデータソースレコードは、Cherry StudioのメインSQLiteデータベースに保存されます。各知識ベースには独自のローカルなlibSQLベクトルストアファイルもあります。

{% hint style="warning" %}
知識ベースのベクトルファイルのみをバックアップしないでください。ベクトルファイルは、メインデータベース内の知識ベースID、データソースレコード、およびモデル設定と一貫している必要があります。単独でリストアしても、完全な知識ベースが再現されないことがほとんどです。
{% endhint %}

## ローカルファイルはコピーされますか？

ローカルファイルを知識ベースに追加すると、Cherry Studioはそのファイルの**元の絶対パス**を記録し、ファイルレコードを通じて関連付けます。元のファイルは既存の場所に留まり、知識ベースに追加されても移動しません。

これにはいくつかの直接的な影響があります。

* 元のファイルを移動、名前変更、または削除すると、プレビューや再インデックス作成が失敗する可能性があります。
* 既存のベクトルインデックスは、元のファイルが変更されても自動的には更新されません。
* 元のファイルを変更した後は、知識ベースから手動で再インデックス化する必要があります。
* Cherry Studioデータをバックアップする場合、外部の元のファイルは別途バックアップする必要があります。

ファイルプロセッサによって生成された中間アーティファクトはCherry Studio独自のデータディレクトリに保存されることがありますが、これは元のファイルの長期的なバックアップに代わるものではありません。

## データ保存場所

知識ベースデータは、Cherry Studioのユーザーデータディレクトリに保存されています。デフォルトの場所は通常以下の通りです。

| システム | デフォルトのユーザーデータディレクトリ |
| --- | --- |
| macOS | `~/Library/Application Support/CherryStudio` |
| Windows | `%APPDATA%\CherryStudio` |
| Linux | `~/.config/CherryStudio` |

実際のディレクトリは、インストール方法、アプリのバージョン、開発環境、またはカスタムデータディレクトリによって異なる場合があります。**設定 → データ → データディレクトリ**に表示されている現在のパスを正確な情報として使用してください。

知識ベースに直接関連する一般的なV2コンテンツには以下が含まれます。

* ユーザーデータディレクトリのルートにある `cherrystudio.sqlite`: 知識ベースおよびデータソースメタデータ
* `Data/KnowledgeBase`: 知識ベースごとに整理されたベクトルストアファイル
* `Data/Files`: Cherry Studioによって管理されるファイルと処理アーティファクト

{% hint style="info" %}
これらの内部パスは、バックアップの範囲を明確にするために提供されています。アプリが実行中の間は、手動でファイルを変更しないでください。データディレクトリ全体を変更するには、[ストレージの場所の変更](../personalization-settings/storage.md)を参照してください。
{% endhint %}

## どのコンテンツがデバイスから送信されますか？

「知識ベースはローカルに保存される」ということは、「すべての処理ワークフローがローカルで実行される」という意味ではありません。コンテンツが外部サービスに送信されるかどうかは、選択するプロセッサとモデルによって異なります。

### ドキュメント処理

オンラインのドキュメント解析またはOCRサービスを使用する場合、元のファイルまたはそのコンテンツが対応するプロバイダーに送信される可能性があります。ローカルプロセッサを使用する場合は、このステップをデバイス上に留めることができます。

### インデックス作成

オンラインの埋め込みモデルを使用する場合、チャンク化されたテキスト抜粋は埋め込みプロバイダーに送信され、返されたベクトルはローカルに保存されます。再インデックス作成では、再度埋め込みサービスが呼び出されます。

### 検索とリランキング

知識ベースを照会する場合、ユーザーの質問は埋め込みモデルによって処理されます。オンラインのリランキングモデルが有効な場合、質問と候補抜粋もリランキングプロバイダーに送信されます。

### 回答生成

チャットで知識ベースを使用する場合、ユーザーの質問と検索された抜粋がコンテキストとして現在のチャットモデルに送信されます。

### ウェブページインポート

URLまたはサイトマップをインポートする場合、Cherry Studioはターゲットウェブサイトにアクセスします。そのサーバーはIPアドレス、アクセス時刻、リクエストの詳細を記録する可能性があります。

{% hint style="warning" %}
契約書、医療情報、内部コードなどの機密性の高い資料を処理する前には、ドキュメント処理、埋め込み、リランキング、チャットモデルの4つのすべての段階を確認してください。チャットモデルのみをローカルモデルに切り替えても、他の段階で外部へのリクエストがないことを保証するものではありません。
{% endhint %}

## 外部送信データを減らす方法

ソースをサードパーティに送信できない場合は、以下の手順を実行してください。

1. ローカルのドキュメント解析およびOCR機能を使用します。
2. Ollama、LM Studio、または類似のツールを通じてローカル埋め込みモデルを実行します。
3. オンラインのリランキングモデルは有効にしないか、ローカルサービスに置き換えます。
4. チャットステージにはローカルモデルを選択します。
5. 認証が必要な内部ウェブページのインポートを避けます。

ローカルモデルの設定については、[埋め込みモデル](emb-models-info.md)および関連するモデルプロバイダーガイドを参照してください。

## データを削除するとどうなりますか？

### データソースの削除

データソースを削除すると、Cherry Studioはそのレコードとベクトル抜粋を削除します。フォルダまたはサイトマップの場合、展開された子アイテムも処理されます。

知識ベースからファイルデータソースを削除しても、**元のファイルがディスクから削除されるわけではありません**。

### チャンクの削除

個別の抜粋をチャンク詳細から削除すると、その抜粋の検索データのみが削除され、元のファイルは変更されません。後でデータソースを再インデックス化した場合、現在のチャンキングルールに従って削除された抜粋が再度生成される可能性があります。

### 知識ベース全体の削除

知識ベースを削除すると、Cherry Studioはまず関連するバックグラウンドタスクを停止し、次にメインデータベースからそのベクトルストアとレコードを削除します。

この操作では、インポート時に参照された外部の元のファイルは削除されませんが、知識ベースの設定と既存のインデックスは削除されます。削除する前に、復元可能な完全なバックアップがあることを確認してください。

## 知識ベースのバックアップ

### 推奨される方法

1. **設定 → データ**から組み込みのバックアップ機能を使用します。
2. 完全な知識ベースをリストアする必要がある場合は、**ファイルデータのスキップ**を有効にしないでください。
3. すべての外部元のファイルとフォルダは個別にバックアップしてください。
4. 使用したモデルプロバイダー、埋め込みモデル、ドキュメントプロセッサを記録します。
5. 安全な環境で、バックアップがリストアできることを定期的に検証します。

組み込みのバックアップオプション「ファイルデータのスキップ」は、ユーザーデータディレクトリ内の`Data`コンテンツを除外します。このコンテンツには、Cherry Studioによって管理される知識ベースのベクトルファイルや処理アーティファクトが含まれるため、このオプションで作成されたバックアップは完全な知識ベースのバックアップではありません。

### データディレクトリ全体のコピー

ファイルレベルのスナップショットを作成するには、`Data/KnowledgeBase` のみをコピーするのではなく、Cherry Studio を完全に終了してから**ユーザーデータディレクトリ全体**をコピーしてください。

アプリが実行中の場合、SQLiteデータベースやベクトルファイルへの書き込みが行われている可能性があります。アクティブなファイルを直接コピーすると、一貫性のないスナップショットになる可能性があります。

### リストア後の確認事項

リストア後、知識ベースの名前が表示されているかだけを確認しないでください。以下の点も確認してください。

* データソース一覧を開き、ステータスとカウントを確認する
* いくつかのソースをプレビューする
* 固定の質問セットで検索テストを実行する
* チャット内で引用されたソースを確認する
* 更新が必要な外部ファイルを再インデックス化する

オペレーティングシステム間またはメジャーバージョン間で移動した場合、あるいは埋め込みモデルを変更した後は、環境のコピーでまずリストアを検証してください。デバイス間で外部ファイルのパスが変更されると、元のパスへの参照が機能しなくなる可能性があります。

## 移行とディスク容量

知識ベースのディスク使用量は主に以下に依存します。

* 元のソースと処理アーティファクトのサイズ
* チャンクの数
* 埋め込みベクトルの次元数
* 知識ベースの数
* 反復的なインポートや再インデックス作成によって生成されたデータ量

データディレクトリを移動するには、Cherry Studioのデータディレクトリ設定を使用し、移行前に必ずバックアップを完了してください。移行後には、少なくとも1つのデータソースプレビュー、検索テスト、およびチャットでの引用を確認してください。

ディスク容量を空けるだけでよい場合は、まずアプリ内から未使用のデータソースや知識ベースを削除してください。内部データベースファイルを直接削除しないでください。

## よくある質問

### 知識ベースを削除しても元のファイルは残りますか？

はい。知識ベースが参照する外部ローカルファイルは、知識ベースと一緒に削除されません。削除されるのは、Cherry Studioによって管理されているレコードとインデックスのみです。

### 元のファイルを移動した後も検索は続けられますか？

既存のインデックスは一時的に古い抜粋を返し続けるかもしれませんが、元のパスが無効なため、プレビューや再インデックス作成は失敗します。新しいパスからファイルを再度追加し、検索結果を確認してください。

### `Data/KnowledgeBase`のみをバックアップできますか？

いいえ。そのディレクトリにはベクトルストレージしか含まれていません。メインデータベースからのメタデータやデータソースの関連性が欠けており、外部の元のファイルも含まれません。

### ローカル埋め込みモデルはすべてを完全にオフラインにしますか？

必ずしもそうとは限りません。ドキュメントプロセッサ、リランキングモデル、チャットモデルがローカルで実行されること、および外部ウェブページがインポートされたかどうかを確認する必要があります。

### インデックスの再構築に料金はかかりますか？

使用量ベースのオンラインドキュメント処理、埋め込み、またはリランキングサービスを使用する場合、再インデックス作成によって再度モデル呼び出し料金が発生する可能性があります。
