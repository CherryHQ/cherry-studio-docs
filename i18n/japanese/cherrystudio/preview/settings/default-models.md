# デフォルトモデル設定

Cherry Studio の各機能は、個別にモデルが指定されていない場合、デフォルトモデルを使用します。V2 では現在、**デフォルトアシスタントモデル**、**クイックモデル**、**翻訳モデル**という 3 つのグローバルロールが用意されています。

これらは同じモデルを選択することも、品質、速度、コストに応じて個別に設定することもできます。

## 使用前の準備

デフォルトモデル設定に進む前に、以下の点を確認してください。

1. **設定 → モデルサービス**で少なくとも 1 つのプロバイダーを設定していること。
2. ターゲットモデルがそのプロバイダーに追加されていること。
3. プロバイダーとモデルの両方が有効になっていること。
4. 接続テストまたは実際の会話で、対象モデルが利用できることを確認済みであること。

設定方法は[モデルサービスの設定](providers.md)を参照してください。

{% hint style="info" %}
デフォルトモデルのセレクターには、有効なプロバイダーに属する有効なモデルだけが表示されます。埋め込み、リランキング、画像生成専用のモデルは表示されません。対象モデルが見つからない場合は、まずモデルサービスに戻り、有効状態と機能タグを確認してください。
{% endhint %}

## モデル設定を開く

移動先：

> **設定 → モデル**

ページには 3 つのモデルセレクターがあり、各項目の右側にそのロールの追加設定が表示される場合があります。

## 3 つのデフォルトモデル

| ロール | 主な用途 | 選定のポイント |
| --- | --- | --- |
| デフォルトアシスタントモデル | アシスタントがモデルを個別に指定しない場合の対話モデル | 安定性、指示追従性、日常的なコスト |
| クイックモデル | トピック名付け、ノート要約、一部の軽量な内部タスク、LLM 言語検出 | 高速応答、簡潔な出力、低コスト |
| 翻訳モデル | 翻訳ページ、クイック翻訳、および統一翻訳サービスを呼び出すその他の機能 | 言語カバレッジ、忠実度、フォーマット保持 |

## デフォルトアシスタントモデル

### いつ使用するか

アシスタントの実際のモデルの優先順位は通常以下の通りです：

1. 現在のアシスタントで明示的に選択したモデル；
2. アシスタント自身に保存されているデフォルトモデル；
3. グローバルなデフォルトアシスタントモデル。

したがって、グローバルデフォルトモデルを変更しても、個別に選択されたすべてのモデルを強制的に置き換えるわけではありません。

### 選び方

日常的な使用においては、以下の点を優先して考慮すると良いでしょう：

- テキスト対話の安定性；
- システムプロンプトに従う能力；
- 一般的なタスクに必要なコンテキスト長を満たしていること；
- 現在のアカウントのクォータと遅延が許容できること；
- MCP、インターネット接続、またはエージェントを頻繁に使用する場合は、モデルがツール呼び出しをサポートしていること。

モデル名のみに基づいて能力を手動でタグ付けしないでください。ビジョン、ネイティブなインターネット接続、ツール呼び出しなどの機能は、サーバー側で実際にサポートされているものと一致する必要があります。

### デフォルトアシスタントの追加設定

右側の設定ボタンをクリックすると、デフォルトアシスタントの以下の項目を変更できます：

- 名前とアイコン；
- システムプロンプト；
- Temperature；
- Top P；
- コンテキストメッセージ数；
- 最大出力トークン；
- ツール呼び出しモード。

これらのパラメータはデフォルトアシスタント設定を使用する場面に適用されます。既存の各アシスタントに保存された個別設定を自動で上書きするものではありません。

{% hint style="warning" %}
Temperature と Top P を同時に調整すると、出力を予測しにくくなる場合があります。明確な要件がなければ、まずデフォルト値のまま使用してください。最大出力トークンも、サーバー側モデルの実際の上限を超えないようにします。
{% endhint %}

## クイックモデル

クイックモデルは、メインのチャットモデルの全機能を必要としないバックグラウンド処理や軽量タスクを担当します。例えば：

- 直近の会話内容に基づいてトピック名を生成する；
- ノートの内容から短いタイトルや要約を生成する；
- 翻訳機能で LLM 検出を選択した際にソース言語を識別する；
- アプリケーションがクイックモデルを呼び出す内部プロセスなど。

### 選択ガイドライン

クイックモデルは以下のような場合に適しています：

- 初回応答が速い；
- 短いテキストの指示への追従が安定している；
- 短い結果を確実に出力できる；
- 単一呼び出しのコストが低い；
- 複雑なツールや超長コンテキストに依存しない。

最も速いモデルが必ずしも最適とは限りません。トピック名が頻繁に内容からずれる、言語認識が不安定、または出力に説明文が混入する場合は、より信頼性の高い軽量モデルに変更できます。

### トピック名設定

クイックモデルの右側にある設定ボタンをクリックすると、以下の操作が可能です：

- 自動トピック名のオン/オフ切り替え；
- トピック名生成プロンプトの変更；
- デフォルトプロンプトへの復元。

自動トピック名をオフにした場合、アプリケーションはクイックモデルを呼び出して名前を生成する代わりに、最初のメッセージのテキストをトピック名として使用しようとします。

カスタムプロンプトを設定する際は、インターフェースの説明で必要な変数を保持する必要があります。変数を誤って削除したり、モデルに長文出力を要求したりすると、トピック名が不完全になる可能性があります。

### 翻訳言語検出との関係

翻訳ページの言語検出方法は、アルゴリズムまたは LLM を選択できます。LLM を選択した場合にクイックモデルが呼び出されます。

一部の翻訳専用モデルは言語検出に適していません。たとえば現在の実装では、Qwen-MT のようなモデルを使用した LLM 言語検出は実行できません。翻訳モデルに専用モデルを使用する場合でも、クイックモデルには通常のチャットモデルを選択してください。

## 翻訳モデル

翻訳モデルは、以下の用途に使用されます：

- 翻訳ページ；
- クイックアシスタントでの翻訳；
- テキスト選択ツールの翻訳操作；
- 統一翻訳サービスを呼び出すその他のエントリポイント。

クイック操作の入口については、[クイックアシスタント](../kuai-jie-zhu-shou.md)と[テキスト選択ツール](../selection-assistant.md)を参照してください。

### 選択の推奨事項

ご自身の言語組み合わせでテストを行ってください：

- 固有名詞が正しく保持されるか；
- Markdown、コード、プレースホルダーが意図せず書き換えられないか；
- 長文が翻訳漏れを起こさないか；
- マイナーな言語で安定しているか；
- 出力に説明や前置きが付加されないか；
- コストと応答速度が許容できるか。

通常のチャットモデルと専用の翻訳モデルの両方を使用できますが、能力とパラメータが異なります。ベンダーの宣伝文句だけに基づいて選択するのではなく、実際のテキストでテストを行うべきです。

### 翻訳追加設定

翻訳モデルの右側にある設定ボタンをクリックすると、以下の項目を変更できます：

- 翻訳プロンプト；
- カスタム言語名、コード、アイコン。

翻訳プロンプトが変更されると、ページに「元に戻す」ボタンが表示されます。この操作により、現在のカスタムプロンプトが置き換えられます。

翻訳プロンプト内のターゲット言語および原文変数は保持する必要があります。変数を削除すると、モデルがどの言語に翻訳すべきか分からない場合や、翻訳対象のテキストを受け取れない場合があります。

## 推奨設定方法

### シンプルさを追求する場合

3つのロールに同じ安定した汎用チャットモデルを使用します。利点は設定が少ないことです。欠点は、バックグラウンドタスクや翻訳も同じコストと速度を使用することです。

### コストと性能のバランスを取る場合

| ロール | 推奨 |
| --- | --- |
| デフォルトアシスタントモデル | 日常的に最も信頼できるメインのチャットモデル |
| クイックモデル | 安価で低遅延な軽量チャットモデル |
| 翻訳モデル | 対象言語の組み合わせで最高のパフォーマンスが確認されたモデル |

### プライバシーを重視する場合

ローカルモデルを選択できますが、以下の点を確認する必要があります。

- ローカルサービスが起動していること；
- モデルが Cherry Studio から接続可能であること；
- マシンメモリまたはVRAMが十分であること；
- 翻訳とトピック名の速度が許容できること；
- 関連機能が同時に外部ネットワークやサードパーティツールを呼び出さないこと。

## 変更後の確認

### デフォルトアシスタントモデル

1. 個別に固定されていないアシスタントまたはチャットを作成します。
2. 上部のモデル名を確認します。
3. 短いメッセージを送信します。
4. ツールが必要な場合は、追加でツール呼び出しテストを行います。

### クイックモデル

1. 自動トピック命名を有効にします。
2. トピックを新規作成し、少なくとも1ターンの対話を行います。
3. トピック名が更新されるのを待ちます。
4. 名前が簡潔で内容に関連しているか確認します。

LLM 言語検出を使用する場合は、翻訳ページに短いテキストを入力して認識結果を確認してください。

### 翻訳モデル

1. 翻訳ページを開きます。
2. 固有名詞、Markdown、またはコードを含むテストテキストを入力します。
3. 一般的なターゲット言語を選択します。
4. 訳文の完全性とフォーマットを比較します。
5. クイックアシスタントまたはテキスト選択ツールでも再度テストします。

## よくある質問

### セレクタにターゲットモデルがない場合

プロバイダーとモデルの両方が有効になっているか確認し、モデルが以下のいずれかにマークされていないことを確認してください。

- 埋め込み；
- リランキング；
- 画像生成専用。

これらのタイプは、3 つのデフォルトモデルセレクターには表示されません。

### 選択したモデルが後で空白になる場合

モデルが削除された、無効化された、プロバイダーが無効化された、またはモデルの一意の ID が移行後に変更された可能性があります。

[モデルサービス設定](providers.md) に戻ってモデルを再取得するか追加し、再度選択してください。

### デフォルトアシスタントモデルを変更した後も、既存のアシスタントに変更がない場合

これは正常な動作です。既存のアシスタントが独自のモデルを保存している場合、引き続きその選択を優先します。各アシスタントを手動で編集するか、個別のモデル設定をクリアする必要があります。

### 自動トピック名付けが機能しない場合

以下を確認してください。

- 自動トピック名付けが有効になっていること；
- クイックモデルが存在し、有効になっていること；
- クイックモデルのプロバイダーと API キーが利用可能であること；
- 会話に十分なメッセージが生成されていること；
- トピック名が手動で編集されていないこと；
- カスタムの命名プロンプトから必須変数が削除されていないこと。

### 翻訳モデルが見つからない場合

翻訳モデルを再選択してください。専用の翻訳モデルを使用している場合は、プロバイダーが特殊なパラメータやサポートする言語コードを要求していないか確認する必要があります。

### バックグラウンドタスクの費用が想定より多い場合

トピック名付け、ノート要約、LLM 言語検出、および翻訳はそれぞれ独立したリクエストを生成する可能性があります。クイックモデルをよりコストの低いモデルに変更するか、不要な自動トピック名付けや LLM 検出をオフにすることができます。

## データとセキュリティ

- デフォルトのモデル設定には API キーは含まれておらず、認証情報は引き続きモデルサービスによって管理されます。
- モデル呼び出しでは、処理対象のテキストが選択したプロバイダーに送信されます。
- トピック名付けには、直近のメッセージの本文が送信される場合があります。
- 翻訳では、翻訳対象のテキストが送信されます。
- 機密性の高いコンテンツを扱う場合は、プライバシー要件を満たすプロバイダーまたはローカルモデルを選択してください。

### ヘルプの取得とフィードバックの送信

デフォルトモデルが機能しない場合は、[フィードバックと提案](../../../question-contact/suggestions.md)に記載された公式窓口から報告してください。Cherry Studio のバージョン、3 つのモデルロールの選択内容、プロバイダー、モデル ID、機密情報を除いたエラーメッセージを添えることを推奨します。
