# ナレッジベース

ナレッジベースでは、文書やウェブページなどの資料を検索可能な参照ライブラリとして整理できます。チャット中、Cherry Studio は最初にナレッジベースから関連するチャンクを取得し、そのチャンクをモデルへ渡して回答を生成します。

ナレッジベースがモデルをトレーニングしたり変更したりすることはありません。繰り返し検索する場合、複数のチャットで資料を再利用する場合、資料の総量が多い場合に適しています。

{% hint style="info" %}
このページはナレッジベースのクイックスタートです。各パラメーターの詳細については、[ナレッジベースの完全ガイド](../../knowledge-base/knowledge-base.md)を参照してください。
{% endhint %}

## 使用前の準備

ナレッジベースを作成するには、**埋め込み（Embedding）**機能に対応するモデルを少なくとも 1 つ有効にする必要があります。埋め込みモデルは、資料と質問を検索可能なデータへ変換します。

事前に次の点を確認することをおすすめします。

* モデルプロバイダーの設定が完了し、埋め込みモデルを正常に呼び出せる
* スキャン版 PDF や複雑な文書に適した文書処理方法が設定されている
* 検索結果の順序をさらに最適化する必要がある場合は、リランキング（Rerank）モデルを用意する

参考：

* [埋め込みモデルの参考情報](../../knowledge-base/emb-models-info.md)
* [文書の前処理](../../knowledge-base/zhi-shi-ku-wen-dang-yu-chu-li.md)

## ナレッジベースを作成する

1. ランチパッドで **ナレッジベース** を開きます。
2. 左側の追加ボタンをクリックし、ナレッジベースの作成を選択します。
3. ナレッジベースの名前を入力します。
4. 必要に応じて、ナレッジベースを既存のグループに入れます。
5. 有効な埋め込みモデルを 1 つ選択し、作成を完了します。

{% hint style="warning" %}
埋め込みモデルとベクトル次元によって、ナレッジベースのインデックス形式が決まります。後でモデルまたは次元を変更する場合は、ナレッジベースを再構築する必要があります。そのため、資料を一括インポートする前に設定を確定することをおすすめします。
{% endhint %}

## 資料を追加する

ナレッジベースを開き、資料の追加をクリックしてソースを選択します。

| ソース | 適した内容 | 現在の説明 |
| --- | --- | --- |
| ファイル | 1 つまたは複数のローカルファイル | PDF、DOCX、MD、XLSX、TXT、CSV、EPUB に対応 |
| フォルダー | ローカル資料のまとまり | フォルダーを選択し、その中のファイルを一括インポート |
| URL | 単一のウェブページ | ウェブページのアドレスを入力し、ページ内容を抽出 |
| Sitemap | ウェブサイト内の複数のページ | Sitemap のアドレスを入力し、ウェブページを一括検出 |
| ノート | 手動で入力した内容 | 現在のバージョンでは、追加画面からまだ送信できません |

追加タスクを送信した後は、ダイアログを閉じてアプリを使い続けることができます。資料の読み取り、分割、埋め込みはバックグラウンドで継続します。

## インデックスの完了を待つ

資料は準備、読み取り、処理、埋め込みなどの段階を順番に進みます。ソースによって表示される中間状態が異なる場合がありますが、最終的に状態が**完了**になっていることを確認してください。

| 状態 | 意味 | 推奨する操作 |
| --- | --- | --- |
| 準備中／読み取り中／処理中／埋め込み中 | インデックスを作成中 | アプリを起動したまま待つ |
| 完了 | 検索とチャットで利用可能 | まず検索テストを 1 回行う |
| 失敗 | 現在の資料のインデックスが未完了 | モデル、ネットワーク、ファイルの問題を修正してから再インデックスする |
| 削除中 | 資料とインデックスを消去中 | 消去が完了するまで待つ |

安定して検索に使用できるのは、インデックス作成が完了した内容だけです。処理中の資料を強制的に再インデックスすることはできません。処理の完了または失敗を待ってから操作してください。

## 資料を確認・管理する

ナレッジベースのデータソースページでは、次の操作を行えます。

* ファイル、フォルダー、URL、Sitemap で絞り込む
* 資料名を検索し、準備完了した資料の数を確認する
* 抽出後の内容をプレビューする
* 資料を分割したチャンクを確認する
* 個別のチャンクを削除する
* 完了または失敗した資料を再インデックスする
* 複数の資料を選択し、一括で再インデックスまたは削除する

元のファイルが更新されている場合、再インデックスすると古いインデックスを新しい内容で置き換えられます。資料を削除すると、対応する検索データも非同期で消去されます。

## 最初に検索テストを行う

ナレッジベース上部で**検索テスト**を開き、実際にユーザーが入力しそうな質問を入力します。

テスト結果には、一致したチャンク、スコア、順位、所要時間が表示されます。特に次の点を確認してください。

* 正しい資料が上位の結果に含まれているか
* 取得されたチャンクに回答に必要な情報が含まれているか
* チャンクが長すぎる、短すぎる、または誤って分断されていないか
* 無関係な結果が多すぎないか

検索結果そのものが不正確な場合、通常はチャットモデルも信頼できる回答を生成できません。先に資料または検索設定を調整し、その後でチャットの効果を確認してください。

## チャットで使用する

### ナレッジベースを一時的に選択する

1. **チャット**を開き、チャットに入ります。
2. 入力ボックスのツールエリアでナレッジベース選択メニューを開きます。
3. 1 つまたは複数のナレッジベースを選択します。
4. 資料に関連する質問を入力します。

この入口は、現在のアシスタントとツールモードがナレッジベースに対応している場合にだけ使用できます。入力ボックスにファイルが添付されている場合、ナレッジベースの選択は無効になります。先に添付ファイルを削除してから、ナレッジベースを選択してください。

### アシスタントに固定する

同じ資料を継続的に使用するアシスタントでは、**アシスタントライブラリ → アシスタント**を開き、アシスタントを編集してナレッジベースを関連付けることができます。以後そのアシスタントを使用するときは、毎回選択し直す必要はありません。

その他のアシスタント設定については、[アシスタント](agents.md)を参照してください。

{% hint style="warning" %}
ナレッジベースは関連するチャンクを提供しますが、最終的な回答はチャットモデルによって生成されます。重要な結論は、引用されたチャンクと元の資料を照らし合わせて確認してください。
{% endhint %}

## RAG 設定を調整する

ナレッジベース上部の RAG 設定ボタンをクリックすると、検索処理を調整できます。

| 設定 | 役割 | 調整のヒント |
| --- | --- | --- |
| ファイルプロセッサー | 文書を分割可能なテキストに変換 | スキャン、画像、複雑なレイアウトでは、この項目を最初に確認 |
| チャンクサイズとオーバーラップ | 各検索チャンクの範囲を決定 | 変更後は既存の資料を再インデックスする必要があります |
| 埋め込みモデルと次元 | ベクトルインデックスを生成して保存 | 変更すると再構築または復元処理が開始されます |
| 検索モード | ベクトル検索、キーワード検索、ハイブリッド検索から選択 | まずデフォルトのハイブリッド検索を使用します |
| 結果数 | モデルへ返すチャンク数を制御 | 少なすぎると情報を見落とし、多すぎるとノイズが混入する可能性があります |
| 類似度のしきい値 | 関連性が不足する結果を除外 | 対応する検索モードでのみ有効です |
| ハイブリッドの重み | セマンティック一致とキーワード一致のバランスを調整 | 固有名詞が多い場合は、検索テストと組み合わせて調整できます |
| リランキングモデル | 最初の検索結果を再度並べ替え | モデル呼び出しが 1 回増え、待ち時間も長くなります |

一度に変更するパラメーターは 1 種類だけにし、同じ質問の組み合わせで検索テストを繰り返すことをおすすめします。これにより、どの調整が実際に効果をもたらしたかを判断しやすくなります。

## よくある質問

### 作成時に選択できる埋め込みモデルがない

モデルプロバイダーが有効か、モデルに埋め込み機能のマークがあるか、API 設定が利用可能かを確認してください。通常のチャットモデルは埋め込みモデルの一覧には表示されません。

### 資料が処理中のままになる／失敗と表示される

まず現在のタスクが終了するまで待ち、ネットワーク、モデルプロバイダー、ファイル形式、文書プロセッサーを確認します。問題を修正した後、失敗した資料を再インデックスしてください。

### スキャン版 PDF から有効なテキストを取得できない

スキャン版 PDF は通常、画像だけで構成されています。OCR または画像解析に対応した文書処理方法を使用する必要があります。[文書の前処理](../../knowledge-base/zhi-shi-ku-wen-dang-yu-chu-li.md)を参照してください。

### 正しい内容を検索できない

まず資料のインデックス作成が完了していることを確認し、検索テストを使って問題を特定します。元のテキストの品質、チャンクサイズ、検索モード、結果数、しきい値、リランキング設定を順番に確認してください。

### チャットでナレッジベースが使用されない

現在のチャットでナレッジベースが選択され、対象資料の状態が完了で、アシスタントとツールモードがナレッジベースに対応していることを確認してください。入力ボックスにファイルが添付されている場合は、先に添付ファイルを削除します。

## データ、プライバシー、料金

ナレッジベースのメタデータとベクトルインデックスは Cherry Studio が管理します。選択した文書処理、埋め込み、リランキング、チャットサービスに応じて、原文または抽出された内容が各プロバイダーへ送信される場合があります。回答時には、取得されたチャンクも現在のチャットモデルへ送信されます。

機密資料をインポートする前に、プロバイダーのデータポリシーと導入方法を確認してください。インデックスの作成、再インデックス、リランキング、チャット回答では、モデルの呼び出し料金が発生する場合もあります。

ナレッジベース関連のファイルと消去方法については、[ナレッジベースのデータ](../../knowledge-base/data.md)を参照してください。
