# S3 互換ストレージへのバックアップ

Cherry Studio V2 は、AWS S3、Cloudflare R2、Alibaba Cloud OSS、Tencent Cloud COS、Volcengine TOS、MinIO など、S3 互換 API を提供するオブジェクトストレージへバックアップを保存できます。

ここでの S3 はリモートバックアップ先であり、リアルタイム同期サービスではありません。復元すると選択したバックアップで現在のデータが上書きされ、別々のデバイスで追加した内容は統合されません。

{% hint style="warning" %}
バックアップには、チャット、プロバイダー設定、その他の機密情報が含まれる場合があります。Bucket は非公開にし、対象の Bucket またはディレクトリだけへアクセスできる専用の認証情報を使用してください。
{% endhint %}

## Bucket と認証情報を準備する

オブジェクトストレージのコンソールで次を行います。

1. 非公開の Bucket を作成または選択します。
2. Bucket の Region を確認します。
3. プロバイダーが提供する S3 API Endpoint を確認します。
4. Cherry Studio 専用のアクセス認証情報を作成します。
5. サービスが対応している場合は、Cherry Studio 用ディレクトリだけにアクセスできるよう認証情報を制限します。

Cherry Studio には少なくとも、オブジェクトの一覧表示、アップロード、読み取り権限が必要です。古いバックアップの自動削除や管理画面からの削除には、オブジェクトの削除権限も必要です。

権限名はサービスによって異なります。AWS IAM では `s3:ListBucket`、`s3:PutObject`、`s3:GetObject`、`s3:DeleteObject` が一般的です。他の互換サービスでは同等の権限を使用してください。

## 設定項目

**設定 > データ設定 > S3**を開き、次を入力します。

| フィールド | 説明 |
| --- | --- |
| API アドレス | プロバイダーが提供する S3 API Endpoint。`http://` または `https://` を含める |
| Region | Bucket の Region。プロバイダー指定の値を使用する |
| Bucket | Bucket 名。コンソール上の表示名やディレクトリ名ではない |
| Access Key ID | 専用アクセス認証情報の識別子 |
| Secret Access Key | Access Key ID と対になる秘密鍵 |
| バックアップディレクトリ | Cherry Studio のバックアップを分離するための任意のオブジェクト Key プレフィックス |

**バックアップディレクトリ**以外の項目は、手動バックアップとバックアップ管理画面を使用するために必須です。

### Endpoint に Bucket を重複して入力しない

Endpoint の形式はプロバイダーによって異なり、Region 単位、アカウント単位、独自サーバーのアドレスなどがあります。Cherry Studio は**Bucket**を独立したパラメーターとして S3 クライアントへ渡すため、プロバイダーの S3 SDK ドキュメントで明示されていない限り、アドレスへ Bucket を重複して追加しないでください。

コンソールの Web 管理アドレス、オブジェクトの公開 URL、S3 API Endpoint はまったく異なる場合があります。ブラウザーでファイルを開いた URL ではなく、「S3 互換 Endpoint」をコピーしてください。

Cherry Studio は Endpoint のドメインに応じて virtual-host または path-style のリクエストを選択します。

- Alibaba Cloud、Tencent Cloud、Volcengine の認識済み公式ドメインは virtual-host 形式
- `localhost`、IP アドレス、その他多くの互換サービスは path-style
- 解析できないアドレスは path-style へフォールバック

サービスが複数形式に対応する場合は、AWS SDK / S3 SDK ドキュメントに記載された Endpoint を優先してください。

### バックアップディレクトリを設定する

**バックアップディレクトリ**はオブジェクト Key のプレフィックスになります。`cherry-studio` または `/cherry-studio/` と入力でき、保存時に先頭と末尾の余分な `/` が削除されます。

Cherry Studio のデータセットごとに独立したプレフィックスを推奨します。例：

```text
cherry-studio/personal
```

バックアップ管理画面には、このプレフィックス配下にある `.zip` で終わるオブジェクトだけが表示されます。ディレクトリを変更しても、元のディレクトリのバックアップは自動移動せず、新しい一覧にも表示されません。

## 設定を検証する

現在の画面には独立した「接続テスト」ボタンがありません。最も完全な検証手順：

1. 必須項目をすべて入力し、自動バックアップを一時的にオフにします。
2. **今すぐバックアップ**をクリックします。
3. デフォルトのファイル名で小さなテストバックアップを作成します。
4. **バックアップを管理**をクリックします。
5. アップロードした ZIP、更新時刻、サイズが一覧に表示されることを確認します。

この手順で Endpoint、Region、Bucket、認証情報、バックアップディレクトリ、一覧表示と書き込み権限を同時に確認できます。Bucket は表示できるがアップロードできない場合は、通常オブジェクトの書き込み権限がありません。アップロードできるが表示されない場合は、プレフィックスまたは一覧表示権限を確認してください。

## 手動バックアップ

**今すぐバックアップ**をクリックすると、ファイル名を確認または変更できます。デフォルト名には時刻、ホスト名、デバイス種別が含まれ、`.zip` 拡張子がなければ自動で追加されます。

**コンパクトバックアップ**を有効にすると、アプリの `Data` ディレクトリ内の画像、ナレッジベースなどのファイルデータを除外し、チャット履歴や設定などだけを保存します。増分バックアップではなく、復元時に除外されたファイルを取り戻すことはできません。

S3 へのアップロード前にローカルで ZIP を作成し、そのファイルをメモリへ読み込んでから送信します。大きな完全バックアップはディスクとメモリの使用量を大幅に増やす場合があります。処理中にアプリを終了したり、ネットワークを切断したり、システムをスリープさせたりしないでください。

## 自動バックアップと保存数

**自動同期**は実際には定期バックアップを行います。選択できる間隔：

- オフ
- 1、5、15、30 分ごと
- 1、2、6、12、24 時間ごと

まず手動バックアップを成功させてから自動バックアップを有効にします。頻度が高いほど、リクエスト数、通信量、オブジェクトストレージの操作料金が増えます。

**最大バックアップ数**には、無制限、1、3、5、10、20、50 を設定できます。上限に達すると、Cherry Studio はデフォルトのファイル名に含まれるホスト名とデバイス種別を使い、現在のデバイスの古いバックアップを削除します。

次のオブジェクトは通常、自動削除されません。

- 別のデバイスからのバックアップ
- カスタムファイル名に現在のデバイス識別子がないバックアップ
- 現在のバックアップディレクトリ以外のオブジェクト
- `.zip` ではないオブジェクト

「無制限」を選ぶ場合は、オブジェクトストレージ側で容量アラートまたはライフサイクルルールを設定し、長期的な蓄積を防いでください。

## バックアップを管理、復元する

**バックアップを管理**をクリックすると、現在のディレクトリ配下の ZIP バックアップを表示、更新、復元、削除できます。

復元前：

1. 現在のデータをもう一度バックアップします。
2. ファイル名、更新時刻、サイズから対象バージョンを確認します。
3. 他のデバイスが同じディレクトリへ書き込んでいないことを確認します。
4. 対象ファイルの**復元**をクリックし、上書きを確認します。

復元後、アプリが自動的に再起動する場合があります。オブジェクトの削除は取り消せません。認証情報に削除権限がない場合、表示と復元は成功しても、削除と自動整理は失敗します。

{% hint style="warning" %}
複数のコンピューターで同じ Bucket とプレフィックスを共有できますが、復元でデータは統合されません。デバイス間を移行するときは、対象デバイスを先にバックアップし、元デバイスの確認済みバージョンを復元してください。
{% endhint %}

## セキュリティと費用に関する推奨事項

- 非公開 Bucket を使用し、バックアップディレクトリの公開読み取りを有効にしない
- 独立した最小権限の Access Key を使用し、クラウドアカウントのルート認証情報を入力しない
- スクリーンショット、ログ、フィードバックに Secret Access Key 全文を表示しない
- 公開 Endpoint では HTTPS を使用する。独自 MinIO にも信頼できる証明書を設定するか、信頼できるネットワーク内だけで使用する
- ストレージ容量、PUT / GET / LIST リクエスト、外向き通信の料金を確認する
- 鍵が漏えいしたら、Cherry Studio の値を変えるだけでなく、プロバイダーのコンソールで直ちに無効化して再作成する

## よくある質問

### 「今すぐバックアップ」ボタンが無効

API アドレス、Region、Bucket、Access Key ID、Secret Access Key がすべて入力されていることを確認します。バックアップディレクトリは空でもかまいません。

### 301、PermanentRedirect、Region 不一致が返る

Endpoint または Region が Bucket のリージョンと一致していません。オブジェクトストレージのコンソールに戻り、その Bucket 用の S3 Endpoint と正確な Region をコピーしてください。

### 403、AccessDenied、SignatureDoesNotMatch が返る

Access Key と Secret が正しい組み合わせで有効か、システム時刻が正しいかを確認します。Endpoint 形式、Region、最小権限ポリシーも確認してください。署名エラーはアドレスまたは Region の不一致でよく発生します。

### 独自 MinIO に接続できない

Endpoint に `https://minio.example.com:9000` のようなポートを含め、Cherry Studio のデバイスからアクセスできることを確認します。IP または `localhost` では path-style が使用されます。MinIO がリバースプロキシの背後にある場合は、証明書、リクエスト本文、タイムアウト制限も確認してください。

### アップロードできるが管理画面に表示されない

現在の**バックアップディレクトリ**がアップロード時と同じであること、認証情報に Bucket の一覧表示権限があることを確認します。管理画面には、現在のプレフィックス配下の `.zip` で終わるオブジェクトだけが表示されます。

### 最大バックアップ数を超えても古いファイルが残る

自動整理は、現在のデバイスかつデフォルトの命名規則に従うバックアップだけを認識します。カスタム名、別デバイス、別プレフィックスのオブジェクトは、手動削除またはストレージサービスのライフサイクルルールで処理してください。

### 大きなバックアップでメモリ使用量が増える

現在の S3 アップロードは、作成した ZIP をメモリへ読み込みます。**コンパクトバックアップ**でサイズを減らす、ナレッジベースや画像ファイルを減らす、データ量の少ない時間に実行する、といった方法があります。

解決しない場合は、[フィードバックと提案](../../question-contact/suggestions.md)から Cherry Studio のバージョン、ストレージサービス名、匿名化した Endpoint / Region / Bucket、HTTP ステータス、エラー全文を送信してください。
