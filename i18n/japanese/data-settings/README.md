# データ設定

**設定 → データ設定**では、アプリデータディレクトリ、インポートとエクスポートのオプション、キャッシュ、ログ、ノートサービスへの接続を管理できます。

{% hint style="warning" %}
現在、アプリ内の Backup & Restore V2 はまだ利用できません。データ、ローカルバックアップ、WebDAV、Nutstore、S3 の各ページには「Backup & Restore V2 はまだ利用できません」という通知が表示され、バックアップ関連の操作は無効です。重要なデータの保存や復元にこれらの入口を使用しないでください。
{% endhint %}

## ページの概要

| グループ | ページ | 現在の用途 |
| --- | --- | --- |
| データ | データ | アプリデータディレクトリの確認と移行、ログ表示、キャッシュ消去、データのリセット、プライバシー設定 |
| クラウドバックアップ | ローカルバックアップ、WebDAV、Nutstore、S3 | ページは表示されますが、バックアップ、復元、自動同期、認証情報の入力は現在利用不可 |
| インポート設定 | アプリデータをインポート | インポートメニューに表示する取得元を選択 |
| エクスポート設定 | エクスポートメニュー | 会話のエクスポートメニューに表示する形式と送信先を選択 |
| エクスポート設定 | Markdown エクスポート | デフォルトディレクトリ、ファイル名、数式、モデル情報、引用形式を設定 |
| ノートエクスポート | Notion、Yuque、Joplin、Obsidian、SiYuan | 各ノートサービスまたはローカルノート保管庫へのエクスポート先を設定 |

## データページ

### アプリデータディレクトリ

**アプリデータ**の行には、現在のインスタンスが実際に使用しているディレクトリが表示されます。パスまたは**ディレクトリを開く**をクリックするとシステムファイルマネージャーで確認でき、ディレクトリ変更アイコンをクリックすると移行を開始できます。

移行ではアプリが再起動し、データベース、内部ファイル、ナレッジベース、メモがコピーされる場合があります。先に[ストレージ場所の変更](../personalization-settings/storage.md)を読み、オフラインコピーを用意して、空のディレクトリを移行先に使用してください。

### アプリログ

**ログを開く**をクリックするとログディレクトリが開きます。問題を報告するときは、障害発生時刻に関係する必要なログだけを提出し、パス、プロンプト、その他の機密情報が含まれていないか確認してください。

### キャッシュを消去

**キャッシュを消去**は再生成できるキャッシュとローカル Trace データを削除します。会話の削除やアプリ全体のリセットとは異なります。ログイン状態、モデル設定、ナレッジベースの問題に対する万能な修復方法として使用しないでください。

### データをリセット

**データをリセット**は破壊的な操作です。現在のインスタンスのデータを消去して初期状態へ戻します。アプリ内バックアップは現在利用できないため、独立したコピーがない状態では実行しないでください。

## インポート設定

**アプリデータをインポート**では、インポートメニューに表示する取得元を管理します。変更されるのはメニュー項目だけであり、他のアプリのデータがバックグラウンドで自動的に読み取られることはありません。

インポート前にファイルの取得元が信頼できることを確認し、元ファイルを保持してください。結果は取得元の形式と現在のバージョンが対応する形式によって異なります。

## エクスポート設定

### エクスポートメニュー

会話をエクスポートするときに表示する形式やサードパーティの送信先を選択します。項目を無効にしても入口が非表示になるだけで、すでにエクスポートしたファイルは削除されません。

### Markdown エクスポート

デフォルトの保存先、ファイル名規則、モデル情報、引用、数式などを含めるかどうかを設定できます。独立して保管できるよう、エクスポート先はアプリデータディレクトリの外部に設定してください。

### ノートエクスポート

Notion、Yuque、Joplin、Obsidian、SiYuan にはそれぞれ個別の設定があります。サービスアドレス、トークン、またはローカルディレクトリを設定した後、機密情報を含まない 1 件をテスト出力し、送信先と形式を確認してから一括エクスポートしてください。

{% hint style="info" %}
エクスポートは一方向の書き出しであり、双方向同期でも完全なバックアップでもありません。外部添付ファイル、ナレッジベースのインデックス、アプリ内部の状態が含まれない場合があります。
{% endhint %}

## 現在のデータ保護方法

Backup & Restore V2 が利用可能になるまで：

1. **アプリデータ**に表示される現在のディレクトリを記録します。
2. Cherry Studio を完全に終了します。
3. ディレクトリ全体を別のドライブへコピーし、コピーを読み取れることを確認します。
4. 重要な資料の元ファイルと、必要な会話のエクスポートを保持します。

アプリの実行中にデータベースファイルをコピーまたは結合しないでください。バックアップ機能が利用可能になった後は、アプリ内の状態とこのページの最新説明に従ってください。
