# Obsidian の設定とエクスポート

Cherry Studio V2 では、トピック全体、単一のメッセージ、Cherry Studio のノートを Obsidian の Markdown ファイルとしてエクスポートできます。エクスポートには Obsidian 組み込みの `obsidian://` URI とシステムのクリップボードを使用するため、サードパーティ製の Obsidian プラグインは不要です。

設定画面は **設定 > 連携 > Obsidian** にあります。**データ設定 > エクスポートメニュー** は、メニューに「Obsidian にエクスポート」を表示するかどうかだけを制御します。

{% hint style="warning" %}
「新規作成（存在する場合は上書き）」を選ぶと、同じパスにある既存の Markdown ファイルが置き換えられます。初めて使用するときはテスト用フォルダーを作成し、重要な Vault をあらかじめバックアップしてください。
{% endhint %}

## 使用前の準備

1. 現在のコンピューターに Obsidian をインストールし、少なくとも一度起動します。
2. Obsidian で対象のローカル Vault を開きます。
3. Vault のフォルダーが存在し、現在のユーザーに読み書き権限があることを確認します。
4. Cherry Studio の Obsidian 設定を開き直します。

Cherry Studio は Obsidian のローカル設定を読み取り、このコンピューターに登録されている Vault を一覧表示します。

- Windows：ユーザーのアプリデータにある Obsidian 設定を読み取ります。
- macOS：`~/Library/Application Support/obsidian/obsidian.json` を読み取ります。
- Linux：一般的な XDG、Snap、Flatpak の設定場所に対応しています。

別のコンピューターと同期されていても、現在の Obsidian クライアントで一度も開いていない Vault は一覧に自動表示されません。

## デフォルト Vault を選択する

1. **設定 > 連携 > Obsidian** を開きます。
2. **デフォルト Obsidian Vault** で対象の Vault を選択します。
3. 会話画面に戻ります。

デフォルトをまだ選択していない場合、Cherry Studio は Vault を検出すると一覧の先頭を使用します。エクスポート時のダイアログでは、別の Vault に一時的に変更できます。

{% hint style="info" %}
Cherry Studio の画面で「リポジトリ」や「保管庫」と表示される項目は、どちらも Obsidian Vault を指します。ここで選ぶのは Vault 名であり、Obsidian Sync のリモート Vault やアカウントではありません。
{% endhint %}

## エクスポートメニューを有効にする

メニューに「Obsidian にエクスポート」がない場合：

1. **設定 > データ設定 > エクスポートメニュー** を開きます。
2. **Obsidian にエクスポート** を有効にします。
3. 会話またはノートに戻り、エクスポートメニューを開き直します。

このスイッチは入口の表示だけを制御し、Vault の検出や `obsidian://` プロトコルには影響しません。

## エクスポートダイアログを開く

### トピック全体をエクスポートする

左側のトピック一覧で対象トピックのメニューを開き、**Obsidian にエクスポート** を選択します。

トピック全体がメッセージ順に Markdown へ変換されます。デフォルトの処理方法は **新規作成（存在する場合は上書き）** です。

### 単一のメッセージをエクスポートする

メッセージメニューを開き、**Obsidian にエクスポート** を選択します。

現在のメッセージ内容だけがエクスポートされます。ダイアログでは引き続きタイトル、保存先パス、処理方法を変更できます。

### Cherry Studio のノートをエクスポートする

ノートのメニューで **Obsidian にエクスポート** を選択します。ノートでは現在の Markdown 内容が使用され、「思考過程をエクスポート」スイッチは表示されません。

## エクスポートダイアログを設定する

| 項目 | 役割 |
| --- | --- |
| タイトル | 新規ファイル名の基になります。新規作成モードでは YAML の `title` にもなります |
| Vault | 今回のエクスポート先となる Obsidian Vault |
| パス | Vault のルート、既存フォルダー、または既存の `.md` ファイル |
| タグ | 新規作成モードで YAML の `tags` に書き込みます。複数のタグは半角カンマで区切ります |
| 作成日時 | 新規作成モードで YAML の `created` に書き込みます |
| ソース | 新規作成モードで YAML の `source` に書き込みます。デフォルトは `Cherry Studio` です |
| 処理方法 | 新規作成／上書き、先頭へ挿入、末尾へ追加 |
| 思考過程をエクスポート | 会話やメッセージに思考内容がある場合、それも含めるかを指定します |

タイトルは空にできません。新規ファイルを作成するとき、Cherry Studio は各プラットフォームでファイル名に使用できない文字を削除し、長すぎる名前を切り詰めます。

### パスを選択する

パス選択画面は対象 Vault 内のフォルダーと Markdown ファイルを読み取り、名前が `.` で始まる隠し項目を除外します。

- **ルートディレクトリ** またはフォルダーを選択すると、タイトルを基に新しい `.md` ファイル名が生成されます。
- 既存の `.md` ファイルを選択すると、そのファイルパスが直接使用され、タイトルがファイル名に変わり、処理方法はデフォルトで **末尾へ追加** に切り替わります。
- Vault を切り替えた場合は、パスを選び直す必要があります。

ディレクトリツリーが空の場合は、Vault のパスがまだ存在するか、Cherry Studio にそのディレクトリの読み取り権限があるかを確認してください。

## 3 種類の処理方法

| 処理方法 | 同名の既存ファイル | 書き込み位置 | YAML Properties |
| --- | --- | --- | --- |
| 新規作成（存在する場合は上書き） | 既存内容を上書き | ファイル全体を置き換える | `title`、`created`、`source`、`tags` を書き込む |
| 先頭へ挿入 | 既存内容を保持 | 新しい内容を先頭に追加 | 新しい Properties は書き込まない |
| 末尾へ追加 | 既存内容を保持 | 新しい内容を末尾に追加 | 新しい Properties は書き込まない |

先頭への挿入と末尾への追加では、新旧の内容の間に Markdown の区切り線が挿入されます。タイトルの統合や既存 YAML の再生成は行われません。

{% hint style="warning" %}
フォルダーを選び「新規作成（存在する場合は上書き）」を使用すると、タイトルが保存先のファイル名になります。対象ディレクトリに同名ファイルがある場合は置き換えられます。
{% endhint %}

## 思考内容をエクスポートする

会話とメッセージのエクスポートダイアログには **思考過程をエクスポート** スイッチがあります。

- オフ：通常の回答内容だけをエクスポートします。
- オン：メッセージに思考／推論内容がある場合、それも書き込みます。

エクスポートされた内容は通常の Markdown になります。ファイルを他人と共有または公開する場合は、下書き、中間過程、機密情報が含まれていないか事前に確認してください。

このスイッチは元から存在しない思考内容を生成せず、Cherry Studio のノートをエクスポートするときには表示されません。

## エクスポートの仕組み

確認をクリックすると、Cherry Studio は次の処理を行います。

1. Markdown の内容をシステムのクリップボードに書き込みます。
2. Vault、ファイルパス、処理方法を含む `obsidian://new` URI を構築します。
3. システムに Obsidian を開くよう要求します。
4. Obsidian がクリップボードからファイルを作成、上書き、先頭へ挿入、または末尾へ追加します。

このため、Cherry Studio の成功通知はエクスポート要求が送信されたことを示すだけで、ファイルへの書き込み完了を保証するものではありません。Obsidian に切り替え、対象ファイルが存在し、内容が正しいことを確認してください。

この処理は [Obsidian 公式 URI](https://help.obsidian.md/Extending%2BObsidian/Obsidian%2BURI) が提供する `clipboard`、`append`、`overwrite` などのパラメーターを利用しています。

## よくある質問

### 設定に「Obsidian Vault が見つかりません」と表示される

同じシステムユーザーで Obsidian を起動し、対象のローカル Vault を開いてから、Cherry Studio の設定を開き直してください。Obsidian のローカル設定に登録された Vault だけが検出されます。

### Vault は表示されるが、パス一覧が空である

Vault フォルダーが移動、オフライン、または読み取り権限のない状態になっている可能性があります。Obsidian に戻って Vault を正常に開けるか確認し、外付けドライブやネットワークディレクトリがオンラインかも確認してください。

### エクスポートをクリックしても Obsidian が開かない

システムに `obsidian://` プロトコルが登録されていない可能性があります。Windows と macOS では通常、Obsidian の実行後に自動登録されます。Linux ではデスクトップファイルの `Exec` が `%u` パラメーターに対応していることを確認してください。登録方法は Obsidian 公式 URI ドキュメントを参照できます。

### Cherry Studio は成功と表示するがノートが生成されない

成功通知は URI が送信されたことだけを示します。Obsidian が開いたか、対象の Vault が正しいか、システムが Cherry Studio による外部プロトコルの起動を許可しているかを確認してください。クリップボードがセキュリティソフトにより遮断されたり、直後に書き換えられたりしていないかも確認します。

### エクスポートで古いノートが上書きされた

「新規作成（存在する場合は上書き）」は同じパスのファイルを置き換えます。Vault のバックアップ、バージョン管理、Obsidian Sync のバージョン履歴から復元できます。以降は別のタイトルやフォルダーを使うか、先頭への挿入または末尾への追加を選択してください。

### 先頭へ挿入または末尾へ追加した後に Properties がない

これは現在の仕様です。YAML Properties が生成されるのは新規作成／上書きモードだけです。先頭への挿入と末尾への追加では、区切り線と Markdown 本文だけが書き込まれます。

### 会話メニューに Obsidian がない

**設定 > データ設定 > エクスポートメニュー** を開き、**Obsidian にエクスポート** を有効にしてください。すでに有効な場合は、現在の会話を開き直してからメニューを再表示します。

### Linux で Vault が引き続き見つからない

Obsidian のインストール方法と設定パスを確認してください。Cherry Studio は一般的な XDG、Snap、Flatpak の場所を確認しますが、カスタムポータブル版や標準外のパスは自動検出できない場合があります。

解決しない場合は、[フィードバックと提案](../../question-contact/suggestions.md)から Cherry Studio と Obsidian のバージョン、OS、インストール方法、`obsidian://` リンクを開けるかどうか、マスキング済みの Vault 名とパスを送信してください。
