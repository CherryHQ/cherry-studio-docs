# AI の基礎知識

このページでは、Cherry Studio でよく使われる AI の概念を説明します。目的は用語を暗記することではなく、モデルが失敗する理由、結果に影響する設定、データが送信される可能性のある場所を理解することです。

## モデル、プロバイダー、API

### モデル

モデルは、入力を処理して出力を生成する計算システムです。モデルごとに、テキスト、画像理解、画像生成、Embedding、Rerank、推論、ツール呼び出しなど、得意な分野が異なります。

同じモデル名が複数のプロバイダーから提供される場合があります。プロバイダーが異なると、次も異なる可能性があります。

* Model ID、バージョン、コンテキスト上限。
* 利用可能な地域、価格、レート制限、アカウント権限。
* OpenAI、Anthropic、Gemini、その他の API 形式。
* 画像、ツール、推論パラメーターなどの機能。

したがって、モデル名が同じでも API の動作が同じとは限りません。実際に使用するプロバイダーでテストしてください。

### プロバイダー

プロバイダーは、API アドレス、認証、モデル一覧、課金、リクエスト制限を提供します。Cherry Studio は接続設定の保存、リクエストの構成、結果の表示を行いますが、プロバイダーのアカウント、クォータ、モデル権限を代わりに有効化することはできません。

設定については[モデルサービス](../pre-basic/providers/)を参照してください。

### API とエンドポイント

API はリクエストとレスポンスの形式を定義します。一般的なエンドポイントには次があります。

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* Ollama Chat

「ある API と互換」という表現は、通常、基本形式が似ていることだけを意味し、その API の高度な機能がすべて実装されていることを保証しません。エージェントでは、さらに **Anthropic Messages** エンドポイントから利用できるモデルが必要です。

## Token と Tokenizer

### Token とは

Token は、モデルがテキストを処理するときに使用する断片です。1 つの Token は次のいずれかになります。

* 完全な単語。
* 単語の一部。
* 1 つまたは複数の文字。
* 句読点、空白、特殊記号。

Token は文字数や単語数と同じではなく、特定の言語で一定の文字数に固定されてもいません。

### Tokenizer とは

Tokenizer は、入力をモデルが使用する Token の列に変換します。モデルやバージョンごとに異なる Tokenizer を使用する場合があり、同じ文章でも Token 数が異なります。

これは次に影響します。

* コンテキスト上限を超えるか。
* リクエスト速度。
* 入力と出力の費用。
* 長いドキュメントの分割方法。

Cherry Studio に表示される Token 数はコンテキストの規模を判断するための目安です。最終的な課金と正確な使用量は、プロバイダーのレスポンスを基準にしてください。

## コンテキストウィンドウ

コンテキストとは、1 回のリクエストでモデルが実際に受け取る情報です。次が含まれる場合があります。

* システムプロンプトとアシスタント設定。
* 現在のユーザーメッセージ。
* 保持されたメッセージ履歴。
* 画像、ファイル、Web ページの内容。
* ナレッジベースから検索されたチャンク。
* ツール定義、呼び出しパラメーター、結果。
* モデルが続けて出力するための領域。

コンテキストウィンドウには上限があります。内容が多すぎると、プロバイダーがリクエストを拒否する、アプリが一部を切り捨てる、モデルが一部の情報にしか注意を向けない、といったことがあります。

### コンテキストは長いほど良いか

必ずしもそうではありません。長いコンテキストは費用と待ち時間を増やし、無関係な情報がタスクを妨げる場合もあります。より効果的な方法は次のとおりです。

* プロジェクトごとに別のトピックを使用する。
* 段階が変わるときに**新しいコンテキスト**を使用する。
* タスクに必要なファイルだけを添付する。
* ナレッジベースから関連するチャンクだけを検索する。
* 安定した規則はアシスタントへ、一時的な情報は現在のメッセージへ入れる。

トピックとコンテキストの操作は[チャット画面](../cherrystudio/preview/chat.md)を参照してください。

## システムプロンプト、アシスタント、トピック

### システムプロンプト

システムプロンプトは、長期的な役割、行動の境界、出力規則を定義します。モデル自体の知識、コンテキスト上限、サーバー側の機能を変更することはできません。

システムプロンプトが長すぎたり互いに矛盾したりすると、コンテキストを消費して予測可能性を下げます。安定した規則だけを残し、日付、資料、今回の目的はユーザーメッセージへ入れてください。

### アシスタント

アシスタントは、再利用できるチャット設定を保存します。例：

* システムプロンプト。
* デフォルトのモデルとパラメーター。
* コンテキスト数。
* ナレッジベース。
* Web 検索と MCP。

1 つのアシスタントに複数のトピックを作成できます。アシスタント設定は共通ですが、トピック履歴は独立しています。詳しくは[アシスタントライブラリ](../cherrystudio/preview/selection-assistant.md)を参照してください。

## Temperature、Top P、出力パラメーター

Temperature と Top P は、生成のランダム性と候補範囲の調整によく使われますが、実装はモデルとプロバイダーによって異なります。一部の推論モデルは、これらの値を無視、制限、固定します。

一般的な推奨事項：

* 事実の抽出、形式変換、コード修正では、安定したデフォルト値を優先します。
* 創作では多様性を適度に高められます。
* 複数のパラメーターを同時に大きく変更してから、1 つの効果を判断しないでください。
* パラメーターエラーが発生したらデフォルトへ戻し、現在のモデルの公式説明を確認します。

最大出力長は、今回モデルが生成できる内容を制限するもので、入力コンテキストを拡大しません。出力が突然止まった場合は、出力上限、プロバイダー制限、リクエストのタイムアウトを確認してください。

## 推論モデル

推論モデルは回答前に追加の計算を行い、多段階の分析、数学、計画、複雑なコード作業に適しています。通常、推論にはより長い待ち時間または費用が必要です。

注意事項：

* 画面に「思考中」と表示されても、すべてのモデルが同じ方法で推論内容を返すわけではありません。
* 推論過程が非表示でも、モデルが推論していないとは限りません。
* 推論能力が高くても、事実が必ず正しいとは限りません。
* 単純なタスクで最高の推論強度が必要とは限りません。

モデルを選ぶときは、タスクの正確さ、速度、価格、ツール互換性を合わせて評価してください。

## ツール呼び出し

モデルは、ある Web サイトを「知っている」だけで自動的にアクセスできるわけではありません。ツール呼び出しは通常、次の 3 段階で行われます。

1. アプリが利用可能なツールとパラメーター形式をモデルに伝える。
2. モデルが構造化されたツール呼び出しリクエストを返す。
3. Cherry Studio または対応する Server がツールを実行し、結果をモデルへ返す。

したがって、ツールは異なる箇所で失敗する可能性があります。

* モデルがツールを選択しない。
* モデルが誤ったパラメーターを生成する。
* ユーザーが権限を拒否する。
* ツールプログラムまたはリモートサービスが失敗する。
* ツールの結果が大きすぎる、または形式が不正。

モデルが文章で「検索する」と述べても、実際に呼び出したことにはなりません。メッセージ内のツール記録または[トレース](../advanced-basic/diao-yong-lian-shi-yong-shuo-ming.md)を確認してください。

## Web 検索

Web 検索は次から提供される場合があります。

* モデルプロバイダーのネイティブ検索機能。
* Cherry Studio で設定した検索サービス。
* MCP が提供する検索ツール。

検索では通常、候補の Web ページを取得し、その一部を読んでモデルへ渡します。引用リンクが存在しても、モデルの結論を必ず裏付けるとは限りません。公開日、一次情報、引用内容を確認してください。

設定方法は [Web 検索](../websearch/README.md)を参照してください。

## マルチモーダル

マルチモーダルモデルは、画像、音声、ファイルなどテキスト以外の入力を処理できます。機能は個別に判断してください。

| 機能 | 説明 |
| :--- | :--- |
| 画像理解 | 画像を読み取り、質問に回答する |
| 画像生成 | プロンプトから画像を作成または編集する |
| ファイル入力 | PDF、ドキュメント、その他のファイルを受け取る |
| 音声理解 | 音声を受け取り、分析する |

画像理解への対応は、画像生成への対応を意味しません。画像を読めても、すべてのファイル形式を読めるとは限りません。

Cherry Studio の機能タグは、画面とリクエストルーティングを制御します。タグを手動で変更しても、プロバイダーの実際の API は変わりません。変更後は最小のテストを実行してください。

## ハルシネーション

「ハルシネーション」とは、流暢ではあるものの、根拠がない、入力と矛盾する、または事実として誤っている出力を指します。主な原因：

* 質問に重要なコンテキストがない。
* モデルが学習時の古い情報を使用した。
* 検索結果が無関係、または出典が信頼できない。
* 長いコンテキストで重要な情報が無視された。
* ユーザーが必ず答えるよう求め、空欄を残しにくくした。

リスクを下げる方法：

* 出典、日付、入力位置を求める。
* 事実、推論、仮定を区別する。
* 「不明」という回答を許可する。
* 重要なデータを人が抜き取り確認する。
* 高リスクの判断は専門家が確認する。

Web 接続とナレッジベースは新しい資料を提供できますが、ハルシネーションを自動的に解消するものではありません。

## Embedding

Embedding モデルは、テキストをベクトルと呼ばれる数値の列へ変換します。意味の近いテキストは通常ベクトル空間でも近くなるため、類似度検索に使用できます。

Embedding モデルはチャットモデルではありません。通常はベクトルを返し、自然言語の回答は生成しません。

### 次元

次元はベクトル内の数値の数です。同じナレッジベースでインデックス作成と検索を行うには、互換性のあるモデルと次元が必要です。モデルまたは次元を変更した場合、古いベクトルは通常再構築する必要があります。

次元が大きければ必ず正確になるわけではありません。言語、テキスト種別、入力上限、速度、費用、実際の検索結果も考慮してください。

詳しくは[埋め込みモデル](../knowledge-base/emb-models-info.md)を参照してください。

## チャンク分割とベクトル検索

ナレッジベースを作成するとき、長いドキュメントは小さなチャンクへ分割され、各チャンクのベクトルが生成されます。

チャンクが大きすぎる場合：

* 多すぎる主題を含む。
* Embedding の入力上限を超える。
* 返されたチャンクがコンテキストを多く消費する。

チャンクが小さすぎる場合：

* 文の間の関係が失われる。
* 大量のインデックスとリクエストが生成される。
* 説明が不足した局所的な語句だけが検索される。

オーバーラップは隣接チャンクの一部のコンテキストを維持しますが、インデックス数を増やします。最適値はドキュメント構造と質問の種類によって異なるため、検索テストで選択してください。

## Rerank

ベクトル検索は最初に候補チャンクを見つけ、Rerank モデルが現在の質問に合わせて並べ直します。候補順を改善できますが、次は修復できません。

* 原文に回答が存在しない。
* ドキュメントの抽出が誤っている。
* 候補段階で関連チャンクがまったく検索されていない。
* 最終的なチャットモデルが正しいチャンクを誤解する。

Embedding と Rerank は異なる機能であり、交換できません。

## RAG

RAG は Retrieval-Augmented Generation、つまり「検索拡張生成」です。Cherry Studio のナレッジベースでは、次のようにまとめられます。

1. ドキュメントを抽出してチャンクに分割する。
2. Embedding でインデックスを作成する。
3. ユーザーの質問から検索ベクトルを生成する。
4. 類似チャンクを検索する。
5. 必要に応じて Rerank で並べ直す。
6. チャンクをコンテキストとしてチャットモデルへ渡す。
7. チャットモデルが回答を生成する。

検索が正しく回答が誤っている場合は、チャットモデルとプロンプトを確認します。検索自体が誤っている場合は、資料、チャンク分割、Embedding、Rerank を確認します。全体の流れは[ナレッジベースガイド](../knowledge-base/knowledge-base.md)を参照してください。

## MCP

MCP（Model Context Protocol）は、AI アプリケーションが共通の方法で外部機能へ接続するためのプロトコルです。Server は次を提供できます。

* **Tools**：検索、書き込み、API 呼び出しを実行する。
* **Prompts**：再利用可能なプロンプトテンプレートを提供する。
* **Resources**：読み取り可能な内容を提供する。

MCP はプロトコルであり、セキュリティサンドボックスではありません。STDIO Server は現在のユーザー権限でローカル実行される場合があり、リモート Server は送信されたデータを受け取ります。インストール前に、出所、コマンド、パラメーター、環境変数、アクセス範囲を確認してください。

使用方法は [MCP](../advanced-basic/mcp/)を参照してください。

## スキル

スキルは、エージェント向けのタスク指示、手順、リソースの集合です。主に「ある種類の作業をどのように完了するか」を示し、MCP は主に「何を呼び出せるか」を提供します。

スキル自体がスクリプト、テンプレート、ツールを参照する場合もあります。インストール前に `SKILL.md` と付属ファイルを読み、信頼できる出所だけを有効にしてください。詳しくは[スキル](../pre-basic/settings/skills.md)を参照してください。

## アシスタントとエージェント

| | アシスタント | エージェント |
| :--- | :--- | :--- |
| 主な用途 | 固定設定で継続的にチャットする | 目的と権限の下で多段階タスクを実行する |
| ローカル作業ディレクトリ | エージェント式のディレクトリ権限はない | アクセス可能なディレクトリを制限できる |
| ファイルとコマンドのツール | 特定の MCP などで拡張する | 組み込みツール、MCP、スキルを利用できる |
| 適した場面 | 執筆、質問回答、ナレッジベース検索 | ファイル変更、コマンド実行、ワークフロー完了 |

どちらを使用するか判断するときは、[概念入門](../advanced-basic/concepts-101.md)を参照してください。

## ローカルモデルとクラウドモデル

### クラウドモデル

リクエストはプロバイダーへ送信されます。一般的な利点は、ローカルへの導入が不要でモデルの選択肢が多いことです。ネットワーク、アカウント、費用、地域、プロバイダーのデータポリシーを考慮する必要があります。

### ローカルモデル

モデルの推論は自分のデバイスまたはローカルネットワーク上のサービスで実行されます。外部へ送信するモデルリクエストを減らせますが、十分なメモリ、GPU メモリ、ストレージ、計算能力が必要です。

「ローカルモデルを使用する」ことは、ワークフロー全体が完全にオフラインであることを意味しません。次は外部サービスへアクセスする場合があります。

* Web 検索。
* リモート MCP。
* クラウドの Embedding または Rerank。
* クラウドのドキュメントプロセッサー。
* 画像生成、チャンネル、第三者連携。

プライバシーを評価するときは、チャットモデルの場所だけでなく、データフロー全体を要素ごとに確認してください。

ローカルモデルの設定は [Ollama](../pre-basic/providers/ollama.md) と [LM Studio](../pre-basic/providers/lm-studio.md)を参照してください。

## 費用が発生する場所

費用が発生する可能性のある項目：

* チャットモデルの入力、出力、推論 Token。
* 画像、音声、ファイルの処理。
* Embedding と Rerank のリクエスト。
* 画像生成。
* 検索、ドキュメントプロセッサー、MCP、その他の第三者 API。
* クラウドストレージとネットワーク通信量。

同じタスクでの複数モデルの並列実行、繰り返し再試行、長いコンテキスト、高頻度のスケジュールタスクは、いずれも使用量を増やします。Cherry Studio の見積もり表示は、プロバイダーの請求書の代わりにはなりません。

## データとプライバシー

1 つのワークフローで、データは次の経路を通る場合があります。

```text
ユーザー入力
→ Cherry Studio
→ ドキュメント処理 / 検索 / ナレッジベース / MCP
→ モデルプロバイダー
→ Cherry Studio の表示またはローカルファイル
```

実際の経路は有効な機能によって異なります。使用前に次を確認してください。

* データがデバイス外へ出るか。
* どのサービスが処理するか。
* リクエストが保存または学習に使用されるか。
* 認証情報の保存場所と権限の範囲。
* ログ、バックアップ、スクリーンショットに機密情報が含まれるか。

API Key、Token、パスワード、秘密鍵、不要な個人情報をプロンプト、ナレッジベース、ドキュメントに入れないでください。機密性の高い資料は先に匿名化し、組織のポリシーに準拠するモデルとツールを選択してください。

## 推奨する学習順序

1. まずモデル、プロバイダー、Token、コンテキストを理解する。
2. [チャット画面](../cherrystudio/preview/chat.md)で小さなタスクを完了する。
3. 安定したプロンプトをアシスタントに保存する。
4. ナレッジベースを作成して検索テストを行う。
5. 外部ツールが必要になったら MCP を学ぶ。
6. ローカルファイルと多段階実行が必要になったら、エージェントとスキルを使用する。

概念ではなく実際の不具合については、[よくある質問](questions.md)から確認してください。
