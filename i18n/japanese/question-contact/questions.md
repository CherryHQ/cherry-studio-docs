# よくある質問

このページでは、問題の種類を切り分け、該当するトラブルシューティング項目へ進めます。不具合が発生したら、まず元のエラーとデータを保全してください。すぐに再インストール、データのリセット、アプリケーションディレクトリの削除を行わないでください。

## 最初に確認する 5 項目

1. **設定 → バージョン情報**で Cherry Studio の完全なバージョン番号を記録します。
2. OS、チップアーキテクチャ、問題が発生した時刻を記録します。
3. 画面に表示されたエラー全文を保存します。「使えない」だけではなく、具体的な内容を残してください。
4. 新しいチャット、小さなファイル、簡単なツールを使って問題の範囲を絞ります。
5. すべてのモデルで失敗するのか、特定のプロバイダー、モデル、機能だけで失敗するのかを確認します。

アップデート後に問題が発生した場合は、アップデート前のバージョンと、データディレクトリを移行したかどうかも記録してください。

{% hint style="warning" %}
データのリセットはローカルデータベースとアプリが管理するファイルを消去します。一般的な修復手順ではありません。利用可能なバックアップがない場合は実行しないでください。キャッシュの消去でも、アカウント、モデル、API 設定のエラーは修復できません。
{% endhint %}

## アプリをインストールまたは起動できない

### インストーラーを開けない

ダウンロードした OS とアーキテクチャが正しいことを確認します。

* Apple Silicon Mac では arm64 パッケージ、Intel Mac では x64 パッケージを使用します。
* Windows と Linux でも、デバイスのアーキテクチャに合うバージョンを選択します。
* インストーラーは[クライアントのダウンロード](../cherrystudio/download.md)または公式 Release から入手します。

macOS で「開発元を確認できません」またはファイルが破損しているという警告が表示された場合は、[macOS インストールガイド](../pre-basic/installation/macos.md)に従ってください。出所不明の再署名済みインストーラーはダウンロードしないでください。

### 起動後に白い画面、レイアウト崩れ、ボタンの消失が起きる

カスタム CSS を使用したことがある場合は、まず [CSS 設定の消去](../personalization-settings/clear-css.md)を参照してください。誤ったセレクターで設定画面への入口が隠れることがありますが、データディレクトリ全体を削除すると他の内容も失われます。

カスタム CSS を使用していない場合は、バージョンと OS を記録し、再起動後にもう一度再現させます。引き続き発生する場合は、ログを保存してフィードバックを送信してください。

### アップデート後に新規インストールのように見える

アプリのデータディレクトリを変更していないか、外付けディスクがオンラインか、起動時に新しい空のディレクトリが選択されていないかを確認します。新しいディレクトリで大量のデータをすぐに作成したり、古いディレクトリを削除したりしないでください。[保存場所の変更](../personalization-settings/storage.md)を参照してください。

## モデルサービス

### API Key を保存しても使用できない

次の順序で確認します。

1. プロバイダーが有効になっている。
2. API Key が現在のプロバイダーとリージョン用で、余分な空白がない。
3. API アドレスがプロバイダー指定のルートパスとエンドポイント種別を使用している。
4. アカウントで対象モデルが有効になっており、残高、クォータ、課金方法が利用できる。
5. モデルが同期済みまたは手動追加済みで、モデル一覧で有効になっている。

接続チェックの成功は、通常、基本的な 1 回のリクエストが到達できたことだけを示します。画像認識、推論、ツール呼び出し、Embedding、画像生成がすべて使用できるとは限りません。各機能を個別にテストしてください。

一般的な設定は[モデルサービス](../pre-basic/providers/)、各テンプレートへの入口は[全プロバイダーのクイックリファレンス](../pre-basic/providers/quick-reference.md)を参照してください。

### モデル一覧を取得できない

一部の互換サービスは標準のモデル一覧を提供しないか、アカウントにアクセス権があるモデルだけを返します。まず Base URL、認証情報、リージョン、プロキシを確認してください。プロバイダーが Model ID の手動入力を許可している場合は、公式ドキュメントに従って追加します。

見た目が同じという理由だけで、別のプラットフォームから Model ID をコピーしないでください。名前空間、大文字と小文字、バージョンサフィックスが異なる場合があります。

### プロバイダー画面にはモデルがあるが、チャットで見つからない

モデルは次の条件をすべて満たす必要があります。

* 所属するプロバイダーが有効になっている。
* モデル自体が有効になっている。
* モデル種別が現在の入口に適している。

Embedding、Rerank、画像生成モデルは通常のチャットモデルとして表示されません。エージェントでは、さらに **Anthropic Messages** エンドポイントから利用できるモデルが必要です。

### よくある HTTP ステータスコード

エラーの定義はプロバイダーによって異なる場合があります。レスポンス本文とプロバイダーのドキュメントを基準にしてください。

| ステータス | 主な原因 | 最初に確認する項目 |
| :--- | :--- | :--- |
| `400` | リクエストパラメーター、コンテキスト、内容形式が無効 | モデルエンドポイント、添付ファイル、コンテキスト長、カスタムパラメーター |
| `401` | 認証失敗 | API Key、Authorization 方式、Key の有効期限 |
| `403` | アカウント、モデル、リージョン、内容の権限不足 | モデル権限、課金、地域、組織権限 |
| `404` | パス、デプロイ、モデルが存在しない | Base URL、Deployment、Model ID、エンドポイント種別 |
| `408` / `504` | リクエストまたは上流のタイムアウト | ネットワーク、プロキシ、サービス状態、入力サイズ |
| `413` | リクエスト本文が大きすぎる | 画像とファイルのサイズ、コンテキスト、バッチ入力 |
| `422` | パラメーターは解析できるが処理できない | フィールド型、必須値、モデル固有パラメーター |
| `429` | レート、Token、クォータの上限 | RPM/TPM、残高、同時実行数、時間を置いて再試行 |
| `500` / `502` / `503` | 上流の内部エラー、ゲートウェイ障害、過負荷 | サービス状態、プロキシ、小さなリクエストで再試行 |

特定のモデルだけでエラーになる場合は、同じプロバイダーの別の基本テキストモデルでテストします。すべてのプロバイダーで失敗する場合に、ローカルネットワークとプロキシを確認してください。

## チャット

### 送信後に応答がない

メッセージ上部に表示される実際のモデルとプロバイダーを確認します。複数モデルのチャットでは、1 つのモデルの失敗が他のモデルの失敗を意味するわけではありません。各応答のエラーを個別に確認してください。

デフォルトのアシスタントと空のチャットを作成し、次の短いテキストだけを送信できます。

```text
「接続は正常です」と返信してください
```

小さなリクエストは成功し、元のチャットだけが失敗する場合、コンテキスト長、添付ファイル、ツール、アシスタントのカスタムパラメーターが原因である可能性が高くなります。詳しい操作は[チャット画面](../cherrystudio/preview/chat.md)を参照してください。

### コンテキストが長すぎる、またはリクエスト本文が大きすぎる

履歴メッセージを減らし、不要なコンテキストを無効にし、大きな添付ファイルを削除するか、新しいチャットを作成します。コンテキストの消去は、以降のモデルリクエストに含める履歴範囲だけに影響し、画面上のすべてのメッセージを削除する操作ではありません。

### 画像をアップロードできない、またはモデルが画像を認識できない

モデルに画像認識機能のタグがあり、現在のプロバイダーエンドポイントが実際に画像を受け付けることを確認します。機能を手動で選択しても、Cherry Studio の画面フィルターとリクエストルーティングが変わるだけで、サーバーに本来ない機能は追加されません。

複数モデルのチャットに画像をアップロードする場合は、メンションしたすべてのモデルが画像入力に対応している必要があります。

### 数式がソースコードとして表示される

まず、モデルが完全な区切り記号を出力したことを確認します。

* インライン数式：`$...$` または `\(...\)`
* 独立数式：`$$...$$` または `\[...\]`

区切り記号がコードブロック内にある、エスケープが不完全、モデル出力が途中で切れている場合、数式としてレンダリングされません。表示の問題と判断する前に、元のメッセージを確認してください。

## ネットワークとプロキシ

### ブラウザーでは接続できるが Cherry Studio では接続できない

システムブラウザーと Electron アプリでは、使用するプロキシ、証明書、ログイン状態が異なる場合があります。[一般設定](../cherrystudio/preview/settings/general.md)を開き、プロキシモード、プロキシアドレス、再起動が必要かどうかを確認します。

さらに次を確認します。

* 会社のネットワークまたはファイアウォールが対象ドメインを遮断していないか。
* HTTPS 証明書がプロキシによって置き換えられていないか。
* システム時刻が正しいか。
* サービスに地域制限またはログイン要件がないか。

システムのセキュリティソフトを無効にしたり、証明書エラーを無視したりする方法を長期的な解決策にしないでください。

### プロキシを有効にするとすべてのリクエストが失敗する

比較のため、一時的にシステムプロキシまたはプロキシなしに戻します。手動プロキシには正しいプロトコル、ホスト、ポートが必要です。HTTP、HTTPS、SOCKS は、同じポートを使用しているという理由だけで交換できません。

## ナレッジベース

### ナレッジベースを作成できない、または次元を取得できない

ナレッジベースを作成する前に、利用可能な Embedding モデルが必要です。次を確認します。

1. 選択したモデルが通常のチャットモデルではなく Embedding モデルである。
2. プロバイダー、API Key、Base URL、Model ID が正しい。
3. モデルが実際の埋め込みリクエストを 1 回完了できる。
4. モデルが返すベクトル次元が設定と一致する。

詳しいトラブルシューティングは[埋め込みモデル](../knowledge-base/emb-models-info.md)を参照してください。

### ファイルが処理中のまま、または失敗と表示される

現在のキューが完了するのを待ってから、失敗状態を確認します。主な原因には、ファイルを読み込めない、Web ページにアクセスできない、ドキュメントプロセッサーの失敗、Embedding リクエストの失敗、レート制限があります。

設定を修正した後、失敗した資料を再インデックスします。全体の流れは[ナレッジベースガイド](../knowledge-base/knowledge-base.md)を参照してください。

### チャットの回答が正確でない

まず検索テストを使い、正しいチャンクが見つかったか確認します。

* 検索が誤っている：資料、チャンク分割、Embedding、Rerank を調整します。
* 検索は正しいが回答が誤っている：チャットモデル、プロンプト、コンテキストを確認します。

ナレッジベースは検索チャンクを提供するだけで、最終回答は引き続きチャットモデルが生成します。

## エージェント

### モデルがエージェントのモデル選択に表示されない

エージェントは **Anthropic Messages** を含むエンドポイント種別を必要とし、Embedding、Rerank、画像生成モデルは対象外です。プロバイダーエンドポイントと機能タグを確認し、簡単なツールタスクで実際の互換性を検証してください。

### エージェント画面にサービスが実行されていないと表示される

まず画面の起動ボタンをクリックします。引き続き失敗する場合は、**設定 → API サーバー**を開き、ポートと実行状態を確認します。他のプログラムがポートを使用している場合は、競合するプロセスを停止するか、利用可能なポートに変更します。

### エージェントがファイルを読み書きできない

対象ディレクトリがアクセス可能なパスに追加されていること、ツールが有効であること、権限リクエストが承認されていることを確認します。エラーを回避するためだけに、ユーザーディレクトリ全体やディスク全体をアクセス可能なパスへ追加しないでください。

詳しいトラブルシューティングは[エージェント](../advanced-basic/agent.md)と [API サーバー](../advanced-basic/api-server.md)を参照してください。

## MCP

### Server を起動できない

ローカルの STDIO Server では、まず Command、Arguments、実行環境、作業ディレクトリを確認します。リモート Server では、URL、Headers、認証、プロトコル種別を確認します。

Server 詳細の**ログを表示**を開き、無効にしてから再度有効にすると、最初の起動エラーを見つけやすくなります。完全なチェックリストは [MCP のよくある質問](../advanced-basic/mcp/chang-jian-wen-ti.md)を参照してください。

### 接続済みだがツールがない

接続成功は、Server が必ず Tools を提供することを意味しません。Prompts または Resources だけを提供する場合もあります。Server 詳細の機能一覧と、ログの初期化エラーまたは `listTools` エラーを確認してください。

### モデルがツールを説明するだけで呼び出さない

次を確認します。

* 現在のアシスタントまたはエージェントに MCP Server が接続されている。
* Server が有効で、対象ツールが表示されている。
* 現在のモデルとエンドポイントがツール呼び出しに対応している。
* ツールの承認が拒否されていない。

## データ、バックアップ、復元

### 自動バックアップが作成されない

スケジュールが「オフ」ではないこと、保存先ディレクトリまたはリモートサービスがオンラインであることを確認し、画面に表示された最新エラーを確認します。外付けディスク、NAS、リモートストレージでは、空き容量、権限、接続状態も確認してください。

### 復元後に画像またはナレッジベースのファイルがない

バックアップ時に**コンパクトバックアップ**を有効にしていた場合、アプリの `Data` ディレクトリ内の画像とナレッジベースファイルは除外されます。これは想定された動作であり、コンパクトバックアップで除外されたファイルは復元できません。

### 複数のパソコンのデータが自動的に統合されない

バックアップと復元は上書き処理であり、リアルタイムの双方向同期ではありません。復元前にバージョンと時刻を比較し、現在のデバイスを先にバックアップしてください。

詳しくは[データ設定](../data-settings/README.md)を参照してください。

## ログを取得する

**設定 → データ設定 → データ**へ移動し、**アプリケーションログ**からログディレクトリを開きます。問題を再現した後、発生時刻を基準に該当ファイルを探します。

送信前に、次の情報を削除または隠してください。

* API Key、Token、Cookie、認証 Header。
* チャット、プロンプト、ナレッジベース、ファイルの内容。
* メールアドレス、ユーザー名、個人ディレクトリ、内部ネットワークアドレス。
* 第三者サービスへのリクエストとレスポンス。

1 つのエラーが複数行に記録される場合があります。エラー前後の必要なコンテキストは残しますが、アプリケーションデータディレクトリ全体やバックアップファイルを公開アップロードしないでください。

## フィードバックに含める情報

対応可能な報告には、少なくとも次の情報が必要です。

```text
Cherry Studio バージョン：
OS とアーキテクチャ：
プロバイダーとモデル（関連する場合）：
問題の発生時刻：
期待する結果：
実際の結果：
最小の再現手順：
エラー全文：
試した操作：
匿名化したログまたはスクリーンショット：
```

まず[効果的な質問方法](ask.md)を読み、次に[フィードバックと提案](suggestions.md)に記載された窓口から送信してください。クラッシュまたはデータの問題では、バックアップの有無、データディレクトリを移行したか、問題発生後もデータを書き込んだかを記載してください。
