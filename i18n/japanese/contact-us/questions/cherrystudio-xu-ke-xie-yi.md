## 最初に理解すべき 3 つのポイント

1. **オープンソースは商用利用の禁止を意味しません。** Cherry Studio の公式リポジトリは、AGPL-3.0 を完全に遵守することを条件として、Community Edition の商用利用を明示的に認めています。
2. **商用利用できることは、ソースを非公開にできることを意味しません。** 変更、配布、またはネットワーク経由で他者に機能を提供すると、ソースコード、ライセンス表示、ネットワーク相互作用に関する義務が生じる場合があります。
3. **AGPL-3.0 の要件からの免除が必要な場合は、商用ライセンスを申請してください。** 商用ライセンスは別の契約であり、このページによって自動的に付与されるものではありません。

## AGPL-3.0 で認められること

ライセンスを遵守することを条件として、AGPL-3.0 は次の行為を認めています。

* ソフトウェアを実行する。
* ソースコードを閲覧し、研究する。
* ソフトウェアを変更する。
* 原版または変更版を複製し、再配布する。
* ソフトウェアに料金を設定する、または商用環境で使用する。

「フリーソフトウェア」とは、使用、研究、変更、共有の自由を表すものであり、すべてのサービス、導入、サポートを無償にしなければならないという意味ではありません。

## 義務を重点的に確認すべき場面

| 場面 | 重点的に確認する内容 |
| :--- | :--- |
| 公式版を自分の端末だけで実行する | LICENSE 全文、第三者コンポーネントのライセンス、免責事項 |
| 変更版を組織内で使用する | 変更範囲、利用者、配布またはリモートネットワーク相互作用の有無 |
| 顧客または他の主体にインストーラーを配布する | AGPL 第 4～6 節の表示、ライセンス本文、Corresponding Source の要件 |
| 変更版を配布する | 変更表示、同一ライセンスでの許諾、Corresponding Source |
| ユーザーがネットワーク経由で変更版と相互作用する | リモートユーザーへ Corresponding Source を提供する AGPL 第 13 節の要件 |
| 非公開の製品またはサービスへ統合する | 作品の境界、結合方法、依存関係、商用ライセンスの必要性 |

{% hint style="info" %}
「内部利用」「ネットワークサービス」「プラグイン」「独立プロセス」「少量のコードだけを変更」といった説明だけでは、遵守状況を判断できません。実際のアーキテクチャ、提供先、適用法を合わせて検討する必要があります。
{% endhint %}

## ソフトウェア配布時の一般的な義務

Cherry Studio またはその変更版を配布する場合、通常は次の事項を確認する必要があります。

* 適用される著作権表示とライセンス表示を保持する。
* 受領者に AGPL-3.0 のライセンス本文を提供する。
* 自分が変更したバージョンと変更日を明示する。
* 対象となる作品全体を AGPL-3.0 で許諾する。
* ライセンスで認められた方法により Corresponding Source を提供する。
* AGPL-3.0 と矛盾する追加制限を課さない。
* 受領者がライセンスで認められた権利を行使することを技術的手段で妨げない。

具体的な要件とソースコードの提供方法は、LICENSE 第 4～7 節の原文を基準としてください。

## 変更版をネットワーク経由で提供する場合

AGPL-3.0 と GPL v3 の重要な違いの一つは、リモートネットワーク相互作用に関する規定です。

プログラムを変更し、その変更版がネットワーク相互作用に対応しており、ユーザーがコンピューターネットワーク経由でリモートから相互作用できるようにした場合、AGPL 第 13 節は、当該バージョンの **Corresponding Source** を入手できる機会をそのユーザーに明確に提供することを求めています。入手方法は、ネットワークサーバーを通じて無償で提供され、標準的または一般的な複製方法を使用する必要があります。

この要件を「すべてのサーバーコードを公開しなければならない」と単純化することも、「インストーラーを配布しなければ義務はない」と単純化することもできません。どのコードがライセンス対象の作品とその Corresponding Source を構成するかを判断する必要があります。

## Corresponding Source とは

Corresponding Source は、任意のソースコード圧縮ファイルをアップロードすればよいというものではありません。ライセンスでは、対象作品を変更するために適したソースコードの形式と定義され、通常は次の内容も含まれる場合があります。

* オブジェクトコードのビルド、インストール、実行に必要なソースコード。
* これらの操作を制御するスクリプト。
* 対象作品が特に依存するインターフェース定義と関連ソースコード。
* 対象作品に加えた変更。

システムライブラリ、汎用ツール、他のソースコードから自動的に再生成できる部分は、ライセンスの定義により除外される場合があります。実際のビルド方法と提供方法に基づいて確認してください。

## 第三者コンポーネントとコンテンツ

Cherry Studio のリポジトリとインストーラーには、異なるライセンスの依存関係、フォント、アイコン、モデル情報、その他のリソースが含まれる場合があります。

AGPL-3.0 は、その対象となる Cherry Studio のコードに適用されます。第三者コンポーネントの独立したライセンスを自動的に AGPL-3.0 へ置き換えるものではありません。再配布前に次の事項も確認してください。

* リポジトリとインストーラーに付属する第三者に関する表示。
* 依存関係自体のライセンスと NOTICE の要件。
* 商標、Logo、画像、フォント、データセットに対する個別の許諾。
* 追加したコードとリソースを再配布する権利があるか。

ソフトウェアライセンスは、Cherry Studio の名称、Logo、その他のブランド資産を使用するための商標許諾ではありません。

## 無保証と責任の制限

AGPL-3.0 第 15～17 節には、無保証と責任制限の条項があります。法律で認められる範囲において、ソフトウェアは現状のまま提供され、品質、性能、適合性に関するリスクは利用者が負います。
