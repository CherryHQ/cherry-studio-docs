# カスタムCSSの設定をクリアする

カスタムCSSの構文エラーやセレクタエラーは、ボタンを覆い隠したり、テキストを非表示にしたり、スクロールを防止したり、さらには設定画面自体にアクセスできなくさせたりすることがあります。インターフェースがまだ使用できるかどうかによって、以下の回復方法を選択してください。

## 方法1：設定からクリアする

設定を開ける場合は以下を実行します。

1. **設定 > 一般設定 > カスタムCSS** に移動します。
2. トラブルシューティングに必要なCSSをテキストファイルにコピーします。
3. エディタ内のすべてを選択して削除します。
4. インターフェースが復旧するのを待ちます。
5. Cherry Studioを完全に終了し、再度開き、問題が再発しないことを確認します。

これが推奨される方法です。エディタをクリアすると、保存されているカスタムCSS設定も削除されます。

## 方法2：開発者ツールで一時的にインターフェースを復元する

誤ったスタイルによって設定画面が使用できなくなった場合は、まず現在のウィンドウから注入されたスタイルノードを削除します。

{% hint style="warning" %}
以下のコマンドは**現在のウィンドウのみを一時的に復元します**。再読み込みまたはアプリの再起動を行う前に、必ず設定に戻りCSSをクリアする必要があります。そうしないと、誤ったスタイルが再表示されます。
{% endhint %}

### 1. 開発者ツールを開く

いずれかの方法を使用してください。

- Windows / Linux: <kbd>Ctrl</kbd> + <kbd>Shift</kbd> + <kbd>I</kbd> を押します。
- macOS: <kbd>Command</kbd> + <kbd>Option</kbd> + <kbd>I</kbd> を押します。
- アプリメニュー: **表示 > 開発者ツールを切り替え** を選択します。
- ページ上の空の領域を右クリックし、**検証** を選択します。

### 2. コンソールを開く

開発者ツールの最上部にある **コンソール** を選択します。開発者ツールをドッキングするとスペースが不足する場合、別ウィンドウに移動させてください。

### 3. 現在のスタイルを削除する

コンソールに以下の行を手動で入力し、Enterキーを押します。

```javascript
document.getElementById('user-defined-custom-css')?.remove()
```

コマンド実行後、カスタムCSSは現在のメインウィンドウから即座に削除されているはずです。

一部のChromiumバージョンでは、コンソールへの直接貼り付けがブロックされることがあります。開発者ツールに表示されるセキュリティプロンプトに従うか、この短いコマンドを手動で入力してください。不明なソースからの他のスクリプトは貼り付けないでください。

### 4. 保存されたCSSを削除する

現在のウィンドウを再読み込みしたり閉じたりしないでください。直ちに以下を実行します。

1. Cherry Studioに戻ります。
2. **設定 > 一般設定 > カスタムCSS** を開きます。
3. エディタをクリアします。
4. 開発者ツールを閉じます。
5. アプリケーションを完全に終了し、再度開きます。

再起動後にインターフェースが正常に動作する場合、保存されていたCSSはクリアされています。

## 問題のあるルールのみを削除する

テーマの他の部分は保持したい場合は以下を実行します。

1. 方法2を使用して一時的にインターフェースを復元します。
2. エディタ内のすべてのCSSを外部のテキストファイルにコピーします。
3. エディタをクリアし、アプリが復旧することを確認します。
4. 一度に小さなセクションだけを復元します。
5. ライトモード、ダークモード、チャット、設定、ダイアログなどを個別に確認します。

問題が再発した場合は、最後に復元したルールからトラブルシューティングを始めるのが最も良いでしょう。

一般的な原因には以下のようなものがあります。

- `}`, `;`、または引用符の欠落
- `display: none`、`position: fixed`、または極端に高い `z-index` を使用するグローバルな上書き設定
- すべてのボタン、入力フィールド、スクロールコンテナを非表示にするルール
- `body[theme-mode="dark"]` のような古いクラス名やレガシーなテーマセレクタ
- `!important` の広範な使用
- 現在のDOM構造と互換性のないサードパーティ製テーマ

## よくある質問

### コマンド実行後も何も変わらない場合

コンソールがCherry Studioのメインページに接続されていることを確認してください。ミニアプリのウェブページや開発者ツール自体には接続されていません。このコマンドを再度実行してください。

```javascript
document.getElementById('user-defined-custom-css')
```

`null` が返された場合は、現在のウィンドウにこのスタイルノードが存在しないことを意味します。問題はカスタムCSSによるものではないか、またはコマンドが間違ったページコンテキストで実行されている可能性があります。

### 再起動後に問題が再発する場合

これは、保存されている設定をクリアせずに、現在のページからスタイルノードのみを削除したために発生します。方法2を再度実行し、ページを再読み込みすることなくCSSエディタを開いて内容をクリアしてください。

### キーボードショートカットで開発者ツールが開かない場合

アプリメニューから **表示 > 開発者ツールを切り替え** を試すか、右クリックして **検証** を選択してみてください。システムのキーボードショートカットユーティリティがデフォルトのキーの組み合わせをインターセプトしている可能性があります。

### 設定画面を開けないままの場合

アプリケーションのデータディレクトリ全体を削除したり、データベースを直接編集したりしないでください。現在のバージョン番号、システム情報、ログディレクトリは保持し、公式フィードバックチャネルを通じてサポートを求めてください。

### CSSをクリアしてもカスタムスタイルが残る場合

オペレーティングシステムのテーマ、Cherry Studioの組み込みテーマカラー、フォント設定、またはサードパーティ製のウィンドウツールが有効になっていないか確認してください。これらはカスタムCSSとは別物であり、本ページの手順ではリセットされません。

## 再発防止策

- ルールは一度に小さなセクションだけを追加します。
- 変更を加える前に動作するバージョンを保存します。
- 内部クラス名やDOM階層に頼るよりも、意味的な変数（セマンティック変数）の上書きを優先します。
- Cherry Studioをアップグレードした後は、複雑なテーマはセクションごとに検証する前に無効化します。
- 読み取り可能で理解できるサードパーティのCSSのみを使用します。

詳しい書き方については、[カスタム CSS](css.md) を参照してください。
