# ストレージ場所の変更

Cherry Studio アプリケーションのデータディレクトリには、データベース、内部ファイル、ナレッジベース、メモ、および一部の実行時状態が保存されています。システムドライブの空き容量が不足している場合や、オンラインで接続されている別のローカルドライブにデータを移動したい場合は、アプリ内からディレクトリを移行してください。

{% hint style="danger" %}
データディレクトリの変更はリスクの高い操作です。必ず復元可能なバックアップを作成し、必要なファイルが含まれていることを確認してください。移行中は、アプリを終了したり、シャットダウンしたり、ターゲットドライブを取り外したりしないでください。
{% endhint %}

## 現在のディレクトリの表示

**設定 > データ設定 > データディレクトリ** を開き、**アプリデータ**の行に表示されている現在のパスを確認します。パスをクリックするか、**ディレクトリを開く**をクリックすると、システムファイルマネージャーで開かれます。

設定に表示されるパスは、現在のインスタンスにとって正確であり、オンラインで見つかるデフォルトのパスよりも優先されます。

一般的なデフォルトの場所には以下が含まれます。

| システム | 一般的な場所 |
| --- | --- |
| macOS | `~/Library/Application Support/CherryStudio` |
| Windows | `%APPDATA%\CherryStudio` |
| Linux | `~/.config/CherryStudio` |
| Windows ポータブル版 | プログラムの隣にある `data` フォルダ |

インストール方法、古いバージョン、ポータブルビルドによって使用されるパスが異なる場合があります。アプリに表示されているパスを使用してください。

## 影響を受けるもの

アプリのデータディレクトリには通常、以下が含まれます。

- ローカルの Cherry Studio データベース。
- アプリによって内部的に管理されるファイル。
- ナレッジベースとメモのデータ。
- インストールされたリソースやワークスペースの一部。
- Chromium / Electron のセッションおよびネットワーク状態。
- 一部のログとキャッシュ。

ディレクトリと一緒に移動しない可能性のあるもの：

- ディレクトリの外にあり、Cherry Studio から参照されているのみのファイル。
- オペレーティングシステムにインストールされたフォントやシステムレベルの設定。
- ユーザーのホームディレクトリ直下にある独立した Cherry Studio のインフラストラクチャディレクトリ。
- サードパーティ製アプリ、クラウドサービス、またはモデルサービス内のデータ。

アプリのデータディレクトリの変更を完全なバックアップ方法として扱わないでください。

## 移行の準備

1. **設定 > データ設定** でローカルバックアップを作成するか、[WebDAV](../data-settings/WebDAV.md) / [S3互換ストレージ](../data-settings/s3-compatible.md) を使用します。
2. アップロードしたファイルを保持する必要がある場合は、「バックアップ中にファイルデータをスキップする」が有効になっていないことを確認してください。
3. アクティブな生成、ナレッジベース処理、ファイルインポート、同期タスクを停止します。
4. ターゲットドライブに十分な空き容量があり、安定した接続があり、現在のユーザーに書き込み権限があることを確認します。
5. ターゲットとして**空のフォルダ**を作成します。
6. 現在のパスを記録し、移行が検証されるまで元のディレクトリを保持してください。

{% hint style="warning" %}
ネットワーク共有、オンデマンドのクラウド同期ディレクトリ、または頻繁に取り外されるリムーバブルドライブは避けてください。データベースと実行時状態には、継続的で安定したローカルファイルアクセスが必要です。
{% endhint %}

## ターゲットディレクトリの選択

1. **設定 > データ設定 > データディレクトリ** を開きます。
2. **アプリデータ**の右側にある変更ディレクトリアイコンをクリックします。
3. ターゲットフォルダを選択または作成します。
4. 確認ダイアログで「**元のパス**」と「**新しいパス**」を確認します。
5. 「**データのコピー**」を有効にするかどうかを決定します。
6. 確認後、アプリが移行と再起動を完了するまで待ちます。

Cherry Studio が拒否するターゲット：

- ドライブまたはファイルシステムのルート。
- 現在のアプリデータディレクトリ自体、またはその内部のディレクトリ。
- Cherry Studio のインストールディレクトリ。
- 現在のユーザーに書き込み権限がないディレクトリ。

## 「データのコピー」スイッチ

### 有効の場合

アプリが再起動した後、元のディレクトリから新しいディレクトリへデータをコピーします。これを使用すると、現在の会話、アシスタント、ファイル、ナレッジベースを保持したまま移動できます。

- 空のディレクトリを推奨します。
- コピー時間は、ファイルの数、ナレッジベースのサイズ、ドライブの速度によって異なります。
- アプリは複数回再起動する場合があります。
- コピー中に強制終了しないでください。

### 無効の場合

ディレクトリのみが切り替わり、古いデータはコピーされません。新しいディレクトリは最初は空の Cherry Studio 環境として表示されることがありますが、古いデータは元のディレクトリに残ります。

これを無効にするのは、新しくクリーンなデータディレクトリを意図的に作りたい場合、または別の方法でターゲットディレクトリを準備した場合のみです。

{% hint style="danger" %}
ターゲットディレクトリが空でない状態で続行すると、既存のファイルが上書きされ、データ損失やコピー失敗のリスクがあります。内容を置き換えることができない限りは、キャンセルして空のディレクトリを選択してください。
{% endhint %}

## 移行後の確認

移行直後に元のディレクトリを削除しないでください。以下の順序で確認してください。

1. **設定 > データ設定 > データディレクトリ** を開き、新しいパスが表示されていることを確認します。
2. ランダムにいくつかの過去のトピックとアシスタントを開きます。
3. ナレッジベース、メモ、内部ファイルが利用可能であることを確認します。
4. テスト会話を作成し、正常に終了します。
5. Cherry Studio を再度起動し、新しいデータが保持されていることを確認します。
6. もう一度バックアップを作成します。

元のディレクトリをアーカイブまたは削除するかどうかを決定する前に、少なくとも2回の完全な起動を行い、しばらくアプリを使用してください。

## 別のリムーバブルドライブの使用

データディレクトリが外付けドライブにある場合：

- Cherry Studio を開始する前にドライブを接続します。
- 同じマウントポイントまたはドライブレターを維持します。
- アプリ実行中にドライブを取り外さないでください。
- システムスリープ、アップデート、またはバックアップの前に、ドライブがオンラインであることを確認してください。

初回起動が新規インストールのように見える場合は、まずアプリを終了し、リセットしたり大量の新しいデータを生成したりしないでください。元のドライブを再接続し、そのパスとドライブレターを確認してから、再度起動してチェックを行ってください。

## 元のディレクトリへの戻り方

新しいディレクトリが正しく動作しない場合：

1. 新しいディレクトリも古いディレクトリも削除しないでください。
2. アクセス可能なデータがあればすべてバックアップします。
3. **データディレクトリ** で元のディレクトリを再度選択します。
4. 元のディレクトリに完全なデータが残っている場合は、どちらの方向にも上書きしないよう **データのコピー**を無効にします。
5. 再起動し、「移行後の確認」の手順を繰り返します。

アプリが実行されている間に、2つのデータディレクトリを手動でマージしないでください。同じ名前のデータベース、設定、および実行時状態ファイルは、通常のファイル上書きでは安全にマージできません。

## よくある質問

### ドライブのルートを選択できない場合

これは保護機能です。ドライブ上に `CherryStudioData` のような専用のサブディレクトリを作成し、それを選択してください。

### アプリが書き込み権限がないと報告する場合

ディレクトリの所有者と権限を確認するか、現在のアカウントから書き込み可能な場所を選択してください。管理者としてアプリを恒久的に実行することで問題を回避しないでください。

### 移行に時間がかかる場合

大きなファイルやナレッジベースはコピー時間を増加させます。すぐに強制終了するのではなく、まずドライブがまだアクティブかどうかを確認してください。最終的に失敗した場合は、元のディレクトリを保持し、アプリのログを確認してください。

### 再起動後も元のパスが表示される場合

移行でエラーが報告されなかったか、ターゲットドライブがまだオンラインであるか、ディレクトリの権限が正しいかを確認してください。すぐに元のディレクトリを削除しないでください。数回の再起動でも切り替わらない場合は、バージョン、システム、およびログの詳細を公式チャネルから報告してください。

### 新しいディレクトリに外部ファイルがない場合

アプリは管理しているデータディレクトリのみを移行します。他の場所に存在する外部ファイルは自動的にはコピーされません。それらの元のパスにアクセスできるようにするか、個別に移行して再リンクしてください。

***

### ヘルプの取得とフィードバックの送信

移行中に問題が発生した場合は、両方のディレクトリとログを保持し、[フィードバックと提案](../question-contact/suggestions.md) に記載された公式窓口からお問い合わせください。
