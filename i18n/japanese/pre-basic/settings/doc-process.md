# 文書処理

文書処理は、画像をプレーンテキストに変換したり、PDFなどの文書をMarkdownに変換して、後続の検索、解析、ナレッジベースのインデックス作成に使用します。

Cherry Studio V2 は処理能力を2種類に分類しています：

| 能力 | 入力 | 出力 | 一般的な用途 |
| --- | --- | --- | --- |
| 画像をテキストに変換（OCR） | 画像ファイル | プレーンテキスト | スクリーンショットやスキャン画像からの文字抽出 |
| 文書を Markdown に変換 | 文書ファイル | Markdown および関連リソース | タイトル、段落、表などの構造を保持し、ナレッジベースでのさらなる処理に利用 |

2つの能力それぞれでデフォルトのプロセッサーを選択します。同じサービスが両方の能力をサポートする場合、リストに2回表示され、設定とデフォルト状態も個別に管理されます。

## 文書処理設定を開く

**設定 > 文書解析** に移動します。

左側には、現在デバイスで利用可能な機能が以下の順序でリスト表示されます：

1. 画像をテキストに変換：System OCR、Tesseract OCR、PaddleOCR、Mistral、Intel OV OCR。
2. 文書を Markdown に変換：Mistral、MinerU、Doc2x、Open MinerU、PaddleOCR。

プロセッサーはプラットフォームと実行環境に基づいてフィルタリングされます。リストが本文と完全に一致しない場合は、アプリケーションの実際の表示に従ってください。

{% hint style="warning" %}
V2 では、画像または文書のデフォルトプロセッサーは初期設定されません。設定完了後、対応する機能項目で **デフォルトに設定** をクリックする必要があります。APIキーのみを入力しても自動的にはデフォルトになりません。
{% endhint %}

## プロセッサー能力比較

### 画像をテキストに変換

| プロセッサー | 実行場所 | 認証情報 | 対応範囲 |
| --- | --- | --- | --- |
| System OCR | ローカル | なし | macOS および Windows；システムOCRの直接呼び出し |
| Tesseract OCR | ローカル | なし | macOS、Windows、Linux；言語パックを選択可能 |
| PaddleOCR | API またはセルフホストサービス | API Key | 画像OCR；PaddleOCR解析モデルを選択可能 |
| Mistral | Mistral API | API Key | 画像をテキストに変換 |
| Intel OV OCR | ローカル | なし | 条件を満たすWindows搭載のIntel Core Ultraデバイスでのみ表示 |

System OCRはLinuxをサポートしていません。Intel OV OCRは、必要なローカル実行スクリプトがアプリケーションによって検出される必要があるため、すべてのIntelデバイスで利用できるわけではありません。

### 文書を Markdown に変換

| プロセッサー | デフォルトAPIアドレス | 認証情報 | 説明 |
| --- | --- | --- | --- |
| Mistral | `https://api.mistral.ai` | API Key | Mistral OCRを使用して文書を解析します |
| MinerU | `https://mineru.net` | API Key | リモート解析ジョブを送信し、結果をポーリングします |
| Doc2x | `https://v2.doc2x.noedgeai.com` | API Key | リモート解析およびエクスポートジョブを送信します |
| Open MinerU | `http://127.0.0.1:8000` | オプション | セルフホストされたMinerU互換サービスに接続します |
| PaddleOCR | `https://paddleocr.aistudio-app.com/` | API Key | 文書解析をサポートし、セルフホストアドレスに変更することも可能です |

表中のアドレスは現在の組み込み値です。サービスプロバイダーのインターフェースが変更された場合や、自己構築のリバースプロキシまたはプライベートデプロイメントを行う場合は、インターフェース内で**APIアドレス (Base URL)** を変更できます。

{% hint style="info" %}
リモートプロセッサーは、処理対象ファイルを対応するサービスに送信します。契約書、顧客資料、その他の機密ファイルを処理する前には、必ずサービスプロバイダーのデータ処理、保持、およびコンプライアンスポリシーを確認してください。ファイルがローカルに残ることを希望する場合は、利用可能なローカルプロセッサーまたは信頼できるセルフホストサービスを選択する必要があります。
{% endhint %}

## ローカル OCR の設定

### System OCR

System OCR は macOS と Windows でのみ表示されます。選択すると、システム OCR が利用可能であることがページに表示され、API キーやアドレスの入力は不要です。

- macOS では、システムが提供する OCR 機能を使用し、言語セレクターは表示されません。
- Windows では、「**言語**」で認識言語を選択できます。必要な言語は引き続きオペレーティングシステムによってサポートされている必要があります。

「**デフォルトに設定**」をクリックすると、System OCR が画像のテキスト変換のデフォルトプロセッサーになります。

### Tesseract OCR

Tesseract は 3 つのデスクトッププラットフォームすべてで使用でき、ローカルで実行されます。

「**言語**」で認識したい言語を一つ以上選択してください。何も選択されていない場合、現在のバージョンでは簡体字中国語、繁体字中国語、および英語がデフォルトの組み合わせとして使用されます。

言語が多いほど正確になるとは限らず、処理時間が増加する可能性もあります。画像に実際に含まれている言語のみを選択するのが通常より適切です。

### Intel OV OCR

Intel OV OCR は、以下の条件がすべて満たされた場合にのみ表示されます。

- Windows システム；
- CPU モデルに Intel および Ultra が含まれること；
- アプリケーションのインストール中に必要な OV OCR 実行スクリプトが存在すること。

これは「すべての Intel グラフィックカードで利用可能」という汎用的なオプションではありません。リストに表示されない場合は、現在の環境が利用可能性チェックを通過していないことを示します。

## API プロセッサーの設定

PaddleOCR、Mistral、MinerU、Doc2x はすべて API キーが必要です。Open MinerU のキーはオプションであり、必要かどうかはサーバーサイドの実装によります。

### API キーの入力

**API キー (API Key)** 入力フィールドに直接 1 つ以上のキーを入力するか、カンマで区切って複数入力できます。また、入力フィールド右側のリストボタンをクリックして、個別に新規追加、編集、コピー、または削除することも可能です。

保存時に自動的に以下の処理が行われます：

- 前後の空白の除去；
- 空の値の無視；
- 重複するキーのマージ。

複数のキーを設定した場合、同じプロセッサーが新しいタスクを開始する際に順番にローテーションして使用されます。画像と文書の機能は、このプロセッサーのキーリストを共有します。

スクリーンショット、問題報告、または設定の共有時に完全なキーを漏洩させないでください。

### API アドレスの変更

**API アドレス (Base URL)** は入力フィールドからフォーカスが外れたときに検証され、保存されます。アドレスが無効な場合、ページに警告が表示され、その値は適用されません。

セルフホストまたはプロキシのアドレスを使用する場合：

1. サービスが、単なる OpenAI 互換のチャットインターフェースではなく、対応するプロセッサーが必要とするインターフェースを実装していることを確認してください。
2. 正しい `http://` または `https://` プロトコルを保持してください。
3. Cherry Studio が動作するデバイスからそのアドレスにアクセスできることを確認してください。
4. アドレスがローカルネットワークサービスを指す場合は、ファイアウォール、ポート、証明書を確認してください。

### PaddleOCR モデルの選択

PaddleOCR ページでは以下を選択できます：

- `PaddleOCR-VL-1.5`
- `PaddleOCR-VL`
- `PP-StructureV3`
- `PP-OCRv5`

組み込みのデフォルト値は `PaddleOCR-VL-1.5` です。選択されたモデルは、対象の PaddleOCR サービスによってサポートされている必要があります。セルフホスト版で利用可能なモデルは、クラウド版と異なる場合があります。

セルフホストの参考として、[PaddleOCR プロジェクト](https://github.com/PaddlePaddle/PaddleOCR)へのリンクがあります。Cherry Studio がサーバーのインストールや保守を代行することはありません。

## それぞれのデフォルトプロセッサーを設定する

画像をテキストに変換する場合と、文書を Markdown に変換する場合のデフォルト値は互いに独立しています。

1. 左側で、画像をテキストに変換するためのプロセッサーを選択します。
2. ローカル言語または API の設定を完了します。
3. **デフォルトに設定** をクリックします。
4. 次に、文書を Markdown に変換するためのプロセッサーを選択します。
5. API の設定を完了し、**デフォルトに設定** をクリックします。

デフォルトに設定すると、左側の項目と詳細ページの両方に **デフォルト** マークが表示されます。

同じプロセッサーが2つの機能をサポートする場合、API Key はプロセッサーレベルで共有されますが、API アドレスとモデル値は機能ごとに個別に保存されます。一方の機能のアドレスを変更しても、もう一方の機能も同期的に変更されるとは限りません。

## ナレッジベースとの関係

ナレッジベースのドキュメントファイルは、まず Markdown に変換してから、チャンキング、埋め込み、インデックス作成を行うことができます。関連するフローについては、[ナレッジベースの文書前処理](../../knowledge-base/zhi-shi-ku-wen-dang-yu-chu-li.md)を参照してください。

{% hint style="warning" %}
各ナレッジベースは独自のファイルプロセッサー選択を保存します。ここでのグローバルデフォルト設定は、既存のナレッジベースの設定を自動的に上書きしませんので、必ずナレッジベースの RAG 設定で **ファイル処理** 項目も確認してください。
{% endhint %}

プロセッサーを切り替えても、既に完了したインデックス作成が自動的に再実行されるわけではありません。古いドキュメントを新しいプロセッサーで使用したい場合は、ナレッジベース機能が提供する方法に従って再処理または再インポートする必要があります。

文書処理はコンテンツ変換のみを担当し、埋め込みモデルに取って代わるものではありません。変換された Markdown は、引き続き[埋め込みモデル](../../knowledge-base/emb-models-info.md)によってベクトルインデックスを構築する必要があります。

## 設定の検証

現在のドキュメント解析設定ページには、独立した「接続テスト」ボタンがありません。最も信頼性の高い検証方法は以下の通りです。

1. 目的の機能にデフォルトのプロセッサーを設定します。
2. ナレッジベースの場合、そのナレッジベースの RAG 設定で同じ文書プロセッサーを選択します。
3. 機密情報を含まない小規模なテスト画像またはドキュメントを使用して、実際の処理を一度実行します。
4. タスクが完了したか、また出力されたテキスト、タイトル、表、段落が期待通りであるかを確認します。

異なるプロセッサーのファイルサイズ、ページ数、フォーマット、クォータ、および並行処理制限はサーバー側で決定されるため、対応するサービスの現在のルールを基準としてください。

## よくある質問

### リストに System OCR がない場合

System OCR は macOS および Windows のみがサポートされています。Linux の場合は、Tesseract、PaddleOCR、または利用可能な他のプロセッサーを使用してください。

### リストに Intel OV OCR がない場合

このプロセッサーは、要件を満たす Windows 版の Intel Core Ultra 環境でローカルコンポーネントが存在する場合にのみ表示されます。API アドレスを手動で入力しても表示させることはできません。

### API Key を入力したが、処理時にデフォルトプロセッサーがないと表示される場合

Key とデフォルトプロセッサーは独立した設定項目です。対応する機能のプロセッサーページに戻り、**デフォルトに設定** をクリックしてください。

### API Key がたくさんある場合、どう管理しますか？

Key 入力欄の右側にあるリストボタンから個別に管理してください。重複する Key は重ねて保存されず、複数の有効な Key は、このプロセッサーで新しいタスクを開始するたびに順番に切り替えて使用されます。

### セルフホストサービスが接続できない場合

Base URL、ポート、ファイアウォール、HTTPS 証明書、およびサーバーインターフェースのバージョンを確認してください。PaddleOCR と Open MinerU はそれぞれ互換性のあるインターフェースを必要とし、一般的なチャットモデルの API アドレスを直接入力することはできません。

### プロセッサーを変更したが、既存のナレッジベースに変更がないのはなぜですか？

ナレッジベースは独立したファイル処理プロセッサー選択で保存されるため、インデックスが完了しても自動的に再構築されません。ナレッジベースの RAG 設定を修正し、必要に応じて関連ドキュメントを再処理してください。

上記でも解決しない場合は、[フィードバックと提案](../../question-contact/suggestions.md) から、OS、プロセッサー名、ファイルタイプ、エラーメッセージ、および匿名化した設定のスクリーンショットを提出してください。
