# カスタムプロバイダー

カスタムプロバイダーは、Cherry Studio にまだ組み込まれていないクラウドプラットフォーム、OpenAI 互換プロキシ、LAN ゲートウェイ、セルフホストモデルサービスへ接続するために使用します。

Cherry Studio V2 には、次の 2 つの作成方法があります。

| 方法 | 用途 | 主な特徴 |
| --- | --- | --- |
| カスタムプロバイダーを追加 | 新しいプラットフォーム、OpenAI 互換サービス、ローカル推論サービス | デフォルトでは OpenAI Chat Completions を主なチャットプロトコルとして使用 |
| プリセットプロバイダーからインスタンスを追加 | 同じ事業者の 2 つ目のアカウント、リージョン、ゲートウェイ、プライベートアドレス | 元のプロバイダーの認証方式、デフォルトプロトコル、専用アダプターを維持 |

{% hint style="info" %}
対象プラットフォームにプリセットプロバイダーがある場合は、まずそのプロバイダーの別インスタンスを追加してください。完全なカスタムプロバイダーは標準互換インターフェース向けであり、特定事業者専用の認証、画像タスク、パラメーターアダプターは自動的に追加されません。
{% endhint %}

## 利用前の準備

作成する前に、対象サービスの公式ドキュメントで次の点を確認します。

1. 使用する API プロトコル
2. Web コンソールのアドレスではなく Base URL
3. API Key またはその他の認証方式
4. モデル一覧インターフェースが利用可能か
5. 呼び出す完全な Model ID
6. モデルがビジョン、思考、ツール、Embedding、Rerank に対応しているか
7. 追加のリクエストヘッダーが必要か
8. IP 許可リスト、プロキシ、証明書の要件があるか

「インターフェースが互換」というだけでは不十分です。レスポンスフィールド、ストリーミング形式、ツール呼び出し、思考内容、エラー構造も、選択したプロトコルと互換性がある必要があります。

## 作成方法の選択

### 完全なカスタムプロバイダーを追加

適しているケース：

- OpenAI 互換クラウドサービス
- OneAPI、NewAPI などの統合ゲートウェイ
- vLLM、LocalAI などのセルフホストサービス
- 企業内部の互換プロキシ
- プリセット一覧にまだないプラットフォーム

V2 の完全なカスタムプロバイダーでは、デフォルトのメインエンドポイントとして次を使用します。

```text
OpenAI Chat Completions
```

作成時に、旧版の「OpenAI / Gemini / Anthropic / Azure OpenAI」プロバイダータイプのドロップダウンは使用しません。

### プリセットプロバイダーからインスタンスを追加

適しているケース：

- 同じプロバイダーで複数の独立したアカウントを使用する
- リージョンごとに異なる Base URL を使用する
- 企業プロキシと公式アドレスを併用する
- Azure、Vertex AI、Bedrock などの専用認証を維持する必要がある
- プロバイダー専用の画像、思考、モデル同期アダプターを維持する必要がある

プリセットプロバイダーのグループで**インスタンスを追加**をクリックするか、プロバイダーのメニューを開いて同じ操作を選択します。新しいインスタンスを作成した後、自分の認証情報とアドレスを入力します。

{% hint style="warning" %}
プリセットプロバイダーをコピーしても、複製されるのは設定構造だけで、元のインスタンスの機密認証情報はコピーされません。作成後、新しいインスタンスの詳細ページで認証情報を入力し直してください。
{% endhint %}

## 完全なカスタムプロバイダーの追加

1. `設定 → モデルサービス`を開きます。
2. 必要に応じて、フィルターを**すべてのプロバイダー**に切り替えます。
3. プロバイダー検索欄の右側にある `+` をクリックします。
4. 識別しやすいプロバイダー名を入力します。
5. 組み込みアイコンを選択するか、独自のアイコンをアップロードできます。
6. メインの Base URL を入力します。
7. 必要に応じて、最初の API Key を入力します。
8. プラットフォームが他の互換プロトコルも提供している場合は、**その他のエンドポイント**を展開します。
9. **追加**をクリックします。
10. 新しいプロバイダーの詳細ページでモデルの設定を続けます。

名前は表示だけに影響し、リクエストプロトコルは変更しません。プラットフォーム、リージョン、用途を名前に含めることをおすすめします。たとえば「社内ゲートウェイ-東京」です。

## Base URL の入力

Base URL はインターフェースのルートアドレスであり、完全なリクエストアドレスではありません。

OpenAI Chat Completions の例：

```text
正しい：https://api.example.com/v1
誤り：https://api.example.com/v1/chat/completions
誤り：https://console.example.com/models
```

V2 はエンドポイントタイプに応じて具体的なリクエストパスを追加します。`/v1`、`/v1beta`、またはカスタムパスが必要かどうかは、対象サービスの公式ドキュメントに従ってください。

{% hint style="warning" %}
他のクライアントに表示された「プロキシアドレス」をそのままコピーしないでください。求められているものが Base URL であることを確認する必要があります。同じプラットフォームでも、ツールによってルートアドレスまたは完全なリクエストアドレスのどちらを入力するかが異なる場合があります。
{% endhint %}

### ローカルホストと LAN のアドレス

ローカルサービスでよく使用されるアドレス：

```text
http://127.0.0.1:8000/v1
```

サービスが Docker、仮想マシン、別のコンピューターで動作している場合、`localhost` が示す機器は異なることがあります。Cherry Studio を実行しているコンピューターからアクセスできるアドレスを使用し、ファイアウォールと待ち受けネットワークインターフェースを確認してください。

HTTPS サービスで自己署名証明書を使用している場合は、システムの証明書検証によって接続が拒否されることもあります。証明書の問題を解決するために、コンピューター全体のセキュリティ検証を無効にしないでください。

## その他のエンドポイントの設定

完全なカスタムプロバイダーの作成ページでは、次のエンドポイントも追加できます。

- Anthropic Messages
- Google Gemini
- OpenAI Responses

作成後、API Host の右側にある**リクエスト設定**を開いて、エンドポイントを追加または変更することもできます。

これらのアドレスは、同じプロバイダーが提供する異なるプロトコルの入口を記述するためのものです。OpenAI だけに対応するモデルが、自動的に Anthropic または Gemini モデルへ変わるわけではありません。

通常の手動追加カスタムモデルでは、引き続きプロバイダーのデフォルトエンドポイントが主なプロトコルになります。特定事業者のプロトコルまたは専用認証が必須の場合は、対応するプリセットプロバイダーからインスタンスを追加してください。

## API Key と複数 Key

作成時に最初の API Key を入力することも、空欄にして後から設定することもできます。

プロバイダーの詳細ページでは、次の操作ができます。

- 複数の Key を追加
- 識別しやすいラベルを Key に追加
- 特定の Key を一時停止
- 無効または漏えいした Key を削除

リクエストに使用できるのは、有効になっている Key だけです。複数の Key が同じモデル、残高、組織権限を持つかどうかは、引き続きサーバー側で決まります。

{% hint style="danger" %}
実際の API Key をドキュメント、チャット、公開リポジトリ、スクリーンショット、カスタムリクエストヘッダーの例に記載しないでください。漏えいした場合は、直ちにサーバー側で取り消してください。
{% endhint %}

認証を必要としないローカルサービスでは、Key を入力しなくてもかまいません。フォームを通過するためだけに、本番環境の認証情報を適当に入力しないでください。

## カスタムリクエストヘッダー

API Host の右側にあるリクエスト設定ボタンをクリックすると、一覧または JSON 形式で追加のリクエストヘッダーを入力できます。

一般的な用途：

- 組織またはプロジェクトの識別子
- 企業ゲートウェイのテナントヘッダー
- プロキシが要求するバージョンヘッダー
- サーバー側で明示的に必要とされるカスタム認証ヘッダー

入力する前に、次の点に注意してください。

1. 公式ドキュメントで明示的に必要とされるフィールドだけを追加します。
2. `Content-Type` を重複して上書きしないでください。
3. API Key とカスタムヘッダーの両方で、競合する `Authorization` を設定しないでください。
4. JSON モードではオブジェクトを入力する必要があります。
5. オブジェクトの値は文字列として送信されます。
6. 変更後、接続チェックを再実行します。

リクエストヘッダーは、関連するリクエストとともに対象アドレスへ送信されます。信頼できないプロキシに機密ヘッダーを送らないでください。

## プロバイダーの有効化

作成後：

1. 新しいプロバイダーを選択します。
2. API Key と API Host を確認します。
3. プロバイダーのスイッチをオンにします。
4. モデルを同期または手動追加します。
5. 実際に必要なモデルだけを有効にします。
6. ヘルスチェックを実行します。

プロバイダーが無効になっていると、モデルを追加済みでも、対応するモデル選択位置には正常に表示されません。

## モデルの同期

OpenAI 互換サービスでは、V2 はデフォルトで次のアドレスからの取得を試みます。

```text
GET {Base URL}/models
```

対象サービスがモデル一覧インターフェースを正しく実装している場合、Cherry Studio は同期プレビューを表示します。適用前に次を確認してください。

- 新しいモデル
- 更新されるモデル
- サーバー側から削除されたモデル
- Model ID と表示名
- モデルの機能が正しく認識されているか

同期に失敗しても、チャットインターフェースが必ず失敗するとは限りません。一部のサービスは Chat Completions だけを実装し、`/models` を実装していません。この場合は、モデルを手動で追加してください。

## モデルの手動追加

1. モデル一覧で**モデルを追加**をクリックします。
2. サーバー側が要求する完全な Model ID を入力します。
3. 読みやすい表示名とグループを任意で設定できます。
4. 公式仕様に従ってコンテキストと最大出力を入力します。
5. モデルが実際に対応する機能を選択します。
6. 保存して有効にします。
7. ヘルスチェックを実行します。

手動で設定できる機能：

- 画像理解
- Web 検索
- 思考
- ツール呼び出し
- Embedding
- Rerank

機能ラベルは、画面の絞り込みとリクエストのルーティングに使用され、サーバー側の機能を変更するものではありません。誤ったラベルを設定すると、リクエストが失敗したり、Embedding または Rerank モデルがチャット一覧に誤って表示されたりする場合があります。

{% hint style="warning" %}
Model ID はサーバー側と完全に一致させる必要があります。表示名は変更できますが、リクエスト内の Model ID の代わりに使用することはできません。
{% endhint %}

## 接続チェックとモデルのヘルスチェック

段階的に確認することをおすすめします。

1. まずプロバイダーの接続を確認します。
2. 次に個別のチャットモデルを確認します。
3. ストリーミング出力を個別にテストします。
4. ビジョン、思考、ツール呼び出しを個別にテストします。
5. ナレッジベースで Embedding と Rerank を実際にテストします。

現在の V2 の一般的なヘルスチェックでは Rerank モデルがスキップされるため、Rerank はナレッジベースの検索フローで検証する必要があります。

接続チェックの成功は、次のことを保証しません。

- すべてのモデルへのアクセス権がある
- 十分な残高がある
- ビジョンまたはツール呼び出しが利用できる
- 長いコンテキストが必ず成功する
- サーバー側のすべての拡張パラメーターに互換性がある

## OpenAI 互換機能の境界

完全なカスタムプロバイダーでは、次の標準 OpenAI 互換機能を利用できます。

- Chat Completions
- ストリーミング出力
- ビジョン入力
- Function Calling
- Embeddings
- 標準モデル一覧

利用できるかどうかは、サーバー側と具体的なモデルによって異なります。通常、次の機能は「OpenAI 互換」であるだけでは自動的に利用できません。

- 事業者固有の非同期画像タスク
- 専用ファイルアップロード
- クラウドナレッジベース
- 特殊な思考パラメーター
- 非標準 Rerank
- OAuth、IAM、クラウドアカウント署名
- 事業者固有のモデル同期分類

プロバイダーがこれらの機能を必要とする場合は、プリセットアダプターまたは専用ドキュメントを使用してください。

## vLLM を使用したローカルプロバイダーの作成

vLLM は OpenAI 互換サーバーを提供します。インストール方法とハードウェア要件については、まず[vLLM 公式ドキュメント](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)を参照してください。

チャットテンプレートに対応するモデルでサービスを起動します。

```sh
vllm serve NousResearch/Meta-Llama-3-8B-Instruct \
  --dtype auto \
  --api-key local-test-token
```

デフォルトの待ち受けポートは `8000` です。Cherry Studio で完全なカスタムプロバイダーを追加します。

```text
プロバイダー名：vLLM Local
Base URL：http://127.0.0.1:8000/v1
API Key：local-test-token
```

その後、`/v1/models` を同期するか、vLLM が返す Model ID を手動で追加します。

{% hint style="info" %}
上記の Key はローカルマシンでの例にのみ使用します。LAN またはインターネットに公開する場合は、強力な認証情報、アクセス制御、TLS、ファイアウォールを使用し、認証なしの推論ポートを直接公開しないでください。
{% endhint %}

「chat template がありません」と返された場合は、チャットテンプレートを含むモデルを使用するか、vLLM のドキュメントに従って `--chat-template` を設定してください。

## PDF、添付ファイル、プライバシー

一般的なチャットモデルの場合、Cherry Studio はまずローカルで PDF のテキストを抽出し、その後サーバーへ送信します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書には OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出されたテキストはコンテキストを消費します。
- PDF 内の画像にはビジョンモデルが必要です。

カスタムプロバイダーの Base URL によって、データの最終送信先が決まります。プロキシまたは企業ゲートウェイへ接続する前に、次の点を確認してください。

- 運営者の身元
- データ保持ポリシー
- ログとトレーニングのポリシー
- 国境を越えるデータ転送
- TLS と証明書
- 組織のコンプライアンス要件

## よくある問題

### 401 が返される

API Key が正しくない、認証ヘッダー形式に互換性がない、またはカスタムリクエストヘッダーが正しい `Authorization` を上書きしています。サーバー側の認証説明を再確認してください。

### 403 が返される

Key にモデルまたはプロジェクトの権限がない、IP が許可リストにない、または組織のポリシーによってリクエストが拒否されています。

### 404 が返される

通常は Base URL に完全なリクエストアドレスを入力した、バージョンパスが不足している、またはサーバー側に対応するインターフェースがありません。`/models` と `/chat/completions` を個別に確認してください。

### 400 が返される

モデルが現在のパラメーター、メッセージ形式、画像、思考、ツール呼び出しに対応していません。まずテキストだけのメッセージとデフォルトパラメーターでテストしてください。

### 429 が返される

サーバー側のリクエスト数、Token、同時実行数の上限に達しています。同時実行数を減らし、バックオフして再試行してください。

### モデルの同期結果が空

対象サービスが `/models` を実装していないか、そのインターフェースに別の権限が必要な場合があります。アドレスを確認してから、Model ID を手動で追加してください。

### モデルはチャットできるが画像に失敗する

通常のテキストモデルがビジョンに対応しているとは限りません。モデルの機能と、サーバー側の画像メッセージ形式を確認してください。

### ツールがモデルによって説明されるだけで、実際には呼び出されない

モデルが Function Calling に対応していないか、レスポンス形式に互換性がない可能性があります。まず 1 つの単純なツールで構造化された呼び出しを確認してください。

### Embedding がチャット一覧に表示される

モデルタイプのラベルが正しくありません。モデルを編集して Embedding 機能を有効にし、実際には存在しないチャット機能を無効にしてください。

### Rerank がヘルスチェックに合格しない

一般的なヘルスチェックでは Rerank がスキップされます。ナレッジベースでモデルを設定し、実際に検索を実行してください。

### ローカルサービスをブラウザーで開けるが Cherry Studio から接続できない

ブラウザーでルートページを開けても API が利用可能とは限りません。`/v1/models`、ファイアウォール、待ち受けアドレス、プロキシ、自己署名証明書、チャットテンプレートを確認してください。

### Anthropic または Gemini のアドレスを追加したが、モデルが OpenAI を使用し続ける

完全なカスタムプロバイダーのメインエンドポイントは、デフォルトで OpenAI Chat Completions です。セカンダリエンドポイントを入力するだけでは、通常の手動モデルが自動的にプロトコルを切り替えるとは限りません。対応事業者のプロトコルが必要な場合は、プリセットプロバイダーからインスタンスを追加してください。

一般的な設定については、[モデルサービス](README.md)と[モデルサービス設定](../../cherrystudio/preview/settings/providers.md)を参照してください。vLLM インターフェースについては、[OpenAI-Compatible Server](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)を参照してください。フィードバック方法については、[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
