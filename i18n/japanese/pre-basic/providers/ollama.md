# Ollama

Ollama は macOS、Windows、Linux でローカルモデルを実行できるほか、Ollama Cloud を通じてクラウドモデルを呼び出すこともできます。Cherry Studio V2 は Ollama ネイティブの Chat API を使用し、`/api/tags` から現在のインスタンスで見えるモデルを同期します。

ローカルで実行する場合、モデルの推論とチャットリクエストはデフォルトでデバイス上で処理されます。Cloud モデル、Ollama のクラウド API、またはウェブ検索機能を選択した場合、リクエストは引き続きローカルデバイスの外部へ送信されます。

{% hint style="info" %}
Cherry Studio で**追加**またはモデル同期をクリックしても、Ollama にすでに存在するモデルリストを読み取るだけで、モデルの重みはダウンロードされません。先に Ollama でモデルをプルしてから、Cherry Studio に戻って同期してください。
{% endhint %}

## 使用方法を選択する

| 方法 | Base URL | API Key |
| --- | --- | --- |
| 同じコンピューター上の Ollama | `http://localhost:11434` | 空欄 |
| LAN またはリモートの自前 Ollama | サーバーの実際のアドレス | リバースプロキシによる |
| Ollama Cloud へ直接接続 | `https://ollama.com` | Ollama API Key |
| ローカル Ollama から Cloud モデルを中継 | `http://localhost:11434` | ローカルでログイン後は通常空欄 |

ローカル API はデフォルトで認証を必要としません。API Key が空でない場合、Cherry Studio は `Authorization: Bearer ...` を送信します。これは Ollama Cloud または Bearer 認証を設定したリバースプロキシで使用できます。

## Ollama をインストールする

[Ollama 公式サイト](https://ollama.com/)で対応するシステム版をダウンロードし、インストールします。

Linux では公式インストールスクリプトも使用できます。

```bash
curl -fsSL https://ollama.com/install.sh | sh
```

インストール後、サービスが実行中であることを確認します。

```bash
ollama list
```

コマンドがモデルリストを返せば、Ollama CLI とローカルサービスは基本的に利用できます。

## モデルをプルする

[Ollama モデルライブラリ](https://ollama.com/library)からモデルとタグを選択し、次のコマンドを実行します。

```bash
ollama pull <model>:<tag>
```

例：

```bash
ollama pull gemma3
```

よく使用する管理コマンド：

```bash
ollama list
ollama ps
ollama stop <model>
ollama rm <model>:<tag>
```

- `ollama list`：プル済みのモデルを表示します。
- `ollama ps`：現在読み込まれているモデルと CPU/GPU の使用状況を表示します。
- `ollama stop`：モデルをメモリまたは VRAM からアンロードします。
- `ollama rm`：ローカルのモデルファイルを削除します。

モデルタグは、パラメーター規模、量子化方式、コンテキスト、ディスク使用量に影響します。モデルシリーズ名だけで選ばず、メモリ、VRAM、タスクに応じて具体的なタグを選択してください。

## Cherry Studio で設定する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. **Ollama** を選択します。
4. ローカルで使用する場合は Base URL `http://localhost:11434` を維持します。
5. ローカルサービスの API Key は空欄にします。
6. ページ上部のプロバイダースイッチをオンにします。
7. **追加**をクリックして Ollama のモデルリストを読み取ります。
8. 同期プレビューを確認して変更を適用します。
9. 使用するモデルだけを有効にします。

Cherry Studio は、`http://localhost:11434`、`/v1` を含むアドレス、`/api` を含むアドレスを Ollama ネイティブの `/api` パスへ正規化します。混乱を避けるため、特定の API を含まないホストアドレスを入力することを推奨します。

プルしたばかりのモデルが表示されない場合は、まず `ollama list` に完全に同じタグが表示されることを確認し、もう一度**追加**をクリックしてください。

## API Key と Cloud モデル

### ローカル Ollama から Cloud モデルを使用する

先に Ollama でログインします。

```bash
ollama signin
```

その後、公式の手順に従って `:cloud` タグ付きのモデルをプルまたは実行します。Cherry Studio は引き続き `http://localhost:11434` に接続し、ローカル Ollama がクラウド認証を処理します。

### Ollama Cloud へ直接接続する

1. Ollama アカウントで API Key を作成します。
2. Base URL を `https://ollama.com` に変更します。
3. API Key 欄にそのキーを入力します。
4. クラウドで利用できるモデルを同期します。
5. 接続チェックとモデルのヘルスチェックを実行します。

{% hint style="warning" %}
API Key をチャットメッセージ、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。Cloud Key が漏えいした場合は、Ollama アカウントですぐに取り消し、再作成してください。
{% endhint %}

ローカルモデルが自動的にクラウドモデルへ変わることはありません。モデルタグと現在接続している Ollama ホストを確認し、データが実際に処理される場所を誤解しないようにしてください。

## チャット、ビジョン、ツールモデルを選択する

Ollama モデルの機能はモデル自体とタグによって決まります。Cherry Studio はモデル ID から一般的な機能を認識します。

### 通常のチャット

Ollama Chat API に対応する生成モデルは、すべて基本的なチャットに使用できます。最初のリクエストでは重みを読み込む必要があるため、その後のリクエストより応答が明らかに遅くなる場合があります。

### 画像理解

Ollama モデルライブラリで Vision 対応と明記されているモデルを選択します。同期後、Cherry Studio に画像機能が表示されていることを確認し、小さな画像を 1 枚アップロードしてテストしてください。

- モデル名が似ていても、すべてが画像に対応するとは限りません。
- タグが異なると機能も異なる場合があります。
- 画像はコンテキストとメモリの使用量を増やします。
- モデル ID が自動認識されない場合、表示名だけを変更して機能を偽装しないでください。

### ツール呼び出しと MCP

Cherry Studio で MCP を安定して使用するには、モデルが Tool Calling をネイティブサポートしている必要があります。

1. モデルライブラリでツール呼び出し対応と明記されているモデルを選択します。
2. 先に通常のチャットを完了します。
3. 単純な MCP ツールを 1 つだけ有効にします。
4. ツールを呼び出すようモデルへ明示します。
5. モデルが実際に呼び出しを開始したことを確認します。
6. その後、ツールを追加します。

一部の小規模モデルは「ツールを呼び出す予定」とテキストで出力しても、構造化された呼び出しを生成しません。この場合、プロンプトを繰り返し追加するのではなく、ツール機能の強いモデルへ変更してください。

## 思考モードを設定する

Ollama Chat API は `think` パラメーターで思考を制御します。

- GPT-OSS の段階的推論に対応するモデルには、Cherry Studio から低、中、高を送信できます。
- その他の思考対応モデルは、通常、オンまたはオフだけを受け付けます。
- **オフ**を選択すると `think: false` を送信します。
- デフォルトまたはオンを使用したときの実際の動作は、引き続きモデルによって決まります。

モデルが `think` に対応しておらずパラメーターエラーを返す場合は、思考をオフにするか、正しいモデルタグを使用してください。あるモデルの思考オプションをすべてのローカルモデルにそのまま適用しないでください。

## コンテキストとハードウェア使用量

Ollama の実際のコンテキストは、モデル、サーバー設定、利用可能なメモリによって決まります。コンテキストを長くすると、RAM または VRAM の使用量が大幅に増えます。

Ollama の起動時にデフォルトコンテキストを設定できます。

```bash
OLLAMA_CONTEXT_LENGTH=8192 ollama serve
```

モデルが GPU で実行されているか確認します。

```bash
ollama ps
```

`PROCESSOR` 列に CPU、GPU、または混合読み込みの割合が表示されます。

Cherry Studio に入力したモデルコンテキストが Ollama の実際の設定より大きい場合、サーバーが入力を切り捨てるか、上限超過を返す可能性があります。Ollama のランタイム設定とログを基準にしてください。

## モデルの読み込みと同時実行

Ollama はデフォルトで、アイドル状態になるとリソースを解放するためモデルをアンロードします。調整する場合は、Ollama の `OLLAMA_KEEP_ALIVE`、`OLLAMA_MAX_LOADED_MODELS`、`OLLAMA_NUM_PARALLEL`、`OLLAMA_MAX_QUEUE` を使用できます。

- モデルを常駐させると最初の回答を待つ時間を短縮できますが、メモリまたは VRAM を継続的に使用します。
- 同時実行数を増やすほど、各モデルに必要なコンテキストメモリが増えます。
- 複数の大規模モデルを同時に読み込むと、待ち行列への追加またはアンロードが発生する場合があります。
- キューが満杯になると、サーバーが 503 を返す場合があります。

同時実行パラメーターだけを増やさないでください。まず `ollama ps` とシステムモニターでハードウェアの余力を確認します。

## ナレッジベースと埋め込みモデル

Ollama は、ナレッジベースと[グローバルメモリ](../../advanced-basic/memory.md)で使用できるローカル埋め込みモデルを提供できます。

1. モデルライブラリから専用の埋め込みモデルをプルします。
2. Cherry Studio に戻ってモデルを同期します。
3. モデルが埋め込みモデルとして認識されていることを確認します。
4. ナレッジベースでそのモデルを選択します。
5. 次元を検出し、ヘルスチェックを実行します。
6. その後、ドキュメントをインポートします。

Cherry Studio の Ollama はリランキングモデルに対応していません。Rerank が必要な場合は、別のプロバイダーを選択してください。

埋め込みモデルを既存のナレッジベースで使用した後は、モデルや次元をむやみに変更しないでください。通常、ベクトルインデックスの再構築が必要になります。

## PDF と添付ファイル

現在の V2 は PDF を Ollama へ直接送信しません。Cherry Studio は先にローカルで PDF のテキストを抽出してから、モデルへ渡します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストはモデルコンテキストを消費します。
- PDF 内の画像はビジョンモデルへ個別に送信する必要があります。

## リモート Ollama に接続する

Ollama はデフォルトで `127.0.0.1:11434` だけをリッスンします。別のデバイス上の Cherry Studio から接続するには、Ollama ホストでリッスンアドレスを設定します。例：

```bash
OLLAMA_HOST=0.0.0.0:11434 ollama serve
```

環境変数の設定方法とサービスの再起動方法はシステムによって異なります。[Ollama FAQ](https://docs.ollama.com/faq) を参照してください。

{% hint style="danger" %}
認証されていない Ollama ポートをインターネットへ直接公開しないでください。LAN でもファイアウォールを併用し、インターネットからアクセスする場合は VPN、または HTTPS と認証を備えたリバースプロキシを使用してください。
{% endhint %}

Docker、仮想マシン、WSL 内の Ollama に接続する場合、`localhost` は Cherry Studio が動作するシステムを指し、必ずしもコンテナまたは仮想マシンではありません。ホストから到達できるアドレスを使用し、ポートマッピングを確認してください。

## 接続を確認する

1. Ollama ホストで `ollama list` を実行します。
2. 対象モデルがプル済みであることを確認します。
3. Cherry Studio でプロバイダーの接続チェックを実行します。
4. **追加**をクリックしてモデルを同期します。
5. モデルのヘルスチェックを実行します。
6. チャット画面に戻り、簡単なメッセージを送信します。
7. その後、思考、画像、MCP、ナレッジベースをテストします。

ローカルコマンドも失敗する場合は、先に Ollama を修復してください。Cherry Studio だけが失敗する場合は、Base URL、ネットワーク、モデルタグを重点的に確認します。

## よくある問題

### `localhost:11434` に接続できない

Ollama が起動していない、ポートが変更された、またはファイアウォールにブロックされています。まず `ollama list` を実行し、Ollama のログを確認してください。

### モデルリストが空

現在の Ollama ホストにプル済みモデルがないか、Cherry Studio が誤ったホストへ接続しています。`ollama list` と Cherry Studio は同じインスタンスを参照する必要があります。

### ダウンロードしたばかりのモデルが見つからない

もう一度**追加**をクリックしてリストを同期し、`ollama list` に表示される完全な名前とタグを使用してください。Cherry Studio の同期が代わりにダウンロードを実行することはありません。

### 最初の回答が遅い

Ollama がモデルをメモリまたは VRAM に読み込んでいます。`ollama ps` で読み込み先を確認してください。その後のリクエストは通常、速くなります。

### メモリ不足、クラッシュ、または待ち行列が続く

パラメーター数の少ないモデルまたは量子化率の高いモデルを選び、コンテキストと同時実行数を減らし、読み込み済みの他のモデルを停止してください。

### 503 が返る

サーバーの負荷が高すぎるか、キューが満杯です。同時実行数を減らし、現在のリクエストが完了するまで待つか、Ollama のキュー設定を調整してください。

### 画像または MCP を使用できない

具体的なモデルタグが該当する機能に対応していることと、Cherry Studio が正しく認識していることを確認してください。通常のチャットを使用できても、モデルがビジョンやツールに対応するとは限りません。

### リモート接続が拒否される

Ollama がローカル以外のアドレスをリッスンしていること、ポートが開いていること、リバースプロキシのパスが正しいことを確認してください。インターネット接続の問題を、すべてのセキュリティ対策を無効にして解決しないでください。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。Ollama API については[公式ドキュメント](https://docs.ollama.com/api/introduction)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
