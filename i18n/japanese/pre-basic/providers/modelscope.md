# ModelScope（魔搭）

ModelScope は API-Inference を通じて、一部のオープンソースモデルを直接呼び出せるオンライン API として提供します。Cherry Studio V2 には ModelScope プロバイダーが組み込まれており、OpenAI 互換チャット、ビジョンモデル、埋め込みモデル、非同期画像生成に対応しています。

デフォルトの Base URL：

```text
https://api-inference.modelscope.cn/v1/
```

{% hint style="info" %}
ModelScope のモデルライブラリにあるすべてのモデルが API-Inference に対応するとは限りません。モデルページに API-Inference の表示と呼び出し例があるモデルだけを Cherry Studio へ直接接続できます。
{% endhint %}

## 使用前の確認

現在、ModelScope の無料 API-Inference を使用するには次の条件が必要です。

1. ModelScope へ登録してログインする。
2. Alibaba Cloud アカウントを連携する。
3. 対応する Alibaba Cloud アカウントで実名認証を完了する。
4. ModelScope Access Token を作成する。
5. 現在も API-Inference に対応するモデルを使用する。

API-Inference は試用向けの無料サービスであり、本番 SLA は提供されません。商用、高同時実行、または安定したサービスが必要な場合は、商用 API プロバイダーを使用するか、モデルを自分でデプロイしてください。

## Access Token を取得する

1. [ModelScope](https://modelscope.cn/) へログインします。
2. [アクセストークン](https://modelscope.cn/my/myaccesstoken)を開きます。
3. 新しいトークンを作成し、識別しやすい名前を入力します。
4. 生成された Access Token をコピーします。
5. Token を安全な場所に保管します。

{% hint style="danger" %}
Access Token はアカウントの認証情報に相当します。チャット、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。漏えいした場合は、ModelScope ですぐに削除して再作成してください。
{% endhint %}

## Cherry Studio で設定する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. **ModelScope 魔搭**を選択します。
4. API Key に Access Token を貼り付けます。
5. Base URL `https://api-inference.modelscope.cn/v1/` を維持します。
6. ページ上部のプロバイダースイッチをオンにします。
7. **追加**またはモデル同期をクリックします。
8. 同期プレビューを確認して変更を適用します。
9. 使用するモデルだけを有効にします。
10. モデルのヘルスチェックを実行します。

同期リストに旧モデルが含まれていても、まだ呼び出せると仮定しないでください。ModelScope は新しいモデルの公開に伴い、旧モデルを段階的に変更または廃止します。モデル詳細ページで API-Inference の状態を確認してください。

## 利用できるモデルを探す

1. [ModelScope モデルライブラリ](https://modelscope.cn/models)を開きます。
2. **API-Inference** 対応モデルで絞り込みます。
3. モデル詳細ページを開きます。
4. 右側に API 呼び出しの入口と例があることを確認します。
5. 完全な Model ID をコピーします。
6. Cherry Studio で同期するか、その ID を手動で追加します。
7. ヘルスチェックを実行します。

Model ID は通常、組織名とモデル名を含みます。例：

```text
Qwen/Qwen3.5-35B-A3B
```

大文字と小文字、スラッシュ、サフィックスはすべて ID の一部です。ページの表示名、リポジトリ URL、ローカルファイル名を API Model ID として使用しないでください。

{% hint style="warning" %}
V2 の組み込みモデルリストは候補にすぎず、プラットフォームのリアルタイムな対応状況が優先されます。404 またはモデル利用不可が返る場合は、廃止済みモデルを繰り返し試さず、先に ModelScope のモデルページで確認してください。
{% endhint %}

## チャットモデル

ModelScope の LLM API-Inference は OpenAI 互換 Chat Completions を使用します。モデルを選択するときは、ベースモデル、Embedding モデル、画像生成モデルではなく、チャットまたは指示モデルであることを確認してください。

次の順序でテストすることを推奨します。

1. 短いテキストメッセージを送信します。
2. ストリーミング出力をテストします。
3. システムプロンプトを追加します。
4. 長いコンテキストをテストします。
5. 最後に思考、画像、ツール呼び出しをテストします。

オープンソースモデルごとに、パラメーターとプロンプトテンプレートが異なる場合があります。特に思考モデルでは、ModelScope 公式が推奨するモデル詳細ページの API 例を基準にしてください。

## ビジョンモデル

ビジョン対応モデルは、OpenAI 互換メッセージを通じて画像 URL または Base64 画像を受け取れます。

Cherry Studio では：

1. ビジョン対応と明記された Model ID を選択します。
2. モデルに画像機能が表示されることを確認します。
3. まず小さな画像を 1 枚アップロードします。
4. モデルが画像を実際に理解しているか確認します。
5. その後、複数画像または高解像度画像を試します。

同じモデルシリーズ名でも、すべてのバリアントがビジョンに対応するとは限りません。画像はより多くのコンテキストと無料割り当ても消費します。

## 思考とツール呼び出し

### 思考

思考モデルは、モデル固有のパラメーターまたはレスポンス形式を使用する場合があります。思考オプションの変更後にエラーが発生した場合：

1. **デフォルト**へ戻します。
2. カスタムパラメーターを削除します。
3. モデルページの例と比較します。
4. ヘルスチェックを再実行します。

### MCP とツール呼び出し

Cherry Studio MCP を使用するには、モデルが構造化 Tool Calling を出力できる必要があります。

1. 先に通常のチャットを完了します。
2. 単純な MCP ツールを 1 つだけ有効にします。
3. 呼び出すよう明示します。
4. 構造化された呼び出しが実際に生成されるか確認します。
5. 結果がモデルへ返されることを確認します。
6. その後、ツールを追加します。

ModelScope プラットフォームの MCP 広場と ModelScope モデルサービスは別の機能です。モデルの Access Token を対応するプラットフォーム機能で使用できる場合もありますが、Cherry Studio では「モデルプロバイダー」と「MCP サーバー」を個別に設定する必要があります。

## 画像の生成と編集

Cherry Studio V2 は ModelScope 専用の非同期画像生成経路を実装しています。

1. `/v1/images/generations` へタスクを送信する。
2. `task_id` を取得する。
3. `/v1/tasks/{task_id}` をポーリングする。
4. タスク成功後に画像 URL を読み取る。

ModelScope が現在対応する AIGC モデルを選択すると、描画ページで次の機能を使用できます。

- 画像サイズ。
- ネガティブプロンプト。
- サンプリングステップ数。
- Guidance。
- Seed。
- 対応モデルの画像編集入力。
- 対応モデルの LoRA。

モデルごとに対応するサイズ、ステップ数、Guidance、編集機能は異なります。モデル詳細ページに示された範囲を基準にしてください。

画像タスクは非同期で実行されるため、待ち時間はチャットより明らかに長くなる場合があります。タスクのキャンセル、ネットワーク中断、割り当て不足、プラットフォームの高負荷によってポーリングが失敗することもあります。

## 埋め込みモデルとナレッジベース

Cherry Studio の ModelScope プロバイダーは OpenAI 互換 Embeddings 呼び出しを実装していますが、ModelScope が互換 Embedding API を実際に提供しているモデルだけを使用できます。

1. モデルページでタスクタイプと API 例を確認します。
2. 完全な Model ID を追加します。
3. Cherry Studio が埋め込みモデルとして認識していることを確認します。
4. ナレッジベースで次元を検出します。
5. ヘルスチェックを実行します。
6. その後、ドキュメントをインポートします。

モデルまたは次元を既存のナレッジベースで使用した後は、むやみに変更しないでください。通常、ベクトルインデックスの再構築が必要になります。

## PDF と添付ファイル

現在の V2 は先にローカルで PDF のテキストを抽出し、ModelScope のチャットモデルへ送信します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストはコンテキストと無料呼び出し割り当てを消費します。
- PDF 内の画像はビジョンモデルへ個別に送信する必要があります。

ModelScope はクラウドサービスです。アップロード前に、ドキュメントがプライバシーと組織のセキュリティ要件を満たすことを確認してください。

## 割り当てとレート制限

ModelScope の現在の無料 API-Inference ルールには次が含まれます。

- 登録ユーザー 1 人あたり、1 日合計で最大 2,000 回の呼び出し。
- 通常、1 モデルあたり 1 日最大 200 回の呼び出し。
- 一部の大規模モデルでは、1 日 100 回以下に制限される場合がある。
- 同時実行数はプラットフォーム負荷に応じて動的に調整される。
- AIGC モデルには個別の制限がある場合がある。
- 具体的なモデル割り当ては随時動的に変更される場合がある。

サービスのレスポンスヘッダーには次の情報が含まれる場合があります。

| レスポンスヘッダー | 意味 |
| --- | --- |
| `modelscope-ratelimit-requests-limit` | ユーザーの 1 日の総割り当て |
| `modelscope-ratelimit-requests-remaining` | ユーザーの 1 日の残り割り当て |
| `modelscope-ratelimit-model-requests-limit` | 現在のモデルの 1 日の割り当て |
| `modelscope-ratelimit-model-requests-remaining` | 現在のモデルの残り割り当て |

現在の Cherry Studio は、これらのレスポンスヘッダーを完全な請求ページとして表示しません。割り当ては、エラー情報、ModelScope ページ、プラットフォームの最新ルールを組み合わせて判断してください。

予備アカウントを作成または切り替えてプラットフォームの制限を回避しないでください。無料割り当ては試用とプロトタイプ用です。バッチ呼び出しには適切な商用サービスを使用してください。

## API-Inference と API-Provider

ModelScope は外部 API プロバイダーを連携できる API-Provider も提供しています。無料 API-Inference とは割り当てと課金元が異なります。

- API-Inference：ModelScope が試用向けの推論リソースを提供します。
- API-Provider：連携した外部プロバイダーを呼び出します。無料 API-Inference と同じ上限には制約されませんが、外部プロバイダーの課金と制限が適用されます。

このページのデフォルト `api-inference.modelscope.cn` 設定は API-Inference を指します。課金元を理解せずに外部プロバイダーの認証情報と混在させないでください。

## よくある問題

### 401 が返る

Access Token が誤っている、削除済み、空白を含む、または正しく送信されていません。Token をもう一度コピーし、Base URL がプロキシによって書き換えられていないことを確認してください。

### 403 が返る

Alibaba Cloud アカウントが連携されていない、実名認証が完了していない、またはモデル権限が制限されている可能性があります。まず ModelScope のウェブページでアカウント要件を完了してください。

### 404 が返る

モデル ID が誤っている、モデルが廃止済み、または Base URL が正しくありません。完全な ID とモデルページの API-Inference 状態を確認してください。

### 429 が返る

ユーザー総割り当て、モデル単位の割り当て、AIGC の個別割り当て、または動的同時実行制限に達している可能性があります。頻度を下げて割り当ての回復を待ってください。本番環境では商用サービスを使用します。

### モデルリストが空

Token、Base URL、ネットワークを確認します。モデルページから現在対応する完全な Model ID をコピーし、手動で追加することもできます。

### プリセットモデルを使用できない

V2 のプリセットが、プラットフォームによる廃止または名称変更より古い場合があります。ModelScope の現在のモデルページを基準に、再同期するか、まだ対応するモデルへ変更してください。

### 画像生成が待機し続ける

タスクがまだキュー内にある、プラットフォームが混雑している、ポーリングネットワークに失敗した、または割り当てが不足しています。ModelScope のタスク状態を確認し、同時実行数を減らしてください。

### 画像編集でパラメーターエラーが発生する

対象モデルが編集に対応していない、入力サイズが要件に合わない、または特定の `image_url` が必要な可能性があります。モデルページの例とパラメーター範囲を確認してください。

### MCP を使用できない

まずモデルがツール呼び出しに対応していることを確認します。ModelScope MCP 広場のサービスは、Cherry Studio の MCP 設定で個別に同期または追加する必要もあります。

### 安定した高同時実行が必要

無料 API-Inference は SLA または商用の高同時実行には適しません。ModelScope API-Provider、他の商用モデルサービス、または自分でデプロイしたオープンソースモデルを使用してください。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。ModelScope のモデル、API、最新の割り当てについては [API-Inference ドキュメント](https://modelscope.cn/docs/model-service/API-Inference/intro)と[使用制限](https://modelscope.cn/docs/model-service/API-Inference/limits)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
