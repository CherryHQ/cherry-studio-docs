# MiniMax Token Plan（旧 Coding Plan）

MiniMax は Coding Plan を **Token Plan** へアップグレードしました。個人開発者、AI プログラミング、日常的な高頻度利用を対象とし、サブスクリプションの割り当てまたは Credits を使用して MiniMax モデルを呼び出します。

Cherry Studio V2 には「Coding Plan」専用のプロバイダーはありません。組み込みの **MiniMax** または **MiniMax Global** プロバイダーに Token Plan 専用 Key を入力してください。

{% hint style="info" %}
このページのパスは旧ドキュメントとの互換性のために残されています。MiniMax プラットフォームの実際の製品名、プラン、割り当ては、現在の **Token Plan** ページを基準にしてください。旧チュートリアルの M2.1、固定月額料金、「5 時間ごとに 40 回」など、古い情報を適用しないでください。
{% endhint %}

## Token Plan と通常の API の違い

| 項目 | Token Plan | 通常の従量課金 API |
| --- | --- | --- |
| Key の取得元 | Token Plan / サブスクリプション管理 | API Key |
| 一般的な Key | `sk-cp...` | 通常の API Key |
| 計測方法 | プラン割り当て、Credits、ローリングウィンドウ | 実際の API 使用量に基づく課金 |
| 有効期限 | サブスクリプション、シート、Credits に依存 | アカウント残高と Key の状態に依存 |
| 用途 | 個人の対話、プログラミングツール、日常利用 | 本番統合、安定した従量課金呼び出し |

2 種類の Key に**互換性はありません**。通常の API Key を Token Plan の用途で使用したり、Token Plan Key を通常の従量課金 Key として使用したりすると、401、割り当てエラー、または誤った課金方法が適用される可能性があります。

MiniMax は、本番環境では従量課金 API を優先することを推奨しています。Token Plan には RPM、TPM、ローリングウィンドウ、週次割り当て、ピーク時の動的レート制限が存在する場合があり、無制限のバッチサービスには適しません。

## 中国本土または国際プラットフォームを選択する

| アカウントとサブスクリプション | Cherry Studio のプロバイダー | OpenAI Base URL | Anthropic Base URL |
| --- | --- | --- | --- |
| 中国本土の MiniMax プラットフォーム | MiniMax | `https://api.minimaxi.com/v1` | `https://api.minimaxi.com/anthropic` |
| MiniMax 国際プラットフォーム | MiniMax Global | `https://api.minimax.io/v1` | `https://api.minimax.io/anthropic` |

中国本土サイトと国際サイトのアカウント、Key、Base URL を混在させないでください。判断基準は現在地ではなく、Token Plan を購入し、Key を作成したプラットフォームです。

## Token Plan Key を取得する

### 中国本土プラットフォーム

1. [MiniMax オープンプラットフォーム](https://platform.minimaxi.com/)へログインします。
2. [Token Plan](https://platform.minimaxi.com/subscribe/token-plan)を開きます。
3. プランを購入するか、権利を引き換えるか、Team からシートが割り当てられていることを確認します。
4. API Key ページへ移動します。
5. **Token Plan Key を作成**を選択します。
6. 新しい Key をコピーし、安全に保管します。

### 国際プラットフォーム

1. [MiniMax API Platform](https://platform.minimax.io/) へログインします。
2. [Token Plan](https://platform.minimax.io/subscribe/token-plan)を開きます。
3. プランまたは Credits を購入するか、Team のシートを確認します。
4. API Keys へ移動します。
5. **Token Plan Key** を作成します。
6. 新しい Key をコピーし、安全に保管します。

{% hint style="danger" %}
Token Plan Key をチャット、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。Key が漏えいすると、サブスクリプションの割り当てや Credits が消費される可能性があります。MiniMax プラットフォームですぐに削除して再作成してください。
{% endhint %}

`sk-cp` プレフィックスだけでは Key が使用できることを証明できません。サブスクリプションが有効で、シートが割り当てられ、Credits が利用可能であり、Key が正しいプラットフォームで作成されたことも確認してください。

## Cherry Studio で設定する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. 中国本土のアカウントでは **MiniMax**、国際アカウントでは **MiniMax Global** を選択します。
4. API Key に Token Plan Key を貼り付けます。
5. Base URL がアカウントのプラットフォームと一致しているか確認します。
6. ページ上部のプロバイダースイッチをオンにします。
7. **追加**またはモデル同期をクリックします。
8. 同期プレビューを確認して変更を適用します。
9. 現在のプランで使用を許可されているモデルだけを有効にします。
10. モデルのヘルスチェックを実行します。

Cherry Studio の MiniMax プリセットには、OpenAI と Anthropic の互換アドレスがどちらも保持されています。通常のチャットではデフォルトで OpenAI 互換経路を使用し、一部の Code Tools は Anthropic 互換経路を使用できます。

プロトコル、ビジョン、思考、MCP、PDF の詳細な境界については、[MiniMax](minimax.md)を参照してください。

## モデルを選択する

現在の Cherry Studio V2 の MiniMax プリセットには次のモデルが含まれます。

- `MiniMax-M3`
- `MiniMax-M2.7`
- `MiniMax-M2.7-highspeed`

MiniMax Token Plan で利用できるモデルは、プランと製品のアップグレードに伴って変わります。サブスクリプションページ、アカウント使用量ページ、実際のモデル同期結果を基準にしてください。

推奨事項：

1. まず、現在のプランで推奨されている `MiniMax-M3` をテストします。
2. 旧ワークフローとの互換性が必要な場合に `MiniMax-M2.7` をテストします。
3. プランに高速モデルが明示的に含まれる場合にだけ `MiniMax-M2.7-highspeed` を使用します。
4. 旧版の `MiniMax-M2.1` を手動で追加し、現在もプランに含まれると仮定しないでください。
5. 同じ名前のモデルでも、Token Plan と従量課金 API では割り当てルールが異なる場合があります。

{% hint style="warning" %}
モデルが Cherry Studio のプリセットまたは同期リストに表示されても、そのモデルが必ず Token Plan に含まれるとは限りません。最終的な権限は MiniMax サーバー側で判断されます。
{% endhint %}

## 思考、ビジョン、MCP

### 思考

MiniMax M シリーズは思考内容を返します。Cherry Studio は、後続リクエストのコンテキストを連続させるため、複数ターンのチャットで思考ブロックとツール呼び出し情報を保持する必要があります。

思考オプションを変更した後にパラメーターエラーが返る場合は、まず**デフォルト**へ戻して再試行してください。Token Plan Key が、モデル自体の受け付けるパラメーターを変えることはありません。

### ビジョン

Token Plan はマルチモーダルモデルにも拡張されていますが、Cherry Studio が現在画像を直接送信できるかは、具体的なモデル ID と V2 の機能認識にも依存します。

同期後にモデルへ画像機能が表示されることを確認し、小さな画像でテストしてください。`MiniMax-M3` のビジョン機能が現在の V2 でまだ正しく認識されない場合は、表示名だけを変更して制限を回避しないでください。

### MCP

Cherry Studio MCP はモデルの Tool Calling を使用します。MiniMax Token Plan も公式の Web Search MCP と Understand Image MCP を提供していますが、Cherry Studio で独自に設定する MCP サーバーとは異なります。

Cherry Studio MCP を使用する場合：

1. 先に通常のチャットを完了します。
2. 単純なツールを 1 つだけ有効にします。
3. モデルが実際に構造化された呼び出しを生成するか確認します。
4. その後、ツールを追加します。

MiniMax 公式の Token Plan MCP が必要な場合は、公式ガイドに従って個別に設定し、対応するプランのリソースを消費することに注意してください。

## 使用量を確認する

もっとも確実な方法は、MiniMax プラットフォームの Token Plan またはサブスクリプション管理ページを開き、次の項目を確認することです。

- 現在のプランまたは Team シート。
- 残りの割り当てと Credits。
- 各モデルの使用量。
- ローリングウィンドウの回復時刻。
- 期間ごとの割り当て。
- 高速モデルの利用資格。
- サブスクリプションの有効期限。

Cherry Studio で成功したリクエスト数だけを基に残量を推測しないでください。長いコンテキスト、ビジョン、生成モデル、異なるモデルでは、別の割り当てプールが使用される場合があります。

## 上限と 429

Token Plan には、次の制限が同時に存在する場合があります。

- RPM / TPM の短期レート制限。
- 5 時間のローリングウィンドウ。
- 週次割り当て。
- マルチモーダルモデルの個別割り当て。
- ピーク時の動的レート制限。
- プランの同時実行制限。

したがって、`429 Too Many Requests` は、サブスクリプション全体の割り当てを使い切ったことを必ずしも意味しません。

確認手順：

1. 1 分間停止してから再試行します。
2. Token Plan の使用量ページを確認します。
3. ローリングウィンドウと週次割り当てを確認します。
4. 同時実行、長いコンテキスト、自動再試行を減らします。
5. 複数人が同じ個人 Key を共有していないことを確認します。
6. 必要に応じてプランをアップグレードするか、従量課金 API Key へ変更します。

同じプロバイダーで通常の API Key へ直接置き換えると、割り当てと課金元が変わります。操作前にアカウント残高と予算を確認してください。

## よくある問題

### 401 が返る

Key が誤っている、削除済み、サブスクリプションの期限切れ、シートの無効化、または中国本土と国際の Base URL が混在しています。該当するプラットフォームから Token Plan Key をもう一度コピーしてください。

### 403 が返る

現在のプラン、Team ポリシー、モデル権限ではリクエストが許可されていません。Token Plan の権利とモデル範囲を確認してください。

### 404 が返る

Base URL、プロトコルパス、またはモデル ID が誤っています。MiniMax / MiniMax Global のプリセットアドレスへ戻し、モデルを再同期してください。

### 429 が返る

分単位のレート制限、ローリングウィンドウ、週次割り当て、ピーク時の動的レート制限が原因の可能性があります。リクエストを繰り返すだけでなく、Token Plan の使用量ページを基準にしてください。

### 通常モデルは使用できるが高速モデルは使用できない

現在のプランに高速モデルの権利が含まれていないか、その時点で高速リソースを利用できない可能性があります。標準モデルを使用し、プランの説明を確認してください。

### モデルリストに旧モデルが残る

再同期し、プロバイダーが正しいプラットフォームへ接続していることを確認します。手動で残した旧モデルが、現在のプランで対応していることを自動的に示すわけではありません。

### Key のチェックには成功するがチャットで残高を消費した

Token Plan Key ではなく、通常の従量課金 API Key を入力した可能性があります。すぐに MiniMax の請求と Key の種類を確認してください。

### 本番環境で使用すると頻繁にレート制限が発生する

Token Plan は個人の対話と開発ワークフローを対象としています。本番、バッチ、高同時実行サービスでは従量課金 API を使用し、予算、監視、再試行ポリシーを設定してください。

MiniMax Token Plan の現在のプラン、モデル、使用量ルールについては、[中国本土向けドキュメント](https://platform.minimaxi.com/docs/token-plan/quickstart)または[国際向けドキュメント](https://platform.minimax.io/docs/token-plan/quickstart)を参照してください。一般的なプロバイダー設定については [MiniMax](minimax.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
