# Moonshot AI (Kimi)

Cherry Studio V2 の組み込み Moonshot AI テンプレートは、Kimi API オープンプラットフォームへの接続に使用します。テンプレートは初期状態で OpenAI Chat Completions プロトコルを使用し、Moonshot の Anthropic 互換エンドポイントも提供します。

現在の Kimi モデルは、一般的なチャット、長時間のコーディング、画像理解、Agent などの用途に対応します。モデルの世代によって使われる思考パラメーターが異なるため、設定するときは先にモデル ID を確認してから、Cherry Studio の思考オプションを選択してください。

{% hint style="info" %}
Kimi ウェブ版、Kimi 会員、Kimi Code、Kimi API オープンプラットフォームは別の製品です。ウェブ版や会員のログイン状態は Cherry Studio に自動的に反映されません。Cherry Studio から呼び出すには、別途 API Key を作成し、オープンプラットフォームの規則に従って料金を支払う必要があります。
{% endhint %}

## 始める前の準備

- [Kimi API オープンプラットフォーム](https://platform.kimi.com/)にログインできるアカウント
- [API Keys](https://platform.moonshot.cn/console/api-keys) で作成した API Key
- 対象モデルに必要な残高とアクセス権があるアカウント
- 現在の[モデルリスト](https://platform.kimi.com/docs/models)とパラメーター制限を確認済みであること

使用量を区別し、権限を取り消しやすくするため、Cherry Studio 専用の Key を作成することをおすすめします。

## Moonshot AI を設定する

1. `設定 → モデルプロバイダー` を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替え、**Moonshot AI** を選択します。
3. Kimi API Key を入力します。
4. 既定の Base URL `https://api.moonshot.cn` を変更せずに使用します。
5. 画面上部にあるプロバイダーのスイッチをオンにします。
6. モデルリストで**追加**をクリックし、同期プレビューを確認して変更を適用します。
7. 使用するモデルだけを有効にします。

{% hint style="danger" %}
API Key をチャットメッセージ、ドキュメント、コードリポジトリ、または問題報告用のスクリーンショットに含めないでください。Key が漏えいした場合は、オープンプラットフォームですぐに削除して作り直してください。
{% endhint %}

公式 SDK ドキュメントのアドレスは通常 `https://api.moonshot.cn/v1` と記載されています。Cherry Studio のテンプレートが API パスを処理するため、組み込みテンプレートでは画面の既定アドレスを維持し、リクエストパスを重複して追加しないでください。

## モデルを選ぶ

実際の同期リストを優先してください。現在の主なモデルは、次のように選択できます。

| モデル ID | 主な用途 | Cherry Studio での注意点 |
| --- | --- | --- |
| `kimi-k3` | フラッグシップ汎用モデル、1M コンテキスト、長時間のコーディング、知識作業、複雑な推論 | 現在の V2 では思考を**デフォルト**のままにすることを推奨 |
| `kimi-k2.7-code` | 256K コンテキストのコーディングおよび Agent モデル | 常に思考するため、**デフォルト**のままにする |
| `kimi-k2.7-code-highspeed` | K2.7 Code と同じシリーズで出力が高速 | リソース混雑時に変動する場合がある |
| `kimi-k2.6` | 256K コンテキスト、一般的なチャット、画像、Agent に適する | 既定の思考を使用するか、必要に応じて無効化できる |

Kimi K3、K2.7 Code、K2.6 は、いずれも公式にはテキスト、画像、動画の入力に対応します。実際の添付入口は、現在の Cherry Studio がモデル機能を正しく識別できるかどうかにも左右されます。

モデル名、アクセス条件、ライフサイクルは変更されます。古いスクリーンショットだけを基にモデル ID を手動入力しないでください。まず**追加**をもう一度クリックしてリストを同期し、Kimi の公式ドキュメントを確認してください。

## 思考モードを設定する

Kimi のモデルシリーズでは、異なる推論パラメーターを使用します。

- Kimi K3 は常に思考を有効にし、トップレベルの `reasoning_effort` で `low`、`high`、`max` を使用します。既定値は `max` です。
- Kimi K2.7 Code は常に思考を有効にし、無効化には対応しません。
- Kimi K2.6 は `thinking` で思考の有効・無効を制御します。

{% hint style="warning" %}
現在の Cherry Studio V2 は Kimi K2.5 以降のモデルをすべて Kimi 思考モデルとして識別し、デフォルト以外のオプションでは `thinking` パラメーターを送信します。Kimi K3 は `reasoning_effort` を使用し、K2.7 Code は思考を無効にできません。そのため、K3 または K2.7 Code では**デフォルト**のままにし、非互換のパラメーターによる 400 エラーを避けてください。
{% endhint %}

Kimi K3 の低、高、最高の 3 段階の推論強度は、現在の Cherry Studio の思考メニューに完全には表示されない場合があります。デフォルトのままなら、K3 はプロバイダーの既定値 `max` を使用します。強度を正確に制御する必要がある場合は、Cherry Studio の対応が更新されるまで待ってください。

K2.6 を使用する場合：

- **デフォルト**：プロバイダーの既定の動作を上書きしません。
- **オフ**：思考を無効にするパラメーターを送信します。
- **自動**：現在の V2 は思考を有効にするパラメーターを送信します。

K2.5 以降のモデルには、固定または制限されたサンプリングパラメーターがあります。パラメーターエラーが発生した場合は、まず温度、Top P、ペナルティ項目を既定値へ戻してください。

## 画像、動画、ファイルを使用する

公式のモデル機能とクライアントによる現在の識別結果を個別に確認してください。

1. モデルリストを再同期します。
2. 対象モデルを選択します。
3. 入力欄に画像またはファイルの入口が表示されるか確認します。
4. まず通常の画像を 1 枚アップロードしてヘルスチェックを行います。
5. その後で動画または大きな添付ファイルをテストします。

現在の V2 は K2.6 のビジョン機能を自動的に識別できます。K3 と K2.7 Code の公式機能は比較的新しく、現在のバージョンではビジョンタグが完全に表示されない場合があります。添付入口が表示されない場合は、まず Cherry Studio とモデルリストを更新してください。それでも利用できない場合は、一時的に `kimi-k2.6` を使用し、対応していない内容をテキストとして無理に送信しないでください。

PDF については、現在の組み込み Moonshot テンプレートは Kimi のネイティブファイルアップロード API を直接使用しません。Cherry Studio は先に PDF のテキストをローカルで抽出し、そのテキストをモデルへ送信します。

- テキスト形式の PDF は通常そのまま処理できます。
- スキャンした PDF は先に OCR が必要な場合があります。
- 表、複雑なレイアウト、画像情報は抽出時に失われる場合があります。
- 抽出後のテキストはモデルの入力 Token を消費します。

## ツール呼び出しと MCP

Kimi の公式モデルはツール呼び出しに対応しますが、Cherry Studio に MCP 機能が表示されるかはモデル機能の識別にも左右されます。

次の順序で検証することをおすすめします。

1. まず通常のチャットを 1 回完了します。
2. 簡単な MCP ツールを 1 つ有効にします。
3. ツール呼び出しを明確に要求するプロンプトを使用します。
4. モデルが実際に呼び出しを開始することを確認します。
5. その後で複数のツールまたは長い処理のタスクを追加します。

現在の V2 には Kimi K2 シリーズのツール識別ルールが含まれますが、K3 と K2.7 Code の自動識別は公式のモデル公開より遅れる場合があります。MCP の入口がない場合は、まず Cherry Studio を更新してください。それでも識別されない場合は、現在のバージョンで識別できるモデルを一時的に使用してタスクを完了してください。

MCP が画像、音声、大きなバイナリデータを含むリソースを返した場合、Cherry Studio は base64 コンテンツが Kimi のリクエストサイズ上限を超えないよう、結果をテキスト要約へ変換します。その場合、モデルはツール結果の説明文を確認できますが、置き換えられた元のメディアを直接分析することはできません。

## ナレッジベースと埋め込みモデル

組み込み Moonshot AI テンプレートには現在チャットエンドポイントが設定され、埋め込みモデルは提供されません。ナレッジベースまたは[グローバルメモリ](../../advanced-basic/memory.md)を使用する場合：

- チャットモデルには引き続き Kimi を選択できます。
- 埋め込みモデルは別のプロバイダーから選択する必要があります。
- チャットモデルと埋め込みモデルを同じプロバイダーから選ぶ必要はありません。
- 設定後、それぞれでモデルのヘルスチェックを実行します。

## 接続を確認する

1. API Key エリアで接続チェックを実行します。
2. 同期して有効にしたモデルを 1 つ選択します。
3. チェックに成功することを確認します。
4. モデルリストでヘルスチェックを実行します。
5. チャット画面に戻り、簡単なメッセージを送信します。
6. 続いて思考、添付ファイル、MCP を個別にテストします。

接続チェックに成功しても、基本的な認証情報が利用できることしか確認できません。アカウントにすべてのモデルの権限がある、または現在のクライアントがすべてのモデル機能を識別できるとは限りません。

## よくある質問

### 401 が返される

API Key が無効、削除済み、または正しくコピーされていません。Key を作り直し、余分な空白が含まれていないことを確認してください。

### 残高またはアクセス条件のエラーが返される

オープンプラットフォームの残高、アカウントレベル、対象モデルのアクセス条件を確認してください。Kimi ウェブ版の会員残高を API の残高として使用することはできません。

### 404 または「モデルが存在しません」と返される

モデル ID が変更された、提供終了になった、またはアカウントにアクセス権がありません。もう一度**追加**をクリックしてリストを同期し、[モデルリスト](https://platform.kimi.com/docs/models)で確認してください。

### 400 または `thinking` パラメーターが無効と表示される

Kimi K3 または K2.7 Code を使用している場合は、思考オプションを**デフォルト**へ戻し、温度や Top P などのパラメーターも既定値へ戻してください。K3 は K2.6 が使用する `thinking` スイッチを受け付けません。

### 429 またはリクエストが混雑していると表示される

アカウントが同時実行数、RPM、TPM、TPD の制限に達したか、高速モデルのリソースが一時的に混雑しています。同時実行数を減らし、コンテキストを短くするか、後でもう一度試してください。

### K3 または K2.7 Code に画像、動画、MCP の入口がない

これは公式のモデル機能と現在の Cherry Studio の自動識別ルールが同期していない状態です。Cherry Studio を更新してモデルを再同期してください。それでも入口がない場合は、K2.6 を一時的に使用し、クライアントの対応更新を待ってください。

### PDF の内容が完全に認識されない

PDF がスキャンされたものか確認してください。先に OCR を実行するか、重要なページを画像に変換してから、Cherry Studio がビジョンモデルとして識別できる Kimi モデルを使用してください。

一般的な設定は[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。Kimi のパラメーター差異は[モデルパラメーターリファレンス](https://platform.kimi.com/docs/api/models-overview)を、フィードバック先は[フィードバックとご提案](../../question-contact/suggestions.md)を参照してください。
