# NewAPI

NewAPI は統合 LLM ゲートウェイです。サーバー側で OpenAI、Anthropic、Google などの上流チャネルへ接続し、Cherry Studio に統一されたモデルリスト、認証、ルーティング、課金 API を提供します。

Cherry Studio V2 には専用の **New API** プロバイダータイプが組み込まれているため、通常の OpenAI プロバイダーに見せかける必要はありません。この専用タイプでは、モデルごとに OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Google Generate Content、画像生成、リランキングの各エンドポイントを選択できます。

{% hint style="warning" %}
リクエストは NewAPI インスタンスと、そこに設定された上流チャネルを経由します。自分でデプロイしたサービス、または明確に信頼でき、上流サービスを合法的に利用する権限とコンプライアンス責任を備えたサービスだけを使用してください。機密データや API Key を出所不明の公開インスタンスに渡さないでください。
{% endhint %}

## 自分の役割を先に確認する

一般ユーザーと NewAPI 管理者では、必要な準備が異なります。

| 役割 | NewAPI で行う作業 |
| --- | --- |
| 一般ユーザー | トークンを作成し、割り当て、グループ、モデル権限、IP 制限を確認する |
| 管理者 | 上流チャネル、モデルマッピング、グループ、課金を先に設定してテストし、その後ユーザーへトークンを発行する |

他者が管理するインスタンスを使用するだけであれば、Cherry Studio に上流プロバイダーの Key を入力する必要はありません。その NewAPI インスタンスが発行したユーザートークンだけを入力してください。

## NewAPI でトークンを作成する

1. 信頼できる NewAPI インスタンスへログインします。
2. **トークン**ページを開きます。
3. Cherry Studio 専用のトークンを作成します。
4. 必要に応じて、割り当て、有効期限、モデル制限、グループ、IP ホワイトリストを設定します。
5. トークンをコピーし、安全に保管します。
6. NewAPI 内蔵の Playground で、まずモデルを 1 つテストします。

デバイスや用途ごとに個別のトークンを作成することを推奨します。漏えい時に影響を受けたトークンだけを取り消すことができ、使用量も確認しやすくなります。

{% hint style="danger" %}
NewAPI トークンをチャットメッセージ、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。漏えいした場合は、NewAPI コンソールですぐに削除し、再作成してください。
{% endhint %}

## 正しい API アドレスを取得する

NewAPI のホーム画面に表示される API Base URL を優先してコピーするか、インスタンス管理者へ確認してください。一般的な形式は次のとおりです。

| デプロイ方法 | 例 |
| --- | --- |
| HTTPS ドメイン | `https://newapi.example.com` |
| バージョンパスを含む | `https://newapi.example.com/v1` |
| ローカルデプロイ | `http://localhost:3000` |
| LAN IP | `http://192.168.1.20:3000` |

Cherry Studio は通常の NewAPI アドレスに `/v1` を補完し、すでに `/v1` が含まれている場合は重複して追加しません。そのため、サイトのルートアドレスと標準の `/v1` Base URL のどちらでも入力できます。

- `http` と `https` はサーバーの実際の設定と一致させる必要があります。
- 公開インスタンスでは有効な HTTPS 証明書を使用してください。
- ブラウザー管理画面の `/console/...` は API Base URL ではありません。
- トークンページ、ログインページ、特定の `/chat/completions` パスを Base URL に入力しないでください。

## New API を設定する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. 組み込みの **New API** を選択します。
4. NewAPI が発行したトークンを入力します。
5. Base URL をインスタンスの API アドレスに変更します。
6. ページ上部のプロバイダースイッチをオンにします。
7. **追加**をクリックしてモデルリストを同期します。
8. モデルとエンドポイントタイプを確認してから変更を適用します。
9. 使用するモデルだけを有効にします。

組み込みテンプレートのデフォルトアドレスは `http://localhost:3000` であり、ローカルのデフォルトデプロイでのみ使用できます。リモートインスタンスへ接続する場合は、実際のアドレスへ変更する必要があります。

NewAPI 管理者が Cherry Studio のワンクリックインポートリンクを設定している場合は、リンクを使用してアドレスとトークンを事前入力できます。インポート前に対象ドメインを必ず確認し、悪意のあるリンクによってキーが誤ったサーバーへ送信されないようにしてください。

## エンドポイントタイプを理解する

NewAPI では、同じモデル名が 1 つまたは複数のプロトコルに対応する場合があります。Cherry Studio は、モデルのエンドポイントタイプに応じて異なるリクエスト実装を選択します。

| Cherry Studio のエンドポイントタイプ | 典型的な用途 |
| --- | --- |
| OpenAI Chat Completions | 大多数の OpenAI 互換チャットモデル |
| OpenAI Responses | Responses API をネイティブサポートする OpenAI モデル |
| Anthropic Messages | Claude またはその他の Messages ネイティブ互換モデル |
| Google Generate Content | Gemini ネイティブプロトコル |
| OpenAI Image Generation | 描画ページの生成・編集モデル |
| Jina Rerank | ナレッジベースのリランキングモデル |

比較的新しい NewAPI インスタンスは、`/models` のレスポンスで `supported_endpoint_types` を返します。Cherry Studio は同期時にこの情報を読み取ります。

サーバーがエンドポイントのメタデータを返さない場合：

- 一括追加するときは、そのモデル群が共通で使用するエンドポイントタイプを選択します。
- プロトコルが異なるモデルは分けて追加します。
- モデルを手動で追加するときは、少なくとも 1 つのエンドポイントタイプを選択します。
- NewAPI インスタンスが実際に対応しているプロトコルだけを選択します。
- モデル名だけを見て推測しないでください。

エンドポイントタイプが誤っていると、404、パラメーターの非互換、ツール呼び出しの欠落、画像リクエストの失敗が発生する場合があります。リストにモデルが表示されても、すべてのプロトコルが利用できるとは限りません。

## 管理者：チャネルとモデルマッピングを先に確認する

NewAPI インスタンスを管理する場合は、ユーザーが Cherry Studio に接続する前に次の点を確認してください。

1. 各上流チャネルが NewAPI のチャネルテストに合格している。
2. チャネルで選択したモデルが実際の権限と一致している。
3. モデルマッピングに、クライアントがリクエストするモデル ID を使用している。
4. ユーザートークンのグループが対応するチャネルへアクセスできる。
5. 課金倍率、割り当て、自動無効化ポリシーを確認している。
6. `/v1/models` がユーザー権限と一致するモデルを返す。
7. Chat、Responses、Messages、Gemini、画像の各エンドポイントを個別にテストしている。

モデルマッピングは、Cherry Studio がリクエストする名前を上流の名前へ変換します。ヘルスチェックでモデルが存在しないと返された場合は、Cherry Studio のモデル ID、NewAPI のモデルマッピング、上流チャネルの実際の ID をすべて確認してください。

## チャット、思考、ツール呼び出し

NewAPI はルーティング層にすぎません。最終的な機能は、上流モデル、チャネルタイプ、プロトコル変換、インスタンスのバージョンによって決まります。

- 思考オプションは、対象モデルとエンドポイントタイプに合わせます。
- Claude のネイティブ機能には Anthropic Messages を優先します。
- OpenAI のネイティブ Responses 機能には OpenAI Responses を優先します。
- Gemini のネイティブ機能には Google Generate Content を優先します。
- MCP を使用するには、モデル、上流、変換層のすべてでツールフィールドを保持する必要があります。
- 複数ターンのツール呼び出しが失敗する場合は、まずツールを 1 つだけ使用して調査します。

通常のチャットでモデルを使用できても、思考内容、ツール呼び出し、ウェブ検索、構造化出力がすべて完全に動作するとは限りません。重要なワークフローごとにヘルスチェックを行い、「こんにちは」という 1 文だけのテストで済ませないでください。

## 描画、埋め込み、リランキング

Cherry Studio の NewAPI 対応では、次の機能も使用できます。

- OpenAI 互換の画像生成と画像編集。
- OpenAI 互換の埋め込みモデル。
- Jina 互換のリランキングモデル。

使用前に、NewAPI インスタンスが該当するエンドポイントを実際に公開していることを確認し、モデルに正しいエンドポイントタイプを選択してください。

### 描画モデル

1. 画像モデルを同期するか、手動で追加します。
2. エンドポイントタイプを **OpenAI Image Generation** に設定します。
3. モデルを有効にします。
4. 描画ページでこの NewAPI プロバイダーを選択します。
5. 生成と編集を個別にテストします。

画像生成に成功しても、画像編集にも対応しているとは限りません。この 2 つは、異なる上流エンドポイント、パラメーター、課金方法を使用する場合があります。

### 埋め込みとリランキング

- 埋め込みモデルは Embeddings API を使用し、ナレッジベースと[グローバルメモリ](../../advanced-basic/memory.md)で利用できます。
- リランキングモデルでは **Jina Rerank** を選択する必要があります。
- チャット、埋め込み、リランキングモデルは異なる上流から選択できます。
- 個別にヘルスチェックを実行し、倍率を確認します。

## PDF と添付ファイル

NewAPI は統合ゲートウェイです。モデル名に Claude、Gemini、OpenAI が含まれていても、Cherry Studio はゲートウェイがネイティブ PDF を完全にサポートすると仮定しません。

現在の V2 は、先にローカルで PDF のテキストを抽出し、そのテキストを NewAPI に送信します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストは入力 Token として計上されます。
- ネイティブのマルチモーダル添付ファイルが必要な場合は、検証済みのエンドポイントとモデルを使用してください。

## 接続を確認する

サーバーからクライアントの順に確認することを推奨します。

1. NewAPI Playground で、同じトークンを使用して対象モデルをテストします。
2. Cherry Studio でプロバイダーの接続チェックを実行します。
3. **追加**をクリックし、モデルを同期できることを確認します。
4. モデルのエンドポイントタイプを確認します。
5. モデルのヘルスチェックを実行します。
6. チャット画面に戻り、通常のメッセージを送信します。
7. その後、思考、MCP、描画、ナレッジベースをテストします。

Playground でも失敗する場合、通常は NewAPI のトークン、チャネル、残高、上流側に問題があります。Playground では成功して Cherry Studio では失敗する場合は、Base URL、エンドポイントタイプ、クライアントのバージョンを重点的に確認してください。

## よくある問題

### 401 が返る

トークンが無効、削除済み、期限切れ、またはコピーが不完全です。入力したものが上流プロバイダーの Key ではなく、NewAPI のユーザートークンであることを確認してください。

### 403 が返る

トークンのモデル権限、グループ、IP ホワイトリストが現在のリクエストを許可していません。インスタンス管理者に、トークン、チャネル、グループの共通範囲を確認してもらってください。

### 404 が返る

Base URL にコンソールのパスが入力されている、エンドポイントタイプが誤っている、またはサーバーが該当ルートを公開していません。サイトのルートアドレスまたは標準の `/v1` アドレスに戻して、もう一度試してください。

### モデルリストが空

トークンで利用できるモデルがない、チャネルが有効になっていない、グループが一致しない、または旧バージョンの NewAPI の `/models` レスポンスに互換性がありません。まず NewAPI Playground と `/v1/models` で確認してください。

### モデルは存在するが、呼び出すと「未対応」と表示される

モデルマッピング、上流チャネル、Cherry Studio のエンドポイントタイプを確認します。モデルが `/models` に表示されることは、モデルが見えることだけを示し、現在のプロトコルとパラメーターの組み合わせが利用できることを保証しません。

### 割り当てまたは倍率に関するエラーが返る

ユーザー残高、トークン割り当て、グループ倍率、モデル倍率、上流アカウント残高を確認します。NewAPI の割り当てが十分でも、上流チャネルの残高が不足している場合があります。

### MCP が呼び出し計画だけを出力する

モデルがツール呼び出しに対応し、NewAPI のバージョンとチャネルが `tools`、`tool_calls`、ツール結果を保持できることを確認します。まず単純なツールを 1 つ使用し、モデルのネイティブプロトコルも試してください。

### 描画モデルがチャットリストに表示される

モデルを編集し、エンドポイントタイプを **OpenAI Image Generation** に変更して、描画ページで使用してください。画像生成モデルは通常のチャットモデルではありません。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。NewAPI の使用方法と管理方法については[公式ドキュメント](https://docs.newapi.pro/)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
