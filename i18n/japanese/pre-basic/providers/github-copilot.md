# GitHub Copilot

Cherry Studio は GitHub のデバイス認証を通じて Copilot アカウントに接続し、そのアカウントで現在利用できるモデルを読み取ることができます。API Key を手動で作成する必要はありませんが、GitHub アカウントに有効な Copilot 利用資格が必要です。

{% hint style="info" %}
GitHub Copilot、GitHub Models、GitHub Copilot CLI はそれぞれ異なる入口です。このページでは、Cherry Studio のチャットで Copilot モデルを呼び出すための `設定 → モデルプロバイダー → GitHub Copilot` について説明します。
{% endhint %}

## 使用前の確認

開始前に次の点を確認してください。

1. 正常にログインできる GitHub アカウントがある。
2. アカウントで Copilot Free、Student、Pro、Pro+、Max が有効になっているか、組織から Business / Enterprise 権限が割り当てられている。
3. 組織または企業のポリシーで、該当するモデルや Copilot 機能が禁止されていない。
4. 現在のネットワークから GitHub のログインと Copilot サービスへアクセスできる。
5. 現在のプランで利用できるモデルの範囲と [GitHub AI Credits](https://docs.github.com/en/copilot/concepts/billing) のルールを理解している。

モデル、割り当て、課金ルールはプランによって変わる場合があります。Cherry Studio は Copilot API から、アカウントで現在見えており、ポリシーで無効化されていないモデルを同期します。旧版チュートリアルの固定モデルリストを基準にしないでください。

GitHub Copilot Free と Student は、現在、主に自動モデル選択を通じて限られたモデルへのアクセスを提供します。有料プランと組織プランでは選択できるモデルが増えますが、引き続きアカウント、地域、組織ポリシー、GitHub の現在の公開状況に左右されます。

## Cherry Studio で認証する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. **GitHub Copilot** を選択します。
4. **認証を開始**をクリックします。
5. Cherry Studio が Device Code を生成するまで待ちます。
6. 認証コードをコピーします。通常はアプリが自動的にコピーしますが、手動でもコピーできます。
7. **認証ページを開く**をクリックします。
8. ブラウザーで、使用する GitHub アカウントにログインします。
9. Device Code を入力して認証を確認します。
10. Cherry Studio に戻ります。
11. **GitHub に接続**をクリックして接続を完了します。

接続に成功すると、ページに GitHub のユーザー名とアバターが表示され、プロバイダーが自動的に有効になります。

{% hint style="warning" %}
ブラウザーですでにログインしているアカウントが、接続する予定のアカウントとは限りません。認証前にユーザー名を確認してください。特に個人、仕事、Enterprise Managed User の各アカウントを切り替える場合は注意が必要です。
{% endhint %}

## 認証中に行われること

Cherry Studio は GitHub Device Flow を使用します。

1. GitHub へ一時的な Device Code をリクエストする。
2. ユーザーが GitHub ページで認証を確認する。
3. 認証結果を GitHub アクセストークンと交換する。
4. Copilot リクエストで使用できる一時トークンを取得する。
5. GitHub アクセストークンをシステムの安全なストレージで暗号化し、ローカルに保存する。
6. 以降のモデル同期またはチャット時に Copilot トークンを更新する。

したがって、「GitHub ページで認証に成功」は最初の段階にすぎません。Cherry Studio が Copilot トークンの取得にも成功して初めて、接続成功と表示されます。

{% hint style="danger" %}
Device Code、アクセストークン、Copilot トークンを他者へ送信したり、ドキュメント、チャット、コードリポジトリ、スクリーンショットに含めたりしないでください。認証コードは一時的でも、有効期限内に悪用される可能性があります。
{% endhint %}

## モデルを同期する

認証に成功した後：

1. GitHub Copilot プロバイダーが有効であることを確認します。
2. **追加**またはモデル同期をクリックします。
3. 同期プレビューを確認します。
4. 変更を適用します。
5. 使用するモデルだけを有効にします。
6. 各モデルでヘルスチェックを実行します。

Cherry Studio は Copilot の `/models` API にアクセスし、次の項目を除外します。

- GitHub ポリシーによって利用不可とマークされたモデル。
- アカウントルーティングなど、直接利用するモデルではない項目。
- 音声や文字起こしなど、現在のチャットリストに適さないモデル。

モデルが突然増減したり名称が変わったりする場合、通常は GitHub のプラン、組織ポリシー、サーバー側の公開状況の変化が原因です。再同期すると現在のリストを取得できます。

## プラン、モデル、料金

GitHub Copilot の使用量は GitHub アカウントで計測されます。Cherry Studio から開始しても無料の呼び出しにはなりません。

- プランごとに含まれる GitHub AI Credits が異なります。
- モデルの消費量は、入力、出力、キャッシュされた token、モデル価格によって決まります。
- 組織または企業は、共有割り当て、ユーザー予算、追加の使用制限を設定できます。
- 割り当てを使い切ると、呼び出しが停止されるか追加料金が発生する場合があります。
- 一部の旧年間プランでは、期限まで従来の premium request 計測が使用される場合があります。

モデルが Cherry Studio に表示されても、現在のプランですべて同じ料金になるとは限りません。使用前に GitHub の請求と Copilot 使用量ページを確認してください。

## レート制限

GitHub Copilot プロバイダーページには 1～60 の**レート制限**スライダーがあり、デフォルト値は 10 です。Cherry Studio がこのプロバイダーへ連続してリクエストするときの最小待機時間を秒単位で制御します。

- 日常的なチャットでは、まずデフォルト値を維持することを推奨します。
- レート制限が発生した場合は値を上げます。
- 高速に連続テストする場合は下げられますが、GitHub サーバー側の制限を回避することはできません。
- 複数ウィンドウ、自動タスク、同時リクエストでもアカウントの上限に達する場合があります。

GitHub は容量、公平な利用、不正利用防止に基づいてサーバー側のレート制限も実施します。制限が発生した場合は、短時間に再送し続けず、待ってから再試行し、使用量とプランを確認してください。

## モデルと機能を選択する

### 通常のチャット

モデルリストで現在利用できるモデルを選び、短いメッセージを送信します。基本的なチャットが成功してから、長いコンテキスト、画像、ツールをテストしてください。

### 画像理解

Cherry Studio は Copilot リクエストにビジョン対応のリクエストヘッダーを付加しますが、画像を実際に処理できるかは、具体的なモデルとアカウント権限によって決まります。

1. 画像対応と明記されたモデルを選択します。
2. 小さな画像を 1 枚アップロードします。
3. モデルが画像内容を実際に理解していることを確認します。
4. その後、複数画像または高解像度画像をテストします。

同じモデルでも GitHub の更新前後で機能が変わる場合があります。現在のヘルスチェックと実際の結果を基準にしてください。

### MCP とツール呼び出し

Cherry Studio MCP を使用するには、モデルが構造化 Tool Calling に対応する必要があります。

1. 先に通常のチャットを完了します。
2. 単純な MCP ツールを 1 つだけ有効にします。
3. ツールを呼び出すようモデルへ明示します。
4. 構造化された呼び出しが実際に生成されるか確認します。
5. ツール結果が返った後もモデルが回答を継続できることを確認します。
6. その後、ツール数を段階的に増やします。

アカウントで Copilot を使用できても、表示されるすべてのモデルがツールに対応するとは限りません。モデルが「ツールを呼び出す」と説明するだけで実際には呼び出さない場合は、ツール機能がより強いモデルへ変更してください。

### 思考とパラメーター

Copilot モデルごとに使用する推論パラメーターは異なります。Cherry Studio はモデルを認識して適切な設定を適用しますが、サーバー側のモデル更新がクライアントの認識ルールより先行する場合があります。

パラメーターエラーが発生した場合：

1. 思考オプションを**デフォルト**へ戻します。
2. カスタムパラメーターを削除します。
3. モデルを再同期します。
4. ヘルスチェックを再実行します。
5. その後、必要なパラメーターを 1 つずつ有効にします。

## PDF と添付ファイル

現在の V2 は、先にローカルで PDF のテキストを抽出し、Copilot の OpenAI 互換 API を通じてモデルへ送信します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストはコンテキストと GitHub AI Credits を消費します。
- PDF 内の画像はビジョンモデルへ個別に送信する必要があります。

ファイルをアップロードする前に、内容が組織のデータ使用と機密保持要件を満たすことを確認してください。Copilot はクラウドサービスであり、ローカルのオフラインモデルとして扱わないでください。

## 組織と企業アカウント

組織または企業は、Copilot の機能、モデル、ネットワークアクセスを制御できます。アカウントに Copilot が割り当てられていても、ポリシーによって一部のモデルを使用できない場合があります。

組織アカウントで問題が発生した場合は、管理者に次の点を確認してもらってください。

- ユーザーに Copilot シートが割り当てられているか。
- Copilot Chat と関連モデルが有効か。
- モデル単位のポリシー制限があるか。
- 予算または GitHub AI Credits を使い切っていないか。
- 企業ネットワークが特定の Copilot サブスクリプション用エンドポイントだけを許可しているか。
- ファイアウォール、プロキシ、TLS インスペクションが GitHub Copilot を遮断していないか。

組織ポリシーは Cherry Studio だけでなく、その認証情報を使用する複数の入口に適用されます。

## プロキシとネットワーク

認証とモデル呼び出しには、少なくとも GitHub ログイン、GitHub API、Copilot サービスへのアクセスが必要です。企業のプロキシ、ファイアウォール、VPN、セキュリティソフトが一部のアドレスだけを許可すると、次の問題が発生する場合があります。

- Device Code を生成できない。
- ブラウザーでは認証に成功しても、Cherry Studio の接続に失敗する。
- ユーザー情報は取得できても、Copilot トークンを取得できない。
- モデルリストが空になる。
- チャットリクエストがタイムアウトするか拒否される。

Cherry Studio が現在対応しているシステムプロキシまたは HTTP プロキシを優先して使用し、ネットワーク管理者に [GitHub Copilot allowlist](https://docs.github.com/en/copilot/reference/copilot-allowlist-reference) に従って必要なアドレスを許可してもらってください。

出所不明のカスタムリクエストヘッダーをむやみに追加しないでください。GitHub Copilot ページのリクエストヘッダー編集機能は、主に特殊なプロキシまたは互換性のために用意されています。誤った `Authorization`、`Host`、クライアント識別子、ルーティングヘッダーは認証失敗の原因になります。

## ログアウトとアカウントの変更

アカウントを変更する場合：

1. GitHub Copilot プロバイダーページで**GitHub からログアウト**をクリックします。
2. ユーザー名とアバターが消えたことを確認します。
3. ブラウザーで対象の GitHub アカウントへ切り替えます。
4. デバイス認証をもう一度実行します。
5. モデルを再同期します。

Cherry Studio からログアウトすると、ローカルに保存された Copilot の認証情報とプロバイダーキーが削除されますが、GitHub アカウントの OAuth 認証が取り消されるわけではありません。デバイスを紛失した場合や認証情報の漏えいが疑われる場合は、GitHub の Authorized applications 設定でもアクセスを取り消し、アカウントのセキュリティ履歴を確認してください。

## よくある問題

### Device Code の取得に失敗する

ネットワーク、プロキシ、ファイアウォール、GitHub のサービス状態を確認します。システム時刻が正しいことを確認し、GitHub のログインリクエストを遮断する可能性があるセキュリティソフトを無効にしてから再試行してください。

### GitHub ページでは認証済みだが接続に失敗する

Cherry Studio がまだ GitHub または Copilot トークンを取得していません。アプリへ戻って**GitHub に接続**をクリックしてください。タイムアウトした場合は Device Code を再生成し、古いコードを再利用しないでください。

### ユーザー名は表示されるがモデルを同期できない

GitHub へログインできても、アカウントに Copilot 権限があるとは限りません。Copilot プラン、組織のシート、モデルポリシー、使用割り当てを確認し、ログアウトして再認証してください。

### モデルリストが空

アカウントに自動モデル選択の権限しかない、組織がモデルを無効にしている、または Copilot の `/models` リクエストがネットワークで遮断されている可能性があります。まず GitHub 公式 Copilot ページでアカウントを使用できることを確認し、再同期してください。

### モデルが突然消えた

GitHub がモデルの公開状態、プラン範囲、組織ポリシーを変更した可能性があります。再同期し、GitHub の現在のモデルリストを確認してください。

### 401 または 403 が返る

認証情報の期限切れ、認証の取り消し、Copilot 権限の不足、組織ポリシーによる拒否が考えられます。ログアウト後に再認証してください。それでも失敗する場合は、アカウントのプランと管理者ポリシーを確認します。

### 429 またはレート制限が返る

待ってから再試行し、Cherry Studio のレート制限値を上げ、GitHub AI Credits、予算、サーバー側のレート制限状態を確認してください。

### 画像または MCP を使用できない

選択したモデルが該当する機能に対応していることを確認します。基本的なチャットに成功しても、モデルがビジョンまたはツール呼び出しに対応するとは限りません。

### 企業ネットワークで使用できない

ネットワーク管理者に Copilot allowlist、サブスクリプション専用ドメイン、プロキシ認証、TLS インスペクションを確認してもらってください。すべてのセキュリティポリシーを無効にして問題を解決しないでください。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。Copilot のプラン、使用量、ポリシーについては [GitHub Copilot 公式ドキュメント](https://docs.github.com/en/copilot)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
