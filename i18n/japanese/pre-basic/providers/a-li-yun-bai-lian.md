# Alibaba Cloud Model Studio

Alibaba Cloud Model Studio（阿里云百炼）は、Qwen と複数のサードパーティモデルを提供します。Cherry Studio V2 には Model Studio プロバイダーが組み込まれており、OpenAI 互換チャット、Anthropic 互換呼び出し、Embedding、Rerank、専用の画像生成・編集経路に対応しています。

V2 の中国（北京）リージョンのデフォルトアドレス：

| プロトコル | デフォルトの Base URL |
| --- | --- |
| OpenAI 互換 | `https://dashscope.aliyuncs.com/compatible-mode/v1/` |
| Anthropic 互換 | `https://dashscope.aliyuncs.com/apps/anthropic` |

{% hint style="info" %}
Model Studio の API Key、Base URL、モデルリストはリージョンごとに分離されており、リージョンをまたいで混在させることはできません。北京の Key とシンガポールのアドレス、またはシンガポールの Key と北京のアドレスを組み合わせると、通常は 401 が返ります。
{% endhint %}

## 使用前の準備

Model Studio API を初めて使用する場合、通常は次の準備が必要です。

1. Alibaba Cloud アカウントを登録してログインする。
2. アカウントの実名認証を完了する。
3. Alibaba Cloud Model Studio を有効にする。
4. 使用するリージョンを選択する。
5. API Key を作成する。
6. アカウント残高、無料割り当て、サブスクリプションの権利を確認する。
7. 対応するワークスペース ID を記録する。

モデル、価格、無料割り当て、リージョンでの提供状況は変更されます。このページでは料金を固定して記載しません。[Model Studio モデルリスト](https://help.aliyun.com/zh/model-studio/models)とコンソールの請求を基準にしてください。

## リージョンと Base URL を選択する

Model Studio はワークスペース専用ドメインの利用を推奨しています。通常、旧 DashScope 共有ドメインより安定しており、`{WorkspaceId}` を実際のワークスペース ID に置き換える必要があります。

一般的な OpenAI 互換アドレス：

| リージョン | Base URL |
| --- | --- |
| 中国（北京）デフォルト | `https://dashscope.aliyuncs.com/compatible-mode/v1/` |
| 中国（北京）専用ドメイン | `https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/compatible-mode/v1/` |
| シンガポール | `https://{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1/` |
| 日本（東京） | `https://{WorkspaceId}.ap-northeast-1.maas.aliyuncs.com/compatible-mode/v1/` |
| ドイツ（フランクフルト） | `https://{WorkspaceId}.eu-central-1.maas.aliyuncs.com/compatible-mode/v1/` |
| 米国（バージニア） | `https://dashscope-us.aliyuncs.com/compatible-mode/v1/` |

対応する Anthropic 互換アドレスでは通常、末尾のパスを `/apps/anthropic` に置き換えます。モデルごとに対応リージョンとプロトコルが異なる場合があります。モデル名から推測せず、モデル詳細ページからアドレスをコピーしてください。

{% hint style="warning" %}
`{WorkspaceId}` をそのまま Cherry Studio へ入力しないでください。ワークスペース ID は Model Studio のワークスペース管理ページで確認でき、通常は `llm-...` のような形式です。
{% endhint %}

## API Key を取得する

1. [Model Studio API Key 管理](https://bailian.console.aliyun.com/?tab=model#/api-key)を開きます。
2. ページ右上で対象リージョンを確認します。
3. **API Key を作成**をクリックします。
4. 所属するワークスペースを選択します。
5. すべての権限を選択するか、組織の要件に従って IP ホワイトリストとモデル範囲を設定します。
6. 識別しやすい説明を入力します。
7. 作成後すぐにコピーし、安全に保管します。

新しく作成した従量課金 Key は `sk-ws` で始まる場合があり、作成時に一度だけ表示されます。旧版の `sk-` Key も引き続き使用できる場合があります。

{% hint style="danger" %}
API Key はアカウントの認証情報に相当します。チャット、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。漏えいした場合は、Model Studio コンソールですぐにリセットまたは削除してください。
{% endhint %}

## Cherry Studio で設定する

### 北京のデフォルトアドレスを使用する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. **Bailian / Alibaba Cloud Model Studio** を選択します。
4. 北京リージョンの API Key を貼り付けます。
5. OpenAI Base URL `https://dashscope.aliyuncs.com/compatible-mode/v1/` を維持します。
6. ページ上部のプロバイダースイッチをオンにします。
7. **追加**またはモデル同期をクリックします。
8. 同期プレビューを確認して変更を適用します。
9. 使用するモデルだけを有効にします。
10. モデルのヘルスチェックを実行します。

### 他のリージョンまたは専用ドメインを使用する

1. Model Studio コンソールで対象ワークスペースの API Host をコピーします。
2. Cherry Studio の OpenAI Base URL を、対応する `/compatible-mode/v1/` アドレスへ変更します。
3. Anthropic 互換ワークフローを使用する場合は、Anthropic Base URL も更新します。
4. **同じリージョン、同じ課金プラン**で作成された API Key を使用します。
5. モデルを再同期します。
6. 各モデルでヘルスチェックを実行します。

V2 は、ユーザーが設定した OpenAI Base URL から画像 API のホストを推定します。そのため、専用ドメインへ変更した後は、画像リクエストもそのドメインを使用し、北京の共有ドメインへ強制的に戻ることはありません。

## モデルを同期・追加する

Model Studio のモデル範囲は頻繁に更新され、V2 の組み込みリストは初回表示用にすぎません。同期時は、Model Studio が現在返す結果を基準にしてください。

推奨手順：

1. リージョンと Key が一致することを確認します。
2. モデルを同期します。
3. 追加、更新、削除項目を確認します。
4. 同期結果を適用します。
5. モデルの機能タグを確認します。
6. 手動で残していた期限切れモデルを削除します。
7. 1 つずつヘルスチェックを実行します。

同期結果が不完全な場合は、Model Studio のモデルページから完全な Model ID をコピーして手動で追加できます。大文字と小文字、スラッシュ、バージョンサフィックスはすべて ID の一部であり、サードパーティモデルには組織プレフィックスが付く場合があります。

{% hint style="warning" %}
モデルが V2 のプリセットまたは別リージョンに表示されても、現在の API Key で呼び出せるとは限りません。最終的な権限は、Model Studio サーバー、ワークスペース権限、リージョンのモデルリストによって共同で決まります。
{% endhint %}

## チャットモデル

通常のチャットは OpenAI 互換 Chat Completions を使用します。

次の順序でテストすることを推奨します。

1. 短いテキストメッセージを送信します。
2. ストリーミング出力を確認します。
3. システムプロンプトを追加します。
4. より長いコンテキストをテストします。
5. その後、画像、思考、ツール呼び出しをテストします。

Model Studio は Qwen とサードパーティモデルを提供します。同じプロバイダーのモデルであっても、Model Studio を通じて呼び出す場合は、他のプラットフォームの ID をコピーせず、Model Studio のモデルページに記載された Model ID とパラメーターを使用してください。

## Anthropic 互換と Code Tools

Model Studio は Anthropic 互換 Messages API を提供し、カスタム Anthropic アドレスに対応するプログラミングツールや Agent ワークフローで使用できます。

Cherry Studio では：

1. 対象モデルが Anthropic 互換プロトコルに対応することを確認します。
2. リージョンに対応する Anthropic Base URL を入力します。
3. API Key とリージョンを一致させます。
4. 先に通常のチャットを実行します。
5. その後、Code Tools または Agent の場面でテストします。

OpenAI と Anthropic の互換アドレスは同じパスではありません。OpenAI Base URL だけを変更しても、Anthropic ワークフローが自動的に同じリージョンを指すとは限りません。

## 思考モード

Model Studio 上の Qwen、DeepSeek、GLM、Kimi などのモデルでは、異なる思考パラメーターを使用する場合があります。Cherry Studio V2 は、モデルシリーズに応じて `enable_thinking` や思考予算などのパラメーターを適用します。

思考を有効にした後にエラーが発生した場合：

1. 思考設定を**デフォルト**へ戻します。
2. モデルのカスタムパラメーターを削除します。
3. 現在の Model ID を使用していることを確認します。
4. 現在のリージョンにおけるモデルの公式例を確認します。
5. ヘルスチェックを再実行します。

一部のモデルは思考のオン・オフだけに対応し、`low`、`medium`、`high` などの強度を選択できません。他のプラットフォームの推論パラメーターを Model Studio へ直接コピーしないでください。

## ビジョンとマルチモーダル

画像、音声、動画入力に明示的に対応するモデルだけが、該当する添付ファイルを受け取れます。

ビジョンモデルをテストする場合：

1. 最新の Model ID を同期します。
2. モデルに画像機能が表示されることを確認します。
3. まず小さな画像を 1 枚アップロードします。
4. モデルが内容を実際に理解しているか確認します。
5. その後、複数画像、動画、高解像度ファイルを試します。

同じシリーズでも、テキスト版、ビジョン版、Omni 版が異なるモデルの場合があります。添付ファイルはコンテキスト、ネットワーク時間、料金を増やします。

## MCP とツール呼び出し

Cherry Studio MCP を使用するには、モデルが構造化 Tool Calling に対応する必要があります。

1. 先に通常のチャットが動作することを確認します。
2. 単純な MCP ツールを 1 つだけ有効にします。
3. 呼び出すよう明示します。
4. 構造化された呼び出しが生成されるか確認します。
5. ツール結果がモデルへ返されることを確認します。
6. その後、ツールを追加します。

モデルが「ツールを呼び出す」とテキストで説明するだけでは実際の呼び出しではありません。この場合は、モデル機能、プロトコル、プロンプト、ツール定義を確認してください。

## Embedding、Rerank、ナレッジベース

Model Studio はテキストとマルチモーダルの Embedding、およびテキストとマルチモーダルの Rerank を提供します。現在のモデルページで推奨される項目には、次が含まれる場合があります。

- テキスト Embedding：`text-embedding-v4`。
- テキスト Rerank：`qwen3-rerank`。
- マルチモーダル Embedding：`qwen3-vl-embedding`。
- マルチモーダル Rerank：`qwen3-vl-rerank`。

これらはプラットフォームの例であり、恒久的なリストではありません。`gte-rerank` は 2026 年 5 月 30 日に廃止されたため、旧チュートリアルに従って設定しないでください。

ナレッジベースを作成する場合：

1. 現在利用できる Embedding モデルを追加します。
2. Cherry Studio が埋め込みモデルとして認識していることを確認します。
3. ベクトル次元を検出します。
4. ヘルスチェックを実行します。
5. Rerank モデルを追加してテストします。
6. 少数のドキュメントをインポートして試します。
7. 検索とリランキングの結果を確認してから一括インポートします。

Embedding モデルまたはベクトル次元を既存のナレッジベースで使用した後は、直接変更しないでください。通常、ベクトルインデックスの再構築が必要になります。

Model Studio の Rerank エンドポイントと機能はリージョンごとに異なる場合があります。モデルを追加できてもリランキングリクエストに失敗する場合は、まず Rerank を無効にして基本検索を利用できる状態にし、現在の V2 バージョン、リージョン API、モデル権限を確認してください。

## 画像の生成と編集

Cherry Studio V2 は Model Studio 専用の画像転送経路を実装しています。

1. モデルに応じてネイティブの DashScope 画像 API を選択する。
2. 非同期モデルではリクエストで `X-DashScope-Async` を有効にする。
3. `task_id` を取得する。
4. タスク状態をポーリングする。
5. 成功後に画像 URL を読み取る。

V2 は対応済みモデルにだけ、対応するモードとパラメーターを表示します。例：

- テキストから画像。
- 画像編集。
- 画像翻訳。
- サイズ。
- Seed。
- ネガティブプロンプト。
- ウォーターマーク。
- 一部のモデルの参照画像または機能タイプ。

Model Studio 公式サイトに掲載されるすべての画像モデルが、現在の V2 ですでに対応済みとは限りません。Cherry Studio の描画ページで選択できる Model Studio モデルからテストしてください。

{% hint style="warning" %}
画像タスクは、正常に出力された枚数に基づいて課金される場合があります。初回テストでは出力数を 1 に設定し、非同期結果の待機中に再送信しないでください。
{% endhint %}

Cherry Studio で待機をキャンセルしても、ローカルのポーリングが停止するだけです。DashScope には現在の V2 から呼び出せる汎用タスクキャンセル API がないため、送信済みタスクが実行を続け、料金が発生する場合があります。

## PDF と添付ファイル

現在の V2 は先にローカルで PDF のテキストを抽出し、Model Studio のチャットモデルへ送信します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストはモデルコンテキストと料金を消費します。
- PDF 内の画像はビジョンモデルへ個別に送信する必要があります。

Model Studio はクラウドサービスです。ドキュメント、画像、ナレッジベースの内容をアップロードする前に、プライバシー、国境を越えるデータ移転、組織のセキュリティ要件を満たすことを確認し、選択したリージョンのデータ処理範囲に特に注意してください。

## 割り当て、権限、レート制限

Model Studio では、次の要因が同時に制限となる場合があります。

- アカウント残高と無料割り当て。
- ワークスペース予算。
- Key の IP ホワイトリスト。
- Key のモデル権限。
- RPM / TPM。
- 同時実行タスク数。
- 画像タスクのキュー。
- リージョンのリソース提供状況。

複数の自動タスクが同じ Key を共有して無制限に再試行しないよう、コンソールで予算と使用量アラートを設定することを推奨します。

## よくある問題

### 401 が返る

API Key が誤っている、リセット済み、または Key と Base URL のリージョンが一致していません。先にリージョンを確認し、対応する Key をもう一度コピーしてください。

### 403 が返る

Key にモデル権限がない、IP がホワイトリストにない、ワークスペースが認証されていない、またはアカウント状態が制限されています。Key の権限とワークスペースポリシーを確認してください。

### 404 が返る

Base URL、Workspace ID、プロトコルパス、または Model ID が誤っています。コンソールページの URL を API アドレスとして使用しないでください。

### 429 が返る

RPM、TPM、同時実行、またはタスクキューの上限に達しています。同時実行数を下げ、コンテキストを短くして、回復を待ってください。すぐにループして再試行しないでください。

### 残高不足または割り当て不足が表示される

アカウント残高、無料割り当て、ワークスペース予算、モデルの課金方法を確認します。モデルごとに異なる割り当てプールを使用する場合があります。

### モデルリストが空

リージョン、API Key、Base URL、ネットワークプロキシを確認します。現在のリージョンのモデルページから完全な Model ID をコピーして手動で追加することもできます。

### プリセットモデルを使用できない

V2 のプリセットが、Model Studio によるモデルの廃止またはリージョン変更より古い場合があります。再同期し、現在のリージョンのモデルリストを基準にしてください。

### 通常のチャットは使用できるが Agent または Code Tools は使用できない

Anthropic Base URL が北京のデフォルトアドレスを指したままになっていないか、対象モデルが Anthropic 互換プロトコルとツール呼び出しに対応するか確認してください。

### 画像生成で誤ったアドレスが返る

OpenAI Base URL に正しいワークスペースドメインと `/compatible-mode/v1/` サフィックスが含まれることを確認します。V2 はこのアドレスからネイティブ画像 API のホストを推定します。

### 画像タスクが待機し続ける

タスクがまだキュー内にある、ポーリングネットワークに失敗した、割り当て不足、またはモデルが混雑しています。まずエラー情報と Model Studio のタスク状態を確認し、再送信しないでください。

### Rerank モデルを選択できるが機能しない

モデルが廃止済みでないこと、リージョン API に互換性があること、ナレッジベースで Rerank が実際に有効であることを確認します。必要に応じて一時的にリランキングを無効にし、先に Embedding 検索を検証してください。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。Model Studio の現在のリージョン、Key、モデルについては[リージョンと接続ドメイン](https://help.aliyun.com/zh/model-studio/regions/)、[API Key の取得](https://help.aliyun.com/zh/model-studio/get-api-key/)、[モデルの選択](https://help.aliyun.com/zh/model-studio/models)、[ベクトルとリランキング](https://help.aliyun.com/zh/model-studio/embedding-rerank-model/)、[画像の生成と編集](https://help.aliyun.com/zh/model-studio/image-model)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
