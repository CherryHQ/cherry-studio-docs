# OneAPI

OneAPI は、複数の上流 LLM チャネルを OpenAI 互換 API に変換するゲートウェイです。管理者が OneAPI で上流の Key、モデル、ルーティングを設定し、一般ユーザーは OneAPI が発行したトークンを使用して Cherry Studio に接続します。

Cherry Studio V2 には OneAPI 専用の組み込みプロバイダーはありません。OneAPI と NewAPI は **New API** 互換アダプターを共有します。標準の OneAPI インスタンスでは、通常、モデルのエンドポイントタイプに **OpenAI Chat Completions** を選択します。

{% hint style="warning" %}
リクエストは OneAPI インスタンスとその上流チャネルを経由します。自分でデプロイしたサービス、または明確に信頼でき、上流サービスを合法的に利用する権限とコンプライアンス責任を備えたサービスだけを使用してください。出所不明の公開インスタンスは、リクエストの記録、添付ファイルの漏えい、誤課金を引き起こす可能性があります。
{% endhint %}

## OneAPI と NewAPI の違い

OneAPI は以前からある統合ゲートウェイプロジェクトです。NewAPI は同様のアーキテクチャを基に、より多くのネイティブプロトコル、エンドポイントタイプ、モデルメタデータを追加しています。

| 項目 | Cherry Studio での推奨設定 |
| --- | --- |
| OneAPI | New API 互換プロバイダーを使用し、デフォルトで OpenAI Chat Completions として処理する |
| NewAPI | 専用の New API タイプを使用し、モデルごとに Chat、Responses、Anthropic、Gemini、画像、Rerank を選択する |

インスタンスが二次開発またはテーマのカスタマイズを行っている場合、ページの外観だけではどちらのプロジェクトか判断できません。サーバーのバージョンと対応する API プロトコルを管理者へ確認してください。

## 自分の役割を先に確認する

一般ユーザーに必要なのは、インスタンスのアドレスとユーザートークンだけです。管理者は上流チャネルも管理する必要があります。

| 役割 | 準備作業 |
| --- | --- |
| 一般ユーザー | 専用トークンを作成し、割り当て、グループ、モデル権限を確認する |
| 管理者 | 上流チャネル、モデルマッピング、倍率、グループ、フェイルオーバーを設定する |

OpenAI や Anthropic など、上流プロバイダーの Key を Cherry Studio の OneAPI 接続へ直接入力しないでください。クライアントでは OneAPI が発行したトークンを使用します。

## OneAPI でトークンを作成する

1. 信頼できる OneAPI インスタンスへログインします。
2. **トークン**ページを開きます。
3. Cherry Studio 専用の新しいトークンを作成します。
4. 必要に応じて、名前、割り当て、有効期限、利用可能なモデルを設定します。
5. トークンをコピーし、安全に保管します。
6. OneAPI 内蔵のテスト機能でモデルを 1 つ検証します。

デフォルトトークンを長期的に共用することは推奨しません。個別のトークンなら、使用量の監査、上限の設定、個別の取り消しが容易になります。

{% hint style="danger" %}
OneAPI トークンをチャットメッセージ、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。漏えいした場合は、OneAPI コンソールですぐに削除し、再作成してください。
{% endhint %}

## API Base URL を取得する

OneAPI の公式な OpenAI 互換形式では、通常、次の形式を使用します。

```text
https://your-oneapi.example.com/v1
```

Cherry Studio の New API 互換アダプターは、サイトのルートアドレスに `/v1` を補完します。そのため、次の 2 つの形式をどちらも使用できます。

- `https://your-oneapi.example.com`
- `https://your-oneapi.example.com/v1`

ローカルまたは LAN でのデプロイでは、次の形式も使用できます。

- `http://localhost:3000`
- `http://192.168.1.20:3000`

注意事項：

- `http` と `https` はサーバーの実際の設定と一致させる必要があります。
- 公開サービスでは有効な HTTPS 証明書を使用してください。
- `/console/...`、ログインページ、トークンページは API Base URL ではありません。
- 特定の `/chat/completions` パスを入力しないでください。

## Cherry Studio で設定する

他の NewAPI ゲートウェイを使用していない場合は、組み込みの **New API** をそのまま設定できます。すでに別のインスタンスを使用している場合は、既存の設定を上書きしないよう、New API 互換プロバイダーをコピーまたは新規追加してください。

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. **New API** を選択するか、New API をテンプレートにしたプロバイダーを追加します。
4. 名前を識別しやすい OneAPI インスタンス名に変更します。
5. OneAPI のユーザートークンを入力します。
6. OneAPI の Base URL を入力します。
7. ページ上部のプロバイダースイッチをオンにします。
8. **追加**をクリックしてモデルリストを同期します。
9. 標準 OneAPI モデルのエンドポイントタイプを **OpenAI Chat Completions** に設定します。
10. 使用するモデルだけを有効にします。

OneAPI の `/models` レスポンスは通常、新しい NewAPI バージョンの `supported_endpoint_types` を提供しません。そのため、Cherry Studio が一括追加時にエンドポイントタイプの選択を求める場合がありますが、これは正常です。

## モデルを追加する

他のインスタンスのモデル名をコピーせず、サーバーからの同期を優先してください。

同期に失敗した場合は、手動で追加できます。

1. OneAPI コンソールで、トークンから見える完全なモデル ID を確認します。
2. Cherry Studio で**モデルを追加**をクリックします。
3. 完全に同じモデル ID を入力します。
4. エンドポイントタイプに **OpenAI Chat Completions** を選択します。
5. 保存してヘルスチェックを実行します。

モデルの表示名はカスタマイズできますが、実際のモデル ID は OneAPI の利用可能なモデルまたはマッピング名と一致させる必要があります。

{% hint style="info" %}
OneAPI はクライアントがリクエストしたモデル ID を上流モデルへマッピングします。モデルが存在しない場合は、Cherry Studio の ID、OneAPI のチャネルモデル、管理者が設定したモデルマッピングをすべて確認してください。
{% endhint %}

## 機能の境界

OneAPI は主に、異なる上流サービスを OpenAI 互換形式に統一します。基本的なチャットは通常もっとも安定していますが、新しいネイティブ機能が完全に保持されるとは限りません。

- Claude のネイティブ thinking block は変換または欠落する場合があります。
- Gemini のネイティブなマルチモーダル構造は、インスタンスのバージョンによって制限される場合があります。
- OpenAI Responses 専用の機能は Chat Completions と同じではありません。
- ツール呼び出しでは、OneAPI と上流サービスの両方が `tools` と `tool_calls` を正しく変換する必要があります。
- ウェブ検索、キャッシュ、サービス階層など、プロバイダー固有のパラメーターが機能しない場合があります。
- モデルがリストに表示されても、すべてのパラメーターの組み合わせが利用できるとは限りません。

ワークフローが特定プロバイダーの最新ネイティブ機能に依存する場合は、モデルの公式プロバイダー、または対応するネイティブエンドポイントをサポートする新しいバージョンの NewAPI を優先してください。

## ツール呼び出しと MCP

Function Calling に対応する OneAPI モデルを MCP に接続できますが、まず最小構成でテストしてください。

1. ツール呼び出しに明確に対応するモデルを選択します。
2. 通常のチャットを 1 ターン完了します。
3. 単純な MCP ツールを 1 つだけ有効にします。
4. そのツールを呼び出すようモデルへ明示します。
5. OneAPI のログにツールリクエストが記録されていることを確認します。
6. その後、ツールを追加します。

モデルが呼び出し計画だけを出力する場合は、上流モデルがツールに対応していない、OneAPI の変換が不完全、またはチャネルがツールフィールドを削除している可能性があります。まず OneAPI で同じモデルを直接テストしてください。

## ナレッジベースと埋め込みモデル

OneAPI インスタンスが互換性のある Embeddings API を公開している場合、埋め込みモデルをナレッジベースまたは[グローバルメモリ](../../advanced-basic/memory.md)で使用できます。

- インスタンスが実際に提供する埋め込みモデルだけを追加します。
- チャットモデルを埋め込みモデルとして使用しないでください。
- チャットと埋め込みには異なるプロバイダーを使用できます。
- 個別にヘルスチェックを実行します。
- OneAPI と上流サービスの課金倍率を確認します。

旧バージョンのインスタンスまたは特定のチャネルには、埋め込み API がない場合があります。モデル名が存在しても、`/v1/embeddings` を使用できるとは限りません。

## PDF と添付ファイル

OneAPI は統合ゲートウェイです。Cherry Studio は、モデル名だけを見てネイティブ PDF に対応しているとは判断しません。

現在の V2 は、先にローカルで PDF のテキストを抽出し、その後 OneAPI へ送信します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストは入力 Token を消費します。
- 画像などのマルチモーダル添付ファイルは、引き続きインスタンスと上流サービスの機能に依存します。

## 管理者向けチェックリスト

ユーザーへトークンを発行する前に、管理者は次の点を確認してください。

1. 上流チャネルのテストに成功している。
2. チャネルで有効にしたモデルが実際の権限と一致している。
3. モデルマッピングにスペルミスがない。
4. ユーザーグループが対象チャネルへアクセスできる。
5. モデル倍率とグループ倍率が正しい。
6. トークン制限がユーザーの用途と一致している。
7. `/v1/models` と `/v1/chat/completions` がどちらも利用できる。
8. 重要なモデルでツール呼び出しのテストを完了している。

複数チャネルの負荷分散では、同じモデルが異なる上流へルーティングされる場合があります。安定した動作が必要な場合は、一貫性のないチャネルを減らすか、OneAPI が対応する方法で管理者にチャネルを固定してもらってください。

## 接続を確認する

1. OneAPI 内蔵のテストまたは互換リクエストで同じトークンを検証します。
2. Cherry Studio でプロバイダーの接続チェックを実行します。
3. **追加**をクリックし、モデルリストを同期できることを確認します。
4. エンドポイントタイプが OpenAI Chat Completions であることを確認します。
5. モデルのヘルスチェックを実行します。
6. チャット画面に戻り、簡単なメッセージを送信します。
7. その後、ツール呼び出し、添付ファイル、ナレッジベースをテストします。

サーバー側でも失敗する場合は、OneAPI のチャネル、トークン、上流サービスを優先して確認します。Cherry Studio だけが失敗する場合は、Base URL、モデル ID、エンドポイントタイプを重点的に確認してください。

## よくある問題

### 401 が返る

トークンが無効、削除済み、期限切れ、またはコピーが不完全です。入力したものが上流プロバイダーの Key ではなく、OneAPI のユーザートークンであることを確認してください。

### 403 が返る

トークンに対象モデルの権限がない、割り当てを使い切った、またはグループから利用可能なチャネルへアクセスできません。インスタンス管理者へ確認してください。

### 404 が返る

Base URL に管理画面または特定の API パスが入力されているか、インスタンスが標準の OpenAI 互換ルートを公開していません。サイトのルートアドレスまたは `/v1` に戻してください。

### モデルリストが空

トークンから見えるモデルがない、チャネルが有効になっていない、グループが一致しない、またはインスタンスの `/models` レスポンスに互換性がありません。まず OneAPI でテストし、`/v1/models` を確認してください。

### モデルは存在するが呼び出しに失敗する

OneAPI のモデルマッピングと上流チャネルを確認します。リストのモデル名は入口にすぎず、実際のルーティング先が見つからない、または権限がない場合があります。

### 思考内容、ウェブ検索、ツール機能がない

OneAPI の OpenAI 形式変換が、プロバイダーのネイティブフィールドを保持していない可能性があります。単純な Chat Completions 機能と比較してください。完全なネイティブ機能が必要な場合は、公式プロバイダーまたは NewAPI の対応するエンドポイントを使用します。

### リクエスト結果が安定しない

複数チャネルでモデルのバージョン、パラメーター対応、残高が一致していません。管理者にチャネルテスト、優先順位、重み、自動無効化の状態を確認してもらってください。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。インスタンスが実際には NewAPI の場合は、[NewAPI](newapi.md)を参照してください。OneAPI プロジェクトについては[公式リポジトリ](https://github.com/songquanpeng/one-api)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
