# OpenRouter

OpenRouter は複数のモデルを統合するゲートウェイです。Cherry Studio V2 の組み込み OpenRouter テンプレートでは、1 組の API Key で OpenRouter のチャットモデルと埋め込みモデルを同期でき、推論内容、ウェブ検索プラグイン、モデル機能にも対応しています。

{% hint style="warning" %}
OpenRouter はモデルの開発元ではありません。リクエストは OpenRouter を経由し、複数の上流推論プロバイダーへルーティングされる場合があります。機密データを使用する前に、OpenRouter のコンソールでプライバシー、ログ、プロバイダーのルーティングポリシーを確認してください。
{% endhint %}

## 始める前の準備

- [OpenRouter](https://openrouter.ai/) にログインできるアカウント
- [OpenRouter Keys](https://openrouter.ai/settings/keys) で作成した API Key
- 利用可能な残高または無料モデルのクォータがあるアカウント
- モデルの料金、コンテキスト、ツール、データポリシーを確認済みであること

Cherry Studio 専用の Key を作成し、OpenRouter で適切な利用上限を設定することをおすすめします。使用量を区別しやすくなり、Key が漏えいした場合のリスクも抑えられます。

## OpenRouter を設定する

1. `設定 → モデルプロバイダー` を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替え、**OpenRouter** を選択します。
3. OpenRouter API Key を入力します。
4. 既定の Base URL `https://openrouter.ai/api/v1/` を変更せずに使用します。
5. 画面上部にあるプロバイダーのスイッチをオンにします。
6. モデルリストで**追加**をクリックし、同期プレビューを確認して変更を適用します。
7. 使用するモデルだけを有効にします。

{% hint style="danger" %}
API Key をチャットメッセージ、ドキュメント、コードリポジトリ、または問題報告用のスクリーンショットに含めないでください。漏えいした場合は、OpenRouter ですぐに取り消して作り直してください。
{% endhint %}

## モデル ID を理解する

OpenRouter のモデル ID は通常、`<組織>/<モデル>` 形式です。例：

| 種類 | 例 |
| --- | --- |
| 固定モデル | `openai/gpt-oss-120b` |
| 開発元の最新別名 | `~anthropic/claude-sonnet-latest` |
| 自動ルーティング | `openrouter/auto` |
| 無料ルーティング | `openrouter/free` |
| 無料版 | 特定のモデル ID の末尾に `:free` を付加 |

- 完全なモデル ID によって上流モデルとルーティング動作が決まります。
- `latest`、自動ルーティング、無料ルーティングで実際に使われるモデルは変わる場合があります。
- 再現可能な結果が必要な場合は、動的な別名ではなく固定バージョンを選択します。
- 無料版にはレート、可用性、データポリシーの制限がある場合があります。
- 表示名だけで料金と機能を判断しないでください。

**追加**をクリックすると現在のモデルが同期されるため、数百個のモデルをすべて有効にする必要はありません。チームが実際に使用する少数のモデルを優先すると、モデル選択が見やすくなります。

## チャットモデルと埋め込みモデル

Cherry Studio は OpenRouter のチャットモデル API と埋め込みモデル API を個別に呼び出し、同期結果を統合します。

- チャットモデルは、アシスタント、翻訳、通常のチャットで使用できます。
- ツール呼び出しに対応するモデルは、MCP または Agent で使用できます。
- 埋め込みモデルは、ナレッジベースと[グローバルメモリ](../../advanced-basic/memory.md)で使用できます。
- 同じ Key でも、モデルごとに権限、料金、制限が異なる場合があります。
- モデルが一覧に表示されても、すべての上流プロバイダーを利用できるとは限りません。

ナレッジベース用のモデルを選ぶときは、開発元の名前だけで判断せず、実際に埋め込みモデルであることを確認してください。

## 思考モードを設定する

OpenRouter はモデルごとに異なる推論パラメーターを `reasoning` 設定へ統一します。Cherry Studio はモデルの機能に応じて、無効化、強度、予算の設定を送信し、複数ターンのツール呼び出しに必要な推論内容も維持します。

- **デフォルト**を選択すると、OpenRouter または上流の既定の動作をできるだけ使用します。
- **オフ**を選択すると、対応するモデルに推論を無効にする設定を送信します。
- 低、中、高などの選択肢は、該当する強度に対応するモデルでのみ機能します。
- 推論 Token は通常、出力使用量に含まれます。
- 一部のモデルは、表示可能な思考内容を返しません。

モデルを切り替えた後に思考ボタンの選択肢が変わるのは正常です。1 つのモデルの推論設定をすべてのモデルへそのまま適用しないでください。

## ウェブ検索を使用する

チャットの入力欄で**ウェブ検索**を有効にすると、現在の Cherry Studio V2 は OpenRouter のリクエストに Web Search プラグインを追加し、ウェブ検索設定の最大結果数を渡します。

使用手順：

1. OpenRouter のモデルを選択します。
2. 入力欄の**ウェブ検索**を有効にします。
3. 現在のウェブ情報が必要な質問を入力します。
4. 検索とモデルの回答を待ちます。
5. 引用を展開して確認します。

{% hint style="info" %}
OpenRouter のウェブ検索には追加の検索料金が発生します。基になるモデルが無料版でも課金される場合があります。OpenRouter は従来の Web プラグインからサーバー側検索ツールへ移行中です。ウェブ検索が突然使えなくなった場合は、まず Cherry Studio を更新し、OpenRouter の最新ドキュメントを確認してください。
{% endhint %}

Perplexity Sonar や OpenAI Search など検索機能を内蔵するモデルでは、ウェブ検索の動作が異なる場合があります。モデル自体がウェブ検索を必須とするかどうかも、OpenRouter と上流の機能によって決まります。

## ツール呼び出しと Agent

組み込み OpenRouter テンプレートには OpenAI Chat Completions と Anthropic Messages のエンドポイントが含まれますが、実際のツール機能はモデルと上流のルーティングによって異なります。

使用前：

1. ツール呼び出しに明確に対応するモデルを選択します。
2. 通常のチャットでヘルスチェックを実行します。
3. 簡単な MCP ツールを 1 つ有効にします。
4. モデルが実際に呼び出しを開始することを確認します。
5. その後で複数のツールまたは長い処理の Agent を追加します。

Agent の安定性に問題がある場合は、モデル開発元、Anthropic、CherryIN への直接接続と結果を比較できます。OpenRouter の統合された入口は便利ですが、上流ルーティングという変数が 1 つ増えます。

## プライバシーと上流ルーティング

OpenRouter は既定で、利用可能な上流間をルーティングして可用性を高めます。現在の Cherry Studio は、OpenRouter のすべてのプロバイダールーティング項目とプライバシー項目をユーザーに代わって設定しません。

OpenRouter のコンソールで次を確認してください。

- 入出力ログが有効か
- OpenRouter による入出力の使用を許可しているか
- データを保存する可能性がある上流を制限しているか
- Zero Data Retention を必須にしているか
- fallback を許可しているか
- 組織または Key のモデル制限と利用上限

これらは OpenRouter のアカウントポリシーです。Cherry Studio がローカルクライアントであっても自動的には変わりません。

## 接続を確認する

1. API Key エリアで接続チェックを実行します。
2. 同期して有効にしたモデルを 1 つ選択します。
3. チェックに成功することを確認します。
4. モデルリストでヘルスチェックを実行します。
5. チャット画面に戻り、簡単なメッセージを送信します。
6. 続いて推論、ウェブ検索、ツール呼び出しを個別にテストします。

接続チェックに成功しても、基本的な認証情報が利用できることしか確認できません。特定のモデルは、残高、上流の障害、プライバシーポリシー、パラメーターの非互換性などによって失敗する場合があります。

## よくある質問

### 401 が返される

API Key が無効、取り消し済み、または正しくコピーされていません。Key を作り直し、余分な空白が含まれていないことを確認してください。

### 残高または利用枠のエラーが返される

OpenRouter の残高、Key の上限、組織ポリシーを確認してください。無料モデルにも個別のレート制限がある場合があります。

### 404 または「モデルが存在しません」と返される

モデル ID が変更された、モデルが削除された、または動的な別名を現在利用できません。もう一度**追加**をクリックしてリストを同期し、[OpenRouter Models](https://openrouter.ai/models)で確認してください。

### 429 が返される

現在のモデル、上流プロバイダー、または Key がレート制限に達しています。同時実行数を減らして後でもう一度試すか、別の利用可能なルートを選択してください。

### 同じモデルの結果または料金が変わる

動的な別名、自動ルーティング、上流の fallback によって、異なるバージョンまたはプロバイダーが選択される場合があります。安定した動作が必要な場合は固定モデル ID を使用し、OpenRouter のコンソールでルーティングを制限してください。

### ウェブ検索に引用がない

入力欄でウェブ検索が有効であることを確認し、OpenRouter の検索機能が現在の Cherry Studio バージョンと互換性があるか確認してください。検索プラグインとモデル内蔵の検索は異なる仕組みです。

### ツール呼び出しが不安定

モデルページでツール対応と表示されていることを確認し、上流がリクエスト内のすべてのパラメーターに対応しているか確認してください。特定のプロバイダールートに固定するか、モデル開発元へ直接接続して比較できます。

一般的な設定は[モデルプロバイダー](README.md)、[ウェブ検索モード](../../websearch/README.md)、[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。フィードバック先は[フィードバックとご提案](../../question-contact/suggestions.md)を参照してください。
