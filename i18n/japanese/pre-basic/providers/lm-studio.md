# LM Studio

LM Studio は macOS、Windows、Linux でローカルモデルをダウンロードして実行し、OpenAI 互換 API を通じて Cherry Studio にチャット、ビジョン、ツール呼び出し、埋め込み機能を提供できます。

Cherry Studio V2 には LM Studio プロバイダーが組み込まれており、デフォルトで `http://localhost:1234` に接続します。通常のチャットは OpenAI 互換 API を使用し、モデルリストは `/v1/models` から取得します。

{% hint style="info" %}
Cherry Studio のモデル同期は LM Studio から現在見えるモデルを読み取るだけで、モデルのダウンロードは行いません。先に LM Studio の **Discover** ページでモデルをダウンロードし、ローカル API Server を起動してください。
{% endhint %}

## LM Studio を準備する

1. [LM Studio 公式サイト](https://lmstudio.ai/)から最新版をダウンロードしてインストールします。
2. **Discover** を開き、モデルを検索してダウンロードします。
3. デバイスのメモリまたは VRAM に応じて、パラメーター規模と量子化版を選択します。
4. **Developer** ページを開きます。
5. **Start server** をクリックして API Server を起動します。

デフォルトのリッスンアドレス：

```text
http://localhost:1234
```

ターミナルから起動することもできます。

```bash
lms server start
```

初めて使用する場合は、先に LM Studio 内で一度モデルを読み込んでチャットし、モデル自体が動作することを確認してから Cherry Studio に接続してください。

## モデルと量子化を選択する

モデルファイル、量子化方式、コンテキスト長は、すべてメモリ使用量と速度に影響します。

- パラメーター規模が大きいほど一般に能力は高くなりますが、より多くの RAM または VRAM が必要です。
- GGUF モデルは CPU と GPU を組み合わせた推論を使用できます。
- Apple Silicon では互換性のある MLX モデルを使用できます。
- 低ビット量子化は使用量を減らしますが、出力品質が下がる場合があります。
- コンテキストが長いほど KV Cache の使用量が増えます。
- ビジョンモデルは画像のエンコードも必要なため、通常は同規模のテキスト専用モデルより多くのリソースを使用します。

迷う場合は、まずデバイスで安定して読み込める中小規模モデルと一般的な量子化版を選び、その後パラメーター規模やコンテキストを段階的に増やしてください。

LM Studio CLI でもリソース使用量を見積もれます。

```bash
lms load --estimate-only <model-key>
```

## Cherry Studio で設定する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. **LM Studio** を選択します。
4. Base URL `http://localhost:1234` を維持します。
5. LM Studio で認証を有効にしていない場合、API Key は空欄にします。
6. ページ上部のプロバイダースイッチをオンにします。
7. **追加**またはモデル同期をクリックします。
8. 同期プレビューを確認して変更を適用します。
9. 使用するモデルだけを有効にします。
10. モデルのヘルスチェックを実行してから、チャットでテストします。

Base URL にはホストとポートを入力すればよく、`/v1` を手動で追加する必要はありません。Cherry Studio は OpenAI 互換 API を通じてモデルリストとチャット API にアクセスします。

## モデルリストが変化する理由

LM Studio の `/v1/models` は、サーバーから現在見えるモデルを返します。

| LM Studio の設定 | モデルリストの動作 |
| --- | --- |
| Just-In-Time Model Loading がオン | ダウンロード済みの全モデルを返し、最初のリクエスト時に自動読み込みできる |
| Just-In-Time Model Loading がオフ | 通常、すでにメモリへ読み込まれたモデルだけを返す |

したがって、旧版チュートリアルの「同期前に必ず手動で Load する」という説明は、すべてのバージョンには当てはまりません。

Cherry Studio のモデルリストが空の場合：

1. API Server が起動していることを確認します。
2. ブラウザーまたはターミナルで `http://localhost:1234/v1/models` へアクセスします。
3. LM Studio で JIT Loading がオンか確認します。
4. JIT がオフの場合は、先に LM Studio でモデルを読み込みます。
5. Cherry Studio に戻り、もう一度同期します。

{% hint style="warning" %}
モデル同期の成功は、デバイスがそのモデルを必ず読み込めることを意味しません。JIT を有効にすると未読み込みのモデルもリストに表示されるため、最初のチャット時に初めて読み込みが行われ、メモリ不足や過大なコンテキストなどの問題が判明する場合があります。
{% endhint %}

## API Token と認証

LM Studio はデフォルトで API Token を必要としません。ローカルで使用する場合、Cherry Studio の API Key は空欄にできます。

LM Studio 0.4.0 以降では、`Developer → Server Settings` で **Require Authentication** を有効にできます。

1. **Manage Tokens** を開きます。
2. Token を作成し、権限を設定します。
3. 新しい Token をコピーします。
4. Cherry Studio の LM Studio プロバイダーに Token を入力します。
5. モデルを再同期し、ヘルスチェックを実行します。

Cherry Studio は、空でない API Key を Bearer Token として送信します。LM Studio は OpenAI および Anthropic 互換 API で一般的な認証ヘッダーにも対応しています。

{% hint style="danger" %}
API Token は作成時にだけ完全表示されます。Token をチャット、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。漏えいした場合は、すぐに削除して再作成してください。
{% endhint %}

## チャット、ビジョン、MCP

### 通常のチャット

Chat Completions に対応する指示モデルを選択します。基本的なチャットが動作した後、思考、画像、ツール呼び出しをテストしてください。

ローカルモデルの回答品質は、モデル、量子化、プロンプトテンプレート、コンテキスト設定によって決まります。応答が返ることは API が動作することだけを示し、モデルがすべてのタスクに適しているとは限りません。

### 画像理解

LM Studio の OpenAI 互換 Chat Completions はテキストと画像に対応しますが、具体的なモデル自体にビジョン機能が必要です。

1. ビジョンモデルと明記されたバージョンをダウンロードします。
2. LM Studio で読み込むか、JIT 読み込みを許可します。
3. Cherry Studio へ同期します。
4. モデルに画像機能が表示されることを確認します。
5. まず小さな画像を 1 枚送信してテストします。

モデル名が似ていても、すべての量子化版やバリアントが画像に対応するとは限りません。Cherry Studio がビジョン機能を認識しない場合は、表示名だけを変更せず、先にモデル ID とランタイム対応を確認してください。

### ツール呼び出しと MCP

Cherry Studio の MCP は、モデルによる構造化 Tool Calling に依存します。LM Studio はモデルテンプレートに応じてネイティブまたは互換モードを提供しますが、実際の安定性はモデルによって決まります。

次の順序でテストすることを推奨します。

1. 先に通常のチャットを完了します。
2. 単純な MCP ツールを 1 つだけ有効にします。
3. そのツールを呼び出すようモデルへ明示します。
4. 構造化された呼び出しが生成されるか確認します。
5. ツール結果がモデルへ返されることを確認します。
6. その後、ツール数を段階的に増やします。

小規模モデルは「ツールを呼び出す準備」とテキストで出力しても、実際には呼び出さない場合があります。この場合は、ネイティブ Tool Use の表示がある、パラメーター規模が大きい、またはツール学習が充実したモデルを優先してください。

Cherry Studio MCP と LM Studio サーバー自体の MCP 統合は別の経路です。Cherry Studio MCP だけを使用する場合は、同じツールを LM Studio で重複設定する必要はありません。

## 思考モデルと構造化出力

LM Studio が思考パラメーターまたは構造化出力を処理できるかは、モデルテンプレートと OpenAI 互換実装によって決まります。

- LM Studio が明確に対応しているモデルとテンプレートを優先します。
- モデルごとの思考スイッチと強度パラメーターは共通ではありません。
- 思考を有効にしてパラメーターエラーが返る場合は、デフォルトへ戻すか思考をオフにします。
- JSON または構造化出力に失敗する場合は、先に LM Studio で同じモデルを検証します。
- 表示名を変更して別の機能に見せかけないでください。

## モデル読み込み、JIT、VRAM

JIT Loading を有効にすると、Cherry Studio が初めてモデルを呼び出したときに、LM Studio がモデルをメモリまたは VRAM へ自動的に読み込めます。最初の回答はその後のリクエストより明らかに遅くなります。

LM Studio 0.4+ では次の機能も提供されます。

- **Idle TTL**：アイドル状態になったモデルを自動的にアンロードするまでの時間。
- **Auto-Evict**：新しいモデルを読み込む前に、JIT で読み込んだ以前のモデルを自動的にアンロード。
- **Only Keep Last JIT Loaded Model**：最後に使用した JIT モデルだけを保持。

Cherry Studio の LM Studio プロバイダーページには**キープアライブ時間**も表示されます。実際にアンロードされるか、いつメモリが解放されるかは、LM Studio の JIT、TTL、Auto-Evict、手動読み込み状態にも影響されます。問題調査では、LM Studio の読み込み済みモデルリストとサーバー設定を基準にしてください。

手動で制御する場合：

```bash
lms load <model-key> --context-length 8192 --gpu max
lms unload <model-key>
lms unload --all
```

デバイスの上限に近い大規模モデルを複数同時に読み込まないでください。モデルを頻繁に切り替える場合は、モデルを追加し続けるより Auto-Evict を有効にする方が通常は安定します。

## コンテキスト長

モデルが対応する最大コンテキストと、実際に読み込まれたコンテキストは別の概念です。LM Studio でモデル読み込み時に設定する Context Length が、現在のインスタンスで利用できる範囲を決定します。

コンテキストが長すぎると、次の問題が発生する場合があります。

- RAM または VRAM が不足する。
- 最初の読み込み時間が増える。
- プロンプト処理が遅くなる。
- リクエストが切り捨てられるか、上限超過が返る。
- ビジョンや長文書のタスクが失敗しやすくなる。

Cherry Studio のモデル情報が LM Studio の実際の読み込み値より大きい場合は、LM Studio のランタイム設定を基準にします。まず短いコンテキストで安定性を検証し、必要に応じて増やしてください。

## ナレッジベースと埋め込みモデル

LM Studio は OpenAI 互換の `/v1/embeddings` API を提供し、専用の埋め込みモデルを実行できます。

1. 埋め込みモデルをダウンロードします。
2. LM Studio で読み込むか、JIT 読み込みを許可します。
3. Cherry Studio でモデルを同期します。
4. モデルが埋め込みモデルとして認識されることを確認します。
5. ナレッジベースで選択し、次元を検出します。
6. ヘルスチェックを実行してからドキュメントをインポートします。

Cherry Studio の LM Studio はリランキングモデルに対応していません。Rerank が必要な場合は、別のプロバイダーを選択してください。

埋め込みモデルまたは次元を既存のナレッジベースで使用した後は、むやみに変更しないでください。通常、ベクトルインデックスを再構築する必要があります。

## PDF と添付ファイル

現在の V2 は PDF の元ファイルを LM Studio へ直接送信しません。Cherry Studio は先にローカルで PDF のテキストを抽出してから、モデルへ渡します。

- テキスト形式の PDF は通常処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は失われる場合があります。
- 抽出したテキストはコンテキストを消費します。
- PDF 内の画像はビジョンモデルへ個別に送信する必要があります。

## Code Tools と Anthropic 互換 API

Cherry Studio の LM Studio プリセットには Anthropic 互換アドレスも保持され、デフォルトは同じく `http://localhost:1234` です。一部の Code Tools で使用します。

LM Studio は `/v1/messages` を提供します。Code Tool が Anthropic 互換サービスを必要とする場合：

1. 比較的新しい LM Studio を使用していることを確認します。
2. API Server を起動します。
3. 対象モデルが必要なツール機能に対応していることを確認します。
4. 認証を有効にした場合は同じ Token を入力します。
5. LM Studio の実際のモデル識別子を使用します。
6. まず単純なタスクで検証してから、ファイルまたはコマンド権限を許可します。

Messages API に対応しても、任意のローカルモデルがコード Agent タスクを確実に完了できるとは限りません。モデル能力、コンテキスト、ツール呼び出し品質、デバイス性能が結果に影響します。

## LAN またはリモートの LM Studio に接続する

Cherry Studio と LM Studio が同じデバイスにない場合：

1. LM Studio の Server Settings で **Serve on Local Network** を有効にします。
2. **Require Authentication** を有効にして Token を作成します。
3. システムのファイアウォールがサーバーポートを許可していることを確認します。
4. Cherry Studio に LM Studio ホストの LAN アドレスを入力します。
5. Token を入力します。
6. 先に `/v1/models` へアクセスしてから、ヘルスチェックを実行します。

CLI ですべてのネットワークインターフェイスをリッスンすることもできます。

```bash
lms server start --bind 0.0.0.0
```

認証されていない LM Studio ポートをインターネットへ直接公開しないでください。インターネットから使用する場合は VPN、または HTTPS、認証、アクセス制御を適切に設定したリバースプロキシを使用してください。

Docker、仮想マシン、WSL、リモートデスクトップ環境では、`localhost` は Cherry Studio が動作するシステムを指し、必ずしも LM Studio を実行するホストではありません。実際に到達できるアドレスを使用してください。

## よくある問題

### `localhost:1234` に接続できない

LM Studio API Server が起動していない、ポートが変更された、またはファイアウォールにブロックされています。まず Developer ページにサーバーが実行中と表示されていることを確認します。

### モデルリストが空

`/v1/models` がレスポンスを返すか確認します。JIT がオフの場合はモデルを先に読み込む必要があります。JIT がオンの場合は、モデルがダウンロード済みでサーバーから見えることを確認してください。

### モデルは同期できるが、チャットでエラーになる

モデルの読み込みに失敗している、リソース不足、コンテキストが大きすぎる、または API テンプレートに互換性がない可能性があります。LM Studio のサーバーログと読み込み状態を確認してください。

### 最初の回答が遅い

JIT がモデルを読み込んでいます。その後のリクエストは通常、速くなります。事前にモデルを読み込むこともできますが、メモリまたは VRAM を継続して使用します。

### メモリまたは VRAM 不足が返る

より小さなモデルまたは圧縮率の高い量子化を使用し、コンテキストを短くしてください。GPU Offload を増やす場合はデバイスの余力を前提とし、他のモデルをアンロードします。

### 画像または MCP を使用できない

通常のチャットを使用できても、モデルにビジョンやツール機能があるとは限りません。モデル版、テンプレート、Cherry Studio の機能認識、LM Studio のログを確認してください。

### API Token が無効

LM Studio で Require Authentication が有効であること、Token が削除されていないこと、権限が正しいこと、Cherry Studio の入力に余分な空白がないことを確認します。

### リモート接続が拒否される

Serve on Local Network が有効であること、ポートへ到達できること、ファイアウォールとリバースプロキシのパスが正しいことを確認してください。インターネット接続の問題を、すべてのセキュリティ対策を無効にして解決しないでください。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。LM Studio のサーバー、互換 API、モデル管理については[公式ドキュメント](https://lmstudio.ai/docs)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
