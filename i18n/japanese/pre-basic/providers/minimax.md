# MiniMax

Cherry Studio V2 には、**MiniMax** と **MiniMax 海外版**の 2 つのプロバイダーが組み込まれています。どちらも MiniMax の言語モデル API に接続できますが、使用するオープンプラットフォーム、Base URL、API Key は異なります。

このページでは、Cherry Studio で MiniMax M シリーズを使用して、チャット、プログラミング、Agent タスクを実行する方法を説明します。MiniMax の音声、画像、動画、音楽生成は個別の API を使用し、ここで扱う言語モデルサービスとは異なります。

{% hint style="info" %}
中国本土向けオープンプラットフォームでは **MiniMax**、国際向けオープンプラットフォームでは **MiniMax 海外版**を選択してください。2 つのプラットフォームのアカウント、Key、残高、サブスクリプションはそれぞれ独立している場合があるため、混在させないでください。
{% endhint %}

## 始める前の準備

アカウントを作成したプラットフォームに応じて認証情報を準備します。

| プラットフォーム | Cherry Studio のプロバイダー | デフォルトの Base URL |
| --- | --- | --- |
| 中国本土 | MiniMax | `https://api.minimaxi.com/v1/` |
| 国際 | MiniMax 海外版 | `https://api.minimax.io/v1/` |

- 中国本土のユーザーは [MiniMax オープンプラットフォーム](https://platform.minimaxi.com/)で API Key を作成できます。
- 国際ユーザーは [MiniMax API Platform](https://platform.minimax.io/) で API Key を作成できます。
- Key に従量課金の残高、または有効な Token Plan があることを確認します。
- 現在利用できるモデル、コンテキスト、レート制限を確認します。

従量課金の API Key と Token Plan Key では、使用する残高または割り当てが異なります。接続に成功しても割り当てエラーが返る場合は、別のアカウント残高だけを確認するのではなく、その Key を作成した側の課金ページを確認してください。

## MiniMax を設定する

1. `設定 → モデルプロバイダー`を開きます。
2. 左側のフィルターを**すべてのプロバイダー**に切り替えます。
3. 中国本土のアカウントでは **MiniMax**、国際アカウントでは **MiniMax 海外版**を選択します。
4. 対応するプラットフォームで作成した API Key を入力します。
5. 組み込みのデフォルト Base URL は変更しません。
6. ページ上部のプロバイダースイッチをオンにします。
7. モデルリストで**追加**をクリックし、同期プレビューを確認して変更を適用します。
8. 使用するモデルだけを有効にします。

{% hint style="danger" %}
API Key をチャットメッセージ、ドキュメント、コードリポジトリ、問題報告のスクリーンショットに書き込まないでください。漏えいした場合は、該当する MiniMax オープンプラットフォームですぐに削除し、再作成してください。
{% endhint %}

`.com` プラットフォームの Key を `.io` のプロバイダーに入力した場合、またはその逆に混在させた場合は、通常、認証エラーが返されます。組み込みアドレスをむやみに上書きせず、まず正しいプロバイダー項目を選択しているか確認してください。

## モデルを選択する

Cherry Studio V2 では、現在 2 つの MiniMax プロバイダーに次の主要モデルがプリセットされています。

| モデル ID | 主な用途 |
| --- | --- |
| `MiniMax-M3` | 1M コンテキストを公式に提供する、フラッグシップのマルチモーダルプログラミングおよび Agent モデル |
| `MiniMax-M2.7` | プログラミング、ツール呼び出し、オフィス作業、複雑な Agent ワークフロー |
| `MiniMax-M2.7-highspeed` | M2.7 と同じシリーズで、より低い出力遅延を優先 |

同期したリストには、M2.5、M2.1、その他のモデルが表示される場合もあります。モデル ID とライフサイクルは、実際の同期結果と MiniMax の公式ドキュメントを基準とし、古いドキュメントの `abab` シリーズ名に依存しないでください。

- 日常的な総合タスクでは、まず M3 を試します。
- コードとツール呼び出しが中心の場合は、M3 と M2.7 を比較します。
- 出力速度を重視する場合は `MiniMax-M2.7-highspeed` を選択します。
- 結果を再現できるようにする場合は、表示名だけでなく完全なモデル ID を記録します。

## OpenAI と Anthropic の互換エンドポイント

組み込みの 2 つのプロバイダーには、いずれも OpenAI Chat Completions と Anthropic Messages の互換アドレスが含まれています。

| プラットフォーム | OpenAI 互換 | Anthropic 互換 |
| --- | --- | --- |
| 中国本土 | `https://api.minimaxi.com/v1/` | `https://api.minimaxi.com/anthropic` |
| 国際 | `https://api.minimax.io/v1/` | `https://api.minimax.io/anthropic` |

Cherry Studio はデフォルトで OpenAI Chat Completions を使用します。通常のチャットとモデル同期では、まずデフォルト設定を維持できます。

MiniMax は、思考ブロックとインターリーブ思考の処理に Anthropic 互換エンドポイントをより推奨しています。Cherry Studio でモデルのエンドポイントタイプを手動で切り替える場合は、次の点も確認してください。

- Base URL がアカウントの地域と一致している。
- モデルが Anthropic Messages プロトコルを使用している。
- Key が同じプラットフォームで発行されている。
- 通常のチャット、思考の表示、ツール呼び出しがすべてヘルスチェックに再度合格する。

Base URL だけを変更し、誤ったプロトコルタイプを残さないでください。OpenAI と Anthropic の互換 API では、メッセージ構造が完全には同じではありません。

## 思考内容と複数ターンのツール呼び出し

MiniMax M シリーズは推論内容を返します。M2 シリーズは Cherry Studio に推論モデルとして認識されます。M3 は比較的新しく、現在の V2 では専用の思考コントロールがまだ完全には表示されない場合があります。

使用時の推奨事項：

- 思考設定は**デフォルト**のままにします。
- 思考が固定されているモデルに、無効化やカスタム予算を強制的に送信しないでください。
- 長い回答にはストリーミング出力を使用します。
- Temperature、Top P、ペナルティ項目をむやみに変更しないでください。
- プロトコルを切り替えた後、思考内容が正しく表示されるか再テストします。

{% hint style="warning" %}
MiniMax の複数ターンのツール呼び出しは、思考内容と `tool_calls` を含む完全な assistant メッセージに依存します。Cherry Studio が会話履歴を維持するため、ツールの実行途中で直前のメッセージを手動で削除または書き換えないでください。モデルが推論の連続性を失う可能性があります。
{% endhint %}

OpenAI 互換エンドポイントの使用中に `<think>` タグが表示される場合、通常はプロバイダーが思考内容を `content` に格納しています。Anthropic 互換エンドポイントへ切り替える前に、既存のチャットに影響を与えないよう、別のプロバイダーコピーでテストしてください。

## ツール呼び出しと MCP

Cherry Studio V2 は MiniMax M2、M2.x、M3 シリーズのツール呼び出し機能を認識しており、MCP や Agent の場面で使用できます。

次の順序で検証することを推奨します。

1. 同期して有効化した M3 または M2.7 を選択します。
2. 通常のチャットを 1 ターン完了します。
3. 単純な MCP ツールを 1 つ有効にします。
4. ツール呼び出しを明示的に求めるプロンプトを使用します。
5. モデルが実際にツール呼び出しを開始したことを確認します。
6. その後、複数のツールや長い一連のタスクを追加します。

長い一連のタスクでは、完全なコンテキストを保持してください。モデルが同じツールを繰り返し呼び出す場合は、まずツール数を減らし、システムプロンプトを短くして、停止条件を明確にします。

## 画像、動画、ファイル

MiniMax M3 は公式にテキスト、画像、動画の入力をサポートしていますが、現在の Cherry Studio V2 の自動ビジョンモデル認識ルールには M3 がまだ含まれていない場合があります。そのため：

- 入力欄に画像または動画の入口が表示される場合は、まず小さなファイルでヘルステストを行います。
- 入口が表示されない場合は、まず Cherry Studio を更新してモデルを再同期します。
- 表示名だけを変更してモデルの機能を偽装しないでください。
- 現在のバージョンでまだ使用できない場合は、クライアントの対応アップデートを待ってください。

MiniMax の OpenAI および Anthropic 互換 API に含まれる旧 M2 モデルは、通常、テキストとツール呼び出しだけをサポートします。MiniMax の個別の画像、動画、音声生成モデルをチャットモデルとして追加しないでください。

PDF の場合、現在の Cherry Studio は先にローカルでテキストを抽出し、そのテキストを MiniMax に送信します。

- テキスト形式の PDF は通常そのまま処理できます。
- スキャンされた文書は、先に OCR が必要です。
- 表、複雑なレイアウト、画像の情報は抽出時に失われる場合があります。
- 抽出したテキストはコンテキストと入力使用量を消費します。

## マルチモーダル生成はチャットモデルではない

MiniMax は音声、画像、動画、音楽生成 API も提供していますが、これらの API には個別のリクエスト形式とタスクフローがあります。オープンプラットフォームにモデルが表示されても、Cherry Studio のチャットプロバイダーから直接呼び出せるとは限りません。

たとえば、動画生成モデルをチャットモデルリストへ手動で追加しても、通常はパラメーターまたはエンドポイントのエラーが返るだけです。必要な機能には、Cherry Studio が対応している専用の入口を使用してください。現在対応していない API は、モデル名を変更しても代用できません。

## ナレッジベースと埋め込みモデル

組み込みの MiniMax プロバイダーは、現在、言語モデルのエンドポイント用に設定されており、埋め込みモデルは提供しません。ナレッジベースまたは[グローバルメモリ](../../advanced-basic/memory.md)を使用する場合：

- チャットモデルには引き続き MiniMax を選択できます。
- 埋め込みモデルは別のプロバイダーから選択する必要があります。
- 2 種類のモデルを同じプロバイダーから選ぶ必要はありません。
- 設定後、それぞれモデルのヘルスチェックを実行します。

## 接続を確認する

1. 正しい中国本土向けまたは国際向けプロバイダーを選択していることを確認します。
2. API Key の欄で接続チェックを実行します。
3. 同期して有効化したモデルを選択します。
4. モデルリストでヘルスチェックを実行します。
5. チャット画面に戻り、簡単なメッセージを送信します。
6. 長い回答、思考の表示、MCP を個別にテストします。

接続チェックの成功は、基本的な認証情報が使用できることだけを示します。Key にすべてのモデル権限があることや、Token Plan にまだ利用可能な割り当てがあることを示すものではありません。

## よくある問題

### 認証エラーまたはエラーコード 1004 が返る

API Key が無効、削除済み、または Key と `.com` / `.io` のプロバイダーが一致していません。プロバイダーの地域を確認してから、Key を再作成してください。

### 残高不足またはエラーコード 1008 が返る

現在の Key を作成した課金タイプとアカウントを確認します。従量課金の残高と Token Plan の割り当ては個別に確認する必要があります。

### レート制限、1002、1041 が返る

リクエストがレートまたは同時実行数の制限に達しています。並列リクエストを減らし、コンテキストを短くして、後でもう一度試してください。継続して発生する場合は、アカウントレベルと公式の上限を確認します。

### Token 超過またはエラーコード 1039 が返る

現在のチャット、添付ファイルのテキスト、予想される出力がモデルのコンテキストを超えています。新しいチャットを作成し、添付ファイルと履歴を減らすか、より長いコンテキストのモデルを選択してください。

### モデルリストが古いモデルのまま

もう一度**追加**をクリックしてリストを同期し、Base URL が誤って変更されていないことを確認します。リモートのリストに新しいモデルがまだ返されない場合は、組み込みのプリセットモデルを使用するか、公式の完全な ID を手動で追加します。

### M3 に思考または画像の入口がない

M3 の公式機能が、現在の Cherry Studio の自動認識ルールより新しい状態です。まずクライアントを更新して再同期してください。それでも表示されない場合は、モデルタイプを強制的に上書きせず、対応アップデートを待ってください。

### MCP 呼び出しが中断する、またはコンテキストが乱れる

まずツールを 1 つだけ有効にし、M3 または M2.7 を使用していることを確認します。ツール呼び出し直前の assistant メッセージは削除しないでください。必要に応じて新しいチャットを作成し、再テストします。

一般的な設定については、[モデルプロバイダー](README.md)と[モデルプロバイダー設定](../../cherrystudio/preview/settings/providers.md)を参照してください。モデル機能については [MiniMax Models](https://platform.minimax.io/docs/guides/models-intro)、フィードバック窓口については[フィードバックと提案](../../question-contact/suggestions.md)を参照してください。
