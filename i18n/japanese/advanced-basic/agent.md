# エージェント

エージェントは、制御された権限の範囲内でワークスペースを読み取り、ツールを呼び出し、複数ステップのタスクを継続して実行できます。複数ファイルの整理、プロジェクトコードの変更、MCP サービスの呼び出し、スケジュールに沿ったレポート作成など、実際の操作が必要な作業に適しています。

固定された役割、ナレッジベースを使った質疑応答、日常的な会話だけが必要な場合は、まずアシスタントを使用するほうが簡単です。違いについては、[コンセプト入門](concepts-101.md)を参照してください。

## はじめる前に

### 利用可能なモデルを設定する

エージェントのモデルは、Anthropic Messages エンドポイントに対応している必要があります。モデル選択欄では Embedding、Rerank、画像生成モデルが自動的に除外され、エージェントによる対話形式のタスク実行に適したモデルだけが表示されます。

一覧が空の場合は、まず **設定 → モデルサービス** で次の操作を行ってください。

1. API アドレスと API Key を設定します。
2. モデル一覧を取得するか、モデルを手動で追加します。
3. そのモデルが Anthropic Messages エンドポイントに対応していることを確認します。

モデルサービスの一般的な設定方法は、[モデルサービス](../pre-basic/providers/)を参照してください。

### ローカル API サーバーが利用できることを確認する

エージェントページは、内部で Cherry Studio のローカル API サーバーに依存しています。V2 では新しいエージェントを作成するときに自動でサービスの起動を試みるため、通常は事前に設定ページを操作する必要はありません。

エージェントページにサービスが無効または未起動と表示された場合は、ページ内の起動ボタンを直接クリックしてください。それでも起動できない場合は、**設定 → API サーバー**でポートと実行状態を確認します。詳しくは、[API サーバー](api-server.md)を参照してください。

## エージェントを作成する

ランチパッドまたはサイドバーから**エージェント**を開き、左側のエージェント一覧の上にある **+ エージェント**をクリックします。

[リソースライブラリ](../cherrystudio/preview/library.md)を開き、**エージェント**に切り替えてから新規作成をクリックすることもできます。リソースライブラリからは、完全な設定ページが直接開きます。

### 最低限必要な項目

| 項目 | 必須 | 説明 |
| :--- | :--- | :--- |
| 名前 | はい | 一覧とセッションに表示されるエージェント名 |
| モデル | はい | 主にタスクを実行するモデル。Anthropic Messages 対応モデルだけが表示される |
| アクセス可能なディレクトリ | いいえ | エージェントがアクセスできるローカルディレクトリを制限する。指定しない場合はデフォルトの作業ディレクトリが作成される |
| 説明 | いいえ | 用途を記載し、リソースライブラリで識別しやすくする |

{% hint style="warning" %}
アクセス可能なディレクトリはセキュリティ境界でもあります。ユーザーディレクトリ全体、システムディレクトリ、秘密情報を保存するディレクトリを直接許可しないでください。タスクごとに独立したワークスペースを作成し、本当に必要な場所だけを追加することをおすすめします。
{% endhint %}

保存すると、エージェントが左側の一覧とリソースライブラリに表示されます。スキルはエージェントごとに関連付けられるため、最初に一度保存してから、そのエージェントでスキルを有効にしてください。

## 設定ページ

リソースライブラリでエージェントカードをクリックするか、エージェントの会話画面上部から設定を開くと、次の項目を編集できます。

| 設定項目 | 設定できる内容 |
| :--- | :--- |
| 基本設定 | アバター、名前、メインモデル、計画モデル、小型モデル、アクセス可能なディレクトリ、自律モード、ハートビート、説明 |
| プロンプト設定 | エージェントのシステム指示 |
| 権限モード | ツール呼び出しに対するデフォルトの承認方法 |
| 機能拡張 | 組み込みツール、MCP Server、スキル |
| 詳細設定 | 最大実行ターン数と環境変数 |

### メインモデル、計画モデル、小型モデル

* **メインモデル**は必須で、大半の会話とツール実行を担当します。
* **計画モデル**は任意で、独立した計画が必要なプロセスに使用できます。
* **小型モデル**は任意で、軽量モデルに適した補助ステップに使用できます。

3 か所とも、エージェントと互換性のあるモデルだけが表示されます。明確な必要性がなければ、メインモデルだけを設定してください。

### プロンプト

プロンプトでは、役割、目標、作業規則、出力要件を定義します。大量の背景情報を並べるよりも、次の点を明確にすることをおすすめします。

* エージェントが担当することと、担当しないこと。
* 使用できるディレクトリ、データソース、ツール。
* 実行前に確認が必要な操作。
* 結果の保存先と形式。

セキュリティ制限をプロンプトだけに依存させないでください。ディレクトリ範囲、権限モード、ツールの有効・無効は個別に設定する必要があります。

## 権限モードを選択する

権限モードは、どのツールを自動承認するかを決定します。モードを切り替えると、Cherry Studio は、そのモードによって自動追加されるツールを同期して更新します。

| モード | デフォルトの動作 | 適した用途 |
| :--- | :--- | :--- |
| 通常モード | ファイルは自由に読み取れる。ファイルの編集またはコマンドの実行前に確認する | 初めて使う場合、対話型のタスク |
| 計画モード | ファイルを読み取って計画を作成する。ファイルの編集やコマンドの実行はできない | コードレビュー、設計、リスク評価 |
| 自動編集モード | ファイルは自由に読み書きできる。コマンドの実行前に確認する | 文書整理、制御されたコード変更 |
| フルオートモード | 現在利用可能なツールを個別の承認なしで実行できる | 無人で実行し、対象範囲が厳密に制御されたタスク |

各モードが自動追加するツール以外にも、**機能拡張 → 組み込みツール**でツールを手動追加できます。

{% hint style="danger" %}
フルオートモードでは、ツールの承認が省略されます。エージェントがファイルを書き込み、コマンドを実行し、外部サービスを呼び出す可能性があります。隔離されたワークスペースでのみ使用し、同じタスクを事前に通常モードで一通りテストしてください。
{% endhint %}

## 自律モードとハートビート

### 自律モード

自律モードを有効にすると、エージェントはワークスペース内の Soul ファイルを使ってカスタムシステムプロンプトを構築し、自律的なタスク管理機能を利用します。また、無人実行に適さない対話型ツールは無効になります。

自律モードを有効にすると、権限モードも同時に**フルオートモード**へ切り替わります。フルオートモードから別のモードへ変更すると、自律モードは無効になります。

自律モードは、長期実行、チャンネル、その他の無人運用に適しています。回答品質を向上させるための汎用スイッチではありません。ユーザーへの確認が頻繁に必要なタスクには、通常のエージェントのほうが適しています。

### ハートビート

ハートビートを使うと、自律実行に対応するエージェントが設定された間隔で状況を確認し、作業を続けることができます。基本設定で有効または無効にし、間隔を分単位で設定できます。

エージェントに明確な目標、制限されたディレクトリ、安全なツールセットが用意されている場合にのみ、ハートビートを有効にしてください。目的のない処理が繰り返されるのを防ぐためです。

## ツール、MCP、スキルを追加する

**機能拡張**を開くと、3 つのタブを切り替えられます。

### 組み込みツール

組み込みツールは、ファイルの読み取り、編集、コマンドの実行、タスク管理などの機能を提供します。権限モードによって一部のツールが自動追加されます。モードのマークが付いたツールは個別に削除できません。

タスクに本当に必要なツールだけを有効にしてください。通常モードを使用していても、ツールが多すぎるとモデルが誤ったツールを選ぶ可能性が高まります。

### MCP

ここには、Cherry Studio に登録されている MCP Server が表示されます。無効になっている Server は関連付け済み一覧には表示されることがありますが、新規追加一覧からは選択できません。先に **設定 → MCP サーバー**で有効にする必要があります。

MCP Server は、ローカルプログラムまたはリモートサービスにアクセスする場合があります。関連付ける前に、コマンド、環境変数、ディレクトリ、リモートアドレスを確認してください。詳しくは、[MCP 利用ガイド](mcp/)を参照してください。

### スキル

スキルは、タスクの説明、手順、スクリプト、テンプレートを提供します。保存され、ID が割り当てられたエージェントでのみ、スキルを有効にできます。

一覧が空の場合は、先にリソースライブラリまたは **設定 → スキル**からインストールしてください。詳しくは、[スキル](../pre-basic/settings/skills.md)を参照してください。

## 詳細オプションを設定する

### 最大実行ターン数

最大実行ターン数は、1 回のタスクを継続できるターン数を制限します。空欄のままにするか `0` を指定するとデフォルト値が使用されます。現在のデフォルト上限は 100 です。

ターン数は「回答の長さ」ではありません。エージェントによる計画、ツール呼び出し、実行の継続は、それぞれターンを消費する場合があります。タスクが異常なループに陥った場合は、上限を引き上げ続けるのではなく、まずプロンプトとツールの結果を確認してください。

### 環境変数

環境変数は、1 行に 1 つずつ `KEY=VALUE` の形式で入力します。例：

```text
PROJECT_ENV=staging
OUTPUT_FORMAT=markdown
```

環境変数は、エージェントの実行設定に渡されます。パスワード、API Key、アクセストークンを文書、プロンプト、スクリーンショットに記載しないでください。機密値は制御された設定にだけ保存し、最小権限で管理してください。

## 会話を開始する

1. **エージェント**ページを開きます。
2. 左側からエージェントを選択します。
3. 新しいセッションを作成し、範囲が明確なタスクを入力します。
4. ツール呼び出しカードを確認します。通常、計画、自動編集モードでは、表示される指示に従って操作を承認または拒否します。
5. 生成または変更されたファイルを確認してから、次のステップへ進みます。

最初のテストには、範囲が小さく、結果を確認しやすいタスクが適しています。例：

> 現在のワークスペースにある `README.md` を読み取り、更新が必要な箇所を 3 つ挙げてください。まだファイルは変更しないでください。

読み取り範囲が正しいことを確認した後、編集、コマンド、外部ツールを段階的に許可してください。

## ワークスペースとメモリ

エージェントがアクセスできる最初のディレクトリが、メインワークスペースになります。一部の機能は、自律モードの Soul ファイルやエージェントのワークスペースメモリなど、永続的なファイルをワークスペース内に保存します。

2 つのエージェントが同じ最初のアクセス可能ディレクトリを使用すると、同じワークスペースファイルを読み書きする可能性があります。プロジェクトや ID を分離する必要がある場合は、エージェントごとに異なるディレクトリを使用してください。

ワークスペースメモリのファイル構造と使用方法は、[エージェントのワークスペースメモリ](memory.md)を参照してください。

## よくある問題

### エージェントページに API サーバーが実行されていないと表示される

まず、ページ内の起動ボタンをクリックします。起動に失敗した場合：

1. **設定 → API サーバー**を開きます。
2. ポートが他のプログラムによって使用されていないか確認します。
3. サービスを再起動し、エージェントページに戻ります。

### 作成時に選択できるモデルがない

エージェントには、Anthropic Messages エンドポイントに対応した会話モデルだけが表示されます。モデルサービスにモデルが追加されているか、エンドポイント機能が正しく設定されているかを確認してください。Embedding、Rerank、画像生成モデルは表示されません。

### スキルを有効にできない

先にエージェントを保存してください。スキルの有効状態はエージェント ID ごとに保存されるため、まだ保存されていない新規エージェントには関連付け可能な ID がありません。

### 特定の MCP Server が見つからない

**設定 → MCP サーバー**を開き、Server が追加され、有効になっていることを確認してください。エージェントの新規追加一覧では、有効な Server だけを選択できます。

### ファイルの編集やコマンドの実行のたびに確認される

これは通常モードで想定される動作です。リスクに応じて自動編集モードを選択するか、機能拡張で個々のツールを調整してください。確認を減らすことだけを目的に、フルオートモードへ直接切り替えないでください。

### タスクが途中で停止する、または処理が繰り返される

次の順に確認してください。

1. モデルがツール呼び出しに安定して対応しているか。
2. ツールの戻り値にエラーが含まれていないか、必要なデータが不足していないか。
3. プロンプトに明確な終了条件があるか。
4. 最大実行ターン数が小さすぎないか。
5. 自律モードまたはハートビートにより、適さない状況でタスクが続行されていないか。

* [エージェントのワークスペースメモリ](memory.md)について確認する。
* エージェントが安定して動作するようになったら、[チャンネル](agent-channels.md)または[スケジュールタスク](scheduled-tasks.md)を設定する。
