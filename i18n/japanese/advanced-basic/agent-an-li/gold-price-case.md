# Kimi K2.5 で金市場レビュー Agent を作る

この事例では、Cherry Studio のエージェントを使って「金価格変動のレビュー」を行う方法を説明します。公開情報を検索し、価格とイベントの時刻を揃え、出所を保存して、人が検証しやすいレポートを作成します。

Kimi K2.5 は、この事例で使うモデルの例です。Cherry Studio のエージェントで **Anthropic Messages** エンドポイントを通じて利用できるモデルであれば、別のモデルに変更できます。プロバイダーによって、提供モデル、価格、ツール互換性が異なるため、最初に小さなタスクで検証してください。

{% hint style="warning" %}
この事例は調査ワークフローの説明用であり、投資助言ではありません。モデルは資料を見落とす、データを誤読する、誤ったコードを生成する可能性があります。生成結果に基づいて直接取引しないでください。
{% endhint %}

## 最終成果物

成果物は次の 4 ファイルに限定することを推奨します。

```text
gold-review/
├── sources.md       # 出所、公開時刻、取得時刻、用途
├── market-data.csv  # 今回実際に使用した価格データ
├── analysis.md      # イベントの時系列、計算過程、不確実な項目
└── report.html      # 最終的な閲覧用レポート
```

4 ファイルは、それぞれ「資料の出所」「使用したデータ」「結論に至った方法」「結果の見せ方」に答えます。見栄えのよい HTML だけを作らせないでください。最初の 3 ファイルがなければ、最終ページの検証が困難になります。

## ワークフロー設計

タスクを 3 段階に分けます。

| 段階 | 主な作業 | 必ず残す証拠 |
| :--- | :--- | :--- |
| データ収集 | 指定期間の価格とマクロ経済資料を取得する | 出所 URL、公開時刻、取得時刻、元の数値 |
| イベント照合 | 大きな変動と同じ時間帯のイベントを比較する | タイムゾーン、イベント時刻、価格範囲、支持証拠と反証 |
| レポート作成 | グラフ、時系列、結論、制約を構成する | 計算方法、引用リンク、欠損データ、リスク表示 |

エージェントの `Task` ツールを使って独立した調査をサブタスクに分けることはできますが、「並列」であるだけでは品質は保証されません。最後に主タスクで時刻、単位、情報源の基準を統一する必要があります。

## 手順 1：モデルを準備する

1. **設定 → モデルサービス**を開きます。
2. Kimi K2.5 を提供するプロバイダーを設定するか、ツール呼び出しに適した別のモデルを選びます。
3. モデルのエンドポイント種類に **Anthropic Messages** が含まれることを確認します。
4. 保存後、通常の会話を 1 回完了し、エージェントのモデル選択欄に表示されることを確認します。

エージェントのモデル選択欄は、Embedding、Rerank、画像生成モデルを除外します。通常の会話では使えるのにエージェントに表示されない場合は、エンドポイントの種類と機能タグを先に確認してください。

モデルの設定は[モデルサービス](../../pre-basic/providers/)を参照してください。モデルを手動追加したり機能タグを修正したりする場合は、[カスタムプロバイダー](../../pre-basic/providers/zi-ding-yi-fu-wu-shang.md)のモデル管理方法も参照できます。

## 手順 2：作業ディレクトリを準備する

`gold-review` などの空ディレクトリを新規作成し、今回のタスクに必要な資料だけを入れます。ユーザーディレクトリ全体、ダウンロードディレクトリ、認証情報を含むプロジェクトディレクトリは選択しないでください。

すでに価格データがある場合は、先に `market-data.csv` として保存できます。少なくとも次の列を推奨します。

```csv
timestamp,open,high,low,close,unit,timezone,source
2026-01-01T00:00:00Z,,,,,USD/oz,UTC,
```

列は変更できますが、単位とタイムゾーンを明示する必要があります。異なる市場やデータソースの値を、基準を変換せずに直接結合しないでください。

## 手順 3：エージェントを作成する

1. **ライブラリ**を開き、エージェントを新規作成します。
2. 名前に `金市場レビュー` と入力します。
3. 前の手順で検証したモデルをメインモデルにします。
4. アクセス可能なディレクトリに、作成した `gold-review` を追加します。
5. 権限モードは最初に**通常モード**を選びます。
6. エージェントを保存します。

通常モードはファイルを読み取れますが、ファイル編集やコマンド実行では確認を求めます。初回実行で「完全自動」を選ぶことは推奨しません。金融データの取得とローカルファイルへの書き込みは、人が確認する必要があります。

各設定の説明は[エージェント](../agent.md)を参照してください。

## 手順 4：ツールを追加する

エージェントの**能力拡張 → 組み込みツール**で、次のツールが利用できることを確認します。

| ツール | この事例での用途 | 必須 |
| :--- | :--- | :--- |
| `Read`、`Glob`、`Grep` | 既存資料の読み取りとファイル検索 | はい |
| `WebSearch` | 公開情報の検索 | はい |
| `WebFetch` | 指定したウェブページの読み取り | はい |
| `Write` | CSV、Markdown、HTML の作成 | はい |
| `Task`、`TodoWrite` | タスクの分割と進捗の記録 | 推奨 |
| `Bash` | データ処理またはローカル検証コマンドの実行 | 任意 |

`WebSearch`、`WebFetch`、`Write`、`Bash` は、ネットワークアクセスまたはローカル内容の変更を伴います。ツールを追加しても、通常モードでは必要時に確認が表示されます。現在の手順に必要な呼び出しだけを許可してください。

ウェブページにログインや CAPTCHA が必要、または自動取得が禁止されている場合は、手動で資料をダウンロードして作業ディレクトリに入れてください。アクセス制限を回避するようエージェントに依頼しないでください。

## 手順 5：必要に応じてスキルをインストールする

この事例はシステムプロンプトだけでも実行できます。繰り返し使う場合は、安定した手順をスキルとして整理します。例：

* `market-data-verifier`：データ列、単位、タイムゾーン、複数情報源の照合方法を定義する。
* `event-timeline`：イベント時系列と因果関係の強さの表示方法を定義する。
* `research-report`：レポート構成、引用形式、失敗時の説明を定義する。

インストールするスキルは、`SKILL.md` を含むディレクトリまたは ZIP である必要があります。操作手順：

1. **設定 → スキル**を開きます。
2. ディレクトリまたは ZIP からスキルをインストールします。
3. 保存済みエージェントの**能力拡張 → スキル**へ戻ります。
4. 現在のエージェントに必要なスキルを有効にします。

スキルは最初に Cherry Studio のグローバルスキルライブラリへ保存されます。エージェントで有効にすると、アプリがそのエージェントの作業ディレクトリにある `.claude/skills/` へリンクします。出所不明の `.claude` 設定一式を手動コピーしたり、アプリが作成したスキルリンクを上書きしたりしないでください。

詳しくは[スキル](../../pre-basic/settings/skills.md)を参照してください。

## 手順 6：システムプロンプトを入力する

次のテンプレートをエージェントのシステムプロンプトに入れ、必要に応じて変更します。

```text
あなたは市場調査アシスタントです。検証できる金市場レビューを整理することが役割であり、
収益を予測したり売買を勧めたりすることではありません。

作業規則：
1. 最初に、対象商品、市場、通貨、単位、タイムゾーン、日付範囲を確認する。
2. 価格、金利、指数、イベントは、今回読み取ったファイルまたはツール結果から取得する。
   現在値をモデルの記憶で補わない。
3. 重要な事実について、出所 URL、出所名、公開時刻、今回のアクセス時刻を記録する。
4. 重要な結論は、相互に独立した 2 つ以上の情報源で確認する。1 つしかない場合は明記する。
5. 事実、計算結果、解釈、仮説を厳密に区別し、時間的に近いだけの出来事を因果関係として書かない。
6. データ不足、ページへのアクセス不能、計算失敗がある場合は、欠損を残して理由を説明する。
7. ファイルへ書き込む前に計画を列挙する。現在の作業ディレクトリ内だけでファイルを作成・変更する。
8. 最後に sources.md、market-data.csv、analysis.md、report.html を作成する。
9. report.html はローカルで開けるようにし、認証情報や個人情報を埋め込まない。
10. レポート末尾に「調査と学習のみを目的とし、投資助言ではありません」と記載する。
```

システムプロンプトには長期的な規則を定義します。具体的な調査日とイベントは毎回のタスクに入れ、システムプロンプトへ固定しないでください。

## 手順 7：先に資料計画を実行する

最初のタスクでは完全なレポートを直接要求せず、先に資料計画を作らせます。

```text
金現物価格の変動レビューに必要な資料計画を作成してください。
まだレポートは作成しないでください。

範囲：
- 商品：開始前に私へ確認する
- 単位：米ドル / トロイオンス
- タイムゾーン：UTC
- 日付範囲：私が確認した後に検索を始める

出力：
1. 必要なデータ列
2. 使用予定の情報源の種類
3. 呼び出すツールと理由
4. 作成するファイル
5. 確認が必要な権限と潜在的な費用
```

計画がディレクトリとデータの範囲を拡大していないことを確認してから、収集の開始を許可します。

## 手順 8：レビューを実行する

範囲を確認したら、次のタスクを送信できます。

```text
確認済みの範囲でレビューを実行してください。

要件：
- 最初に情報源を収集・保存し、その後に分析する
- 価格変化が最大の時間帯を示す
- イベント時刻をすべて UTC へ変換する
- 各要因について証拠、反証、信頼度を記載する
- すべての計算に入力列と数式を記載する
- 検証できない内容は「要確認」に入れ、補わない
- Markdown の中間成果物を完成してから report.html を作成する
- 最後に、作成・変更したファイルと未解決事項を報告する
```

実行中は、次の 3 種類のツール要求を重点的に確認します。

1. **ネットワーク要求**：ドメインが計画中の情報源と一致するか。
2. **ファイル書き込み**：パスが `gold-review` 内にあるか。
3. **コマンド実行**：今回のデータだけを処理するか、パッケージをインストールする、または別のネットワークへアクセスするか。

データ処理ライブラリを一時的にインストールする必要がある場合は、一度停止して、パッケージ名、出所、コマンドを自分で確認してください。依存関係のインストールを「タスクを続行する」ための当然の許可にしないでください。

## 手順 9：中間成果物を検収する

### `sources.md` の確認

各情報源には、少なくとも次を含めます。

* 情報源名と URL。
* ウェブページまたはデータの公開時刻。
* 今回のアクセス時刻。
* どの事実またはデータを裏付けるか。
* ログインや購読が必要か、二次転載か。

開けないリンクを唯一の証拠にできません。転載記事は、できるだけ元の公開者までたどってください。

### `market-data.csv` の確認

次を確認します。

* 時刻形式とタイムゾーンが統一されている。
* 価格の単位が統一されている。
* 欠損値が無断で補完されていない。
* データ範囲がタスク要件と一致する。
* `source` が `sources.md` の項目に対応する。

いくつかの時点を無作為に選び、元の情報源と手作業で照合します。

### `analysis.md` の確認

「あるイベントの後で価格が下がった」という記述は時間的な関係だけを示し、自動的に因果関係を証明するものではありません。各解釈には次の構造を推奨します。

```text
観察：
時間帯：
支持証拠：
反証または別の説明：
信頼度：高 / 中 / 低
要確認：
```

テクニカル指標にも、数式、パラメーター、入力範囲を残す必要があります。計算過程なしに結果の数値だけを示しても、合格とはみなせません。

### `report.html` の確認

ローカルで開き、次を確認します。

* アクセスできないローカル絶対パスに依存していない。
* 表やグラフの数値が CSV と一致する。
* 重要な結論を情報源までたどれる。
* 欠損データと制約が最終レイアウトで隠されていない。
* API Key、Cookie、ユーザー名、個人ディレクトリを含まない。

## よくある質問

### Kimi K2.5 がエージェントのモデル一覧に表示されない

モデルのエンドポイント種類に **Anthropic Messages** が含まれることを確認し、Embedding、Rerank、画像生成として誤って分類されていないかを確認します。同じ名前のモデルでも、プロバイダーによって同じエンドポイント機能を公開しているとは限りません。

### エージェントがウェブを検索しない

`WebSearch` と `WebFetch` が現在のエージェントに追加され、ツール要求が拒否されていないことを確認します。モデルが「ウェブ接続に対応」と宣伝されていても、Cherry Studio が自動的にウェブツールを提供するわけではありません。

### スキルをインストールしても動作しない

先にエージェントを保存し、作業ディレクトリがあることを確認してから、エージェントのスキル一覧で有効にします。ファイルを作業ディレクトリへ置くだけでは、インストールおよび関連付けは完了しません。

### レポートファイルを作成できない

`Write` が利用でき、現在の権限要求が承認され、保存先がアクセス可能なディレクトリ内にあることを確認します。パスの問題を解決するために、ディスク全体へ権限を広げないでください。

### データは完全に見えるが、出所と一致しない

最終レポートの作成を停止し、各数値の出所行を 1 項目ずつ示すようエージェントへ依頼します。出所を見つけられない数値は、文章を整え続けるのではなく、削除するか要確認とします。

## 拡張方法

基本ワークフローが合格してから、次の機能を 1 つずつ追加できます。

* MCP から、レビュー済みのデータサービスへ接続する。
* スケジュールタスクで定期的にレビューを作成する。ただし、人による確認は残す。
* チャンネルでは取引結論を直接送らず、「レポートが作成されました」という通知を送る。
* 安定した検証規則をチームスキルとして整理する。

毎回 1 種類の機能だけを追加し、権限、費用、出力を再確認してください。詳しい設定は [MCP](../mcp/)、[スケジュールタスク](../scheduled-tasks.md)、[チャンネル](../agent-channels.md)を参照してください。
