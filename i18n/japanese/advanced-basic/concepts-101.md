# コンセプト入門：アシスタント、エージェント、スキル、MCP、チャンネル

Cherry Studio V2 では、「モデルと対話すること」と「モデルにタスクを実行させること」が異なるレベルに分けられています。以下の概念を理解すれば、どこから設定を始めるべきかをすばやく判断できます。

## まず結論

| 概念 | 主な役割 | 代表的な用途 |
| :--- | :--- | :--- |
| モデルサービス | モデルと API へのアクセスを提供する | DeepSeek、Claude、GPT などのモデルを接続する |
| アシスタント | 再利用可能な会話設定を保存する | 翻訳、執筆、質疑応答、ナレッジベース検索 |
| エージェント | 制御された権限でツールを呼び出し、複数ステップのタスクを完了する | ファイル処理、コマンド実行、ワークフローの実行 |
| スキル | 特定のタスクに関する手順、プロセス、リソースをエージェントに提供する | プレゼンテーションの作成、コードレビュー、チーム規約に沿った文書作成 |
| MCP | 共通プロトコルで外部ツールやデータに接続する | Web 検索、データベースの読み取り、サードパーティサービスの呼び出し |
| チャンネル | エージェントをインスタントメッセージングプラットフォームに接続する | Feishu、Telegram、Slack などからエージェントを利用する |
| スケジュールタスク | 1 回、一定間隔、または Cron スケジュールでエージェントを実行する | 日次レポート、定期チェック、定時集計 |

最も一般的な選び方は次のとおりです。

* 一貫した役割、モデルパラメータ、ナレッジベースを使った質疑応答だけが必要な場合：**アシスタント**を使用します。
* AI にディレクトリの読み取り、ファイルの編集、コマンドの実行、連続したツール呼び出しを行わせる場合：**エージェント**を使用します。
* エージェントに特定の作業方法が不足している場合：**スキル**をインストールして有効にします。
* アシスタントまたはエージェントが Cherry Studio 外部のツールを必要とする場合：**MCP** を設定します。
* チームメンバーがチャットツールからエージェントを利用する場合：**チャンネル**を設定します。
* エージェントを無人でスケジュール実行する場合：**スケジュールタスク**を作成します。

## モデルサービス：能力の供給元

モデルサービスには、API アドレス、キー、モデル一覧が保存されます。アシスタントとエージェントはいずれもモデルを選択しますが、モデルに対する要件は異なります。

* アシスタントは日常的な会話向けで、用途に応じてテキスト、ビジョン、推論、ツール呼び出しに対応するモデルを選択できます。
* エージェントのモデル選択欄には、Anthropic Messages エンドポイントに対応し、対話形式でのタスク実行に適したモデルだけが表示されます。Embedding、Rerank、画像生成モデルは表示されません。

最初に **設定 → モデルサービス** で設定を完了してから、アシスタントまたはエージェントを作成してください。具体的な手順は、[モデルサービス](../pre-basic/providers/)を参照してください。

## アシスタント：再利用可能な会話設定

アシスタントは、長期的に再利用する一連の会話動作を保存するための機能です。名前やプロンプトに加え、モデル、サンプリングパラメータ、コンテキスト数、ナレッジベース、MCP モードも設定できます。

たとえば、次のようなアシスタントを作成できます。

* 用語と出力形式を固定した翻訳アシスタント。
* 製品資料のナレッジベースに接続したカスタマーサポート用アシスタント。
* 検索 MCP を呼び出せる調査用アシスタント。

アシスタントは、会話を中心とするタスクに適しています。ナレッジベースを検索したり、設定済みの MCP ツールを呼び出したりできますが、エージェントのようにローカル作業ディレクトリ、ファイル編集権限、コマンド実行権限を持つことはありません。

アシスタントは[リソースライブラリ](../cherrystudio/preview/library.md)で作成、管理し、メインの会話画面で使用します。続けて[アシスタントライブラリ](../cherrystudio/preview/agents.md)と[会話](../cherrystudio/preview/chat.md)をお読みください。

## エージェント：実行可能なタスク設定

エージェントでは、プロンプトとモデルに加えて、次の項目を設定できます。

* アクセスを許可するローカルディレクトリ。
* ツールの権限モード。
* 組み込みツール、MCP Server、スキル。
* メインモデル、計画モデル、小型モデル。
* 最大ターン数、環境変数、ハートビートなどの実行設定。

これらの設定により、エージェントは操作方法を提案するだけでなく、1 つの目標に向かって複数ステップの処理を継続できます。たとえば、ワークスペース内のファイルを読み取り、文書を編集し、MCP サービスを呼び出して、結果をローカルに保存できます。

{% hint style="warning" %}
エージェントの権限範囲によって、読み書きできるディレクトリや、ツールを直接実行できるかどうかが決まります。使い始めはアクセス可能なディレクトリを制限し、確認が必要な権限モードを優先してください。確認を省略するモードは、リスクを十分に理解している場合にのみ使用してください。
{% endhint %}

エージェントページは、内部で Cherry Studio のローカル **API サーバー**に依存しています。V2 では新しいエージェントを作成するときに自動で起動を試みるため、通常は事前に設定ページで手動設定する必要はありません。サービスが無効になっている、または起動できない場合は、エージェントページに起動を促すメッセージが表示されます。API サーバーは、他のアプリケーションからローカル HTTP インターフェースを通じて Cherry Studio を呼び出すためにも使用できます。詳しくは[エージェント](agent.md)と[API サーバー](api-server.md)を参照してください。

## スキル：エージェントに「一連の作業方法」を伝える

スキルは、インストール可能なタスク手順と関連リソースのまとまりです。作業マニュアルのように、使用条件、実行手順、品質要件、必要に応じて使用するスクリプトやテンプレートを記述します。

スキルは Agent ID ごとにエージェントへ関連付けられます。新しいエージェントでは、まず保存を行い、その後、そのエージェントの **機能拡張 → スキル** でスキルを有効にできます。

スキルが適しているのは、次のような場合です。

* 同じ種類のタスクで、毎回決まった手順に従わせたい。
* チーム規約、テンプレート、チェックリストを再利用したい。
* 確立された作業方法を複数のエージェントで共有したい。

インストール、検索、管理の方法は、[スキル](../pre-basic/settings/skills.md)を参照してください。

## MCP：AI を外部機能に接続する

MCP（Model Context Protocol）は、AI アプリケーションを外部のツール、プロンプト、リソースに接続するためのプロトコルです。Cherry Studio では、ローカルの STDIO Server を追加できるほか、SSE または Streamable HTTP Server に接続できます。

MCP Server は、モデルに次の 3 種類の機能を提供できます。

| 機能 | 用途 |
| :--- | :--- |
| Tools | 検索、照会、書き込み、API 呼び出しなどの操作を実行する |
| Prompts | 再利用可能なプロンプトテンプレートを提供する |
| Resources | 読み取り可能なデータやコンテキストを提供する |

アシスタントでは、MCP モードを無効、自動、手動の 3 種類から選択できます。エージェントでは、有効になっている MCP Server から関連付けるサービスを選択できます。

{% hint style="warning" %}
MCP Server はローカルでプログラムを実行する場合も、内容をリモートサービスへ送信する場合もあります。追加する前に、提供元、コマンド、環境変数、アクセス先ディレクトリ、リモートアドレスを確認し、タスクに必要な権限だけを付与してください。
{% endhint %}

設定方法は、[MCP 利用ガイド](mcp/)を参照してください。

## スキルと MCP の違い

この 2 つはよく組み合わせて使用されますが、解決する問題は異なります。

| 比較項目 | スキル | MCP |
| :--- | :--- | :--- |
| 中心となる問題 | エージェントに「どう進めるか」を伝える | モデルに「何を呼び出せるか」を提供する |
| 主な内容 | 説明、手順、テンプレート、スクリプト、リソース | ツール、プロンプト、リソースのインターフェース |
| 主な利用場所 | エージェント | アシスタントとエージェント |
| 外部サービスへの依存 | 必須ではない | 個々の Server による |

たとえば、「チームのテンプレートに沿って週報を書く」という手順はスキルにできます。「プロジェクト管理システムから今週のタスクを取得する」機能は MCP で提供できます。両方を組み合わせると、エージェントは執筆手順を理解したうえで、必要なデータも取得できます。

## チャンネル：エージェントをチャットプラットフォームに接続する

チャンネルは、1 つのエージェントをインスタントメッセージングプラットフォームに関連付けます。Cherry Studio V2 では現在、Feishu / Lark、Telegram、QQ、WeChat、Discord、Slack のチャンネルを設定できます。

チャンネルはプラットフォームからメッセージを受信し、関連付けられたエージェントに処理させ、結果を元のプラットフォームへ返します。チャンネルがエージェント自体の代わりになるわけではありません。モデル、プロンプト、ツール、ディレクトリ、権限は引き続きエージェントで設定します。

チャンネルは通常、無人で動作します。有効にする前に、次の点も確認してください。

* 関連付けるエージェントとモデルが正しいか。
* 応答を許可する会話 ID またはチャンネル ID が制限されているか。
* エージェントにタスクを完了するために必要なツール権限があるか。
* プラットフォームのトークンとキーが対応する設定内にだけ保存されているか。

詳しくは、[チャンネル](agent-channels.md)を参照してください。

## スケジュールタスク：予定に沿ってエージェントを実行する

スケジュールタスクでも、エージェントが処理を実行します。次のタスクを作成できます。

* 1 回だけ実行するタスク。
* 一定の間隔で繰り返すタスク。
* Cron 式で実行時刻を指定するタスク。

スケジュールタスクは、人の入力を待つ必要がない作業に適しています。作成する前に、対象のエージェントが通常のセッションで同じタスクを正常に完了できることを確認し、適切な権限、タイムアウト、実行スケジュールを設定してください。詳しくは、[スケジュールタスク](scheduled-tasks.md)を参照してください。

## 機能を組み合わせる例

「チームのプロジェクト進捗を毎日まとめ、Feishu グループに送信する」場合を例にします。

1. **モデルサービス**で、エージェントが利用できるモデルを設定します。
2. **エージェント**を作成し、集計ルールと出力形式を指定します。
3. チーム週報用の**スキル**をインストールして有効にし、執筆手順を固定します。
4. **MCP** でプロジェクト管理システムに接続し、タスクデータを読み取ります。
5. **スケジュールタスク**を作成し、エージェントを毎日決まった時間に実行します。
6. Feishu の**チャンネル**を作成し、チームメンバーがグループチャットから追加の質問をできるようにします。

すべての機能が必要とは限りません。まずアシスタントまたはエージェントから始め、明確な必要性が生じたときだけスキル、MCP、チャンネル、スケジュールタスクを追加すると、設定を管理しやすくなります。

## 推奨する学習順序

1. [モデルサービス](../pre-basic/providers/)を設定し、通常の会話を 1 回行います。
2. [リソースライブラリ](../cherrystudio/preview/library.md)でアシスタントを作成し、プロンプト、モデル、ナレッジベースの使い方を確認します。
3. [エージェント](agent.md)を作成し、制限されたディレクトリと確認が必要な権限から始めます。
4. タスクに応じて[スキル](../pre-basic/settings/skills.md)または [MCP](mcp/)を追加します。
5. エージェントが安定して動作するようになったら、[スケジュールタスク](scheduled-tasks.md)と[チャンネル](agent-channels.md)を設定します。
