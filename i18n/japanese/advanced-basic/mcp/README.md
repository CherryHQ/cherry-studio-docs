# MCP 利用ガイド

MCP（Model Context Protocol）は、モデルが外部ツールやデータを利用するための標準プロトコルです。MCP Server に接続すると、Cherry Studio のアシスタントや Agent は、回答中に Web ページの読み取り、データベースの検索、ファイル操作、業務 API の呼び出し、サーバーが提供するプロンプトやリソースの利用などを行えるようになります。

## MCP の仕組み

一般的な呼び出しには、次の役割が関係します。

| 役割 | 働き |
| --- | --- |
| モデル | ツールが必要かどうかを判断し、ツールの引数を生成する |
| Cherry Studio | MCP Server に接続し、権限を確認して呼び出し過程を表示する |
| MCP Server | ツール、プロンプト、リソースを提供し、実際の処理を実行する |

おおまかな流れは次のとおりです。

1. アシスタントまたは Agent にタスクを依頼する。
2. モデルが許可済みのツールから使用するものを選ぶ。
3. Cherry Studio がサーバーとツールの権限に基づき、ユーザーの確認が必要かどうかを判断する。
4. MCP Server が処理を実行し、結果を返す。
5. モデルがその結果を踏まえて回答を続ける。

モデルがコンピューターやアカウントへ直接「ログイン」するわけではなく、MCP Server が提供するインターフェースを通じて動作します。ただし、MCP Server 自体はローカルの実行プログラムである場合も、リモートサービスである場合もあるため、提供元と権限を確認する必要があります。

## 主な用途

- ローカルファイルの読み取りや検索。
- Web ページの取得、ブラウザー操作、ネットワーク API の呼び出し。
- ナレッジベース、データベース、チーム文書の検索。
- Python などのコードの実行。
- ノート、メッセージ、プロジェクト管理などのオンラインサービスとの連携。
- 明示的な許可に基づく書き込み、削除、業務操作の実行。

実際に利用できる機能は、サーバーが提供するツールによって異なります。同じ種類の MCP Server でも、権限、データの送信先、品質が異なる場合があります。

## MCP Server が提供できるもの

MCP が扱うのは「ツール」だけではありません。

- **Tools**：検索、読み取り、書き込みなど、モデルが呼び出せる操作。
- **Prompts**：サーバーが提供する再利用可能なプロンプトテンプレート。
- **Resources**：サーバーが提供するファイル、文書、その他のコンテキストリソース。

サーバーを有効にすると、詳細ページで実際に提供されている機能を確認できます。特定の種類の機能が提供されていない場合、対応するタブは空になるか、表示されないことがあります。

## MCP と Skills の違い

| 比較項目 | Skills | MCP |
| --- | --- | --- |
| 主な役割 | 特定のタスクを完了する方法を Agent に指示する | モデルが外部ツールやデータを呼び出せるようにする |
| 主な内容 | 手順、ワークフロー、任意のリソース | ツール、プロンプト、リソース、接続プロトコル |
| 外部操作を実行するか | Skill が呼び出すツールによる | 通常はローカルプログラムまたはリモートサービスに接続する |
| V2 での利用場所 | 主に Agent で利用 | 通常のアシスタントと Agent の両方で利用可能 |

Skill は Agent に、いつ、どの手順で MCP を使うかを指示できます。一方、MCP は実際のツール呼び出しを担います。この 2 つは組み合わせて利用できます。詳しくは [Skills](../../pre-basic/settings/skills.md) を参照してください。

## Cherry Studio で MCP を使う

一連の手順は次のとおりです。

1. **設定 → MCP サーバー**でサーバーをインストールまたは追加する。
2. コマンド、URL、引数、Header、環境変数を入力する。
3. サーバーを有効にし、ツールとログを確認する。
4. 通常のアシスタントまたは Agent にそのサーバーを追加する。
5. ツール呼び出しに対応したモデルでタスクを開始する。

{% hint style="info" %}
追加の実行環境が必要になる可能性があるのは、`uv`、`uvx`、`npx`、`bun` などのローカルコマンドで起動する STDIO サーバーだけです。リモートサーバーと大半の内蔵サーバーでは、事前に UV や Bun をインストールする必要はありません。
{% endhint %}

詳しい手順は、[MCP の設定と使用](config.md)を参照してください。

## サーバーの探し方

Cherry Studio の MCP 設定には、次の入口があります。

- **内蔵サーバー**：Cherry Studio が対応済みの一般的なサーバー。
- **MCP マーケット**：接続済みのマーケットからサーバーを探す。
- **サービスプロバイダー**：対応する MCP サービスプロバイダーに接続する。
- **JSON または DXT からインポート**：開発者が提供する設定や拡張パッケージを使用する。
- **手動で新規作成**：公式ドキュメントに従い、STDIO、SSE、Streamable HTTP の設定を入力する。

初めて利用する場合は、[内蔵 MCP サーバー](in-memory.md)から始めることをおすすめします。設定手順が明確で、権限も確認しやすいためです。

## セキュリティ境界

{% hint style="danger" %}
MCP のツール宣言はセキュリティサンドボックスではありません。STDIO Server は現在のユーザー権限で動作するプログラムであり、悪意のあるサーバーや侵害されたサーバーは、そのプロセス権限でアクセス可能なデータを読み取るおそれがあります。リモート Server にも、ツールへ送信した内容が渡ります。
{% endhint %}

サーバーをインストールまたは有効化する前に、次の点を確認してください。

- 開発者、パッケージ、ダウンロード先、更新履歴を確認する。
- タスクの実行に必要なディレクトリ、アカウント、API Scope のみを許可する。
- 実際の秘密鍵をプロンプトや共有 JSON に記載しない。
- **ツール**ページで不要なツールを無効にする。
- ファイルの書き込み、データの削除、メッセージの送信、注文の作成などでは、ユーザーによる確認を残す。
- 使用しなくなったサーバーは無効化またはアンインストールする。

自動承認は確認手順を減らすだけであり、ツール自体の権限を弱めるものではありません。よく知らないサーバーで、自動承認を一括して有効にしないでください。

## サポートを受ける

ログだけでは問題を特定できない場合は、Cherry Studio のバージョン、OS、サーバーの種類、機密情報を除いたエラー内容を添えて、[フィードバックと提案](../../question-contact/suggestions.md)からお知らせください。
