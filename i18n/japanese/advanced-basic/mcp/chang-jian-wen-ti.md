# MCP のよくある質問

このページでは、MCP Server が起動しない、接続後にツールが表示されない、呼び出しがタイムアウトする、または引数エラーが発生する場合の対処方法を説明します。MCP を初めて設定する場合は、先に [MCP の設定と使用](config.md) を参照してください。実行環境がない場合は、まず [MCP 環境のインストール](install.md) を完了してください。

## 最初に接続タイプを確認する

`設定 → MCP Server` を開いて問題のある Server に入り、タイプと必須項目が一致しているかを確認します。

| タイプ | 必須設定 | よくある問題 |
|---|---|---|
| `stdio` | Command、Arguments、必要に応じて環境変数 | コマンドが存在しない、引数の分け方が誤っている、依存関係が未インストール |
| `SSE` | Server URL、必要に応じて Headers | URL パスが誤っている、サービスが実行されていない、認証に失敗した |
| `Streamable HTTP` | Server URL、必要に応じて Headers | SSE のアドレスを誤って `/mcp` に設定した、またはその逆 |
| 内蔵 | ページの説明に従って設定 | 認証、ディレクトリ、検索キーが不足している |

`stdio` では Cherry Studio がローカルの子プロセスを起動します。SSE と Streamable HTTP は、すでに実行中のリモートまたはローカルサービスに接続します。対処方法が異なるため、URL や Command だけを入れ替えて再試行し続けないでください。

## リアルタイムログを確認する

Server の詳細ページで、タイトル横の **ログを表示** をクリックします。ログには次の内容が表示されます。

* `stdout` / `stderr`：ローカルコマンドの出力。
* `info` / `warn` / `error`：接続、初期化、呼び出しの状態。
* 最近の起動引数、接続エラー、ツールの戻り値。

最初に Server を無効にし、ログを開いてからもう一度有効にすると、最初のエラーを見つけやすくなります。ログに保持されるのは、ページの現在のセッションにおける最新の記録だけです。問題を再現したら、必要な部分を早めにコピーしてください。

{% hint style="warning" %}
ログには、コマンド引数、ファイルパス、リクエストアドレス、ツールの戻り値が含まれる場合があります。フィードバックを送信する前に、Token、API Key、Cookie、個人ディレクトリ、業務データをマスキングしてください。
{% endhint %}

## Server を有効にできない

### `npx`、`uvx`、またはその他のコマンドが存在しない

Cherry Studio はログイン Shell の環境変数を読み取ってコマンドを検索します。`npx` の場合は内蔵 Bun の利用も試み、`uv` / `uvx` の場合はインストール済みの内蔵バージョンの利用を試みます。

それでも `not found` と表示される場合：

1. `設定 → MCP Server → 環境インストール` を開きます。
2. Server に必要な Node.js または `uv` の実行環境をインストールします。
3. Cherry Studio を完全に終了してもう一度起動し、新しい PATH を反映します。
4. Server の詳細ページに戻り、もう一度有効にします。

ターミナルで確認することもできます。

```bash
node --version
npx --version
uvx --version
```

実際にその Server が使用するコマンドだけを確認すればよく、すべての環境をインストールする必要はありません。

### Command と Arguments の入力が誤っている

Cherry Studio では次のように入力します。

* **Command** には、`npx`、`uvx`、実行ファイルの絶対パスなど、実行するコマンドだけを入力します。
* **Arguments** には、1 行に 1 つの独立した引数を入力します。
* コマンド全体を Command 欄に貼り付けないでください。
* 空白を含むファイルパスは 1 つの引数として入力します。Server のドキュメントで明示的に求められていない限り、Shell の引用符を自分で追加しないでください。

たとえば、次の JSON は：

```json
{
  "command": "npx",
  "args": ["-y", "@example/mcp-server", "--mode", "read-only"]
}
```

フォームでは次のように入力します。

```text
Command
npx

Arguments
-y
@example/mcp-server
--mode
read-only
```

### JSON のインポートに失敗する

JSON から追加する場合、最上位に `mcpServers` を含め、1 回につき 1 つの Server だけをインポートします。

```json
{
  "mcpServers": {
    "example": {
      "command": "npx",
      "args": ["-y", "@example/mcp-server"]
    }
  }
}
```

よくある原因：

* 全角の引用符または余分なカンマを使用している。
* `args` が文字列の配列ではない。
* 1 つの JSON に複数の Server が含まれている。
* `url`、`command`、タイプを互換性のない構成で混在させている。
* コピーした内容に Markdown のコードフェンスが含まれている。

## リモート Server に接続できない

### URL またはプロトコルが一致しない

Server の公式ドキュメントで、SSE と Streamable HTTP のどちらが提供されているかを確認してください。

* SSE の一般的なアドレス：`http://localhost:3000/sse`
* Streamable HTTP の一般的なアドレス：`http://localhost:3000/mcp`

パスは Server 側で決まるため、`/sse` と `/mcp` は一般的な例にすぎません。まずターミナルまたはブラウザーでサービスがそのアドレスを実際にリッスンしていることを確認し、それから対応するタイプを選択してください。

Server が Docker、仮想マシン、または別のデバイスで動作している場合、`127.0.0.1` は Cherry Studio が動作しているシステムを指し、Server のホストを指すとは限りません。

### 401 または 403 が返される

**Headers** に、1 行につき `名前=値` の形式で認証情報を入力します。

```text
Authorization=Bearer YOUR_TOKEN
```

実際の Token を公開可能な設定に含めないでください。Headers を変更したら保存します。有効になっている Server は新しい設定での再接続を試み、失敗すると自動的に無効状態へ戻ります。

## 接続済みだがツールが表示されない

次の項目を順に確認してください。

1. `設定 → MCP Server` で Server が有効になっている。
2. Server 詳細の **ツール** タブにツールが表示されている。
3. 対象ツールが一覧で個別に無効化されていない。
4. 現在のアシスタントまたは Agent でその MCP Server が有効になっている。
5. 新しい会話を開始し、新しいツール設定をコンテキストに反映する。

「Server が接続済み」という状態は、プロトコルの初期化が成功したことだけを示します。各アシスタントにそのツールが自動的に付与されるわけではありません。

Server のドキュメントではツールが提供されるとされているのに一覧が空の場合は、ログに `listTools`、プロトコルバージョン、初期化エラーが記録されていないか確認してください。

## ツール呼び出しがタイムアウトする

Cherry Studio のデフォルトのツール呼び出しタイムアウトは 60 秒です。Server 詳細の **Timeout** で秒数を増やせます。長時間タスクのサポートを有効にすると、Server が進捗イベントを送信している間は待機時間を延長できますが、合計時間には引き続き上限があります。

接続の初期化には、より長い待機時間が設定されています。初回の依存関係ダウンロードやリモート Server の起動には数分かかる場合があります。次の違いを確認してください。

* **有効化時のタイムアウト**：通常はインストール、ネットワーク、URL、初期化の問題です。
* **ツール実行時のタイムアウト**：通常は Server の処理自体が遅いか、進捗が送信されていません。

Timeout を無制限に増やさないでください。まずログでリクエストが実際に進行しているかを確認し、Server が MCP Progress に対応しているかを調べてください。

## 環境変数が反映されない

Server の環境変数は、1 行につき `KEY=VALUE` の形式で入力します。Cherry Studio はログイン Shell の環境と結合してから、`stdio` の子プロセスに渡します。

確認項目：

* キー名が Server のドキュメントと完全に一致しているか。
* 値に誤って引用符または前後の空白が含まれていないか。
* 変更後に保存して再接続したか。
* Token の有効期限が切れていないか。
* Server が環境変数を実際に読み取るのか、Header または設定ファイルを要求しているのか。

リモートの SSE / Streamable HTTP Server では通常、認証情報をローカルプロセスの環境変数ではなく Headers に設定します。

## `mcp-server-time` のタイムゾーンが誤っている

公式の Time Server は Python Server で、通常は `uvx` から起動します。ローカルタイムゾーンを指定する場合は、独立した引数として入力します。

```json
{
  "mcpServers": {
    "time": {
      "command": "uvx",
      "args": [
        "mcp-server-time",
        "--local-timezone=Asia/Shanghai"
      ]
    }
  }
}
```

タイムゾーンには、`Asia/Shanghai`、`Europe/Berlin`、`America/New_York` などの IANA 名を使用してください。`UTC+8` のようなオフセットの略記は使用しないでください。

`uvx not found` と表示される場合は、先に MCP の Python 環境をインストールし、Cherry Studio を再起動してください。Time Server のインストール方法や引数はバージョンによって変わる場合があります。最終的には [公式 MCP Servers リポジトリ](https://github.com/modelcontextprotocol/servers/tree/main/src/time) を参照してください。

## 問題を最小構成で再現する

それでも解決しない場合：

1. 必須項目だけを含む新しい Server 設定を作成します。
2. プロキシ、カスタムミラー、不要な環境変数を一時的に削除します。
3. 空のアシスタントで、この MCP Server だけを有効にします。
4. 最も単純で副作用のないツールを 1 つ呼び出します。
5. エラーポップアップと **ログを表示** 内の対応する時間帯の情報を保存します。

フィードバックを送信する際は、Cherry Studio のバージョン、OS、Server タイプ、機密情報を除いた設定とログを添付してください。実際の認証情報を添付しないでください。公式窓口は [フィードバックと提案](../../question-contact/suggestions.md) を参照してください。
