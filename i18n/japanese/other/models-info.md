# モデルデータ

Cherry Studio V2 は、ドキュメント内の静的な巨大モデル一覧に依存しません。モデルのバージョン、コンテキスト、価格、プロバイダーの機能は頻繁に変わるため、長期にわたる手作業の更新では、古い情報が確定事項のように見えてしまいます。

このページでは、アプリに表示されるモデルデータの出所、各フィールドの意味、現在のプロバイダーでモデルが実際に利用できるかを確認する方法を説明します。

{% hint style="info" %}
アプリに表示されるモデル情報は、設定とルーティングに使われます。利用可否、制限、料金については、モデルプロバイダーの公式ドキュメント、コンソール上の権限、実際の API 応答が最終的な根拠です。
{% endhint %}

## モデルデータの出所

V2 は複数のデータを統合し、最終的に表示するモデル情報を作成します。

1. **モデルカタログ**：一般的な名前、機能、入出力形式、コンテキスト、パラメーター、価格などの基礎情報を提供します。
2. **プロバイダー別の上書き情報**：特定プロバイダーのエンドポイント、固有の制限、別名、代替モデルを記述します。
3. **プロバイダーのモデル一覧**：一部のプロバイダーは、現在のアカウントから見える Model ID を API で返します。
4. **ユーザー設定**：手動で追加したモデル、名前、機能タグ、エンドポイント、制限などのカスタム情報です。

統合時はユーザー設定が最優先され、次にプロバイダー別の上書き情報、最後に共通モデルカタログが使われます。

プロバイダー API が Model ID だけを返す場合、Cherry Studio はカタログから詳細を補完します。カタログにない ID もカスタムモデルとして追加できますが、一部のフィールドが空になる場合があります。

## 確認場所

**設定 → モデルサービス**を開き、プロバイダーを選択します。モデル一覧では次の操作ができます。

* モデル名または ID を検索する。
* 機能で絞り込む。
* 個別のモデルを有効または無効にする。
* 現在の絞り込み結果を一括で有効にする。
* モデル編集パネルを開き、一部のフィールドを確認または変更する。
* プロバイダーが自動表示しないモデルを手動で追加する。

多くのモデル選択欄には、有効なモデルだけが表示されます。モデルを無効にしても設定は削除されません。

プロバイダーの詳しい設定手順は[モデルサービス](../pre-basic/providers/)を参照してください。

## 主なフィールド

### 表示名と Model ID

| フィールド | 用途 |
| :--- | :--- |
| 表示名 | Cherry Studio の画面に表示する名前。API ID と異なってもかまいません |
| Model ID | プロバイダー API へのリクエストで使う実際のモデル識別子 |
| プロバイダー | 認証、エンドポイント、リクエストのルーティングを担当する設定 |
| グループ | モデル一覧の整理だけに使われ、API の動作には影響しません |

同じ Model ID が複数のプロバイダーに存在することがあります。アプリ内部ではプロバイダーと Model ID の組み合わせが一意の識別子になりますが、モデルを手動追加するときは、通常、プロバイダーのドキュメントに記載された API Model ID を入力します。アプリ内部の接頭辞を独自に付けないでください。

### エンドポイントの種類

エンドポイントの種類によってリクエスト形式が決まります。V2 が対応するモデルエンドポイントは次のとおりです。

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* OpenAI Image Generation
* Jina Rerank

モデル名が同じでも、すべてのプロバイダーが同じエンドポイントに対応しているとは限りません。種類を誤ると、`400`、`404`、無効なツールパラメーター、応答構造の解析失敗などが発生します。

### コンテキストと出力上限

| フィールド | 意味 |
| :--- | :--- |
| コンテキストウィンドウ | 1 回のリクエストで処理できる全体の Token 規模 |
| 最大入力 | プロバイダーが許可する入力 Token の上限 |
| 最大出力 | 1 回の生成で許可される出力 Token の上限 |

これらの値を単純に足し合わせることはできません。プロバイダーが画像、ツール定義、キャッシュ、推論 Token、特定プランに別の制限を設けている場合もあります。

ドキュメント中の `k` や `M` という略記を、正確な利用可能値とみなさないでください。数値を設定する場合は、プロバイダーの最新 API ドキュメントにある整数値を使い、最小リクエストで検証します。

### 入力と出力の形式

モデルは、対応する入力形式と出力形式を個別に宣言できます。

* テキスト
* 画像
* 音声
* 動画

「画像を理解できる」ことと「画像を生成できる」ことは別の機能です。音声入力に対応していても、音声を生成できるとは限りません。

### 機能タグ

モデル一覧には次の機能が表示される場合があります。

| 機能 | 説明 |
| :--- | :--- |
| 画像理解 | 画像を受け取り、テキストの結果を生成する |
| 画像生成 | 画像を生成または編集する |
| 音声理解 | 音声を受け取る、または認識する |
| 音声生成 | 音声または読み上げを生成する |
| 動画理解 | 動画を受け取り、内容を理解する |
| 動画生成 | 動画を生成する |
| 推論 | 推論強度や思考関連の設定に対応する |
| ツール呼び出し | 構造化された関数またはツール呼び出しを生成する |
| ネイティブ検索 | モデルまたはプロバイダーのエンドポイントが検索機能を提供する |
| Embedding | ナレッジベースのインデックス作成と検索に使うベクトルを生成する |
| Rerank | 候補テキストを並べ替える |

機能タグは、モデルの絞り込み、画面のコントロール、リクエストのルーティングに影響します。タグを手動で選択しても、Cherry Studio に使い方を伝えるだけで、**プロバイダー上のモデルに実際の機能が追加されるわけではありません**。

### 対応パラメーター

モデルごとに対応するパラメーターが異なる場合があります。例：

* Temperature
* Top P
* Top K
* Frequency Penalty
* Presence Penalty
* Max Tokens
* Stop Sequences
* System Message

推論モデルは、従来のサンプリングパラメーターの一部を無視または拒否することがあります。`unsupported parameter` が発生した場合は、まず既定値に戻し、そのモデルの最新公式ドキュメントに従って 1 項目ずつ有効にしてください。

### 推論設定

推論モデルには次の情報が含まれる場合もあります。

* 推論の種類。
* 利用できる推論強度。
* 思考 Token の最小値、最大値、既定値。
* インターリーブ思考への対応有無。

実際に利用できる値は、モデル、エンドポイント、プロバイダーの実装に左右されます。同じモデルでも、OpenAI 互換エンドポイントと Anthropic Messages エンドポイントではパラメーター形式が異なる場合があります。

### 価格

カタログには、入力、出力、キャッシュ、画像、音声、動画の価格を保存できますが、これは見積もりにだけ使用してください。

* プロバイダーがいつでも価格を変更する可能性があります。
* 地域、プラン、販売経路によって価格が異なる場合があります。
* 推論、キャッシュ、バッチ処理、ツール呼び出しに別料金が設定される場合があります。
* サードパーティーの中継サービスが独自の料金体系を使う場合があります。

支払いと費用の照合には、プロバイダーの請求書を使用してください。

## 同名モデルで情報が異なる理由

主な理由は次のとおりです。

* プロバイダーが異なるスナップショットや別名にマッピングしている。
* エンドポイントの種類が異なる。
* 現在のアカウントで一部の機能だけが有効になっている。
* プロバイダーがコンテキストまたは出力長を制限している。
* 集約サービスが独自の Model ID と価格を使っている。
* ローカルモデルの量子化、テンプレート、実行パラメーターが異なる。
* ユーザーが機能または制限フィールドを手動で変更したことがある。

モデルを比較するときは、表示名だけでなく、**プロバイダー、Model ID、エンドポイント、日付**も記録してください。

## モデル一覧を自動取得する際の注意

「モデル一覧の取得に成功した」ことは、プロバイダーが Model ID の集合を返したことだけを示します。次の事項は保証されません。

* 現在の API Key に呼び出し権限がある。
* モデルが画像、ツール、推論、検索に対応している。
* コンテキストと価格の情報が完全である。
* そのモデルをすべてのエンドポイントで使用できる。
* プロバイダーが後でモデルを終了または改名しない。

一覧を取得したら、必要なモデルを有効にし、実際のリクエストを 1 回実行してください。

## モデルを検証する方法

### 1. 基本接続

プロバイダー設定で API Host と認証情報を確認し、接続チェックを実行します。チェックに成功したら、短いテキストで実際の会話を完了させます。

### 2. 必要な機能だけをテストする

| 対象機能 | 最小テスト |
| :--- | :--- |
| 画像理解 | 機密情報を含まない画像を 1 枚アップロードし、明確な要素を説明させる |
| ツール呼び出し | 副作用のないツールを 1 つ割り当て、固定情報を読み取らせる |
| 推論 | 人手で確認できる多段階の問題を使い、パラメーターが受理されるかを確認する |
| ネイティブ検索 | 更新直後で検証可能な情報を質問し、実際の検索記録と引用を確認する |
| Embedding | 次元数を取得し、小さなサンプル文書で検索テストを 1 回行う |
| Rerank | 固定した候補テキストを並べ替え、結果が質問に合うかを確認する |
| 画像生成 | 単純なプロンプトでテスト画像を生成し、応答形式とサイズを確認する |

### 3. テスト環境を記録する

少なくとも次の項目を記録します。

* Cherry Studio のバージョン。
* プロバイダー。
* Model ID。
* エンドポイントの種類。
* テスト日。
* 成功した機能とパラメーター。

こうしておくと、プロバイダーがモデルを更新した後でも、「モデルの動作変更」と「ローカル設定の変更」を区別できます。

## モデルデータを手動で変更する

カタログ情報が不足している場合や、プロバイダーがカスタム ID を使う場合は、モデルを編集できます。

変更前の推奨手順：

1. 現在の Model ID、エンドポイント、機能を保存します。
2. 一度に 1 つのフィールドだけを変更します。
3. 対応する最小テストをすぐに実行します。
4. 失敗した場合は元の値に戻します。

{% hint style="warning" %}
モデルを特定のフィルターに表示するためだけに、機能をむやみに選択しないでください。誤った Embedding、Rerank、画像生成、ツール呼び出しのタグにより、互換性のないインターフェースへリクエストが送られる可能性があります。
{% endhint %}

## よくある質問

### プロバイダーのコンソールにはモデルがあるのに、Cherry Studio に表示されない

まずモデル一覧を取得します。それでも表示されない場合は、プロバイダーが示す正確な Model ID を使って手動追加してください。専用エンドポイント、地域、API バージョンが必要かどうかも確認します。

### 一覧にモデルがあるが、リクエストが 404 を返す

API Host、Model ID、地域、エンドポイントの不一致が主な原因です。一覧の表示名だけを見て、大文字と小文字を変えたり、バージョン接尾辞を削除したりしないでください。

### モデルタグと実際の機能が一致しない

まずプロバイダーの公式ドキュメントと実際のリクエストを基準にし、その後で機能タグを編集します。共通カタログの誤りであれば、[フィードバックと提案](../question-contact/suggestions.md)にプロバイダー、Model ID、公式ドキュメントへのリンク、テスト結果を添えて報告してください。

### 公称値までコンテキストを使えない

最大出力、画像、ファイル、ツール定義、履歴メッセージの使用量を確認してください。集約サービスがモデルメーカーより低い上限を設定している場合もあります。

### 価格が請求額と異なる

カタログの価格が古い、または現在の経路に適用されない可能性があります。その値を会計処理に使うのをやめ、現在のプロバイダーの価格ページと請求明細を確認してください。
