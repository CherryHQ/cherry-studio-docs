# Web 検索モード

Web 検索モードでは、モデルが回答する前に Web を検索したり、指定されたリンクを読み取ったりできます。ニュース、バージョン更新、料金、ポリシーなど、時間の経過とともに変わる可能性がある情報の確認に適しています。

これは「回答が自動的に最新であることを保証する」スイッチではありません。Cherry Studio は検索結果または Web ページの本文をモデルへ渡しますが、最終的な回答の正確性は、検索元、モデルのツール呼び出し能力、回答品質によって異なります。

{% hint style="info" %}
Web 検索モードを使用した場合でも、引用元を開き、公開日、原文の文脈、重要な数値を確認してください。医療、法律、金融などの高リスク情報について、モデルの要約だけに基づいて判断しないでください。
{% endhint %}

## 2 種類の Web 検索方法

Cherry Studio は、現在のモデルに応じて Web 検索方法を自動選択します。

| Web 検索方法 | 使用する場合 | 検索の実行元 | Web 検索プロバイダーの設定が必要か |
| --- | --- | --- | --- |
| モデルネイティブ Web 検索 | 現在のモデルとプロバイダーが組み込み Web 検索に対応している | モデルプロバイダー | 通常は不要 |
| Cherry Studio 外部 Web 検索 | 現在のモデルに利用可能なネイティブ Web 検索機能がない | Cherry Studio が設定済みの検索サービスと Web ページ読み取りサービスを呼び出す | デフォルト検索プロバイダーとデフォルト URL 取得プロバイダーの両方を選択する必要がある |

どちらもチャット入力欄の同じ Web 検索スイッチを使用しますが、課金、検索範囲、引用形式、利用可能なパラメーターが異なる場合があります。

### モデルネイティブ Web 検索

Cherry Studio は Web 検索パラメーターを現在のモデルプロバイダーへ渡し、プロバイダーが検索と結果の整理を実行します。利用できるかどうかは、次の条件によって異なります。

- 現在のモデルが Web 検索対応として認識されているか
- 現在のプロバイダーが対応するインターフェースを実装しているか
- アカウント、リージョン、モデルの権限
- プロバイダーの現在の API 規則

一部のモデルは、独自の Web 検索機能を強制的に使用します。たとえば一部の Sonar または OpenRouter Web 検索モデルは、外部検索プロバイダーを個別に設定していなくても検索を実行する場合があります。

### Cherry Studio 外部 Web 検索

現在のモデルがネイティブ Web 検索を使用しない場合、Cherry Studio はモデルへ次の 2 つのツールを提供します。

- **Web を検索**：キーワードから候補 Web ページを取得
- **URL を読み取る**：検索結果または会話内で指定されたリンクを開き、本文を抽出

モデルは、ツールを呼び出すタイミング、使用するキーワード、Web ページを続けて読み取るかどうかを自ら判断します。検索結果は、回答内で引用できる番号付きの参考情報として整理されます。

{% hint style="warning" %}
外部 Web 検索はモデルのツール呼び出し性能に依存します。スイッチを有効にしていても、モデルが検索しない、検索が不十分、または引用元を正しく示さない場合があります。
{% endhint %}

## 利用前の設定

ネイティブ Web 検索に対応するモデルだけを使用する場合は、[チャットで Web 検索を有効にする](#チャットで-web-検索を有効にする)まで読み飛ばせます。

通常のモデルで外部 Web 検索を使用するには、次を開きます。

```text
設定 → Web 検索
```

少なくとも次の 2 項目を設定します。

1. **デフォルト検索プロバイダー**を選択します。
2. **デフォルト URL 取得プロバイダー**を選択します。

この 2 つの役割は独立しています。

- 検索プロバイダーは、キーワードから Web ページを見つけます。
- URL 取得プロバイダーは、特定の Web ページの本文を読み取ります。

どちらかが未設定の場合、通常のモデルで Web 検索を有効にすると設定画面へ移動するよう案内されます。

## プロバイダーの選択

現在のバージョンには、次の Web 検索プロバイダーが組み込まれています。

| プロバイダー | キーワード検索 | URL の読み取り | 設定 |
| --- | :---: | :---: | --- |
| Zhipu | ✓ |  | Zhipu モデルプロバイダーの API Key を使用 |
| Tavily | ✓ |  | Tavily API Key が必要 |
| SearXNG | ✓ |  | セルフホストまたはアクセス可能な SearXNG インスタンスへ接続 |
| Exa | ✓ |  | Exa API Key が必要 |
| ExaMCP | ✓ |  | Exa MCP サービスを介して検索 |
| Bocha | ✓ |  | Bocha API Key が必要 |
| Querit | ✓ |  | Querit API Key が必要 |
| Fetch |  | ✓ | Cherry Studio 組み込みの URL 取得サービス |
| Jina | ✓ | ✓ | 検索と Web ページ読み取りの両方に使用可能 |

プロバイダーのプラン、クォータ、利用可能なリージョンは変更される場合があります。各プロバイダーの公式サイトで最新情報を確認してください。すぐに開始する場合は、[無料 Web 検索モード](./mian-fei-lian-wang-mo-shi.md)も参照してください。

### API プロバイダーの設定

1. **設定 → Web 検索**で対象のプロバイダーを開きます。
2. API Key を入力します。
3. プロキシ、プライベートデプロイ、互換ゲートウェイを使用する場合は、必要に応じて API アドレスを変更します。
4. **検出**をクリックします。
5. 検証に成功したら、対応するデフォルトプロバイダーとして設定します。

一部のプロバイダーでは複数の API Key を入力できます。実行時にローテーションできますが、各 Key は自分が利用権を持つアカウントから取得してください。キーをプロンプト、スクリーンショット、公開ドキュメントに記載しないでください。

### SearXNG の設定

SearXNG には、Cherry Studio を実行しているコンピューターからアクセスできるインスタンスのアドレスが必要です。デフォルトアドレス：

```text
http://localhost:8080
```

SearXNG が別のコンピューター、NAS、Docker コンテナ、インターネット上のサーバーで動作している場合は、実際にアクセスできるアドレスを入力してください。インスタンスで Basic Auth が有効になっている場合は、ユーザー名とパスワードも入力する必要があります。

詳細な手順については、[SearXNG の設定](searxng.md)を参照してください。

### Zhipu API Key

Zhipu Web 検索では、Zhipu モデルプロバイダーに保存された API Key を使用します。まず**設定 → モデルサービス**で Zhipu の設定を完了し、次に**設定 → Web 検索**へ戻って Zhipu を選択し、検出を実行します。

## 検索結果の設定

### 検索結果数

**検索結果数**は `1–100` に設定でき、デフォルト値は `5` です。

結果数を増やすと通常は対象範囲が広がりますが、次の影響もあります。

- レスポンス時間が増加する
- コンテキストの使用量が増える
- Token の消費量が増える
- 重複または関連性の低い情報源が増える

通常の質問ではデフォルト値から開始してください。複数の情報源を比較する必要がある場合に限り、段階的に増やします。

### 検索結果の圧縮

次の方法を選択できます。

| 圧縮方法 | 動作 | 用途 |
| --- | --- | --- |
| 圧縮しない | プロバイダーが返した本文を保持 | 結果数が少なく、原文の文脈がより多く必要 |
| 切り詰め | 設定した上限に従って各結果の本文を短縮 | 結果数が多く、コンテキスト消費を抑えたい |

**切り詰め**を有効にした場合は、切り詰める長さを入力する必要があります。短すぎると重要な文脈が失われ、長すぎると Token を効果的に制限できません。まずデフォルト値を使用し、回答に不足があるかどうかに応じて調整してください。

### ブラックリスト

ブラックリストは、外部検索結果がモデルへ渡される前に、一致するドメインを除外します。コンテンツファーム、ミラーサイト、使用したくない Web サイトのブロックに適しています。

ルール形式とサブスクリプションの設定については、[Web 検索ブラックリスト](blacklist.md)を参照してください。

{% hint style="info" %}
モデルネイティブ Web 検索はモデルプロバイダーによって実行されます。ブラックリストが有効になるか、いくつの除外規則に対応するかはプロバイダーの実装次第であり、外部 Web 検索と完全に同じだとは限りません。
{% endhint %}

## チャットで Web 検索を有効にする

1. チャットを開きます。
2. 使用するモデルを選択します。
3. 入力欄の下にある**地球**アイコンをクリックします。
4. アイコンが強調表示されたら質問を送信します。

Web 検索の状態は、現在のアシスタントに保存されます。モデルを切り替えると、Cherry Studio は新しいモデルに応じて、ネイティブ Web 検索と外部 Web 検索のどちらを使用するかを再判定します。

Web 検索に適した質問例：

```text
Cherry Studio の直近の正式リリースの更新内容を調べ、公式リリースページを引用してください。
```

```text
この 3 つの製品の現在の公式料金を比較し、それぞれの公式サイトだけを情報源として使用してください。
```

```text
このリンクを読み、主な結論を要約して、記事の公開日と著者を示してください。
```

より信頼できる結果を得るには、質問で次の点を指定することをおすすめします。

- 対象期間
- 優先する情報源
- フォーラムやまとめサイトを除外するか
- 項目ごとの引用が必要か
- 確認するフィールド（バージョン番号、料金、公開日など）

## 引用の表示と確認

外部 Web 検索では、検索結果が番号付きの参考資料として整理され、モデルには `[1]`、`[2]` などの形式で引用するよう指示されます。モデルネイティブ Web 検索の引用形式は、各プロバイダーによって決まります。

回答を受け取った後、少なくとも次の点を確認してください。

1. 引用元を開けるか
2. ページタイトルと回答の主題が一致しているか
3. 原文が実際に該当する結論を裏付けているか
4. 公開日が質問の対象期間を満たしているか
5. 情報源の間に矛盾がないか

検索結果が空でも、関連情報が Web 上に存在しないとは限りません。キーワード、サービスのクォータ、ネットワーク、ブラックリスト、Web サイトのボット対策が原因の場合もあります。

## 既知の互換性制限

### 古い Gemini モデルと MCP

古い Gemini モデルでは、関数ツールモードでモデル組み込み Web 検索と有効な MCP を同時に使用できません。競合が発生した場合、Cherry Studio は Web 検索を無効にして通知を表示します。

次の方法を試してください。

- MCP を一時的に無効にする
- この組み合わせに対応する新しいモデルへ切り替える
- 別の Web 検索対応モデルを使用する

### GPT-5 シリーズの minimal 思考強度

GPT-5 シリーズの推論モデルで `minimal` の思考強度を使用すると、OpenAI Web 検索を有効にできません。Cherry Studio は Web 検索を無効にして通知を表示します。

思考強度を上げて再試行するか、別の Web 検索方法を選択してください。

## プライバシーと料金

Web 検索を有効にすると、検索キーワード、読み取る URL、必要な会話の文脈が、モデルプロバイダー、検索プロバイダー、Web サーバーへ送信される場合があります。

使用前に次の点を確認してください。

- 検索語にパスワード、API Key、個人識別情報、社内機密を含めない
- 対象サービスが組織のデータコンプライアンス要件を満たしている
- 検索、モデル呼び出し、ネットワークトラフィックの料金規則
- Web ページには誤情報やモデルを対象とした悪意ある指示が含まれる場合がある

{% hint style="danger" %}
Web ページの内容は信頼できない入力です。Web ページまたはモデルの回答に要求されても、キーの貼り付け、不明なコマンドの実行、不審なファイルのダウンロード、セキュリティ設定の変更を行わないでください。
{% endhint %}

## よくある問題

### Web 検索アイコンをクリックすると設定画面へ移動する

現在のモデルがネイティブ Web 検索を使用しておらず、**デフォルト検索プロバイダー**または**デフォルト URL 取得プロバイダー**が選択されていません。両方を設定してから再試行してください。

### プロバイダーの検出に失敗する

次の順序で確認します。

1. API Key が完全で有効であり、利用可能なクォータがあるか
2. API アドレスが Web コンソールではなく、インターフェースのアドレスであるか
3. プロキシ、ファイアウォール、DNS がアクセスを許可しているか
4. セルフホストサービスが起動し、正しいアドレスで待ち受けているか
5. システム時刻が正確か
6. プロバイダーのステータスページで障害が報告されていないか

### Web 検索を有効にしたが回答に引用がない

考えられる原因：

- モデルが検索ツールを呼び出していない
- モデルネイティブ Web 検索が表示可能な引用を返していない
- 検索結果が空または関連性が低い
- モデルが引用指示に従っていない
- 現在の質問に Web 検索が不要で、モデルが直接回答した

「必ず検索し、情報源を項目ごとに引用する」と明示するか、ツール呼び出しがより安定したモデルへ変更してください。

### 検索結果が長すぎる、または回答が遅くなる

**検索結果数**を減らすか、**切り詰め**を有効にして切り詰める長さを段階的に短くしてください。結果数と切り詰める長さを同時に大きくしないでください。
