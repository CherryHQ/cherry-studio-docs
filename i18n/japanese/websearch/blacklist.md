# Web 検索ブラックリスト

Web 検索ブラックリストは、コンテンツファーム、ミラーサイト、低品質なまとめページ、業務に関係のないサイトなど、モデルのコンテキストへ入れたくない Web ページを除外する機能です。

ブラックリストルールが保存される場所は以下の通りです。

```text
設定 → Web 検索 → ブラックリスト
```

{% hint style="info" %}
ブラックリストは主に不要な情報源を減らすためのものであり、ファクトチェックやセキュリティフィルターではありません。ブロックされなかったサイトには、誤り、古い情報、または悪意のあるコンテンツが含まれている可能性があります。
{% endhint %}

## ブラックリストの仕組み

Cherry Studio の外部 Web 検索の場合、サービスプロバイダーが結果を返した後、アプリケーションが再度ブラックリストに基づいて URL をフィルタリングし、一致した結果はモデルに渡されません。

モデルネイティブ Web 検索の場合、ブラックリストのサポートレベルはモデルのサービスプロバイダーによって異なります。

- Anthropic のネイティブ検索では、変換されたブロックドメインを受信します。
- xAI のネイティブ検索では、最大で最初の `5` 個の変換されたドメインを受信します。
- その他のネイティブ Web 検索サービスは、ブラックリストをサポートしていないか、使用しない場合があります。

同じルールセットが、すべてのモデルとプロバイダーでまったく同じように機能するとは限りません。

## ルールの追加方法

1. **設定 → Web 検索** を開きます。
2. **ブラックリスト** を探します。
3. 1 行につき 1 つのルールを入力します。
4. **保存** をクリックします。
5. 「無効なエントリ」の警告が表示されないことを確認します。
6. 新しい Web 検索対話を開始するか、既存のものを続けて検証を行います。

入力欄の横にある数字は、現在保存されているルール数です。

{% hint style="warning" %}
無効なルールが 1 つでもあると、ブラックリスト全体が保存されません。すべての無効なエントリを修正してから、もう一度「保存」をクリックしてください。
{% endhint %}

## 対応する 2 つの形式

### マッチパターン

マッチパターンは、プロトコル、ドメイン名、サブドメイン、パスに基づいてサイトをブロックするのに適しています。

一般的な例：

```text
*://*.example.com/*
```

`example.com` およびそのすべてのサブドメインの HTTP および HTTPS ページをブロックします。

```text
https://example.com/private/*
```

`https://example.com/private/` 以下にあるページのみをブロックします。

```text
*://news.example.com/archive/*
```

指定されたサブドメインの `archive` パスのみをブロックします。

マッチパターンの構造は以下の通りです：

```text
プロトコル://ホスト/パス
```

| 部分 | 例 | 説明 |
| --- | --- | --- |
| プロトコル | `https`、`http`、`*` | ここでの `*` は HTTP と HTTPS にマッチします |
| ホスト | `example.com`、`*.example.com`、`*` | `*.example.com` はルートドメインとサブドメインの両方にマッチします |
| パス | `/*`、`/news/*` | 必ず `/` から始まり、`*` を使用できます |

完全なルール説明については、[MDN マッチパターン](https://developer.mozilla.org/zh-CN/docs/Mozilla/Add-ons/WebExtensions/Match_patterns)を参照してください。

{% hint style="warning" %}
単に `example.com` とだけ入力しないでください。純粋なドメイン名は有効なマッチパターンではないため、`*://*.example.com/*` のように記述する必要があります。
{% endhint %}

### 正規表現

より詳細な URL マッチングが必要な場合は、正規表現を使用できます。ルールは `/` で始まり、`/` で終わる必要があります：

```text
/example\.(com|org)/
```

```text
/example\.com\/(ads|sponsored)\//
```

Cherry Studio は大文字小文字を区別せず、「プロトコル + ドメイン + パス + クエリパラメータ」全体に対してルールをテストします。

正規表現は次の用途に適しています：

- 複数のトップレベルドメインに同時にマッチさせたい場合。
- 特定のパスセグメントを含むページをブロックしたい場合。
- URL のクエリパラメータに基づいて結果を除外したい場合。
- 通常のマッチパターンでは表現しにくいルール。

構文については、[MDN 正規表現ガイド](https://developer.mozilla.org/zh-CN/docs/Web/JavaScript/Guide/Regular_expressions)を参照してください。

{% hint style="danger" %}
範囲が広すぎる正規表現は、多数の結果を誤ってブロックする可能性があります。出所が不明で、内容を理解できない複雑な式をコピーしないでください。
{% endhint %}

## コピー可能な例

以下のルールは必要に応じて修正できます：

```text
*://*.example.com/*
*://mirror.example.org/*
https://news.example.net/archive/*
/example\.io\/sponsored/
```

各ルールは独立した行に記述し、空の行は無視されます。

### ドメインとそのすべてのサブドメインをブロックする

```text
*://*.example.com/*
```

以下にマッチします：

```text
https://example.com/article
https://www.example.com/article
http://docs.example.com/guide
```

### 特定のパスのみをブロックする

```text
https://example.com/ads/*
```

以下をブロックします：

```text
https://example.com/ads/page-1
```

以下はブロックしません：

```text
https://example.com/blog/page-1
```

### 複数の類似ドメインを同時にブロックする

```text
/example\.(com|net|org)/
```

固定した 3 つのサイトだけを対象にする場合は、通常のマッチパターンを 3 行に分けた方が管理しやすくなります。

## サポートされていない旧機能

現在の V2 ブラックリストページでは、手動でのルール入力のみをサポートしており、以下の機能は提供されていません：

- ブラウザのツールバーから直接サイトをブロックすること。
- 購読 URL を入力して自動的にルールをダウンロードすること。
- uBlacklist の購読の自動更新。
- ブラウザ拡張機能の完全な設定のインポート。

旧ドキュメントにある購読元テーブルやスクリーンショットは、現在のインターフェースでは適用されません。

公開ルールセットを使用する必要がある場合は、まず内容を確認し、Cherry Studio が対応するマッチパターンまたは正規表現へ手動で変換してください。何千件ものルールをそのまま貼り付けないでください。ルールが多すぎると保守が難しくなり、正常な情報源を誤ってブロックする危険も増えます。

## ルールの検証

保存後は、結果を確認しやすい質問でテストできます：

```text
example.com 上にある Cherry Studio に関する内容を検索し、引用元をリストアップしてください。
```

`example.com` をブロックしている場合、外部 Web 検索の回答にそのドメインの結果は表示されません。

検証時の注意点：

1. 現在使用しているモデルが外部 Web 検索か、モデルネイティブ Web 検索かを確認します。
2. タイトルだけでなく、引用された最終 URL を確認します。
3. ウェブページがリダイレクトされた場合、別のドメインになる可能性があることに注意してください。
4. 新しいルールは、履歴メッセージにすでに書き込まれた古い引用を削除しません。
5. ネイティブ Web 検索のプロバイダーによっては、一部のルールが無視される場合があります。

## よくある質問

### 「無効なエントリ」という警告が表示される場合

一般的な誤り：

| 間違った記述 | 問題点 | 推奨される記述 |
| --- | --- | --- |
| `example.com` | プロトコルとパスが不足している | `*://*.example.com/*` |
| `https://example.com` | パスが不足している | `https://example.com/*` |
| `*.example.com` | 完全なマッチパターンではない | `*://*.example.com/*` |
| `/[example/` | 正規表現の構文が無効 | 括弧または文字グループを修正する |
| `# example` | コメント行はサポートされていない | この行を削除する |

すべての無効なエントリを修正してから、再度保存してください。

### 保存後もブロックされたサイトが見える場合

考えられる原因：

- 現在のモデルがネイティブ Web 検索を使用しており、サービスプロバイダーがブラックリストを適用していない。
- ルールがルートドメインのみにマッチし、実際のサブドメインにはマッチしていない。
- ルールが HTTPS のみにマッチし、結果が HTTP を使用している。
- パス指定が狭すぎる。
- 引用が、ルール保存前の履歴の回答から来ている。
- ページがリダイレクトを起こした。
- モデルが検索を行わずに、既存の知識に基づいてそのサイトに言及した場合。

まず `*://*.example.com/*` のような完全なルールでテストし、その後徐々に範囲を狭めてください。

### すべての検索結果が消えた場合

以下のパターンを誤って使用していないか確認してください：

```text
<all_urls>
```

このパターンはすべての HTTP および HTTPS URL にマッチします。これを削除して保存してください。

また、正規表現が広すぎる可能性も確認してください。例：

```text
/.*/
```

### デフォルトの状態に戻したい場合

ブラックリストの入力欄を空にして、**保存**をクリックします。件数が `0` になると、外部 Web 検索ではカスタムルールによる結果の除外が行われなくなります。

## 使用上のアドバイス

- ドメイン名でのブロックを優先し、複雑なシナリオでのみ正規表現を使用します。
- 少数の明確なルールから始めるようにしてください。
- 定期的に無効になった、または重複したルールを削除してください。
- ブロックする前に、サイト全体ではなく一部のページだけが低品質ではないか確認してください。
- 重要な結論については、複数の独立した情報源からの裏付けを要求するようにしてください。
- ブラックリストで引用の目視確認を代替しないでください。
