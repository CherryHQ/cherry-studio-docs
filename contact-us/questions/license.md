# Cherry Studio 开源许可协议

Cherry Studio 社区版代码仓库采用 **GNU Affero General Public License v3.0（AGPL-3.0）**。

请以以下法律原文为准：

* [Cherry Studio 仓库中的 LICENSE](https://github.com/CherryHQ/cherry-studio/blob/main/LICENSE)
* [GNU AGPL v3.0 官方文本](https://www.gnu.org/licenses/agpl-3.0.html)

{% hint style="warning" %}
本页用于帮助理解，不是法律意见，也不会修改或替代 AGPL-3.0。实际义务取决于使用、修改、分发和网络提供方式；有疑问时应让组织的法律顾问审查。

## 先理解三个结论

1. **开源不等于禁止商业使用。** Cherry Studio 官方仓库明确允许在完整遵守 AGPL-3.0 的前提下商业使用社区版。
2. **商业使用不等于可以闭源。** 修改、分发或通过网络向他人提供功能时，可能触发许可证中的源代码、许可声明和网络交互义务。
3. **需要豁免 AGPL-3.0 要求时，应申请商业许可。** 商业许可属于另一份协议，不会由本页自动授予。

## AGPL-3.0 允许什么

在遵守许可证的前提下，AGPL-3.0 允许：

* 运行软件。
* 阅读和研究源代码。
* 修改软件。
* 复制和再分发原版或修改版。
* 对软件收费或在商业环境中使用。

“免费软件”描述的是使用、研究、修改和分享的自由，不表示所有服务、部署或支持都必须免费。

## 什么时候需要重点检查义务

| 场景 | 需要重点阅读的内容 |
| :--- | :--- |
| 仅在自己的设备上运行官方版本 | LICENSE 全文、第三方组件许可、免责声明 |
| 修改后在组织内部使用 | 修改范围、谁能访问、是否发生分发或远程网络交互 |
| 向客户或其他主体分发安装包 | AGPL 第 4–6 节的声明、许可文本和 Corresponding Source 要求 |
| 分发修改版 | 修改声明、同许可证授权、Corresponding Source |
| 让用户通过网络与修改版交互 | AGPL 第 13 节关于向远程用户提供 Corresponding Source 的要求 |
| 集成到闭源产品或服务 | 作品边界、组合方式、依赖关系及是否需要商业许可 |

{% hint style="info" %}
“内部使用”“网络服务”“插件”“独立进程”或“仅修改少量代码”等说法，本身不足以得出合规结论。应结合实际架构、交付对象和适用法律判断。
{% endhint %}

## 分发软件时的常见义务

分发 Cherry Studio 或其修改版时，通常需要关注：

* 保留适用的版权和许可声明。
* 向接收者提供 AGPL-3.0 许可文本。
* 明确标记自己修改过的版本及相关日期。
* 以 AGPL-3.0 授权受覆盖的完整作品。
* 按许可证允许的方式提供对应源代码。
* 不施加与 AGPL-3.0 冲突的额外限制。
* 不通过技术措施阻止接收者行使许可证授予的权利。

具体要求和提供源代码的方式，以 LICENSE 第 4–7 节原文为准。

## 通过网络提供修改版

AGPL-3.0 与 GPL v3 的重要差异之一是远程网络交互。

如果你修改了程序，并让用户通过计算机网络远程与该修改版交互，而该版本支持这种交互，AGPL 第 13 节要求向这些用户显著提供获取该版本 **Corresponding Source** 的机会。获取方式应通过网络服务器免费提供，并使用标准或惯常的复制方式。

这项要求不应简化为“所有服务器代码都必须公开”，也不能简化为“只要不分发安装包就没有义务”。需要判断哪些代码构成受许可证覆盖的作品及其对应源代码。

## 什么是 Corresponding Source

Corresponding Source 不是任意上传一个源码压缩包。许可证将其定义为修改该作品所需的首选源代码形式，通常还可能包括：

* 构建、安装和运行对象代码所需的源代码。
* 控制这些操作的脚本。
* 该作品专门依赖的接口定义和相关源代码。
* 你对受覆盖作品所做的修改。

系统库、通用工具和能够从其他源代码自动重新生成的部分，可能按许可证定义排除。应根据实际构建与交付方式核对。

## 第三方组件和内容

Cherry Studio 仓库和安装包可能包含不同许可证下的依赖、字体、图标、模型信息或其他资源。

AGPL-3.0 适用于 Cherry Studio 受其覆盖的代码，不会自动把第三方组件的独立许可证替换为 AGPL-3.0。再分发前应同时检查：

* 仓库和安装包附带的第三方声明。
* 依赖自身的许可证与 NOTICE 要求。
* 商标、Logo、图片、字体和数据集的单独授权。
* 你新增的代码和资源是否有权再分发。

## 商标与品牌

软件许可证不等于 Cherry Studio 名称、Logo 或其他品牌资产的商标授权。

如果计划发布衍生产品、重新包装安装包、对外宣传合作关系或使用官方品牌素材，应先确认品牌使用范围，不应让用户误以为衍生版本由 Cherry Studio 官方发布或担保。

## 无担保与责任限制

AGPL-3.0 第 15–17 节包含无担保和责任限制条款。法律允许的范围内，软件按现状提供，质量、性能和适用性风险由使用者承担。

如果组织需要服务等级、赔偿、专门支持或其他保证，应通过单独的商业合同确认，而不是从开源许可证中推定。
