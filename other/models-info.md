# 模型数据

Cherry Studio V2 不再依赖文档中的静态模型大表。模型版本、上下文、价格和服务商能力变化很快，长期手工维护会让过期信息看起来像确定事实。

本页改为说明应用中的模型数据来自哪里、每个字段表示什么，以及如何判断当前服务商上的模型是否真的可用。

{% hint style="info" %}
应用中显示的模型信息用于配置和路由。模型服务商的官方文档、控制台权限与实际 API 响应，才是可用性、限制和计费的最终依据。
{% endhint %}

## 模型数据来自哪里

V2 会把多类数据合并成最终显示的模型：

1. **模型目录**：提供通用名称、能力、输入输出类型、上下文、参数和价格等基础资料。
2. **服务商覆盖信息**：描述某个服务商上的端点、特殊限制、别名或替代模型。
3. **服务商模型列表**：部分服务商可以通过 API 返回当前账户可见的 Model ID。
4. **用户配置**：手动添加的模型、名称、能力标签、端点和限制等自定义信息。

合并优先级以用户配置最高，其次是服务商覆盖信息，最后是通用模型目录。

服务商 API 只返回 Model ID 时，Cherry Studio 会尝试用目录补全资料；目录中找不到的 ID 仍可作为自定义模型加入，但字段可能不完整。

## 在哪里查看

打开**设置 → 模型服务**并选择一个服务商。模型列表可以：

* 搜索模型名称或 ID。
* 按能力筛选。
* 启用或停用单个模型。
* 批量启用当前筛选结果。
* 打开模型编辑面板查看或修改部分字段。
* 手动添加服务商没有自动列出的模型。

只有已启用模型会出现在多数模型选择器中。停用模型不会删除其配置。

模型服务商的完整配置流程见[模型服务](../pre-basic/providers/)。

## 常见字段

### 显示名称与 Model ID

| 字段 | 作用 |
| :--- | :--- |
| 显示名称 | Cherry Studio 界面中显示的名称，可以与 API ID 不同 |
| Model ID | 请求服务商 API 时使用的真实模型标识 |
| 服务商 | 负责认证、端点和请求路由的配置 |
| 分组 | 只用于整理模型列表，不改变 API 行为 |

同一个 Model ID 可以存在于多个服务商下。应用内部会把服务商与 Model ID 组合成唯一标识，但手动添加模型时通常应填写服务商文档给出的 API Model ID，不要自行添加应用内部前缀。

### 端点类型

端点类型决定请求格式。V2 支持的模型端点包括：

* OpenAI Chat Completions
* OpenAI Responses
* Anthropic Messages
* Google Generate Content
* OpenAI Image Generation
* Jina Rerank

模型名字相同，不代表每个服务商都支持相同端点。端点选错时，常见表现是 `400`、`404`、工具参数无效或返回结构无法解析。

### 上下文与输出限制

| 字段 | 含义 |
| :--- | :--- |
| 上下文窗口 | 一次请求可处理的整体 Token 规模 |
| 最大输入 | 服务商允许的输入 Token 上限 |
| 最大输出 | 一次生成允许的输出 Token 上限 |

这些值不是简单相加规则。服务商还可能为图片、工具定义、缓存、推理 Token 或特定套餐设置单独限制。

不要把文档中的 `k` 或 `M` 简写直接当成精确可用值。需要设置数值时，使用服务商当前 API 文档给出的整数，并通过最小请求验证。

### 输入与输出类型

模型可以分别声明支持的输入和输出：

* 文本
* 图片
* 音频
* 视频

“可以理解图片”与“可以生成图片”是两种能力；支持音频输入也不代表可以生成语音。

### 能力标签

模型列表可能显示以下能力：

| 能力 | 说明 |
| :--- | :--- |
| 视觉理解 | 接收图片并生成文本结果 |
| 图片生成 | 生成或编辑图片 |
| 音频理解 | 接收或识别音频 |
| 音频生成 | 生成音频或语音 |
| 视频理解 | 接收并理解视频 |
| 视频生成 | 生成视频 |
| 推理 | 支持推理强度或思考相关配置 |
| 工具调用 | 生成结构化函数或工具调用 |
| 原生联网 | 由模型或服务商端点提供搜索能力 |
| Embedding | 生成向量，用于知识库索引和检索 |
| Rerank | 对候选文本重新排序 |

能力标签会影响模型筛选、界面控件和请求路由。手动勾选标签只会告诉 Cherry Studio 如何使用模型，**不会为服务商模型增加真实能力**。

### 参数支持

不同模型可能支持不同参数，例如：

* Temperature
* Top P
* Top K
* Frequency Penalty
* Presence Penalty
* Max Tokens
* Stop Sequences
* System Message

推理模型可能忽略或拒绝部分传统采样参数。遇到 `unsupported parameter` 时，先恢复默认设置，再按该模型当前官方文档逐项启用。

### 推理配置

推理模型还可能包含：

* 推理类型。
* 可用的推理强度。
* 思考 Token 最小值、最大值和默认值。
* 是否支持交错思考。

实际可用值同时受模型、端点和服务商实现影响。同一个模型经 OpenAI 兼容端点与 Anthropic Messages 端点调用时，参数格式可能不同。

### 价格

目录可以保存输入、输出、缓存、图片或音视频价格，但该信息只适合估算：

* 服务商可能随时调整价格。
* 不同地区、套餐和渠道可能不同。
* 推理、缓存、批处理和工具调用可能单独计费。
* 第三方中转服务可能使用自己的计价方式。

付款和成本核对应以服务商账单为准。

## 为什么同名模型显示不同信息

常见原因包括：

* 服务商映射到不同快照或别名。
* 端点类型不同。
* 当前账户只开通部分能力。
* 服务商限制了上下文或输出长度。
* 聚合服务使用自己的 Model ID 和价格。
* 本地模型的量化、模板或运行参数不同。
* 用户曾手动修改能力或限制字段。

比较模型时，应同时记录**服务商、Model ID、端点和日期**，不能只比较显示名称。

## 自动获取模型列表的边界

“获取模型列表成功”只说明服务商返回了一组模型 ID，不代表：

* 当前 API Key 一定有调用权限。
* 模型支持图片、工具、推理或联网。
* 上下文和价格信息完整。
* 该模型适用于所有端点。
* 服务商不会在之后下线或改名。

获取列表后，应启用需要的模型并执行一次真实请求。

## 如何验证一个模型

### 1. 基础连接

在服务商设置中检查 API Host 和凭据，再执行连接检查。连接检查通过后，用一条短文本完成真实对话。

### 2. 只测试需要的能力

| 目标能力 | 最小测试 |
| :--- | :--- |
| 视觉理解 | 上传一张无敏感信息的图片，要求描述一个明确元素 |
| 工具调用 | 绑定一个无副作用工具，要求读取固定信息 |
| 推理 | 使用可人工核对的多步问题，并观察参数是否被接受 |
| 原生联网 | 询问一个刚更新且可查证的信息，检查真实搜索记录与引用 |
| Embedding | 获取维度并用小样本文档完成一次召回测试 |
| Rerank | 对一组固定候选文本排序，检查结果是否符合问题 |
| 图片生成 | 使用简单提示生成测试图，检查返回格式和尺寸 |

### 3. 记录测试环境

至少记录：

* Cherry Studio 版本。
* 服务商。
* Model ID。
* 端点类型。
* 测试日期。
* 成功的能力与参数。

这样在服务商升级模型后，可以区分“模型行为变化”和“本地配置变化”。

## 手动修改模型数据

目录信息缺失或服务商使用自定义 ID 时，可以编辑模型。

修改前建议：

1. 先保存当前 Model ID、端点和能力。
2. 只修改一个字段。
3. 立即执行对应的最小测试。
4. 失败时恢复原值。

{% hint style="warning" %}
不要为了让模型出现在某个筛选器中而盲目勾选能力。错误的 Embedding、Rerank、图片生成或工具调用标签，可能把请求发送到不兼容的接口。
{% endhint %}

## 常见问题

### 服务商控制台有模型，Cherry Studio 没显示

先尝试获取模型列表；仍未出现时，按服务商提供的准确 Model ID 手动添加。检查该模型是否需要专用端点、区域或 API 版本。

### 列表中有模型，但请求返回 404

常见原因是 API Host、Model ID、区域或端点不匹配。不要仅凭列表名称修改大小写或删除版本后缀。

### 模型标签与实际能力不符

先以服务商官方文档和真实请求为准，再编辑能力标签。如果是公共目录错误，可按[反馈与建议](../question-contact/suggestions.md)提供服务商、Model ID、官方文档链接和测试结果。

### 上下文没有达到标称值

检查最大输出、图片、文件、工具定义和历史消息占用。聚合服务也可能使用比模型厂商更低的上限。

### 价格与账单不同

目录价格可能过期或不适用于当前渠道。停止用该值做财务结算，并改查当前服务商的价格页和账单明细。
