# 知识库数据

本页说明 Cherry Studio 把知识库数据存在哪里、哪些内容可能发送给模型服务商，以及如何安全地删除、备份和迁移。

如果只想创建和使用知识库，请先阅读[知识库教程](knowledge-base.md)。

## 知识库保存了什么

V2 的知识库数据不是一个可以单独复制的文件，而是由几类数据共同组成。

| 数据 | 主要内容 | 用途 |
| --- | --- | --- |
| 知识库元数据 | 名称、分组、模型、分块和检索配置 | 让应用识别并管理知识库 |
| 数据源记录 | 原始路径或网址、类型、状态和错误信息 | 追踪导入内容与处理进度 |
| 向量索引 | 文档片段、向量和检索字段 | 执行召回测试与聊天检索 |
| 文件记录与处理产物 | 原始文件引用、解析后的文本等 | 预览来源、重新索引和文档处理 |

元数据与数据源记录保存在 Cherry Studio 的主 SQLite 数据库中。每个知识库还有独立的本地向量存储文件。

{% hint style="warning" %}
不要只复制某个知识库的向量文件作为备份。向量文件必须与主数据库中的知识库 ID、数据源记录和模型配置保持一致，单独恢复通常无法得到完整知识库。
{% endhint %}

## 本地文件是否会被复制

从知识库添加本地文件时，Cherry Studio 会记录该文件的**原始绝对路径**，并通过文件记录关联它。原文件仍保留在原来的位置，不会因为加入知识库而被移动。

这会带来几个直接影响：

* 移动、重命名或删除原文件后，预览和重新索引可能失败
* 已建立的向量索引不会自动跟随原文件更新
* 修改原文件后，需要在知识库中手动执行重新索引
* 备份 Cherry Studio 数据时，外部原文件仍需要单独备份

文件处理器生成的中间产物可能由 Cherry Studio 保存在自己的数据目录中，但它们不能替代原文件的长期备份。

## 数据存储位置

知识库数据位于 Cherry Studio 的用户数据目录。默认位置通常为：

| 系统 | 默认用户数据目录 |
| --- | --- |
| macOS | `~/Library/Application Support/CherryStudio` |
| Windows | `%APPDATA%\CherryStudio` |
| Linux | `~/.config/CherryStudio` |

实际目录可能因安装方式、应用版本、开发环境或自定义数据目录而不同。应以 **设置 → 数据 → 数据目录** 中显示的当前路径为准。

V2 中与知识库直接相关的典型内容包括：

* 用户数据目录根部的 `cherrystudio.sqlite`：知识库与数据源元数据
* `Data/KnowledgeBase`：按知识库保存的向量存储文件
* `Data/Files`：Cherry Studio 管理的文件和处理产物

{% hint style="info" %}
这些内部路径用于理解备份范围，不建议在应用运行时手动修改文件。需要调整整个数据目录时，请参考[修改存储位置](../pre-basic/personalization-settings/storage.md)。
{% endhint %}

## 哪些内容会离开本机

“知识库存储在本地”不等于“整个处理过程都在本地”。是否向外部服务发送内容，取决于你选择的处理器和模型。

### 文档处理

如果使用在线文档解析或 OCR 服务，原文件或其内容可能会发送给对应服务商。使用本地处理器时，这一步可以留在本机。

### 建立索引

使用在线嵌入模型时，切分后的文本片段会发送给嵌入服务商，返回的向量保存在本地。重新索引也会再次调用嵌入服务。

### 检索与重排序

查询知识库时，用户问题会由嵌入模型处理。如果启用了在线重排序模型，问题和候选片段还会发送给重排序服务商。

### 生成回答

在对话中使用知识库时，用户问题和召回到的相关片段会作为上下文发送给当前聊天模型。

### 导入网页

导入网址或 Sitemap 时，Cherry Studio 会访问目标网站。目标服务器可能记录 IP、访问时间和请求信息。

{% hint style="warning" %}
处理合同、医疗、内部代码等敏感资料前，应同时检查文档处理、嵌入、重排序和聊天模型四个环节。只把聊天模型换成本地模型，并不能保证其他环节没有出站请求。
{% endhint %}

## 降低数据外发

如果资料不能发送给第三方，可以：

1. 使用本地文档解析和 OCR 能力。
2. 通过 Ollama、LM Studio 等方式运行本地嵌入模型。
3. 不启用在线重排序模型，或改用本地服务。
4. 在聊天阶段选择本地模型。
5. 避免直接导入需要身份验证的内部网页。

本地模型的配置方法请参考[嵌入模型](emb-models-info.md)和相应的模型服务教程。

## 删除数据会发生什么

### 删除一个数据源

删除数据源时，Cherry Studio 会清理该数据源的记录和向量片段。对于文件夹或 Sitemap，展开得到的子项也会一并处理。

删除知识库中的文件数据源**不会删除磁盘上的原文件**。

### 删除一个分块

在分块详情中删除单个片段，只会移除该片段的检索数据，不会修改原文件。之后重新索引该数据源时，被删除的片段可能根据当前分块规则再次生成。

### 删除整个知识库

删除知识库时，Cherry Studio 会先停止相关后台任务，再删除该知识库的向量存储和主数据库记录。

此操作不会删除你导入时引用的外部原文件，但会移除知识库配置和已经建立的索引。删除前应确认有可恢复的完整备份。

## 备份知识库

### 推荐方式

1. 在 **设置 → 数据** 中使用内置备份功能。
2. 如果目标是完整恢复知识库，不要启用**跳过文件数据**。
3. 单独备份所有外部原文件和文件夹。
4. 记录所使用的模型服务、嵌入模型和文档处理器。
5. 定期在安全环境中验证备份能否恢复。

内置备份中的“跳过文件数据”会跳过用户数据目录下的 `Data` 内容，其中包含知识库向量文件和 Cherry Studio 管理的处理产物，因此不适合作为完整知识库备份。

### 复制整个数据目录

如需制作文件级快照，应先完全退出 Cherry Studio，再复制**整个用户数据目录**，而不是只复制 `Data/KnowledgeBase`。

应用运行时，SQLite 数据库和向量文件可能正在写入。直接复制活动文件可能得到不一致的快照。

### 恢复后检查

恢复完成后，不要只检查知识库名称是否出现，还应：

* 打开数据源列表，确认状态与数量
* 预览几份资料
* 使用固定问题运行召回测试
* 在对话中核对引用来源
* 对需要更新的外部文件执行重新索引

跨系统、跨大版本或更换嵌入模型后，建议先在副本环境中验证。外部文件路径在不同设备上发生变化时，原路径引用可能失效。

## 迁移与磁盘空间

知识库占用空间主要取决于：

* 原始资料与处理产物的大小
* 分块数量
* 嵌入向量维度
* 知识库数量
* 多次导入和重新索引产生的数据

需要移动数据目录时，应使用 Cherry Studio 的数据目录设置，并在迁移前完成备份。迁移后至少检查一次数据源预览、召回测试和对话引用。

如果只是释放空间，优先在应用内删除不再使用的数据源或知识库。不要直接删除内部数据库文件。

## 常见问题

### 删除知识库后，原文件还在吗

在。知识库引用的外部本地文件不会随知识库删除。删除操作只清理 Cherry Studio 管理的记录和索引。

### 移动原文件后还能继续检索吗

已有索引可能暂时仍能返回旧片段，但预览和重新索引会因原路径失效而失败。应重新添加新路径下的文件并确认召回结果。

### 只备份 `Data/KnowledgeBase` 可以吗

不可以。该目录只有向量存储，缺少主数据库中的元数据和数据源关系，也不包含外部原文件。

### 使用本地嵌入模型就完全离线了吗

不一定。还需要确认文档处理器、重排序模型和聊天模型是否也在本地，以及是否导入了外部网页。

### 重建索引会产生费用吗

如果使用按量计费的在线文档处理、嵌入或重排序服务，重新索引可能再次产生调用费用。
