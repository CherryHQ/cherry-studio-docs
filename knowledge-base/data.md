# 数据、隐私与维护

知识库会托管导入资料的副本、解析文本、Chunks 和索引。原始资料在哪里、选择了哪些服务，以及备份是否包含数据文件，共同决定资料的存储和传输边界。

> 本章目标：知道资料会复制到哪里、哪些操作可能发送到云端，以及怎样备份、更新和清理知识库。

### 导入后发生什么

* 文件和目录中的文件会复制到 Cherry Studio 管理的数据中，后续不依赖原路径持续存在。
* 网页会保存导入时抓取的内容快照，不会实时跟随网页更新。
* Cherry Studio 笔记也以导入时的内容建立资料快照，不会实时同步。
* 解析文本会被切分为 Chunks，并建立关键词索引；配置嵌入模型时还会生成向量索引。

删除知识库条目不会删除原始文件或原笔记，但会移除知识库托管的副本和索引。

### 本地与云端边界

| 选择的能力   | 可能接收什么         |
| ------- | -------------- |
| 云端文档处理器 | 用于解析的文件内容      |
| 云端嵌入模型  | 需要向量化的资料片段和查询  |
| 云端重排序模型 | 查询和候选片段        |
| 云端聊天模型  | 问题、对话上下文和被召回片段 |
| 本地对应服务  | 在本机完成相应处理      |

使用本地嵌入模型并不等于整个流程完全离线。解析、重排序或聊天中任一环节使用云服务，都可能发送完成任务所需的相关内容。

### 备份知识库

打开【设置】→【数据】可以进行备份与恢复。

#### 完整备份

完整备份可包含知识库文件数据，适合迁移设备或需要恢复完整资料的情况。知识库较大时，备份文件也会明显增大。

#### 精简备份

开启【精简备份】后，会跳过图片、知识库等数据文件，主要保留聊天记录和设置。它更快、更省空间，但不能单独用于恢复完整知识库资料。

恢复前确认备份类型和时间。重要迁移建议先保留一份完整备份，并在目标环境验证知识库条目、正文和召回测试。

### 更新资料

知识库不是与原文件、网页或笔记持续同步的镜像。资料更新时：

1. 用相同名称重新添加资料。
2. 在冲突窗口选择【替换】，避免新旧版本并存。
3. 等待状态变为【就绪】。
4. 抽查正文和 Chunks。
5. 运行固定的召回回归问题。

如果只改变了解析、切分或模型设置，对现有条目执行【重新索引】。

### 日常维护清单

#### 每次资料更新后

* 删除或替换过期版本。
* 检查错误和长期处理中状态。
* 抽查正文、Chunks 和召回。

#### 每月或每个版本周期

* 清理临时测试资料和重复网页快照。
* 用固定问题集做一次召回回归。
* 检查云端服务的 API Key、额度和数据策略。
* 创建一份可恢复的完整备份。

#### 迁移或大改设置前

* 记录知识库使用的解析器、嵌入和重排序模型。
* 创建完整备份。
* 在少量代表性资料上验证新设置。
* 分批重新索引，避免一次性失去可用基线。

### 删除与恢复

删除资料或整个知识库前，确认：

* 原始文件、网页地址或原笔记仍可找到。
* 是否需要保留历史版本。
* 最近完整备份是否包含知识库数据文件。
* 是否有 Agent 仍绑定该知识库。

精简备份不包含完整知识库文件数据，不能把它当作删除前的唯一恢复保障。

### 完全离线检查

需要完全离线时，逐项确认：

* 文档解析和 OCR 使用系统或本地能力。
* 嵌入模型使用本地模型。
* 不使用云端重排序，或使用本地重排序能力。
* 对话和 Agent 使用本地聊天模型。
* 没有启用会把内容发送到外部系统的 MCP、网络搜索或频道。
