# 文档解析与 OCR

知识库只能检索解析出的文字。遇到扫描 PDF、复杂排版、表格或图片时，应先选择合适的文档处理器和 OCR，再检查正文与 Chunks。

> 完成标准：抽查的正文顺序可读，扫描文字已识别，关键表格或条款没有在解析阶段丢失。

### 先判断资料类型

| 资料                      | 建议起点                    |
| ----------------------- | ----------------------- |
| 结构简单的 Markdown、TXT、HTML | 先用内置读取，不必额外配置云解析        |
| 可复制文字的普通 PDF、DOCX、PPTX  | 先尝试默认处理；复杂版式再换处理器       |
| 扫描 PDF、截图或图片型页面         | 配置 OCR，并抽查识别结果          |
| 多栏论文、复杂表格、公式较多的 PDF     | 尝试专用文档处理器，比较正文顺序和表格保留情况 |

### 配置文档处理器

打开【设置】→【文档处理】，选择服务并填写所需的 API Key 和地址。不同服务的账号、额度和数据策略各不相同。

在知识库设置中也可以选择文件处理器。当前界面提供 PaddleOCR、MinerU、Doc2X、Mistral 和 Open MinerU 等选项；实际可用性取决于版本、平台和服务配置。

选择云端处理器意味着相关文档内容会发送给对应服务完成解析。涉及敏感资料时，先阅读服务条款，或优先使用本地能力。

### 配置 OCR

打开【设置】→【OCR】。系统会显示当前可用的 OCR 引擎。在支持的平台上，【System OCR】会调用 macOS Live Text 或 Windows OCR 等系统能力。

系统 OCR 通常速度快、无需额外 API Key，但准确率会受系统版本、语言和图片质量影响。当前版本还提供可下载的本地 PaddleOCR 模型，是否可用以【设置】→【本地模型】的界面为准。

### 推荐测试流程

1. 先只导入一份有代表性的文档。
2. 等待状态变为【就绪】。
3. 打开正文预览，检查标题、段落、页码、表格和扫描文字。
4. 打开【查看 Chunks】，确认关键条件和结论没有被拆散。
5. 用一个能命中该文档的真实问题做召回测试。
6. 解析不合格时，更换处理器或 OCR，再重新索引同一文档比较。

不要一次导入大量资料后才检查解析。先用代表性样本确定方案，可以避免整批返工。

### 解析问题的典型表现

#### 正文为空或只有少量字符

文件可能是扫描件，或默认读取器无法处理其编码。启用 OCR，或更换专用处理器。

#### 双栏论文顺序错乱

普通文本提取可能交错读取两栏。尝试擅长版面分析的处理器，并在正文预览中比较阅读顺序。

#### 表格被拆成零散文字

先确认问题是否必须依赖完整表格。若必须，选择更擅长表格解析的处理器；也可以把关键规则另存为结构清楚的 Markdown 笔记后导入。

#### 页眉页脚反复出现

重复噪声会占用 Chunk 并影响召回。优先更换解析器或清理源文档，而不是只增加 Top K。

#### OCR 有错字

提高图片清晰度、裁掉无关背景，确认识别语言。对金额、日期、编号和人名等高风险字段进行人工核对。

### 设置改变后要重新索引

文件处理器、OCR 或 Chunk 参数的变化不会自动重做旧资料。回到知识库，对相关条目执行【重新索引】，再用相同问题复测。

### 隐私提醒

* 系统 OCR 和本地 OCR 在本机处理。
* 云端文档处理器会接收完成解析所需的文件内容。
* 云端嵌入、重排序和聊天模型还可能分别接收文本片段。
* 要实现完全离线，解析、OCR、嵌入、重排序和聊天都必须选择本地服务。

更完整的数据路径见数据、隐私与维护。
