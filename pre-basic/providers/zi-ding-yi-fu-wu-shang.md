# 自定义服务商

自定义服务商用于接入 Cherry Studio 尚未内置的云平台、OpenAI 兼容代理、局域网网关或自托管模型服务。

Cherry Studio V2 提供两种创建方式：

| 方式 | 适用场景 | 主要特点 |
| --- | --- | --- |
| 添加自定义服务商 | 新平台、OpenAI 兼容服务、本地推理服务 | 默认以 OpenAI Chat Completions 作为主要对话协议 |
| 从预置服务商添加实例 | 同一厂商的第二个账号、区域、网关或私有地址 | 保留原服务商的认证方式、默认协议和专用适配 |

{% hint style="info" %}
如果目标平台已经有预置服务商，优先添加该服务商的另一个实例。完全自定义服务商适合标准兼容接口，不会自动获得某个厂商的专用认证、图片任务或参数适配。
{% endhint %}

## 使用前准备

创建前先从目标服务的官方文档确认：

1. 使用哪种 API 协议；
2. Base URL，而不是网页控制台地址；
3. API Key 或其他认证方式；
4. 模型列表接口是否可用；
5. 准备调用的完整 Model ID；
6. 模型是否支持视觉、思考、工具、Embedding 或 Rerank；
7. 是否要求额外请求头；
8. 是否有 IP 白名单、代理或证书要求。

只有“接口兼容”还不够。返回字段、流式格式、工具调用、思考内容和错误结构也需要与所选协议兼容。

## 选择创建方式

### 添加完全自定义服务商

适合：

- OpenAI 兼容云服务；
- OneAPI、NewAPI 等统一网关；
- vLLM、LocalAI 等自托管服务；
- 企业内部的兼容代理；
- 尚未出现在预置列表中的平台。

V2 的完全自定义服务商默认主端点是：

```text
OpenAI Chat Completions
```

创建时不再使用旧版的“OpenAI / Gemini / Anthropic / Azure OpenAI”服务商类型下拉框。

### 从预置服务商添加实例

适合：

- 同一服务商使用多组独立账号；
- 不同区域使用不同 Base URL；
- 公司代理与官方地址并存；
- 需要保留 Azure、Vertex AI、Bedrock 等专用认证；
- 需要保留服务商专用的图片、思考或模型同步适配。

在预置服务商所在分组点击**添加实例**，或打开服务商菜单后选择相同操作。新实例创建后，再填写自己的认证信息和地址。

{% hint style="warning" %}
复制预置服务商只复制配置结构，不会复制原实例的敏感凭据。创建后应在新实例详情页重新填写认证信息。
{% endhint %}

## 添加完全自定义服务商

1. 打开 `设置 → 模型服务`；
2. 如有需要，将筛选切换为**全部服务商**；
3. 点击服务商搜索框右侧的 `+`；
4. 填写便于识别的提供商名称；
5. 可选择内置图标或上传自己的图标；
6. 填写主要 Base URL；
7. 可选填第一条 API Key；
8. 如平台同时提供其他兼容协议，展开**更多端点**；
9. 点击**添加**；
10. 进入新服务商详情页继续配置模型。

名称只影响显示，不会改变请求协议。建议在名称中包含平台、区域或用途，例如“内部网关-上海”。

## 填写 Base URL

Base URL 是接口根地址，不是完整请求地址。

以 OpenAI Chat Completions 为例：

```text
正确：https://api.example.com/v1
错误：https://api.example.com/v1/chat/completions
错误：https://console.example.com/models
```

V2 会根据端点类型拼接具体请求路径。是否需要 `/v1`、`/v1beta` 或自定义路径，应以目标服务的官方文档为准。

{% hint style="warning" %}
不要照搬其他客户端的“代理地址”，除非确认它要求的正是 Base URL。同一个平台在不同工具中可能要求填写根地址或完整请求地址。
{% endhint %}

### 本机与局域网地址

本机服务常见地址：

```text
http://127.0.0.1:8000/v1
```

如果服务运行在 Docker、虚拟机或另一台电脑上，`localhost` 指向的设备可能不同。应使用 Cherry Studio 所在电脑能够访问的地址，并确认防火墙和监听网卡。

HTTPS 服务使用自签名证书时，系统证书校验也可能阻止连接。不要为解决证书问题直接关闭整台电脑的安全校验。

## 配置更多端点

完全自定义服务商创建页可额外填写：

- Anthropic Messages；
- Google Gemini；
- OpenAI Responses。

创建后也可以在 API Host 右侧打开**请求配置**，添加或修改端点。

这些地址用于描述同一服务商提供的不同协议入口。它们不会把一个只支持 OpenAI 的模型自动变成 Anthropic 或 Gemini 模型。

对于普通手动添加的自定义模型，主要协议仍以服务商默认端点为准。如果必须使用某个厂商协议或专用认证，优先从对应预置服务商添加实例。

## API Key 与多 Key

创建时可以填写第一条 API Key，也可以留空后再配置。

在服务商详情页可以：

- 添加多条 Key；
- 为 Key 添加便于识别的标签；
- 暂停某条 Key；
- 删除已失效或泄露的 Key。

只有启用的 Key 才可用于请求。多条 Key 是否都拥有相同模型、余额和组织权限，仍由服务端决定。

{% hint style="danger" %}
不要把真实 API Key 写入文档、聊天、公开仓库、截图或自定义请求头示例。泄露后应立即在服务端吊销。
{% endhint %}

没有认证要求的本地服务可以不填 Key。不要为了通过表单随意填写生产凭据。

## 自定义请求头

在 API Host 右侧点击请求配置按钮，可以使用列表或 JSON 方式填写额外请求头。

常见用途包括：

- 组织或项目标识；
- 企业网关的租户头；
- 代理要求的版本头；
- 服务端明确要求的自定义鉴权头。

填写前应注意：

1. 只添加官方文档明确要求的字段；
2. 不要重复覆盖 `Content-Type`；
3. 不要同时在 API Key 和自定义头中配置冲突的 `Authorization`；
4. JSON 模式必须是对象；
5. 对象值会按字符串发送；
6. 修改后重新运行连接检查。

请求头会随相关请求发送到目标地址。不要把敏感头用于不可信代理。

## 启用服务商

创建完成后：

1. 选择新服务商；
2. 检查 API Key 和 API Host；
3. 打开服务商开关；
4. 同步或手动添加模型；
5. 只启用实际需要的模型；
6. 运行健康检查。

服务商未启用时，即使模型已经添加，也不会正常出现在对应的模型选择位置。

## 同步模型

对于 OpenAI 兼容服务，V2 默认尝试读取：

```text
GET {Base URL}/models
```

如果目标服务正确实现模型列表接口，Cherry Studio 会展示同步预览。应用前检查：

- 新增模型；
- 更新模型；
- 已从服务端移除的模型；
- Model ID 和显示名称；
- 模型能力是否识别正确。

同步失败不等于对话接口一定失败。有些服务只实现 Chat Completions，没有实现 `/models`，此时应手动添加模型。

## 手动添加模型

1. 点击模型列表中的**添加模型**；
2. 填写服务端要求的完整 Model ID；
3. 可填写更易读的显示名称和分组；
4. 按官方规格填写上下文与最大输出；
5. 选择模型实际支持的能力；
6. 保存并启用；
7. 运行健康检查。

可手动标记的能力包括：

- 图片理解；
- 联网搜索；
- 思考；
- 工具调用；
- Embedding；
- Rerank。

能力标记用于界面筛选和请求路由，不会改变服务端能力。错误标记可能导致请求失败或把 Embedding、Rerank 模型错误显示在对话列表中。

{% hint style="warning" %}
Model ID 必须与服务端完全一致。显示名称可以自定义，但不能用显示名称代替请求中的 Model ID。
{% endhint %}

## 连接检查与模型健康检查

建议分层检查：

1. 先检查服务商连接；
2. 再检查单个对话模型；
3. 单独测试流式输出；
4. 单独测试视觉、思考和工具调用；
5. 在知识库中实际测试 Embedding 与 Rerank。

当前 V2 的通用健康检查会跳过 Rerank 模型，因此 Rerank 需要在知识库检索流程中验证。

连接检查通过不代表：

- 每个模型都有权限；
- 余额充足；
- 视觉或工具调用可用；
- 长上下文一定成功；
- 服务端所有扩展参数都兼容。

## OpenAI 兼容能力边界

完全自定义服务商可复用标准 OpenAI 兼容能力：

- Chat Completions；
- 流式输出；
- 视觉输入；
- Function Calling；
- Embeddings；
- 标准模型列表。

是否可用取决于服务端与具体模型。以下能力通常不能只靠“兼容 OpenAI”自动获得：

- 厂商原生异步图片任务；
- 专用文件上传；
- 云端知识库；
- 特殊思考参数；
- 非标准 Rerank；
- OAuth、IAM 或云账号签名；
- 厂商特有的模型同步分类。

如果服务商需要这些能力，应使用预置适配或专门文档。

## 用 vLLM 创建本地服务商

vLLM 提供 OpenAI 兼容服务器。安装方式和硬件要求请先参阅[vLLM 官方文档](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)。

使用一个支持聊天模板的模型启动服务：

```sh
vllm serve NousResearch/Meta-Llama-3-8B-Instruct \
  --dtype auto \
  --api-key local-test-token
```

默认监听端口为 `8000`。在 Cherry Studio 中添加完全自定义服务商：

```text
提供商名称：vLLM Local
Base URL：http://127.0.0.1:8000/v1
API Key：local-test-token
```

然后同步 `/v1/models`，或手动添加 vLLM 返回的 Model ID。

{% hint style="info" %}
上面的 Key 只用于本机示例。局域网或公网部署必须使用强凭据、访问控制、TLS 和防火墙，不要直接暴露无认证的推理端口。
{% endhint %}

如果返回“缺少 chat template”，需要使用带聊天模板的模型，或按 vLLM 文档配置 `--chat-template`。

## PDF、附件与隐私

对于通用对话模型，Cherry Studio 会先在本地提取 PDF 文本，再发送给服务端：

- 文本型 PDF 通常可以处理；
- 扫描件需要 OCR；
- 表格、复杂排版和图片信息可能丢失；
- 提取文本会占用上下文；
- PDF 中的图片需要视觉模型。

自定义服务商的 Base URL 决定数据最终发送到哪里。接入代理或企业网关前，应确认：

- 运营方身份；
- 数据保留策略；
- 日志与训练政策；
- 跨境传输；
- TLS 与证书；
- 组织合规要求。

## 常见问题

### 返回 401

API Key 错误、鉴权头格式不兼容，或自定义请求头覆盖了正确的 `Authorization`。重新检查服务端认证说明。

### 返回 403

Key 没有模型或项目权限，IP 不在白名单，或组织策略拒绝请求。

### 返回 404

通常是 Base URL 填成了完整请求地址、缺少版本路径，或服务端没有对应接口。分别检查 `/models` 和 `/chat/completions`。

### 返回 400

模型不支持当前参数、消息格式、图片、思考或工具调用。先用纯文本和默认参数测试。

### 返回 429

达到服务端的请求、Token 或并发限制。降低并发并使用退避重试。

### 模型同步为空

目标服务可能没有实现 `/models`，或该接口需要不同权限。确认地址后手动添加 Model ID。

### 模型能对话，但图片失败

普通文本模型不一定支持视觉；检查模型能力和服务端的图片消息格式。

### 工具只被模型描述，没有真正调用

模型可能不支持 Function Calling，或返回格式不兼容。先用一个简单工具验证结构化调用。

### Embedding 出现在对话列表

模型类型标记错误。编辑模型并启用 Embedding 能力，关闭不真实的对话能力。

### Rerank 无法通过健康检查

通用健康检查会跳过 Rerank。请在知识库中配置模型并实际执行检索。

### 本地服务在浏览器能开，Cherry Studio 仍连接失败

浏览器打开根页面不代表 API 可用。检查 `/v1/models`、防火墙、监听地址、代理、自签名证书和聊天模板。

### 添加了 Anthropic 或 Gemini 地址，但模型仍走 OpenAI

完全自定义服务商的主要端点默认是 OpenAI Chat Completions。仅填写二级端点不会保证普通手动模型自动切换协议；需要对应厂商协议时，优先从预置服务商添加实例。

更多一般设置请参阅[模型服务](README.md)和[模型服务设置](../settings/providers.md)，vLLM 接口请参阅[OpenAI-Compatible Server](https://docs.vllm.ai/en/stable/serving/openai_compatible_server/)；意见反馈渠道请参阅[反馈与建议](../../question-contact/suggestions.md)。
