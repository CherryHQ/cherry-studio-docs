# 模型服务设置

模型服务是 Cherry Studio 调用大语言模型、视觉模型、嵌入模型和重排序模型的连接入口。这里负责配置服务商凭证、请求地址、协议端点及模型列表；各服务商的注册和 Key 获取方式见[模型服务](../providers/)。

{% hint style="info" %}
不同平台可能把凭证称为 API Key、密钥、令牌或 Token。它们的具体格式和权限由服务商决定，并不代表不同平台的 Key 可以互换。
{% endhint %}

## 打开模型服务

进入：

> **设置 → 模型服务**

左侧是服务商列表，右侧是当前服务商的连接和模型设置。

服务商列表支持：

- 按服务商名称、模型名称或模型 ID 搜索；
- 查看已启用、已停用、全部或适合智能体的服务商；
- 拖动调整显示顺序；
- 展开同一预设下创建的多个实例；
- 通过右键菜单复制、编辑或删除可管理的服务商；
- 点击搜索框旁的 **+** 添加自定义服务商。

如果所有服务商都处于停用状态，列表会自动显示全部服务商，方便完成首次配置。

## 配置内置服务商

### 1. 选择并启用服务商

在左侧选择服务商，打开右上角开关。

服务商开关只决定该服务商是否在应用中可用，不代表 API Key、地址和模型已经配置正确。

### 2. 填写 API Key

把服务商控制台中创建的 API Key 粘贴到 **API 密钥**。

输入框右侧通常提供：

- 显示或隐藏 Key；
- 复制 Key；
- 打开多 Key 管理；
- 打开连接检测。

少数服务商使用 OAuth、云账号身份或设备授权，不一定显示普通 API Key 输入框。应按对应服务商页面的流程登录或填写云账号参数。

{% hint style="danger" %}
不要把真实 API Key 放进截图、公开仓库、聊天记录或反馈附件。截图前应关闭 Key 显示；怀疑泄露时，立即在服务商控制台撤销旧 Key。
{% endhint %}

### 3. 检查请求地址

内置服务商通常已经提供默认 API 地址。没有使用代理、兼容网关或私有部署时，建议保留默认值。

常见的 Base URL 示例：

```text
https://api.example.com/v1
```

不要因为服务商文档展示了完整请求示例，就盲目把 `/chat/completions`、`/responses` 或 `/messages` 拼到 Base URL 后面。Cherry Studio 会按模型端点类型生成请求路径。

若地址已被修改，界面可能提供**恢复默认地址**。请求配置入口还可管理不同协议的端点地址和自定义请求头。

### 4. 检测连接

点击 API Key 输入框右侧的**连接检测**。

当前 V2 会打开检测面板，让你选择：

- 一枚已启用的 API Key；
- 一个已添加且可用于检测的模型。

检测会实际向所选模型发起请求。连接成功至少说明这组 Key、地址、端点和模型可以完成基本调用，但不保证所有模型、图片、工具调用或长上下文请求都可用。

## 管理多枚 API Key

点击 Key 输入框旁的**密钥列表**按钮，可以：

- 添加多枚 Key；
- 为 Key 添加便于识别的标签；
- 单独启用或停用 Key；
- 编辑、复制或删除 Key；
- 查看已启用数量。

运行时会在已启用 Key 之间按顺序轮换。停用的 Key 不参与轮换；没有任何已启用 Key 时，普通 API Key 服务商将无法完成请求。

{% hint style="warning" %}
旧版常用英文逗号把多枚 Key 写在一个输入框中。V2 更适合通过密钥列表逐条管理，这样可以单独命名、停用和检测，也能避免误用中文逗号或把标签当成 Key。
{% endhint %}

多 Key 轮换不能绕过服务商的账号级额度、组织级限制或使用条款。同一账号下的多枚 Key 可能共享账单与限额。

## API 地址与端点

### Base URL

大多数情况下填写服务根地址或版本根路径，例如：

```text
https://api.example.com/v1
```

具体是否需要 `/v1`，以服务商文档和 Cherry Studio 对应预设为准。地址必须使用有效的 `http://` 或 `https://` URL。

### 完整端点与 `#`

兼容接口如果只提供完整端点，可以在地址末尾保留 `#`，让 Cherry Studio 识别并停止继续拼接该端点。例如：

```text
https://api.example.com/custom/chat/completions#
```

只有在服务商明确给出非常规完整路径时才使用这种写法。当前可识别的常见端点包括：

- `chat/completions`
- `responses`
- `messages`
- `generateContent`
- `streamGenerateContent`
- 图像生成或编辑端点

普通 Base URL 不应添加 `#`。

### 多协议端点

自定义服务商和部分内置服务商可分别配置：

| 协议端点 | 常见用途 |
| --- | --- |
| OpenAI Chat Completions | 多数 OpenAI 兼容聊天模型 |
| OpenAI Responses | 使用 Responses API 的模型 |
| Anthropic Messages | Claude 原生或兼容 Messages API |
| Google Generate Content | Gemini 原生或兼容接口 |

一个网关显示多个协议，并不代表每个模型都支持所有端点。模型的端点类型必须与服务端实际协议一致。

### 自定义请求头

在**请求配置**中可以按列表或 JSON 方式设置额外请求头。

仅在网关文档明确要求时添加，例如租户 ID 或项目标识。不要重复添加与 Cherry Studio 已管理的鉴权头，也不要把 API Key 同时写进多个位置。

### 服务商 API 选项

服务商名称旁的闪电按钮可能提供：

- 数组内容格式；
- `developer` 角色；
- Stream Options；
- Service Tier；
- 思考开关或 verbosity；
- Anthropic Prompt Cache 相关设置。

这些选项只会改变请求格式，不会让服务端获得原本不支持的能力。遇到 `400`、未知参数或响应格式错误时，可先恢复默认选项。

## 同步模型列表

在服务商下方的模型列表中点击**拉取**，Cherry Studio 会从服务商获取可用模型，并先显示同步预览。

预览通常会区分：

- 服务端新增、可加入本地的模型；
- 本地已有、仍在服务端存在的模型；
- 本地存在但服务端列表中已缺失的模型；
- 用户可以选择启用、停用或保留的项目。

确认选择后再应用，不要假设拉取会自动启用服务端的所有模型。

如果服务商不提供模型列表接口，或代理没有实现相应接口，可使用**添加**手动创建模型。

## 手动添加和编辑模型

手动添加至少需要准确的**模型 ID**。模型 ID 是请求中发送给服务端的值，应与服务商文档完全一致。

还可以设置：

- 显示名称；
- 分组名称；
- 端点类型；
- 上下文窗口；
- 最大输入和输出 Token；
- 模型能力。

可标记的常见能力包括：

- 视觉；
- 原生网络搜索；
- 推理；
- 工具调用；
- 嵌入；
- 重排序。

{% hint style="warning" %}
能力标记只告诉 Cherry Studio 应如何使用模型，不会改变服务端能力。把普通模型误标为视觉、原生联网或工具调用模型，可能导致请求失败，或让外部工具无法正确注入。
{% endhint %}

嵌入模型和重排序模型用于知识库等检索流程，不应当作普通对话模型使用。

## 模型可见性与健康检查

服务商开关和模型开关是两层独立控制：

1. 服务商必须启用；
2. 具体模型也必须启用。

模型列表工具栏可以：

- 搜索模型；
- 按能力筛选；
- 批量启用或停用可见模型；
- 运行模型健康检查；
- 拉取服务端模型；
- 手动添加模型。

健康检查适合一次核对多枚模型；连接检测适合验证指定 Key 与指定模型。两者都可能产生真实 API 请求和少量费用。

## 添加自定义服务商

点击服务商搜索框旁的 **+**，创建自定义服务商。

基本流程：

1. 填写服务商名称；
2. 选择或上传图标；
3. 填写主要 Base URL；
4. 可选填写第一枚 API Key；
5. 如有需要，展开**更多端点**填写其他协议地址；
6. 创建后进入详情页补充 Key 和模型；
7. 启用服务商并执行连接检测。

新建自定义服务商默认以 OpenAI Chat Completions 作为主要端点。若目标服务只兼容 Anthropic、Google 或 Responses API，应在端点配置和模型设置中明确选择正确协议。

还可以从某个内置预设**复制服务商**，创建相互独立的配置实例。例如同一网关有测试和生产地址时，可以分别命名、配置 Key 和启用状态。

## 推荐配置顺序

为减少排错范围，建议：

1. 启用服务商；
2. 填写一枚确认有效的 Key；
3. 保留或核对默认 API 地址；
4. 拉取或手动添加一个对话模型；
5. 确认该模型已启用；
6. 使用该 Key 和模型运行连接检测；
7. 回到对话页发送简短消息；
8. 基本调用正常后，再增加多 Key、自定义头和高级端点。

不要一开始同时修改 Key、地址、端点、请求头和高级选项，否则失败时难以确定原因。

## 常见问题

### 服务商已配置，但模型选择器里没有模型

检查：

- 服务商右上角开关是否启用；
- 模型列表中是否已经添加目标模型；
- 目标模型本身是否启用；
- 当前页面是否按能力筛选隐藏了模型；
- 模型 ID 是否保存成功。

### 连接检测提示没有可检测模型

先拉取或手动添加至少一个非重排序模型，并启用它。重排序模型不能用于普通连接检测。

### 返回 401 或 403

通常与鉴权或权限有关：

- Key 是否完整且未撤销；
- Key 是否属于正确项目、区域或组织；
- 所选模型是否已授权；
- 自定义请求头是否覆盖了正确的鉴权头；
- 云服务是否还需要区域、项目或 API 版本。

### 返回 404

重点核对：

- Base URL 是否包含或缺少必要的版本路径；
- 是否误把完整 `/chat/completions` 当成普通 Base URL；
- 模型端点类型是否与服务端协议一致；
- 自定义网关是否实现模型列表和对话路径；
- Azure 等服务是否要求部署名或 API Version。

### 返回 400 或“未知参数”

恢复服务商 API 选项和模型能力到默认值，移除不必要的自定义请求头，再测试最简单的文本对话。

### 拉取模型失败

有些服务商没有开放模型列表接口，或网关只代理聊天接口。此时可按官方模型 ID 手动添加。

拉取成功也不代表每个模型都已对当前账号开放；仍需用健康检查或实际对话验证。

### 连接检测成功，对话仍失败

检测通常只覆盖一个 Key、一个模型和一次基本请求。继续核对：

- 对话实际选中的是否为同一模型；
- 多 Key 轮换中是否有无效 Key；
- 长上下文、图片、联网或工具调用是否超出模型能力；
- 助手是否设置了不兼容的自定义参数；
- 服务商是否出现额度、并发或内容策略限制。

### Key 被轮换到无效凭证

打开密钥列表，停用或删除失败的 Key，再分别检测剩余 Key。只要无效 Key 仍处于启用状态，它就会继续参与轮换。

## 安全与备份

- 不要用真实 Key 制作文档截图；
- 不要在问题反馈中粘贴完整请求头；
- 不要把生产和测试 Key 混在无法识别的列表中；
- 删除服务商或清理数据前先创建备份；
- 备份或同步后，在目标设备上重新核对本机路径、代理和云账号权限；
- 需要共享配置时，优先分享不含凭证的服务商名称、地址结构和模型 ID。
