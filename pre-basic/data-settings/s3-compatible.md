# S3 兼容存储备份

Cherry Studio V2 可以把备份保存到 AWS S3、Cloudflare R2、阿里云 OSS、腾讯云 COS、火山引擎 TOS、MinIO 等提供 S3 兼容 API 的对象存储。

S3 在这里是远程备份位置，不是实时同步服务。恢复会用选中的备份覆盖当前数据，不会合并不同设备分别新增的内容。

{% hint style="warning" %}
备份可能包含对话、服务商配置和其他敏感信息。存储桶必须保持私有，并使用仅限目标存储桶或目录的专用凭据。
{% endhint %}

## 准备存储桶和凭据

在对象存储控制台中：

1. 创建或选择一个私有存储桶。
2. 确认存储桶所在 Region。
3. 找到服务商提供的 S3 API Endpoint。
4. 创建专用于 Cherry Studio 的访问凭据。
5. 若服务支持，限制凭据只能访问该存储桶中的 Cherry Studio 目录。

Cherry Studio 至少需要列出、上传和读取对象的权限。希望自动清理旧备份或在管理器中删除文件时，还需要删除对象权限。

不同服务对权限名称的表达不同。AWS IAM 中常见的对应动作包括 `s3:ListBucket`、`s3:PutObject`、`s3:GetObject` 和 `s3:DeleteObject`；其他兼容服务请使用其等价权限。

## 配置字段

打开 **设置 > 数据设置 > S3**，填写：

| 字段 | 说明 |
| --- | --- |
| API 地址 | 服务商提供的 S3 API Endpoint，包含 `http://` 或 `https://` |
| 区域 | 存储桶的 Region；必须使用服务商要求的值 |
| 存储桶 | Bucket 名称，不是控制台显示名称或目录名 |
| Access Key ID | 专用访问凭据的标识 |
| Secret Access Key | 与 Access Key ID 配套的密钥 |
| 备份目录 | 可选的对象 Key 前缀，用于隔离 Cherry Studio 备份 |

除 **备份目录**外，其余字段都是执行手动备份和打开备份管理器的必要条件。

### Endpoint 不要重复填写 Bucket

Endpoint 的格式由服务商决定，可能是区域级地址、账户级地址或自建服务地址。Cherry Studio 会把 **存储桶**作为独立参数传给 S3 客户端，因此不要自行把 Bucket 重复拼入地址，除非服务商的 S3 SDK 文档明确要求这样填写。

例如，控制台中的网页管理地址、对象公开访问地址和 S3 API Endpoint 可能完全不同。应复制“兼容 S3 的 Endpoint”，而不是浏览器中打开某个文件时的 URL。

Cherry Studio 会根据 Endpoint 域名选择 virtual-host 或 path-style 请求方式：

- 阿里云、腾讯云和火山引擎的已识别官方域名使用 virtual-host 风格；
- `localhost`、IP 地址和多数其他兼容服务使用 path-style；
- 无法解析的地址会回退到 path-style。

如果服务同时支持多种地址形式，优先使用其 AWS SDK / S3 SDK 文档提供的 Endpoint。

### 设置备份目录

**备份目录**会成为对象 Key 的前缀。可以填写 `cherry-studio` 或 `/cherry-studio/`，保存时会去掉首尾多余的 `/`。

建议每套 Cherry Studio 数据使用独立前缀，例如：

```text
cherry-studio/personal
```

备份管理器只会列出该前缀下以 `.zip` 结尾的对象。更改目录后，原目录中的备份不会自动移动，也不会出现在新目录的列表中。

## 验证配置

当前页面没有独立的“测试连接”按钮。最完整的验证方式是：

1. 填完全部必填字段，暂时关闭自动备份。
2. 点击 **立即备份**。
3. 保留默认文件名，创建一份小型测试备份。
4. 点击 **管理备份**。
5. 确认列表中能看到刚上传的 ZIP、修改时间和大小。

这一步同时验证 Endpoint、Region、Bucket、凭据、备份目录，以及列出和写入权限。能列出存储桶但不能上传，通常是缺少对象写入权限；能上传但不能显示，通常需要检查前缀或列出权限。

## 手动备份

点击 **立即备份**后，可以确认或修改文件名。默认名称包含时间、主机名和设备类型；没有 `.zip` 扩展名时会自动补上。

打开 **精简备份**后，Cherry Studio 会跳过应用 `Data` 目录中的图片、知识库等文件数据，只备份聊天记录和设置等内容。精简备份不是增量备份，恢复时无法找回被跳过的文件。

S3 上传前会先在本机生成 ZIP，并把文件读入内存再上传。大型完整备份可能明显增加磁盘和内存占用；执行期间不要退出应用、断网或让系统休眠。

## 自动备份和保留数量

**自动同步**实际执行的是周期性备份，可选择：

- 关闭；
- 每 1、5、15 或 30 分钟；
- 每 1、2、6、12 或 24 小时。

先成功完成一次手动备份，再开启自动备份。频率越高，请求次数、流量和对象存储操作费用越多。

**最大备份数**可设为不限、1、3、5、10、20 或 50。达到上限后，Cherry Studio 会根据默认文件名中的主机名和设备类型，清理当前设备较旧的备份。

以下对象通常不会被自动清理：

- 来自其他设备的备份；
- 自定义文件名中没有当前设备标识的备份；
- 不在当前备份目录下的对象；
- 不是 `.zip` 的对象。

选择“不限”时应在对象存储侧设置容量告警或生命周期规则，避免长期累积。

## 管理和恢复备份

点击 **管理备份**可以查看、刷新、恢复和删除当前目录下的 ZIP 备份。

恢复前：

1. 为当前数据再创建一份备份。
2. 根据文件名、修改时间和大小确认目标版本。
3. 确认没有其他设备正在向同一目录写入。
4. 点击目标文件的 **恢复**并确认覆盖。

恢复完成后应用可能自动重新启动。删除对象不可撤销；若凭据没有删除权限，查看和恢复可能正常，但删除与自动清理会失败。

{% hint style="warning" %}
多台电脑可以共用同一 Bucket 和前缀，但恢复不会合并数据。跨设备搬迁时，先备份目标设备，再恢复来源设备的目标版本。
{% endhint %}

## 安全与费用建议

- 使用私有 Bucket，不要为备份目录开启公开读取。
- 使用独立、最小权限的 Access Key，不要填写云账户的根凭据。
- 不在截图、日志或反馈中显示完整 Secret Access Key。
- 公网 Endpoint 使用 HTTPS；自建 MinIO 也应配置可信证书或仅在受信网络中访问。
- 关注存储容量、PUT / GET / LIST 请求和出网流量费用。
- 密钥泄露后立即在服务商控制台撤销并重新创建，不要只修改 Cherry Studio 中的值。

## 常见问题

### 立即备份按钮是灰色的

确认 API 地址、区域、存储桶、Access Key ID 和 Secret Access Key 均已填写。备份目录可以留空。

### 返回 301、PermanentRedirect 或区域不匹配

Endpoint 或 Region 与 Bucket 所在区域不一致。回到对象存储控制台，复制该 Bucket 对应的 S3 Endpoint 和准确 Region。

### 返回 403、AccessDenied 或 SignatureDoesNotMatch

检查 Access Key 与 Secret 是否配对、凭据是否有效，以及系统时间是否准确。还要确认 Endpoint 格式、Region 和最小权限策略；签名错误经常由地址或区域不匹配引起。

### 自建 MinIO 无法连接

确认 Endpoint 包含端口，例如 `https://minio.example.com:9000`，并检查 Cherry Studio 所在设备可以访问该地址。使用 IP 或 `localhost` 时会采用 path-style；若 MinIO 位于反向代理后，还要检查证书、请求体和超时限制。

### 能上传，但管理器看不到文件

检查当前 **备份目录**是否与上传时一致，并确认凭据有列出 Bucket 的权限。管理器只显示当前前缀下以 `.zip` 结尾的对象。

### 达到最大备份数后旧文件仍然存在

自动清理只识别当前设备且符合默认命名规则的备份。自定义名称、其他设备或其他前缀中的对象需要手动删除或通过存储服务生命周期规则处理。

### 大型备份导致内存占用升高

当前 S3 上传会把生成的 ZIP 读入内存。可以开启 **精简备份**减小体积，减少知识库与图片文件，或选择数据量较小时执行。

如仍无法解决，请通过[反馈与建议](../../question-contact/suggestions.md)提交 Cherry Studio 版本、存储服务名称、已脱敏的 Endpoint / Region / Bucket、HTTP 状态码和完整错误信息。
