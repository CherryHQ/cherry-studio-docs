# V1 升级到 V2：功能差异与迁移须知

{% hint style="danger" %}
V1 数据只能单向迁移到 V2。V2 中新增或修改的数据不会同步回 V1，V1 与 V2 的备份文件也不能跨版本恢复。升级前请同时保留一份完整备份，以及完全退出 Cherry Studio 后复制的整个 V1 数据目录。
{% endhint %}

### 目标与前置条件

本文适用于准备把现有 Cherry Studio V1 数据迁移到 V2 的用户。完成后，常用设置、模型服务、助手、会话、Agent、知识库和其他业务数据会进入 V2 的新数据结构。

开始前请确认：

* 当前 V1 版本不低于 1.9.12；建议先升级到最终版 1.9.13。
* 首次迁移使用 V2 2.0.0 系列，不能从 V1 直接跳到 2.0.1 或更高版本。
* 自定义数据目录和外置磁盘均可正常访问。
* 所有 Agent 任务、知识库导入、文件处理和内容生成都已结束。

{% hint style="warning" %}
迁移向导读取的是当前 V1 数据目录，而不是 V1 备份 ZIP。备份用于意外恢复，不能代替原数据目录参与迁移。
{% endhint %}

### 术语

| 术语     | 含义                                     |
| ------ | -------------------------------------- |
| 完整备份   | 包含业务数据和托管文件的备份；创建前应关闭【精简备份】。           |
| 数据目录副本 | 完全退出应用后复制的整个 V1 数据目录，用于保留可继续运行的 V1 状态。 |
| 单向迁移   | V1 数据导入 V2 后，V2 的新变化不会写回 V1。           |
| 迁移警告   | 某一类数据未完整迁移，但其余数据已完成；重启前应展开查看。          |

### 升级路线

<figure><img src="../../.gitbook/assets/clipboard (11).png" alt=""><figcaption></figcaption></figure>

先确认版本和备份，再启动 V2 迁移。出现错误时优先修复问题并重试；只有明确不需要旧数据时，才选择【直接使用 V2】。

### 操作步骤

{% stepper %}
{% step %}
#### 将 V1 更新到可迁移版本

打开 V1 的【关于】页面确认版本。低于 1.9.12 时，先从 [V1 下载页](https://cherryai.com.cn/download/v1) 安装 1.9.13，再重新启动一次 V1。
{% endstep %}

{% step %}
#### 创建完整备份

在 V1 的数据备份页面关闭【精简备份】，创建一份完整备份，并确认备份文件已经生成。把备份放在当前应用数据目录之外。
{% endstep %}

{% step %}
#### 复制整个 V1 数据目录

在 V1 的数据设置中确认当前数据目录，然后完全退出 Cherry Studio。复制整个目录并保留原有层级；不要只复制数据库文件，也不要修改副本内容。
{% endstep %}

{% step %}
#### 检查自定义目录和外置磁盘

如果数据目录位于移动硬盘、网络卷或其他自定义位置，先确认该位置已挂载并且可以读写。路径不可访问时不要改用默认目录继续迁移，否则 V2 可能按没有旧数据处理。
{% endstep %}

{% step %}
#### 首次启动 V2 2.0.0

从 [V2 下载页](https://cherryai.com.cn/download) 获取与当前系统和芯片匹配的安装包。完全退出 V1 后安装并启动 V2 2.0.0 系列。
{% endstep %}

{% step %}
#### 完成【数据迁移向导】

确认向导显示的数据位置正确，再选择【开始迁移】。迁移期间保持应用运行，不要移动数据目录、卸载 V1 或断开外置磁盘。
{% endstep %}

{% step %}
#### 查看结果并重启

迁移完成后先展开警告信息，再选择【重启应用】。进入 V2 后按本文的升级后检查清单逐项确认。
{% endstep %}
{% endstepper %}

### 数据如何处理

| 处理方式   | 数据范围                                                                  | 升级后要做什么                   |
| ------ | --------------------------------------------------------------------- | ------------------------- |
| 自动迁移   | 设置、模型服务与模型、助手与分组、会话与消息、Agent 与会话、MCP、知识库及有效索引、文件、绘画、翻译、笔记、提示词、用量记录    | 抽查常用项目能否正常打开和使用。          |
| 需要人工复核 | Anthropic 凭据、网络搜索默认服务、Agent 工具权限与知识库绑定、提示词顺序、知识库失败项、自定义 CSS、侧栏收藏、缺失文件 | 按下方检查清单重新确认或配置。           |
| 不会继承   | Agent 定时任务历史运行记录、旧版站点地图展开结果、部分临时图片引用、笔记当前打开状态、已移除功能的配置                | 需要时重新创建，不要尝试用 V1 备份覆盖 V2。 |

{% hint style="info" %}
原始 V1 数据不会因迁移被删除。迁移后的 Agent 托管会话会收到原工作区普通文件的副本；Agent 身份和记忆由 Agent 共享，但一个会话中新建的普通文件不会自动出现在其他会话中。
{% endhint %}

### 主要功能差异

| 功能              | V1 行为                                | V2 行为                                         | 用户要做什么                                  |
| --------------- | ------------------------------------ | --------------------------------------------- | --------------------------------------- |
| 助手与提示词          | 独立助手库；快捷短语可与助手关联                     | 助手在聊天和 Agent 中管理；快捷短语合并为全局提示词                 | 检查助手分组，并重新整理提示词顺序和用途。                   |
| Agent 身份与会话     | 部分配置和工作区跟随会话                         | 身份、记忆和主要配置归 Agent 所有；会话创建后工作区固定               | 为不同目录新建会话；检查每个 Agent 的模型、权限和工具。         |
| Agent 知识与授权     | 知识工具可能访问全局知识库；旧授权偏好自动批准部分工具          | 知识工具只访问显式绑定的知识库；工具可能重新请求授权                    | 在 Agent 编辑页重新绑定知识库，并核对禁用工具和权限模式。        |
| 知识库检索           | 可手动选择检索模式、混合比例和站点地图来源                | 无嵌入模型时使用 BM25，有嵌入模型时使用混合检索；站点地图按普通网址处理        | 检查嵌入与重排序模型；对红色失败来源执行重建或重新上传。            |
| 网络搜索            | 可在助手或输入区选择搜索服务；含本地搜索、RAG 压缩和订阅黑名单    | 在【设置】→【网络搜索】统一配置关键词搜索和网址读取；相关旧选项移除            | 重新选择两项默认服务，检查 API 凭据、手动黑名单和截断上限。        |
| MCP             | 已添加服务和第三方发现市场并存                      | 已添加服务继续迁移；旧第三方发现市场不再提供                        | 检查现有服务状态；新服务通过当前市场或 JSON 手动添加。          |
| 模型服务            | Anthropic 可保存 OAuth 凭据；既有和新服务沿用旧启用状态 | Anthropic OAuth 不迁移；AWS Bedrock 区域保留；新增服务默认关闭 | 为 Anthropic 重新填写 API Key，并按需启用新服务和发现模型。 |
| 文件              | 文件副本与业务对象的引用关系较弱                     | 托管文件按引用管理；最后一个引用删除后会延迟清理托管副本                  | 需要长期保留的文件放入【文件】或导出；用户原文件不会被删除。          |
| 绘画、Mini App 与侧栏 | 绘画参数位于独立区域；运行中的 Mini App 和收藏保留在旧侧栏结构 | 绘画参数移到提示词工具栏；Mini App 显示在顶部标签栏；侧栏收藏重置         | 熟悉新入口并重新设置收藏。                           |
| 自定义 CSS         | V1 选择器直接生效                           | CSS 内容会保留，但迁移后默认禁用                            | 按 V2 语义选择器修改样式，再移除禁用标记并启用。              |
| Code CLI        | 可选择 iFlow                            | iFlow 已由 Qoder 替代                             | 需要相关工作流时安装并配置 Qoder。                    |
| 备份与回退           | V1 备份只面向 V1 数据格式                     | V2 使用新的备份格式，不能与 V1 相互恢复                       | 分别保留 V1 和 V2 备份，不要跨版本导入。                |

### 升级后检查清单

* 在【设置】→【模型服务】检查常用服务、API Key 和模型列表。
* 在【设置】→【默认模型】确认聊天、嵌入、重排序和绘画模型。
* 打开常用助手，确认分组、模型、知识库和 MCP 关联。
* 打开【工作】，逐个检查 Agent 的工作区、权限、内置工具、知识库、MCP 和技能。
* 打开最近使用的会话，抽查消息分支、附件、引用和文件。
* 在【知识库】确认各知识库状态，并对失败来源执行重建或重新上传。
* 在【设置】→【网络搜索】重新选择关键词搜索和网址读取的默认服务。
* 检查【绘画】【翻译】【笔记】和【文件】中的常用内容。
* 重新设置侧栏收藏，并检查自定义 CSS 是否需要适配。
* 在【设置】→【数据】创建一份新的 V2 完整备份。

### 迁移失败与回退

| 选项        | 适用情况                      | 影响与注意事项                                                             |
| --------- | ------------------------- | ------------------------------------------------------------------- |
| 【重试】      | 数据目录恢复可访问、磁盘空间已释放或临时错误已解决 | 保留迁移流程，应该优先选择。                                                      |
| 【保存问题信息】  | 重试仍失败，需要向支持团队求助           | 文件只保存到本地；内容可能包含路径、对话片段或凭据，只提供给 Cherry Studio 支持团队。                  |
| 【直接使用 V2】 | 明确决定不导入任何 V1 数据           | 清除本次已经写入的部分 V2 数据并按默认配置启动；迁移向导之后不会再自动出现。V1 原始数据仍保留，部分已经复制的文件可能继续存在。 |
| 【继续使用 V1】 | 暂时无法解决迁移问题，需要恢复工作         | 安装 V1 并继续使用原 V1 数据目录；V2 中的新变化不会返回 V1。                               |

{% hint style="danger" %}
不要把 V2 备份恢复到 V1，也不要把 V1 备份导入 V2。误选【直接使用 V2】或无法判断数据状态时，不要删除数据库或反复覆盖安装，请联系 `support@cherry-ai.com`。
{% endhint %}

### 配置说明

| 配置项        | 产品默认值           | 建议起点               | 作用                 | 适用场景            | 注意事项                             |
| ---------- | --------------- | ------------------ | ------------------ | --------------- | -------------------------------- |
| 【精简备份】     | 以当前界面显示为准       | 升级前关闭              | 决定备份是否包含体积较大的托管文件  | 需要完整回退保障        | 精简备份不能替代完整数据目录副本。                |
| Agent 权限模式 | 保留可迁移的 Agent 配置 | 首次运行先使用需要确认的模式     | 控制工具调用是否需要用户批准     | 检查迁移后的 Agent    | 旧版自动批准偏好不会按原语义继承。                |
| Agent 知识库  | 仅使用显式绑定项        | 逐个绑定实际需要的知识库       | 限定 Agent 知识工具的检索范围 | 私有资料问答和项目 Agent | 未绑定时，即使知识库已迁移，Agent 也无法通过知识工具访问。 |
| 网络搜索默认服务   | 以迁移结果和服务可用性为准   | 分别选择一个关键词搜索和网址读取服务 | 决定搜索词和网页链接由哪个服务处理  | 联网问答与资料整理       | 检查服务凭据、隐私和额度。                    |

### 开发者与 API 兼容性

<details>

<summary>API Gateway 的模型标识有什么变化？</summary>

`model` 字段由 `provider::model` 改为 `provider:model`，并在第一个英文冒号处分隔服务 ID 与模型 ID。使用 `/v1/chat/completions`、`/v1/messages` 或 `/v1/responses` 的客户端需要更新固定配置。

</details>

<details>

<summary>Knowledge API 的返回结构有什么变化？</summary>

`knowledge_bases`、`results`、`searched_bases` 和 `total` 等外层字段保持不变，但数组中的条目改用 V2 字段。知识库条目包含 `embeddingModelId`、`createdAt` 等字段；搜索结果包含 `chunkId`、`score`、`scoreKind`、`rank`、`knowledge_base_id` 和 `knowledge_base_name`，不再提供 `page` 字段。

</details>

<details>

<summary>外部客户端还能通过 API Gateway 使用 MCP 吗？</summary>

不能。V1 的 `/v1/mcps`、`/v1/mcps/:server_id` 和 MCP Streamable HTTP 入口在 V2 中返回 404，目前没有 HTTP 替代方案。Cherry Studio 应用内部使用 MCP 不受影响。

</details>

<details>

<summary>流式 API 的错误处理需要调整吗？</summary>

需要兼容两种路径：模型尚未输出内容时发生的启动错误可能直接返回 HTTP 4xx、5xx 或 504；流式输出开始后的错误仍通过 SSE 错误事件返回。

</details>

<details>

<summary>定时任务集成需要检查什么？</summary>

依赖旧定时任务触发参数的脚本需要按 V2 接口重新适配。任务本身会迁移，但历史运行记录不会迁移。

</details>

### 用户案例

小林长期使用 V1，保存了多个模型服务、助手、项目 Agent 和知识库。他先将 V1 更新到 1.9.13，关闭【精简备份】创建完整备份，再完全退出应用并复制整个数据目录。首次启动 V2 2.0.0 后，他核对向导中的数据位置并完成迁移。

重启后，小林先恢复 Anthropic API Key，再为项目 Agent 绑定对应知识库，重新选择网络搜索的两项默认服务，并重建一个显示失败的知识来源。最后，他在【设置】→【数据】创建新的 V2 完整备份。常用对话、Agent 会话、知识库和文件均能打开，才把 V2 作为后续工作环境；V1 数据目录副本继续保留一段时间。

### 预期结果

* V2 可以正常启动，迁移向导不再出现。
* 常用模型、助手、会话、Agent、知识库和文件可以打开。
* 迁移警告中的项目已经逐项处理或记录。
* 网络搜索、Anthropic 凭据、Agent 权限与知识库绑定已经重新确认。
* V1 完整备份、V1 数据目录副本和新的 V2 备份分别保存，未相互覆盖。

### 常见问题

<details>

<summary>可以从 V1 直接安装最新的 2.0.1 或更高版本吗？</summary>

不可以。第一次迁移必须先运行 V2 2.0.0 系列并完成迁移，之后再更新到更高版本。

</details>

<details>

<summary>只有 V1 备份 ZIP，没有原数据目录，可以迁移吗？</summary>

迁移向导不会读取备份 ZIP。请先在兼容的 V1 中恢复并确认数据正常，再保留完整数据目录，然后启动 V2 迁移。不要直接把 V1 备份导入 V2。

</details>

<details>

<summary>知识库迁移后都需要重新建立索引吗？</summary>

不需要。有效索引会随知识库迁移。只有显示失败、缺少嵌入模型或无法读取的知识来源需要重建或重新上传。

</details>

<details>

<summary>迁移会删除电脑上的原始附件吗？</summary>

不会。V2 清理的是 Cherry Studio 管理的文件副本，不会删除用户磁盘上的原文件。需要长期保留的托管副本可放入【文件】或导出到其他目录。

</details>

<details>

<summary>选择【直接使用 V2】后还能自动重新迁移吗？</summary>

迁移向导不会再次自动出现。若误选该项，不要删除数据库或继续大量写入数据，请保留 V1 原数据和备份并联系 Cherry Studio 支持团队。

</details>
